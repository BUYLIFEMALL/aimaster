# 마크다운 문서 자동화 개발 플랜

2026-10-13. 아래는 전체 개발 계획이며 모든 항목이 구현된 것은 아닙니다. **1단계 공통 틀·문서 모델 및 기본 화면은 로컬 구현·검수를 마쳤고 운영 연결은 대기 중**입니다. 세부 증거는 [1단계 기록](PHASE1_IMPLEMENTATION.md), 별도 승인 항목은 [운영 설정안](PROVISIONING_PLAN.md)에 있습니다. 2~5단계는 남은 작업입니다.

## 1. 제품 목표·출시 범위

**마크다운을 작성하거나 가져오면 서식을 확인하고 HTML·PDF·Word로 변환하여 보관·전달하는 문서 작업실**을 만듭니다. 원본의 편집 편의성은 유지하고 저장 신뢰성·문서 호환성·회원별 분리를 보강합니다.

작업명 제안: **마크다운 문서 자동화**. 프로젝트 폴더/슬러그 가칭: `markdown-studio`. 도메인 후보: `markdown-studio.buylife.xyz`. 등록 전 충돌 확인과 명칭 확정이 필요하며 현재 도메인·카탈로그 등록은 없습니다.

초기 출시 목표는 원본 핵심 기능 전체 + 안정성 보완 + `.md`/JSON 가져오기·백업입니다. 본인 Drive 저장·복원도 출시 범위에 포함하지만 실제 본인 OAuth 확인 전에는 완료로 표시하지 않습니다. AI 글 생성·외부 공개 발행·실시간 공동 편집은 후속 확장으로 분리합니다.

## 2. 사용 흐름·화면

**새 문서/가져오기 → 편집 및 실시간 미리보기 → 문서 검토 → 원하는 형식으로 내보내기/본인 Drive 저장**.

공통 좌측 메뉴는 다음을 사용합니다.

1. 대시보드: 최근 문서·저장 상태·빠른 시작.
2. 번호 1 `문서 준비`: 새 문서, `.md`/`.txt` 가져오기, 예제·문서 템플릿.
3. 번호 2 `편집·미리보기`: 문서 탐색기 + 편집기 + 미리보기.
4. 번호 3 `변환·내보내기`: 단일/폴더 묶음, 변환 설정, 다운로드 결과.
5. 번호 4 `문서 보관함`: 폴더·검색·휴지통·백업·복원.
6. 구분선 아래 `API키등록·플랫폼연동`, `연동 & 사용 매뉴얼`.
7. 마지막 메뉴 바로 아래 8~16px로 로그인 이메일·로그아웃. `mt-auto`/큰 빈 공간으로 하단에 밀지 않음.

우측 편집 화면:

- 상단: 문서 이름·경로, “이 기기에 저장됨/저장 중/저장 실패”, Drive 상태, 다운로드.
- 그 아래 원본 20개 명령을 모두 지원하는 서식 툴바. 추가로 실행 취소/다시 실행·찾기/바꾸기.
- 작업 영역 안에 문서 탐색기, Markdown 편집기, 미리보기 3열. 탐색기 접기와 분할 비율 저장.
- HTML 소스/미리보기 선택, Markdown/HTML 각각 복사, 목차·글자 수.
- 모바일: 탐색기는 서랍, 문서 영역은 편집/미리보기 탭. 최소 너비를 보장하며 3열을 강제하지 않음.
- 본문·카드·입력창은 흰색 또는 옅은 중성색. 원본 HTML 소스의 다크 배경도 웹 공통 규칙에 맞게 밝은 색으로 변경. 다운로드는 눈에 띄는 노란색 배경·어두운 글자와 명확한 형식 이름.
- 날짜·날씨·불필요한 모델 표시·개발자 내부 정보는 작업 화면에 넣지 않음.

## 4. 구현 구조 제안

| 영역 | 제안 | 선택 이유·제약 |
|---|---|---|
| 앱 | Next.js + React + TypeScript + Tailwind, 독립 서브프로젝트 | 기존 AIMaster 앱 패턴·SSO 재사용; 버전은 저장소 지원 상태 확인 후 고정 |
| 편집 | CodeMirror 6 기반 Markdown 편집 | 선택 영역·실행 취소·단축키·찾기·조합 입력을 일관되게 처리; 한글 IME 검수 필수 |
| 변환 핵심 | Marked의 토큰/렌더링 + DOMPurify | 단순 자체 정규식 Markdown 함수 대신 GFM 유지; HTML 정제는 제거하지 않음 |
| 로컬 저장 | IndexedDB, 로그인 회원별 이름 공간 | 매 키 입력마다 전체 보관함 기록을 피하고 문서 단위 저장·리비전·실패 복구 |
| PDF | pdfmake + 배포에 포함된 한글 글꼴을 우선 검증 | 이미지 PDF 대신 텍스트 PDF; 긴 표·글꼴 크기·특수기호 검증 후 채택. 인쇄/PDF 저장은 보조 경로 |
| DOCX | `docx`로 문단·제목·목록·표·이미지를 OOXML로 구성 | altChunk를 그대로 쓰지 않고 편집 가능한 문서 생성; 다양한 앱에서 열어보기 |
| 다운로드/백업 | Blob 다운로드 + ZIP, 버전이 있는 JSON manifest | `.md`, HTML, 여러 파일·첨부 자산을 관리; 백업에 토큰/키 포함 금지 |
| Drive | Google 공식 OAuth 및 Drive API, 회원 소유 앱 | `drive.file` 범위를 우선 사용; 기존 파일 선택이 필요하면 공식 Picker 등 별도 검증 |
| 선택적 서버 보관 | 공유 Supabase에 사용자 소유 문서 테이블·RLS | 여러 기기/이력 보관 필요 시 추가; **스키마 승인 전 적용하지 않음** |

외부 CDN 스크립트에 필수 기능을 의존하지 않고 패키지를 설치해 lockfile로 고정합니다. PDF/DOCX/ZIP 등 큰 기능은 사용할 때 지연 로드합니다. 문서 미리보기는 입력 조합 완료 및 적절한 debounce를 적용하고, 큰 문서에서는 worker 도입 필요성을 측정합니다. 라이브러리 채택은 조사 결과에 근거한 제안이며 아직 설치·검증 완료가 아닙니다.

HTML 출력은 한 변환 모듈과 서식 설정을 공유합니다. DOCX/PDF는 동일 Markdown 토큰을 문서 요소로 매핑하여 제목·목록·표 정렬을 유지합니다. 원본처럼 미리보기 CSS와 내보내기 CSS가 서로 어긋나지 않게 합니다.

기본 편집·변환은 AI API 비용이 없습니다. 본인 Drive 이용량은 본인의 Google 환경을 따릅니다. 서버형 PDF/대용량 저장/AI를 추가하면 실제 운영 비용을 별도 산정하고 FREE·프리미엄 정책을 임의로 정하지 않습니다.

## 5. 필요한 기능·설정값 상세

### 문서와 폴더

- 생성·이름 변경·복제·이동·정렬·검색·휴지통·복원.
- 같은 폴더에서 이름 중복 시 이름을 바꾸거나 사용자가 교체를 선택. 빈 이름·경로 문자 검증.
- 검색: 기본 파일명, 선택적으로 본문 포함. 검색어를 정규식으로 직접 해석하지 않음.
- 상위 폴더 이동 순환 차단, 키보드 이동 대안, 터치 사용자 메뉴.
- 마지막 선택 문서·탐색기 펼침·분할 비율은 **회원별** 저장. 삭제한 기본 문서를 자동 부활시키지 않음.

### 편집

- 원본 제목 1~3, 굵게·기울임·취소선, 글머리/숫자/알파벳 목록, 체크리스트, 들여쓰기·내어쓰기, 인용, 코드, 링크, 이미지, 표 3명령, 구분선, 특수기호, 원문 복사.
- Enter: 숫자 증가·체크박스 이어쓰기·빈 목록 종료. 알파벳 목록은 GFM과 다르므로 렌더링 정책을 명확히 정의하고 편집·변환에서 일치시킴.
- 표: 원본 3열×2행 프리셋 + 원하는 행/열 수, 행/열 추가·삭제, 왼쪽/가운데/오른쪽 정렬, 셀의 escaped pipe 처리.
- 코드 언어 선택, 안전한 URL 입력, 로컬 이미지 등록·미리보기. 상대 이미지 경로는 가져온 자산 묶음과 연결.
- `Ctrl/Cmd+B`, `I`, `S`, `Z`, redo, Tab/Shift+Tab; S는 로컬 저장과 Drive 업로드의 의미를 구분해 표시.
- HTML 소스보기·복사, 완성 미리보기, 목차·본문 찾기, 글자 수. 복사 권한 실패도 안내.

### 변환

- 형식: `.md`, `.html`, `.pdf`, `.docx`, JSON 백업, 묶음 ZIP.
- 대상: 현재 문서 / 선택 문서 / 폴더(하위 포함).
- 묶음 방식: 한 문서로 합치기 / 개별 파일 ZIP. 정렬과 파일별 페이지 구분 선택.
- 페이지: A4/Letter, 세로/가로, 여백, 기본 글꼴/크기, 제목·줄간격, 표 넘침 정책. PDF/DOCX 용지 크기 일치.
- HTML: 정제된 본문 조각 또는 CSS 포함 전체 문서; 스크립트·토큰은 포함하지 않음.
- 이미지/특수기호 누락은 알리고, 외부 이미지 CORS·크기 제한·지원 형식을 검사. 본문 임의 누락 금지.
- 문서/폴더 이름을 출력에 넣을 때 escape. 파일명 안전화 및 중복 파일명 처리.

### 저장과 Drive

- 회원 본인 Client ID 설정, 현재 도메인 복사, Drive API/동의 화면/테스트 사용자 매뉴얼.
- 연결 계정 표시·연결 해제·토큰 만료/재연결; 토큰·키는 클립보드/백업/로그에 넣지 않음.
- **로컬 자동 저장**과 **Drive 수동 저장/가져오기**를 별개 상태로 표시. 성공을 추정하지 않음.
- 변경 파일만 업로드, ID 기반 연결, 부모 폴더 이동 반영, 업로드 성공 후 원격 메타데이터 확인.
- 원격 수정 충돌: 로컬/원격/두 버전 모두 유지 선택. 이름만 보고 덮어쓰지 않음.
- 로컬 휴지통과 Drive 삭제를 분리. Drive에서의 삭제는 사용자 명시 선택 + 휴지통 이동을 기본으로 하며 영구 삭제 자동 연동 금지.
- 부분 실패 파일별 재시도, 429/5xx 제한적 지연 재시도, 401 사용자 재연결, 취소·오프라인 후 재개.
- 원격 루트 폴더 준비 실패 시 중단. Drive 최상위로 폴백하지 않음.

## 6. 데이터·API 제안과 승인 의존성

기본 모델 예:

```ts
type DocumentNode = {
  id: string;
  userId: string;
  kind: 'folder' | 'document';
  parentId: string | null;
  name: string;
  markdown?: string;
  revision: number;
  updatedAt: string;
  deletedAt: string | null;
  driveFileId?: string;
  lastSyncedRevision?: number;
  remoteModifiedTime?: string;
};
```

이는 설계 예시이며 코드·DB를 만든 상태가 아닙니다. 외부 Drive 계정을 바꾸면 이전 계정의 ID 연결을 재사용하지 않습니다. 첨부 자산도 문서와 같은 소유자·이름 공간으로 관리합니다.

서버 보관 후보: `markdown_documents`(폴더 포함), `markdown_document_revisions`, 필요 시 연동 정보. 모두 `user_id`, RLS owner-only, 코드의 명시적 `user_id` 필터를 적용합니다. 서버 OAuth 방식을 쓰면 `state`와 현재 세션의 일치 확인, 비밀 정보 암호화 저장을 적용합니다. 기존 연동 저장·공통 키 패턴을 조사한 뒤 방식을 확정하고 새로운 provider명을 독단으로 DB에 추가하지 않습니다.

후보 API는 documents/import/backup/export/settings/connect/callback/disconnect입니다. 서버가 불필요한 처리는 브라우저에서 완결합니다. 모든 서버 API에 로그인 + 프로그램 이용 권한 + 소유자 확인, `force-dynamic`/`force-no-store`를 적용합니다.

**DB 스키마·환경변수 신설/변경은 구체적인 SQL·설정안을 준비한 뒤 승인 대상으로 제시합니다.** 승인 전에는 로컬 문서 기능·변환 검증처럼 독립적으로 할 수 있는 부분을 진행할 수 있습니다. 운영 DB를 먼저 바꾸지 않습니다.

## 7. 검사 계획

- 단위: Markdown 공통 표본(제목·강조·중첩·표·코드·링크·체크리스트), 이름/검색 특수문자, 이동 순환, 리비전 충돌, 올바른 PDF/DOCX 내용.
- 보안: script/onerror/javascript URL 차단, 파일명 HTML 삽입, 다른 회원 문서 지정, 로그아웃/회원 전환, JSON 순환·과대 데이터·잘못된 스키마.
- 저장: 신규→편집→재로딩→복원, 빈 보관함, 용량/쓰기 실패, 오프라인, 두 탭 동시 수정, 이력 복원.
- 실제 화면: 일반 회원으로 20개 명령/목록/이동/모바일/실제 단축키, 원문·미리보기·다운로드 비교.
- 다운로드: 실제 한글 본문과 표·이미지·코드·다중 페이지 표본. PDF 글자 추출·페이지 수, DOCX 문단/표 XML, Word/Google Docs 표시 확인.
- Drive: 모의 401/403/429/5xx/중간 실패 + 본인 Google 계정 업로드/갱신/가져오기/충돌. 모의 결과와 실제 연결을 구분해 보고.
- 마무리: 빌드·필요 검사·권한 판정·도메인·버전·카탈로그 링크·썸네일·매뉴얼 확인.

검사 결과를 기능 비교표에 실행일·증거와 함께 기록합니다. 실행하지 않은 기능은 대기/미확인으로 두고, 다운로드가 된 것만으로 레이아웃·호환성까지 합격 처리하지 않습니다.

## 8. 운영 등록·인수인계

- `lib/version.ts`의 `APP_VERSION`과 DB `programs.version`을 초기 `v1.01`로 일치. 표시명·슬러그·도메인·FREE 설정은 등록 전 확정.
- `programs.app_url`과 기본 3단계 `pricing_plans`를 함께 등록. 실비 기준으로 분류하며 과금 정책을 새로 추정하지 않음.
- 문서 편집·변환의 성격을 보여주는 실사 썸네일. 인물은 한국인이 기본. 기존 로고·참고 개발자 표시를 가져오지 않음.
- `platform_guides`, 앱 `/guide`, README/AGENTS/HANDOFF에 실제 조작·제한·남은 작업 기록.
- 다른 CLI에 이 분석을 넘기고 구현된 항목과 미구현 항목을 혼동하지 않게 유지.
- 플랜 작성 단계에는 앱 빌드·DB 변경·운영 배포가 필요하지 않음. 구현 이후 각 작업은 공통 완료 절차를 따름.

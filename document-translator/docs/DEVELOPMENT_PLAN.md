# AI 문서번역 자동화 — 개발 플랜

작성: 2026-10-14, Codex. 주인님의 원본 분석·개발 플랜 요청을 바탕으로 ‘진행해줘’ 이후 로컬 v1.01을 구현했습니다. **운영 변경은 승인·적용 완료이며 v1.02 프로덕션 배포 완료입니다. v1.03 줄바꿈 수정 배포도 완료했으며 최종 회원 화면 검수는 Chrome 로그인 창 준비 대기입니다. 최신 운영 상태는 RELEASE_CHECKS.md를 기준으로 합니다.** 원래 제안에서 구체화한 API 통합·최대10구간·응답 캐시 제거·청록색 자체 CSS·만료 Cron은 [실제 구현 기록](IMPLEMENTATION_STATUS.md)을 우선합니다. 근거: [원본 분석](REFERENCE_ANALYSIS.md).

## 1. 제품과 이름

추천 이름은 **AI 문서번역 자동화**입니다. 문서 입력부터 다국어 번역·용어/문맥/문체 검토·역번역·저장까지 이어지는 회원용 작업 공간을 만듭니다. 원본의 UI 문구·프롬프트·코드는 복제하지 않고 기능 구조를 참고합니다.

후보 slug/폴더/Vercel 프로젝트는 `document-translator`, 운영 주소 후보는 `https://document-translator.buylife.xyz`. 첫 출시 계획은 v1.01이며 아직 코드·DB 버전은 없습니다. 대안 이름은 AI 번역검수 자동화, AI 다국어 번역 스튜디오입니다.

## 3. 화면과 사용 순서

흰색 작업 화면·중성 회색 경계·어두운 본문 글자를 기본으로 합니다. 브랜드 포인트는 인디고, 용어 표시는 제한적인 청록색입니다. 원본 다크 테마와 원본 제작자 링크를 가져오지 않습니다.

좌측 메뉴: 프로그램명/버전 → 다른 프로그램 보기(https://www.buylife.xyz/programs) → 대시보드 → ①문서번역 → ②용어집 → ③작업 보관함 → API키등록·플랫폼연동 → 사용 안내 → 바로 아래 회원 이메일·로그아웃. 번호형 작업 흐름·여백은 docs/SIDEBAR_LAYOUT_STANDARD.md를 적용합니다.

번역 작업 화면 내부는 **원문 준비 → 언어·분야·모델 설정 → 번역 및 검수 → 수정·역번역 → 다운로드·보관** 순서입니다. 데스크톱은 원문/번역문2열과 우측 검수 패널, 중간 폭에서는 검수 패널을 아래로, 모바일에서는 원문/번역문/검수 탭으로 바꿉니다. 숨겨진 영역의 중요 버튼이 접근 불가능하지 않도록 합니다.

입력 파일명·실제 감지 언어·선택 대상·실제 모델·결과 생성 기준을 표시합니다. 언어를 바꾼 뒤 예전 결과가 새 언어로 번역된 것처럼 보이지 않게 합니다. 문체 점수는 **AI 참고 평가**이며 실제 정확도나 전문 검수 인증으로 쓰지 않습니다.

## 4. 입력·출력 정책

### 입력

- 파일당5MiB, 텍스트 PDF 최대50페이지, 추출 결과 최대20,000 Unicode 문자. 서버도 같은 문자 한도를 검사합니다. 파일 한도는 초기 제안이며 구현 중 메모리·시간 검수 결과로 줄일 수 있습니다.
- TXT는 UTF-8/UTF-8 BOM을 기본으로 읽고 잘못된 인코딩은 명확히 안내합니다. PDF는 PDF.js 작업자를 앱 정적 파일로 제공하고 읽기 순서·줄바꿈을 보수적으로 복원합니다.
- DOCX는 확장자와 ZIP 구조를 검사하고 압축 해제 총량20MiB·항목 수 한도를 적용합니다. 외부 파일/이미지 접근을 켜지 않고 문서 파싱을 작업자에서30초 제한으로 처리합니다. Mammoth의 HTML은 정화한 뒤 Markdown 블록으로 바꾸며 그대로 innerHTML로 삽입하지 않습니다.
- 원본 파일은 기기에서 파싱하며 서버에 파일을 업로드하지 않습니다. 추출 내용이 없으면 스캔 문서 또는 빈 문서 안내를 표시합니다. AI가 빈 파일의 내용을 지어내도록 보내지 않습니다.
- 파일 선택 자체는 AI 호출0회입니다. 구조 추론이 필요하면 회원이 별도 **AI 문서 정리**를 선택하며, 사실·날짜·수치·순서 변경 없이 정리하도록 합니다. 정리 실패 시 추출한 원문을 유지합니다.

### 출력

- TXT/Markdown은 원문과 현재 수정본을 따로 저장합니다. DOCX는 제목·문단·단순 목록·굵게·기울임·단순 표를 지원하고, 이미지를 포함한 원본 레이아웃 완전 재현은 후속 범위입니다.
- 문서 이름은 금지 문자와 경로 구분자를 제거하고, 대상 언어·파일명·필요 시 버전을 포함합니다. 비동기 생성 실패를 처리합니다.
- 용어 CSV는 UTF-8 BOM·CRLF·모든 셀 따옴표·따옴표 이스케이프·스프레드시트 수식 보호를 적용합니다.
- 프로젝트 JSON은 프로그램 식별자·백업 버전·exportedAt·언어·모델·문서/분석을 포함하고 키는 넣지 않습니다. 가져오기 전4MiB·구조·지원 버전·참조를 검증해 미리보기 후 새 프로젝트로 추가합니다. 기존 프로젝트 덮어쓰기 기본값은 없습니다.

## 5. AI 설계와 비용 제어

회원 본인 `user_api_keys(provider=gemini,user_id=로그인 회원)`를 서버에서 조회합니다. 클라이언트에는 등록 여부만 반환합니다. 키 입력·저장은 기존 공통 API키등록 화면 패턴을 사용하며 실제 Gemini 발급 매뉴얼을 연결합니다. 관리자 서비스 롤은 DB 권한 조사·본인 필터 조회 용도이며 외부 AI 키 대체 용도가 아닙니다.

모델 제안: 기본 `gemini-3.8-flash`, 경제형 선택 `gemini-3.5-flash-lite`. [현재 공식 모델 안내](https://ai.google.dev/gemini-api/docs/models)를 확인했습니다. 구현·배포 직전 모델 지원/구조화 출력/출력 토큰 한도를 다시 확인하며, 선택 모델 실패 시 다른 모델이나 다른 키를 자동 호출하지 않습니다.

### 문서 분할

20,000자 문서는 문단 경계 기준으로 최대4,000자씩5조각까지 나눕니다. 긴 단일 문단도 Unicode 문자를 끊지 않는 안전 분할을 적용합니다. 각 원문 블록에 고정 ID를 부여하고 응답의 ID 집합·순서를 검증합니다. 첫 조각의 감지 정보와 누적 용어집을 다음 조각에 전달해 일관성을 유지합니다. 분석 용어 수는 조각당50개, 문서 합계200개 이내로 제한합니다.

기본 번역은 조각당1회입니다. 화면에 예상 조각 수/최대 호출 수를 보여주고 완료/실패한 조각을 표시합니다. 자동 전체 재시도는 하지 않으며 회원이 실패한 조각만 다시 실행합니다. 취소하면 다음 조각 호출을 중단하고 현재 서버 호출의 취소가 비용 취소를 보장한다고 표시하지 않습니다.

동일 작업의 동시 실행·재전송은 회원별 operationId와 입력 fingerprint로 차단합니다. 서버리스 메모리만으로 중복 호출을 막았다고 주장하지 않고 DB의 원자적 실행권 획득을 사용합니다. 실제 운영 스키마 적용은 승인 후 진행합니다.

### 프롬프트·응답

- 시스템 프롬프트에 `new Date().getFullYear()`를 넣습니다. 새 설명은 당해 연도 맥락을 사용하되 **원문에 적힌 과거 날짜·수치·인명·URL은 사실대로 보존**합니다.
- 문서 내용은 번역 대상 데이터로 구분하고 문서 안의 명령·키 요청·외부 URL 실행 지시를 따르지 않습니다. 문서에 없는 설명·표·사실을 추가하지 않습니다.
- `sourceTerm`/`targetTerm`/`explanation`처럼 언어에 중립적인 이름을 사용하고, 검수 설명 언어는 한국어를 기본으로 합니다. 전용 용어집은 회원이 승인한 대응만 사용합니다.
- JSON Schema를 공급사에 제공하고 Zod로 문자열/배열/언어/점수1~10/블록 ID를 재검증합니다. STOP 외 완료 상태·길이 제한·차단·누락을 성공으로 처리하지 않습니다. [구조화 출력의 값 검증 안내](https://ai.google.dev/gemini-api/docs/structured-output).
- 숫자·날짜·URL 점검은 규칙 검사와 AI 제안을 구분해 보여주며, 단위/표현 방식 차이를 무조건 오역으로 판정하지 않습니다.
- 역번역은 현재 수정본을 기준으로 실행합니다. 비교 대상은 최초 원문·현재 번역문·역번역3종입니다. 역번역이 유사해도 정확성 보증은 하지 않습니다.

## 6. 상태·오류·저장

문서/설정/번역 수정마다 revision과 fingerprint를 바꿉니다. 늦은 응답은 요청 시점의 revision과 현재 상태가 같을 때만 적용합니다. 번역·분석·역번역의 기준 revision을 별도로 저장합니다.

원문 수정 또는 모델/대상 언어 변경 시 기존 번역을 지우지 않고 **이전 설정의 결과·재번역 필요**를 표시합니다. 번역문을 수동 수정하면 기존 문맥/용어/문체 점검과 역번역을 오래된 결과로 표시합니다. 새 문서로 바꿀 때만 미저장 변경 확인 후 초기화합니다.

진행 상태는 추출/번역/검수/역번역/저장을 분리하고 동시 실행 충돌을 막습니다. AbortController·요청 ID·서버 조각 타임아웃90초·전체 조각 상한으로 처리합니다. 실패 시 기존 결과를 보존하며 키 누락·키 권한·한도·응답 미완료·JSON 오류·파일 오류를 쉬운 한글로 구분합니다. 원문·키·공급사 원시 응답은 서버 로그에 남기지 않습니다.

원본 파일은 서버에 보관하지 않습니다. 원문과 결과는 AI 실행 중 요청에 포함됩니다. 완료 응답 재조회/중복 방지용 임시 결과 캐시는 최대10분으로 안내하고, 별도의 프로젝트 보관은 **회원이 저장을 선택할 때만** 수행합니다. 보관함은 최대100건/기본30일 제안이며 자동 저장은 기본 꺼짐입니다. 저장 실패를 저장 완료로 표시하지 않고 저장 성공·실패·미저장 상태를 보여줍니다.

## 7. 기술·API·DB 설계

독립 Next.js App Router·TypeScript·React·Tailwind·Zod 앱으로 작성합니다. 별도 Git 저장소는 만들지 않습니다. 공용 Supabase 프로젝트 `esgxyikcnnvmlhygjkth`, 공용 회원·프로그램 권한·키를 재사용합니다.

참고할 기존 구현: ai-task-planner의 서버 Gemini/JSON 검증·자기 키 조회·CSV 보호·백업 검증, markdown-studio의 문서/Markdown 편집 패턴, 루트 access 판정·SSO 쿠키 도우미. 기능 범위를 조사한 뒤 필요한 부분만 각 서브폴더 안에 옮기고 프로젝트 사이 런타임 상대 참조는 만들지 않습니다.

| API 제안 | 책임 |
|---|---|
| `GET /api/keys` | 본인 Gemini 등록 여부·허용 모델만 반환 |
| `POST /api/translation` | 인증·권한·출처·입력/revision·operationId 검증, 조각 번역/분석 |
| `POST /api/review` | 현재 수정본의 문맥·용어·문체 재검수 |
| `POST /api/reverse` | 현재 수정본 조각의 역번역 |
| `POST /api/structure` | 회원이 선택한 문서 정리 |
| `GET/POST/PATCH /api/projects` | 본인 저장 프로젝트 조회·추가·revision 기반 수정 |
| `POST /api/projects/remove` | 본인이 선택한 프로젝트 삭제, 소유자·출처 검증 |
| `GET/POST/PATCH /api/glossaries` | 회원별 용어집 조회·추가·수정 |

권한이 있는 모든 라우트/레이아웃은 dynamic force-dynamic, fetchCache force-no-store를 함께 선언합니다. API는 JSON 오류, 페이지는 로그인/권한 안내로 처리합니다. POST/PATCH 출처 검사, body 최대256KiB 제안, 서버 문자열 한도, `user_id` 직접 필터, suspended 계정 차단, 핸드폰 필수 정책, 관리자 예외, FREE 우선 판정 규칙을 적용합니다.

| 새 데이터 후보 | 최소 필드·원칙 |
|---|---|
| `dt_projects` | id·user_id·title·payload JSONB·revision·created_at·updated_at·expires_at. 회원이 선택한 원문/결과만 보관 |
| `dt_glossaries` | id·user_id·name·entries JSONB·revision·timestamps. 언어별 대응·중복·길이 검사 |
| `dt_operations` | user_id·operation_id unique·input_hash·status·lease_expires_at·response JSONB·expires_at. 원자적 중복 방지·10분 응답 보존. 원본 파일·키 없음 |

새 테이블은 RLS owner-only를 적용하고 anon 접근을 허용하지 않습니다. 서버 서비스 롤에서도 user_id로 한정합니다. 실행권 획득 RPC는 service role에만 허용하고 소유자·input_hash·임대 만료를 검증합니다. 이 표는 설계이며 SQL을 아직 만들거나 적용하지 않았습니다. 미래 마이그레이션 SQL은 이 프로그램의 supabase/migrations에 남깁니다.

원문/결과 JSONB가 크므로 조회 목록은 제목·언어·상태·수정일만 반환하고 상세 조회에서 payload를 읽습니다. 수정은 기대 revision과 일치할 때만 저장하며 충돌은409로 안내합니다. 데이터 삭제/보관 만료 작업의 범위와 승인은 운영 적용 전에 구분합니다.

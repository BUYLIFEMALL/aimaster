# 구현·검수 기록 — document-translator v1.01

2026-10-14, Codex. 이름과 구현은 ‘진행해줘’에 따라 적용했습니다. 운영 변경은 저장소의 특수 작업 사전 승인 규칙에 따라 대기 중입니다.

## 구현한 기능

흰색 작업 화면·번호형 사이드바·공용 Supabase 로그인·프로그램 권한·본인 Gemini 등록 상태와 실제 발급 가이드, TXT/PDF/DOCX 로컬 작업자,10종 언어/분야/모델, 분할 번역·3종 검수, 문단별 수정·수정본 재검수·역번역, 용어 강조/설명/승인 용어집, 숫자/URL 대조 제안, 문서3형식·용어2형식·JSON 백업, 회원 보관함·revision 충돌·만료 차단을 구현했습니다.

파일 선택에 AI 호출 없음, 수동 AI 실행, 타인/운영자 키 폴백 없음, 자동 공급사 재시도·모델 폴백 없음. 요청 출처/한도/구조와 공급사 STOP·문단ID·점수·필드를 검증합니다. AI 실패·언어 변경 시 기존 결과를 보존하고 재번역/재검수 필요를 표시합니다.

## 초기 제안에서 구체화한 결정

- UI 포인트는 청록색입니다. 별도 디자인 라이브러리 없이 자체 CSS를 사용합니다.
- AI 라우트는 `POST /api/ai`의 `kind`4종으로 통일했습니다. 인증/본인 키/중복 방지 경계를 공통 처리합니다. projects/glossaries는 GET/POST, 본인 삭제는 POST remove입니다.
- 문단 경계를 보존하면20,000자라도 정확히5조각에 맞지 않을 수 있습니다. 번역은 최대4,000자·최대10요청, 재검수는 최대15요청, 역번역은 현재 번역문 합계60,000자·요청당12,000자입니다. 실제 예정 번역 요청 수를 UI에 표시합니다.
- AI 입력 최대512KiB, 프로젝트 저장1MiB, 그 외 JSON256KiB를 스트림 누적 검사합니다.
- 임시 AI 응답 서버 캐시는 제거했습니다. 작업ID·입력 해시·종류·상태의24시간 메타데이터만 보관합니다. 같은ID 재전송은 다시 호출하지 않지만 연결 실패 후 새ID 수동 요청에는 추가 사용량이 생길 수 있습니다.
- 유효한 유료 결과를 받은 뒤 DB 상태 완료 기록만 실패하면 그 결과는 사용자에게 전달합니다. 최초 처리중 기록은 남아 같은 요청의 재전송을 계속 막습니다.
- 만료 읽기 차단만으로 실제 DB 원문이 삭제되지 않으므로 별도 pg_cron 정리 SQL을 준비했습니다. 운영 적용 전까지 자동 삭제 완료를 주장하지 않습니다.

## 발견·수정한 문제

1. Unicode 분할에서 문자열 인덱스와 문자 배열 인덱스를 섞으면 이모지 문단이4,000자 한도를 넘었습니다. 문자 배열에서 경계를 찾도록 수정하고 왕복 보존 검사를 추가했습니다.
2. 숫자20을 문자열 포함 검사하면2026의 일부로 잘못 통과했습니다. 번역문 숫자 토큰 집합으로 대조하도록 수정했습니다.
3. PDF.js6 표시 API를 가져오기 Worker에서 직접 초기화하면 window/document 접근으로 텍스트 PDF가 실패했습니다. 명시적 nested Worker port·useWorkerFetch와 작업자 정리를 적용한 뒤 실제 PDF 표본을 읽었습니다.
4. 만료 프로젝트는 일반 API뿐 아니라 직접 PostgREST RLS 읽기도 차단해야 합니다. expires_at 조건을 정책에 포함하고 실제 PostgreSQL 역할 검사로 확인했습니다.

# 개발 플랜 — 행정동 찾기·행정동별 매물 보기 (2026-11-01)

작성: Claude Code(윈도우) `claude-win-realty-docs` [역할: realty]. 대상: ① AIMaster 운영, `commercial-land-trade-alert`.
근거: 회원 피드백 「노량진1동, 상도2동으로 세분화」, 「법정동/행정동 구분」, 「1동, 2동으로 구분되어 있어 중개사님들에게 더 편할 것」. 주인님 「플랜을 세워주고 작업 진행하자」.

주 사용자: 공인중개사(2026-11-01 주인님). 동네 단위 영업과 임대 중개가 본업이라, 2단계에서는 월세 매물이 잘리지 않는 것도 함께 본다.

## 문제
네이버 매물, 동 코드, 실거래가 모두 법정동 기준이다. 행안부 자료(`KIKmix.20261026`) 대조: 행정동 3,595개 중 887개가 여러 법정동에 걸치고, 법정동 690개가 여러 행정동에 걸친다. 예: 노량진제1동 → 노량진동·본동, 노량진제2동 → 노량진동, 상도제2동 → 상도동.

## 1단계: 행정동 찾기 (구현 완료, 미배포 대기)
행정동을 넣으면 법정동을 알려 주고 눌러서 지역을 고른다. 매물을 행정동으로 거르지는 않는다.
- 자료: `public/admin-dongs.json`, 생성 `scripts/build-admin-dongs.mjs`. 행정동이 바뀌면 새 `jscode*.zip`으로 다시 만든다.
- 출처 표시: 행안부 저작권정책이 공공누리 자료는 출처 표시를 요구한다. 이 자료의 공공누리 표시 여부는 게시물에서 확인하지 못했다.

## 2단계: 행정동별 매물 보기 (사전 검증 뒤 결정)
방식: 회원 PC에서 매물 좌표(`latitude`, `longitude`)가 어느 행정동 경계 안인지 판정해 화면·알림을 거른다. 매물과 좌표는 서버로 보내지 않는다.

### 사전 검증 (통과해야 구현)
| 확인할 것 | 통과 기준 |
|---|---|
| 좌표가 실제 위치인지, 건물별로 다른지 | 표본 대부분이 건물 근처이고 같은 좌표로 뭉치지 않음 |
| 행정동 판정 정확도 | 주소를 아는 표본 30건 중 27건 이상 일치 |
| 경계 자료 | 이용 조건 확인(SGIS 원본 우선, 국토부 자료는 제4유형이라 쓰지 않음), 용량 확인 |
| 쪽수 상한 | 동 전체를 끝까지 읽을 수 있는 비율. 지도 묶음(`clusters`) 범위로 나눠 읽는 방식의 가능성·수집 부담 |

### 알려진 한계
- 화면당 15페이지 상한 뒤의 매물은 걸러도 나타나지 않는다. 거래방식·유형으로 나눠 보완한다.
- 실거래 자료는 법정동 기준이고 일반 건물 지번이 가려져 시세 비교는 법정동 단위로 둔다.
- 경계에 걸친 매물과 좌표가 없는 매물은 「판정 불가」로 표시한다.

### 구현 범위(통과 시)
감시 화면에 행정동 선택 칸 추가, 결과·알림·주간 리포트 거르기, 경계 자료 생성 스크립트, 시험 추가. 서버 스키마 변경은 칸 1개 정도로 예상하며 적용 전 승인받는다. 빌드는 1~2회 예상, 승인 뒤 진행.

## 검수·비용
1단계: 시험, 타입 검사, 배포 뒤 시험 계정 크롬 데스크톱·375px 확인. 추가 비용 없음(다음 배포 묶음).
2단계 사전 검증: 좌표 진단을 확장에 넣어야 해 다음 배포 묶음과 함께 나가며 추가 빌드는 없다. 구현 빌드는 별도 승인.

## 사전 검증 기록
- 2026-11-01 1차(v1.22, 백석동 월세 1개 화면): 좌표 있음 298/300건, 서로 다른 위치 136곳, 소수 6자리. 표본 30건은 약 10m 단위로 27곳, 범위 약 1.3km. 한 점에 뭉치지 않아 건물 단위 좌표로 보이나 실제 주소 대조는 아직 안 함. 다른 4개 화면은 이 회차에 없음.
- 2026-11-01 2차(경계 `vuski/admdongkor` ver20261001, 사전 검증용, 데이터 CC BY 4.0, SGIS 가공 자료, 저장소 안내상 일부 경계 오차 가능): 백석동 월세 표본 30건 모두 판정, 백석1동 17건·백석2동 13건, 다른 동으로 벗어난 표본 0건. 실제 주소 대조는 아직 안 함.
- 크기: 전체 34.7MB, 소수 5자리로 줄이면 15.7MB. 시·군·구별로 나누면 중간값 50KB, 최대 243KB라 필요한 지역만 받을 수 있다.
- 다음 제안: 결과 화면에 「행정동(추정)」 칸과 거르기를 먼저 넣고 중개사가 아는 동네로 정확도를 확인한 뒤 알림 거르기로 넓힌다. 15페이지 상한은 그대로 남는다.
- 2026-11-01 1차 구현 v1.23(주인님 승인): 결과 표 칸과 거르기만. 알림·감시 화면 거르기는 실제 정확도 확인 뒤. 경계 자료는 256개 시·군·구로 나눔(15.7MB).
- 2026-11-02 정확도 측정(무료, 내 PC): 정답 = 행정안전부 위치정보요약DB 건물별 「관할행정동」(202609, 임장 노트 격자 v2). 시·군·구마다 경계 안 건물 최대 3,000곳을 우리 경계(`public/dong-boundaries/`)로 판정해 비교. **전국 256곳 84만 1,243곳: 맞음 98.6% · 판정 불가 0.6% · 다른 동 0.8%**, 시·군·구 중간값 99.3%. 강남구 99.9%(3,053곳), 고양 일산동구 99.2%(3,348곳). 낮은 곳은 경북 경산 86.6%·강원·전북 농촌(대부분 「판정 불가」=경계 빈틈, 다른 동 오판은 적음). 기준 「30건 중 27건(90%)」 통과. 한계: 매물 좌표가 아니라 건물 출입구 좌표로 잰 값(매물 좌표가 건물 단위라는 1차 기록과 함께 보면 비슷할 것으로 봄). 스크립트는 저장소 밖 스크래치(재현: 경계 파일 × 격자 v2 12번째 칸).

## 3단계 구현안: 감시 화면·알림을 행정동으로 거르기 (2026-11-02 작성, 승인 대기)
| 순서 | 내용 | 비용·승인 |
|---|---|---|

| 4 | 시험: 거르기·판정 불가 처리·경계 파일 저장, 시험 계정 크롬 데스크톱·375px | 무료 |

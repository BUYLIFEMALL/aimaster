## 2. 고칠 범위 (한 가지)

이번 회차에 **켜져 있는데 읽지 못한 감시 화면**(상한·막힘·실패 모두)은 직전 `lastResult`에 있던 그 화면의 결과를 남기고, 화면에 「이전 회차(시각) 결과」라고 표시한다.

하지 않는 것: 15페이지 잘림 해결, 상한 값 변경, 서버 쪽 결과 저장, 알림 방식 변경.

## 3. 설계 — Master가 짚은 다섯 가지

### 3-1. 이름 충돌 → 감시 화면 `id`로 묶는다
- 감시 화면 표 `commercial_land_listing_targets`는 `id uuid`가 고유이고 `name`은 겹칠 수 있다(`unique (user_id, url)`뿐, `name` 기본값 `''`). 결과 표 첫 칸 「감시 화면」은 이름만 담으므로 **이름으로 합치면 같은 이름의 두 화면이 섞인다.**
- 그래서 `lastResult`에 표와 같은 길이의 **줄별 감시 화면 id 목록** `rowTargetIds`를 함께 저장한다(표 칸·엑셀·CSV는 그대로, 화면에 안 보임). `perTarget`에도 `id`를 넣는다.
- 보존·교체는 모두 이 `id` 기준이다.

### 3-2. 삭제·끄기·이름 바꿈
- **삭제했거나 끈 화면**: 확장은 켜진 화면만 받는다(`/api/extension/settings`, `enabled = true`). 이번 `targets`에 없는 `id`의 이전 줄은 **남기지 않는다**(지운 화면이 결과에 계속 남지 않게).
- **이름 바꿈**: `id`가 같으니 보존 대상이다. 남긴 줄의 첫 칸과 `perTarget.name`은 **지금 이름으로 바꿔** 적는다(드롭다운 거르기·엑셀이 새 이름으로 묶이게).
- **주소(url)를 바꾼 화면**: 같은 `id`라도 네이버 화면이 다르므로 이전 결과를 남기면 다른 지역 매물이 섞인다 → `perTarget`에 `url`도 저장해, `url`이 달라졌으면 남기지 않는다.

### 3-3. 갱신 시각
- `perTarget` 항목마다 `at`(그 화면을 실제로 읽은 회차 시각)을 둔다. 이번에 읽은 화면은 이번 `startedAt`, 남긴 화면은 **처음 읽었던 시각을 그대로**(남긴 것을 다시 남겨도 시각을 새로 고치지 않음).
- 남긴 화면은 `stale: true`. 결과 화면 「🔎 이번 회차에 읽은 범위」에서 그 화면 줄에 「⏸ 이번에 못 읽어 이전 회차(11-19 19:47) 결과를 보여 줘요 — 사유: 오늘 한도/네이버 막힘/오류」를 붙인다.
- 너무 오래된 결과: 남긴 결과의 `at`이 **7일**을 넘으면 남기지 않는다(시세·매물이 크게 달라졌을 수 있음). 7일은 예약 주기(기본 6시간)보다 충분히 길고, 상한에 며칠 연속 걸려도 화면이 비지 않게 하는 값 — 주인님·Master가 바꿀 수 있음.
- 결과 화면 머리의 「○○ 수집」 시각은 지금처럼 이번 회차 시각이고, 남긴 화면이 있으면 「(일부 화면은 이전 회차)」를 덧붙인다.

### 3-4. 과거 결과와 알림·기록 분리
- 합친 결과는 **`lastResult` 저장에만** 쓴다.
- 알림 전달 `deliver(...)`, 주간·누적 기록 `pushHistory`/`pickEvents`, 수익률 `applyYields`, 서버 상태 보고 `reportStatus`에는 **지금처럼 이번 회차에 읽은 것만** 넘긴다 — 남긴 줄이 알림으로 다시 나가거나 통계에 두 번 쌓이지 않게.
- 비교 기준 `states`는 지금처럼 읽은 화면만 고친다(변경 없음).

### 3-5. 기존 데이터 호환
- 지금 회원 PC에 저장된 `lastResult`에는 `rowTargetIds`·`perTarget[].id/at/url`이 없다. 이 경우 **보존하지 않고 지금처럼 통째 교체**한다(이름으로 추측해 합치지 않음). 새 확장으로 한 번 다 읽은 뒤부터 보존이 동작한다.
- 결과 화면(`ResultsClient`)은 새 칸이 없으면 지금과 똑같이 보인다(`stale` 없음 = 표시 없음). 옛 확장 + 새 웹, 새 확장 + 옛 웹 모두 깨지지 않는다(새 칸은 선택 칸).
- 표 최대 2,000줄 제한(`table.slice(0, 2000)`)은 유지하되 **이번 회차 줄을 먼저, 남긴 줄을 뒤에** 붙여 잘려도 새 결과가 남게 한다. `rowTargetIds`도 같은 길이로 자른다.
- `places`(매물 번호 → 좌표)는 남긴 줄의 매물 번호 것만 이전 값에서 가져온다. `sggByWatch`(이름 → 시군구)는 `id`로 다시 만든다.

## 5. 시험(로컬, 무료)

1. 5곳 중 1곳만 읽음 → 읽은 1곳은 새 줄, 나머지 4곳은 이전 줄·`stale`·이전 `at`
2. 모두 읽음 → 지금과 같은 결과(보존 없음)
3. 같은 이름 두 화면 중 하나만 읽음 → 다른 하나만 남고 섞이지 않음(`id` 기준)
4. 삭제/끈 화면·주소 바뀐 화면 → 남기지 않음, 이름만 바뀐 화면 → 새 이름으로 남김
5. 7일 넘은 이전 결과 → 남기지 않음, 남긴 것을 다시 남겨도 `at` 그대로
6. 옛 모양 `lastResult`(새 칸 없음) → 통째 교체(지금 동작), 2,000줄 자르기에서 이번 회차 줄 우선

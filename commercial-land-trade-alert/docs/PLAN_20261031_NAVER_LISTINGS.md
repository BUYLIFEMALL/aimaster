# 개발 플랜 — 네이버 매물 읽기 + 시세 대비 분석

상태: 승인(2026-10-31), 0단계 진행 중. 코드·확장·DB 변경 없음.
0단계 현황: 에이전트 도구는 네이버 부동산·약관 페이지를 안전 제한으로 열지 못한다(우회하지 않음). 주인님이 `extension/`의 사전 검증 메뉴로 화면 3종을 열어 결과 파일을 준다(1단계에서 수집 엔진으로 교체, 프로그램 폴더 안에 두는 것은 주인님 지시). 다운로드 ZIP·DB 확장 버전은 회원에게 낼 때 맞춘다. 이용 조건은 2026-10-24 분석(`docs/analysis-naver-realty-collector-20261024/REPORT.md` §3)의 「자동 수집 제한, 법률 검토 필요」에서 나아가지 못했다.
근거: 주인님 「네이버 매물 읽기도 해야지」, 「실시간 가격변동 체크, 좋은 매물 찾기 위한 모니터링, 그리고 투자가치분석 기존 시세대비 가격변동률」.
옛 플랜: `docs/analysis-naver-realty-collector-20261024/PLAN_20261025_BUILDING_LISTING_ALERT.md`(건물만, 별도 프로그램). 이 플랜이 대체한다.

## 1. 추천
- 별도 프로그램이 아니라 이 프로그램에 크롬 확장을 더한다. 실거래 표가 이미 있어 호가와 바로 비교할 수 있고, 2026-10-31 묶음 방향과 맞다.
- 이름은 매물이 들어가므로 「상가·건물·토지 매물·실거래 알림」을 추천한다(slug 유지, 확장 표시명도 같게).
- 수집 원칙은 `realty-listing-alert`와 같다: 회원 PC, 회원 본인 계정, 화면이 불러온 내용만, 하루 상한, 차단 화면이면 그날 멈춤. 매물은 서버로 보내지 않는다.

## 2. 요청 기능과 의견
| 요청 | 방법 | 의견 |
|---|---|---|
| 실시간 가격변동 | 매물 번호별 이전 가격과 비교, 새 매물·내림·올림·사라짐 알림 | 진짜 실시간은 차단 위험이 커서 하지 않는다. 1~24시간 예약, 권장 3~6시간 |
| 좋은 매물 모니터링 | 조건 저장 + 후보 점수(시세 대비 낮음, 가격 내림 횟수, 오래된 매물) | 「급매」로 단정하지 않고 「확인할 후보」와 근거를 보여 준다. 같은 건물 중복 등록은 묶는다 |
| 시세 대비 변동률 | 호가 평당가 ÷ 같은 동·같은 분류 실거래 평당가 중간값(12개월, 5건 이상) | 가장 큰 차별점. 일반/집합을 나누고, 표본이 적으면 표시하지 않는다 |
| 투자가치 분석 | 규칙 계산 먼저, 그다음 AI 요약 | 월세·보증금이 있는 상가만 수익률 계산. 대출·세금·공실은 회원 입력. AI는 회원 본인 Claude 키, 버튼을 누를 때만, 숫자만 전달 |

## 3. 위험
- 네이버 이용 조건: 0단계에서 점검한다. 결과가 나쁘면 진행하지 않고 보고한다.
- 지역 단위 매물은 단지보다 페이지가 많아 차단 위험이 크다. 지역 수·페이지 상한을 더 낮게 둔다.
- 면적 기준 차이: 매물과 실거래의 면적 정의가 다르면 비교가 틀어진다. 0단계에서 확인하고 다르면 비교 문구를 제한한다.
- 지번이 가려져 매물과 실거래를 건물 단위로 잇지 못한다. 비교는 동 단위 참고값이다.
- 회원 PC와 크롬이 켜져 있어야 수집된다.

## 4. 순서
| 단계 | 내용 | 비용 |
|---|---|---|
| 0 | 사전 검증: 상가·건물·토지 화면 3종 소량 읽기, 칸·월세·면적 정의, 페이지 수, 이용 조건 | 무료, 빌드 없음 |
| 1 | 확장 뼈대·연결·지역 감시·가격 변동·알림 | 빌드 1~2회 |
| 2 | 시세 대비 변동률, 후보 점수, 결과 화면 | 빌드 1회 |
| 3 | 수익률 계산, AI 요약 | 빌드 1회, AI 시험 소액 |
| 4 | 실물 시험, 공개 회원 안내 | 없음 |

단계마다 결과를 보고한다. 1~3단계 빌드는 3~4회이며 대기 중인 상세 문구 수정도 함께 나간다.

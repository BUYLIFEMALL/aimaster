# 개발 플랜 — AI 비서 검색 도구 고르기 (2026-11-15, [역할: workspace])

주인님 지시: 「사용자가 선택할 수 있는 선택지로 여러 가지 검색 도구를 제시할 수 있도록 기능 확장해」
배경: Gemini 키 회원은 웹 검색이 아예 안 됨(검토 `docs/REVIEW_20261115_GEMINI_WEB_SEARCH.md`). Claude·OpenAI는 모델에 들어 있는 검색만 씀.

## 1. 만들 것
- AI 비서 설정에 **「🔎 웹 검색 도구」** 고르기 칸(회원별, 기본 「자동」).
- 고른 검색 도구는 **Claude·OpenAI·Gemini 어느 모델에서나** 같은 방법으로 쓴다 — 비서가 「web_search」 도구를 부르면 우리 서버가 회원 본인 키로 그 검색 서비스를 불러 결과(제목·주소·요약 5~8개)를 돌려준다. 화면의 「검색함 · 출처」 표시는 지금과 같다.
- 키는 **공용 `user_api_keys`에 이미 있는 것을 그대로 재사용**한다(새 등록 화면 없음, 없으면 「API키등록·플랫폼연동」 안내).

## 2. 선택지(모두 회원 본인 키, 운영자 키 없음)
| 선택지 | 쓰는 키(공용 저장소) | 지금 등록 회원 | 특징 |
|---|---|---|---|
| 자동(추천 기본값) | — | — | Claude·OpenAI는 모델 내장 검색, Gemini는 아래 중 등록된 키를 차례로(네이버 → 카카오 → Tavily → Perplexity → SerpAPI) |
| 모델 내장 검색 | Claude·OpenAI 키 | — | 지금 방식(Gemini는 없음) |
| 네이버 검색 | `naver_client_id`·`naver_client_secret` | 5 | 국내 블로그·뉴스·웹문서에 강함, 무료(하루 한도) |
| 카카오(다음) 검색 | `kakao_rest_api_key` | 4 | 다음 웹문서·블로그, 무료(하루 한도) |
| Tavily | `tavily` | 2 | AI용 검색, 요약 포함 |

- 무료 한도·요금은 구현 때 각 공식 가격표로 다시 확인해 화면 안내에 적는다(회원 키로 청구).

## 3. 구현 순서
1. `src/server/searchProviders.ts`(새): 제공자 6종 호출 + 결과 모양 통일(순수 함수로 응답 변환, 시험 가능) — 회원 키는 `memberIntegrations`/`user_api_keys` 읽기 재사용.
2. 비서(`src/litpage/server/ai/service.ts`)·에이전트(`agents/runs.ts`): 「웹 검색」이 켜져 있고 고른 도구가 외부 검색이면 서버 도구 대신 **함수 도구 `web_search(query)`**를 넣고 `executeTool`에서 실행 → 기존 「검색함」 단계·출처 표시로 연결. 내장 검색일 때는 지금 그대로.
3. 설정 화면(AI 설정): 고르기 칸 + 키 등록 상태(✅/키 없음 → 등록 링크) + 한 줄 요금 안내.
4. 시험: 제공자별 응답 변환 시험(가짜 응답), 키 없음·실패 시 한국어 안내, Gemini에서 함수 도구로 검색되는지.
5. 매뉴얼 AI 비서 단락에 「검색 도구 고르기」 추가.

## 4. 검수
- 로컬: tsc·시험·빌드.
- 운영(엣지, 시험 계정): 시험 계정에 등록된 검색 키로 1~2회씩 실제 검색(무료 한도 안) — 키가 없는 제공자는 「키 없음」 안내만 확인.

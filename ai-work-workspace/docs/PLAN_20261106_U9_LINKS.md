## 3. 구현 내용
### 3-1. 공통 (워크스페이스)
- `PageMenu.tsx`의 보내기 메뉴를 「📨 다른 프로그램으로 보내기」 하위 메뉴 하나로 묶는다. 항목은 할 일 플래너(기존), 슬라이드, 번역, 문서 챗봇이다.
- 서버 `workInboxSendPage({ pageId, target })`를 추가한다. 페이지 본문을 마크다운으로 바꿔(기존 내보내기 변환 재사용) `kind: "document"`로 넣는다. 받는 곳은 허용 목록 4개만 받는다.
- `InboxBoard.tsx`의 보낸 프로그램 이름표(`SOURCE`)에 `ai-audio-analyzer`·`document-translator`를 추가한다.
- 공용 기준 코드 `src/lib/workInbox.ts`의 사본을 받는 프로그램에 그대로 복사한다. 사본은 직접 고치지 않는다. 받는 쪽에서 쓸 「내 목록 읽기·가져감 표시」가 기준 코드에 없으면 기준에 먼저 추가한 뒤 사본을 맞춘다.

### 3-2. U9-A 음성 분석 → 워크스페이스
- 화면: `SpeechReportView.tsx` 결과 위에 「📨 업무 워크스페이스로 보내기」 버튼을 둔다. 음성 분석 결과에만 두고, 음악 분석에는 두지 않는다.
- 서버: `/api/work-inbox`(POST)에서 `checkProgramAccessApi()`로 로그인 회원을 확인한 뒤 `kind: "meeting"`으로 넣는다.
- 본문은 마크다운으로 넣는다. 순서는 요약, 할 일(담당·기한), 핵심 질문, 주제·키워드, 화자별 정리, 전체 받아쓰기(시각·화자)다. 20만 자를 넘으면 받아쓰기부터 줄인다.
- 결과를 DB에 저장하지 않는 프로그램이라, 화면에 있는 결과를 그대로 보낸다. 서버는 길이와 형식만 검사하고, 받는 회원은 항상 로그인 회원 본인이다.

### 3-3. U9-B 워크스페이스 → 슬라이드
- 슬라이드 프로그램에 `/api/work-inbox/received`(목록)와 `/api/work-inbox/received/[id]`(가져감 표시)를 만든다. 둘 다 `user_id` + `target_slug = 'ai-slide-builder'` 조건을 붙인다(할 일 플래너 `received` 라우트와 같은 방식).
- 화면: 원문 칸 위에 「📥 워크스페이스에서 받은 원고(N)」를 둔다. 하나를 고르면 원문 칸을 채우고 가져감으로 표시한다. AI 호출은 회원이 「생성」을 누를 때만 한다.

### 3-4. U9-C 워크스페이스 ↔ 번역
- 받기: 슬라이드와 같은 `received` 라우트(`target_slug = 'document-translator'`). 화면 「📥 받은 문서」에서 고르면 새 번역 작업을 열고 원문을 채운다. 번역은 회원이 직접 누를 때만 한다.
- 보내기: 번역 결과 화면에 「📨 업무 워크스페이스로 보내기」를 둔다. 제목은 「(번역) 원제목 — 언어」, 본문은 번역문이다.

### 3-5. U9-D 워크스페이스 → 문서 챗봇
- 받기: 같은 `received` 라우트(`target_slug = 'ai-doc-chatbot'`). 문서 화면 「📥 워크스페이스에서 받은 문서」에서 「문서로 등록」을 누르면 기존 문서 등록 흐름(텍스트 문서)으로 넣는다.
- 색인은 기존처럼 회원 본인 Upstage 키로 한다. 키가 없으면 기존 「본인 키 등록」 안내를 그대로 쓴다.
- 구현 전에 확인할 것: 기존 업로드 API가 파일 없이 텍스트만으로 문서를 만들 수 있는지 본다. 안 되면 마크다운을 `.md` 파일로 만들어 같은 업로드 흐름에 태운다.

## 4. 진행 순서
1. **U9-A**: 워크스페이스는 이름표 한 줄만 바꾸면 된다. 사용자에게 가장 바로 쓸모가 있고 가장 작다.
2. **U9-B**: 받기 라우트 틀을 여기서 만든다.
3. **U9-C**: U9-B의 틀을 재사용하고, 보내기 버튼을 하나 더한다.
4. **U9-D**: 색인 비용과 업로드 흐름 확인이 있어 마지막에 한다.
- 단위마다 구현 → 테스트·tsc → 커밋 → 미배포 대기로 둔다. 워크스페이스 보내기 메뉴는 B~D 받는 쪽이 모두 배포된 뒤에 같이 연다. 받는 쪽이 없는데 메뉴만 열리면 회원이 보낸 문서가 갈 곳이 없기 때문이다.

## 7. 주인님 결정 항목
1. **다른 역할 폴더 수정**: `ai-audio-analyzer`(music 역할)와 `ai-doc-chatbot`(docbot-prompt 역할) 폴더에 버튼과 라우트를 이 세션이 직접 넣어도 되는지. 추천은 직접 넣는 것이다. 둘 다 지금 작업 중이 아니고, 넣기 직전에 작업 중 표를 다시 확인하고 그 역할 파일에도 남긴다.
2. **범위**: 4개 모두 할지, U9-A(음성 분석)부터 하나씩 결과를 보고 다음으로 갈지. 추천은 4개 모두 플랜대로 구현하고, 배포만 마지막에 한 묶음으로 하는 것이다.
3. **비용**: 빌드 5회와 시험 호출 2회(합계 수 원)를 승인하실지. 승인 전에는 구현·로컬 검사·커밋까지만 하고 배포하지 않는다.

## 8. 검수 방법
- 자동: 각 프로그램 tsc와 기존 시험, 받는 라우트의 회원 격리 시험(다른 회원 id·다른 `target_slug` 줄이 안 보이는지).

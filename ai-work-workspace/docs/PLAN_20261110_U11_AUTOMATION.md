## 3. 범위 (권장안)

1. **자동화·버튼 열기** — `stagePolicy`에서 `saveAutomation`·`setAutomationStatus`·`deleteAutomation`·`duplicateAutomation`·`runButtonServerSteps` 줄을 지움. 웹훅·에이전트 동작은 동작 목록에서 회색 + 「준비 중」으로(저장 시 서버도 거절).
2. **이벤트 실행 보장** — 자동화가 걸린 저장 요청 끝에 Next `after()`로 대기 중인 실행을 비움(서버리스에서 사라지지 않게). 시험: 저장 1회 → 실행 기록 1건.
3. **회원별 정시 실행** — 공용 기준 `memberScheduler.ts` 사본을 이 프로그램에 추가하고:
   - 회원이 처음 정시 자동화(반복 자동화·리마인더·반복 템플릿)를 켜면 회원 cron-job.org에 「1분마다 회원 전용 주소 호출」 작업을 자동으로 켬(키는 공용 연동 `cronjob_org_api_key`, 한 번 등록하면 모든 프로그램 재사용).
   - 새 주소 `/api/cron/member/[token]` — 토큰 해시로 회원을 찾아 **그 회원 워크스페이스의 `scheduled_jobs`만** 처리. 남은 일이 없으면 작업을 끔.
   - 키가 없는 회원: 정시 자동화를 켤 때 「cron-job.org 키를 한 번 등록하면 정해진 시각에 돕니다」 안내(메인 사이트 `/api-settings`). 이벤트·버튼 자동화는 키 없이 바로 동작.
   - 화면: 설정에 주기·켜기 칸을 두지 않음(지침 26번). 자동화 목록 위에 「정시 실행: 켜짐/꺼짐 · 일시정지」 한 줄만.
4. **알림** — 앱 안 알림함 그대로 사용(이미 열림). 자동화 「알림」 동작 → 알림함·실시간 표시 확인.
5. **보관** — 자동화 실행 기록(자동화당 최근 100건)과 알림은 생성 30일 뒤 정리(관리자·시험 계정 `retention_exempt` 제외). 자동화 설정 자체는 회원 설정이라 보관.
6. **매뉴얼** — `/guide`에 「⚡ 자동화」 4단계 카드(만들기 → 트리거 → 동작 → 실행 기록) + cron-job.org 연결 팁·함정 배너.
7. **구글 캘린더 연동** — 이번에는 **검토 문서만**(공용 연동 `member_platform_accounts`로 가능한지, OAuth 앱은 회원 본인 앱이 필요한지). 구현은 결정 뒤 별도 단위.

## 4. 자동화 최소 설정 지표

- 처음 설정: 이벤트·버튼 자동화 **3단계**(⚡ → 트리거 고르기 → 동작 고르기), 정시 자동화는 cron-job.org 키 1번 등록 포함 **4단계**(다른 프로그램에서 이미 등록했으면 3단계).
- 매일 조작: **0번**. 동의: **0번**(회원 본인 워크스페이스 안에서만 동작, 바깥 전송 없음).

## 5. 검수·비용·배포

- 시험: 연결부 통합 시험 새로 — 자동화 저장 허용(막힘 해제)·웹훅/에이전트 저장 거절·`after()` 뒤 실행 기록·회원 토큰 주소가 다른 회원 일을 처리하지 않음·남은 일 0이면 작업 끄기. 기존 시험 전부 + 타입 검사 + 로컬 빌드.
- 운영 확인(ego, 시험 계정): 표에 「상태=완료면 완료일 채우기」 자동화 → 행 바꾸기 → 값 채워짐 / 버튼 「알림 보내기」 → 알림함 / 「매시간」 자동화 → cron-job.org 작업 생성·1시간 안 실행 기록 → 자동화 끄면 작업 꺼짐.
- 비용: Vercel 빌드 **1회**(+ 고칠 일 생기면 1회, 최대 2회) — 시작 전에 다시 여쭙니다. cron-job.org는 무료, 회원 본인 계정. AI 호출 없음.
- 버전: v1.23(코드 `src/lib/version.ts`·사이드바 + DB `programs.version`). **미배포 대기 중인 출처 이름표 `3c175bcce`도 이 배포에 함께 나감.**

## 1. 화면 — 왼쪽 메뉴 「📅 캘린더 연동」(`/calendar-sync`)
두 카드를 나란히 보여 주고 회원이 고른다(둘 다 써도 됨).

| 방식 | 하는 일 | 회원 설정 |
|---|---|---|
| ① 간편 구독(ICS) — 「설정 2단계」 배지 | 고른 표(날짜 칸이 있는 데이터베이스)의 행을 **구글 캘린더에 보여 주기**(한 방향). 구글이 몇 시간~하루마다 새로 읽음 | 표 고르기 → 「구독 주소 만들기」 → 주소 복사 → 구글 캘린더 「URL로 추가」 |
| ② 구글 계정 연결(OAuth) — 「두 방향」 배지 | 표 행 → 구글 일정 **만들기·고치기**(지금 보내기), 구글 일정(앞으로 30일) → 워크스페이스 표 **가져오기**. 바로 반영 | 회원 본인 구글 OAuth 앱(유튜브·구글 블로그와 같은 키) → 리디렉션 주소 추가 → 「구글 연결」 동의 |

## 3. 저장·보안
- ICS: 워크스페이스 자체 표 `aww_cal_feeds`(회원당 1개: 토큰 **해시만** 저장, 고른 표 목록). 주소는 만들 때·다시 만들 때만 보여 줌. 「주소 다시 만들기」로 옛 주소 무효. 주소를 연 요청마다 회원 이용 권한 확인(권한 끝나면 빈 캘린더).
- OAuth: 토큰은 공용 `member_platform_accounts`(platform `google_calendar`, 권한 `calendar.events`), 앱 키는 회원 본인 `user_api_keys`. 보낸 일정 연결은 워크스페이스 자체 표 `aww_gcal_links`(행 id ↔ 구글 일정 id, 중복 방지).
- 운영자 공용 앱·다른 회원 키 금지(최상위 규칙). 구글 일정 데이터는 가져올 때만 읽고 따로 쌓지 않음(표로 가져온 행은 회원 데이터).

## 4. 자동화 최소 설정 지표
ICS: 처음 설정 **2단계** · 매일 조작 **0번** · 동의 0번. OAuth: 처음 설정 **5단계**(앱 키는 다른 프로그램에서 이미 등록했으면 2단계) · 매일 조작 **0~1번**(「지금 보내기·가져오기」) · 동의 1번(구글 동의 화면).

## 5. 검수·비용·배포
- 시험: ICS 글자(날짜 하루 종일·시간 있는 일정·특수문자 처리), 토큰 해시·다른 회원 주소로 못 읽음, OAuth 상태값·권한 확인, 보내기 중복 방지(모의 응답). 기존 시험 + tsc + 빌드.

## 3. 데이터 원본 형식

- 입력: 노션 데이터베이스 「내보내기 → Markdown & CSV」의 **CSV 파일 1개**, 또는 그 내보내기 ZIP 안의 데이터베이스 CSV.
- 예상 열(실제 표본 확인 전): 제목 · 날짜 · 완료(체크칸) · 분류(선택) · 그 밖의 글 열.
- 범위 밖: 행마다 딸린 Markdown 본문·그림·하위 페이지, 반복 일정, 관계형·롤업·수식 열(글로 들어오면 글 그대로 두거나 가져오지 않음 — 미리보기에서 회원이 고름).
- **기존 CSV 경로와 분리하는 근거**: 기존 `importFiles`의 CSV 가져오기와 `mergeCsv`는 날짜만 읽고 중복을 보지 않는다. 그 동작을 바꾸면 이미 쓰는 회원의 결과가 달라진다. 그래서 날짜 해석 확장과 중복 건너뜀은 **새 명령(강의 일정 가져오기)에서만** 켜고, 기존 두 경로는 결과가 그대로인지 회귀 시험으로 고정한다. 공용으로 쓰는 것은 CSV 줄 읽기(`csvRowsOf`)와 저장 직전의 잠금·권한 확인뿐이다.
- **크기 제한**: 이 기능은 CSV 한 개만 다루므로 기존 `mergeCsv`의 10,000행 한도와 일반 파일 올리기 한도를 그대로 쓴다. 내보내기 ZIP을 통째로 받는 경우에도 안에서 데이터베이스 CSV 하나만 읽고 나머지는 열지 않는다. 50MiB를 넘는 ZIP의 큰 ZIP 작업 경로(`import_jobs`)는 이 기능에서 쓰지 않으며, 그런 파일은 「CSV 파일만 골라 올려 주세요」로 안내하고 거절한다. ZIP 안에서 CSV를 고르는 기준(여러 개일 때)은 실제 표본을 본 뒤 정한다 — 그 전까지 1차 구현은 **CSV 파일 직접 올리기만** 지원한다.

## 4. 날짜·시각·시간대

### 4-1. 받는 표기 (지원 형식)

| 종류 | 예 | 저장 |
|---|---|---|
| 날짜만 | `2026-11-20` · `November 20, 2026` · `2026년 11월 20일` | `type: date`, `start_date` |
| 날짜 + 시각 | `November 20, 2026 10:00 AM` · `2026년 11월 20일 오전 10:00` · `2026-11-20 10:00` | `type: datetime`, `start_time` |
| 날짜 범위 | `November 20, 2026 → November 22, 2026` | `type: daterange`, `end_date` |
| 일시 범위(같은 날) | `2026년 11월 20일 오전 10:00 → 오후 12:00` | `type: datetimerange`, `end_date` = 시작일, `end_time` |
| 일시 범위(다른 날) | `November 20, 2026 10:00 PM → November 21, 2026 1:00 AM` | `type: datetimerange`, `end_date`·`end_time` |

- 범위 구분자: `→`, ` ~ `, ` – `(en dash), ` - `(양쪽 공백이 있을 때만).
- 시각: 12시간(`AM`/`PM`, `오전`/`오후`)과 24시간. 초는 버린다(분 단위 저장).
- **`end_time`은 저장하고 달력에도 표시한다**(§6-3). 종료가 시작보다 앞서면 그 행은 실패.
- 위 표에 없는 표기는 **추정하지 않고 그 행을 실패로** 둔다(§5 미리보기의 실패 목록).

### 4-2. 시간대 — 보존·거절 정책

1. **시각은 변환하지 않는다.** 파일에 적힌 벽시계 시각을 그대로 `start_time`·`end_time`에 넣는다.
2. **`(GMT+9)` 같은 숫자 오프셋을 지역 이름으로 바꾸지 않는다.** 오프셋 하나에 지역이 여럿이고(예: +9는 서울·도쿄 등) 서머타임이 있는 지역은 오프셋만으로 정할 수 없다. 오프셋 표기는 **읽어서 검증에만** 쓴다.
3. `time_zone`에 넣는 값은 **회원이 미리보기에서 고른 시간대** 하나다. 기본값은 회원 설정(`user_settings.settings.time_zone`), 없으면 `Asia/Seoul`. 고른 값은 이번 가져오기의 모든 행에 똑같이 적용한다.
4. 파일의 오프셋 표기가 고른 시간대의 그 날짜 오프셋과 **다르면** 그 행을 「시간대 불일치」로 미리보기에 표시한다. 회원은 (가) 시간대를 바꾸거나 (나) 그 행을 빼고 가져오거나 (다) 「표기된 시각 그대로 가져오기」를 명시적으로 고른다. 조용히 변환하거나 조용히 무시하지 않는다.
5. `(KST)`·`(UTC)`처럼 **이름으로 적힌 표기**는 `KST`→`Asia/Seoul`, `UTC`/`GMT`→`UTC` 두 가지만 받는다. 그 밖의 약어(`EST`·`CST` 등)는 뜻이 여럿이라 받지 않고 「시간대 표기 미지원」 실패로 둔다.
6. 한 파일 안에 서로 다른 오프셋이 섞여 있으면 미리보기 맨 위에 경고로 건수를 보여 준다.

## 5. 미리보기 (쓰기 0)

- 순서: 파일 고르기 → **미리보기**(서버가 해석만 하고 DB에 쓰지 않음) → 「가져오기」.
- 보여 주는 것:
  1. 열별 형식 고르기(기존 화면 재사용)와 **날짜 열 지정**, 시간대 고르기.
  2. 해석 결과 표(처음 20행): 원문 → 시작·종료·하루 종일 여부.
  3. 집계: 새로 N · 중복(건너뜀) M · 실패 K · 시간대 불일치 Z.
  4. 중복 목록: 어느 기존 행(또는 파일의 몇째 줄)과 **어떤 키로** 같은지(제목·시작일·시작 시각).
  5. 실패 목록: 줄 번호·원문·사유(표기 미지원 / 종료가 시작보다 앞섬 / 제목 없음 / 시간대 표기 미지원).
- 실패가 있어도 나머지만 가져올 수 있다. 미리보기 집계와 실제 결과가 다르면(그사이 표가 바뀜) 결과 화면에 실제 숫자를 다시 보여 준다.

## 6. 저장·중복·동시성

### 6-1. 중복 키

- 키 = 정규화한 제목(앞뒤 공백 제거·연속 공백 하나로·유니코드 NFC) + `start_date` + `start_time`(없으면 빈 값).
- 판정 대상: 파일 안의 앞 줄, 그리고 대상 표의 기존 행.
- 기본 동작: **건너뜀**. 기존 행을 고치거나 지우지 않는다(갱신·삭제 맞춤은 지속 동기화에 해당).

| 경우 | 처리 |
|---|---|
| 이름이 다르고 시작 일시가 같음 | 다른 일정 — 둘 다 가져온다(같은 시각의 다른 강의) |
| 이름·시작 일시가 같고 **종료가 다름** | 키가 같으므로 건너뛴다. 미리보기 중복 목록에 「종료가 다름: 기존 ○○ / 파일 ○○」을 근거로 표시해 회원이 알 수 있게 한다. 덮어쓰기는 하지 않는다 |
| 이름·시작일이 같고 시각만 다름 | 다른 일정 — 둘 다 가져온다 |
| 이름이 같고 한쪽은 하루 종일, 한쪽은 시각 있음 | 키가 다르므로 둘 다 가져오고, 미리보기에 「비슷한 일정」 경고로 표시 |

### 6-2. 동시 재시도·부분 실패

- 저장은 **한 트랜잭션**에서 한다: 표·컬렉션·보기를 잠그고(기존 `mergeCsv`와 같은 잠금 순서), 권한·대상을 다시 확인하고, **잠근 뒤의 최신 행으로 중복을 다시 판정**한 다음 새 행만 넣는다. 미리보기 때의 판정은 안내용이고 저장 때의 판정이 기준이다.
- 같은 파일을 두 번 누르거나 두 탭에서 동시에 보내면: 잠금 순서대로 차례로 처리되고, 둘째 요청은 첫째가 넣은 행을 중복으로 보고 건너뛴다(결과: 새로 0).
- 중간에 실패하면 트랜잭션 전체가 되돌려져 **일부만 들어간 상태가 남지 않는다.** 응답을 못 받은 경우(시간 초과·연결 끊김)에도 다시 실행하면 중복 건너뜀 덕분에 같은 결과가 된다. 자동 재시도는 넣지 않는다.
- 가져오는 동안 표의 열·보기가 바뀌면 기존과 같이 409로 멈추고 다시 시도하게 안내한다.
- 표 「강의 일정」이 없으면 같은 트랜잭션에서 한 번 만든다(두 요청이 동시에 만들지 않도록 회원 설정 키를 잠근 뒤 확인 — 예약 표 첫 생성 직렬화 `d7895f6d4`와 같은 방식).

### 6-3. 달력 표시

- 「강의 일정」 표의 기본 보기는 달력(날짜 열 지정), 표 보기 하나를 더 둔다. 카드에 완료 체크칸과 분류를 보인다.
- **시각 표시**: 카드에 시작 시각을, 일시 범위는 「10:00–12:00」처럼 종료 시각까지 보인다. 지금 달력 보기에 시각 표시가 없으면 이 작업에서 넣는다(먼저 화면으로 현재 동작 확인). 하루 종일 일정은 시각을 보이지 않는다.

## 7. 업무 현황판 오른쪽 달력

- **새로 만드는 현황판**: `column_list` 두 단 — 왼쪽(넓게) 안내·받은 업무 연결 보기·할 일 표, 오른쪽 강의 일정 달력 연결 보기. 「강의 일정」 표가 아직 없으면 오른쪽 단에 「강의 일정을 가져오면 여기에 달력이 보입니다」 안내와 가져오기 링크를 둔다. 콘텐츠 캘린더 연결 보기는 왼쪽 단에 그대로 둔다.
- **기존 현황판**: 건드리지 않는다. 현황판을 열었을 때 강의 일정 달력이 아직 없으면 「오른쪽에 강의 일정 달력 넣기」 버튼을 보이고, 누르면 **맨 위에 두 단을 새로 넣지 않고** 페이지 끝에 달력 연결 보기를 한 번 추가한다(회원이 손댄 배치를 옮기지 않기 위함 — 단으로 옮기는 것은 회원이 끌어서 한다). 이미 넣었으면 버튼을 숨긴다(회원 설정에 표시).
- 좁은 화면(767px 이하): 단을 한 줄로 쌓는다(기존 단 블록의 동작 확인, 다르면 CSS 보완).

## 9. 구현 순서 (승인 뒤)

1. 날짜 해석 — 새 함수(기존 `parseDateCell`은 그대로 두고 옆에 추가) + 표기별 시험.
2. 미리보기 명령(쓰기 0)과 집계·중복·실패 목록.
3. 저장 명령(트랜잭션·잠금·재판정) + 동시성·실패 주입 시험.
4. 화면: 가져오기 흐름(시간대 고르기·미리보기 표), 달력 카드 시각.
5. 현황판 두 단·버튼.
6. 실제 표본이 오면 합성 표본과 대조해 열 이름·표기를 보정.

예상 파일: `content/csv.ts`(또는 새 `content/notionDates.ts`) · `api/modules/import.ts`(새 명령 2개) · `web/features/import/`(미리보기 화면) · `views/calendar/`(시각 표시) · `src/server/workDashboard.ts` · 시험. **DB 구조 변경 없음 예상**(기존 날짜 값 형식과 회원 설정 칸 사용).

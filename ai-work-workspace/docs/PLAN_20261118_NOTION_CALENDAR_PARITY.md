## 2. 진행 순서

1. **나란히 화면 대조 (비용 0)** — 노션 페이지와 우리 같은 표를 같은 창의 두 탭으로 열고, 아래 점검표를 하나씩 눌러 보며 「있음 / 다름 / 없음」을 채운다. 결과를 이 문서 §3에 적는다.
   - 점검표: 새 일정 만들기(빈 칸 클릭·「새로 만들기」), 카드 열기(옆 미리보기·전체 페이지), 카드 속성 표시 고르기, 체크칸 바로 체크, 날짜 없음 목록, 끌어서 옮기기·늘리기, 하루에 많을 때 「+N개 더」, 주 보기, 시간 있는 일정 표시(오전 11:00), 필터·정렬·검색, 「캘린더에서 관리하기」, 보기 추가·복제, 모바일 폭.
2. **부족 목록 확정 → 주인님 결정** — 「없음/다름」 항목만 우선순위(자주 쓰는 것 먼저)로 정리해 여쭙는다.
3. **구현** — 항목마다 시험(`tests/`) 먼저 → 코드 → `tsc`·시험 통과. 원본 litpage 코드에 같은 기능이 있으면 그대로 살려 쓴다(새로 짜지 않음).
4. **화면 검수** — 배포 뒤 실제 창에서 노션과 같은 동작 확인, 캡처 보고.
5. **인수인계** — `docs/IMPROVEMENTS.md` 미배포 대기, 역할 파일·HANDOFF 갱신.

## 5. 주인님 결정 항목

1. **「우측 캘린더」가 뜻하는 것** — 첫째 노션의 강의 일정 데이터가 우리 캘린더에도 보여야 한다는 뜻인지(= 노션 표 가져오기·동기화, 새 기능), 둘째 캘린더 화면 기능·모양을 노션처럼 맞추라는 뜻인지. 둘 다면 둘째부터 한다.
2. 첫째라면 가져오기 방식 — 한 번 가져오기(CSV·노션 내보내기 파일) / 노션 API로 계속 맞추기(회원 본인 노션 연결 필요, 공용 연동 표 `member_platform_accounts` 재사용).
3. 메뉴 중복(§4-2) 처리 방식.

# 개발 플랜 — 볼타 수정발행·PDF 내려받기 (2026-11-15, [역할: workspace])

주인님 지시: 「볼타 수정발행부터 진행해」 (백로그 「볼타 수정발행·발급 취소(지금은 정발행만) · 발급 완료 PDF 내려받기」)

## 1. 문제
- 지금은 정발행만 된다. 금액이 바뀌었거나, 반품이 있거나, 잘못 적었거나, 두 번 발행했을 때 프로그램 안에서 고칠 방법이 없어 볼타 화면이나 홈택스로 가야 한다.
- 발급이 끝난 세금계산서 PDF를 프로그램에서 받을 수 없다.
- 국세청에 이미 나간 세금계산서는 지울 수 없다. 볼타의 「발급 취소」도 실제로는 수정발행(계약의 해제·착오에 의한 이중발급)이다. 그래서 「취소」는 수정발행 안에 넣는다.

## 2. 볼타 공식 API (docs.bolta.io, 2026-11-15 확인)
| 수정 사유 | 주소 | 보내는 것 | 결과 |
|---|---|---|---|
| 계약의 해제 | `POST /v1/taxInvoices/{issuanceKey}/amend/termination` | 작성일자(`date`)만 | 원본 금액 전부를 마이너스로 상계 |
| 착오에 의한 이중발급 | `POST …/amend/doubleIssuance` | 없음 | 원본을 마이너스로 상계(작성일자는 원본 날짜) |
| 공급가액 변동 | `POST …/amend/changeSupplyCost` | 늘어난(+)·줄어든(-) 차이 품목 + `taxType` | 차이 금액만 발행 |
| 환입(반품) | `POST …/amend/return` | 환입일 + 돌려받은 금액을 마이너스 품목으로 | 마이너스 발행 |
| 기재사항 착오정정 | `POST …/amend/misspell` | 고친 전체 내용(정발행 형식) | 취소분·수정분 두 장 발행(`cancelIssuanceKey`·`issuanceKey`), 포인트 2장 차감 |
| PDF | `GET /v1/taxInvoices/{issuanceKey}/pdf` | — | 내려받기 주소 |

수정발행 결과도 정발행과 같이 접수 번호 → 나중에 결과(웹훅 또는 조회)로 확인한다.

## 3. 만들 것
1. **서버** `src/server/bolta.ts`·`boltaCore.ts`
   - `btAmend`: 발급 완료(`issued`) 문서만 받는다. 사유 다섯 가지, 사유별 본문을 `boltaCore`의 순수 함수로 만든다(시험 가능).
   - 중복 방지: 수정발행마다 새 `Bolta-Client-Reference-Id`. 응답이 불확실하면 자동으로 다시 보내지 않고 관리번호 조회로 확인한다(정발행과 같은 규칙).
   - 실제 키는 정발행과 같은 「실제 발급 동의」가 있어야만 보낸다.
   - 수정발행 결과는 원본 문서 안 `boltaAmends` 목록에 쌓는다(사유·접수 번호·상태·국세청 승인번호·취소분 번호). 원본 발행 기록은 건드리지 않는다.
   - 결과 확인은 기존 「발급 결과 확인」 흐름과 웹훅을 그대로 쓴다(웹훅이 수정분·취소분 번호도 찾게 보강).
   - `btPdf`: 발급 완료 문서(원본·수정분)의 PDF 주소를 받아 새 창으로 연다.
2. **화면** `ReceiptsBoard.tsx`(발행 탭 표)
   - 발급 완료 줄에 「✏️ 수정발행」과 「📄 PDF」 버튼.
   - 수정발행 창: 사유 고르기 → 사유별 입력칸만 보이기(계약의 해제=작성일자 / 이중발급=입력 없음 / 공급가액 변동·환입=차이 품목 / 기재사항 착오정정=원본 내용을 불러와 고치기) → 마이너스·플러스 금액 미리보기 → 「수정발행 보내기」.
   - 보내기 전 확인 창에 「국세청으로 나가며 되돌릴 수 없습니다. 포인트 ○장 차감」을 보여 준다(실제 키일 때 빨간 표시).
   - 줄 아래에 수정 이력(사유·금액·상태·승인번호)을 표시.
3. **시험** `tests/`
   - 사유별 본문 만들기 순수 함수 시험(세액 규칙: 과세=값, 영세=0, 면세=생략 / 환입 합계 음수 / 이중발급 본문 없음).
   - 발급 완료가 아닌 문서·동의 없는 실제 키는 거절되는지 시험.
4. **문서**: 사용 매뉴얼(`/guide`) 수정발행 단계 추가, AGENTS·백로그·인수인계.

## 4. 검수 방법
- 로컬: tsc, 시험(155개 + 새 시험), 로컬 빌드.
- 실제 볼타 호출은 **테스트 키(test_)만** 쓴다(국세청 전송·포인트 차감 없음). 관리자 계정에는 지금 실제 키가 등록돼 있으므로, 시험 계정(`buylifemall@naver.com`)에 테스트 키를 두고 시험하거나 주인님이 정하신 방법을 따른다.
- 운영 배포 뒤 ego로: 테스트 키 문서 정발행 → 「발급 완료」 → 다섯 사유 중 계약의 해제·공급가액 변동 수정발행 → 결과 확인 → PDF 열기.
- **실제 키로는 어떤 발행도 하지 않는다**(주인님 지시 2026-11-14).

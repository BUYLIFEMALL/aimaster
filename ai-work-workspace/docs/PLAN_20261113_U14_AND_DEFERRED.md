## 2. 항목별 제안

### 2-1. 웹훅 자동화 동작 (작음·중간)
- 무엇: 자동화의 「웹훅 보내기」 동작을 연다(회원이 자기 서버·Make·n8n·Zapier 주소로 행 변경을 보냄).
- 방식: 원본 `safefetch.ts`가 이미 위험 주소를 막으므로 그대로 쓰고, **추가 제한**: https만 · 회원당 하루 500회·분당 20회 · 본문 64KB · 10초 · 실패 3번 연속이면 그 자동화 일시정지 + 앱 알림 · 실행 기록에 주소·상태 코드만(본문 저장 안 함).
- 위험: 운영자 서버(Vercel) IP에서 바깥으로 나가는 호출 — 회원이 남의 서버를 두드리는 데 쓰일 수 있음 → 위 한도·기록으로 줄임.
- 비용: 없음(Vercel 함수 실행 시간 조금).
- **구현(2026-11-13, 미배포)**: `src/litpage/server/aimasterWebhookGuard.ts`(https만·회원당 분당 20·하루 500, 이식판 DB `aww_webhook_usage`에 한국 날짜로 셈) → 자동화 엔진 `sendWebhook`·버튼 웹훅 둘 다 거침. 저장 단계 거절(`LATER_AUTOMATION_STEPS`·화면 `LATER_STEPS`) 해제. 「3번 실패 시 일시정지」는 원본이 **1번 실패에 즉시 일시정지 + 알림**으로 더 엄격하므로 원본 그대로 둠. 본문 64KB·10초·위험 주소 차단은 원본 `safefetch.ts` 그대로. 시험 121개 통과.

### 2-2. 메일·카카오 알림 (중간)
- 무엇: 자동화 동작 「메일로 알리기」「카카오톡 나에게 보내기」 + 리마인더(예정된 일정) 알림을 회원 본인 메일·카카오로.
- 방식: **새 연결 화면을 만들지 않고** 공용 연동 재사용 — 메일 = `user_smtp_accounts`(회원 Gmail 앱 비밀번호, 받는 사람은 본인 주소만), 카카오 = `member_platform_accounts` `kakao`(회원 본인 카카오 앱, 「나에게 보내기」만 — 다른 사람에게 보내지 않음). 연결이 없으면 「○○ 프로그램에서 한 번 연결해 주세요」 안내.
- 한도: 회원당 하루 메일 100통·카카오 100건, 같은 내용 1분 안 중복 금지.
- 비용: 없음(회원 본인 메일·카카오 무료 한도).
- **구현(2026-11-13, 미배포)**: 새 동작 종류 대신 기존 「알림 보내기」 동작(자동화에서만)에 선택 칸 「내 메일로도 / 내 카카오톡(나에게 보내기)으로도」(`external`)를 붙임. 받는 사람 = 자동화를 만든 회원 본인. 발송 `src/server/externalNotify.ts` — 메일은 공용 `user_smtp_accounts`(첫 활성 계정, 원본 `mail.ts`의 `deliver`로 보냄 → 새 라이브러리 없음)에서 회원 로그인 메일로, 카카오는 공용 `member_platform_accounts` kakao(`talk_message`) + 회원 본인 REST 키 갱신(기준 realty·commercial `notifyChannels.ts`). 채널별 하루 100건(이식판 DB `aww_external_notify_usage`), 같은 내용 1분 중복 금지, 실패는 앱 알림으로 채널별 한 시간에 한 번. 리마인더(예정 일정) 알림은 다음 단계. 시험 124개 통과(실제 메일·카톡 발송 시험은 배포 뒤 시험 계정 연결 상태로).

### 2-3. 에이전트 웹 검색 (작음)
- 무엇: 업무 비서가 최신 정보를 찾을 수 있게.
- 방식(권장): 운영자 서버가 주소를 가져오는 원본 방식이 아니라, **회원 키 AI의 내장 웹 검색만** 켠다 — Claude `web_search` 도구 · OpenAI 웹 검색 도구 · Gemini Google 검색 연결. 에이전트 설정의 「웹 액세스」 스위치(지금 「준비 중」)를 켜고, 켤 때 비용 안내 표시.
- 비용(회원 본인 키, 공식 가격 배포 전 재확인): 검색 1회당 대략 15~50원 + 읽은 글자 수만큼 토큰. 에이전트 월 상한(700 크레딧)은 그대로.

### 2-4. U14 개방 — MCP 서버 + 공개 REST API (큼)
- 무엇: 회원이 **자기 워크스페이스를 Claude Desktop·Cursor 같은 외부 AI 도구나 자기 프로그램에서** 읽고 쓰게 한다.
- 방식(권장 순서): **1단계 MCP 서버만**(`/api/mcp` 라우트 연결, 설정 → MCP에서 개인 토큰 발급·해지, 원본 그대로 토큰 사용자 권한으로만 동작·해시 저장) → 2단계 공개 REST API(/v1)는 수요를 보고. 바깥 MCP 연결(에이전트가 남의 MCP를 부르는 것)은 운영자 서버의 바깥 호출이라 이번에도 닫음.
- 한도: 토큰당 분당 60회, 토큰 만료 기본 90일, 회원당 토큰 5개.
- 위험: 토큰이 새면 그 회원 워크스페이스 읽기·쓰기 가능 → 발급 화면에 경고·마지막 사용 시각·즉시 해지, 관리자·시험 계정 외 사용 기록 남김.
- 비용: 없음(Vercel 실행 시간 조금).
- **구현(2026-11-13, 미배포)**: Next 라우트 `src/app/api/mcp/route.ts`(원본 `aiStream.ts`의 /api/mcp와 같은 규칙 + **토큰 주인 회원의 AIMaster 이용 권한 확인** → 회원 본인 AI 키로 감싸 원본 `handleMcpHttp` 실행 → 응답 뒤 자동화 마무리). 원본 `litMcp.ts`에 한도 얹음(회원당 토큰 5개·90일 만료·토큰당 분당 60회, `mcpTokenOwner` 추가). 단계 정책에서 토큰·연결 도구 관리 명령 12개만 엶(`MCP_OPEN_RPCS`), 바깥 MCP 서버 등록(프리셋 3개)·에이전트 바깥 연결은 계속 닫힘. 설정 → Workspace MCP 화면(원본, 주소 `/api/mcp`)에 한도·주의 안내 한 줄. 시험 129개 통과(실제 Claude Desktop 연결 시험은 배포 뒤).

**제안(권장)**
1. **1차는 팝빌만**(REST·테스트 서버가 문서로 확인됨). 바로빌은 회원 요청이 있으면 2차.
2. 회원이 **본인 사업자로 팝빌 API를 직접 신청**해 LinkID·SecretKey를 받고, 워크스페이스 「영수증·세금계산서」 설정에 등록(공용 `user_api_keys` provider `popbill_link_id`·`popbill_secret_key` — 다른 프로그램도 재사용). 운영자 파트너 키 없음.
3. 「처음 설정」 4단계: 키 등록 → 「연동회원 등록」 버튼(본인 사업자번호로 `JoinMember`, 이미 있으면 건너뜀) → 「공동인증서 등록」 버튼(팝빌 팝업) → 「시험 발급」(테스트 서버, 무료 포인트).
4. 발급: 지금의 홈택스 일괄발급 엑셀과 **같은 행(받은 업무·영수증 표)**에서 「팝빌로 바로 발급」 버튼. 회원이 한 건씩 내용을 확인하고 누름(자동 대량 발급 없음). 결과(승인번호·상태·실패 이유)를 그 행에 기록, **결과가 불확실하면 다시 보내지 않음**(이중 발급 방지 — 문서번호 `MgtKey`로 조회 먼저).
5. 기본은 **테스트 모드**, 회원이 「실제 발급으로 전환」을 직접 켬(전환 때 「건당 요금은 팝빌이 회원에게 청구」 안내 + 동의 1번).
6. 홈택스 엑셀은 그대로 유지(무료 대안).
- 비용: 운영자 없음(빌드만). 회원은 팝빌 포인트(본인 결제). 시험: 시험 계정이 팝빌 테스트 키를 받아야 실제 시험 가능(무료 포인트).

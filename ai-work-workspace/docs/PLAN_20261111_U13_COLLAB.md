## 2. 만드는 것
1. **회원 찾기·초대(AIMaster 회원만)**: 이메일로 AIMaster 회원(`profiles`)을 서버에서 찾고 → 그 회원의 **이 프로그램 이용 권한**(`checkProgramAccess(그 회원 id)`)을 확인 → 내부 사용자를 **그 회원의 Supabase id로** 미리 만들어 권한을 붙임(임의 id 금지). 회원이 아니거나 권한이 없으면 「AIMaster 회원이면서 이 프로그램을 쓸 수 있는 분만 초대할 수 있습니다」. 메일은 보내지 않고 화면 알림함 + 「📨 받은 업무」에 「○○님이 ○○를 함께 쓰자고 초대했습니다」.
2. **두 가지 공유**: (가) 워크스페이스 멤버 초대(`inviteMembers`·역할 바꾸기·내보내기) (나) 페이지만 공유(`invitePagePermissions`·접근 제한·상속 복구·접근 요청/승인). 소유자는 언제든 거둠.
3. **공유받은 사람 화면**: 사이드바 「공유됨」에 받은 페이지, 워크스페이스 전환 목록에 초대받은 워크스페이스. 첨부 파일은 그 페이지를 읽을 수 있으면 내려받기 허용(`files.ts`).
4. **실시간(권장: 짧은 간격 확인)**: 열린 페이지가 **다른 사람과 공유된 경우에만** 5초마다 `getChangesSince`로 바뀐 것만 받아 화면에 반영(누가 보고 있는지 표시 포함). 혼자 쓰는 페이지는 지금처럼 확인하지 않음(비용 0).
5. **동시 편집 안전장치**: 트랜잭션에서 고칠 행을 잠그고(`FOR UPDATE`) 같은 칸을 동시에 고치면 나중 것이 이기되 **다른 칸·다른 블록 변경은 사라지지 않게**.
6. **닫힌 채 둘 것**: 초대 링크(링크만 있으면 들어오는 방식), 공개 페이지·공개 폼·공개 사이트, 이메일 도메인 자동 합류, 운영자 메일 — 최상위 규칙 예외 범위(초대한 회원끼리) 밖.
7. **누구 키로 도는가(공유 표)**: 자동화는 만든 사람, 에이전트는 주인, AI 채우기·요약은 **누른 사람 본인 키**(지금 구조 그대로, 다른 회원 키로 대신 실행 금지). 정리 보관 기간은 지정(1년, 음악·영상 30일) 그대로 — 기준은 데이터를 만든 회원.
8. **개인정보**: 다른 사용자 프로필은 **같은 워크스페이스 멤버·같은 페이지 공유 상대에게만** 이름·사진, 이메일은 초대한 사람·관리자에게만(`records.ts:71` 조임).

## 4. 순서·검수
1. 회원 찾기·초대 서버(+시험: 회원 아님·권한 없음·자기 자신·중복 초대·거두기) 2. 열 명령 정리(stagePolicy) 3. 공유받은 사람 화면·첨부 파일 4. 실시간 확인·화면 반영 5. 동시 편집 잠금(+시험) 6. 프로필 공개 범위 조임 7. 매뉴얼 「👥 함께 쓰기」 카드 8. 로컬 시험·빌드 → 배포 → 운영 확인(관리자 계정이 시험 계정을 초대 → 두 창에서 같은 페이지 동시 편집·댓글·멘션·거두기).

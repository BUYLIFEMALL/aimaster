# 검토 — 구글 캘린더 연동 (U11 결정 5번: 이번엔 검토 문서만, 2026-11-10, [역할: workspace])

- 플랜: `docs/PLAN_20261110_U11_AUTOMATION.md` §3-7·§6-5. **구현하지 않음.** 아래 결정을 받은 뒤 별도 단위로.

## 1. 무엇을 하려는가

워크스페이스 「📅 콘텐츠 캘린더」·날짜 속성이 있는 표의 행을 회원 본인 구글 캘린더 일정으로 보내기(한 방향), 또는 구글 일정을 표로 받아 오기(반대 방향).

## 2. 지금 있는 것

| 항목 | 상태 |
|---|---|
| 원본 설정 「메일·캘린더」 탭 | 숨김(`src/litpage/web/features/shell/trimPolicy.ts:7`) — 원본도 연결 화면만 있고 실제 동기화는 없음 |
| 공용 연동 저장소 | `member_platform_accounts`(루트 `docs/MEMBER_INTEGRATIONS.md`). 구글은 YouTube 권한(`force-ssl`·`upload`·`readonly`)만 기록, **캘린더 권한 항목 없음** |
| 회원 본인 OAuth 앱 규칙 | 핵심 원칙 4번 — 운영자 공용 OAuth 앱 금지. 구글은 「테스트 중」 앱이면 등록한 테스터(최대 100명)만 로그인되고, 캘린더 권한은 **민감 범위**라 앱 공개(인증 심사) 전에는 7일마다 갱신 토큰이 만료됨 |

## 3. 방법 비교

| 방법 | 회원 설정 | 장점 | 단점·위험 |
|---|---|---|---|
| A. 회원 본인 구글 OAuth 앱(YouTube 프로그램과 같은 방식) + `calendar.events` 권한 | 구글 클라우드 프로젝트·OAuth 동의 화면·클라이언트 ID 만들기(10단계 안팎) | 양방향 가능, 공용 표에 저장해 다른 프로그램 재사용 | 처음 설정이 무거움(자동화 최소 설정 목표 5단계 초과), 「테스트 중」 앱은 7일마다 재연결 필요 |
| B. ICS 구독 주소(워크스페이스가 회원 전용 비밀 주소로 `.ics` 제공 → 구글 캘린더 「URL로 추가」) | 주소 복사 → 구글 캘린더에 붙여 넣기(3단계) | OAuth·키 없음, 운영자 비용 거의 없음, 구글·애플·아웃룩 모두 됨 | 한 방향(워크스페이스 → 캘린더)만, 구글이 몇 시간마다 가져가 즉시 반영 안 됨, 비밀 주소가 새면 일정이 보임(주소 재발급 버튼 필요) |
| C. 자동화 동작 「구글 캘린더에 일정 만들기」 | A가 필요 | 자동화와 바로 연결 | A의 단점 그대로 |

## 4. 권장

1. **먼저 B(ICS 구독 주소)** — 설정 3단계·키 없음으로 「콘텐츠 캘린더를 내 구글 캘린더에서 보기」를 해결한다. 날짜 속성 하나를 고른 표만 대상, 회원 전용 토큰 주소(DB엔 해시), 30일 지난 행 제외 없음(회원 업무 자료), 주소 재발급.
2. 양방향·자동화 동작(A·C)은 회원 요청이 쌓이면 검토 — 공용 연동 저장소에 `google_calendar` 항목을 추가하는 방식으로(다른 프로그램 재사용).

## 5. 주인님께 여쭐 것

- B(ICS 구독 주소) 방식으로 별도 작은 단위를 진행할지. 예상: 빌드 1회, DB 표 1개(회원 토큰 해시), AI 호출 없음.

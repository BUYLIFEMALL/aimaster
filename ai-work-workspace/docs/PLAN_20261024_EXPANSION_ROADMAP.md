# AI 업무 워크스페이스 자동화 — 업무 향상 확장 개발 플랜 (단위별 로드맵)

- 작성: 2026-10-24 · Claude Code(윈도우) · 세션 `claude-win-20261024-workspace`
- 대상: ① AIMaster 운영 (공용 DB ref `esgxyikcnnvmlhygjkth`, 전용 스키마 `aww`) · 현재 v1.03
- 주인님 지시(2026-10-24, 원문 요지):
  1. 업무 향상을 도와주는 자동화 프로그램으로 확장한다. 자세히 분석해 AIMaster 다른 프로그램과 **연계할 기능**과 **불필요한 기능**을 나누고, 더할 것은 더하고 뺄 것은 빼며 계속 개발한다.
  2. 원래 노션을 바탕으로 한 프로그램이므로 노션 기능을 다시 검토해 경쟁력 있는 기능은 가져온다. 노션과 비슷한 **이름·설명은 AIMaster 규칙에 맞춰 다른 프로그램처럼 보이게 모두 바꾼다.**
  3. **디자인·레이아웃·프로그램 간 연계도 AIMaster 기준으로** 바꾼다.
  4. **한 번에 다 하지 않는다.** 플랜을 세우고 단위별로 쪼개 하나씩 확장·병합한다.
- 이 문서는 분석과 플랜만 담는다. 코드는 아직 고치지 않았다. 단위마다 착수 전에 그 단위의 상세 플랜을 다시 보여 드리고 승인받는다.

## 3. AIMaster 다른 프로그램과의 연계

### 3-1. 연계 방식 — 「업무 받은편지함」 공용 표 (프로그램끼리 서로 호출하지 않음)

- AIMaster 규칙상 프로그램끼리 서로의 API를 부르지 않고 각자 독립 배포한다. 그래서 **공용 DB에 회원별 「업무 받은편지함」 표를 하나** 둔다(가칭 `public.work_inbox`: `user_id`·보낸 프로그램 slug·종류·제목·본문(마크다운)·구조 데이터(JSON)·만든 때·가져간 때).
- 다른 프로그램은 결과 화면에 **「업무 워크스페이스로 보내기」** 버튼을 달아 이 표에 한 줄을 넣는다(서버, 회원 본인 `user_id`).
- 워크스페이스는 좌측 **「받은편지함」** 메뉴에서 그 줄을 보고 「페이지로 만들기 / 표에 행으로 넣기」를 누른다.
- 회원 데이터 격리: `user_id` + RLS(본인만), 가져가지 않은 항목은 30일 뒤 자동 삭제(생성 데이터 30일 규칙). 가져간 페이지는 회원 업무 자료라 30일 삭제 대상이 아니다(1단계 결정 §7-1).
- 이 표는 공용 DB 스키마 변경이라 U7 착수 때 주인님 승인을 받는다. 공용 연동 규칙(`docs/MEMBER_INTEGRATIONS.md`)처럼 다른 프로그램도 재사용할 수 있게 만든다.

### 3-2. 연계 후보 표

| 프로그램 | 연계 기능 | 방향 | 우선순위 | 단위 |
|---|---|---|---|---|
| `ai-task-planner` (할 일·집중 시간) | 워크스페이스 업무 보드 ↔ 오늘 할 일 | 양방향 | 높음 | U8 |
| `ai-audio-analyzer` (음성 회의록·화자 분석) | 음성 회의 분석 결과 → 회의록 페이지 | 받기 | 높음 | U9 |
| `ai-doc-chatbot` (내 문서 근거 챗봇) | 위키 페이지 → 챗봇 문서로 보내기 | 보내기 | 중간 | U9 |
| `document-translator` (문서 번역) | 페이지 → 번역본 페이지 | 왕복 | 중간 | U9 |
| `ai-slide-builder` (슬라이드) | 페이지·회의록 → 발표 슬라이드 | 보내기 | 중간 | U9 |
| 블로그·Threads·인스타·유튜브 발행 프로그램 | 원고·발행 기록 → 「콘텐츠 캘린더」 표 (IDEA-AWW-01) | 받기 | 높음 | U10 |
| `competitor-analysis`·`longtail-keyword-expander`·`blog-keyword` | 분석 리포트 → 페이지 | 받기 | 중간 | U10 |
| `website-scraper`·`web-crawler-saas` | 수집 결과 → 표 행(웹 클리퍼 대체) | 받기 | 중간 | U10 |
| `crm-google-form`·`booking-reminder`·`stepmail` | 신청자·예약·발송 대상 ↔ 고객 관리 표 | 받기(먼저) | 낮음 | U11 이후 |
| `comment-inbox` | 처리할 문의 → 할 일 행 | 받기 | 낮음 | U11 이후 |
| `ai-image-studio` | AI 이미지 블록 대신 「AI 이미지 자동화에서 만들기」 링크 | 연결 | 낮음 | U2 |
| `markdown-studio`·`ebook-studio` | 위키 → 마크다운·전자책 | 보내기 | 낮음 | 후보 |

다른 프로그램에 버튼을 다는 일은 그 프로그램 담당 세션과 겹치지 않게 `docs/ACTIVE_WORK.md`를 확인하고, 프로그램마다 한 단위씩 진행한다.

## 4. 이름·문구·디자인을 AIMaster 기준으로

### 4-1. 이름·문구 바꾸기 (U1)
- 원본·노션식으로 보이는 이름을 AIMaster 방식(한국어, 기능이 바로 보이는 이름)으로 바꾼다. 화면에 「Notion」이라는 단어는 없지만(2026-10-24 확인) 다음이 남아 있다.

| 지금 | 바꿀 이름(안) |
|---|---|
| 탭 제목 「○○ \| Workspace」 | 「○○ \| AI 업무 워크스페이스」 |
| 기본 페이지 Team Home · Meeting notes · Expenses · Team wiki · Welcome to Workspace(영어) | 팀 홈 · 회의록 모음 · 지출 기록 · 팀 위키 · 시작 안내 (새 회원부터 적용, 기존 회원 페이지 이름은 건드리지 않음) |
| 「캘린더를 Workspace에 연결」, 「Workspace 커뮤니티 템플릿 둘러보기」 등 원본 브랜드 문구 | 「AI 업무 워크스페이스」로 바꾸거나, 뺄 기능이면 문구째 삭제 |
| 노션식 메뉴 이름(라이브러리·팀 General·Inbox 등) | 용어 표를 만들어 한 번에 정리(예: 라이브러리 → 보관함, 팀 General → 기본 팀 공간) — U1 상세 플랜에서 전체 표 제시 |
| 연동 & 사용 매뉴얼·메인 사이트 상세 소개 | 노션 비교 표현 없이 이 프로그램만의 차별점(업무 받은편지함·현황판) 중심으로 다시 씀(`docs/PROGRAM_DESCRIPTION_STANDARD.md`) |

- 오픈소스 표시(MIT, © 씨그로)는 라이선스 의무라 「오픈소스 고지」 자리에 그대로 둔다.

### 4-2. 디자인·레이아웃 (U5)
- 지금은 원본의 노션식 어두운 화면 그대로다. AIMaster 디자인 표준(`DESIGN.md`, `docs/PROGRAM_DESIGN_STANDARD.md`)의 템플릿 하나를 정해 색 토큰·사이드바(`docs/SIDEBAR_LAYOUT_STANDARD.md`)·모바일 767px·매뉴얼 8대 스타일(`docs/MANUAL_AND_INTEGRATION_GUIDELINES.md`)을 맞춘다.
- 추천 템플릿: **스마트 매트릭스(대시보드형)** — 업무 현황판·받은편지함이 중심이 되는 방향과 맞음. 흰색·검정 두 테마.
- 역할 분담상 디자인 리뉴얼은 agy 담당이 기본이다(메모 「Claude = 코딩, AGY = 디자인」). U5는 주인님이 담당 CLI를 정해 주시면 그 CLI가 진행하고, 나머지 단위와 겹치지 않게 순서를 맞춘다.

- **Gemini 비중(2026-10-24 코드 조사)**: 다른 AIMaster 프로그램 코드에서 `user_api_keys` 제공자 이름은 `gemini` 83곳, `openai` 3곳이었고 Claude 쪽 이름은 이번 검색에서 나오지 않았다. 회원 대부분이 Gemini 키만 등록했을 가능성이 높으므로 **U4(Gemini)를 U3 바로 뒤에 붙여 진행**하고, U3 상세 플랜에서 Claude 키의 실제 제공자 이름(`integration_catalog`)을 먼저 확인한다.
- 순서 원칙: 「바꾸기·빼기 → AI → 디자인 → 회의록 → 연계 → 자동화 → 협업」. 앞 단위가 운영에서 확인된 뒤 다음으로 넘어간다.
- 1단계 플랜의 「3단계 협업 → 4단계 자동화」 순서를 이 문서에서 **연계·자동화를 협업보다 앞으로** 바꿨다(업무 향상 자동화 방향에 맞춤). 주인님 확인 사항 §7-2.
- 버전은 실제 배포 때만 +0.01(작은 단위는 모았다가 배포).

```sql

language plpgsql security definer set search_path = public as $$
declare r_id uuid;
begin
  insert into member_platform_accounts (user_id, platform, external_id, username, access_token, refresh_token, token_expires_at, granted_scopes, auth_method, app_ref, connected_via)

  do update set access_token = excluded.access_token,
                refresh_token = coalesce(excluded.refresh_token, case when member_platform_accounts.app_ref = excluded.app_ref then member_platform_accounts.refresh_token end),

    where member_platform_accounts.external_id = excluded.external_id
  returning id into r_id;
  return case when r_id is null then 'other_account' else 'ok' end;
end $$;
revoke all on function public.gmail_account_save(jsonb) from public, anon, authenticated;
grant execute on function public.gmail_account_save(jsonb) to service_role;
```

## 6. A2 설계 보강 (이번 코드 범위 아님)
- **고아 업무 방지**: 「받은 업무 insert → 클레임 insert(ON CONFLICT DO NOTHING)」 순서는 클레임이 충돌하면 앞에 넣은 받은 업무가 남음(고아) → **클레임을 먼저 선점**하고, 한 함수(=한 거래) 안에서:
  1. `insert into public.gmail_inbox_claims (…) values (…) on conflict do nothing returning 1` — 같은 키를 다른 거래가 잡고 있으면 그 거래가 끝날 때까지 기다린 뒤(READ COMMITTED) 충돌이면 아무것도 안 넣음.
  2. 못 넣었으면 기존 클레임의 `inbox_id`를 다시 읽어 `existing`으로 돌려줌(앞 거래가 커밋된 뒤라 보임; 앞 거래가 되돌려졌으면 1번이 성공함).
  3. 넣었으면 `public.work_inbox` insert → 클레임 `inbox_id` 갱신 → `added`. 어느 단계든 오류면 함수 전체가 되돌려져 클레임·업무 둘 다 남지 않음.

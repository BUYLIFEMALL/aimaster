## 2. 용어 표 (바꿀 이름)

| 지금 | 바꿀 이름 | 이유 |
|---|---|---|
| 제품 이름 Workspace (문장 안) | **업무 워크스페이스** | 프로그램 이름 「AI 업무 워크스페이스 자동화」의 짧은 이름. 「워크스페이스」 단독(일반 명사, 예: 워크스페이스 멤버)은 그대로 둠 |
| 탭 제목 「○○ \| Workspace」, 기본 탭 제목 | **「○○ \| AI 업무 워크스페이스」**, 기본 「AI 업무 워크스페이스」 | 다른 AIMaster 프로그램처럼 프로그램 이름이 보이게 |
| AI 이름 AIMaster | **AI 비서** | 플랫폼 이름과 구분, 기능이 바로 보임 |
| 받은편지함(알림) | **알림함** | 실제 기능(알림 모음)대로. 「업무 받은편지함」 이름은 U7용으로 비워 둠 |
| 회의 | **AI 회의록** | 메뉴 안 기능 이름(`lp.shell.ai_meeting_notes`)과 맞춤 |
| 라이브러리 | **보관함** | AIMaster 다른 프로그램의 「보관함」과 같은 말 |
| 비공개(좌측 묶음) | **내 페이지** | 나만 보는 페이지 묶음이라는 뜻이 바로 보이게 |
| 최근 항목 | **최근 본 페이지** | 무엇이 모이는지 바로 보이게 |
| 팀(좌측 묶음 이름) | **팀 공간** | 협업 단계 전까지는 표시만 바꿈 |
| 템플릿 만든 사람 Workspace | **AIMaster** | 템플릿 제공자 표기(플랫폼 이름이 맞는 자리) |
| 시작 페이지 「Workspace에 오신 것을 환영합니다」 | 「AI 업무 워크스페이스에 오신 것을 환영합니다」 | 새 회원부터 적용 |

- 요금제 문구(「Business로 업그레이드」, 「Business 요금제」, 예시 회사 이름 「Acme Inc.」 등)는 이 프로그램에 해당 요금제가 없으므로 **U2에서 문구가 붙은 화면째 숨긴다**(U1에서는 건드리지 않음).
- 뺄 기능(공개 사이트·MCP·개발자 API 등) 화면의 문구도 U1에서 이름만 바꾸고, 화면 숨김은 U2에서 한다.
- 영어 기본 문구(번역 파일에 없을 때 쓰는 코드 안 영어)는 이번에 고치지 않는다. 화면 언어 기본값이 한국어라 번역 파일이 우선한다.

## 3. 구현 순서

1. 바꾸기 스크립트(작업용, 저장소 밖 스크래치 폴더)로 번역 파일의 **값만** 바꾼다(키 이름은 그대로).
   - 「Workspace」 → 「업무 워크스페이스」, 「AIMaster」 → 「AI 비서」 (조사 「가·를·는·와·로」는 둘 다 받침 없는 말이라 그대로 맞음)
   - 메뉴 키 6개(`lp.shell.inbox`·`meetings`·`library`·`private`·`recents`, 좌측 팀 묶음 제목 키)는 키를 지정해 개별로 바꿈
2. 코드에 박힌 문구 4곳: `documentTitle.ts`, `LoginPage.tsx` 탭 제목, `export.ts` 대체 이름, `catalog.ts` `creator`, `koreanSeed.ts` 시작 문구. 바꾼 줄에 「이식판:」 주석.
3. 확인: 번역 파일에 「Workspace」·「AIMaster」가 남지 않았는지 검색(MCP 연결 신호 `clientInfo` 같은 화면에 안 보이는 기술 값은 제외).

## 6. agy 디자인 작업(U5)과의 순서

- 같은 폴더를 두 CLI가 동시에 고치지 않는 규칙 때문에, **agy의 디자인 작업은 이 세션의 U1~U4가 끝나고 `docs/ACTIVE_WORK.md`에서 이 세션 줄이 빠진 뒤 시작**하는 것을 권한다. 디자인을 먼저 하려면 이 세션이 그동안 멈춘다.
- U1에서 바꾼 용어 표(§2)는 디자인 작업에서도 그대로 쓰도록 이 문서를 agy 인계 자료로 넘긴다.

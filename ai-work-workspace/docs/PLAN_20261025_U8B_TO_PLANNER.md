## 1. 목표
워크스페이스의 회의록·업무 페이지에 적은 할 일을 버튼 하나로 할 일 플래너에 넣습니다. 이렇게 되면 로드맵의 「업무 보드 ↔ 오늘 할 일」 양방향이 완성됩니다.
- 프로그램끼리 서로의 API를 부르지 않는 규칙은 그대로 지킵니다.
- U7 공용 표 `public.work_inbox` 하나를 「받는 곳」 열로 나눠 양쪽이 같이 씁니다. 나중에 다른 프로그램도 받는 쪽이 될 수 있습니다.

## 2. 공용 DB 변경 (승인 필요)
```sql
alter table public.work_inbox
  add column if not exists target_slug text not null default 'ai-work-workspace'
  check (target_slug ~ '^[a-z0-9-]{2,60}$');
create index if not exists work_inbox_user_target_created
  on public.work_inbox (user_id, target_slug, created_at desc);
```
- 지금 있는 줄과 지금 돌아가는 코드는 기본값(`ai-work-workspace`) 덕분에 그대로 동작합니다. 깨지는 것은 없습니다.
- 보안 규칙(RLS, 회원 본인 줄만)과 30일 자동 삭제는 바꾸지 않습니다. 플래너로 가는 줄도 같은 30일 정리 대상입니다.
- 파일: `ai-work-workspace/supabase/migrations/20261025000100_work_inbox_target.sql`

## 3. 공용 기준 코드 (`work-inbox-client`)
- `sendToWorkInbox()`에 받는 곳 `targetSlug`를 선택값으로 추가합니다. 기본값은 `ai-work-workspace`입니다.
- 기준은 워크스페이스 파일이고, 할 일 플래너 사본은 동기화 명령으로 맞춥니다(`--sync`).

## 4. 워크스페이스 (v1.19, 빌드 1회)
1. **보내기**: 페이지 상단 「⋯」 메뉴에 「📨 할 일 플래너로 보내기」를 추가하고, 하위 메뉴 두 개를 둡니다.
   - **「체크 안 된 할 일 N개 보내기」**: 페이지 안의 체크 상자 항목 중 체크하지 않은 것(최대 30개)을 하나씩 할 일로 보냅니다. 회의록의 실행 항목을 옮길 때 씁니다.
   - **「이 페이지를 할 일 하나로」**: 제목을 할 일 제목으로 씁니다. 표 행 페이지라면 날짜 속성(마감일·예정일 등 첫 날짜)과 우선순위(높음·보통·낮음)를 함께 보냅니다.
   - 서버 명령은 `workInboxSendToPlanner`입니다. 회원 본인 워크스페이스의 페이지만 읽고, 내용은 서버가 만듭니다.
2. **받은 업무 목록**: 받는 곳이 워크스페이스인 줄만 보이게 거릅니다. 플래너로 보낸 항목은 워크스페이스 목록에 나오지 않습니다.
3. **함께 나가는 수정**
   - 미배포 `c6d4ca3ba`: 표의 「받은 날」을 한국 날짜로 넣습니다. 운영에서 하루 전으로 들어가는 문제가 재현됐습니다.
   - 표 행의 「OPEN」 영어 문구를 한국어로 바꿉니다.
4. **매뉴얼**: 「받은 업무」 구역에 「할 일 플래너로 보내기」 카드를 추가합니다.

## 5. 할 일 플래너 (v1.12, 빌드 1회)
1. **받기**: 대시보드 할 일 목록 위에 **「📥 받은 할 일 N개」** 칸을 둡니다. 받은 항목이 있을 때만 보입니다.
   - 항목마다 제목, 보낸 곳, 예정일이 보이고 「➕ 할 일로 추가」와 「버리기」 버튼이 있습니다.
2. **추가할 때 들어가는 값**
   - 예정일: 받은 날짜가 올바르면 그 날짜, 아니면 화면에서 고른 날짜
   - 우선순위: 받은 값이 있으면 그 값, 없으면 보통
   - 분류: 기본 분류
   - 예상 시간: 0(미설정)
3. **두 번 추가 막기**: 서버가 먼저 그 줄에 「가져감」 표시를 하고(아직 안 가져간 줄만), 그다음 할 일을 추가합니다. 추가에 실패하면 표시를 되돌립니다. 버튼을 두 번 눌러도 하나만 들어갑니다.
4. **API**: `GET /api/work-inbox/received`(목록), `POST`(추가·버리기). 출처 확인과 `authorizePlanner()`를 거치고, 언제나 `user_id` 조건을 붙입니다.
5. **매뉴얼**: 「업무 워크스페이스로 보내기」 구역에 「워크스페이스에서 받기」 카드를 추가합니다.

## 6. 시험
- 단위 시험
  - 워크스페이스: 체크 안 된 할 일 뽑기(중첩 항목, 30개 제한, 체크한 항목 제외), 날짜·우선순위 속성 읽기
  - 플래너: 받은 값을 할 일 입력으로 바꾸기(잘못된 날짜·우선순위 처리), 두 번 추가 막기
- 기존 시험: 워크스페이스 연결부 39개, 플래너 단위 26개·브라우저 30개, 두 프로그램 로컬 빌드
- 크롬(시험 계정, 보이는 창)
  1. 워크스페이스에 체크 상자 3개(1개 체크) 페이지를 만들고 「체크 안 된 할 일 2개 보내기」를 누릅니다.
  2. 워크스페이스 받은 업무에 나오지 않는지 확인합니다.
  3. 플래너 「받은 할 일 2개」에서 「추가」·「버리기」를 누르고 목록을 확인합니다.
  4. 시험 항목은 SQL로 정리합니다.

## 7. 순서
1. 승인 → 작업 중 표 등록 → 운영 DB SQL 적용(크롬 SQL 편집기) → 마이그레이션 파일
2. 기준 코드 `targetSlug` → 워크스페이스 목록 거르기·보내기 명령·메뉴 → 시험·빌드 → 버전 v1.19 → **배포 1**
3. 플래너 사본 동기화·받기 API·받은 할 일 칸 → 시험·빌드 → 버전 v1.12 → **배포 2**(앞 배포 Ready 확인 뒤)
4. 크롬 확인 → 문서(두 프로그램 인수인계, `docs/WORK_INBOX.md` 받는 곳 표, 공용 모듈, 프로그램 비교표, 역할 파일, HANDOFF, 요청함)

# 관리자 중간 지시·일괄 요청 예시

**아래 지시·로그·상태는 모두 설계용 예시이며, 실제 실행·검증 결과가 아닙니다.**

## 1. 관리자 지시 입력

> SNS 로그인을 최우선으로 진행하세요. 디자인은 주황색을 유지하고, 쇼핑몰은 그다음에 진행하세요.

Master는 이를 `CMD-021`로 접수합니다. 우선순위 변경은 기존 작업의 삭제나 운영 배포 허가로 해석하지 않습니다. 이미 진행 중인 작업은 안전한 체크포인트에서 전환하며, 충돌 없는 주황색 디자인 작업은 병행합니다.

## 2. 터미널 표시 예시

```text
[T+00] RECEIVED CMD-021 | SNS 로그인 우선 / 주황 유지 / 쇼핑몰 후순위
[T+01] IMPACT | SNS 인증 의존성 확인 필요, 쇼핑몰 신규 배정 보류
[T+02] PLAN | r7 → r8 / 변경 사유 CMD-021 / 기존 이력 보존
[T+03] ASSIGN | Claude-SNS: 인증 구현 / AGY: 주황 테마 유지
[T+04] ASSIGN | Codex-QA: 인증 인수조건·회귀검사 준비
[T+05] REQUEUE | 쇼핑몰 미착수 작업을 후순위로 이동
[T+06] HUMAN | H-101~103 준비 중 / 독립 구현·모의검사 계속
```

각 로그에는 사건 ID·작업 ID·시각·증거 경로를 연결합니다. 위와 같은 접수 로그만으로 실제 재배정·검증 완료를 주장하지 않습니다. 명령 전송, 작업자 수신 확인, 실제 상태 변화는 별도 사건으로 기록합니다.

## 3. 관리자 일괄 요청 예시

| ID·종류 | 필요한 답변·행동 | 준비할 자료 |
|---|---|---|
| H-101 · DECISION | 로그인 방식 A: 구글 우선 / B: 이메일 우선. 추천 A | 구현 범위·의존성·후속 일정 |
| H-102 · AUTHORIZATION | 지정 테스트 계정에 인증 이메일 1회 발송 허가 | 수신자·본문·비용·환경·실행 시점 |
| H-103 · MANUAL_ACTION | 관리자 계정 로그인과 필요한 동의 화면 처리 | 접속 위치·선택할 계정·완료 확인 절차 |

답변 예: `H-101=A / H-102=제시한 범위 승인 / H-103=작업 완료`

H-101은 제품 결정이며 외부 발송 허가가 아닙니다. H-102는 검토 가능한 수신자와 본문이 준비된 경우에 요청합니다. 비밀번호·OTP·API 키 원문은 채팅이나 이력에 적지 않습니다.

## 4. 직접 작업 완료 확인

“로그인해도 됩니다”는 허가이고, “로그인했습니다”는 완료 보고입니다. Master는 허가만으로 완료 처리하지 않으며, 완료 보고 뒤에도 인증 상태·필요 권한을 확인합니다. 확인 수단이 없으면 “관리자 완료 보고, 검증 대기”로 남깁니다.

## 5. 이력과 단일 기록자

공식 계획·작업 상태·결정 목록은 Master가 판단하고 단일 Controller가 기록합니다. 역할자는 독립된 결과·요청 사건을 제출합니다. 기존 이력은 덮어쓰지 않고 정정 사건으로 연결합니다.

필수 필드: `event_id, timestamp, command_id, actor, task_id, before, after, reason, evidence, approval_id, approval_scope, supersedes`.

중간 지시로 승인 대상·수신자·비용·환경이 범위를 벗어나면 관련 실행만 보류하고 새 요청 버전을 만듭니다. 사전 승인 범위 안의 보완은 재질문하지 않습니다.

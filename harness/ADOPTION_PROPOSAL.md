# AIMaster 하네스 도입 검토안

상태는 운영 적용 전이다. 기준 문서는 루트 AI_TEAM_RULES.md, .ai/TEAM.md, .ai/TRANSPORT.md, .ai/FILE_OWNERSHIP.md와 총괄 개발 플랜이다. package/는 제공받은 프롬프트와 검수 시나리오의 참고 사본이다.

## 배정부터 인수인계까지

1. Master는 기존 개발 플랜에서 우선순위, 선행 작업, 점유 경로, 세션의 현재 수락 건과 장비를 확인한다. 이미 진행 중인 일은 현재 담당자와 작업 번호를 이어 쓴다.
2. 배정에는 작업 번호, 배정 회차, 담당 역할과 실제 터미널, 변경 가능 경로, 기준 커밋, 완료 기준, 검수 담당을 담는다. 다른 회원 자료나 키가 들어간 원문 로그는 전달하지 않는다.
3. 발송, 전달 확인, 담당자 수락을 따로 기록한다. 발송 결과가 불명확하면 기존 터미널과 발송 기록을 확인한다. 같은 메시지나 이전 회차 회신이 도착하면 현재 배정을 덮어쓰지 않는다.
4. 담당자는 결과 커밋, 통과·실패한 시험, 미확인 범위를 제출한다. Master는 다음 독립 작업이 준비됐으면 구현 담당에게 넘기고, 제출판의 검수는 지정 검수자가 병행한다. 같은 파일의 후속 변경은 점유와 검수 기준 커밋을 다시 대조한다.
5. 검수 실패는 재현 근거와 함께 원 담당자에게 돌린다. 통합 뒤 변경이 생기면 영향받은 검수를 최종 커밋에서 다시 한다. 공식 완료는 Master가 기록한다.
6. 로그인·실기기·승인 대기는 해당 작업에 표시한다. 다른 담당의 준비된 일은 계속 배정한다. 사람에게 필요한 결정은 Master가 묶어 올리고, 긴급 중지 지시는 우선 처리한다. 할 일이 소진되면 감시 상태로 전환한다.

## 역할과 권한

| 대상 | 적용 기준 |
|---|---|
| Master | 기존 지휘표와 Orca 수신함에서 우선순위·실제 배정·검수·인수인계·완료를 연결한다. |
| 제품 담당 및 AGY | Workspace, B2B 앞단·뒷단, 전자상거래, 영상, 음악, 부동산, 블로그, SNS, 디자인의 기존 담당과 점유를 따른다. 설계·분석은 필요한 작업에 붙이는 역할이다. |
| MacMini Tester | macOS·Windows 프로그램의 일반 검수·재현·디버깅·개선 제안을 맡는다. Windows 전용 실행은 메인 Windows 담당과 조율해 결과를 합친다. |
| AdminPC Tester | 고사양 로컬 모델 실측과 그 시험에 딸린 디버깅만 맡는다. |
| Support | 사용자 직접 지시와 키트 전담을 유지한다. 일반 대기열 배정 대상에서 제외한다. |

저작권 고지·검색 허용, 비공개 자료와 회원 키 격리, 공유 폴더 점유, 경로별 커밋, 빌드·배포 순번과 기존 비용·운영 쓰기 승인 범위를 따른다. 첨부 패키지의 예시 역할과 기본 지침으로 루트 지침을 덮어쓰지 않는다.

## 도입 순서와 판정

| 단계 | 실행 | 다음 단계로 넘어갈 근거 |
|---|---|---|
| 격리 시험 | 모의 세션과 임시 저장소에서 package/harness/SCENARIO_ACCEPTANCE.md의 16개 상황을 검증한다. | 각 상황의 예상·관측 결과를 기록한다. 중복 발송, 오래된 결과 통합, 재시작 후 작업 분실, 중지 뒤 신규 배정이 없어야 한다. |
| 읽기 병행 | 현재 지휘표와 실제 Orca 결과로 다음 배정을 계산하고 Master의 실제 결정과 비교한다. | 오배정·권한 충돌·누락을 설명하고 수정한다. 현재 수락 건의 담당과 상태가 일치해야 한다. |
| 한 건 시범 | 제품 담당 1곳과 MacMini 검수자에게 기존 플랜의 독립 가능한 한 건을 연결한다. | 결과 제출부터 독립 검수·Master 판정·다음 일의 실제 수락까지 대조한다. |
| 역할별 확대 | 시범을 통과한 흐름을 검증된 기존 터미널부터 확대한다. 이벤트 도착 때 처리하고 기존 30분 점검은 누락 복구에 쓴다. | 준비부터 수락까지의 시간, 검수 대기, 재작업, 중복 배정, 사람 결정 대기를 비교한다. |

중지하거나 판정이 맞지 않으면 하네스의 신규 발송을 멈춘다. 이미 전달된 작업 번호·수락·결과는 원래 지휘표에 남겨 기존 Master 운영으로 이어간다. 추가 세션은 같은 역할에 독립 가능한 준비 작업이 반복해서 쌓이고 장비·권한·점유 문제가 아닌 경우에만 Master가 근거와 함께 제안한다.

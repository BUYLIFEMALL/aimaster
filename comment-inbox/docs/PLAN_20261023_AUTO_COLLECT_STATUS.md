## 1. 문제
1. 설정 「⏱ 예약 모니터링」에 **마지막 확인 시각만** 보여, 12시간 주기 회원은 다음에 언제 도는지 알 수 없다.
2. 「⏱ 예약 모니터링」과 「⏰ 예약 실행 방식」이 떨어져 있어, 처음 쓰는 회원이 실행 방식 칸을 못 보고 지나칠 수 있다(지금 바로가기 링크는 키 없음·Vercel 꺼짐 상태에서만 보임).
3. 세 댓글 앱의 자동 수집이 켜져 있는지 보려면 앱마다 설정 화면에 들어가야 한다.

## 2. 바꿀 것
1. **다음 확인 예정**(세 앱 `components/settings/MonitoringSettingsForm.tsx`): 모니터링이 켜져 있으면 「다음 확인 예정 약 ○월 ○일 ○○:○○」(`last_run_at` + 주기). 아직 한 번도 안 돌았으면 「곧(5분 안)」. 예약 호출이 5분마다 깨우므로 「약」으로 표시. 판단 기준은 기존 `lib/schedule.ts` `isMonitoringDue`와 같은 계산.
2. **실행 방식 바로가기**(세 앱 `components/settings/SchedulePublishingControl.tsx`): 상태 줄 아래에 늘 「실행 방식 바꾸기 ↓」 링크(`#scheduler-mode`). 기존 키 없음·Vercel 꺼짐 안내 링크는 그대로.
3. **통합 받은편지함 「🤖 자동 수집 상태」 카드**(`comment-inbox`): 이용 권한이 있는 앱만, 앱마다 켜짐/꺼짐·확인 주기·마지막 확인·다음 예정, 「설정 열기 ↗」(그 앱 `/settings#scheduler-mode`, 새 창). 서버에서 관리자 클라이언트로 **회원 본인 `user_id` 행만** 읽음(`ig_settings`·`th_settings`·`ytreply_settings`, 기존 받은편지함 읽기 방식과 같음). 쓰기 없음.

## 3. 바꾸지 않는 것
- 자동 수집 동작·예약 주기·DB 구조. 다른 앱의 설정을 받은편지함에서 바꾸지 않는다(보기만).

## 4. 검수
- 네 앱 `tsc`·로컬 build. 받은편지함은 배포하면 크롬에서 카드 표시 확인(관리자: 인스타 켜짐 12시간 · 쓰레드·유튜브 상태).
- 계산 확인: 마지막 확인 12:10 + 12시간 → 「약 10월 24일 00:10」.

## 5. 버전·배포·비용
- 작은 화면 수정이라 지침대로 **미배포 대기**로 모았다가 각 앱 다음 배포 때 함께 내보낸다(버전도 그때 +0.01). 비용 없음.

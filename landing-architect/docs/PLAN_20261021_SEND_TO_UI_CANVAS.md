# 개발 플랜 — 「🧩 UI Canvas로 보내 다듬기」 (2026-10-21, Claude Code 윈도우)

주인님 지시: 병합 D 후속 3번(보고서 §3 제안). 대상: `landing-architect` v1.10 → v1.11. UI Canvas 코드는 바꾸지 않음.

## 해결
| 항목 | 내용 |
|---|---|
| 버튼 | 기획안 결과 영역에 [🧩 UI Canvas로 보내 다듬기] |
| 변환 | AI 없이 규칙으로(비용 0): 헤드라인 → 큰 글자, 서브 헤드라인 → 설명, CTA → 버튼, 메인 페이지 섹션마다 상자 + 제목 + 설명, 색은 디자인 시스템 색. 캔버스 1440 폭, 높이는 섹션 수에 맞춤(최대 4000) |
| 저장 | 새 API `POST /api/canvas-export` — 이 프로그램 권한 확인 + **UI Canvas 이용 권한 확인** + 프로젝트 100개 한도 → 공용 DB 표 `ui_canvas_projects`에 회원 본인 `user_id`로 새 프로젝트 1개(서비스 롤, 쓰기는 본인 행 추가만). 프로그램끼리 서로 호출하지 않음 |
| 열기 | 응답 주소 `https://ui-canvas.buylife.xyz/editor/<id>`를 새 창으로 |
| 검수 | `tsc`·빌드·배포 → 크롬(일반 회원): 기존 기획안 프로젝트에서 보내기 → UI Canvas 편집기에 컴포넌트 배치 확인 → 시험 프로젝트 삭제 |
| 비용 | Vercel 빌드 1회, AI 0회 |

## 후속(2026-10-21, v1.12) — 서브 페이지 함께 보내기 + 이미지 에셋 배치
| 항목 | 내용 |
|---|---|
| 서브 페이지 | UI Canvas 프로젝트는 캔버스 1장(높이 최대 4000)이라 서브 페이지마다 **별도 프로젝트**(「… (랜딩 기획) 서브: 제목」). 내용: 페이지 제목·경로·목적·콘텐츠 명세. 목적·명세가 둘 다 빈 서브 페이지는 건너뜀. 100개 한도는 만들 개수 기준으로 확인, 메인 프로젝트를 새 창으로 연다 |
| 이미지 | `imageAssets` 첫 번째 → 히어로 오른쪽, 나머지 → 섹션마다 오른쪽 이미지 컴포넌트. 주소는 키 없는 무료 임시 사진 `picsum.photos/seed/<키워드>`(기존 프로토타입과 같은 방식), 컴포넌트 설명에 이미지 설명을 남겨 바꿔 넣기 쉽게 |
| 비용 | AI 0회, Vercel 빌드 1회(두 건을 한 번에) |

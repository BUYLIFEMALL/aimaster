쓰레드(Threads) 공개 글 검색 권한 받기 — Meta 비즈니스 앱 승인 절차

※ 이 문서의 <복제본-주소>는 복제한 프로그램의 실제 주소(예: my-tap.vercel.app)로 바꿔 읽으세요.

💡 쇼핑제휴 자동화의 [트렌드 & 떡상 탐지기]에서 다른 사람이 올린 공개 글까지 검색하려면, 내 Meta 앱이 threads_keyword_search 권한의 고급 액세스 승인을 받아야 합니다. 이 매뉴얼은 그 승인을 받는 전체 과정을 순서대로 설명합니다. (2026-09-29 작성)

⚠️ 시작 전에 꼭 알아두세요

  • 사업자등록증이 필요합니다. Meta가 비즈니스 인증을 요구하기 때문에 개인(사업자 없음)은 승인을 받을 수 없습니다.
  • 전체 과정은 보통 수일~수주 걸립니다(인증·검수 대기 포함).
  • 중간에 "테크 제공업체" 등록이 나오는데, 한 번 등록하면 되돌릴 수 없습니다. 매년 Meta의 데이터 사용 점검에 응해야 하는 의무가 생깁니다.
  • 승인 전에도 [🔗 떡상글 직접 가져오기]로 다른 사람의 인기 글을 붙여넣어 똑같이 벤치마킹할 수 있습니다. 급하지 않다면 이 방법만으로도 충분합니다.

0단계: 준비물 체크

  • 사업자등록증 (사진 또는 PDF, 글자가 선명하게)
  • 사업자등록증과 똑같은 상호·주소·대표 전화번호
  • 회사 웹사이트 주소 (하단에 상호·사업자번호·주소가 보이면 인증에 유리합니다)
  • 앱 아이콘 이미지 (정사각형, 512~1024px, 5MB 이하)
  • 이미 연동된 Meta 앱 (없다면 먼저 "쓰레드(Threads) 계정 연동하기" 매뉴얼로 앱을 만들고 연결하세요)

1단계: 앱 기본 설정 채우기

  1. Meta 개발자 센터 → 내 앱 선택 → 왼쪽 [앱 설정] → [기본 설정]
  2. 아래 칸을 채우고 맨 아래 [변경 내용 저장]을 누릅니다.

    개인정보처리방침 URL: https://<복제본-주소>/legal/privacy

    서비스 약관 URL: https://<복제본-주소>/legal/terms

    사용자 데이터 삭제: "데이터 삭제 안내 URL" 선택 → https://<복제본-주소>/legal/data-deletion

    앱 도메인: <복제본-주소> 추가

    카테고리: 비즈니스 및 페이지 · 앱 아이콘: 업로드

  3. URL은 반드시 https://까지 전체 주소로 넣으세요. 페이스북 기본 주소(facebook.com)가 들어가 있으면 반려됩니다.

2단계: Threads 설정에 콜백 주소 3개 넣기

  1. 왼쪽 [이용 사례] → [Threads API 액세스] → [설정]
  2. 세 칸에 아래 주소를 넣고 [저장]합니다.

    리디렉션 콜백 URL: https://<복제본-주소>/api/threads/callback

    제거 콜백 URL: https://<복제본-주소>/api/threads/uninstall

    삭제 콜백 URL: https://<복제본-주소>/api/threads/delete

  3. 제거·삭제 주소는 회원이 앱 권한을 지우거나 데이터 삭제를 요청할 때 연결 정보를 자동으로 정리해 주는 곳입니다. Meta 심사에서 필수로 확인합니다.

3단계: 검색 권한 추가 + 한 번 써보기

  1. [이용 사례] → [Threads API 액세스] → [권한 및 기능]에서 threads_keyword_search 옆 [추가]를 누릅니다.
  2. 쇼핑제휴 자동화 [트렌드 & 떡상 탐지기] 맨 위 안내 박스의 [🔑 검색 권한 포함해서 Threads 연결]을 눌러 승인합니다.
  3. 아무 키워드로 한 번 검색합니다. Meta는 심사 전에 이 권한으로 실제 호출한 기록이 있어야 신청을 받아줍니다. (권한 목록의 "API 호출" 숫자가 1 이상이면 준비 완료)

4단계: 앱 검수에 추가 → 테크 제공업체 등록

  1. threads_keyword_search 줄의 [옵션 ▼] → [앱 검수에 추가]를 누릅니다.
  2. "테크 제공업체가 되어야 합니다" 창이 뜨면 내용을 읽고 [Continue]를 누릅니다. (되돌릴 수 없음)
  3. 다른 권한은 앱 검수에 추가하지 마세요. 쓰지 않는 권한을 함께 올리면 반려 사유가 됩니다. (threads_basic이 필요하다고 나오는 경우에만 함께 추가)
  4. 권한 이름 아래 [요구 사항]을 누르면 남은 단계(비즈니스 인증·액세스 인증·데이터 처리 질문·앱 검수)를 볼 수 있습니다.

5단계: 비즈니스 인증 (가장 오래 걸림)

  1. 왼쪽 [검수] → [인증] 또는 business.facebook.com → 설정 → 보안 센터
  2. 법적 상호는 사업자등록증의 상호와 글자까지 똑같이 입력합니다. (예: 도메인 이름이 아니라 등록증상의 상호)
  3. 주소·전화번호·웹사이트도 등록증 및 웹사이트 하단 정보와 똑같이 맞추고, 사업자등록증을 업로드합니다.
  4. 전화·문자·이메일 확인 절차가 나오면 진행합니다. 결과는 보통 며칠 걸립니다.
  5. "승인되지 않음"이 뜨면 보안 센터에서 거절 사유를 확인하고, 정보를 고친 뒤 [다시 제출]을 누릅니다.

6단계: 액세스 인증

  1. 비즈니스 인증이 끝나면 [검수] → [인증]의 액세스 인증 [인증 시작]이 열립니다.
  2. 안내에 따라 우리 서비스가 어떤 데이터를 어떻게 쓰는지 답하고 제출합니다. 보통 5일 이내에 연락이 옵니다.

7단계: 데이터 처리 질문 답하기

데이터에 접근하는 처리자·서비스 제공업체가 있나요? → 예: Supabase(데이터베이스), Vercel(서버 호스팅)

데이터 책임 주체는? → 사업자등록증상의 상호

지난 12개월간 국가안보 목적으로 공공기관에 데이터를 제공했나요? → 아니요

그런 요청에 대한 정책이 있나요? → "적법성 검토", "필요 최소한만 제공", "요청 문서화" 선택

8단계: 앱 검수 제출

  1. 왼쪽 [검수] → [앱 검수]에서 threads_keyword_search 요청서를 엽니다.
  2. 사용 방법 설명(영문) 칸에 아래 문장을 붙여넣습니다.
    Our app helps a Threads creator plan posts for products they promote. On the "Trends" page, the signed-in user types a keyword and we call the Threads keyword search endpoint with the user's own access token to show recent and top public posts about that topic. Each result shows the post text, author username, time and a link to the original post on Threads. The user can bookmark a post as a reference and then write their own new post with AI assistance, referencing the style of the saved post. We do not republish or modify other people's posts and do not store engagement metrics. Search results are shown only to the user who searched and are never shared, sold, or used for advertising. Saved references and the access token are deleted when the user disconnects, removes the app, or requests data deletion (https://<복제본-주소>/legal/data-deletion).
  3. 테스트 방법 안내: 심사관이 로그인해서 따라 할 수 있게 아래 순서를 영문으로 적고, 맨 아래에 테스트용 계정 이메일·비밀번호를 적습니다. (테스트 계정에 프로그램 이용 권한이 필요하면 운영자에게 요청하세요)
    1. Sign in at https://<복제본-주소>/login with the test account below. 2. Open "API키등록·플랫폼연동" (Settings) and connect a Threads account. 3. Open "트렌드 & 떡상 탐지기" (Trends), type a keyword such as "travel" and press "검색" (Search). 4. Results labeled "실제 Threads 글" come from the keyword search endpoint; click "Threads에서 원문·반응 보기" to open the original post.
  4. 시연 영상(1~2분)을 녹화해 올립니다: 로그인 → Threads 연결(권한 동의 화면) → 트렌드에서 검색 → 결과의 원문 링크 열기 → 찜 → AI 캡션 생성 → 설정에서 연결 해제. 영어 자막을 넣으면 통과에 유리합니다.
  5. [제출]을 누릅니다.

9단계: 승인 후

  1. 승인 알림이 오면 앱을 게시(라이브) 상태로 둡니다.
  2. 트렌드 화면에서 검색하면 다른 사용자의 공개 글이 "실제 Threads 글"로 나오고, 안내 박스의 상태가 "✅ 다른 사람의 공개 글 검색 가능"으로 바뀝니다. 해시태그·미디어·작성자 필터도 쓸 수 있습니다.
  3. 반려되면 반려 사유를 읽고 지적된 부분(설명·영상·URL 등)만 고쳐서 다시 제출하면 됩니다.

💡 자주 막히는 곳

  • "앱 ID가 전송되지 않았습니다"(4476002): 설정에 맨 위 앱 ID가 아니라 기본 설정 하단의 Threads 앱 ID를 넣어야 합니다.
  • "An unknown error occurred"로 검색 실패: threads_keyword_search를 추가한 뒤 검색 권한 포함 재연결을 하지 않은 경우입니다.
  • 비즈니스 인증 반려: 대부분 상호·주소가 등록증과 다르거나 서류가 흐린 경우입니다.
  • 화면을 캡처해 공유할 때: 앱 시크릿 코드가 보이지 않게 가려주세요.

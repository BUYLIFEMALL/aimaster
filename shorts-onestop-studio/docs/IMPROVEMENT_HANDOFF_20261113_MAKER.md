## 1. 결론

1. 새 숏폼 생성기를 만들지 않는다. **원스톱 V3 상품 홍보 쇼츠(v1.44 배포)**가 받는 쪽이다. 다른 영상기(`shots`, `ai-video-studio`)에 같은 받기를 또 만들지 않는다.
2. 지금 원스톱이 받을 수 있는 것은 **글자 4가지(상품명·장점 3개·혜택·보낸 곳)뿐**이다. 상품 사진·상품ID·옵션·상품주소·확정 설명·권리 표시는 **받지 못한다**.
3. 메이커 가공 결과의 기본은 「브라우저 처리 → ZIP」(회원 PC)이므로, 가장 먼저 필요한 것은 **원스톱 배경에 「상품 사진」 출처를 추가하고 회원이 사진 파일을 직접 올리는 경로**다. 서버 저장(자료함 `sourceRef`) 받기는 기능 담당(sdp)의 P2 반환 계약이 정해진 뒤 2단계로 붙인다.
4. **보내는 쪽 버튼은 아직 어디에도 없다**(이커머스 폴더 검색 결과 0건). 보내는 버튼은 sdp·이커머스 담당 몫이다.

## 3. 최소 입력 계약(추가 필드)

기존 4개(`product-name`·`product-point`·`product-offer`·`product-from`)는 **그대로 유지**(하위 호환). 아래만 추가한다. 주소 `#` 뒤라 서버 기록에 남지 않는다.

| 넘기기 이름 | 뜻 | 제한 | 쓰는 곳 |
|---|---|---|---|
| `product-id` | 내부 상품 ID(sdp 계약의 내부상품ID) | 64자, 영문·숫자·`-_` | 대본 기록에 저장 → 같은 상품 재제작·결과 반환 연결 |
| `product-option` | 옵션 표시명 1개 | 60자 | 대본·자막(옵션별 영상일 때) |
| `product-url` | 판매 상품 주소 | https만, 300자 | 유튜브 설명란·아웃트로 구매 안내(AI에는 안 보냄) |
| `product-desc` | 판매자가 **확정한** 설명 | 300자 | 대본의 사실 근거(장점과 같은 「적은 것만 사실」 규칙) |
| `product-image` | 상품 사진(최대 6) | 2단계: 자료함 `sourceRef`만(임의 외부 주소 안 받음) | 「상품 사진」 배경 |
| `product-rights` | 사진 권리 | `owned`(내 사진)·`supplier`(공급사 허용) 중 하나 — **없으면 사진은 받지 않음** | 받기 판정 |
| `product-rev` | 사진·설정 판번호 | 32자 | 묵은 사진으로 만든 영상 구분 |

넘기지 않는 것: 도매가·원가·재고·주문·고객 정보·비밀 키(기존 원칙 그대로). 확정 설명은 한글 300자면 주소가 약 2,700자로 길어지므로 로그인 보관(`sessionStorage`)도 그대로 동작하는지 시험한다.

## 4. 제품 외형·색상·문구 보존

| 위험 | 지키는 방법 | 검수 |
|---|---|---|
| AI가 상품을 다시 그림 | 「상품 사진」 장면에는 **AI 이미지 생성을 쓰지 않는다**(사진 원본을 그대로 깐다). 상품이 아닌 장면만 스톡·AI | 렌더 결과 프레임에서 상품 장면이 원본 사진인지 눈 확인 |
| AI 영상이 형태·색·로고를 바꿈 | 상품 장면 기본 움직임은 **무료 확대·이동(켄 번즈)**. AI 영상은 회원이 켤 때만, 켜면 「형태가 바뀔 수 있음」 경고 + 짧은 길이 + 카메라만 움직이는 지시 | 첫·가운데·끝 프레임을 원본과 나란히 놓고 사람 눈 확인(필수) |
| 9:16에 맞추며 상품이 잘림 | 상품 사진은 **잘라내지 않고 전체를 담기(contain)** + 같은 사진 흐림 배경 | 정사각·가로 사진 각 1장 렌더 확인 |
| 색이 바뀜 | 색 보정·필터를 상품 장면에 적용하지 않음 | 원본과 렌더 프레임 평균 색 차이 측정(로컬·무료) |
| 상품명·옵션 문구가 AI에 의해 바뀜 | 상품명·옵션·혜택은 아웃트로 카드에 **원문 그대로 자막 고정**, 대본 규칙에 「상품명 원문 그대로」 | 자동 시험: 생성 대본·자막에 상품명 원문 포함 확인 |

## 5. 파일 보관

- 회원이 올린 상품 사진: 원스톱 비공개 버킷 `shorts-onestop-studio/<회원번호>/product/…`. 기존 30일 정리·`retention_exempt` 제외·서명 주소가 **코드 수정 없이** 그대로 적용된다(같은 버킷·같은 회원 폴더).
- 용량: 저장 전 `member_storage_policy` 사전 검사 방식은 **정책 담당(policy) 판정 대기**. 지금 원스톱의 300장 한도는 유지.
- 자료함 `sourceRef`로 받은 사진(2단계): 원스톱으로 **복사하지 않고 참조**하는 안을 기본으로 제안(용량 이중 계산 방지). 렌더 직전에 다시 서명하고, 원본이 보관 기간이 지나 지워졌으면 「원본 사진이 지워졌습니다 — 다시 올려 주세요」로 안내. 복사·참조 최종 결정은 policy 담당.
- 유튜브에 올린 뒤 발행 표시(`markPosted`) 연결 여부는 policy 담당과 맞춘다(일반 회원은 발행해도 30일 그대로).

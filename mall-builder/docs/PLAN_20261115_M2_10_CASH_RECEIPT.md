# M2-10 현금영수증(볼타) — 개발 플랜 (2026-11-15)

- 담당: [역할: mall-builder] `claude-win-20261025-workspace`
- 주인님 결정(2026-11-15): **볼타로 발급**(세금계산서 연동 재사용) · **유저가 신청 → 입금 확인 때 자동 발급**
- DB 번호: **0100**(백엔드 0100~0109, S67)

## 1. 볼타 현금영수증 API (2026-11-15 docs.bolta.io 확인)
| 항목 | 내용 |
|---|---|
| 발행 | `POST https://xapi.bolta.io/v1/cashReceipts` — 202 + `issuanceKey`(비동기 접수) |
| 본문 | `itemName`(1~20자) · `issuer`(사업자번호 10자리·상호 20자·대표 10자·전화) · `recipient`(`PHONE`+`purpose` `INCOME_DEDUCTION`/`EXPENSE_PROOF`, `BUSINESS_REGISTRATION_NUMBER`, `SELF`) · `amount`(`supplyAmount`·`vatAmount`·`taxFreeAmount`) |
| 결과 확인 | `GET /v1/cashReceipts/status?clientReferenceId=…` → `ISSUED`(+승인번호) / `PENDING`·`REQUEST_SUCCESS`(진행 중) / `*_FAILED` / `CANCELED` |
| 취소 | `POST /v1/cashReceipts/{issuanceKey}/cancellation`(본문 없음) — **전액 취소만**(부분 취소 없음), 원본이 `PENDING`이면 409 |
| 인증·중복 방지 | 세금계산서와 같음(Basic, `Bolta-Client-Reference-Id`) |
| 요금 | **발행 무료(포인트 차감 없음)** — 볼타 안내. 사전 조건: 운영사 볼타 계정의 발급자·공동인증서 등록 |

## 2. 동작
1. 운영사가 설정에서 「현금영수증 받기」를 켠다(볼타 API 키는 세금계산서 칸 그대로 사용).
2. 유저가 **무통장 입금 주문** 상세에서 신청: 휴대폰(소득공제·지출증빙) 또는 사업자번호(지출증빙). 카드·외상 주문, 세금계산서를 요청한 주문은 신청 불가(세금계산서와 둘 중 하나).
3. **입금 확인(입금 대기 → 결제 완료)** 때 DB가 자동 발급 요청. 이미 결제 완료된 주문에 신청하면 바로 발급 요청.
4. 결과는 운영사·유저 화면에서 「상태 다시 확인」으로 받는다(접수 → 발급 완료·승인번호 / 실패 사유).
5. **취소·반품 완료** 때 자동 전액 취소. 반품비를 빼고 환불했으면 취소가 확정된 뒤 남은 금액으로 다시 발급.
6. 부분 취소 등으로 금액이 바뀌면 운영사 화면에 「취소 후 다시 발급」 버튼.

## 3. 만드는 것
| 구분 | 내용 |
|---|---|
| DB 0100 | `orders.cash_receipt` jsonb · 신청 함수(유저) · 설정 저장 함수(대표) · 발급/취소/상태 확인 함수 · 입금 확인·취소·반품 때 자동 처리 트리거 · 세금계산서와 동시 요청 막기 |
| 화면 | 유저 주문 상세 신청 칸, 운영사 주문 상세 상태 칸(다시 확인·다시 발급), 설정 켜기 칸 |
| 시험 | 로컬 Docker 시나리오(볼타 호출을 가짜 함수로 바꿔 신청·자동 발급·취소·재발급·거절 경우), 단위 시험 |
| 안 하는 것 | 주문서(결제 화면)에서 바로 신청 — 프론트 담당 화면이라 다음에 요청. 신청 안 한 주문의 국세청 자진발급(주인님이 첫 번째 방식 선택) |

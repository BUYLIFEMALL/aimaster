# 쇼핑몰 세 가지 성격 정의 (주인님 정의, 2026-11-14)

> 이 문서가 B2B몰·분양몰·독립몰의 **기준 정의**다. 기능을 만들거나 바꿀 때 먼저 이 정의와 맞는지 본다.
> 정의는 주인님 말씀 그대로 옮기고, 아래 표에 「지금 프로그램과 다른 점」을 적는다.
> **개발 원칙**: 같은 일을 하는 코어는 하나로 같이 쓰고, 몰마다 다른 컨셉은 그 몰 버전에 맞게 따로 만든다(큰 맥락 유지). 진행 플랜: [`PLAN_20261114_MALL_TYPES_ALIGN.md`](PLAN_20261114_MALL_TYPES_ALIGN.md). 분양 정산은 **수수료율 방식**으로 결정(2026-11-14).

## 1. B2B몰 (샘플몰 `aimaster-b2b`)

**주인님 정의**: 공급사가 상품을 직접 등록하고 본사가 승인한다. 주 대상은 **사업자가 저렴하게 상품을 소싱**하는 몰이다. 공급사 / 회원사(상품을 구매하는 사업자) / 일반사용자로 등급을 나눠 상품 가격(할인율)을 다르게 적용해 판매하는 **폐쇄몰 성격의 B2B몰**이다.

**주인님 추가 정의(2026-11-14, 프로셀 관리자 분석 중) — B2B몰 = 「B2B몰 + 리셀러 판매」 접목(프로셀 바이라이프 몰과 같은 성격)**
- 「프로셀몰의 경우 B2B몰 + 리셀러 판매 방식이 접목된 몰이야」「우리가 만드는 B2B몰도 같은 성격으로 만들어져야 해」
- 「공급사가 가입 후 상품을 등록하고, 그 상품을 리셀러들이 상품 제휴 링크를 만들어 판매하면, 공급사가 설정해 놓은 판매 수수료를 정산해 주는 방식」
- 「모든 결제는 본사 쪽에서 입금되고, 상품 판매대금은 공급사에게, 판매 수수료는 리셀러들에게 지급되는 구조야」
- 참고 구현(프로셀 리워드 프로그램, `buylife.prosell.kr/adm` 리셀러 계정·리워드 상품·리워드 적립·출금신청): 리워드 = (판매가 − 즉시할인 − 쿠폰할인) × (리셀러 수수료 + 상품 수수료), 포인트·배송비 제외 / 상품별 수수료·리셀러 수수료 중복 차단 / 리워드 링크·유입 경로 기록 / 지급 예정 → 구매 확정 때 지급 완료, 확정 전 취소·반품은 지급 보류(운영자가 지급·삭제) / 직권 지급·차감 / 출금 최소 1만 원·계좌·통장사본·증빙·공제금액(부가세·원천징수).
- 우리 지금(D33 리셀러): 가입 때 리셀러에 묶인 손님 주문 × 리셀러 수수료율만 — 상품별(공급사가 정하는) 수수료·상품 제휴 링크·주문별 추적·지급 보류·증빙·공제 없음 → **새로 만들 핵심**([진행 플랜](PLAN_20261114_MALL_TYPES_ALIGN.md) R 단계).
- **결정(같은 날 질문 답변)**: 수수료는 공급사 대금에서 빠짐 · 계산은 프로셀과 같게 · **일반가는 누구나 보고 구매, 사업자가는 승인 후**(→ 아래 「폐쇄 정도」 결정과 P2 가격 잠금은 **취소**) · 리셀러는 신청 후 본사 승인. 플랜: [`PLAN_20261114_B2B_RESELLER_REWARD.md`](PLAN_20261114_B2B_RESELLER_REWARD.md).

**주인님 추가 정의(2026-11-14 계속) — 종합몰 겉모습 + 공급사·리셀러를 잇는 B2B, 돈의 흐름**
- 「AIMaster B2B몰은 그 자체가 외부적으로는 종합몰 형태의 쇼핑몰이면서 공급사와 리셀러들을 잇는 B2B몰」, 「운영사는 모든 상품 판매와 상품 노출, 결제, 정산을 담당」, 「공급사는 상품을 등록하면서 리셀러 판매 수수료를 스스로 책정」.
- 「본사가 해당 업체의 판매수수료를 예를 들면 3%로 정하면, 공급사가 리셀러 판매수수료를 10%로 정할 때 최종 공급가가 정해지고, 상품이 판매되면 판매가에서 본사 판매수수료 + 리셀러 수수료를 제외한 판매대금을 공급사에 입금, 리셀러 수수료는 본사가 공급사 대신 지급」 → **공급가 = 판매가 × (1 − 본사율 − 리셀러율)**(자세히: [리셀러 플랜 §0-1](PLAN_20261114_B2B_RESELLER_REWARD.md)).
- 참고 사이트(주인님 제시): 운영사 = 프로셀 `buylife.prosell.kr/adm`·`aimastermall.prosell.kr/adm`, 공급사 = 마이픽셀 `vendor.picksell.co.kr/am/main`, 리셀러 = `picksell.co.kr/celeb/m/main`(**리셀러 화면은 PC·모바일 모두 호환**). 「프로셀과 마이픽셀 사이트를 분석하면 전체 구조가 보일 거야」.

**같은 날 주인님 결정(질문 답변)**
| 항목 | 결정 |
|---|---|
| 폐쇄 정도 | **둘러보기는 공개, 가격·주문은 승인 회원만**(상품·카테고리는 누구나·검색엔진이 봄 — 11-13 「손님 화면 공개」 결정과 함께 감) |
| 입장 방식 | **가입 후 본사 승인**(회원사는 사업자 정보도 함께 심사) |
| 등급 할인율 | 일반 0% · 회원사 10%(상품별 등급 가격이 있으면 그것이 먼저) — **운영 샘플몰에 적용함**(등급 이름 「사업자」→「회원사」) |
| 공급사 | 등록·판매만 하는 계정(공급사 화면에서 등록·발송·정산). 물건을 사는 등급이 아님 |

**지금 프로그램과 대조**
| 정의 | 지금 | 할 일 |
|---|---|---|
| 공급사 등록 → 본사 승인 | ✅ 있음(D35 공급사 화면 등록, 본사가 판매가 정해 승인·반려) | 샘플 공급사 하나 등록해 시연 |
| 등급별 가격 | ✅ 있음(등급 기본 할인율 + 상품별 등급 가격, 사업자 신청·승인) | — |
| 둘러보기 공개·가격/주문은 승인 회원만 | ❌ **중간 단계 없음**. 지금은 「완전 폐쇄(D20, 승인 전 몰 입장 불가)」 또는 상품별 「로그인하면 가격 공개(승인 없음)」만 | **새 모드 필요**(아래 §4 1번) |

## 2. 분양몰

**주인님 정의**: 본사가 직접 운영한다. **본사와 입점사가 등록한 상품**을, 쇼핑몰을 분양받은 사업자가 각자 **자기 쇼핑몰 디자인(템플릿)과 도메인 주소**를 가지고 **자기 몰처럼** 판매하는 방식이다.

**결제·정산(주인님 추가 정의)**: 상품 정보 공유와 **결제는 본사로 들어온다(결제는 본사 하나)**. 분양몰 운영자는 **판매만** 자기 브랜드·주소로 한다. 최종적으로 **본사가 결제 금액 중 정산 금액을 분양몰 운영자에게 수수료 형태로 지급**한다.

**지금 프로그램과 대조**
| 정의 | 지금 | 할 일 |
|---|---|---|
| 결제는 본사 하나 | ✅ 손님 입금 계좌 = 본사 계좌(분양몰 설정에 복사), 입금 확인은 본사만(분양자는 결제·발송 상태를 못 바꿈). 2026-11-14 검수 25단계 통과(계좌이체). 카드 결제는 설계상 본사 토스, **실제 시험은 아직 안 함** | 카드 결제 시험 |
| 본사가 정산금을 수수료로 지급 | ✅ 구매 확정 때 분양자 장부에 적립 → 출금 신청 → 본사 송금·「지급 완료」. 지금 계산 = **분양자가 정한 판매가 − 본사 판매가**(차액 마진, 판매가는 본사가 이상) | **수수료 방식 확인 필요**: 차액 마진 그대로인지, 본사가 정한 수수료율(판매액의 ○%)인지 |
| 본사 운영, 분양 신청·이용 기간 | ✅ 있음(0061~0063, `/resale` 신청·본사 승인·이용 기간·마진 장부·출금) | — |
| 본사 + 입점사 상품 판매 | ✅ 있음(승인된 판매 중 상품, 활동 중인 공급사 상품 포함, 「사업자 전용」 상품은 제외) | — |
| 주문은 본사로 전달 | ✅ 있음(분양몰 주문 → 본사 주문, 배송 상태 따라감) | — |
| **자기 몰 디자인(템플릿)** | ❌ 손님 화면 디자인은 한 가지(106 네오 모던). 분양자가 바꿀 수 있는 것은 몰 이름·로고·첫 화면 블록 정도 | **템플릿 고르기 필요**(§4 2번) |
| **자기 도메인 주소** | △ 하위 도메인(`<몰>.<플랫폼 도메인>`) 코드는 있음, 운영 연결 여부 확인 필요. **자기 도메인(예: mymall.com) 연결은 없음** | **도메인 연결 필요**(§4 3번) |

## 3. 독립몰

**주인님 정의**: 각기 **개별 쇼핑몰**이다(본사·다른 몰과 상품·결제·회원이 묶이지 않는 독립된 몰).

지금까지의 계획: 자기 Supabase·Vercel에 따로 설치하는 몰(T3), 프로셀 상품 이전 H2 완료(Lab `aimaster-retail`), 회원 이전 H3는 하지 않음, 운영 설치 H4·전환 H5·배포 키트 T4는 주인님 지시 대기.

## 5. 사진 보관 (세 가지 몰 공통)
- 몰에 등록한 사진은 **자동 삭제하지 않는다**. 용량 한도(500MB·저장 구독)로 관리하고, 모자라면 추가 용량을 구매한다(2026-11-14 주인님 지정, `docs/TOP_RULE_PERSONAL_ACCOUNT_API.md` §8).

### 6-2. 정의와 어긋나거나 빠진 것
| # | 몰 | 내용 | 영향 |
|---|---|---|---|
| 1 | B2B | 「둘러보기 공개·가격/주문은 승인 회원만」 모드가 없음(완전 폐쇄 D20 또는 상품별 「로그인 시 가격 공개」만) | 샘플몰이 지금은 누구나 가격을 보는 일반 몰처럼 보임 |
| 2 | B2B ↔ 분양 | **충돌**: 분양몰로 나갈 수 있는 상품 = 상품별 가격 공개가 「누구나」인 것만(`0062` 13줄). 1번을 상품별 가격 공개로 만들면 분양 상품이 0개가 됨 | 1번은 **몰 단위 설정**으로 만들고, 분양 조건은 그대로 둔다 |
| 3 | 분양 | 정산 = 분양자가 정한 판매가 − 본사 판매가(차액 마진). 주인님 정의는 「본사가 정산금을 **수수료 형태로** 지급」 | 분양자가 본사가보다 비싸게 팔아야만 돈을 받는 구조. 수수료율 방식이면 계산·화면을 바꿔야 함 → **결정 필요** |
| 4 | 분양 | 분양자 기준가 = 본사 「일반」 판매가. B2B에서 회원사 10% 할인을 켜도 분양자 기준가에는 영향 없음 | 3번 결정과 함께 정함 |
| 5 | 분양 | 자기 디자인(템플릿) 고르기 없음 — 손님 화면 디자인 한 가지 | 새로 만들 것(agy 디자인 몫과 나눠서) |
| 6 | 분양·독립 | 자기 도메인 연결 없음 — 하위 도메인 코드만(운영 연결 확인 필요). 독립몰도 프로셀 도메인 이전(H5)이 필요 | 도메인 연결을 **공통 코어로 한 번** 만들어 둘 다 씀 |
| 7 | 분양 | 카드 결제(본사 토스)는 실제 시험 안 함 | 카드 결제 시험 |
| 8 | B2B | 샘플몰에 공급사가 없음(시험공급사 삭제) — 「공급사가 등록 → 본사 승인」을 보여 줄 수 없음 | 샘플 공급사 1곳·상품 2~3개 시연 등록 |

### 6-3. 제안 순서
1. (결정) 분양 수수료 방식 — 3·4번

# 개발 플랜 — 통계 (D14, 2026-11-06)

주인님 지시(2026-11-06): 「순서대로 진행해」 → 2차 후보 3번 통계. D13 뒤 「진행해」.

## 문제
- 운영자가 얼마나 팔렸는지, 무엇이 잘 팔리는지, 손님이 늘고 있는지를 볼 화면이 없다(주문 목록을 하나씩 세어야 함).

## 범위
운영자 「통계」 메뉴 하나. 기간을 고르면(오늘·7일·30일·이번 달·직접 입력) 아래를 보여 준다.
| 묶음 | 내용 |
|---|---|
| 요약 | 매출(결제된 주문 금액 합), 주문 수, 평균 주문 금액, 취소·반품 건수·금액, 입금 대기 건수, 새 손님 수·전체 손님 수 |
| 일별 추이 | 날짜별 주문 수·매출(막대) |
| 주문 상태 | 기간 안 주문의 상태별 건수 |
| 결제 방법 | 카드·외상·무통장별 건수·금액 |
| 상품별 매출 상위 10 | 수량(취소분 제외)·금액 |
| 장바구니 상위 10 | 지금 장바구니에 담긴 상품(담은 손님 수·수량, 기간과 무관) |

- 매출 기준: 결제가 된 상태의 주문(결제 완료·배송 준비·배송 중·배송 완료·구매 확정·취소 요청·반품 요청)의 주문 금액 `total`. 부분 취소는 `total`이 남은 금액으로 갱신되므로 그대로 반영된다. 취소·반품 완료 주문은 매출에서 빼고 따로 센다.
- 기간은 주문 생성 시각 기준, 한국 시간(Asia/Seoul) 날짜로 묶는다.
- 하지 않는 것: 그래프 라이브러리(막대는 CSS), 엑셀 내려받기, 손님별 매출 순위(다음 묶음 후보).

## 구현
1. DB `0034_stats.sql`(추가만): 함수 `mall_builder_stats(p_store_id, p_from, p_to)` 하나 — 운영자만, 한 번에 jsonb로 돌려줌(읽기만).
2. 공용 코드 `src/lib/stats.ts`(기간 계산·막대 비율·이름표) + 자동 시험.
3. 화면 `admin/stats`(기간 버튼·직접 입력, 요약 카드, 표+막대), 운영자 메뉴 「통계」.
4. 시험: DB 함수 시험(시험 몰 실제 주문으로 값 대조 — 읽기만이라 되돌림 불필요), 자동 시험, 빌드, Lab 배포 뒤 화면 확인.

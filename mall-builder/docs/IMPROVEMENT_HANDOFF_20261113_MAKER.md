## 2. 연결 계약(P2 작업표 ↔ 쇼핑몰 칸)

### 2-1. 쇼핑몰 → 바나나(보내기) 작업표 한 줄 = 상품 사진 한 장

| 작업표 칸(P2) | 쇼핑몰 값 | 비고 |
|---|---|---|
| 몰 식별 | `store_id` + `slug` | 반환 때 **둘 다** 일치해야 받음 |
| 내부 상품 ID | `product_id` | 1순위 매칭 키 |
| 외부 코드 | `product_code` | 사람이 보는 이름·파일명용(매칭 2순위는 쓰지 않음 — 다른 몰 같은 품번 사고 방지) |
| 옵션 | `variant key`·`sku` | 쇼핑몰에 옵션 사진 칸이 없어 **1차는 참고 정보만**(옵션 사진은 §5 후속) |
| 공급사 | `supplier_id`(자체 상품은 null) | 공급사 화면에서 보낸 작업은 자기 상품만 담김 |
| 사진 역할 | `main` = `images[0]`, `sub` = `images[1..4]`, `detail` = 상세 설명 안 그림(1차 제외) | |
| 원본 참조 | `images[n].path`(우리 저장소 경로)·`url` | |
| 작업 기준 시각 | 보낼 때의 `products.updated_at` | 반환 때 달라졌으면 「상품이 그사이 바뀜」 경고 |
| 결과 참조·상태·만료 | 바나나가 채움 | |

### 2-2. 바나나 → 쇼핑몰(돌려받기)

- 방법(추천): 바나나 기존 `postMessage` 약속에 **보낸 곳 `mall`(`https://mall-builder.buylife.xyz`)** 추가 + 메시지 종류 「여러 장」(`aimaster-nukki-batch`: 작업표 줄 + 결과 파일 묶음). 서버를 거치지 않으므로 바나나 저장 기간(30일)과 무관하게 쇼핑몰이 받은 순간 자기 저장소에 올린다.
- 대체 방법: 바나나가 내려 준 **ZIP + 결과 작업표(JSON/CSV)**를 쇼핑몰 「사진 일괄 반영」 화면에 올림(창을 닫았거나 다른 기기).
- 받은 사진은 **로그인한 쇼핑몰 사용자 본인 권한으로** 쇼핑몰 공개 버킷의 올바른 폴더(운영자 `<몰>/…`, 공급사 `<몰>/supplier/<공급사>/…`)에 올린다 → 저장소 규칙이 다른 몰·다른 공급사 폴더를 자동으로 막는다.

## 3. 권한·충돌·중복 검사(반환 때, 줄마다)

| 검사 | 거절 조건 | 결과 |
|---|---|---|
| 몰 일치 | 작업표 `store_id`/`slug`가 지금 화면의 몰과 다름 | 「다른 몰 작업」 거절 |
| 상품 존재·소속 | `product_id`가 이 몰 상품이 아님·지워짐 | 거절(품번으로 대신 찾지 않음) |
| 공급사 일치 | 공급사 화면: 상품 `supplier_id` ≠ 내 공급사 / 운영자 화면: 작업표 `supplier_id`와 상품 `supplier_id` 다름 | 거절 |
| 분양몰 거울 | 상품에 `source_product_id`가 있음 | 거절 + 「본사 상품에서 바꾸면 자동 반영」 안내 |
| 묵은 작업 | 상품 `updated_at` > 작업 기준 시각 | 경고 후 사람이 「그래도 반영」 선택(기본은 건너뜀) |
| 역할·자리 | `main` 2장 이상, 합쳐서 5장 넘음 | 넘는 것 건너뜀·표시 |
| 중복 | 같은 상품·같은 역할·같은 파일(내용 해시) 이미 있음 | 건너뜀 |
| 파일 | 이미지 아님·5MB(일괄 25MB 묶음) 초과 | 그 줄만 실패 |

**바꾸지 않는 것(반환은 사진만)**: 판매가·공급가·옵션 추가금·배송비 정책·승인·판매 상태·공개 범위·재고·카테고리. 분양몰 거울 사진은 본사 사진이 바뀌면 기존 동기화로 따라감.

## 4. 승인 상태 보존 — 「돌려받기 = 바로 반영」이 아니라 「제안 → 적용」

1. 돌려받은 사진은 먼저 **사진 제안**으로만 저장(상품·화면에 즉시 반영하지 않음, 손님에게 안 보임).
2. 화면에서 상품별로 전·후를 보고 **「적용」**을 눌러야 상품 `images`가 바뀐다.
   - **운영자가 적용**: 지금처럼 운영자 수정 = 승인 상태 그대로(자체·공급사 상품 모두).
   - **공급사가 적용**: 기존 규칙 그대로 — 사진이 바뀌므로 「승인 대기」(바로 판매 공급사는 유지). 즉 **가공물 반환 자체는 승인 상태를 바꾸지 않고**, 사람이 적용할 때만 기존 규칙이 돈다.
3. 「되돌리기」: 적용 전 사진 목록을 제안 기록에 남겨 한 번에 되돌림.

## 5. 후속 구현 범위(제안 — 승인 전)

| 단계 | 내용 | DB | 의존 |
|---|---|---|---|

| M5 상세 그림(선택) | 상세 설명 안 그림 교체 | 없음 | 상세페이지 연계 결정 |

- 바나나 쪽 일(보낸 곳 `mall` 등록·여러 장 메시지·작업표 내보내기)은 **이커머스·이미지 담당(Claude sdp/agy) 몫**, 공용 기준 코드 `nukki-handoff` 규칙대로 기준 파일만 고치고 사본 동기화.
- 저장 정책(**Claude policy 몫, 결정 필요**): 쇼핑몰 상품 사진은 몰이 계속 판매하는 「가게 자산」이라 일반 회원 30일 자동 삭제를 적용하면 상품 사진이 깨진다. 몰 사진을 30일 규칙에서 빼는지(또는 몰 대표 저장 구독으로 처리하는지) 정해야 M2를 만든다. 지금 쇼핑몰 사진은 30일 정리 대상이 아니다 — 쇼핑몰에 정리 코드가 없고, 메인 중앙 정리 `member_storage_expired_files`는 **경로에 회원 id가 들어간 파일만** 고르는데 쇼핑몰 사진 경로는 `<몰 id>/…`라 잡히지 않는다(같은 이유로 💾 사용량에도 안 잡힘, 2026-11-13 운영 함수 본문 확인). M2에서 사진 경로에 회원 id를 넣으면 정리 대상이 되므로 **경로 규칙을 바꾸지 말 것**.

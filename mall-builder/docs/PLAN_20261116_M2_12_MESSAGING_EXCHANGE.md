## 1. 문제
- 운영사가 유저에게 **직접 문자·메일을 보내는 화면이 없다**(개별·대량 모두). 솔라피·Resend 연동은 주문 자동 알림에만 쓰인다.
- 자동 알림 **문구를 몰마다 고칠 수 없고**, 반품·취소 완료·교환 알림이 없다. 발송 기록은 「최근 알림」만 있고 기간 검색이 없다.
- **교환 흐름이 없다**(배송비 정책에 교환비 칸만, 0065). 교환비·왕복 배송비를 유저에게 청구할 **개인결제창**도 없다.

## 3. 지키는 규칙
- **회원 본인 키**: 문자는 운영사 본인 솔라피, 메일은 본인 Resend, 결제는 본인 토스 — 운영자(AIMaster) 키 폴백 없음. 키가 없으면 「설정에서 등록」 안내.
- **법정**: 광고성 정보는 수신 동의자에게만·(광고) 표기·무료 수신 거부 방법·야간(21~8시) 별도 동의 없으면 막음. 개인결제창 링크는 추측 불가한 토큰, 금액·주문 고정, 만료일.
- **재발송 금지**: 결과가 불확실(`unknown`)한 문자·결제는 자동으로 다시 보내지 않는다(기존 `sendClaimed` 규칙).
- 대량 발송 한 번 상한(예: 1,000명)과 하루 상한 — 실수로 요금 폭탄 방지.
- 세 몰 공통 코어: 분양몰·독립몰도 같은 화면(분양몰 교환은 본사 전달 주문으로 넘김).

### 8-4. 시험(메인 격리, Lab 자동 확정 함수 정의 그대로 재현)
qa_ DB에 0032 `mall_builder_auto_progress`와 일정 표(auto_confirm_days = 3)·토큰을 그대로 두고 실행:
1. 실제 배송 4일 전 → 자동 확정 실행 → confirmed → 유저 교환 신청 **됨**
2. 실제 배송 8일·10일 전 confirmed → 유저 **막힘**(7일), 직원 대리 **됨**
3. 실제 배송 2일 전 → 유저 신청 → 회수 중 → 배송 시각을 4일 전으로 옮겨 자동 확정 실행 → **그 주문 confirmed + 같은 회차 다른 주문들도 confirmed**(묶음이 깨지지 않음) → 교환 계속: 입고·교환비 미납이면 재발송 막힘·입금 확인 뒤 재발송·완료
4. 진행 중 교환이 있는 delivered 주문의 반품 요청 → 여전히 막힘, 취소 경로도 막힘
5. 교환 없는 다른 주문 자동 확정 정상(회귀)
6. 빨강: 지금 0102(후속 없음)에서 3번 → 자동 확정 실행 오류·같은 회차 다른 주문 확정 0(묶음 전체 실패) 실측
7. 기존 QA004(A1~A23)·0103 카드(F1~F21) 회귀 — 상태 조건만 바뀌므로 기대값 변경이 필요한 항목은 이유 명시

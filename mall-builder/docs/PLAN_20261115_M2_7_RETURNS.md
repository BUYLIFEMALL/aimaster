## 1. 지금
| 단계 | 지금 동작 |
|---|---|
| 유저 반품 요청 | 배송 완료 주문에서 「반품 요청」(사유 칸 없음) |
| 운영사 | 「반품 승인」→ 반품 완료(재고 복구, 카드는 전액 환불) / 「반품 거절」→ 배송 완료 |
| 무통장·외상 주문 환불 | 앱 밖에서 이체 — **환불 계좌·환불했는지 기록 없음** |
| 취소(배송 전) | 무통장 결제 완료 주문 취소도 같은 문제(환불 계좌 없음) |

## 2. 만들 것(주문 상태는 늘리지 않음 — 화면·트리거·분양몰 연동이 상태 목록을 쓰므로)
1. **반품 요청에 사유·사진 없이 사유 선택 + 메모**(단순 변심 / 상품 불량 / 오배송 / 기타) — 사유에 따라 반품비 기본값(변심이면 몰 설정 반품비, 불량·오배송이면 0).
2. **회수 단계**(반품 요청 상태 안의 작은 단계): 요청 → 회수 중(운영사가 회수 택배사·송장 입력) → 회수 완료(입고 확인) → 반품 승인. 유저 화면에 단계·회수 송장 표시.
3. **반품비 차감**: 반품 승인 때 반품비(기본값 → 운영사가 고칠 수 있음)를 뺀 금액만 환불. 카드는 그 금액만 부분 환불(기존 카드 환불 함수 재사용).
4. **환불 계좌**(무통장·외상 주문의 반품·결제 후 취소): 유저가 요청할 때 은행·계좌·예금주 입력. **환불이 끝나면 계좌 정보는 지움**(개인정보 최소 보관), 금액·일시 기록은 5년 보관.
5. **환불 대기**: 무통장 환불이 남은 주문을 운영사 「주문」에 「환불 대기」 칸·필터로, 이체 후 「환불 완료」 누르면 기록. 대시보드 「처리할 일」에도 한 칸.
6. 분양몰: 반품·취소 연동은 지금처럼(본사 전달 주문 따라감), 환불은 본사가 함 — 본사 「분양 주문」에서 같은 환불 대기 처리.

## 3. DB(번호)
- 백엔드 범위 0090~0099 중 **0099 하나 남음** → 이번에 0099를 쓰고, 다음부터 **0100~0109**를 백엔드가 쓰도록 상호 인수인계 §2에 합의 요청(프론트 0080~0089 그대로).
- 0099: `mall_builder_orders` 칸(반품 사유·메모·단계·회수 택배사/송장·반품비·환불 금액·환불 상태·환불 일시) + 환불 계좌 표(주문당 1행, 유저 본인·그 몰 직원만, 환불 완료 때 삭제) + 함수(반품 요청, 회수 단계, 반품 승인(반품비), 환불 완료) + 몰 설정 반품비 기본값.

## 4. 검수

## 1. 문제
지금은 가격을 **등급 단위**(일반·사업자)로만 다르게 줄 수 있다. 도매에서는 같은 사업자라도 거래처마다 계약 단가가 다르다(큰 거래처 A는 23,000원, B는 24,500원). 프로셀의 「회원별 특가」에 해당.

## 2. 지금 가격 순서와 넣을 자리
판매가 + 옵션 추가금 → **등급가** → 공동구매가(있으면 대신) → 수량 구간 할인 → 원 단위 내림.
화면(`src/lib/pricing.ts`)과 DB 주문 함수(`mall_builder_place_order_v2`)가 같은 계산을 한다 — **둘 다 같이 바꾼다**.
→ **거래처 특가는 「등급가」 자리에 먼저 확인**한다: 그 손님의 특가가 있으면 등급가 대신 특가.

## 3. 범위(안)
1. DB 표 `mall_builder_customer_prices`(몰·손님·상품·금액 또는 할인율·끝나는 날 선택·메모), 손님×상품 한 줄. 운영자(직원 「손님」 권한)만 쓰기, 손님은 자기 특가만 읽기
2. 손님마다 **거래처 기본 할인율**(전체 상품 n%, 선택) — 상품별 특가가 없으면 이것, 그것도 없으면 등급가
3. 운영자 화면: 손님 상세에 「거래처 특가」 칸 — 품번(D23)이나 상품 이름으로 찾아 추가·수정·삭제, 기본 할인율 입력
4. 손님 화면: 상품 목록·상세·장바구니·주문서에 「거래처 특가」 표시(원래 가격 취소선)
5. DB 주문 함수 `_v2`에 같은 규칙(함수 정의만 바꿈 — 화면과 같은 숫자로 시험)
- 1차에서 하지 않음: 엑셀로 특가 대량 등록(필요하면 D23 엑셀에 시트 추가로 다음에), 견적·비회원 주문(견적은 운영자가 직접 단가를 넣고, 비회원은 거래처가 아님)

## 4. 결정 항목 (주인님)
| 번호 | 결정할 것 | 추천안 | 다른 안 |
|---|---|---|---|
| 1 | 특가 뒤에 수량 구간 할인을 또 적용할지 | **적용 안 함 — 특가가 최종 단가**(계약가라서) | 등급가처럼 구간 할인도 적용 |
| 2 | 거래처 기본 할인율(전체 상품 n%) | **넣음**(상품별 특가 > 기본 할인율 > 등급가 순) | 상품별 특가만 |
| 3 | 특가 받을 수 있는 손님 | **이 몰에 가입한 손님 누구나**(운영자가 골라서 지정) | 승인 사업자만 |
| 4 | 기간 | **끝나는 날 선택 칸**(비우면 계속, 지나면 자동으로 원래 가격) | 기간 없음 |
| 5 | 공동구매 중인 상품 | **공동구매가가 우선**(지금 등급가와 같은 규칙) | 둘 중 낮은 값 |

## 5. 구현 순서
1. DB `0045_customer_prices.sql`: 표·보안 규칙·손님 기본 할인율 칸(추가만) → 함수 `0045b`: `_v2`의 등급가 자리 교체(함수 정의만 바꿈, 지우는 데이터 없음)
2. `pricing.ts`: `PriceContext`에 `customerPrice` 추가, 특가 우선·(결정 1에 따라) 구간 할인 건너뜀, 표시 이름 「거래처 특가」
3. 가격 문맥 읽기(`getPriceContext(s)`)에서 특가·기본 할인율을 함께 읽음
4. 운영자 손님 상세 화면 「거래처 특가」 칸, 손님 화면 표시
5. 시험: `pricing` 자동 시험(특가·기본 할인율·기간 만료·공동구매 우선·옵션 추가금), DB 시험(다른 손님 특가 안 보임·직원 권한·주문 금액 = 화면 금액, 되돌림), ego 화면(특가 지정 → 그 손님 화면·주문 금액 / 다른 손님은 원래 가격)

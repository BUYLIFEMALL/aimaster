## 0. 개발 원칙 (이후 모든 쇼핑몰 작업의 기준)

1. **큰 맥락 유지**: 코드 하나, 세 몰(B2B몰 → 분양몰 → 독립몰), AIMaster 이커머스 샘플몰로 운영, 나중에 배포 키트. 11-11 [세 몰 플랜](PLAN_20261111_THREE_MALLS.md)의 구조를 바꾸지 않는다.
2. **같은 일을 하는 코어는 하나로 같이 쓴다**: 상품·가격 계산·주문·결제·정산 장부·알림·도메인 연결처럼 두 몰 이상에서 같은 일을 하는 기능은 공통 코어 한 곳에만 만들고 몰 버전이 가져다 쓴다. 새 기능을 만들기 전에 이미 같은 계산·흐름이 있는지 먼저 찾는다(예: 분양 수수료 = 리셀러 수수료와 같은 계산식).
3. **몰마다 다른 컨셉은 그 몰 버전에 맞게 따로 만든다**: 누가 사는지·누가 파는지·돈이 어디로 가는지·무엇을 공개하는지는 몰마다 다르다. 이런 부분은 몰 유형(`stores.kind`·몰 설정·단일 몰 모드)으로 켜고 끄며, 한 몰의 컨셉 때문에 다른 몰의 동작이 바뀌지 않게 한다(예: B2B몰 가격 숨김이 분양 상품 공급을 막으면 안 됨).
4. **정의 문서가 기준**: 기능을 만들거나 바꾸기 전에 [`MALL_TYPES_DEFINITION.md`](MALL_TYPES_DEFINITION.md)와 맞는지 보고, 정의가 바뀌면 그 문서부터 고친다.

## 2. P1 분양 수수료율 — 설계

**정의**: 결제는 본사 하나, 분양몰은 본사 판매가 그대로 팔고, 본사가 판매액의 수수료율만큼을 분양자에게 지급한다.

| 항목 | 지금(차액 마진) | 바꾼 뒤(수수료율) |
|---|---|---|
| 분양몰 판매가 | 분양자가 정함(본사가 이상), 담을 때 인상률 | **본사 판매가와 같음**(분양자가 못 바꿈), 본사 가격이 바뀌면 같이 바뀜 |
| 정산금 | 분양몰 품목 합계 − 본사 전달 주문 품목 합계 | **(분양몰 결제 금액 − 배송비) × 수수료율** — 리셀러(D33)와 같은 식 |
| 수수료율 | — | 본사 몰의 「기본 수수료율」(처음 10%) → 분양몰마다 본사가 따로 정할 수 있음(0 초과~50%, 리셀러와 같은 범위) |
| 언제 쌓이나 | 구매 확정 때 적립, 반품·취소면 회수 | 같음(장부·출금 그대로) |

**코어 공유**: 수수료 계산식 하나 `mall_builder_private.commission_of(total, shipping_fee, rate)`를 만들고 리셀러 적립과 분양 정산이 같이 부른다.

**DB 0067**(Lab → 로컬 시나리오 → 운영, 함수는 정해진 부분만 바꿈)
1. `mall_builder_stores.resale_commission_rate numeric(5,2)` — 본사 몰은 기본값, 분양몰은 자기 값(신청 승인 때 본사 기본값 복사).
2. `commission_of` 코어 함수, 리셀러 적립 함수가 이것을 부르게.
3. `resale_margin(order)` → 수수료 계산으로(이름은 그대로 두어 부르는 곳을 안 바꿈).
4. 거울 상품 판매가 = 원본 판매가(담기·원본 변경 동기화), `mall_builder_resale_price`는 「본사 판매가로 팝니다」로 막음.
5. 본사용 수수료율 바꾸기 함수(본사 몰 기본값·분양몰별).
6. 장부 문구 「마진」 → 「수수료」.

**화면**
- 분양자 「분양」: 인상률·판매가 칸을 빼고 「본사 판매가로 판매 · 수수료 N%」 표시.
- 본사 「분양」: 기본 수수료율 칸, 분양몰 목록에 몰별 수수료율 바꾸기.
- 공개 분양 안내 `/resale`·처음 화면 카드: 「마진 = 내 판매가 − 본사 판매가」 → 「수수료 = 판매 금액(배송비 제외) × 수수료율」.

**검수**: 시나리오 SQL(담기 = 본사가, 본사 가격 변경 → 거울 따라감, 판매가 바꾸기 거절, 구매 확정 수수료 = (결제−배송비)×율, 반품 회수, 리셀러 적립 금액 그대로), 단위 시험·tsc·운영 모드 빌드, 운영은 DB 적용 뒤 화면 확인.

## 3. P2 B2B 가격·주문 승인 회원만 — 설계(요지, P1 끝나고 자세히)
- 폐쇄몰 설정에 모드 추가: `closed.mode = 'full'`(지금, 승인 전 입장 불가) / `'price'`(둘러보기 공개, 가격·장바구니·주문은 입장 승인 회원만).
- 가격 숨김은 **몰 단위**로 하고 상품별 「가격 공개」 칸은 건드리지 않는다 → 분양 상품 공급 조건(`0062` 상품별 가격 공개 = 누구나)과 충돌하지 않음.
- 가격은 DB가 내려보내지 않아야 한다(화면에서만 가리면 주소로 읽힘) → 손님 상품 함수·가격 계산 함수·주문 지킴이에 같은 판정.
- 입장 승인 흐름(가입 → 승인 대기 → 승인)은 D20 그대로 재사용.

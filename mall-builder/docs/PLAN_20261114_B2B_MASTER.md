## 2. 돈의 흐름 (확정)
- 공급가 = 판매가 × (1 − 본사 판매수수료율 − 리셀러 판매수수료율). 예) 10,000원 · 본사 3% · 리셀러 10% → 공급사 8,700원 · 리셀러 1,000원 · 본사 300원.
- 결제는 모두 본사로 → 구매 확정 뒤 공급사 정산(공급가 × 수량, 기존 장부) · 리셀러 리워드(실결제 품목 금액 × 리셀러율, 지급 예정 → 완료/보류).
- 할인(등급가·쿠폰)은 본사 부담, 공급사 입금은 공급가 그대로. 최저 판매가 보호 = 공급가 + 리셀러 수수료(제안 — §7 결정).
- 분양몰: 본사 판매가 그대로 판매, (결제−배송비) × 분양 수수료율(P1, 코드 완료·미배포). 리셀러와 분양자는 같은 「수수료 계산 코어」 사용.

## 3. 코어와 몰 버전별 (개발 원칙)
- **코어(세 몰 공통)**: 상품·가격 계산·주문·결제·배송비·정산 장부(공급사·리셀러·분양)·수수료 계산(`commission_of`)·알림·회원/등급·통계·디자인 빌더·도메인 연결·법정 표시(고시·약관).
- **몰 버전별**: B2B = 공급사 입점·리셀러 판매·회원사 등급, 분양 = 거울 진열·분양자 수수료·자기 브랜드, 독립 = 단일 몰·자기 설치. 한 몰의 설정이 다른 몰 동작을 바꾸지 않게.

## 3-1. 기존 기능 재사용·보존 원칙 (2026-11-14 주인님 지시)
- 주인님: 「지금 개발하던 B2B몰 어느 정도 기능 구현되어 있으니까 보고 사용할 수 있는 건 가져다 사용하고, 필요 없는 기능은 버리지 말고 다른 분양몰·독립몰에서 필요할 수 있으니 그건 그때 가져다가 사용할 수 있도록 해」
- **쓸 수 있는 것은 그대로 가져다 쓴다**: 각 항목 구현 전에 [로드맵 §1 공통 코어](MALL_BACKEND_ROADMAP.md)와 [비교표 §12 우리에게만 있는 기능](analysis/PROSELL_ADMIN_GAP_20261114.md)에서 같은 일을 하는 코드를 먼저 찾는다.
- **필요 없는 기능도 지우지 않는다**: B2B몰 정의와 맞지 않게 된 기능은 코드·DB를 남기고 몰 설정(`stores.modules`·`settings`)의 켜고 끄기로 **B2B몰에서만 끈다**. 함수·표를 지우거나(drop) 덮어써서 동작을 없애지 않는다. 바꿔야 하면 「방식 선택」 칸을 더해 옛 방식을 선택지로 남긴다.
- 보존 목록(이번 결정으로 B2B몰에서 쓰지 않거나 바뀌는 것 — 분양·독립몰 후보):
  | 기능 | B2B몰 | 남겨 두는 방법 | 쓸 수 있는 곳 |
  |---|---|---|---|
  | 공급사가 공급가를 직접 적는 방식(0054·0060) | 공급가 자동 계산(M1-2)으로 바뀜 | 몰 설정 「공급가 방식 = 직접 입력 / 수수료율 자동」(기본: B2B는 자동) | 독립몰(자체 매입·위탁) |
  | 폐쇄몰(D20 입장 승인·초대 코드) | 일반가 공개로 결정 — 켜지 않음 | 그대로(설정에서 끔) | 회원 전용 독립몰·도매 독립몰 |
  | P2 가격 잠금(설계만) | 취소 | 플랜 문서에만(코드 없음) | 필요하면 그때 |

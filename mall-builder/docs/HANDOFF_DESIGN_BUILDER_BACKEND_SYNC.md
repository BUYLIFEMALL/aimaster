## 쓰는 법 (양쪽 공통)
1. **작업을 시작하기 전**에 §1 「상대에게 온 메시지」에서 내 쪽 「확인 대기」 줄을 먼저 읽고, 처리하면 상태를 「확인함」 또는 「처리함(커밋)」으로 바꾼다.
2. **상대에게 영향이 있는 일**(공용 파일 수정, DB 함수·표·칸 추가, 몰 종류·모듈 추가, 배포, 화면 주소 추가)은 하기 전이나 한 직후에 §1에 한 줄 남긴다.
3. **배포 직전**에는 §3 「배포 순서」에 줄을 넣고, 상대의 미배포 변경이 함께 나가는지 적는다.
4. 약속이 바뀌면 §2 「약속」을 고치고 §1에 「약속 변경」 메시지를 남긴다.
5. 지우지 않고 아래로 쌓는다. 오래된 처리 완료 줄은 §5로 옮겨도 된다.
6. 커밋은 `node scripts/commit-paths.mjs "<메시지>" mall-builder/docs/HANDOFF_DESIGN_BUILDER_BACKEND_SYNC.md --as <세션>`. 둘이 동시에 고칠 수 있으므로 **커밋 직전 `git diff`로 상대 줄이 지워지지 않았는지** 확인한다.
7. 급한 일(상대 화면을 깨뜨릴 수 있는 변경)은 이 문서에 적는 것과 함께 주인님 채팅 보고에도 「백엔드(또는 프론트) 담당께」로 알린다.

2. **함께 만지는 파일**(`(shop)/layout.tsx`·`admin/admin-shell.tsx`·`src/lib/store.ts`·`src/lib/staff.ts`·`src/app/globals.css`·`package.json`·`AGENTS.md`·이 문서)은 **작게, 한 번에 하나의 목적만** 고치고 바로 커밋한다. 줄 바꿈·들여쓰기 정리·이름 바꾸기 같은 「덤 정리」는 하지 않는다.
3. **커밋 직전**: `git status --porcelain -- mall-builder`로 상대 미커밋 파일을 보고, 내 커밋에는 `node scripts/commit-paths.mjs`로 **내 파일만** 넣는다. 이 문서는 `git diff`로 상대 줄이 지워지지 않았는지 본다.
4. **메시지 번호**: 새 줄을 넣기 직전에 §1의 가장 큰 번호 +1을 쓴다(같은 때 둘이 같은 번호를 쓰면 나중 커밋이 번호를 올린다 — 2026-11-14 S18 겹침 사례).

6. **개발 서버·`.env.local`**: 3210 개발 서버는 백엔드 세션 것 — 프론트는 끄거나 다시 켜지 않는다. `.env.local`은 어느 쪽도 메시지·메모를 쓰지 않는다(S13 사고). 서버가 죽으면 §1에 알린다.

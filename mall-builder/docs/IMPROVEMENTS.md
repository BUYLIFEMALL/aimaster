# 개선 제안 — AI 쇼핑몰 빌더

## 1. 프로그램 로직·기능
- (2026-11-12, T0) 운영 관문이 요청마다 로그인 확인 + 권한 조회 4번을 한다. 회원이 늘면 짧은 캐시(예: 1분, 사용자별)를 검토. 지금은 샘플몰 규모라 그대로.
- (2026-11-12, T1) 등급 이름 중복은 0057c로 막음. 카테고리 이름도 같은 몰 안 중복을 DB에서 막을지 검토.
- (2026-11-12, T0) 운영에서 공급사 초대는 몰 대표(=관리자)만 할 수 있지만, 직원 권한 「공급사」를 받은 직원도 초대할 수 있다 — 샘플 단계에서는 직원을 두지 않는 것으로 충분, 실제 판매 전 재검토.

## 2026-11-12 운영 보안 점검(advisors) 뒤 개선 후보
- 보안 정의자 함수 중 로그인이 꼭 필요한 것은 `anon` 실행 권한을 거두기(함수 안 검사와 겹으로 막기). 지금 anon이 부를 수 있는 쇼핑몰 함수 125개 — 비회원 주문·재입고 신청·공개 조회처럼 비로그인이 써야 하는 것만 남기고 나머지 `revoke execute … from anon`. Lab에서 먼저 시험 뒤 운영.

## 2026-11-12 쇼핑몰 정보 저장이 막힌 일 (운영 샘플몰)
- (고침, **배포됨 v1.02**) 계좌번호에 복사해 온 비슷한 하이픈(‐ – － 등)이 들어가면 「숫자와 하이픈」 검사에 걸려 저장 전체가 막힘 → 번호 칸(사업자등록번호·통신판매업 신고번호·전화·계좌번호)은 비슷한 하이픈을 일반 하이픈으로 바꾼 뒤 검사(`src/lib/businessInfo.ts`, 시험 `tests/businessInfo.test.mjs`).
- (개선 후보) 「쇼핑몰 정보」 한 화면에 저장 단추가 11개라, 위 묶음을 입력한 뒤 아래 묶음 「…저장」을 누르면 입력이 사라짐(주인님이 실제로 겪음) → 저장 안 한 변경이 있는 묶음 표시·다른 단추를 누르면 경고, 또는 묶음마다 탭으로 나누기.
- (고침, **미배포 대기**) 손님 「내 정보」에서 배송지를 추가해도 성공 알림이 화면 맨 위에만 떠서, 아래 「새 배송지」 칸만 보던 주인님이 반응이 없는 줄 알고 두 번 추가함(같은 배송지 2개, 운영 2026-11-12) → 배송지 저장·기본·삭제 뒤에는 `#addresses`로 돌아가고 알림을 배송지 제목 바로 아래에 띄움(`my/actions.ts` `backAddr`, `my/page.tsx`).

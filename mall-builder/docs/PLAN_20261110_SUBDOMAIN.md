# 하위 도메인 플랜 (2차 후보, 2026-11-10)

> 대상: `labs/mall-builder` · DB `AIMaster_dev`(ref `rjjtjakljjxsgjelqgek`) · 세션 `claude-win-20261103-mall-builder`
> 로드맵 줄: `docs/mall/ROADMAP_AND_VARIANTS.md` 「하위 도메인 — `<몰>.<플랫폼 도메인>`」

## 1. 무엇을 하나
지금 손님 주소는 `dev-mall-builder.vercel.app/s/aimaster-b2b` 처럼 경로 방식이다. 이것을 `aimaster-b2b.<플랫폼 도메인>` 으로도 열리게 한다.

## 2. 지금 상태 (코드 확인)
- 몰 이름 규칙(소문자·숫자·하이픈 3~30자, `--`·끝 하이픈 금지)은 이미 도메인 이름으로 쓸 수 있는 모양이다. 예약어에 `www`·`api`·`admin`·`app` 이 들어 있다 → DB 변경 없음.
- `src/proxy.ts` 가 `/s/*` 요청에 경로 머리글만 붙이고 있다 → 여기에 「주소 이름 → `/s/<몰>` 로 바꿔 읽기」를 넣으면 된다.
- 화면 안 링크 230군데가 `/s/<몰>/…` 를 만든다 → 하위 도메인에서도 `/s/…` 경로는 그대로 통과시켜 **링크를 고치지 않는다**(옛 주소도 계속 동작).

## 3. 막히는 점 — 도메인
- `*.vercel.app` 에는 우리가 하위 주소를 붙일 수 없다.
- Vercel 의 와일드카드 도메인(`*.example.com`)은 그 도메인의 네임서버를 Vercel 로 옮겨야 붙는다. `buylife.xyz` 는 Cloudflare 네임서버이고 운영 도메인이라 Lab 이 손댈 수 없다(운영/Lab 분리 최상위 규칙).
- 그래서 「실제 인터넷 주소」를 언제·어떻게 마련할지가 결정 항목이다.

## 4. 결정 항목 (주인님)
| 번호 | 항목 | 추천 | 다른 안 |
|---|---|---|---|
| 1 | 도메인 마련 | 코드만 만들고 내 PC 주소(`aimaster-b2b.localhost:3210`)로 시험, 실제 도메인은 운영 이전 때 `*.buylife.xyz` 쪽에서 연결(비용 0) | Lab 전용 도메인 구입(연 1~2만 원대, 네임서버 Vercel) / `<몰>.buylife.xyz` 를 몰마다 손으로 추가(운영 도메인을 건드림 → 주인님 명시 승인 필요) |
| 2 | 하위 도메인으로 들어온 손님 주소창 | `/s/<몰>` 이 붙은 링크는 그대로 둠(이번엔 안 고침) | 230군데 링크를 주소 방식에 맞게 바꾸는 공통 함수 도입(규모 큼, 나중에) |
| 3 | 로그인 | 하위 도메인마다 따로 로그인(쿠키는 그 주소 전용) | 플랫폼 도메인 전체 공유 쿠키(운영 이전 때) |

## 5. 구현 순서 (추천안 기준)
1. `src/lib/host.ts`: 요청 주소에서 몰 이름을 뽑는 순수 함수(`MALL_ROOT_DOMAIN` 환경값, 기본 `localhost`). 예약어·형식 틀림·루트 주소는 무시. → 시험: `node --test` 로 경우별 확인.
2. `src/proxy.ts`: 하위 도메인이면 `/x` → `/s/<몰>/x` 로 바꿔 읽기, `/s/…`·`/_next`·`/api`·`/auth` 는 그대로. matcher 를 넓힌다. → 시험: 로컬 서버에서 `aimaster-b2b.localhost:3210/` 이 몰 첫 화면, 루트 주소는 지금 그대로.
3. 운영자 설정 화면에 「하위 도메인 주소」 한 줄 표시(환경값이 실제 도메인일 때만).
4. 시험 150개 + 새 시험·`tsc`·`npm run build`(무료) → 커밋. **배포는 하지 않음**(실제 도메인이 없으면 Lab 에서 볼 수 없으므로 다음 배포 때 함께, 미배포 대기).

## 6. 비용
- 추천안: 없음(로컬 시험만). Lab 빌드는 다음 묶음 배포 때 1회(그때 승인).
- 도메인 구입안을 고르면 도메인 비용 연 1~2만 원대 + 빌드 1회.

## 7. 결과 (2026-11-10)
- 주인님 결정: 세 가지 모두 추천안(코드만·내 PC 시험 / 링크 그대로 / 몰 주소마다 따로 로그인).
- 구현: `src/lib/host.ts`(몰 이름 뽑기·경로 바꿔 읽기·운영자 화면용 주소), `src/proxy.ts`(하위 도메인이면 `/s/<몰>/…` 로 바꿔 읽기, matcher 를 정적 파일 뺀 전체로 넓힘), 대시보드 「하위 도메인」 줄(`MALL_ROOT_DOMAIN` 이 실제 도메인일 때만).
- 시험: 새 시험 6개 포함 156개 통과·`tsc`·`npm run build` 통과. 내 PC(`next dev -p 3210`)에서 `aimaster-b2b.localhost:3210/`·상품·장바구니·FAQ·검색 200, 옛 `/s/` 주소 그대로, 루트·`www` 는 바꾸지 않음, 없는 몰 404, 관리 화면은 같은 하위 도메인의 로그인으로 넘어감(ego 확인).
- 배포: **미배포 대기**(Lab 은 `*.vercel.app` 이라 하위 도메인을 볼 수 없음). 배포 때 Lab 에는 `MALL_ROOT_DOMAIN` 을 넣지 않는다(기본 localhost 라 Lab 동작은 그대로).
- 운영 이전 때 할 일: `MALL_ROOT_DOMAIN` 을 실제 도메인으로, Vercel 에 와일드카드 도메인 연결, Supabase 인증 허용 주소에 `https://*.<도메인>` 추가.
- 참고: proxy 가 모든 요청에서 돌므로(정적 파일 제외) 요청마다 아주 짧은 처리 시간이 더해진다.

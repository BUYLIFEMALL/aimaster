## 1. 비교 — 스마트스토어 상품등록 자동화 vs 쇼핑몰 빌더(v1.07 코드)
기준 코드: `smartstore-register/src/lib/smartstore/fields.ts`(`StoreDefaults`, 판매자센터 배송 칸을 그대로 옮긴 것) · 쇼핑몰 `src/lib/shipping.ts` + DB `mall_builder_shipping_policies`(0005).

| 항목 | 스마트스토어(네이버 판매자센터) | 쇼핑몰 빌더 지금 | 채택·이유 |
|---|---|---|---|
| 무료 | 무료 | `free` 무료 배송 | 그대로 |
| 유료(고정) | 유료 — 기본 배송비 | `fixed` 고정 배송비 | 그대로(이름만 「유료」로 맞춤) |
| 조건부 무료 | 기본 배송비 + ○원 이상 무료 | `conditional` | 그대로. **기본값 3,000원·5만 원 이상 무료**(주인님) |
| **수량별** | ○개마다 기본 배송비 반복 부과(예: 3개마다 3,000원 → 4개면 6,000원) | 없음 | **추가**(주인님 지시 「판매수량별」) |
| 구간별 | ○개까지 기본 배송비, 초과 구매 시 추가 배송비 1번(2구간) | 없음 | 추천: 함께 추가(같은 계산 자리에 칸 2개, 대형·무거운 상품에 씀) — 결정 2 |
| 제주/도서산간 추가 | 설정 안 함 / 2권역 / 3권역(제주·제주 외 도서산간) | 제주·도서산간 따로(=3권역) | 그대로(우리 쪽이 이미 3권역) |
| 묶음배송 | 가능 / 불가(개별 계산) | 같은 정책 상품끼리 항상 묶음 | 추천: 「불가(상품마다 따로)」 선택 추가 — 결정 3 |
| 결제 방식 | 착불 / 선결제 / 둘 다 | 선결제만(주문 때 함께 결제) | 넣지 않음 — 우리 몰은 주문 금액에 배송비를 함께 받는다 |
| 반품·교환 배송비 | 반품(편도)·교환(왕복) 금액 | 없음(교환·반품 화면에서 그때 정함) | 추천: 정책에 두 금액 칸 추가 → 상품 상세 「배송·반품 안내」에 표시 — 결정 4 |
| 택배사·설치비·지역별 차등 글 | 있음 | 택배사는 송장 입력 때 고름 | 넣지 않음(1차 범위 밖) |

## 2. 손볼 곳 (결정 1~4가 모두 「추가」일 때)
| 위치 | 내용 |
|---|---|
| DB 마이그레이션 `0065` | 정책 표에 칸 추가: `repeat_qty`(수량별 ○개마다), `range_upto`·`range_extra_fee`(구간별), `bundle`(묶음 가능 여부), `return_fee`·`exchange_fee`. 종류 제약에 `quantity`·`range` 추가. 배송비 계산을 **한 함수 `mall_builder_private.shipping_fee(정책, 금액 합계, 수량 합계, 지역)`로 모으고**, 지금 계산을 각자 들고 있는 **주문 함수 7개**(일반 주문 2·비회원 주문·견적 주문 2·부분 취소·공급사 배송비 정산 트리거)가 이 함수를 부르게 바꾼다. 묶음별로 금액뿐 아니라 **수량 합계**도 모은다. 묶음 불가 정책은 상품 줄마다 따로 매긴다. |
| `src/lib/shipping.ts` | 같은 계산(장바구니·주문서·견적 화면 미리 보기) + 안내 문구(「3개마다 3,000원」 등) + 입력 검사 |
| 관리자 「배송비」 화면 | 종류 고르기에 수량별·구간별, 칸 표시/숨김, 반품·교환 금액, 묶음 여부 |
| 공급사 배송비(0060) | 공급사도 같은 종류를 고를 수 있게(검사 함수 `supplier_shipping_apply`) |
| 상품 엑셀·프로셀 변환 | 배송비 정책은 이름으로 연결(바뀌지 않음) |
| 시험 | `tests/shipping.test.mjs`에 수량별·구간별·묶음 불가 계산, 시나리오 `scenario-0065-*.sql`(주문 함수 7개가 화면 계산과 같은 금액을 내는지) |
| 손님 화면 | 배송비 안내 한 줄은 `describePolicy` 문구만 바뀜(파일은 agy 범위라 손대지 않음) |

## 3. 위험과 대책
- 주문 함수 7개를 함께 바꾸므로, 화면 계산과 DB 계산이 다르면 「주문 금액이 바뀌었습니다」 오류가 난다 → 계산을 DB 함수 하나로 모으고, 시나리오에서 7개 경로 모두 화면 계산 값과 대조.
- 지금 있는 정책(`free`·`fixed`·`conditional`)과 지난 주문 금액은 그대로(새 칸은 비어 있으면 지금과 똑같이 계산).
- 0064처럼 함수 본문의 정해진 문구만 바꿔 끼우는 방식(문구가 정확히 1번 있을 때만 바꿈)으로, 다른 세션이 고친 부분을 덮어쓰지 않는다.

## 4. 결정 항목
1. **수량별 추가** — 주인님 지시(확정).
2. **구간별(○개까지 / 초과 시 추가 배송비)도 함께 추가할지** — 추천: 함께(계산 자리 같음, 추가 비용 거의 없음).
3. **묶음배송 「불가(상품마다 따로)」 선택 추가할지** — 추천: 추가(대형 상품·공급사 직배송에 필요).
4. **반품·교환 배송비 칸 추가할지** — 추천: 추가(정책에 저장, 상품 상세 안내와 교환·반품 처리 때 기본값). 손님 화면 표시는 agy에 요청.
5. **기본값** — 새 몰·시험 몰 기본 정책 「조건부 무료 3,000원 · 5만 원 이상 무료」(주인님 확정, Lab 시험 몰은 이미 이 값).

## 3. 분석 결과 — 우리 코드 쪽 (백엔드 담당이 정리)
1. **가장 먼저 필요한 것 = 테마 층**: 손님 화면 색·글꼴·모서리·간격을 CSS 변수(예: `--mall-primary`)로 빼고, 몰 설정의 테마 값으로 채운다. 지금은 색이 화면 코드에 박혀 있어 빌더가 색을 바꿀 길이 없다. 106 스타일 값을 **기본 테마 프리셋**으로 옮기면 지금 화면은 그대로 유지된다.
2. **편집 대상 범위 넓히기**: 지금 블록은 첫 화면만. 빌더는 헤더(로고·메뉴·검색)·바닥글·상품 목록/상세의 표시 옵션(카드 모양·열 수·배지)까지 다루되, 주문·결제·가격 계산 화면의 **동작**은 건드리지 않는다(표시만).
3. **미리보기 = 실제 그리기 코드**: 편집 화면 안에 손님 화면을 같은 컴포넌트로 그리고(iframe 또는 같은 트리), 클릭한 블록을 오른쪽 설정 칸에서 고치는 방식이 안전하다. 별도 미리보기 코드를 만들면 실제 화면과 어긋난다.
4. **저장은 기존 초안/게시 구조 재사용**: 테마·헤더·바닥글도 `mall_builder_pages`처럼 「초안 → 게시」로. 게시 전에는 손님에게 안 보임.
5. **분양몰 제한은 서버(DB)에서**: 화면에서 칸만 숨기지 말고 저장 함수가 분양몰의 금지 영역 저장을 거절해야 한다.
6. **외부 위지위그 라이브러리**: GrapesJS(BSD-3)·Puck(MIT)·Craft.js(MIT) 등 후보 — 라이선스 확인 후 **원본 코드 이식 규칙**(CLAUDE.md 「외부 소스 분석·이식 규칙」 — 허용 라이선스면 최대한 그대로 쓰고 출처·NOTICE)을 따른다. 블록 등록표(`blocks.ts`)와 어떻게 이을지가 선택 기준(Puck은 「컴포넌트 등록표 + JSON 저장」 구조라 지금 블록 구조와 가장 가깝다 — 플랜에서 비교해 정할 것).

## 4. 분석 결과 — 프로셀 몰 공개 화면
> 보조 분석 진행 중 — 끝나는 대로 이 칸을 채웁니다(화면 구역·스킨/테마 구조·편집기 단서·기능 후보). 관리자 디자인 편집기는 로그인 화면이라 공개 분석 범위 밖 — **프론트 담당이 플랜 단계에서 주인님께 프로셀 관리자 화면을 같이 보며 분석할지 여쭤 볼 것**(로그인은 주인님이 직접).
> 권리: 프로셀은 다른 회사 상용 프로그램 → 화면 구성·편집 방식·기능은 분석해 그대로 응용하되, **소스 코드는 복사하지 않고 새로 만든다**(CLAUDE.md 핵심 원칙 21).

## 7. 지켜야 할 규칙 요약
- 화면 문장은 모두 한국어, 동그라미 숫자 금지. 진행 안내는 「~하겠습니다./~했습니다.」.
- 커밋은 `node scripts/commit-paths.mjs "<메시지>" <경로>... --as <세션>`(공용 문서는 `safe-commit.mjs`), `git add -A`·`--no-verify` 금지.
- 비용 드는 일(빌드·유료 AI)은 사전 승인, 끝에 비용 리포트. 작은 수정은 모아서 배포.
- 화면 검수는 각자 정해진 브라우저의 보이는 창(Claude Code = ego lite 메인).
- 회원 기능의 AI 호출은 몰 대표 본인 키만.

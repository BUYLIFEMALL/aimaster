## 1. 지금 구조에서 확인한 것
- 주문 금액: `mall_builder_orders.subtotal`(상품) + `shipping_fee` = `total`. 주문 DB 함수 `mall_builder_place_order`(최신 0028)가 다시 계산하고, 화면의 `p_expected_total`과 다르면 막는다. 화면 계산은 `src/lib/pricing.ts`(바꾸면 둘 다 바꿈).
- 부분 취소(0021 `mall_builder_cancel_order_items`)는 남은 상품으로 `subtotal`·`shipping_fee`·`total`을 다시 계산하고, 차액을 환불(카드 0029)·외상 장부에 반영한다. → 쿠폰·포인트가 들어오면 **이 다시 계산에 할인을 넣어야 한다**(가장 위험한 곳).
- 비회원 주문은 별도 함수(0035 `mall_builder_place_guest_order`).
- 손님 표에 생일 칸이 없다 → 생일 쿠폰을 하려면 선택 칸을 추가해야 한다.
- 예약 실행: 이미 있는 cron-job.org 1분·10분 작업에 「자동 발급·포인트 소멸」을 얹을 수 있다(새 작업 없이).

## 3. 결정 항목 (주인님께 여쭐 것)
1. **범위**: 위 D17·D18 전부 할까요? (추천: 전부, 쿠폰 → 포인트 순서로 만들고 Lab 배포는 마지막에 1회)
2. **부분 취소·환불 규칙**: (추천) 쿠폰 할인은 그대로 두되 남은 상품 금액을 넘지 않게, 남은 금액이 최소 주문 금액 아래가 되면 할인 취소 금액만큼 환불에서 뺌 / 포인트는 현금(카드·입금·외상)부터 먼저 돌려주고 그래도 남으면 포인트로 돌려줌 / 전체 취소면 쿠폰(기간 안이면)·포인트 모두 되돌림
3. **B2B와의 관계**: (추천) 쿠폰마다 「사업자 등급가와 같이 쓰기」 선택(기본 끔), 견적 주문에는 쿠폰·포인트 안 씀, 외상 주문은 쿠폰·포인트 사용 가능
4. **비회원 주문**: (추천) 쿠폰·포인트 없음(회원 혜택으로 둠)
5. **생일 칸**: (추천) 손님 정보·가입에 선택 칸 「생일(월·일)」 추가, 연도는 받지 않음

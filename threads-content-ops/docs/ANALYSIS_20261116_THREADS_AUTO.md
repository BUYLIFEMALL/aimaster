# 외부 원본 분석 — threads-auto → AIMaster 쓰레드 프로그램 병합 검토 (2026-11-16)

- 원본: https://github.com/boksajang/threads-auto (최신 커밋 `bd2fec7`, 2026-10-21, `0.1.0-beta.3`)
- 라이선스: **MIT**(package.json `license`). boks-music·boks-youtube-finder와 같은 제작자(복사장).
- 형태: Electron 데스크톱 앱 + better-sqlite3 + Codex CLI + 크롬 확장 + 윈도우 네이티브 호스트(C#). 코드 약 1만 5천 줄.
- **이미 저장소에 사본이 있다:** `threads-content-ops/desktop/`(2026-10-05 반입 `843fad24f`, AI 호출을 AIMaster 웹 `/api/threads-content-ops/generate`로 돌리는 러너 `f432bdf26` 추가, 배포 대상 아님). 사본은 10-05 기준이고 원본은 10-21까지 갱신됨 — 사본과 다른 파일 14개(원본 쪽 갱신: 계정별 자동 댓글 켜기·끄기·취소, 품질 규칙·스케줄러 보강 등 + 사본 쪽 AIMaster 러너 변경).
- 비교 대상: 쓰레드 운영 5개(`threads-content-ops` v2.25 · `auto-threads-posting`(`threads/`) v1.34 · `threads-affiliate-poster` v1.87 · `threads-comment-reply` v1.29 · `threads-easy-planner` v1.52) + `comment-inbox` v1.10.
- 상태: **분석 완료 · 구현 전(주인님 결정 대기)**. 코드·DB 변경 없음. 사실 표는 [`docs/THREADS_FEATURE_MATRIX.md`](../../docs/THREADS_FEATURE_MATRIX.md) §2에 반영.

## 0. 먼저 — 기존 쓰레드 프로그램에 넣을 만한 기능인가

### 0-1. 새 프로그램이 필요한가
없다. 원본의 목적(여러 계정 운영·글감→생성→검수→예약 발행·댓글·성과)은 `threads-content-ops`(운영, 여러 계정 기준)와 같다. 운영은 페르소나·운영 계획 칸·4역할 API까지 만들어 두었지만 **실제로 웹에서 동작하지 않는 부분**이 원본의 핵심이다 → 기존 프로그램 보강.

### 0-4. 결론
- 본체는 **운영(`threads-content-ops`)**, 쇼핑 쪽은 **쇼핑제휴**가 같은 품질 규칙·광고 검사·인사이트를 받는다.
- 댓글·기획은 **지시문(규칙 문장)만** 받고, 포스팅·받은편지함은 넣지 않거나 선택.
- 원본 지시문은 의미 판정형이라 **원문을 거의 그대로 옮기는 것이 이식의 핵심**이다(MIT, 출처·NOTICE 표기).

- 네이버 브랜드커넥트는 공식 API가 없어 상품 정보를 얻으려면 **회원 PC의 크롬 확장이 회원 브라우저로 페이지를 읽는 방식**이 유일하다. AIMaster 규칙(쇼핑제휴 「웹에서 완성 → 확장」 흐름, 서버 고정 IP로 수집하지 않음)과 맞는다.

- 결정 필요: 확장 신규 개발(배포 ZIP·DB 버전 관리 포함), 후기 문장 저장은 회원 소유·30일 정리.

## 1. 비용

| 항목 | 내용 |
|---|---|
| 회원 AI 비용 | 다단계 검수로 글 1개당 호출 2~4회(작성 1 + 검토 1 + 재작성 최대 2). 회원 본인 키. 운영 계획 자동 실행 시 하루 게시 수만큼 늘어남 → 화면에 예상 호출 수 표시 필요 |
| 회원 Threads | 인사이트 권한 추가 시 **재연결 1회** 필요(본인 Meta 앱에 권한 추가) |
| 운영 비용 | 인사이트·운영 계획 실행 표 추가 시 DB 소량, 빌드 프로그램당 1~2 |
| 분석 비용 | 없음 |

## 2. 주인님 결정 항목
1. 범위: 운영 본체 + 쇼핑제휴(권장) / 운영만 먼저
2. 다단계 검수: 기본 켜기(권장, 글당 AI 2~4회) / 회원 선택
3. 운영 계획 자동 실행(요일·시간·비율대로 자동 생성·발행): 넣음 / 지금처럼 수동 — 자동 발행은 「회원이 고른 방식」·결과 불확실 시 재발행 금지 원칙 적용
4. 인사이트: 넣음(회원 재연결 필요) / 보류
5. 크롬 확장 후기 근거 수집: 넣음(쇼핑몰 화면 수집 — 회원 PC·회원 계정) / 보류
6. 운영 웹에 댓글 답글: 넣음 / 댓글 프로그램으로 넘기기만(권장 — 기능 겹침 방지)
7. 블로그 RSS: 기존 제외 결정 유지(권장) / 재검토

## 1. 문제
- 기획 앱은 운영 앱과 같은 일(페르소나·훅·본문·다시 쓰기)을 하지만 Threads 게시가 없고, 결과 사본을 회원 구분 없는 브라우저 저장소에 둔다.
- 운영 앱에는 기획 앱만의 장점 일부가 없다.

## 2. 범위 — 운영 앱으로 옮길 것
| # | 기능 | 기획 앱 위치 | 운영 앱에 넣을 곳 |
|---|---|---|---|
| 1 | 사진(최대 5장)·영상 5컷을 AI가 보고 글쓰기 | `src/lib/mediaProcessor.ts`(브라우저에서 JPEG 압축·영상 프레임 추출), `src/lib/ai/generator.ts` 이미지 입력 | 「콘텐츠 생성」(`AttentionComposer.tsx`)에 사진·영상 첨부 칸, `lib/attention.ts` `callJson`에 이미지 입력(OpenAI·Claude·Gemini 3사) |
| 2 | 요일·시간대 추천 주제·빠른 분위기 칩 | `src/lib/constants/luckyTopics.ts` | 「콘텐츠 생성」 주제 칸 옆 「추천 주제」 |
| 3 | 첫 댓글용 참여 질문 | 생성 결과 | 운영 앱 결과의 CTA와 비교해 없으면 추가(후속 주제 `followUpIdeas`는 이미 있음) |

- **운영 앱의 사실 원칙은 유지한다**: 기획 앱은 1인칭 체험담을 지어내지만, 운영 앱은 글감에 없는 경험을 지어내지 않는다. 사진·영상은 「회원이 직접 찍은 자료」로서 **사진에 보이는 사실만** 글감으로 쓰게 지시한다.
- 서버로 보내는 사진 크기: Next 서버 액션 기본 한도 1MB → 운영 앱 `next.config.mjs`에 `serverActions.bodySizeLimit`을 4MB로(Vercel 요청 한도 4.5MB 안). 브라우저에서 이미 압축해 보낸다.

## 3. 기획 앱 처리
- 주소는 지우지 않는다. 첫 화면(`/`)은 「Threads 콘텐츠 운영으로 옮겼습니다」 안내 + 이동 버튼으로 바꾼다.
- 보관함(`/saved`)은 **30일 동안 읽기 전용으로 남긴다**(저장된 기획은 30일 뒤 어차피 지워지는 자료라 옮기기 기능을 따로 만들지 않음 — 주인님 결정 2번을 기본값으로 정함). 브라우저 사본은 옮기지 않는다.
- 카탈로그: `programs.is_active=false`, 운영 앱 상세 소개에 기획 기능 추가.
- 권한: 기획 앱 권한 회원에게 운영 앱 권한을 같은 기간으로 부여(이미 있으면 긴 쪽 유지). 실행 전에 실제 겹침 수를 조회해 보고.
- 코드 정리는 30일 뒤 백업 폴더 + git 태그 뒤(이번 범위 아님).

## 4. 구현 순서
1. `docs/ACTIVE_WORK.md` 두 폴더 등록 → `programs` 두 행 백업 JSON(분석 폴더)
2. 운영 앱: 이미지 입력 엔진 → 생성 화면 첨부 칸·추천 주제 → 시험 추가(이미지 입력 요청 모양 3사, 사실 원칙 문구) → tsc·`npm test`·build
3. 기획 앱: 안내 화면·보관함 읽기 전용 → tsc·build
4. 커밋·푸시 → DB(크롬 SQL Editor): 권한 부여·카탈로그·버전 → 배포 2회(순차) → 크롬 검수(시험 회원: 운영 앱 사진 첨부 화면·추천 주제, 기획 앱 안내 화면)
5. 역량 지도 카드 「병합됨 → threads-content-ops(2026-10-23)」, 보고서 §6 진행 결과, HANDOFF, ACTIVE_WORK 정리

# PLAN 2026-10-19 — 인스타 예약 게시(자동 포스팅 2차) + 게시 기록 (v1.19)

> 주인님 지시: 「예약 게시 2차 진행해줘」 + 제안 1 「게시 기록(시각·게시물 주소)으로 중복 게시 방지」를 같은 작업으로 합침. DB 표 추가·`CRON_SECRET` 추가는 주인님 승인(「둘 다 승인」).
> 대상 DB: 운영 `esgxyikcnnvmlhygjkth`(① AIMaster). Lab(`labs/`) 무관.

## 문제
- v1.18은 「지금 게시」만 가능 — 올릴 시각을 정할 수 없고, 같은 카드뉴스를 두 번 올려도 알 방법이 없음.

## 범위
1. 게시 기록 표 `cns_insta_posts`(회원 본인 읽기 RLS, 30일 뒤 삭제).
2. 예약 등록·취소 API(`/api/cardnews/instagram/posts`), 예약 실행(`/dispatch`, Vercel 자동 실행 5분마다, `CRON_SECRET`).
3. 즉시 게시도 기록, 패널에 [지금/예약] 전환·기록 목록·중복 경고.
- 연결값은 v1.18과 같이 INSTA 포스팅 자동화의 `insta_accounts`(회원 본인)를 그대로 사용. 운영자 키 폴백 없음.

## 안전장치
- 두 번 게시 방지: `scheduled → publishing` 조건부 업데이트로 한 실행만 가져감.
- 게시 직전 이용 권한 재확인(만료·정지 회원은 게시하지 않고 실패 기록).
- 예약 시각 10분 뒤~60일, 회원당 대기 20건, 이미지 경로는 회원 폴더(`<userId>/insta/…jpg`)만.
- 30분 넘게 「게시 중」이면 실패 처리, 이미지는 게시·취소·실패·30일 정리 때 삭제.

## 검수
- 단위 테스트(시각 범위·한국 시간 변환·표기), tsc, 빌드, 배포 후 401 확인·자동 실행 등록 확인.
- 크롬: 임시 프로젝트로 먼 미래 예약 → 취소 → DB·이미지 삭제 확인 → 임시 데이터 삭제. 실제 게시 없음.

## 비용
- 개발·시험: 유료 AI 호출 없음. 운영자: Vercel 자동 실행(5분마다, 함수 호출 소량), 저장소 이미지는 게시 뒤 삭제. 회원: 인스타 게시는 무료(본인 계정).

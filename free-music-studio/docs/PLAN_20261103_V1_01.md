[내 PC 엔진 앱] 「AI 무료음악 자동화 엔진」 (원본 Electron 메인 프로세스에서 화면 제거·이름 교체)
  PC 사양 진단 · ACE-Step 1.5 자동 설치(SHA-256 고정) · 작업 대기열 · 생성/커버/Repaint/분리/LRC/마스터링 · 음원 파일 보관

- 연결 방식은 `video-to-gif` 「내 PC 고속 변환」(크롬 확장 + 네이티브 호스트)과 달리 **로컬 HTTP**로 한다 — 음원 파일(수 MB)을 주고받아야 해서 네이티브 메시지 크기 제한(1MB)에 걸리기 때문. 사전 검증 0단계에서 크롬이 `https` 페이지 → `127.0.0.1` 호출을 허용하는지 먼저 확인한다(막히면 확장 + 네이티브 호스트 방식으로 바꿈).
- 음원·분리 트랙은 회원 PC에 저장(서버 업로드 없음). 서버 DB에는 곡 정보·가사·설정만(생성 데이터 30일 보관, 관리자·시험 계정 예외 규칙 적용).

**2026-11-03 윈도우 시험에서 알게 된 것**
- 환경: ACE-Step 1.5 `ca1e85f`, Python 3.11(uv 가상 환경 `venv_xpu`), PyTorch `2.15.0+xpu`. 공식 안내의 Intel 시험 버전은 2.8.0. **(정정)** 서버 기록상 첫 실패는 1.7B 언어 모델을 그래픽에 올리다 `OUT_OF_DEVICE_MEMORY`·`OUT_OF_RESOURCES` → 생성 단계 `DEVICE_LOST`, 두 번째는 생성 중 서버 충돌(종료 코드 139) — **내장 그래픽 공유 메모리 부족이 직접 원인일 가능성이 크고**, 버전 차이는 함께 작용했을 수 있는 원인. 엔진 앱에서는 PyTorch 버전을 고정한다.
- 성공 4곡의 조건: `acestep-v15-turbo` + vae + text_encoder 모두 CPU, **언어 모델 끔**. CPU/GPU는 같은 계산이라 음질 차이는 사실상 없고 속도 차이 — 다만 GPU에서는 언어 모델·비 turbo 모델을 켤 수 있어 결과적으로 음질이 나아질 수 있음(마스터PC 5080에서 주인님 판정: 「SUNO보단 못하지만 들을만해」 — CPU 결과와 같은 판정).
- 음질 개선 후보(다음 단계에서 시험): 언어 모델 켜기(GPU 장비), turbo 외 모델·생성 단계 늘리기, 마스터링(LUFS 맞추기)은 5단계.
- 장치 지정 환경 변수는 `ACESTEP_DEVICE`(`PYTORCH_DEVICE`는 무시됨). 모델은 실행 위치 `checkpoints/`에 받는다.
- **원곡 파일 경로를 JSON으로 넘기면 거절**(「absolute audio file paths are not allowed」) → 엔진 앱은 `multipart` 파일 업로드(`src_audio`)로 보낸다.
- **크롬 → `127.0.0.1` 호출**: `https://www.buylife.xyz` 페이지에서 `fetch('http://127.0.0.1:8001/health')`가 CORS·no-cors 모두 8초 시간 초과, 서버 기록에 크롬 요청이 **도착하지 않음**(같은 순간 PC의 curl은 0.008초 응답). 크롬 「로컬 네트워크 접근」 권한 단계에서 멈춘 것으로 추정 — 주소창의 허용 창 여부는 캡처로 보이지 않아 **주인님 화면 확인 필요**. 허용 창이 있으면 「첫 사용 때 허용 1번」 안내로 해결, 없거나 막히면 **우리 크롬 확장(127.0.0.1 권한) 경유**로 바꾼다(네이티브 메시지가 아니라 확장의 fetch라 파일 크기 제한 없음).
- **보컬 분리 모델 BS-RoFormer 6stem은 쓰지 않음**: 이용 조건 「unknown」, 원제작자 계정 삭제 뒤 남은 사본. 후보: ACE-Step Extract(base 모델 필요) · Demucs v4(코드 MIT, 가중치 조건 확인 필요) — 5단계 전에 확정.
- 결론(잠정): **회원 PC 지원 장비 = NVIDIA(CUDA) · Apple Silicon(MLX) 권장, Intel 내장 그래픽은 「CPU 모드」로 동작**(30초 곡 약 1분 30초). 엔진 앱의 PC 사양 진단에서 Intel 내장 그래픽이면 CPU 모드를 기본으로 고른다.

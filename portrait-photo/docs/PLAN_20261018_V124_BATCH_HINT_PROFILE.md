## 1. 일괄 ZIP 저장도 같은 추천 영역 계산으로 통일
- **지금**: 일괄 검사(`autoCropBatch`)·규격 변경(`changePreset`)은 `decideBatchCrop` — 「작음」만 확대 영역을 지정하고, 「범위 안·큼」은 [범위 안 사진도 얼굴을 가로 중앙에 맞춤] 옵션을 켰을 때만 가운데 맞춤. 단일 [규격 저장](v1.23)과 결과가 다를 수 있음. 또 [규격으로 일괄 저장]은 지정 영역이 없으면 측정값이 있어도 가운데 자르기.
- **바꿈**: `decideBatchCrop`이 내부에서 `recommendSizedCrop`을 쓰게 해 단일 저장과 똑같이 판정(작음 → 확대, 범위 안 → 얼굴 가운데, 큼 → 머리가 잘리지 않게 위치만). 옵션 체크박스는 기본 동작이 되므로 정리. `saveSizedBatch`는 지정 영역 → 없으면 측정값 추천 영역 → 없으면 가운데 순서. 보고 문구의 「큼」을 "위치만 맞춤 · 다시 만들기 권장"으로.
- **테스트**: 기존 `decideBatchCrop` 테스트는 지우지 않고 기대값만 새 동작에 맞게 고침(범위 안 → 가운데 영역 생김, 큼 → 위치 맞춤 영역).

## 2. 머리 위치를 모를 때 [머리 비율 검사] 강조
- **지금**: 측정값이 없으면 [규격 저장]은 가운데 자르기이고, 저장한 뒤 안내 문구로만 알림.
- **바꿈**: 머리 기준이 있는 규격인데 지금 사진의 측정값이 없으면, 저장 버튼 줄 위에 안내 한 줄 + [머리 비율 검사 (AI 1회)] 버튼을 강조 표시(주요 버튼 모양) + [얼굴 위치 직접 지정 (무료)] 바로가기(자르기 패널을 직접 지정 모드로 열기 — 기존 `gotoCrop(..., true)` 흐름 재사용). 측정값이 생기면 원래 모양으로.

## 3. 프로필 사진 세트 — 플랜 정정
- **정정**: v1.23 보고에서 "AI 이미지 자동화의 프로필 크롭으로 넘기기"를 제안했으나, 조사해 보니 **ai-image-studio에는 프로필 크롭 기능도, 다른 프로그램 사진을 받는 화면도 없다**(`app/` 화면: dashboard·gallery·prompts·settings·guide). 그쪽에 새로 만들려면 사진 전달(다른 도메인 간 전송·저장소)·새 화면이 필요하고, 프로그램끼리 서로 호출하지 않는 원칙과도 부딪힌다.
- **추천안(A)**: 목표("증명사진과 프로필 사진을 한 번에")를 **인물사진 안에서** 이룬다 — [프로필 세트 저장] 버튼 하나로 같은 결과 사진·같은 머리 측정값을 써서 **SNS 정사각 1:1(1080×1080) · 세로 4:5(1080×1350) · 원형 프로필 PNG(1080, 투명 바깥)**를 ZIP으로 저장. 머리 위치가 있으면 얼굴 기준으로 구도(머리 약 40~45%), 없으면 위쪽 치우친 가운데 자르기. AI 호출 없음, 서버 저장 없음.
  - 순수 함수 `profileCrop(m, aspect, srcW, srcH)` + 단위 테스트, 화면은 기존 `canvas.ts` 렌더·`zip.ts` 재사용.
- **대안(B)**: ai-image-studio에 "다른 프로그램에서 사진 받기" 기능 신설 — 별도 작업(그 폴더·다른 CLI 작업 여부 확인, 도메인 간 전달 설계, 비용). 이번 범위에서 제외하고 원하시면 따로 플랜.

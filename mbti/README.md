# 성격코드 (mbti)

로그인 없이 누구나 즉시 이용하는 **공개 성격유형 테스트 웹사이트**. AIMaster 저장소 안의
서브프로젝트이지만, 기존 threads/blog 같은 "회원이 구독해서 쓰는 자동화 SaaS"와는 성격이
다르다 — 방문자 전체를 대상으로 하는 무료 바이럴 콘텐츠 서비스다(2026-09-14 사용자 결정).

## 설계 배경

### 왜 로그인/Supabase가 없는가
검사 응답과 결과 계산이 전부 클라이언트에서 끝나고(문항 20개 → 4개 지표 합산 →
`/result/[type]` 페이지로 이동), 서버에 저장할 사용자 데이터가 없다. 그래서 이
서브프로젝트는 루트 CLAUDE.md의 멀티테넌시 원칙(`requireProgramAccess`,
`user_api_keys` 등)을 의도적으로 적용하지 않는다 — 애초에 로그인이 필요 없는 무료
공개 서비스이기 때문이다. AIMaster 플랫폼과는 "가볍게"만 연동한다:
- 헤더에 "다른 프로그램 보기" 링크로 `buylife.xyz/programs`로 트래픽을 보낸다.
- `programs` 테이블에 카탈로그 항목으로 등록되어 있다(slug: `personality-code`,
  category: 기타, `supabase/migrations/0001_register_program.sql`). **다른 서브프로젝트와
  달리 `pricing_plans`/`grade_program_access` 행은 만들지 않았다** — 이 사이트는 로그인·
  구독이 전혀 필요 없는 완전 무료 서비스라(2026-09-14 사용자 결정: "요금제 없이 무료로만
  등록"), 유료 요금제를 붙이면 오히려 오해를 산다. 카탈로그 카드에는 `badges: ["free"]`로
  무료 표시만 해뒀다. `required_grade_id`는 다른 모든 프로그램과 동일하게 "일반"(최하위
  기본 등급) 값을 넣어뒀지만 카탈로그 표시 목적일 뿐, 실제 mbti 사이트 자체에는 어떤
  로그인·권한 체크도 없다.

### 왜 "MBTI"라는 이름을 쓰지 않았는가
공식 MBTI(Myers-Briggs Type Indicator)는 The Myers-Briggs Company의 등록상표이자
저작권이 있는 검사다. 서비스명은 상표 리스크를 피하기 위해 "성격코드"로 정했고
(2026-09-14 사용자 확정), 문항(`lib/questions.ts`)과 유형 설명(`lib/types.ts`)도
전부 자체 제작했다 — 공식 검사 문항이나 리포트를 그대로 베끼지 않았다. 다만 융(Jung)
심리유형론에서 유래한 4개 이분지표(E/I, S/N, T/F, J/P)와 16개 유형 코드(INFP 등)
자체는 업계 전반에서 통용되는 일반적인 분류 개념이라 자유롭게 참고했다.

### 채점 방식
문항마다 5점 리커트 척도(1=전혀 아니다 ~ 5=매우 그렇다)로 응답받아 지표별 점수를
합산하고, 중간값 기준으로 좌/우 극을 결정한 뒤 0~100% 스케일로 정규화해 "얼마나 그
쪽으로 기울었는지" 강도까지 함께 보여준다(`lib/scoring.ts`). 개발자 커뮤니티 리서치
결과, 이분법(양자택일) 문항보다 리커트 척도가 편향을 줄이고 강도(%)까지 공유 카드에
넣을 수 있어 이 방식을 택했다.

`scoreAnswers(questions, answers)`가 문항 배열을 그대로 받아 지표별 문항 수에서
점수 범위(최소/최대/중간값)를 동적으로 계산하므로, 문항 수가 다른 두 검사를 하나의
채점 로직으로 처리한다:
- **빠른 검사**(`/test`, `QUICK_QUESTIONS`): 지표당 5문항 × 4지표 = 20문항, 약 2분.
- **정식 검사**(`/test/full`, `FULL_QUESTIONS`): 지표당 15문항 × 4지표 = 60문항, 약
  10분. `QUICK_QUESTIONS`를 그대로 포함하고 지표당 10문항씩 추가한 상위 집합이다
  (실제 심리검사에서도 단축판이 정식판 문항의 부분집합인 경우가 흔한 설계 방식).
  문항이 많을수록 한두 개 애매한 응답의 영향이 줄어 신뢰도는 높아지지만 완주율은
  낮아지므로(2026-09-14 사용자 질문에 대한 답변), 두 버전을 병행 제공해 사용자가
  선택하게 했다. 결과 URL에 `?mode=full` 파라미터를 남겨 결과 페이지에 "정식판(60문항)
  결과" 배지를 표시하고, "다시 검사하기" 링크도 원래 봤던 버전으로 돌아가게 한다.
  60문항도 같은 지표가 연달아 나오면 패턴을 눈치채고 기계적으로 답할 수 있어
  `lib/questions.ts`의 `interleave()`로 4개 지표를 라운드로빈으로 섞어서 출제한다.

### 공유 카드(OG 이미지)
`app/api/og/route.tsx`가 `next/og`의 `ImageResponse`로 유형별 결과 카드를
요청 시점에 동적 생성한다(`/api/og?type=INFP`). 카카오톡/인스타그램에 결과 링크를
공유하면 이 이미지가 미리보기로 뜬다 — 링크만 눌러도 결과가 바로 보이는 게
재확산의 핵심이라는 리서치 결론을 반영했다.

```
NEXT_PUBLIC_MAIN_SITE_URL=  # https://buylife.xyz (기본값에 이미 하드코딩되어 있어 선택사항)
NEXT_PUBLIC_KAKAO_JS_KEY=   # 카카오 디벨로퍼스 앱의 JavaScript 키(REST API 키 아님).
                            # 카카오 디벨로퍼스 "플랫폼 키 > JavaScript 키" 화면에서 이
                            # 사이트 도메인(https://mbti-rho-two.vercel.app)을 "JavaScript
                            # SDK 도메인"으로 등록해둬야 실제로 동작한다(2026-09-14 등록 완료).
                            # 값이 없으면 KakaoScript가 아예 렌더링되지 않고, 카카오톡 공유
                            # 버튼도 조용히 숨겨진다(다른 공유 버튼은 그대로 작동).
```

## 배포

다른 서브프로젝트와 동일하게 자체 Vercel 프로젝트로 `vercel deploy --prod` 배포한다.

## 알려진 로컬 개발 환경 이슈 (Windows)
`/api/og`(`next/og`의 `ImageResponse`)는 Next.js 14.2.35에 번들된 `@vercel/og`가 기본
폰트를 `file://` 경로로 읽어오는 과정에서 `path.join`을 URL 문자열에 그대로 적용해
Windows에서 `Invalid URL` 오류가 난다(`join(import.meta.url, ...)`가 백슬래시 경로와
섞여 깨짐 — `node_modules/next/dist/compiled/@vercel/og/index.node.js` 상단의
전역 초기화 코드에서 발생, 직접 넘긴 커스텀 폰트 유무와 무관하게 항상 실행됨). `next dev`,
`next start` 모두 Windows에서는 동일하게 실패하는 것을 확인했다. Linux 기반인 Vercel
배포 환경에서는 경로 구분자 문제가 없어 정상 동작할 것으로 보이며, 실제 배포 후 확인해야
한다. Windows에서 로컬 확인이 필요하면 WSL2 안에서 `npm run dev`를 실행할 것.

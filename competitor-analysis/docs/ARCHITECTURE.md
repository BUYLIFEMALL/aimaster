그대로는 옮길 수 없다. 자세한 대응표는 [README.md](../README.md)의 "원본 대비 바뀐 점" 참고.

## 회원별 회사 조사와 30일 보관 — 2026-10-16 정책 정정

초기 전역 회사정보 캐시는 최상위 개인 계정/API·생성 데이터 격리 원칙에 위배되므로 폐기합니다. 비용 절감이나 공개 회사정보라는 이유로 회원 A의 생성물을 B에게 제공하지 않습니다.

후보 v1.08은 `competitor_company_profiles(user_id, domain, created_at, ...)`를 사용합니다. 회원별 도메인에 여러 조사 버전을 저장할 수 있고 가장 최근의 유효한 **본인** 조사만 사용합니다. 다른 회원에게 같은 도메인의 자료가 있어도 본인 API로 새 조사합니다. 재조회·HTML 리포트 갱신은 원래 생성일을 연장하지 않습니다.

RLS는 소유자와 30일 만료를 확인합니다. 생성 시각은 DB가 확정하고, 새 조사는 별도 행으로 저장합니다. 소유자 없는 옛 자료는 소유자를 추정하거나 회원에게 복제하지 않습니다. 옛 `competitor_profiles`의 일반 회원 권한을 폐쇄합니다.

검색 회차·결과·분석 리포트·회사 조사는 30일 보관, 키워드 정의·추적 설정·API 키·권한·계정은 별도입니다. 만료 시 조회에서 제외하고 매시 07분 UTC에 전용 `cleanup_competitor_generated_data()`를 postgres Cron이 실행해 실제 삭제합니다(보통 최대 1시간 이내; 실행 장애 시 지연될 수 있어 Cron 이력 확인). 함수는 SECURITY INVOKER, 일반 회원·anon·service_role 직접 실행 금지이며 다른 프로그램/Storage를 건드리지 않습니다.

**운영은 v1.07이며 위 스키마·Cron은 승인 대기인 전환안입니다.** [승인 범위·재개 순서·증거](MEMBER_RETENTION_HANDOFF_20261016.md)를 읽은 후 적용합니다. 0001 마이그레이션은 과거 이력이며 현행 설계 승인 근거로 사용하지 않습니다.

## Google Docs 제거

원본이 SERP 결과를 Google Docs에 계속 append했다가 나중에 다시 읽어서 GPT에 넘긴 건, Make.com의
모듈 간 데이터 전달(특히 배열/반복 처리 결과를 모아서 다음 단계로 넘기는 것)이 번거로워서 택한
임시방편으로 보인다. 실제 Next.js 서버 액션 안에서는 그냥 배열 변수에 모아뒀다가 그대로 GPT
프롬프트에 넣으면 되므로, Google Docs 연동 자체가 불필요하다 — OAuth 연동 관리 부담도 같이
사라진다.

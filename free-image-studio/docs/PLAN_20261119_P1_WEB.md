## 5-2에서 정한 것

- 접수 번호는 보내기 전에 기록한다. 응답을 못 받으면 `unknown` — 스스로 다시 보내지 않는다. `confirm()`이 목록에서 같은 번호를 찾으면 `accepted`, 못 찾으면 `unknown` 그대로다.

  - **작업 번호가 없는 접수됨**은 목록에 접수 번호가 같은 줄이 있어도 채택하지 않는다. 「엔진에 확인」으로 같은 범위에서 작업 번호를 되찾은 뒤에만 저장·조작이 열린다.

- 처리 순서를 `src/lib/convert/handler.ts`(순수 함수)로 옮겼다. 경로 파일은 그것을 부르기만 한다 — 시험한 순서가 그대로 쓰인다. 순서: **이용 권한 → 출처 → 본문 크기 → JSON → 동의 표시 → 변환**. 키 조회와 AI 호출은 앞 단계를 모두 통과한 뒤에만 일어난다(각 단계에서 0인 것을 시험으로 고정).
- 출처: 호스트만 보던 것을 **스킴·호스트·포트가 모두 같은 정확한 origin**으로. Origin 머리글이 없거나 "null"이거나 경로가 붙은 값은 거절.
- 본문 상한: 글자 수가 아니라 **바이트**(32KB — 가장 큰 정상 요청 24줄 × 한글 300자가 약 23KB). Content-Length가 넘으면 읽지 않고, 흘려 읽는 도중 넘으면 그 자리에서 끊는다. 깨진 UTF-8은 받지 않는다.
- 장수 보존: 변환된 영문이 줄 끝 장수 표시(`x2`·`X2`·`*2` 등)로 읽히면 — **실제 묶음 파서(`parseEntries`)에 물어서** — 서버가 응답 전체를 거절한다. 화면도 같은 검사를 하고, 바꾼 줄을 파서로 다시 읽어 설명·장수가 변환 전과 같은지 확인한 뒤에만 반영한다(다르면 한 줄도 바꾸지 않음). 지시문에도 「배수 표시로 끝내지 말 것」을 넣었다. 그런 이름으로 끝나는 줄은 「영문으로 직접 적어 주세요」로 안내한다.
- 동의·중복 누름의 범위(있는 그대로)
  - 동의 기록은 **브라우저에만** 있다(회원별). 서버는 동의를 저장하지 않고, 요청 본문의 `consent: true` 표시가 없으면 거절한다 — 실수로 만들어진 요청이 유료 호출로 이어지지 않게 하는 장치이지, 서버가 회원의 동의 이력을 증명하는 것은 아니다.
  - 중복 누름: 화면 하나 안에서는 `singleFlight`가 실행 중 다시 누른 것을 버린다(버튼 비활성보다 먼저 막는다). **탭을 두 개 열어 각각 누르면 두 번 호출된다** — 서버는 같은 내용의 요청을 걸러 내지 않는다.
- 공용 기준 코드 사본 목록 등록은 Master 지시대로 별도로 둔다(이 커밋에서 하지 않음).
- 시험 129개(새 파일 `tests/convertGuard.test.mjs` 5개). 실제 브라우저의 연속 누름·실제 요청 스트림은 미검증.
- 5-3까지 넣지 않은 것: 한글 변환·글 모델 선택은 5-4에서 넣었다(아래). 사양 지원 문구·요금·무료 배지는 여전히 넣지 않았다(8GB 문구와 접수 기록 손상 안내는 5-5).

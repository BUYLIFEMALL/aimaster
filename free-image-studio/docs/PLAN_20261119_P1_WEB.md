## 5-2에서 정한 것

- 엔진 주소는 `http://127.0.0.1:47821` 고정. 환경변수·설정·사용자 입력으로 바꾸지 않는다.
- 연결 기록과 접수 기록은 로그인 회원 번호별 칸(`fis.engineToken.v1:<회원>`·`fis.submissions.v1:<회원>`). 연결 기록은 `{ v: 2, token, link }` 한 덩어리로 한 번에 저장한다 — 토큰과 범위 표시가 따로 저장돼 어긋나지 않는다. 이 모양이 아닌 값(이전 형식의 토큰 문자열 등)은 연결로 치지 않는다. 회원이 바뀌면 화면이 `dispose()`를 불러 늦게 온 응답을 버린다.
- 접수 번호는 보내기 전에 기록한다. 응답을 못 받으면 `unknown` — 스스로 다시 보내지 않는다. `confirm()`이 목록에서 같은 번호를 찾으면 `accepted`, 못 찾으면 `unknown` 그대로다.
- 엔진이 넣기 전에 막은 것이 확실한 응답(401·403·409·429·503, 사전 검사 문구의 400)만 `rejected`. 그 밖의 400·서버 오류·응답 유실은 `unknown` — 엔진은 작업을 목록에 넣은 뒤 파일 저장을 기다리므로 저장 실패가 400으로 올 수 있다. 자동 재시도 없음.
- 맥미니 검수(`.ai/results/IMG-P1-5-2-CX-QA-01.md`) 반례 4건 보완:
  - 접수 기록을 **연결 범위 표시(`link`)** 에 묶는다. 엔진이 「이전 범위를 이어받았다」고 답한 다시 연결에서만 표시가 유지된다. 연결 끊기·토큰 무효·다시 연결 응답 유실 뒤의 새 범위에서는 과거 접수를 확인도 다시 보내기도 하지 않는다(엔진의 중복 방지는 범위 안에서만 듣는다).
  - **목록에 없다는 것만으로는 미접수를 확정하지 않는다**(Master `msg_99ebb68cdcff`). 지금 엔진에는 「받지 않았다」를 알려 주는 응답이 없고, 끝난 작업은 100개·30일 기준으로 정리되거나 엔진 창에서 지워질 수 있다. 앞선 작업이 남아 있어도 대상 작업만 사라졌을 수 있으므로 `confirm()`은 같은 번호를 **찾았을 때만** `accepted`로 확정하고, 못 찾으면 `unknown`(`notListed`)이다. 처음 보완에서 넣었던 「앞선 작업이 남아 있으면 미접수」 기준은 이 반례로 폐기했다.
  - `resend()`는 넣기 전 거절이 확실하고 다시 해 볼 만한 접수(대기열 가득 참·잠시 뒤·엔진이 닫힘·연결 필요)만 같은 번호·같은 내용으로 보낸다. `unknown`은 다시 보내지 않는다.
  - 접수 번호마다 확인·보내기를 한 번에 하나만 하고, 결과를 적을 때 지금 상태를 다시 본다. 접수됨을 옛 응답이 되돌리지 않는다.
- 맥미니 추가 반례 3건 보완: 작업 줄을 엔진 응답 계약대로 검사(번호 UUID·종류 그림·상태 여섯 가지·접수 번호 형식 — 하나라도 어긋나면 목록·접수 응답을 믿지 않고 상태를 그대로 둔다), 연결 기록 단일 저장(저장 실패 시 새 토큰과 옛 범위가 섞이지 않음), 늦게 실패한 전송은 기록이 아직 「보내는 중」일 때만 반영(다른 화면이 확인한 접수됨을 덮지 않음).
- 화면에서 지킬 것(5-3): `unknown`으로 남은 접수는 「엔진이 이미 그렸을 수 있습니다. 새로 맡기면 같은 그림이 두 번 나올 수 있습니다」를 보여 주고 사용자가 고르게 한다(기록 지우기는 `forget(id, { force: true })`). 자동으로 새 번호를 만들어 넣지 않는다.
- 남는 불편: 응답이 끊긴 접수는 엔진이 실제로 못 받았더라도 자동 복구되지 않고 사용자 선택이 필요하다. 엔진이 접수 번호 단건 조회나 「받지 않음」 응답을 주면 풀린다(개선 제안).

## 5-3에서 정한 것

- 화면 세 개: `/start`(엔진 켜기 → 연결 → 모델 준비), `/create`(용도 4 → 비율 3 → 설명 여러 줄 → 일괄 시작), `/jobs`(진행·결과·동작). 첫 주소 `/`는 `/start`로 보낸다.
- 한 묶음은 그림 24장까지(줄마다 장수의 합). 넘거나 한 줄이라도 문제가 있으면 한 장도 맡기지 않는다.
- **장수는 줄마다 1장 또는 2장, 기본 1장**(플랜 4-2절, Master `msg_ded0ccd52d9a`). 줄 끝에 `x2`(또는 `×2`·`*2`)를 적으면 그 줄만 2장이고, 화면의 줄 목록 버튼이 그 표시를 고쳐 준다. 표시가 글 안에 있어 줄을 끼우거나 지워도 장수가 줄을 따라간다. `x3` 같은 값은 그 줄의 오류다. 그림마다 접수 번호와 시드가 따로다(한 줄의 두 장 포함).
- 처음 5-3에서는 묶음 전체에 1장 또는 2장이었다. 그 값(`copies`)은 지금도 「표시가 없는 줄의 기본 장수」로 읽고, 그렇게 적어 보관해 둔 내용은 되돌릴 때 줄마다 장수로 옮긴다(2장이 1장으로 바뀌지 않는다). 맡기다 만 묶음의 보관 형식은 그대로다.
- 만들기 화면에 적던 내용(줄·줄마다 장수·용도·비율)을 회원별로 보관해 새로고침 뒤 되돌린다. 맡기고 나면 비운다.
- 용도 프리셋은 영문 틀에 사용자의 영문 설명을 끼운다. 사람이 나오고 나라·지역을 밝히지 않은 설명에만 한국인 기본값을 붙인다. 모델 구성은 엔진이 이 PC에 고른 것을 따른다(웹은 사양을 판단하지 않고 사양 문구도 쓰지 않는다 — 엔진이 준 문장만 그대로 보인다).
- 맡기는 중인 묶음을 회원별로 보관해, 새로고침 뒤 「남은 장 이어서 맡기기」가 된다. 이미 접수 기록에 있는 그림은 상태가 무엇이든 건너뛴다(제목·설명·크기·시드로 짝을 맞춘다).
- 작업 기록의 동작은 상태마다 정해져 있다: 대기·그리는 중 → 취소 / 완료 → 저장·다시 만들기·지우기 / 실패·중단·취소 → 다시 시작·지우기 / 접수 안 됨 → (다시 해 볼 만하면) 다시 보내기·기록에서 지우기 / 확인 필요 → 엔진에 확인·새로 맡기기·기록에서 지우기. 「새로 맡기기」는 「같은 그림이 두 번 나올 수 있습니다」 확인 창을 거친다.
- 「모두 멈추기」는 자기 작업을 하나씩 취소한다(엔진에 일시정지 없음). 다시 그리려면 줄마다 「다시 시작」.
- 저장: 접수 번호가 들어간 파일 이름, 같은 그림은 한 번만 쓴다(「다시 저장」은 같은 이름으로). 크롬 계열은 폴더를 골라 바로 쓰고, 그 밖의 브라우저는 내려받기.
- 넣지 않은 것: 한글 변환, 글 모델 선택, 사양 지원 문구, 요금·무료 배지, API 키 화면(시험이 화면·로직 소스를 검사한다).

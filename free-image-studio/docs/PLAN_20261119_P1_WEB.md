## 5-1에서 정한 것

- 프로그램이 `programs`에 등록되기 전에는 `not_found` → 메인 사이트 프로그램 목록으로 보낸다(관리자 포함). 배포를 먼저 하고 등록을 나중에 해도 문이 열리지 않는다.
- 판정 뒤 처리(어디로 보낼지·어떤 오류로 답할지)는 `src/lib/accessDecision.ts`의 순수 함수로 빼서 설치 없이 시험한다.
- 미들웨어(`src/proxy.ts`)는 쿠키 갱신만 하고 차단은 레이아웃·API 판정이 맡는다(쿠키를 지우는 처리 없음 — 2026-10-10 사고 재발 방지).
- 맥미니 검수(`.ai/results/IMG-P1-5-1-CX-QA-01.md`) P2 세 건 보완: 미들웨어가 갱신된 쿠키를 다음 단계로 넘김, 세션 응답에 캐시 헤더, 로그인 액션이 `safeInternalPath` 하나만 사용(정규화 뒤 `//바깥`이 되는 입력도 거절). P3(로그인 화면 규격·label)은 5-5.
- 로그아웃은 Server Action(`signOutAction`)이라 별도 API 주소가 없다.

## 5-2에서 정한 것

- 엔진 주소는 `http://127.0.0.1:47821` 고정. 환경변수·설정·사용자 입력으로 바꾸지 않는다.
- 토큰과 접수 기록은 로그인 회원 번호별 칸(`fis.engineToken.v1:<회원>`·`fis.submissions.v1:<회원>`). 회원이 바뀌면 화면이 `dispose()`를 불러 늦게 온 응답을 버린다.
- 접수 번호는 보내기 전에 기록한다. 응답을 못 받으면 `unknown` — 스스로 다시 보내지 않고, `confirm()`(목록에서 같은 번호 찾기) 뒤 엔진에 없을 때만 `resend()`가 같은 번호·같은 내용으로 보낸다.
- 거절이 분명한 응답(400·401·403·409·429·503)은 `rejected`, 서버 오류·응답 유실은 `unknown`. 자동 재시도 없음.
- 엔진에 없는 것은 그대로다: 일시정지·토큰 폐기 주소 없음(연결 끊기는 브라우저 토큰만 지움).
- 엔진을 실행하지 않았다. 모의 엔진(`tests/mockEngine.mjs`)이 계약을 흉내 내고, 「계약 대조」 시험이 엔진 소스의 해당 줄 23곳과 크기 목록을 읽어 어긋남을 잡는다.

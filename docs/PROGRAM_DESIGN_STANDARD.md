## 1. 지침 개요 및 디자인 철학 (Design Philosophy)

### 1.1 배경 및 문제의식
현재 AIMaster 내 82개 이상의 서브프로그램들은 기능 구현과 자동화 로직에 집중하다 보니, 흰색 사각형 카드 안에 단순 입력창과 텍스트만 나열된 **차갑고, 밋밋하며, 딱딱한 엔지니어링 인터페이스**에 머물러 있었습니다.
사용자 관점에서는 "내가 지금 어떤 단계에 있는지", "다음에 무엇을 해야 하는지", "이 버튼을 누르면 어떤 결과가 나오는지"가 직관적으로 와닿지 않는 아쉬움이 있었습니다.

### 1.2 디자인 목표
1. **직관적인 사용성 (Intuitive UX)**: 설명서를 길게 읽지 않아도 한눈에 사용 흐름이 보이고, 마우스를 올리는 순간 무엇을 해야 할지 바로 알 수 있는 디자인.
2. **고급스럽고 정돈된 심미성 (Aesthetic & Premium)**: 배경색은 **기본 흰색(Light)과 검정색/다크(Dark)를 메인**으로 하되, 프로그램의 성격이나 상황에 따라 **필요 시 다른 색상(차콜, 딥 네이비, 크림, 미드나잇 등)도 유연하게 적용**(2026-10-16 주인님 확정). 섬세한 보더, 부드러운 그림자, 정교한 마이크로 인터랙션을 통해 상용 SaaS 수준의 완성도와 고급스러움을 전달.
3. **생동감 있는 비주얼 장치 (Contextual Visuals)**: 실제 작업 상황을 대변하는 한국인 실사 사진, 프로세스 다이어그램, 친근한 안내 아바타/캐릭터, 세련된 이모티콘을 적극 활용하여 작업의 재미와 이해도를 극대화.
4. **작업 전 디자인 플랜 제시 및 사전 수락 의무 (2026-10-16 주인님 확정)**: 디자인 작업 전 반드시 **작업 플랜, 비주얼 컨셉, 스타일 템플릿 명칭, 그렇게 만들려는 이유**를 명시하여 주인님께 보여드리고, 주인님의 확인 및 수락을 받은 후 구현에 착수.
5. **이모티콘 및 아이콘의 프로그램 스타일 맞춤 색상화 (2026-10-16 주인님 확정)**: 사이드바 메뉴, 헤더, 액션 카드 등에 사용되는 이모티콘 및 아이콘(Lucide Icons 등)의 색상은 단조로운 무채색에 머물지 않고, 해당 프로그램의 고유 스타일 템플릿과 브랜드 컬러(예: 이커머스 로열 블루/오렌지, 수노 앰버/바이올렛, 사이버네온 사이언/퍼플 등)에 어울리도록 유연하게 수정·적용 가능. 열쇠(API키), 책(사용안내), 스튜디오(핵심기능), 로그아웃 등 상징적인 아이콘을 사용해 직관적 사용성을 극대화.
6. **디자인 리뉴얼 착수 전 프로그램 분석 기반 플랜 및 개선사항 인수인계서 작성 의무 (2026-10-16 주인님 확정)**: 디자인 리뉴얼에 착수하기 전 반드시 프로그램 기능·로직·라우트·외부연동 상태를 심층 분석하고, `<프로그램>/docs/PLAN_YYYYMMDD_DESIGN_RENEWAL.md`(디자인 리뉴얼 개발플랜) 및 `<프로그램>/docs/IMPROVEMENTS.md` / `<프로그램>/docs/IMPROVEMENT_HANDOFF_YYYYMMDD.md`(프로그램 개선사항 제안 인수인계서)를 해당 서브프로그램 폴더에 필수 작성하여 저장. 다른 CLI(Codex, Claude Code, Antigravity 등)가 투입되더라도 해당 폴더의 문서를 먼저 읽고 작업 흐름 단절 없이 즉시 이어서 개발할 수 있도록 체계화.
7. **미구현 프로그램 발견 시 매뉴얼 메뉴 및 단계별 사용 매뉴얼 추가 기본 의무 (2026-10-16 주인님 지시)**: 어떤 프로그램이든 작업 중 좌측 사이드바에 매뉴얼 메뉴가 없거나 가이드 페이지가 구현되지 않은 것을 발견하면, 이를 기본 필수 작업으로 간주하여 즉시 추가. 좌측 사이드바 유틸리티 영역에 `📖 연동 & 사용 매뉴얼` 메뉴를 추가하고, 프로그램 사용법을 초보자도 쉽게 따라 할 수 있도록 단계별(Step-by-Step, 4~5단계) 파이프라인 구조와 FAQ를 갖춘 사용 매뉴얼 페이지(`/guide` 또는 `?tab=guide`)를 전면 구축.
8. **작업 완료 시 결과·추가개선 항목별 정리, 프로그램 링크 제공 및 프로그램별 인수인계 문서 작성 의무 (2026-10-16 주인님 지시, 2026-10-17 제안항목 규격화)**: 작업이 완료되면 결과 보고 시 항상 ① 작업한 내용과 ② 「추가개선 제안」(해당 프로그램 및 타 프로그램 탐색 제안)을 항목별로 체계적으로 정리하여 보고하고, ③ 작업 프로그램의 실제 서비스 배포 링크(URL)를 필수로 남깁니다. **「추가개선 제안」 필수 3대 항목**: 1) 프로그램 로직 및 기능 개선, 2) 사용자 인터페이스/UI 가독성, 사용편리성 개선, 3) 현재 만들어져 있는 다른 자동화 프로그램과의 연계가능한 기능. 또한 각각의 항목에 대한 상세 내용을 해당 프로그램 서브폴더 안에 인수인계 문서(`<프로그램>/docs/DESIGN_HANDOFF.md`, `<프로그램>/docs/IMPROVEMENTS.md`, `<프로그램>/docs/IMPROVEMENT_HANDOFF_YYYYMMDD.md`)로 반드시 작성해 남깁니다.
9. **프로젝트 제안 및 보고 시 클릭 가능한 정확한 링크 제공 의무 (2026-10-16 주인님 지시)**: 앞으로 어떤 프로그램이든 다음 작업 대상을 제안하거나 결과 보고를 할 때는, 사용자가 클릭했을 때 즉각 브라우저에서 열릴 수 있도록 Supabase 공유 DB(`programs.app_url`) 및 Vercel에 정식 연결된 실제 공식 도메인 URL을 반드시 사전 확인한 후 링크를 제공합니다. 표(Table) 내부에서 `<br>` 태그로 텍스트와 링크를 함께 넣어 주소와 설명이 한 줄로 찌그러지거나 링크가 깨지는 현상을 엄격히 금지하며, 단독 줄의 명확한 마크다운 하이퍼링크(`[URL](URL)`) 또는 독립 카드형 불릿 레이아웃으로 작성하여 클릭 한 번으로 새 창에서 안정적으로 접속할 수 있도록 합니다. 도메인 변경 시 Vercel Alias/SSL 발급 및 DB `programs.app_url` 동기화를 필수로 진행합니다.
10. **작업 종료 즉시 상태를 「✅ 1차 작업완료」로 변경 의무 (2026-10-16 주인님 지시)**: 모든 빌드, Vercel 배포, 브라우저 실세션 검수, 인수인계 문서 작성이 완료되면 작업 종료 즉시 `DESIGN.md` 전체 프로그램 디자인 현황판의 상태를 「✅ 1차 작업완료 (`vX.YY`, 템플릿명)」로 반드시 변경하고 `docs/ACTIVE_WORK.md`의 작업 중 행을 삭제합니다. 이를 통해 다른 CLI들이 작업 완료 사실을 한눈에 파악하고 대기 없이 다음 프로그램 작업에 즉시 착수할 수 있도록 합니다.
11. **프로그램 내 전체 페이지 단일 배경색 및 일관된 테마 스타일 준수 의무 (2026-10-16 주인님 지시)**: 하나의 자동화 프로그램 안의 모든 페이지(대시보드, 작업 스튜디오, 프로젝트/보관함 목록, 가이드/매뉴얼(`/guide`), 설정 등)는 반드시 동일한 배경색상과 통일된 디자인 템플릿 테마 스타일로 일관되게 구축해야 합니다. 특정 페이지만 다크/라이트 테마가 다르거나(예: 매뉴얼만 블랙이고 스튜디오/보관함은 화이트인 경우 등) 배경색이 어긋나는 화면 불일치를 엄격히 금지하며, 전 화면의 배경색, 카드 서피스, 텍스트 대비, 테두리 스타일을 통일합니다.
12. **로그인/회원가입 화면 표준 레이아웃 준수 (2026-10-17 주인님 확정)**: 모든 서브프로그램의 로그인 및 회원가입 안내 화면은 공식 표준 탭 토글 레이아웃(`(auth)/login/page.tsx` & `(auth)/layout.tsx`)을 동일하게 적용합니다. 은은한 24px 격자 모눈 배경, 상단 프로그램 타이틀 + 안내 문구, 둥근 모서리 카드, 상단 `[로그인]` / `[회원가입]` 2버튼 탭 토글 바, 로그인 폼(이메일/비밀번호/비밀번호 찾기/로그인 버튼), 회원가입 안내 탭(AIMaster 계정 및 구독 권한 안내 + 메인 사이트 회원가입 버튼), 하단 이용약관 및 개인정보 처리방침 푸터 링크 구조를 통일합니다. 단, 배경색, 카드 서피스, 버튼 컬러, 브랜드 이모티콘은 프로그램 고유 테마에 맞추어 유연하게 변경할 수 있습니다. (기준 구현: `threads-comment-reply`)
13. **디자인 리뉴얼 작업완료 보고 시 타 프로그램 탐색 기반 추가개선 제안 리포팅 의무 (2026-10-17 주인님 지시)**: 디자인 리뉴얼 및 서브프로그램 작업 완료 보고 시, 완료된 해당 프로그램의 결과 보고에만 머무르지 않고, 전체 플랫폼 내 다른 서브프로그램들을 함께 둘러보며(카탈로그, 라우트, UI/UX, 외부연동, 안내문구, 테마 일치성, 모바일 반응형 등) 발견한 추가적인 프로그램 개선사항 및 고도화 제안 내용을 리포팅하여 결과 보고에 「추가개선 제안」 섹션으로 반드시 함께 포함합니다. **「추가개선 제안」 필수 3대 항목**: 1) 프로그램 로직 및 기능 개선, 2) 사용자 인터페이스/UI 가독성, 사용편리성 개선, 3) 현재 만들어져 있는 다른 자동화 프로그램과의 연계가능한 기능. 발견된 타 프로그램의 문제점 및 개선 제안사항은 해당 프로그램의 서브폴더 `docs/IMPROVEMENTS.md`에도 선제적으로 기록해 두어, 다음 CLI가 이어받아 작업할 때 즉시 참고할 수 있게 체계화합니다.
14. **모든 프로그램별 루트 문서 규격화 및 기능·로직·아이디어·버전 히스토리 기록 의무 (2026-10-17 주인님 지시)**: 각각의 모든 프로그램 폴더 루트(`AGENTS.md` 및 `README.md`)에는 다른 CLI(Antigravity, Codex, Claude Code)가 읽고 즉시 개선할 수 있도록 7대 핵심 항목(1. 사용목적/대상, 2. 개발도구/기법/스킬, 3. 기능/로직/장단점, 4. 현재 버전 및 변경 히스토리, 5. 추가 개발/디자인 대기 내용, 6. 타 프로그램 연계/병합 및 확장 아이디어 제안, 7. UI/레이아웃/스타일 개선안)을 체계적으로 정리하여 기록하고, 향후 개선 과제는 프로그램 백로그 문서(`<프로그램>/docs/IMPROVEMENT_BACKLOG.md`)로 작성해 관리합니다.

## 2. 기본 2단 레이아웃 시스템 (The 2-Pane Architecture)

모든 웹 서브프로그램은 **좌측 메뉴바(Navigation Pane)**와 **우측 작업 워크스페이스(Workspace Pane)**의 2단 구조를 기본 골격으로 합니다.

```
+-----------------------------------------------------------------------------------+
|  [좌측 사이드바: 240~260px 고정]  |  [우측 메인 워크스페이스: 유동 확장]                 |
|                                  |                                                   |
|  1. 브랜드 헤더 (앱명·버전·뒤로가기) |  1. 비주얼 히어로 배너 (현재 단계·맥락 그래픽)          |
|  2. 🏠 대시보드                   |  2. 메인 액션 카드 (폼, 편집기, 결과물 캔버스)        |
|  3. 번호형 작업 흐름 (1->2->3->4)   |  3. 보조 정보/미리보기/상태 패널 (우측 또는 하단)      |
|  4. 유틸리티 (API연동, 사용가이드)  |  4. 스텝 이동 및 완료 액션 바 (Sticky Footer)         |
|  5. 계정 정보 및 로그아웃 (밀착)    |                                                   |
+-----------------------------------------------------------------------------------+
```

### 2.1 좌측 메뉴바 표준 (Navigation Standard)
- **너비 및 고정**: 데스크톱 `md:w-60` ~ `md:w-64`, 화면 좌측 상시 고정(`sticky top-0 h-dvh`).
- **정보 구조 필수 순서** (`docs/SIDEBAR_LAYOUT_STANDARD.md` 준수):
  1. 프로그램명(한글/영문) + 버전 배지(`v1.xx`) + `← 다른 프로그램 보기` (`/programs` 링크)
  2. `🏠 대시보드`
  3. 번호 배지와 세로 연결선이 있는 핵심 작업 흐름 (`1 → 2 → 3 → 4`)
  4. 구분선 + `🔑 API키등록·플랫폼연동` + `📖 연동 & 사용 매뉴얼`
  5. 계정 이메일과 로그아웃 (마지막 메뉴 바로 아래 8~16px 간격으로 바짝 밀착, 화면 맨 아래로 밀지 않음)
- **모바일 대응**: 767px 이하에서는 좌측 바를 숨기고 상단 접는 햄버거 메뉴(`☰`)로 전환하여 본문이 100% 폭을 사용하도록 함.

### 2.2 우측 메인 워크스페이스 표준 (Workspace Standard)
- **배경색 및 테마 원칙 (2026-10-16 주인님 확정)**:
  - **기본 메인**: **흰색(Light 테마)**과 **검정색(Dark 테마)**을 기본 메인으로 지원·선택합니다.
  - **필요 시 다른 색상 유연 적용**: 프로그램의 성격에 따라 딥 네이비, 차콜, 미드나잇 블루, 크림/아이보리, 세이지 등 **최적의 몰입감과 가독성을 주는 다른 배경 색상도 자유롭게 채택**할 수 있습니다.
    - 예: 문서/텍스트/블로그 중심 ➔ 흰색 또는 부드러운 오프화이트/크림 베이스
    - 예: 미디어/음악/영상/캔버스 중심 ➔ 검정색, 딥 차콜, 미드나잇 베이스
  - **시각적 계층감 (Surface Elevation)**: 작업 카드는 배경과 뚜렷이 구분되도록 표면색을 분리합니다(라이트 테마: 배경 `#f8fafc` + 카드 `#ffffff` + 그림자, 다크 테마: 배경 `#090d16` / `#0f172a` + 카드 `#1e293b` + 미세 보더).
- **여백 리듬**: 패딩 `p-6` ~ `p-8` (모바일 `p-4`), 카드 간격 `gap-6`.
- **히어로 영역 (Hero Context Area)**:
  - 각 화면 상단에는 단순히 "제목"만 두지 않고, 해당 단계의 **목적, 팁, 소요 시간, 관련 일러스트/아이콘**이 결합된 히어로 블록을 배치합니다.

## 4. 비주얼 인핸스먼트 지침 (Visual Elements & Assets)

딱딱한 텍스트 위주의 화면을 살아 숨 쉬는 인터페이스로 탈바꿈하기 위해 다음 요소들을 전략적으로 배치합니다.

### 4.1 실제 업무 상황 및 인물 사진 활용
- **인물 기준 (원칙 3)**: 인물 사진은 기본적으로 한국인(동아시아인) 전문직/크리에이터 실사 컷을 사용합니다.
- **배치 위치**:
  - 대시보드 상단 웰컴 배너 (예: 편안하게 노트북으로 문서를 작성 중인 한국인 전문가)
  - 템플릿 선택 카드 배경 또는 썸네일 (예: 실제 회의 장면, 블로그 작성 장면, 보고서 결재 장면)
  - 기능 안내 툴팁 또는 도움말 모달

### 4.2 직관적인 다이어그램 & 프로세스 맵
- 긴 텍스트 설명 대신 **SVG 또는 Mermaid 기반의 직관적인 순서도/다이어그램**을 화면 상단이나 가이드 탭에 삽입합니다.
  - 예: `[마크다운 작성] ➔ [실시간 렌더링] ➔ [PDF/Word 변환] ➔ [구글 드라이브 동기화]`

### 4.3 친근한 AI 가이드 아바타 / 캐릭터
- 기능이 복잡하거나 오류가 발생하기 쉬운 지점, 또는 첫 진입 시(Empty State)에는 친근한 AI 비서 아바타나 캐릭터 말풍선을 띄워 사용자에게 다음 행동을 자연스럽게 유도합니다.
- 예: "아직 작성된 문서가 없어요! 아래 '새 문서 만들기' 버튼을 눌러 첫 글을 시작해보세요."

### 4.4 이모티콘 및 정밀 아이콘 (Lucide + 3D/Color Emoji)
- 텍스트만 나열된 버튼이나 메뉴는 지양하고, 일관된 디자인 시스템의 Lucide 아이콘과 생동감 넘치는 이모티콘을 조합합니다.
  - 단순 텍스트 `새 문서` ➔ `✨ 새 문서 만들기` + 보조 설명
  - 단순 텍스트 `내보내기` ➔ `📥 내보내기 & 변환` + 포맷 배지

## 5. 기준 모델: Markdown Studio (마크다운 스튜디오) 디자인 개편 표준안

> **프로그램 주소**: `https://markdown-studio.buylife.xyz/`  
> **소스 위치**: `markdown-studio/`  
> **적용 유형**: **Type 1 (스튜디오 / 에디터형)**

현재 Markdown Studio의 5개 주요 화면에 대한 구체적인 비주얼 업그레이드 가이드라인입니다.

### 5.1 대시보드 (Dashboard: `/dashboard`)
- **기존 문제점**: 단순 숫자 3개(저장된 문서, 폴더, 이력)와 텍스트 카드만 덩그러니 놓여 있어 삭막함.
- **업그레이드 표준**:
  1. **웰컴 히어로 카드 (Welcome Hero Banner)**:
     - 부드러운 그라데이션 액센트(예: 은은한 인디고-바이올렛 배경)
     - 한국인 크리에이터의 정갈한 서재/데스크 실사 또는 세련된 일러스트 실루엣 삽입
     - "오늘도 멋진 문서를 완성해 보세요!"(회원 화면에는 "주인님" 호칭을 쓰지 않음) 등 동기부여 문구와 직관적인 바로가기 버튼 3종(새 문서 작성, 최근 문서 이어쓰기, 드라이브 연동).
  2. **비주얼 통계 카드 (Visual Stat Cards)**:
     - 단순 텍스트 대신 은은한 파스텔 배경의 컬러 아이콘 박스 적용.
     - 마우스 호버 시 살짝 떠오르는 부드러운 그림자 애니메이션(`transition-transform hover:-translate-y-0.5`).
  3. **최근 문서 카드 그리드 (Recent Documents)**:
     - 텍스트 리스트 대신 카드 썸네일 형태로 배치.
     - 문서 제목, 첫 두 줄 요약 미리보기, 최종 수정 시간, 글자 수 배지 표시.

### 5.2 1단계: 문서 준비 (Prepare: `/prepare`)
- **기존 문제점**: 회색 테두리의 단순 라디오 버튼으로 템플릿이 나열되어 시각적 매력이 떨어짐.
- **업그레이드 표준**:
  1. **템플릿 비주얼 카드 (Template Visual Cards)**:
     - 템플릿마다 대표 일러스트 또는 미니어처 문서 레이아웃 그래픽 제공 (회의록: 체크리스트 그래픽, 블로그: 사진+단락 그래픽, 기술문서: 코드블록 그래픽).
     - 선택 시 굵은 인디고 보더 + 우측 상단 체크마크 배지 애니메이션.
  2. **드래그 앤 드롭 파일 존 (Modern Dropzone)**:
     - 점선 테두리와 구름/문서 아이콘이 있는 넓고 시원한 업로드 박스.
     - 지원 파일(MD, TXT, HTML, JSON)을 컬러 칩으로 명시.

### 5.3 2단계: 편집·미리보기 (Editor: `/editor`)
- **기존 문제점**: 일반적인 텍스트 에디터와 미리보기가 너무 사무적이고 경직되어 있음.
- **업그레이드 표준**:
  1. **현대적인 스튜디오 툴바 (Floating / Sticky Toolbar)**:
     - 아이콘 간격 및 호버 이펙트 세련화.
     - 서식 도구(B, I, H1, 링크, 표 등) 그룹화 및 단축키 힌트 툴팁.
  2. **종이 질감 / 에디터 캔버스 (Paper-like Canvas)**:
     - 우측 미리보기 영역을 실제 인쇄물이나 고급 노션(Notion) 페이지처럼 부드러운 순백 카드에 적절한 라인하이트(`line-height: 1.8`), 깔끔한 타이포그래피로 렌더링.
  3. **실시간 통계 인디케이터**:
     - 하단 바에 글자 수, 단어 수, 예상 읽기 시간(예: "⏱ 약 3분 소요")을 실시간 칩으로 표시.

### 5.4 3단계: 변환·내보내기 (Export: `/export`)
- **기존 문제점**: 체크박스와 버튼만 있어 변환 결과물의 차이를 느끼기 어려움.
- **업그레이드 표준**:
  1. **포맷별 브랜드 비주얼 카드 (Format Cards)**:
     - **PDF**: 고급스러운 레드 계열 아이콘 + 인쇄용 레이아웃 뱃지
     - **Word (DOCX)**: 오피스 블루 아이콘 + 편집 호환성 뱃지
     - **HTML**: 모던 오렌지 아이콘 + 웹 배포용 뱃지
     - **ZIP**: 파일 패키지 그린 아이콘 + 일괄 보관 뱃지
  2. **원클릭 빠른 다운로드 & 옵션 프리셋**:
     - 복잡한 설정 없이 추천 기본값(예: "A4 여백 표준", "노트북 뷰")을 버튼 하나로 선택 가능하게 구성.

### 5.5 4단계: 문서 보관함 & 구글 드라이브 (Library: `/library`)
- **기존 문제점**: 파일 목록이 텍스트 리스트 형태로 단조로움.
- **업그레이드 표준**:
  1. **타임라인 기반 수정 이력 (Visual History Timeline)**:
     - 단순 표가 아닌 타임라인 점(Dot)과 연결선으로 수정 이력을 표시하여 과거 버전 복원을 직관적으로 수행.
  2. **클라우드 연동 상태 시각화**:
     - Google Drive 연동 여부를 컬러 상태 뱃지(`● 동기화 활성` / `○ 미연동`)로 실시간 표시.

### 5.6 연동 & 사용 매뉴얼 (Guide: `/guide`) 디자인 표준 (2026-10-16 주인님 지시)
- **기존 문제점**: 단순 번호 매김 줄글 리스트(`<ol>`)로만 구성되어 있어 가독성이 떨어지고, 복잡한 API 연동이나 작업 흐름을 한눈에 파악하기 어려움.

  2. **친근한 캐릭터 / 아바타 가이드 (Character & Guide Tone)**:

  4. **상황 설명 인포그래픽 & 한국인 실사/일러스트 (Illustrations & Infographics)**:
     - 복잡한 OAuth Client ID 연동이나 API 키 발급 절차는 3단계 캡처 스텝 다이어그램(콘솔 접속 ➔ 키 복사 ➔ 등록 완료)으로 직관화.
  5. **팁(TIP) & 주의사항(NOTICE) 하이라이트 박스**:
     - 중요 정책(회원 본인 키/계정 1:1 연동 불변 원칙, 브라우저 로컬 저장소 원리 등)을 부드러운 파스텔톤 인포박스로 강조하여 신뢰감 부여.

### 6.2 모더레이트 섀도우 (Subtle Elevation)
딱딱한 플랫 디자인에서 벗어나 부드러운 입체감을 부여합니다:
```css
/* 기본 카드 섀도우 */
box-shadow: 0 1px 3px 0 rgba(0, 0, 0, 0.05), 0 1px 2px -1px rgba(0, 0, 0, 0.05);

/* 호버 시 부유 섀도우 */
box-shadow: 0 10px 15px -3px rgba(0, 0, 0, 0.08), 0 4px 6px -4px rgba(0, 0, 0, 0.04);
```

### 6.4 빈 화면 (Empty State) 가이드라인
자료나 문서가 없을 때 빈 화면만 남겨두지 않습니다:

### 6.5 좁은 칸의 버튼·짧은 문구 (줄바꿈·잘림 방지, 2026-10-22 주인님 지시)
카드·표·툴바처럼 좁은 칸에서 버튼 글자가 두 줄로 꺾이거나 가격·라벨이 눌려 잘리지 않게 만듭니다. 전체 규칙과 사례는 [`DESIGN.md`](../DESIGN.md) 최상위 원칙 19번을 따릅니다.
- **버튼·배지·가격·짧은 라벨**: `whitespace-nowrap`, 버튼 묶음·가격 칸은 `shrink-0`
- **한 줄에 문구와 버튼 묶음을 같이 둘 때**: 부모 `flex flex-wrap gap-y-3`, 버튼 묶음 `ml-auto` → 공간이 모자라면 버튼 묶음 전체가 다음 줄 오른쪽으로 내려감(글자를 눌러 자르지 않음)
- **검수**: 회원 상태별 버튼 중 가장 긴 조합으로, 데스크톱 최소 열 폭(약 330px)과 휴대폰 폭(375~390px)에서 확인하고, 잘림·넘침(`scrollWidth > clientWidth`)이 0개인지 봅니다. 기준 구현: `components/programs/ProgramCard.tsx` 하단 가격·버튼 줄.

### 6.6 주요 링크·실행 버튼·상세페이지 핵심 CTA 3D 엠보싱 버튼 표준 (2026-10-25 주인님 지시)

   - `box-shadow`: 입체 하단 엠보싱 (`0 5px 0 [더 진한 테마색], 0 9px 18px rgba([테마RGB], 0.3)`)
   - `:hover`: `transform: translateY(-1.5px~-2px)` + 그림자 확장 (`0 7px 0 ..., 0 14px 24px ...`)
   - `:active`: `transform: translateY(4px)` + 그림자 밀착 (`0 1px 0 ..., 0 3px 8px ...`) — 물리적 키캡 푸시 피드백

### 6.7 API 키 등록 2단 분리형 카드 포맷 & 모델 역할·키 입력 규격 (2026-10-25 주인님 확정)
API 키 등록과 엔진/모델 선택이 들어가는 모든 프로그램은 아래 2단 분리형 카드 레이아웃을 표준으로 적용합니다:
1. **2행 구조 (완벽한 가로 균형 & 여백 활용)**:
   - **1행 (상단 플랫폼/역할 바)**: `[엔진 이모티콘 + 명칭]` + `[✓ 등록완료/미등록 뱃지]` + `[역할 제목 · 역할 설명]` + `[우상단: 발급 ↗ (3D 오렌지 버튼)]`
   - **2행 (하단 키 관리 & 모델 선택 바)**: `[가림표(••••) 꽉 찬 마스킹 키 박스]` + `[모델 선택 셀렉트박스 (넓은 너비)]` + `[수정 / 삭제 / 저장 버튼]`
2. **선택된 활성 엔진 시각화**: 좌측 포인트 바(`border-l-4`) 및 테마 하이라이트 배경색(`bg-amber-50/60`)을 적용하여 직관적 식별 제공.
3. **프로그램 도메인별 테마 재구성**: 도메인(부동산, 블로그, 음악, 쇼츠 등)에 어울리는 이모티콘, 배경색, 상태 뱃지, 3D 엠보싱 버튼을 맞춤 재구성.
4. **기준 레퍼런스 구현체**: [`realty-listing-alert/app/delivery/DeliveryClient.tsx`](../realty-listing-alert/app/delivery/DeliveryClient.tsx) (`AiEngineRow` 및 `.ra-aieng-top`, `.ra-aieng-bottom`)

각 Base URL 뒤에 `/chat/completions`를 붙인 주소가 이번 공통 호출 대상입니다. 네 곳 모두 회원 본인 Bearer 키/토큰을 사용하고 Cloudflare는 본인 계정 ID도 필요합니다. 정확한 최종 주소·헤더·모델 페이지·조건별 공식 링크는 [조사 문서 1~3절](OFFICIAL_PROVIDERS_20261024.md)에 있습니다.

핵심 판단:

1. **네 공급자를 모두 ‘상시 무료 운영 API’라고 안내하지 않습니다.** Groq/OpenRouter/Cloudflare를 우선 구현 후보로, NVIDIA는 호환 방식 검토와 운영 조건 확인 후보로 분리합니다.
2. OpenAI 호환은 주소만 바꾸면 모든 기능이 같다는 뜻이 아닙니다. 모델별 온도·출력 제한·JSON·스트리밍·추론 필드를 구분합니다. Groq JSON 라우터는 비스트리밍, 답변은 스트리밍 경로로 검증합니다.
3. 무료 선택이 실패하거나 한도에 닿아도 유료 모델/다른 회원·운영자 키로 자동 대체하지 않습니다. 재시도/중복 요청과 비용을 통제합니다.
4. **무료 답변 공급자와 문서 파싱/임베딩 비용은 별개**입니다. Upstage 문서 기능과 Tavily를 켜면 해당 회원의 사용량이 발생할 수 있습니다.

## 4. 단계별 구현·완료 조건

### G-1. 여러 공급자 공용 호출·회원 공용 키

**범위:** Groq·OpenRouter·Cloudflare의 1회 답변/스트리밍·JSON 라우터용 최소 계약, NVIDIA의 조건부 어댑터 설계. 문서 챗봇의 답변/라우터와 AI Prompt의 템플릿 실행에서 선택합니다.

- 문서 챗봇 폴더 안에 기준 모듈(예: `src/lib/chat/providers/compatible/`)을 두고 Prompt에 사본을 배치합니다. 공용 기능 지도/공용 모듈 등록부에 기준·사본·지원 범위를 등록하고 기존 동기화 검사에 연결합니다. 실제 인터페이스/파일 배치는 승인 후 기존 패턴을 대조해 확정합니다.
- 공급자별 고정 공식 주소·모델별 허용 파라미터·한국어 오류·중단 신호·실제 사용 모델을 분리합니다. 임의 API 주소를 서버가 요청하게 하지 않습니다.
- SSE 분할 UTF-8/부분 줄/종료/오류/취소를 검사합니다. 출력 본문과 별도 reasoning 필드를 혼동하지 않습니다. 문서 챗봇에는 기존 NDJSON 이벤트를 계속 제공합니다.
- Cloudflare 계정 ID+토큰을 포함한 공용 등록 항목을 정의하고 `integration_catalog`와 `user_api_keys`를 사용합니다. API 키 항목은 OAuth 계정 토큰 표에 억지로 넣지 않습니다. 기존 등록값이 있으면 재등록을 요구하지 않습니다.
- 등록 UI는 문서 챗봇의 기존 API 설정을 확장하고 Prompt는 같은 회원 값/연결 상태를 가져옵니다. 새 프로그램 전용 키 저장소를 만들지 않습니다. 키는 서버에서 읽고 브라우저에는 마스킹 상태만 제공합니다.
- 기본값/기존 방은 기존 Upstage/Gemini를 유지합니다. 새 공급자 선택 시 필요한 키만 검사하고, 문서 검색/파싱을 켤 때는 Upstage 키, 웹 검색을 켤 때는 Tavily 키를 별도로 안내합니다.
- 문서/대화 근거가 실제로 선택한 클라우드 공급자에게 전달됨을 안내하고 공급자 데이터 처리 조건을 확인합니다. 공급자를 바꿔도 타 회원 자료가 포함되지 않도록 서버 소유자 조건은 유지합니다.
- NVIDIA는 공식 FAQ상 운영 이용 조건 확인 전 실제 회원용 무료 기본 선택지로 활성화하지 않습니다. 추가 운영 비용/계약을 자동으로 발생시키지 않습니다.

**완료 조건:** 승인된 공급자의 본인 키로 한 번 호출·스트리밍·중단·오류 안내가 동작하고, 키 미등록/401/429/취소/손상 스트림을 회귀 검사합니다. 한 앱에서 등록한 값이 다른 앱에서 재등록 없이 사용되고, 타 회원 값 접근이 차단돼야 합니다. Upstage/Gemini 기존 동작과 기존 문서 검색도 유지합니다.

### G-2. 커스텀 봇과 내장 봇

**추천 위치:** 문서 챗봇의 채팅방에서 봇을 선택합니다. 주인님 선택 전에는 위치가 확정된 것이 아닙니다.

- 이름·직접 작성한 지침·공급자/모델·온도를 회원별 설정으로 저장하고 채팅방에 연결합니다. 기본 봇을 제공하되 번역/요약/업무 문서 등 3~4종을 우리 문구로 새로 작성합니다.
- 신규 봇 저장 구조와 방의 선택값은 소유자 조건·RLS·서버 검증을 포함해 설계합니다. 회원이 직접 작성/선택한 역할·모델 등 설정은 설정류로 유지하는 안이며, 대화·문서·AI 생성 결과의 30일 수명은 유지합니다. AI 생성 원문을 단순 저장했다는 이유로 환경설정으로 바꿔 수명을 연장하지 않습니다.
- 봇 수정/삭제가 다른 회원이나 기존 대화를 바꾸지 않게 합니다. 대화 중 봇/모델 변경은 화면에 명확히 표시하고, 응답 생성 때 사용한 봇 설정/모델의 의미를 보존합니다.
- Prompt에 두는 안이면 회원 소유 템플릿/실행 설정과 묶되 기존 `ai_prompt_templates`와 이를 읽는 AI 글쓰기 에디터 계약을 깨지 않습니다. 양쪽 연계는 우선 일방향 가져오기부터 검토하고 이중 저장·양방향 동기화를 기본 범위에 넣지 않습니다.

**완료 조건:** 생성·수정·선택·해제·삭제·재열기, 회원 간 격리, 삭제된 봇/지원 종료 모델 안내, 모델별 온도 검증을 확인합니다.

### G-3. 역할 유지·입력 처리 지침

- 플랫폼의 회원 격리/출력 규칙, 봇의 역할·형식·대상 언어, 사용자 처리 대상, 문서/웹 자료를 구분해 구성합니다. 자료 안의 지시문을 시스템 명령으로 취급하지 않습니다.
- 번역 봇은 질문형 문장도 번역하고, 요약 봇은 입력을 요약하도록 우리 지침과 예시를 작성합니다. 현재 날짜/연도 규칙과 자료 속 과거 사실을 구분합니다.
- 모델에 역할 유지 문장을 넣는 것만으로 완벽한 지침 이탈 방지를 보장하지 않습니다. 입력/출력 형식 검사·회원 소유권·허용 도구/API 범위와 별도로 검증합니다.

**완료 조건:** 번역 봇에 질문형 입력, 역할 변경 유도 문구, 자료 속 명령문, 다른 언어/출력 형식 요청을 넣어 역할 유지 여부를 검사합니다. 구조화 라우터는 비스트리밍 JSON 경로를 별도로 확인합니다.

### G-4. 문서 근거 보강

- 기존 단일 문서 선택과 출처 snippet은 유지하고, 문서 분류·여러 문서 체크·회원 소유 문서 미리보기를 추가합니다.
- 선택 문서는 서버에서 소유자/상태/만료를 확인하고 **벡터/키워드 검색 전에** 범위를 적용합니다. 전체 검색 상위 몇 건을 뽑은 뒤 선택 문서만 걸러 근거를 누락시키는 방식은 피합니다.
- 1024차원·기존 조각/검색 구조를 유지하는 추가 함수/필터 경로를 검토합니다. 기존 RPC 호출 계약은 보존하고 승인 후 실제 운영 칼럼·함수와 대조해 마이그레이션을 확정합니다.
- PDF 추출 결과에 대체문자·비정상 한글/빈 본문 등이 많은지 감지해 ‘글꼴 유니코드/추출 문제 가능성’으로 안내합니다. 감지 결과를 파일 손상의 확정 진단으로 표시하지 않으며 자동 유료 재파싱/OCR은 하지 않습니다.

**완료 조건:** 선택/미선택/삭제/만료/타 회원 문서, 여러 문서 동시 선택, 빈 근거·미리보기 권한, 깨진 PDF 경고와 정상 한글의 과도한 경고를 확인합니다. 선택하지 않은 문서는 답변 근거/출처에 섞이지 않아야 합니다.

### G-5. 회원 PC 로컬 Ollama — 별도 선택

**추천:** 이번에는 보류하거나 연결 시제품까지만 진행합니다. 정식 통합을 승인한 것으로 간주하지 않습니다.

- 주소는 회원 브라우저가 접근하는 `http://localhost:11434/v1/chat/completions`. 운영 서버의 localhost는 회원 PC가 아닙니다. [Ollama OpenAI 호환 공식 문서](https://docs.ollama.com/api/openai-compatibility).
- 회원이 Ollama·모델을 직접 설치합니다. 웹에서 자동 설치/제거·Docker·관리자 권한 실행·대형 모델 자동 다운로드는 이번 범위에 넣지 않습니다.
- 실제 서비스 origin을 `OLLAMA_ORIGINS`에 허용하고 브라우저의 로컬 네트워크 접근 허용을 확인해야 합니다. 보안 기능을 끄거나 모든 origin에 공개하는 안내는 하지 않습니다. [Ollama FAQ](https://docs.ollama.com/faq), [Microsoft Edge LNA](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access).
- 1차 시제품은 일반 대화·연결 확인·스트리밍·중단·모델 목록의 로컬 경로 검증입니다. 서버 RAG/문서 파싱까지 완전히 오프라인으로 만드는 범위가 아닙니다. 로컬/클라우드 Ollama 모델도 구분합니다.
- 회원 PC 사양·모델 크기/라이선스·브라우저/운영체제에 따른 차이를 확인합니다. 로컬 추론에 외부 API 요금이 없더라도 저장공간·다운로드·전기·하드웨어 비용은 별개입니다.

**시제품 완료 조건:** Edge 실제 창에서 서비스 HTTPS→회원 localhost 접속, 권한 허용/거절, Ollama 미기동, 모델 없음, 답변/중단을 확인한 뒤 정식 연결 가능 여부와 추가 플랜/비용을 다시 보고합니다.

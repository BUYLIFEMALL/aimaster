# 인스타 자동화 완성 기준

> **상태: 초안(2026-10-24, 작성 claude-win-dotori [역할: analysis-planning]) — 담당 세션 확인 전.** 인스타 카테고리에는 아직 담당 역할이 없다. 주인님이 담당을 정하고 그 세션이 확인하기 전까지 이 문서는 참고 기준이며, 이 문서를 근거로 기존 기능을 「미완성」으로 고치거나 배포를 막지 않는다.

> **🧭 인스타 작업 핵심 지침 (근거: 주인님 방침 「모든 인스타그램 자동화 프로그램은 예약·즉시 포스팅을 포함해야 한다」(2026-10-19), 회원 연동 공용 저장 규칙(2026-10-19), 인스타 병합 결정(2026-10-20))**
> ① **게시물(이미지·카드뉴스·캡션·해시태그)은 프로그램(웹) 안에서 완성한다** — 회원이 마지막으로 보고 고친 그 내용 그대로 게시한다. 게시 단계에서 문구나 이미지를 새로 만들지 않는다.
> ② **인스타 게시물을 만드는 모든 프로그램은 즉시 게시와 예약 게시를 둘 다 제공한다.** 「이미지 저장 후 직접 올리세요」 안내만으로 끝내지 않는다.
> ③ **인스타 연결은 회원이 한 번만 한다** — INSTA 포스팅 자동화(`auto-instagram-posting`)에서 연결한 공용 값(`member_platform_accounts`, 대체 경로 `insta_accounts`)을 다른 프로그램이 그대로 읽는다. 새 프로그램이 따로 연결 화면을 만들지 않는다.
> ④ 게시 결과(게시물 주소 `permalink`·미디어 ID·게시 시각·실패 사유)를 프로그램에 기록하고 회원에게 보여 준다. **결과가 불확실하면 자동으로 다시 게시하지 않는다.**
> ⑤ 댓글·DM 응대는 기본이 「AI 초안 → 회원 승인 → 게시·발송」이다. 자동 게시·발송은 회원이 위험 안내에 동의한 뒤에만 켠다.

## 1. 적용 범위

인스타 카테고리 운영 프로그램(AIMaster 운영, DB ref `esgxyikcnnvmlhygjkth`)의 신규 개발·기능 추가·병합 비교에 적용한다.

| 프로그램 | 이 기준에서의 역할 |
|---|---|
| INSTA 포스팅 자동화 `auto-instagram-posting`(폴더 `insta_auto_poster`) | 인스타 연결 출발점 · 피드·카드뉴스 제작·게시 기준 · 게시 엔진 공용 기준 코드 보유 |
| AI 인플루언서 자동화 `ai-influencer-studio` | 가상 인물 화보 → 게시(엔진 사본) |
| AI 웹툰 자동화 `ai-webtoon-studio` | 웹툰 컷 → 인스타 판 → 게시·회차 묶음 예약(엔진 사본) |
| INSTA 댓글·DM 자동화 `instagram-comment-reply` | 댓글·DM 응대(게시물 제작 아님) |
| 병합됨 `cardnews-studio` → INSTA, `instagram-dm-reply` → 댓글·DM | 옛 주소 전달만 유지, 새 기능 넣지 않음 |

같은 게시 엔진 사본을 쓰는 `four-cut-comics`(이미지 카테고리)와 릴스를 함께 올리는 `auto-shorts-posting`(유튜브 카테고리)은 자기 카테고리 지침을 따르되, 인스타 게시 부분은 이 문서 §3·§4를 함께 지킨다.

## 2. 완성 흐름

**자료 입력·수집 → 문구·이미지 생성 → 회원 편집·확인 → 게시 방식 선택(즉시·예약) → 회원 본인 인스타 계정으로 게시 → 결과 기록·표시 → 30일 정리.**
댓글·DM 프로그램은 **수집(주기 확인·웹훅) → AI 초안 → 회원 승인(웹·텔레그램·통합 받은편지함) → 게시·발송 → 기록**이다.

생성·저장·이미지 내려받기까지만 된 상태는 「제작 완료」이지 「자동화 완료」가 아니다. 완성 보고에는 단계별로 구현·검수 상태를 따로 적는다.

## 3. 끝났다고 말할 조건

다음을 모두 만족해야 「인스타 자동화 완료」라고 보고한다. 하나라도 빠지면 빠진 단계를 「미구현」 또는 「미검수」로 적는다.

1. **즉시 게시**와 **예약 게시**가 모두 동작한다(회원이 고른 시각, 한국 시간 기준 표시).
2. 예약은 회원이 고른 실행 방식(AIMaster 기본 / 회원 본인 cron-job.org)으로 돈다 — [`SCHEDULER_POLICY.md`](SCHEDULER_POLICY.md). 예약 취소·전체 일시정지가 보관함에 있다.
3. 게시 결과가 기록된다: 성공이면 `permalink`·미디어 ID·게시 시각, 실패면 사유(토큰 문자열은 가림). 「게시 중」에 멈춘 글은 일정 시간 뒤 실패로 바뀌고 자동 재게시하지 않는다.
4. 같은 글이 두 번 게시되지 않는다(예약 실행 선점, 처리 중 상태). 화면 버튼 연타·예약 중복 호출로 시험한다.
5. 게시물 기록과 게시용 이미지는 회원 본인만 읽고(RLS), 생성 30일 뒤 정리된다.
6. 실제 회원 흐름 검수: 시험 계정 `buylifemall@naver.com`으로 로그인해 본인 연결 계정으로 게시하거나, 실제 게시를 하지 않았으면 「모의 검수만」으로 적는다.

## 4. 회원이 고르는 항목

| 항목 | 선택지 | 기본값 |
|---|---|---|
| 게시 방식 | 즉시 게시 / 예약 게시(날짜·시각) | 회원이 매번 고름 |
| 예약 실행 방식 | AIMaster 기본(관리자 지정 프로그램만) / 내 cron-job.org | 프로그램 설정값 |
| 게시 형식 | 피드 1장 / 캐러셀 2~10장(프로그램이 지원하는 것만) | 프로그램별 |
| 올릴 장 | 만든 이미지 중 회원이 고른 장·순서 | 전체 |
| 캡션·해시태그 | AI 초안을 회원이 고쳐서 확정 | AI 초안 |
| 이미지 출처 | AI 생성 / 내 사진 / 무료 사진(회원 본인 Pixabay·Pexels 키) | 프로그램별 |
| 댓글·DM 응대 | 승인 후 게시(기본) / 자동 게시·발송(위험 안내 동의 후) | 승인 후 |
| 승인 경로 | 웹 / 텔레그램 봇 / 통합 받은편지함(`comment-inbox`) | 웹 |

회원이 고르지 않은 방식(예: 승인 없이 자동 발송, 고르지 않은 시각에 게시)으로 동작하지 않는다.

## 5. 하지 않을 것

- 운영자·다른 회원의 인스타 계정·Meta 앱·AI 키로 게시하거나 답하지 않는다. 키가 없으면 「본인 키를 등록해 주세요」로 안내한다.
- 프로그램마다 인스타 연결 화면·연결 표를 새로 만들지 않는다(③).
- 수집한 다른 계정 게시물·릴스를 저장해 두거나 문구를 그대로 옮기지 않는다(분석 뒤 삭제, 문구 겹침 검사 유지).
- 결과가 불확실한 게시를 자동으로 다시 보내지 않는다.
- 인스타그램 개인 계정·비공식 방식(화면 자동 조작, 비밀번호 저장)으로 게시하지 않는다. 공식 Graph API만 쓴다.
- 병합된 원본(`cardnews-studio`·`instagram-dm-reply`)에 새 기능을 넣지 않는다.
- 릴스·스토리 게시는 현재 어느 프로그램에도 없다 — 만들 때는 이 문서에 형식별 규칙을 먼저 추가한다.

## 6. 회원 본인 계정·키 규칙

- 연료는 회원 본인 것이다: Meta 앱(앱 ID·시크릿)·인스타 비즈니스/크리에이터 계정·AI 키(OpenAI·Gemini·Claude·Perplexity)·선택 키(Apify·Pixabay·Pexels·cron-job.org)·텔레그램 봇.
- 연결값과 키는 공용 저장소에 회원별로 한 번 저장하고 재사용한다 — [`MEMBER_INTEGRATIONS.md`](MEMBER_INTEGRATIONS.md)(`member_platform_accounts`·`user_api_keys`). 로그인 방식(`instagram_login` / `facebook_login`)이 맞는 연결만 쓴다.
- 쓰기 API·서버 액션은 모두 프로그램 권한 판정(`requireProgramAccess`/`checkProgramAccessApi`)을 거친다.

## 7. 개발·완료 보고

1. 플랜과 [인스타 기능 상세 비교표](INSTAGRAM_FEATURE_MATRIX.md)에 즉시·예약·결과 기록·중복 방지·30일 정리 칸의 현재 상태를 먼저 적는다.
2. 게시 엔진·예약·보관함 코드는 공용 기준 코드에서 가져온다(비교표 §4). 사본을 직접 고치지 않는다.
3. 완료 보고에 단계별 상태(생성·편집 / 즉시 게시 / 예약 게시 / 결과 기록 / 30일 정리)를 「구현·모의 검수·실제 검수·미구현」으로 구분해 적는다.

## 8. 이 초안 작성 때 확인한 차이 (담당 세션 확인 필요)

- 게시 엔진 `insta_auto_poster/src/lib/instagram/publish.ts`의 `postGraphWithRetry`는 시간 초과(timeout) 오류일 때 `media_publish` 호출을 최대 2번 다시 보낸다. 시간 초과는 결과가 불확실한 경우라 ④와 충돌할 수 있다(중복 게시 가능성). 사본 3곳 동일.
- INSTA 피드 글(`insta_posts`)·`insta-post-images` 30일 정리는 플랜 [`PLAN_20261022_MEDIA_RETENTION.md`](../insta_auto_poster/docs/PLAN_20261022_MEDIA_RETENTION.md)가 승인 대기이고 코드가 없다(카드뉴스 `cns_insta_posts`는 정리 있음).
- 댓글·DM 앱의 댓글·DM 기록 30일 정리 코드는 찾지 못했다(미확인).

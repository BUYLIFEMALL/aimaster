# 최상위 공통 필독 — 데이터베이스 연동 지침

2026-10-16 주인님 지시. **모든 CLI·AI 에이전트는 어떤 프로그램을 작업하든 이 문서와 최신 인수인계를 먼저 읽습니다.** 메인과 모든 서브프로그램에 공통으로 적용합니다. 회원 본인 AI 키·외부 계정 최상위 규칙은 그대로 유지합니다.

## 공통 DB와 연결 값

- AIMaster 공용 Supabase 프로젝트는 **`esgxyikcnnvmlhygjkth` 한 개**입니다. 프로그램별로 별도 회원 DB·회원가입·권한 체계를 만들지 않습니다.
- URL은 `NEXT_PUBLIC_SUPABASE_URL`을 사용합니다. 같은 DB의 공개 키와 서버 키를 등록하고 브라우저/서버 역할을 분리합니다.
- 공개 키: **`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` 우선**, 없거나 공백일 때만 기존 `NEXT_PUBLIC_SUPABASE_ANON_KEY`를 사용합니다.
- 서버 키: **`SUPABASE_SECRET_KEY` 우선**, 없거나 공백일 때만 기존 `SUPABASE_SERVICE_ROLE_KEY`를 사용합니다. 기존 BASE64 서버 변수 지원이 있으면 새·기존 직접 값이 모두 없을 때만 유지합니다.
- 새·기존 변수 이름 중 어느 쪽만 있어도 동작해야 하며, 둘 다 있으면 새 이름을 우선합니다. 설정된 키가 인증 실패했다고 다른 키를 자동 재시도하지 않습니다. 공개 키를 관리자 서버 키의 대체 값으로 쓰지 않습니다.
- 브라우저 공개 변수는 Next.js가 빌드에 넣을 수 있도록 `process.env.NEXT_PUBLIC_...` 직접 참조를 사용합니다. 등록/변경 뒤에는 해당 프로젝트를 재배포합니다. 서버 비밀 키는 `NEXT_PUBLIC_`에 넣거나 브라우저·확장·Git·문서·로그에 노출하지 않습니다.

## 로그인·회원 데이터 원칙

- 로그인과 프로그램 이용 권한은 공용 판정 함수를 사용하고, 권한 테이블 조회는 서버 관리자 클라이언트에서 수행합니다. FREE 여부·등급·구독·기간·정지·핸드폰 정책을 바꾸지 않습니다.
- 사용자 데이터는 `user_id` + 소유자 RLS로 분리합니다. 서버 키로 RLS를 우회하는 요청도 로그인 회원의 소유자 조건을 직접 적용합니다. 회원이 보낸 ID를 그대로 신뢰하지 않습니다.
- 플랫폼 DB 연결 키와 회원 본인의 AI/외부 서비스 키를 혼동하지 않습니다. AI 키는 공용 `user_api_keys`에서 로그인 회원 본인 것만 사용합니다. 운영자 AI 키나 다른 회원 키로 대체하지 않습니다.

## 안정화 전 기존 항목 유지

**기존 환경변수·Supabase 키를 지금 삭제하지 않습니다.** 프로그램별 새 이름 호환·운영 배포·회원 검수가 끝나고 안정화가 확인된 뒤 정리합니다. 다른 프로젝트에 같은 이름이 등록돼 있어도 자동으로 공유된다고 가정하지 않습니다.

### 안정화 후 정리 순서

1. 메인과 모든 서브프로그램·서버/운영 스크립트의 새 이름 지원을 확인합니다.
2. 각 프로젝트의 운영 환경에 새 이름이 등록되어 있고 올바른 같은 DB의 값인지 확인합니다. 새 이름이 없으면 기존 값을 **그대로 복사해 한 번 등록**합니다. 새 키 발급은 필요하지 않습니다.
3. 새 이름을 적용한 배포에서 로그인·세션·회원 권한·DB·파일 접근·관련 확장 동작을 확인합니다. Preview/Development도 사용한다면 환경별로 확인합니다.
4. 대상 목록과 안정화 근거를 제시하고 주인님과 삭제 시점을 확정한 뒤 **기존 이름의 Vercel 환경변수만** 프로젝트별로 정리합니다. 한 프로그램씩 재배포·재검수하며 문제가 있으면 기존 설정을 복구합니다.
5. **Vercel 변수 삭제와 Supabase 실제 키 폐기는 별개입니다.** 새 이름에서도 같은 키 값을 사용 중이면 Supabase 키 자체를 삭제하면 안 됩니다. 실제 키 폐기는 별도의 키 교체 작업으로 모든 사용처 전환을 확인하고 따로 승인받습니다.
6. 새 이름 등록이 끝났다면 주인님이 키 값을 다시 수정할 필요는 없습니다. 정리·재배포·검수·기록은 에이전트가 승인된 범위에서 진행합니다. 전체 완료 전 기존 이름 호환 코드를 제거하지 않습니다.

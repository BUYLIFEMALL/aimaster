## 2. 기능(화면) 목록과 작업 흐름

작업 흐름(원본 안내): 내 블로그 스타일 분석 → 진단 → 키워드 탐색 / 트렌드 관측 / 벤치마킹 → 보관 키워드 선택 → 검색어 목록(자동완성·함께 찾는 검색어) → 검색어 선택 → 실제 상위 5개 확보 → 자료 분석·확인·승인 → 글 작성 → 최종 검수 → 최종본 저장.

| # | 화면 | 하는 일 |
|---|---|---|
| 0 | 시작·연결 설정 | AI(ChatGPT) 로그인·모델·연결 시험, 네이버 API HUB / 검색광고 API 키 저장·진단 |
| 1 | 내 블로그 스타일(진단) | 블로그 URL·ID 입력 → 최신 5/10/20/30개 글 수집 → 문체·주제·독자 패턴 분석(“블로그 DNA”) → 결과 승인. 글 표본 직접 붙여넣기도 가능. 블로그 여러 개 등록 |
| 2 | 키워드 탐색 | 블로그 카테고리(최대 3)·세부 주제(최대 5) → 후보 키워드 발굴 → 공식 월간 검색량·블로그 문서수로 검증 → 등급(“골드키워드” = 검색량 대비 문서수 비율 낮음) → 보관. 단계 로그 |
| 3 | 직접 키워드 분석 | 입력한 키워드의 수치 확인 후 글 작성 준비로 |
| 4 | 트렌드 관측(데일리 브리프) | 내 주제 관련 뉴스 10 + 웹자료 10 수집·요약 → 새 용어 추출 → 검색어 트렌드로 급상승 판정(최근 3일 평균이 직전 7일보다 50%↑ 등) + 문서수 비율 |
| 5 | 블로그 벤치마킹 | 같은 주제 블로그 찾기 → 계정 적합성 → 최근 글 수집 → AI 제목·본문 분석 → 키워드 추출·수치 조회. 관찰 목록(Watch) |
| 6 | 글 작성 준비(SERP) | 검색어 선택 → 실제 상위 5개 글 본문 확보 → AI 사전 지식 정리(근거 구간 확인, 원문과 지나치게 같은 문장 제외) → 보완 웹·뉴스 검색 → 사용자 승인 |
| 7 | 글 작성 | 승인 자료 + 내 문체로 구간별 초안 작성(개요 → 제목·소제목 → 본문 → 자료 활용·중복·밀도 점검), 이어쓰기·중지·재개 |
| 8 | 최종 검수 | 초안 선택 → 문체·작성 원칙·사실/출처·경험 표현·자료 유사 표현·민감/과장 표현 점검 → 수정 → 필수 수정 해결 시 최종본 저장 → 텍스트/서식 복사, TXT 내보내기 |
| 9 | 이미지 제작 | 글 붙여넣기 → 문단 구성 → 대표 1장 + 본문 5~10장 노드(담당 문단·담을 내용·표현 방식·요청) → 개별/전체 생성. 참고 이미지 최대 10장, 참고 사이트 5개, 유사 이미지 찾기(API HUB) |
| 10 | 데이터·로그 | 사용량, 백업·복구·초기화, 업데이트, 공지, 의견 |

공통 설계 특징: 모든 긴 작업은 **단계별 저장 → 중지해도 유지 → 다음에 미완료 단계부터 재개**(탐색당 최대 10분). AI 응답이 실제 본문과 맞지 않으면 적용하지 않고 원본 보존. "검색 순위·수익 보장 없음, 발행 전 확인은 사용자" 고지.

## 3. 웹 재구현 설계 (우리 방식)

| 원본 | 웹 버전 |
|---|---|
| ChatGPT 구독 + Codex 로그인 | **회원 본인 API 키**(`user_api_keys` — OpenAI / Gemini 선택). 운영자 키 폴백 없음(최상위 규칙). 웹에서는 개인 ChatGPT 구독 로그인을 쓸 수 없음 |
| 이미지(ChatGPT) | 회원 본인 **Gemini 이미지**(플랫폼 패턴 §12, Supabase Storage 저장) |
| 네이버 키(자격 증명 관리자) | 회원 본인 **검색광고 API**(License·Secret·Customer ID) + **네이버 검색 API**(developers.naver.com Client ID/Secret — 블로그·뉴스 검색·데이터랩 트렌드). 원본의 API HUB(ncloud 유료형) 대신 무료 개발자 센터 API 기본, 필요 시 HUB 추가. 계정당 한도가 있어 본인 키(최상위 규칙 예외 아님) |
| Kiwi 형태소 분석 | 서버에서 AI 추출 + 간단한 한국어 토큰 규칙(첫 버전). 필요하면 이후 형태소 분석 패키지 검토 |
| 내장 브라우저로 실제 상위 5개 | 서버에서 네이버 검색 API(블로그, 정확도순) 상위 결과 + 모바일 본문 가져오기. 실제 검색 화면 순위와 다를 수 있음을 화면에 고지(우회·스크래핑 차단 회피는 하지 않음) |
| 로컬 SQLite·백업 | 공용 Supabase 새 테이블(모두 `user_id` + RLS): 블로그·스타일 분석, 키워드 보관함, 자료 묶음, 초안·검수·최종본, 이미지 작업, 작업 단계 상태 |
| 10분 백그라운드 작업 | 단계 단위 API(각 60초 이내) + DB 저장 지점 + 화면이 다음 단계 호출(중지·재개 동일하게 유지) |
| 작성 지식(`knowledge.json`) | **사용하지 않음.** 네이버 공식 공개 가이드(서치어드바이저 콘텐츠 기본·어뷰징 가이드)를 우리 문장으로 요약한 작성 원칙을 새로 만든다 |
| 자동 업데이트·백업·로그 | 웹이라 불필요(배포로 대체). 사용량은 간단 기록만 |
| 화면 | 흰색 표준 + 좌측 번호형 작업 흐름 + API키등록·플랫폼연동 + 연동 매뉴얼 + 767px ☰ (원칙 19) |
| 연도 | 모든 프롬프트에 당해 연도·현재 월 주입(원칙 8, `koreaNowRule`) |

재사용: 검색광고·검색 API 호출은 `blog-keyword/src/lib/kw/naver.ts`, 트렌드는 `trending-product-finder/lib/naver/datalab.ts`, 블로그 RSS 수집은 `threads-content-ops/desktop/src/main/providers/blog.ts`를 참고. 서브프로젝트 뼈대는 `four-cut-comics`/`file-merge` 표준(권한·핸드폰·FREE 판정, 사이드바, 버전).

## 4. 단계별 구현 제안

| 단계 | 범위 | 비고 |
|---|---|---|
| **1차(MVP)** | 연결 설정(본인 AI·네이버 키) → ① 내 블로그 스타일 분석 → ② 키워드 탐색·직접 키워드(검색량·문서수·등급, 보관함) → ③ 글 작성 준비(상위 글 + 자료 승인) → ④ 초안 작성(내 문체) → ⑤ 최종 검수·최종본 복사 | 원본 핵심 흐름. v1.01 출시 단위 |
| 2차 | 트렌드 관측(뉴스·웹 요약 + 급상승 판정), 블로그 벤치마킹 | 검색·트렌드 API 호출량 많음 |
| 3차 | 이미지 제작(문단별 노드, 참고 이미지, 일괄 생성) | 회원 Gemini 키 |

- 프리미엄 후보 여부: 운영자 실비(고정 IP·자체 서버·유료 검색 도구) 없음 → **일반 프로그램**(원칙 16 기준). 단 서버 수집량이 크면 다시 판단.
- 기존 프로그램과 겹침: `blog-keyword`(키워드 수치), `naver-blog-agent`·`naver-blog-seo-studio`·`naver-blog-allinone`(글 작성). 이 프로그램의 차별점은 **"내 블로그 문체 분석 → 근거 자료 승인 → 내 문체 초안 → 검수"를 한 흐름으로 묶은 것**.

# 멀티에이전트·멀티세션 공동 작업 규칙

2026-10-23 · 주인님 지시로 등록 · AGY(Antigravity)·CODEX·CLAUDE CODE, 윈도우 메인 PC·맥미니 원격 보조 PC의 모든 세션에 적용합니다.

**목적:** 세션마다 담당·수정 자원·데이터 범위·배포 대상을 분명히 해 다른 세션의 작업을 덮거나 섞는 일을 줄입니다. 이 문서는 작업 조정 규칙이며 자동 잠금 장치가 아닙니다. 실제 파일·Git·DB 상태를 작업 직전에 다시 확인해야 합니다.

| 기본 브라우저 | Claude Code=해당 장비 Chrome, Codex=Edge, AGY=Whale의 실제 창. 주인님의 세션 지정 예외는 해당 세션에만 적용 |

## 2. 세션 식별과 시작 절차

1. 세션명을 정합니다. 예: `codex-win-20261023-guidelines`, `claude-mac-20261023-gif-guide`, `agy-win-20261023-editor`. 같은 세션의 ACTIVE_WORK·커밋 도우미 `--as`·인수인계에는 같은 식별자를 사용합니다.
   - **같은 세션명을 저장소 블랙박스에도(2026-10-23)**: 커밋·푸시 도우미는 `--as <세션명>`(`safe-commit.mjs`·`commit-paths.mjs`), 일반 git 명령은 `AIMASTER_SESSION=<세션명> git commit …`처럼 앞에 붙인다. 명령마다 셸이 새로 열리는 CLI(Claude Code 등)는 환경변수가 이어지지 않으므로 **매 명령에** 붙인다. 공용 스테이징 기록 `.git/aimaster-index-log.txt`에 세션명이 남아, 스테이징 축소 같은 사고 때 「어느 세션 직후였는지」를 바로 좁힐 수 있다.
   - **도우미는 세션 이름 필수(2026-10-23 주인님 결정, `54e2a5c29`)**: `safe-commit.mjs`·`commit-paths.mjs`는 `--as`나 `AIMASTER_SESSION`이 없으면 커밋하지 않고(종료 코드 2) 이름을 붙여 다시 실행하라고 안내한다. `--begin`과 커밋에는 같은 이름을 쓴다(기준 사본을 이름으로 찾음). 이름 첫 단어가 `claude-`·`codex-`·`agy-`가 아니면 커밋은 하되 「블랙박스가 CLI를 구분하지 못함」 안내 — 블랙박스의 CLI 구분·「시작 점검 누락」 알림이 이 첫 단어로 동작한다.
2. 작업 대상이 운영인지 Lab인지 정하고 DB ref·폴더·프로그램 slug·Vercel 프로젝트·건드릴 공용 자원을 확인합니다.
3. `git status --short`, 대상 폴더 차이, 최신 HEAD/관련 커밋, 스테이징을 확인합니다. 미커밋 파일이 있다는 이유로 본인 작업이라고 가정하지 않습니다.
4. ACTIVE_WORK에서 **장비·CLI·세션이 달라도 같은 폴더/자원을 맡았는지** 확인합니다. 비어 있을 때만 자기 행을 추가합니다. 기존 표의 네 칸(대상·에이전트·시작·작업)을 유지하고 작업 칸에 범위와 다음 확인점을 적습니다.
5. 행을 쓴 직후 표와 대상 파일을 다시 읽습니다. 다른 세션도 같은 자원을 예약했다면 편집 전에 충돌을 조정합니다. 예약표 기록만으로 상호배제가 보장됐다고 가정하지 않습니다.

같은 서브프로그램을 동시에 수정하지 않습니다. 담당자가 있는 영역의 읽기 분석은 가능하지만 파일·DB·빌드 산출물·확장 설치 상태를 변경하지 않습니다. 현재 담당자의 작업을 필요로 하면 인수인계로 요청하며, 승인된 담당 전환을 확인하기 전에는 대신 수정하지 않습니다.

## 3. 폴더 외에 함께 확인할 공유 자원

폴더가 달라도 다음 자원이 같으면 충돌할 수 있습니다. 변경 전 범위를 확인하고 필요한 단위로 ACTIVE_WORK에 공용 자원 예약을 남깁니다.

| 자원 | 충돌을 판단하는 단위 | 작업 방식 |
|---|---|---|
| 공용 코드 기준/사본 | 기준 모듈·사본 동기화 대상 | 기준 담당 세션 한 곳에서 수정·동기화, 사본 프로그램 담당자와 검사/배포 순서 조정 |
| 공용 문서 | 파일·절·항목 | 아래 4절 적용. 대규모 구조 변경은 해당 문서/절의 단독 담당 예약 |
| DB 스키마·RLS·트리거·함수 | 프로젝트 ref+DB 객체 | 같은 객체 변경은 한 세션만 실행. 전후 SQL/마이그레이션·영향 범위 인계 |
| 프로그램 메타데이터 | ref+`programs` slug | 같은 프로그램의 버전/주소/다운로드 갱신은 배포 담당 세션이 처리 |
| 회원 데이터·발행 실행 | ref+테이블+소유자/대상 행+실행 번호 | 같은 행/실행을 동시에 수정·복구·재전송하지 않음 |
| Storage | ref+버킷+대상 경로 | 업로드·삭제·이동·공개/비공개·정책 변경을 조정. 버킷 전체 변경은 관련 프로그램 영향 확인 |
| 빌드·의존성 | 프로그램의 `node_modules`·lockfile·`.next`·생성물 | 설치/빌드/산출물 재생성은 한 담당 세션만 실행 |
| 배포·환경변수·도메인 | Vercel 프로젝트+운영/미리보기 대상 | 같은 대상 동시 배포/설정 변경 금지. 직전 소스·버전·대기분 재확인 |
| 브라우저·확장·편집기 | 장비+브라우저/프로필+작업 창/탭+설치 확장 | 다른 세션 창·확장 새로고침·원고 발행·로그인 상태를 변경하지 않음 |

다른 프로그램의 독립된 행을 다루는 경우까지 DB 전체를 독점하지 않습니다. 충돌 가능성이 있는 객체/행/작업 단위만 예약합니다. 단, 스키마 변경과 정리 작업 등 여러 행에 영향을 주는 작업은 해당 전체 범위를 먼저 알립니다.

## 4. 공용 문서의 수정 규칙

- 기존 정책대로 루트 공용 문서의 **독립적인 자기 항목 추가**는 프로그램 폴더 전체 예약과 구분합니다. 자기 문단·표 행만 추가/수정하고 다른 세션의 줄을 정리하지 않습니다.
- 파일 전체 재작성, 표/목차 구조 변경, 기존 규칙의 이동·요약·삭제처럼 여러 항목에 영향을 주면 범위를 먼저 알리고 해당 문서/절을 단독 작업 자원으로 예약합니다. 주인님이 원문 보존을 요청했으면 원문을 남기고 별도 요약만 추가합니다.
- 수정 직전 `node scripts/safe-commit.mjs --begin <파일>... --as <세션명>`으로 기준 사본을 만들고, 수정 뒤 같은 세션명으로 도우미를 사용합니다. 긴 작업이면 파일 저장 직전에 최신 내용과 차이를 다시 확인합니다.
- HANDOFF 맨 위 항목 하나는 도우미의 `--handoff` 방식으로 추가합니다. 예전 파일 전체 사본을 덮어쓰거나 오래된 상태로 표를 재생성하지 않습니다.
- 도우미의 결과 미리보기에 다른 세션 내용이 포함되거나 기존 항목이 사라지면 완료 처리하지 않습니다. 같은 절을 서로 다르게 수정한 충돌은 근거를 비교해 해결하고 결과를 인계합니다.
- 자세한 명령·도우미 한계는 [협업 상세 9번](CLI_COLLABORATION_RULES.md)을 확인합니다. 도우미를 사용해도 전후 diff 확인은 생략하지 않습니다.

## 5. 공유 Git·스테이징 규칙

1. 파일을 저장하기 전후와 커밋 직전에 최신 HEAD·대상 diff·스테이징을 다시 확인합니다. 다른 세션이 커밋한 경우 최신 결과와 양쪽 의도를 비교합니다.
2. `git add .`, `git add -A`, `git commit -a` 등으로 관계없는 변경을 일괄 포함하지 않습니다. 일반 파일의 커밋에도 `git commit -m "…" -- <본인 경로>`처럼 경로를 지정합니다. 다른 세션이 실제 스테이징한 내용은 보존하고 공용 문서는 기존 안전 커밋 경로를 사용합니다.
3. 공유 작업 폴더에서 다른 세션의 변경을 정리하기 위한 reset/stash/checkout/clean을 하지 않습니다. 다른 세션이 작업 중일 때 브랜치 전환·rebase·merge·pull의 작업 트리 변경을 독단 실행하지 않고 범위와 실행 순서를 먼저 조정합니다. 원격 최신 확인과 실제 병합을 구분합니다.
4. `.git/index.lock`이 있으면 지우지 않고 실행 중 Git 작업을 확인합니다. 인덱스를 임의로 삭제·초기화·전체 덮어쓰지 않습니다. 도우미의 임시 인덱스와 공용 인덱스를 혼동하지 않습니다.
5. 커밋 결과의 파일 목록·삭제 규모·요청 범위·부모 HEAD를 확인합니다. 작은 작업인데 수천 파일 삭제처럼 예상 밖 결과가 있으면 푸시/배포를 멈추고 로컬 파일·직전 HEAD·인덱스를 보존한 채 원인을 조사합니다.
6. 푸시 직전 원격/로컬 상태를 대조합니다. 다른 세션의 선행 커밋을 force push로 덮지 않습니다. 푸시 거절 시 다른 세션 결과를 확인하고 공유 작업 트리 전체를 임의로 재정렬하지 않습니다.

루트 최상단에 함께 등록된 2026-10-23 사고 재발 방지 지침의 `check-index-health.mjs`·pre-commit/pre-push 보호 장치를 끄거나 `--no-verify`로 우회하지 않습니다. git 작업은 특히 SMB에서 중간 강제 종료하지 않습니다. 경고가 발생하면 해당 작업을 멈추고 담당/HEAD/현황판을 확인합니다. 정상 파일 개수 같은 숫자는 고정 가정하지 않고 현재 정상 트리와 비교합니다.

이 규칙은 최근 공유 인덱스 축소 사고를 포함한 [에러 교훈](ERROR_LESSONS.md)의 기존 점검과 함께 적용합니다. 다른 세션이 만든 변경의 정리·복구를 이번 작업의 수정으로 섞지 않습니다.

## 6. DB·회원 데이터 수정 규칙

### 수정 전

- 대상 프로젝트 ref, 실제 테이블/칼럼/정책·최신 마이그레이션, 프로그램 slug, 소유자와 수정할 행을 확인합니다. 운영/Lab 연결을 추측하지 않습니다.
- 작업 플랜/승인 범위·자원 담당과 충돌하지 않는지 확인합니다. 조회 가능한 것과 쓰기 권한이 있는 것을 구분합니다. 권한 확인용 관리 클라이언트가 회원 데이터 소유권 확인을 대신하지 않습니다.
- 변경할 행 수와 조건을 읽기로 미리 확인합니다. 큰 변경은 대상/영향·되돌리기 방법을 남기고, 개인정보·키·회원 원문을 공유 문서에 복사하지 않습니다.

### 수정할 때

- 회원 데이터는 **소유자 조건 + 행 식별자**를 함께 지정합니다. 실행/편집 데이터는 가능한 기존 **runId·revision·현재 상태·갱신 시각 등 기대값**까지 조건에 포함해, 읽은 뒤 다른 세션이 바꾼 값을 덮지 않게 합니다.
- 기대한 행 수와 실제 변경 행 수를 대조합니다. 0행이면 조건을 넓혀 재실행하지 말고 최신 상태·권한·다른 세션 변경을 확인합니다. 예상보다 많은 행이 대상이면 중단해 범위를 다시 점검합니다.
- 관련 여러 행은 기존 트랜잭션/RPC 등 원자적 변경 경로를 우선합니다. 마이그레이션은 고유한 시각+작업명으로 해당 프로그램에 보관하고 같은 이름/객체를 두 세션이 따로 적용하지 않습니다.
- 공용 테이블에 자기 프로그램 데이터를 쓰는 경우 slug 등 프로그램 범위를 유지합니다. 모든 회원/프로그램의 값을 일괄 수정하거나 전체 데이터로 덮어쓰는 쿼리는 일반 수정의 대안으로 쓰지 않습니다.
- 최초 생성/수집 시각·회원 소유자·원래 30일 만료·기존 이용권을 유지합니다. 복구/이관을 이유로 새 생성일을 부여하거나 타 회원 데이터를 재사용하지 않습니다.
- 다른 회원/프로그램에 영향이 있는 삭제·스키마 축소·RLS 완화·버킷 공개 전환·키/계정 폐기는 명시적으로 승인된 범위만 처리합니다. 단순 오류 수정이나 분석 요청에 포함됐다고 간주하지 않습니다.

### 수정 후

대상 행·변경 수·소유자·관련 상태·영향받지 않아야 할 범위를 다시 확인합니다. 인수인계에는 ref·객체·마이그레이션·대상 조건의 의미·전후 결과·한계·다음 단계를 남기며 비밀값을 쓰지 않습니다.

## 7. 자동 포스팅·복구·브라우저 충돌 방지

- 같은 플랫폼 계정/원고/실행을 두 세션이 동시에 보내거나 발행하지 않습니다. 연결된 다른 브라우저/PC의 확장이 대기 작업을 가져갈 수 있으므로 시험 계정·확장·현재 실행 담당을 확인합니다.
- 입력·발행 중인 사이드패널/탭/확장을 다른 세션이 닫거나 새로고침·업데이트하지 않습니다. 설치 확장 변경은 현재 작업이 끝난 뒤 담당자가 합니다.
- 발행 요청 뒤 응답이 없으면 실패로 단정해 최종 버튼을 다시 누르지 않습니다. 실제 게시 결과·실행 번호·기존 outbox/결과 재확인 경로를 대조해 결과만 복구합니다.
- 기존 미발행·준비 원고를 시험용으로 바꾸지 않습니다. 새 실제 발행 시험은 승인된 계정·합성 원고·공개 범위·횟수로 수행하고 수동 결과 복구와 자동 성공을 구분합니다.

## 8. 배포·환경변수·맥미니 인계

- 같은 프로그램의 배포/버전/DB 메타데이터 갱신은 한 세션이 담당합니다. 배포 직전 최신 소스·공용 사본·미배포 대기분·ACTIVE_WORK를 다시 확인해 다른 세션의 미검수 코드가 섞이지 않게 합니다.
- 비용 사전 승인을 확인하고 [배포 비용 절감](VERCEL_COST_REDUCTION_PLAN.md)·[시험 비용](TEST_COST_POLICY.md)·`deploy.mjs` 절차를 따릅니다. 이미 승인된 범위는 반복 승인받지 않습니다.
- Ready·공식 도메인·라이브 버전·확장/ZIP·DB 버전까지 확인한 담당자가 운영 완료를 기록합니다. 다른 세션의 작업 완료/예약 해제를 대신 표시하지 않습니다.
- 환경변수는 프로젝트·환경·변수명을 명시하고 해당 값의 다른 프로그램/콜백 의존성을 확인합니다. 다른 세션 값의 삭제·교체·키 폐기를 임의로 하지 않습니다.
- 맥미니는 기존 지침대로 코드/문서와 허용된 검사를 하고, 설치·dev/build·배포·확장 ZIP·운영 DB 쓰기는 윈도우에 인계합니다. 공용 `node_modules`를 macOS용으로 다시 설치하지 않습니다.
- 인계에는 **세션명·프로그램·기준 커밋·변경 파일·로컬 검사/미검수·기대 버전·대기분·필요 자원·비용 승인 범위·다음 실행 순서**를 적습니다. 윈도우 담당자는 최신 내용과 자기 자원 예약을 확인한 뒤 인수합니다.

## 9. 충돌·중단·담당 전환

1. 충돌한 파일/행/배포/탭의 변경을 멈추고 현재 파일·증거를 보존합니다. 관련 없는 독립 작업은 허용 범위에서 계속할 수 있습니다.
2. 세션명·자원·양쪽 목적·최신 지시·차이·영향을 비교합니다. 어느 CLI가 작성했는지나 수정 시각만으로 선택하지 않습니다.
3. 호환 가능한 보완은 기존 작업을 보존해 합치고 근거를 남깁니다. 같은 내용을 서로 다르게 바꿨거나 영향 판단이 어려우면 주인님께 차이와 추천 방향을 설명합니다.
4. 담당 전환은 기존 담당자의 인수인계/종료 또는 주인님의 명시적 재배정을 확인합니다. 오래된 행·무응답만으로 잠금을 강제 해제하지 않습니다. 기존 24시간 지난 행도 확인 후 처리 원칙을 유지합니다.
5. 끝날 때 실제 완료/미완료·검수·비용·커밋/푸시·배포·남은 일·다음 첫 단계·서비스/문서 링크를 남기고 **본인 세션의 행/자원 예약만** 정리합니다.

## 2. 핵심 지침 (맨 위 블록과 같은 내용)

### 첫째, 시작 전 — 누가 무엇을 하는지 본다
- `docs/ACTIVE_WORK.md`(같은 폴더·같은 파일을 다른 세션이 잡고 있는지), `node scripts/dev-requests.mjs list --role <내 역할>`, `docs/HANDOFF.md` 맨 위, 프로그램의 상호 인수인계 문서(예: `mall-builder/docs/HANDOFF_DESIGN_BUILDER_BACKEND_SYNC.md`)를 읽는다.
- `git status --porcelain -- <내가 고칠 파일>`에 이미 수정 표시(` M`)가 있으면 **남의 미커밋 작업**일 수 있다 → 그 세션이 커밋할 때까지 기다리거나 상호 인수인계에 알리고 시작한다.
- 같은 프로그램을 여러 역할이 나눠 맡으면 **범위(파일·폴더)를 ACTIVE_WORK 자기 줄에 적고 그 범위만** 고친다.

### 둘째, 커밋 직전 — 내 줄만 들어가는지 본다
- 커밋은 `node scripts/commit-paths.mjs "<메시지>" <내 경로>... --as <세션>`(공용 문서는 `safe-commit.mjs`, `--begin` 먼저). `git add -A`·`git add .`·경로 없는 커밋 금지.
- **커밋할 파일마다 `git diff -- <파일>`을 열어, 내가 쓰지 않은 줄이 있으면 그 파일은 커밋하지 않는다.** 그 줄의 주인 세션에 알리고(상호 인수인계·ACTIVE_WORK) 그 세션이 먼저 커밋하게 한다. 파일 일부만 골라 커밋하는 대화형 방법(`git add -p`)은 이 환경에서 쓸 수 없다.
- **새 파일을 불러오는(import) 줄을 커밋하면 그 새 파일도 같은 커밋에 넣는다.** 커밋 뒤 `git show --stat HEAD`로 파일 수를 확인하고, 불러오는 파일이 `git ls-files`에 있는지 본다(HEAD가 없는 파일을 부르면 배포 빌드가 깨진다).
- **커밋 도우미 출력에 ⚠ 줄이 있으면 반드시 읽는다.** 2026-11-15부터 공용 스테이징 맞추기가 잠금 경합으로 보류되면 맨 마지막 줄에 「커밋은 정상, 공용 스테이징 맞추기는 보류 — 대기열에 남김」이 나오고, 대기열(`.git/aimaster-pending-sync`)은 다음에 아무 세션의 도우미가 자동으로 맞춘다(`scripts/index-pending-sync.mjs`). 그래도 직후 `git status --porcelain -- <방금 커밋한 경로>`가 비어 있는지 한 번 본다(docs/ERROR_LESSONS.md 2026-11-15).
- 남의 파일이 내 커밋에 섞였거나, 남의 커밋에 내 줄이 섞인 것을 발견하면 **되돌리지 말고**(작업이 사라짐) 빠진 쪽을 바로 커밋해 HEAD를 정상으로 맞추고, 상호 인수인계와 HANDOFF에 적는다.

### 셋째, 공용 파일 — 작게, 한 목적, 바로 커밋
- 여러 역할이 함께 쓰는 파일(예: 공용 레이아웃·`globals.css`·등록표)은 **한 번에 한 목적만, 고친 즉시 커밋**한다. 고친 채로 오래 두지 않는다(남의 커밋에 섞이는 가장 흔한 원인).
- 큰 추가는 **새 파일**로 만들고 공용 파일에는 연결 한두 줄만 넣는다(예: `templates-extra.ts` + `LAYOUTS.push`). 연결 줄과 새 파일은 같은 커밋으로.

### 넷째, 남의 것은 건드리지 않는다
- 다른 세션의 개발 서버(예: 3210 포트)·브라우저 탭/작업 공간·미커밋 파일·역할 파일을 끄거나 고치거나 지우지 않는다.
- 다른 역할 몫을 발견하면 직접 고치지 않고 그 프로그램 `docs/IMPROVEMENTS.md` 「○○ 담당께」 + 채팅 프롬프트로 넘긴다.
- `.env*`에는 어떤 글도 쓰지 않는다(🔐 블록).
- 스테이징 정리(`reset --hard`·`checkout .`·`stash`·`index` 삭제) 금지 — 루트 🚨 블록.

### 다섯째, 배포 — 한 번에 하나, 담당과 함께
- 같은 프로그램을 여러 역할이 맡으면 **배포는 정해진 한 세션(보통 백엔드 담당)이 상호 인수인계의 「함께 배포」 줄로 묶어서** 한다. 다른 역할은 배포하지 않고 「미배포 대기」로 적어 넘긴다.
- 배포 직전 팀 전체 빌드 중 여부 확인, 한 번에 하나(기존 동시 빌드 금지 규칙).

### 여섯째, 끝나면 — 남긴다
- 작업이 끝날 때마다 상호 인수인계(번호 매긴 메시지 줄)·`docs/HANDOFF.md` 맨 위(`[역할: <ID>]`)·역할 파일을 갱신하고 ACTIVE_WORK 자기 줄을 고친다.
- 사고(섞인 커밋 등)가 났으면 `docs/ERROR_LESSONS.md`에 「증상 → 원인 → 해결 → 다음부터」로 남긴다.

## 3. 커밋 직전 점검 한 줄 모음

```bash
git status --porcelain -- <내 파일들>          # 남의 미커밋 표시 확인
git diff -- <파일>                              # 내 줄만 있는지 눈으로 확인
node scripts/commit-paths.mjs "<메시지>" <경로>... --as <세션>
git show --stat HEAD | tail -1                  # 파일 수·삭제 수 확인
git ls-files <새로 불러오는 파일>               # HEAD에 들어갔는지
```

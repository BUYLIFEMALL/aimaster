## 3. 정리 — 확장 설계 결정에 쓸 내용

1. **입력 순서가 정해져 있다**: 카테고리 → (옵션·인증·고시 칸이 생김) → 나머지. 카테고리를 고르기 전엔 옵션이 막혀 있다.
2. **손으로 미리 만들어야 하는 것**: 출고지·반품지 주소, 배송비 정책(번호), 영업허가증 — 모두 ESM+ 「배송정보관리」 등에서 판매자가 먼저 만들어 둔 것을 고르기만 한다. → 처음 설정 단계에 「ESM+에서 배송비 정책 1개 만들기」 안내가 필요(자동화 지표 「처음 설정」에 포함).
3. **가장 단순한 경로**: 상세설명 = HTML 탭 붙여넣기, 고시 = 「상세설명 참조로 전체 입력」, 인증 = 「인증대상이 아님」 기본. 대부분 버튼 글자로 고르는 화면이라 스마트스토어 등록기보다 단순하다.
4. **찾기 규칙**: 매번 바뀌는 React id를 쓰지 말고 구역 제목·칸 이름 글자로 찾는다(위 1절). 화면이 바뀌면 깨지기 쉬운 곳이므로 칸 찾기 실패 시 「어느 구역 어느 칸」을 결과로 돌려준다(블로그 지침 ④처럼 불확실하면 다시 등록하지 않음).
5. **아직 못 본 화면**: 이미지 업로드 뒤 미리보기·순서 바꾸기, 에디터 작성 탭(스마트에디터 류), 「카테고리 선택」(단계별 고르기) 방식, 임시저장 뒤 목록 위치, 등록 결과 화면(상품번호 표시 형식). 등록 결과 화면은 실제 등록이 필요하므로 시험 상품 1개 등록을 주인님이 승인하실 때 확인한다.

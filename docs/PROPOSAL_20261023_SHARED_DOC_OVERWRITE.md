## 2. 왜 생기는가

1. **한 파일에 모두가 맨 위에 쓴다** — 1.8MB 파일의 같은 자리(맨 위)를 여러 세션이 몇 분 간격으로 고친다.
2. **「읽은 뒤 → 커밋」 사이가 길다** — 세션이 파일을 읽고(또는 자기 인덱스에 올리고) 몇 분 뒤 커밋하면, 그 사이 다른 세션 커밋이 빠진 채로 올라간다(마지막에 쓴 사람이 이김).
3. **공용 인덱스가 옛 내용을 들고 있다** — 별도 인덱스로 커밋한 뒤 공용 인덱스를 HEAD에 맞추지 않으면, 다음에 공용 인덱스로 커밋하는 세션이 그 파일을 옛 내용으로 되돌린다(Claude Code도 2번 빠뜨림 — 바로잡음).
4. 이런 되돌림은 **커밋 메시지에 안 드러나고**(그 세션은 자기 변경만 한 줄 알음) 나중에 우연히 발견된다.

## 3. 방안 비교

| 방안 | 내용 | 막는 정도 | 바뀌는 것(모든 CLI) | 비용·위험 |
|---|---|---|---|---|
| **A. 날짜·작성자별 새 파일** | `docs/handoff/2026-10-23/claude-win-0103-thumbnail-v119.md`처럼 **항목마다 새 파일**. `docs/HANDOFF.md`는 맨 위 안내 + 최근 목록만(또는 하루 1번 자동으로 모음) | **매우 큼** — 서로 다른 파일이라 덮어쓸 수 없음 | 모든 CLI의 「HANDOFF 맨 위에 추가」 지침(CLAUDE.md·AGENTS.md·GEMINI.md·여러 문서) 변경, 다른 CLI가 읽는 위치 변경 | 비용 없음. 기존 1.8MB 파일은 그대로 보관. 지침이 퍼지기 전까지 두 방식이 섞임 |
| **B. 「되돌림 감지」 경고 훅** | 기존 `pre-commit` 틀(경고만, 커밋은 안 막음)에 점검 추가: 이번 커밋이 공용 문서(HANDOFF·PENDING_DEPLOYS·CAPABILITY_MAP·SHARED_MODULES·IDEA·ERROR_LESSONS)에서 **최근 2시간 안 다른 커밋이 넣은 줄을 지우면** 「⚠ 다른 세션이 방금 넣은 n줄을 지웁니다」 경고 | 중간 — 경고를 읽는 세션이면 막힘(CLI 출력에 남음) | 훅 설치(`node scripts/git-hooks/install.mjs`, 윈도우·맥미니 각 1회) | 비용 없음. 커밋을 막지 않아 일 흐름은 그대로 |
| **C. 안전 커밋 도우미** | `node scripts/safe-commit.mjs "<메시지>" <파일>…` — 커밋 직전 **최신 HEAD를 다시 읽어 내 변경만 얹고**, 커밋 뒤 공용 인덱스를 HEAD에 맞춤(Claude Code가 지금 손으로 하는 방식을 도구로) | 중간~큼 — 도우미를 쓰는 세션은 되돌림을 만들지 않음 | 각 CLI 지침에 「공용 문서는 이 도우미로 커밋」 한 줄 | 비용 없음. 안 쓰는 CLI가 있으면 효과 줄어듦 |
| D. 현행 유지 | HEAD 기준 내 변경만 커밋 + 덮이면 다시 반영 | 작음 | 없음 | 계속 발견·복구 비용 |

## 4. 추천

1. **지금(가벼움): B + C** — 구조는 그대로 두고, 훅이 되돌림을 **알려 주고**, 도우미가 **만들지 않게** 한다. 모든 CLI 지침에는 C 한 줄만 추가.
2. **다음(효과 큼): A** — B 경고가 계속 뜨거나 HANDOFF가 2MB를 넘으면 날짜·작성자별 파일로 전환. 전환 때는 기존 파일을 보관용으로 두고, 「맨 위 항목 읽기」 지침을 「`docs/handoff/` 최근 파일 읽기」로 바꾼다.

# 마케팅 프로그램 예외·우회 지침 (기준 문서 — 모든 CLI 공통)

> 2026-10-27 주인님 지시: 「이 내용을 마케팅 프로그램 예외/우회 지침으로 넣어놔」. 마케팅용 데이터·회원·아이디 수집과 발송 자동화를 **관리자 지정 예외**로 개발할 때의 기준이다.
> 작성: Claude Code(윈도우) `claude-win-20261027-analysis` [역할: analysis-planning].
> 이 문서는 [최상위 규칙 §0-2·§8](TOP_RULE_PERSONAL_ACCOUNT_API.md)의 요약·실행 지침이며, 충돌하면 최상위 규칙과 최신 주인님 지시가 우선한다. 봇 탐지 회피 세부는 [`docs/PLATFORM_PATTERNS.md` §20](PLATFORM_PATTERNS.md)을 함께 본다.

## 1. 왜 이 지침이 있나 (배경)

마케팅 자동화 프로그램은 **대부분 플랫폼 정책상 어뷰징(약관 위반)**에 해당한다. 그러나 **마케터에게는 업무 효율을 위해 꼭 필요한 도구**다. 그래서 무조건 막지 않고, 관리자(주인님)가 지정한 프로그램에 한해 **위험을 분산·완화**하며 제공한다. 핵심 균형: **최대한 플랫폼 정책을 따르면서, 꼭 필요한 부분만 회원 책임으로 우회한다.**

## 1-1. 공개 등록 연락처를 수집해도 되는 근거 (2026-10-27 주인님)

채널·프로필 운영자는 **원치 않으면 이메일·연락처를 아예 등록하지 않는다.** 그런데도 프로필·채널 정보란에 연락처를 등록해 둔 것은, **본인 채널 홍보·연락 받기(제휴·광고·문의) 목적으로 일부러 노출한 것**이다(인스타·쓰레드·유튜브·블로그·업체 플레이스 등 공통). 따라서 그렇게 공개·등록된 비즈니스 연락처는 그 공개 목적 범위에서 **자동화 프로그램으로 수집·이용할 수 있다.** 반대로 등록하지 않은 사람·비공개·사적 연락처는 수집하지 않는다(그 사람은 연락을 원치 않는다는 뜻).

## 2. 언제 적용하나

- 개인정보·연락처·아이디·회원 정보 수집, 또는 대량 발송·초대가 들어가는 프로그램.
- **반드시 관리자 지정이 있어야 한다** — 주인님이 채팅에서 그 프로그램을 「예외」로 지정하고 [최상위 규칙 §8 「마케팅 수집 지정 목록」](TOP_RULE_PERSONAL_ACCOUNT_API.md)에 적혀 있을 때만. 지정 없이 에이전트가 스스로 「마케팅이니 된다」고 넓히지 않는다.

## 3. 필수 설계 규칙 (모두 지킨다)

1. **우리 서버 고정 IP로 수집·발송하지 않는다.** 대상 플랫폼(네이버·인스타·구글·유튜브·카카오 등)에 보내는 **모든 트래픽·데이터 처리는 회원 각자의 PC·핸드폰**에서 그 회원의 네트워크·계정으로 일어난다(크롬 확장·데스크톱 앱·모바일). 우리 서버는 화면·설정·회원별 저장만 하고 대상 플랫폼에 직접 요청하지 않는다 — 한 IP에 몰려 통째로 차단되는 것을 막고 위험을 회원별로 분산한다.
2. **회원 본인 계정·본인 키만** 쓴다. 운영자·다른 회원 계정으로 대신 수집·발송하지 않는다.
3. **기본은 안정적인 리미트(상한)**. 하루·시간당 횟수 상한과 사람 같은 속도(§20)를 기본값으로 둬 플랫폼이 정상 사용으로 보는 범위 안에서 동작한다. **회원이 필요하면 VPN·IP 변경 서비스를 본인 책임으로 연동**해 상한을 넓힐 수 있다(선택, 기본 꺼짐).
4. **발송은 회원이 자기 기기에서 직접.** 수집 뒤 발송 여부는 회원 각자 책임이며, 회원 본인 PC·핸드폰에서 회원이 눌러 발송하는 형태로 설계한다(우리 서버가 대신 대량 발송하지 않음).
5. **수집 결과는 회원 본인 소유로 격리**(owner-only RLS·회원별 저장), 다른 회원과 공유·재사용 금지. 보관 기간은 최상위 규칙 §0 기준.
6. **사용 책임 고지(리스크 전달)**: 첫 실행·설정·수집/발송 직전에 「이 기능은 플랫폼 약관 위반·계정 제재·법적 책임의 소지가 있으며, 사용·발송 책임은 회원 본인에게 있다」를 확인(동의 체크)받고, 수집 대상·목적·사전 동의 필요를 화면에 적는다.

## 3-1. 목적 — 회원 개인의 마케팅 데이터 구축 (2026-10-27 주인님 지시)

이 프로그램들의 목적은 **회원 각자가 본인 마케팅에 쓸 데이터를 본인 소유로 구축**하는 것이다(업체 리스트·경쟁/협업 대상·카페 회원 등).
- 수집은 **회원 본인 기기·본인 계정**에서 일어나고, 결과는 **그 회원만 보는 저장소**(owner-only RLS·회원별)로 쌓인다.
- **다른 회원과 공유·복사·재사용·판매하지 않는다.** 운영자도 회원 수집 데이터를 들여다보거나 합치지 않는다.
- 한 곳에 몰린 대량 DB가 아니라 회원마다 흩어진 본인 자료라, 데이터·트래픽·법적 위험이 회원별로 분산된다(지침 §3-1).
- **연락처(이메일·전화)**: 수집 항목에 포함하되 **「당사자가 영업·홍보·제휴 목적으로 공개한 비즈니스 연락처」만**(§4). 사적·비공개 연락처 자동 수집은 제외(제50조의2).

## 4. 수집 정보·범위 (2026-10-27 주인님 지시로 확정)

- **수집 정보 = 아이디 · 이메일 · 연락처 · 공개 통계**를 포함한다(주인님 「수집정보: 아이디·이메일·연락처」).
- **연락처(이메일·전화)는 「당사자가 프로필·채널에 스스로 등록·공개해 둔 것」을 수집한다.** 주인님 판단(2026-10-27): **인스타·쓰레드·유튜브·블로그 등에서 프로필·채널 정보란에 연락처·이메일을 등록해 둔 것은, 본인 채널 홍보 목적·연락 받을 목적으로 일부러 노출해 둔 것**이다(유튜브 채널 비즈니스 이메일, 인스타/쓰레드 프로필의 이메일·연락처 버튼, 블로그 프로필·소개의 연락처, 업체 플레이스·홈페이지의 대표 연락처). 그래서 그 공개 목적(연락·제휴·문의) 범위에서 수집·이용할 수 있다.
  - **포함**: 위처럼 당사자가 영업 목적으로 공개한 비즈니스 연락처. → 그 공개 목적(제휴·문의) 범위라 수집·이용 여지가 크다.
  - **제외**: 사적으로 올린 개인 연락처, 비공개 정보, 로그인·우회로만 보이는 것, 당사자가 공개하지 않은 것. 이런 것의 자동 수집은 정보통신망법 제50조의2(무단 수집) 위반 위험이 크므로 넣지 않는다.
  - **수집 방식**: 이렇게 당사자가 공개·등록해 둔 비즈니스 연락처는 **자동화 프로그램으로 수집해도 된다**(주인님 2026-10-27 「예외적으로 자동화 프로그램에서 수집해도 되」). 안정적 리미트·사람 같은 속도(§5)로 회원 본인 기기에서 수집한다.
  - 화면에 「공개된 비즈니스 연락처만 담깁니다. 수집·연락은 그 공개 목적(제휴·문의) 범위에서, 회원 본인 책임입니다」를 고지한다.
- **카페 회원 수집**: 회원이 **운영·가입한 카페 + 동의 범위**에서만. 남의 카페 전수 수집 ❌.
- **발송(동의 없는 광고 금지)**: 공개된 비즈니스 연락처라도 **보낼 때는 광고성 정보 사전 동의**(정보통신망법 제50조)가 필요하다 — 제휴·문의 같은 그 공개 목적에 맞는 연락만 하고, 동의 없는 광고 대량 발송은 하지 않는다. 발송은 회원 기기에서 회원 책임으로.

## 5. 「최대한 안전하게」 우회 설계 방법 (에이전트가 찾아 적용)

주인님 지시: 「최대한 안전하게 사용할 수 있는 우회 방법을 찾아야 된다.」 개발 담당은 아래를 기본으로 적용하고, 플랫폼별로 최신 방법을 조사해 보완한다.

| 영역 | 안전 설계 방법 |
|---|---|
| 접속 주체 | 회원 본인 기기·본인 로그인 세션에서만(우리 서버 경유 ❌). 공식 API가 있으면 공식 API(회원 본인 키) 우선, 없을 때만 회원 기기의 확장이 공개 화면을 읽음 |
| 속도 | `Input.insertText` 한 글자 70~170ms·가끔 250~700ms 쉼(§20), 요청 사이 무작위 간격, 한 번에 조금씩 |
| 양 | 하루·시간당 상한을 보수적으로(플랫폼이 공개한 한도보다 낮게), 연속 작업 사이 긴 휴식, 상한 근접 시 자동 중단 |
| 사람 같은 패턴 | 밤낮·주말 동작 시간대 제한, 매번 같은 시각·같은 간격 금지(±흔들기), 마우스/스크롤 섞기 |
| 중단 | 「제한」·보안 문자·로그인 풀림 안내가 뜨면 **즉시 멈춤**(자동 재시도·우회 ❌), 그날 중지, 회원 알림 |
| IP | 기본은 회원 자기 IP. 회원이 켤 때만 VPN·IP 변경 서비스 연동(본인 책임), 한 작업 안에서 급격히 바꾸지 않음 |
| 계정 | 회원 본인 계정만. 한 기기에서 여러 계정을 빠르게 돌리지 않음(제재 신호) |
| 데이터 | 공개된 것만(당사자가 프로필·채널에 등록·공개한 비즈니스 연락처는 **자동화 프로그램으로 수집 가능**, §4), 사적·비공개 개인정보는 제외, 회원별 격리·기한 삭제 |
| 금지 | 보안 문자 자동 풀기, 플랫폼 계정 대량 생성, 로그인 우회 — 이 지침의 예외에 포함되지 않음(별도 지시 때만) |

이 방법들은 **「탐지를 뚫는 공격」이 아니라 「사람의 정상 사용처럼 보이게 해 계정·데이터를 지키는 보호」**가 목적이다. 플랫폼 화면·정책이 바뀌면 다시 조사해 보완한다.

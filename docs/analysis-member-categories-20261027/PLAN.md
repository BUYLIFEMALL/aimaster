## 1. 원칙 한 줄

**카테고리는 회원 본인 소유이며, 같은 계정(같은 사람)의 여러 프로그램이 함께 쓰되, 다른 회원과는 절대 공유하지 않는다.**
→ CLAUDE.md 「회원 연동 정보 공용 저장·재사용」(한 번 등록 → 그 회원의 모든 프로그램이 재사용, 타인과 격리, RLS owner-only)과 같은 패턴. 관리자 공용 카테고리는 두지 않는다(주인님: 「관리자가 공용 카테고리를 만들 이유가 없어」).

## 2. 현재 실태 (2026-10-27 조사)

| 프로그램 | 카테고리 저장 | 회원 격리 | 비고 |
|---|---|---|---|
| `ai-auto-blog` | `blog_categories`(공용, `user_id` 없음) | ❌ 없음 | 지금 문제 — 관리자만 변경, 일반 회원은 읽기만 |
| `blog_auto_poster` | 같은 `blog_categories` | ❌ 없음 | ai-auto-blog와 같은 테이블 공유(한쪽만 바꾸면 깨짐) |
| `tistory-auto-blog` | 자체 회원별 카테고리(`user_id`) | ✅ 있음 | **이미 회원별 + 본인만 접근**(모범). 마이그레이션 0001에 「BLOG는 공용이라 남의 카테고리를 지울 수 있었다 → 여기선 회원별」로 교훈 기록 |
| `insta_auto_poster` | 카테고리 개념 있음(용도·구조 확인 필요) | 확인 필요 | 블로그 글 분류와 같은 의미인지 §4에서 확인 |

- 회원별 공용 저장소(`member_categories` 등)는 아직 없다.

## 3. ⚠ 먼저 확인할 것 — 「카테고리」의 의미가 같은가 (섣불리 합치지 않기)

주인님도 「카테고리가 있다면 거기선 공유해도 되지」라고 **조건부**로 말씀하셨다. 프로그램마다 「카테고리」가 다른 뜻일 수 있다.
- 블로그(ai-auto-blog·tistory): **발행 글의 분류**(AI자동화·부동산 등) — 네이버/티스토리 블로그의 글 카테고리와 연결.
- 인스타·쓰레드: 글 분류일 수도, **콘텐츠 수집 주제**나 다른 용도일 수도 있다.
→ **의미가 같은 프로그램끼리만 공유**한다. 1단계 착수 전에 인스타·쓰레드 카테고리의 실제 용도를 코드로 확인하고, 다르면 블로그끼리만 먼저 공유하고 인스타·쓰레드는 제외(또는 별도 매핑).

## 4. 설계 (member integrations 패턴)

- **회원별 공용 카테고리 저장소**: 회원별(`user_id`) 카테고리 목록 하나를 두고, 카테고리를 쓰는 프로그램이 **같은 회원의 것을 함께 읽고 쓴다.** RLS owner-only(`auth.uid() = user_id`) — 타인 카테고리는 조회·수정 불가.
  - 방법 A(권장): 기존 `blog_categories`에 `user_id` 추가 → 블로그 계열(ai-auto-blog·blog_auto_poster)이 바로 회원별이 되고, 공용 컴포넌트로 다른 프로그램도 같은 테이블을 공유. 티스토리의 별도 테이블은 2단계에서 이 테이블로 통합.
  - 방법 B: 새 공용 테이블 `member_categories` 신설(블로그·인스타·쓰레드 중립적 이름) + `lib/memberCategories.ts` 공용 컴포넌트. 각 프로그램이 자기 분류 연결(글↔카테고리)은 그대로 두고 「카테고리 목록」만 공용에서 가져옴. member integrations(`member_platform_accounts`)와 가장 닮은 구조.
  - 제안: **블로그 3종만 보면 방법 A가 빠름**. 인스타·쓰레드까지 진짜로 합친다면 방법 B가 깔끔. §3 확인 결과로 택한다.
- **관리자 공용 카테고리 제거**: ai-auto-blog의 「관리자만 변경」 로직·공용 10개를 없애고, 각 회원이 본인 카테고리를 추가·수정·삭제. 화면(`CategoryManagementModal.tsx`)의 `canManage`(관리자 전용) 분기를 「본인 소유면 가능」으로 바꾼다.
- **기존 데이터**: 지금 `blog_categories` 공용 10개(AI자동화·MAKE·n8n 등)와 그 카테고리로 분류된 기존 글 연결을 어떻게 옮길지 1단계에서 데이터 조회로 정한다(사용 중인 소유자에게 이관 / 또는 시드로 각 회원에 복제 / 또는 비우기). 삭제 전 백업.

## 5. 단계 (각 단계 독립, 담당이 진행)

1. **1단계 — `ai-auto-blog` 회원별 전환(급함, 테스트 계정 당장 사용)**: `blog_categories`에 `user_id` + RLS owner-only. API(`/api/categories`) 권한을 「관리자만」 → 「본인 소유면 추가·수정·삭제」로. 모달 화면의 관리자 분기 제거. **같은 테이블을 쓰는 `blog_auto_poster`도 같은 작업에서 함께 고쳐 안 깨지게**(핵심 — 한쪽만 바꾸면 다른 쪽 오류). 기존 공용 10개·글 연결 이관. 글 작성 화면의 카테고리 선택이 본인 것만 나오게.
2. **2단계 — 티스토리 통합**: 티스토리의 별도 회원별 카테고리를 같은 공용 저장소로 합쳐, 블로그 3종이 한 회원의 카테고리를 공유.
3. **3단계 — 인스타·쓰레드(§3 의미 확인 후)**: 카테고리 뜻이 블로그와 같으면 같은 공용 저장소를 쓰게 연결. 다르면 제외.
- 각 단계: 로컬 검사·빌드·배포 1회·버전 +0.01, 회원 화면(크롬) 확인, 인수인계.

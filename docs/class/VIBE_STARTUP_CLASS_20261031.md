# 드림AI 바이브코딩 창업 클래스 보완안 (2026-10-31)

작성: Claude Code(윈도우) `claude-win-20261029-statusbar` [역할: 미지정]. 상태: **강사 검토용 초안.** 운영 프로그램·DB와 무관한 교육 자료다.
대상: 아이디어는 있지만 개발 경험이 없는 예비 창업자. 목표: 사업 타당성 검토부터 실제 고객이 쓰고 결제하는 웹/앱까지 강사와 함께 완성.

## 1. 핵심 진단

원안은 **「어떻게 만드는가」는 매우 자세하지만 「무엇을 왜 만들고, 누가 돈을 내며, 합법적으로 어떻게 받는가」가 짧다.** 개발을 못 하는 수강생에게 가장 큰 위험은 코드가 아니라 아무도 원하지 않는 것을 만드는 일이다. 그래서 세 가지를 바꾼다.

1. 개발 전에 **고객 검증과 진행/중단 판정**을 넣는다.
2. 도구 설치 설명은 부록으로 빼고 **수강생 공통 도구를 하나로 줄인다.**
3. **사업자·법·결제·운영**을 정규 과정에 넣고, 강의마다 제출물과 통과 기준을 둔다.

## 3. 보완 커리큘럼

원안의 6강 틀을 유지하고 사전 과정과 사후 과정을 더했다. **각 강의의 통과 기준을 못 넘으면 다음 단계 개발로 가지 않고 1:1로 수정한다.**

| 단계 | 주제 | 실습 | 제출물 | 통과 기준 |
|---|---|---|---|---|
| 사전 | 계정·설치, 업종 사전 점검 | 설치 마법사, 아이디어 신청서 | 설치 완료 화면, 아이디어 1장 | 환경 동작, 규제·금지 업종 1차 통과 |
| 1강 | 아이디어와 고객 | 마인드맵, 고객 정의, 경쟁 조사(AI 활용), 인터뷰 질문 작성 | 린 캔버스 초안, 인터뷰 대상 명단 | 인터뷰 약속 5명 이상 |
| 2강 | 타당성 판정과 AI 개발 입문 | 인터뷰 결과 분석, 원가·가격·손익 표, AI 작업 방식(스펙·컨텍스트·검증), Git 기초 | 타당성 보고서, **진행·수정·중단 판정** | 같은 문제를 말한 사람 다수, 건당 이익이 플러스 |
| 3강 | 수요 검증과 설계 | 랜딩페이지 배포, 대기자 신청, MVP 범위·화면 설계, PRD 작성, 사업자·PG 준비 시작 | 공개 랜딩 주소, PRD, 사업 준비 체크리스트 | 대기 신청 또는 사전 의사 확보, MVP 기능 1개 확정 |
| 4강 | MVP 구현 | 로그인·DB·핵심 기능, 권한(RLS), AI 교차 검수, 미리보기 배포 | 동작하는 MVP | 고객 흐름 1개가 처음부터 끝까지 동작, 비밀키 검사 통과 |
| 5강 | 결제·법·베타 | 결제 연동, 약관·개인정보처리방침·환불 정책 화면, 오류 알림, 지인 3명+실제 고객 베타 | 정식 도메인, 베타 피드백 표 | 시험 결제와 환불 성공, 치명 오류 0건 |
| 6강 | 출시·수익화·마케팅 | 검색 등록, 콘텐츠·SNS 자동화 1개, 첫 고객 영업, 지표 설정, 운영 매뉴얼, 데모데이 | 출시 주소, 지표판, 다음 30일 계획 | **첫 실사용자 확보, 가능하면 첫 결제** |
| 사후 | 운영 클리닉·지원사업 | 월 1회 1:1, PSST 사업계획서, 정부 지원 공고 대응, 주간 지표 점검 | 사업계획서 | 30일 뒤 지표 보고 |

원안 4강(SNS 채널 자동화)과 5강(CRM·마케팅)은 6강과 선택 트랙으로 옮긴다. 제품이 없는 상태에서 홍보 자동화를 먼저 가르치면 수강생이 알릴 대상이 없기 때문이다.

### 강의 안에 넣을 양식
- 인터뷰 질문: 지난번 이 문제를 겪은 때, 지금 쓰는 방법, 거기에 쓰는 돈과 시간, 가장 불편한 점. 「이 앱 쓰시겠어요?」처럼 답이 정해진 질문은 금지.
- 건당 원가 표: 판매가 - 결제 수수료 - AI 호출비 - 저장·전송비 - 문자·외부 API = 건당 이익. 월 고정비 ÷ 건당 이익 = 손익분기 고객 수.
- 판정표: 문제 강도, 지불 의사, 도달 경로, 건당 이익, 법적 위험, 혼자 운영 가능성을 각 1~5점으로 매겨 **진행 / 범위 축소 / 방향 전환 / 중단** 중 하나를 고른다. 중단도 좋은 결과로 인정한다.
- PRD 1장: 대상 고객, 해결할 문제, 핵심 흐름, 하지 않을 기능, 데이터, 권한, 완료 기준.

## 6. 수업 운영 설계

- **선발:** 1:1 면담을 1분에서 **사전 설문 + 15분 이상**으로 늘린다. 금지 업종, 혼자 운영하기 어려운 규모는 수업 전에 범위를 줄인다.
- **MVP 난이도 기준:** 과정 안에서는 회원 + 핵심 기능 1개 + 결제까지. 실시간 대규모 서비스, 금융·의료 민감 정보, 양면 플랫폼 전체 구현은 범위를 줄이거나 별도 상담.
- **비용 고지:** AI 구독, Vercel, Supabase, 도메인, 문자, PG 수수료를 수강 전 표로 안내하고 월 상한을 정한다. 계정·키는 수강생 본인 명의를 쓴다.
- **책임 범위:** 강사 역할(공동 개발 지도)과 수강생 책임(사업·법적 책임, 운영)을 계약서에 적고, 매출·수익을 보장하지 않는다. 코드와 데이터 소유권도 명시한다.
- **기술 지원:** 배포 키트와 공용 템플릿으로 시작해 환경 문제를 줄인다. 조교 또는 질문 채널, 오류 보고 양식을 둔다.
- **진도 격차:** 공통 실습과 개인 프로젝트 시간을 나누고, 뒤처진 수강생은 범위를 줄인다.
- **졸업 기준:** 공개 주소, 실사용자 3명 이상, 약관·개인정보 화면, 백업 복구 시험, 운영 매뉴얼. 첫 결제는 목표로 두되 수료 조건에는 넣지 않는다.
- **성과 지표:** 수강생별 인터뷰 수, 판정 결과, 출시 여부, 사용자 수, 첫 결제까지 걸린 기간.

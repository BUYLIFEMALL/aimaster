# AIMaster 프로그램 아이디어·개선 검토 원장

2026-10-19 시작. **주인님이 제안한 아이디어와 CLI가 프로그램을 분석하다 발견한 아이디어를 이 표에 계속 추가·검토합니다.** 기록은 개발 착수나 DB/비용/외부 발행 승인과 별개입니다. 프로그램별 구체적인 근거·미작업·다음 단계는 해당 프로그램 docs의 인수인계에 남기고 이 표에서 연결합니다.

## 모든 CLI 필수 — 개발·수정 전 확인 / 종료 후 갱신

프로그램을 새로 개발하거나 기능을 개선·수정하기 전에 이 아이디어 표와 대상 프로그램의 개선 원장·최신 인수인계를 먼저 읽습니다. 기존 제안/구현과 겹치는지, 다른 CLI가 작업 중인지, 어떤 근거와 미작업이 남았는지 확인한 뒤 개발 플랜을 제시합니다.

작업 중 발견한 인사이트·좋은 기능·아이디어·추가 제안은 날짜/발견 CLI/근거와 함께 추가합니다. 종료 후에는 기존 항목의 세 기준별 검토·처리 상태·미작업·다음 단계·프로그램별 인수인계/운영 링크를 갱신합니다. 유용한 새 아이디어가 없었다면 억지로 만들지 않고 '새 제안 없음'을 작업 결과에 기록합니다. 다른 CLI의 기록은 보존하고 같은 항목에 검토 이력을 보완합니다. 변경 판단이 어렵거나 기존 작업을 대체해야 하면 원본 보존 후 주인님께 확인합니다.

원장은 세 CLI가 함께 유지보수합니다. 보고서는 날짜별 스냅샷이며 이 원장이 현재 검토 상태의 기준입니다. 실제 작업 시작 표는 ACTIVE_WORK, 구체적인 구현/검수 증거는 프로그램별 docs에 남깁니다.


## 주인님 확정 검토 기준

| 기준 | 점검 질문 | 확인할 근거 |
|---|---|---|
| 1. 안정적인 자동화 | 자동화 기능이 안정적으로 구현되는가? | 정상/빈 결과/중단/재시도/중복·부분 실패, 비밀 보호, 개인 계정/API와 데이터 격리 |
| 2. 기존 프로그램 적용성 | 현재 개발된 프로그램에 적용 가능한가? | 적용할 프로그램·현재 구현/중복·연결 규격·권한/비용/보관 정책·호환 영향 |
| 3. 사용자 편의 | 사용자에게 편리한 자동화 기능인가? | 실제 작업 단계·반복 입력·수동 확인 부담·상태/실패 안내·복구 흐름·모바일 검수 |

각 기준을 **확인됨 / 조건부 / 검증 필요 / 부적합**으로 구분하고 근거를 씁니다. 근거 없는 종합 점수로 채택하지 않습니다. UI가 멋지거나 기능이 많다는 사실만으로 자동화 안정성과 편의를 통과시키지 않습니다.

## 등록·검토·이어받기

1. 제안 날짜·제안자(주인님/CLI)·대상·문제·기대 효과를 기록합니다. 기존 아이디어/기능/개선 원장을 찾아 중복이면 같은 ID에 추가 제안으로 연결합니다.
2. 위 세 기준을 최신 코드·회원 작업 흐름·테스트 근거로 검토합니다. 비용/위험·선행 조건·구현 범위를 함께 적고, 검증하지 않은 것은 표시합니다.
3. 상태는 **검토 대기 → 검토 중 → 보완 필요 / 보류 / 채택(미착수) → 구현 중 → 검수 대기 → 적용 완료**로 기록합니다. 미채택은 이유와 함께 남기며 행을 지우지 않습니다. 방향 확정과 기능 구현 완료를 구분합니다.
4. 채택 후에는 주인님 우선순위·ACTIVE_WORK와 맞춰 개발 플랜을 먼저 보여드립니다. 기존 작업 대체/판단 어려움은 원본을 보존하고 확인합니다. 필요한 특수 작업 승인은 별도로 따릅니다.
5. 완료 시 실제 변경·실행/미실행 검수·비용·버전·커밋·배포·운영 링크·남은 개선을 프로그램별 인수인계에 기록하고 이 원장의 상태/링크를 갱신합니다.

**당분간 우선순위:** 기존 프로그램의 기능 개선·오류 수정·안정화. 이 과정에서 좋은 기능을 검증해 레퍼런스 모듈로 정리한 뒤 신규 개발·기존 리뉴얼 때 하나씩 적용합니다. 일괄 전환 프로젝트로 바꾸지 않습니다. 사용자 생성 자료는 회원별로 격리하고 원생성일 기준 30일 보관합니다.

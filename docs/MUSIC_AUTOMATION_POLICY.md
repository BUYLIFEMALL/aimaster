## 2. 음악 생성 연동 규칙

1. **Suno는 공식 API가 없다 — sunoapi.org(비공식 중계)로 호출한다**(주인님 확인 2026-10-21 「suno는 본사에서 API키를 제공하지 않는 플랫폼이기 때문에 sunoapi.org를 통해서」). 회원 본인 sunoapi.org 키만 쓴다. 비공식이라 언제든 막힐 수 있음을 화면·문서에 숨기지 않고, Suno 공식 파트너 API가 열리면 교체를 검토한다.
2. **Suno 연동 코드는 공용 기준 코드 `suno-api-client`(기준 `music/lib/ai/suno.ts`) 하나만** 쓴다. 다른 프로그램이 Suno를 부르면 사본을 쓰고 새로 짜지 않는다. 콜백 주소는 음악(SUNO)자동화로 고정, 사본 프로그램은 상태 조회로 받는다.
3. **Suno 모델은 최신(V6 계열)을 기본**으로 한다. sunoapi.org에서 V5_5 이하는 「지원 종료(하위 호환)」다(2026-10-23 주인님 「여기 모델 최신 모델로 바꿔 v6 관련 작업 suno 자동화 이미 구현되어 있어」 → shots v1.39에서 교체).
4. **다른 음악 모델(Lyria·ElevenLabs·fal·Stable Audio 등)은 AI 음악 스튜디오에 먼저 구현**하고, 다른 프로그램은 공용 기준 코드 `music-sync-calls`·`music-gen-adapters` 사본으로 연결 부분만 가져다 쓴다(이미지의 `ai-image-studio` 규칙과 같은 방식). 모델이 종료·교체되면 AI 음악 스튜디오를 먼저 고치고 같은 모델을 쓰는 프로그램의 연결 부분만 바꾼다.
5. **음악 생성 프롬프트(곡 기획·스타일·가사 지시)는 프로그램마다 고유**하다. 공유·복사하지 않는다(공용은 모델·주소·호출·대기 시간·음원 받기까지).
6. 새 플랫폼을 넣을 때는 **공식 API 여부·상업 이용 조건·단가**를 공식 페이지로 확인하고 플랜에 확인 날짜와 함께 적는다. 공개 API가 없거나 다운로드가 막힌 곳(Udio), 신규 가입이 막힌 곳(MiniMax 직접)은 넣지 않는다. 자체 GPU 서버가 필요한 방식은 운영자 비용이 생기므로 하지 않는다(fal 등 중계로 대체).

## 3. 곡 넘기기(배경음악 공용) 규칙

- **방향: 「생성은 AI 음악 스튜디오(또는 음악(SUNO)) 한 곳, 다른 프로그램은 가져다 쓰기」**([배경음악 공용화 플랜](analysis-music-studio-20261023/BGM_SHARED_PLAN.md)). 다른 프로그램은 회원 본인 완성곡 행(`ams_generations`·`music_tracks`)을 읽어 고르기만 하고, 음원은 비공개 버킷의 **1시간 서명 주소**로 받는다.
- 자동 파이프라인(shots처럼 사람이 고르지 않는 흐름)만 공용 사본으로 직접 생성한다.
- 곡을 가져오는 화면에는 **「내 파일 올리기」도 함께** 둔다(2026-10-23 주인님 지시 — 뮤직비디오는 가져오기·직접 올리기 둘 다).
- 시간 가사는 공용 `ams-timed-lyrics`(Lyria)·`sunoAlign.ts`(Suno 단어 시각 → 줄 시간표)를 재사용한다. 반복 후렴 등에서 어긋날 수 있으므로 사람이 고칠 수 있는 싱크 화면을 남긴다.
- 무료 브라우저 렌더·무료 음성(공용 `browser-mp4-encoder`·`browser-free-tts`)이 생기면 음악 프로그램에서 쓸 곳을 먼저 찾는다(2026-10-23 주인님 「음악 쪽에서 연계해서 활용할수 있는 방안을 강구해봐」).

## 4. 회원 본인 키·데이터 규칙 (음악 적용)

1. Suno(sunoapi.org)·Gemini(Lyria)·ElevenLabs·fal·OpenAI 등 모든 키는 회원 `user_api_keys`의 **본인 값만** 쓴다. 키가 없으면 「본인 키를 등록해 주세요」로 안내하고 다른 회원·운영자 키로 대신하지 않는다.
2. **만든 곡·커버·가사·분석 결과는 회원 본인 소유로 격리하고 생성일 기준 30일 뒤 자동 삭제**한다. 기존에 만든 곡도 포함한다(2026-10-21 주인님 「진행해」 — 기존 곡 30일 정리 적용). 음원 저장소 `music-audio`는 비공개 버킷이다.
3. 30일 정리는 첫 실제 삭제 뒤 관리자 정리 표와 대조해 확인한다(음악(SUNO): 2026-10-29 새벽 첫 삭제 예정).
4. 브라우저 처리 프로그램(마스터링·가사영상·LP·무료 음성)은 「파일이 서버로 가지 않는다」는 장점을 유지한다 — 서버 저장이 필요한 기능을 넣을 때는 이 장점이 깨지는지 먼저 따진다.

## 5. 비용·시험 규칙 (음악 적용)

- Suno·Lyria·ElevenLabs 실제 생성은 **곡마다 비용**이 든다. 시험 생성은 시험 계정 본인 키로 **필요한 최소 횟수(보통 1회)**만, 실행 전에 무엇을·몇 회·대략 금액을 보고하고 승인받는다(예: Suno 생성 1회 = sunoapi.org 크레딧 1회분, 2곡).
- 실패하면 크레딧이 환불되는 호출도 승인 대상이다. 곡 연장·MR처럼 크레딧이 드는 부가 기능은 필요할 때만 1회씩 시험한다.
- 무료로 확인할 수 있는 것(브라우저 렌더·무료 음성·서명 주소·화면)은 먼저 무료로 확인한다. 빌드는 모아서 순차 배포한다(루트 규칙 그대로).

## 6. 「끝났다」고 말할 조건 (음악 기능)

1. 회원 본인 키로 동작하고, 키가 없을 때 안내가 나온다.
2. 곡이 실제로 저장되고(웹훅 또는 상태 조회), 보관함에서 재생·내려받기가 된다. 「생성 완료」와 「우리 저장소 보관 완료」를 구분해 보여 준다.
3. 다른 프로그램으로 넘기는 기능이면 받는 쪽에서 곡이 실제로 열리는 것까지 크롬(시험 계정)으로 확인한다.
4. 영상이 나오는 기능이면 미리보기와 결과 MP4가 같은지, 가로·세로를 확인한다.
5. 30일 정리 대상에 들어가는지 확인한다.
6. 하나라도 확인하지 못했으면 「미검수」로 적는다(예: 비용 때문에 시간 가사를 끄고 확인한 경우).

## 7. 하지 않을 것

- 운영자 공용 Suno·Lyria 키로 회원 곡 만들기.
- 같은 기능을 여러 음악 프로그램에 따로 만들기(플레이리스트 모드는 플레이리스트 자동화가 맡음).
- 음악 생성 프롬프트 공유·복사.
- Udio·MiniMax 직접 API·자체 GPU 음악 모델 운영.
- 외부 상용 앱(Lyricbi 등)의 코드·문구·프리셋 값 복사 — 기능만 참고해 새로 만든다.

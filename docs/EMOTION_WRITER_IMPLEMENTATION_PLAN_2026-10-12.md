# 감성 글귀 이미지 생성기 — 조사 결과와 구현 계획

작성일: 2026-10-12 / Codex / 주인님 요청: emotion-writer.vercel.app 및 첨부 화면을 자세히 분석하고 구현 전 계획 준비.

후속 상태: 같은 날 주인님의 “진행해줘”에 따라 v1.01 구현·로컬 검수를 완료했습니다. 아래는 구현 전 조사 기록이며 현재 현황은 [구현 인수인계](../emotion-writer/docs/IMPLEMENTATION_HANDOFF_2026-10-12.md)입니다. 운영 연결 승인은 대기 중입니다.

## 이번 단계

조사와 계획만 준비했습니다. 기능 코드, 회원 데이터, 키, 운영 배포는 변경하지 않았고 유료 생성 호출은 실행하지 않았습니다. 구현 완료나 실제 생성 성공으로 보고하지 않습니다.

## 확인한 근거와 범위

- 운영 루트 HTTP 200. HTML과 공개 번들 `/assets/index-BVqs8xrG.js`의 화면 구성 및 앱 핸들러를 조사했습니다. React 19 계열·Google GenAI 클라이언트·Tailwind CDN·Google Fonts를 사용하는 클라이언트 앱입니다. 번들 형태는 Vite 계열로 추정하며 원본 package.json 확인 전 확정하지 않습니다.
- AIMaster 파일명 검색, 루트 문서의 emotion-writer/감성 글귀 검색, D:/Antigravity 및 D:/PDS 파일명 검색에서 해당 원본 소스/프로젝트 문서를 찾지 못했습니다. 원본 부재를 소스 전체가 없다는 의미로 단정하지 않습니다. 실제 코딩 전 기존 프로젝트 연결과 원본 소스 위치를 먼저 확인해야 합니다.
- 첨부 이미지와 번들 비교는 완료했습니다. 실제 브라우저에서 생성·다운로드는 아직 검수하지 않았습니다. Aside가 실행 중이지 않아 직접 DOM 검사에 사용하지 않았고 현재 Chrome의 다른 프로그램 작업 화면은 조작하지 않았습니다.
- 로컬 HEAD와 origin/master 비교는 0/0. 타 CLI의 미추적 파일은 변경하지 않았습니다.

## 현재 화면과 기능

1. 명언·좋은 글 / 건강·행복 기원 / 카톡·밴드 공유 및 직접 주제 입력.
2. Gemini 나노바나나 / Pixabay / Pexels 배경 선택, 각 API 키 설정 팝업.
3. 이미지 비율 9:16 / 1:1 / 3:4.
4. 줄 수 5 / 6 / 7 / 8.
5. 시 / 에세이 / 짧은 문장 스타일, 글귀 후보 5개 생성·선택.
6. 배경 생성 또는 검색 사진 선택 후 글귀를 겹쳐 표시, Canvas JPEG 다운로드.

주제·이미지 소스를 선택해야 다음 설정이 나타나는 조건부 화면입니다. 첨부 화면에서 3~5가 안 보이는 것은 이미지 방식이 아직 선택되지 않은 경우와 일치하며, 그것만으로 기능 누락이라고 판단하지 않습니다.

## 확인한 문제 및 검수할 위험

- **확정:** UI 연결 상태 `gemini: !!k.gemini || !0`는 항상 참입니다. 본인 Gemini 키가 없어도 “연결됨”으로 표시됩니다. 등록 여부와 연결 테스트 결과를 구분해야 합니다.
- **확정:** 스타일 선택과 줄 수 변경 핸들러가 즉시 글귀 생성 API를 호출합니다. 설정 변경마다 생성 비용이 발생할 수 있어 명시적 “글귀 5개 생성” 버튼으로 실행을 모읍니다.
- **확정:** 키 및 이를 복호화하는 AES 키가 같은 localStorage에 저장됩니다. 같은 브라우저 데이터를 함께 읽으면 복호화할 수 있으므로 회원별 접근 통제를 대체하지 못합니다. 회원 본인 키를 AIMaster 공용 키 관리에서 조회하는 방식으로 통합합니다. 기존 브라우저 키를 자동 수집하거나 서버로 무단 이전하지 않습니다.
- **확정:** 공개 페이지에서 작업 앱을 내려주며 공개 앱 핸들러에서 AIMaster 로그인·이용 권한 확인을 찾지 못했습니다. 전체 서버 설정까지 조사한 것은 아니므로 비로그인 유료 실행 가능 여부는 별도 검증 대상입니다.
- **확정:** 주제/소스/비율 변경 시 후속 스타일·후보·이미지를 초기화합니다. 변경 영향 안내와 재생성 범위를 화면에 표시해야 합니다.
- **확정:** 이미지 변환은 외부 images.weserv.nl 프록시를 우선 사용합니다. 다운로드 성공, 외부 서비스 중단, 이미지 제공처 약관 준수는 아직 검수하지 않았습니다.
- **검수 대상:** 한글 폰트 로딩·줄바꿈·사진 자르기·미리보기와 다운로드 결과 일치, 요청 취소/오래된 결과 덮어쓰기, 모바일 화면의 전체 스크롤 제한, API 실패 메시지, 사진 출처 보존.

## 구현 순서와 완료 기준

### 1. 소스·배포 연결 및 회원 구조 확정

기존 Vercel 프로젝트·원본 위치·프로그램 등록 상태와 사용권한을 확인합니다. 원본이 있으면 해당 코드와 지침부터 읽습니다. 기존 엔진을 유지할 수 있으면 옮기거나 확장하고, 원본을 확보할 수 없으면 AIMaster/emotion-writer/ 안에 Next.js·React·TypeScript로 동일 기능을 구현합니다. 별도 Git 저장소는 만들지 않습니다. 프로그램명/버전, 다른 프로그램 보기, 회원 계정/로그아웃, API키등록·플랫폼연동은 기존 공통 구조를 따릅니다. DB 스키마나 환경변수 변경이 필요한 경우 구체 변경안을 만든 뒤 사전 승인 규칙을 적용합니다.

완료 기준: 소스·배포 대상·버전·권한 판정 경로를 확인했고 다른 프로그램 변경이 섞이지 않습니다.

### 2. 첨부 화면의 작업 흐름 구현

흰색 카드와 분홍 포인트, 왼쪽 설정 / 오른쪽 결과 배치를 재현합니다. 넓은 화면은 2열, 모바일은 설정 다음 결과 1열입니다. 1~6 번호·선택 표시·직접 주제 적용·현재 해야 할 행동 안내를 맞춥니다. 다음 단계 조건을 정확히 안내하고 세 가지 배경 방식을 구분합니다. 본인 키 없음 / 등록됨 / 테스트 성공 / 오류 상태를 별도로 표시합니다.

완료 기준: 초기·선택·준비·로딩·오류·완료 상태가 실제 조건과 일치하며 모바일에서 설정/결과에 접근할 수 있습니다.

### 3. 글귀 생성과 수정

스타일·줄 수·주제를 선택한 후 “글귀 5개 생성”으로 실행합니다. 후보를 직접 수정하거나 본인 문구를 입력할 수 있게 합니다. 명언의 인물 이름이나 출처를 AI가 임의로 붙이지 않게 하고 인물 명언은 검증 가능한 경우에만 표시합니다. 현재 연도를 동적으로 적용합니다. 본인 Gemini 키 사용, 응답 형식/후보 수 검증, 중복 클릭 방지, 시간 제한 및 재시도 버튼을 넣습니다. 설정 변경 자체로 유료 호출을 하지 않습니다.

완료 기준: 후보 생성·수정·선택이 이어지고 실패/취소 후 최신 선택과 이전 결과를 보존하며 오래된 응답이 새 결과를 덮어쓰지 않습니다.

### 4. 배경 생성 및 무료 사진 연동

Google 공식 문서와 실제 사용 가능한 모델을 확인해 Gemini 배경 생성 모델을 선택합니다. Pixabay/Pexels는 본인 키로 검색하며 결과 사진·작가·원본 링크를 함께 보존합니다. 무료 사진 방식에서도 AI 글귀 생성에는 본인 Gemini 키가 필요함을 명확히 안내하고 직접 입력 문구는 별도 AI 글귀 호출 없이 사용하게 합니다. 배경 재생성과 글귀 재생성을 구분합니다. 글자 없는 배경을 생성하고 요청 실패·키 오류·검색 결과 없음·호출 한도 초과를 구분합니다.

완료 기준: 3개 방식별 필요한 본인 키가 맞고 사진을 바꿔도 선택한 글귀를 유지합니다. 무료 사진 다운로드/보관은 제공처 정책에 맞게 처리합니다.

### 5. 미리보기와 다운로드 완성

기존 cardnews-studio의 Canvas 렌더링·Blob 내보내기 구조를 검토해 재사용합니다. 같은 렌더링 함수로 미리보기와 PNG/JPEG 저장을 처리하며 폰트 로딩·사진 크롭·한글 줄바꿈·글자 크기/색·문구 위치·배경 대비를 맞춥니다. 이미지 요청 경로는 허용한 공급처만 다뤄 다운로드 프록시가 임의 URL 요청기가 되지 않게 합니다. 폰트/이미지 실패 시 저장 성공으로 표시하지 않습니다.

완료 기준: 9:16 / 1:1 / 3:4 각각 다운로드 치수·비율이 맞고 긴 한글/여러 줄/선택한 폰트가 화면과 파일에서 일치합니다.

### 6. 검수·문서·릴리스

로그인/사용권한/본인 키·미등록/취소/실패, 3개 배경 방식, 3개 비율, 모바일, 실제 다운로드를 검사합니다. API 호출은 필요한 소량 표본으로 제한합니다. 타입 검사·빌드·관련 회귀 검사를 실행하고, 프로그램 버전/DB 메타데이터를 함께 갱신합니다. 인수인계·오류 교훈 작성 → 커밋 → 푸시 → 해당 프로그램 프로덕션 배포 → 운영 검수 → 결과 보고로 마감합니다. 회원 대신 카톡/밴드에 게시하는 기능은 이번 범위에 포함하지 않습니다.

완료 기준: 정상 회원의 실제 생성/다운로드 증거와 실패 복구 결과를 남기고 확인하지 못한 기능은 별도로 표시합니다.

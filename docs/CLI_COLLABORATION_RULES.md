# CLI 공동작업·협업작업 규칙

2026-10-17 주인님 지시. Antigravity CLI(agy)·Codex·Claude Code와 모든 후속 CLI에 적용합니다. 본인 계정·본인 API·회원 데이터 격리 최상위 규칙을 유지합니다.

1. 시작 전 루트 지침, ACTIVE_WORK, 최신 HANDOFF와 대상 프로그램 문서를 읽고 원격/HEAD·미커밋·스테이징을 확인합니다. 다른 CLI가 같은 폴더를 작업 중이면 시작하지 않습니다.
2. 다른 CLI 결과와 내 결과가 다르면 양쪽의 목적, 주인님의 최신 지시, 실제 변경 차이, 테스트·화면·운영 근거를 비교합니다. 작성자나 작성 시각만으로 우선하지 않습니다.
3. 승인된 범위에서 기존 작업과 호환되는 보완이고 근거가 충분하면 가장 나은 방향을 선택합니다. 기존 작업의 의도와 데이터를 보존하고 선택 이유를 기록합니다.
4. 기존 작업을 대체해야 하거나 의도가 충돌해 판단이 어려우면 기존 파일·데이터·스테이징을 보존합니다. 주인님께 차이, 사용자 영향, 선택지와 추천 이유를 설명하고 확인받은 뒤 진행합니다. 질문 중에는 해당 변경만 멈추고 독립적인 허용 작업은 계속할 수 있습니다.
5. 공유 저장소 전체 reset/stash/checkout, 옛 사본의 공유 문서 덮어쓰기, 다른 CLI 스테이징을 섞은 커밋을 하지 않습니다. 예기치 않게 파일이 바뀌면 먼저 diff/HEAD/기록을 비교합니다. 원인이 확인되지 않으면 특정 CLI의 잘못으로 단정하지 않습니다.
6. 커밋 직전 실제 파일·버전·예약표와 HEAD를 재확인합니다. 본인 경로와 공통 문서의 본인 항목만 커밋하고 다른 CLI의 변경을 유지합니다. 변경 중 HEAD가 바뀌면 최신 기준으로 다시 비교합니다.
7. 종료 시 프로그램별 인수인계와 루트 HANDOFF에 완료/미완료, 검수/배포 증거와 한계, 비교/선택 이유, 보류 질문, 다음 첫 단계 및 실제 프로그램 링크를 기록합니다. 미검수·미배포는 완료로 표시하지 않습니다.

8. **브라우저 분담(2026-10-22 주인님 지시)**: Claude Code = 크롬, Codex = 엣지, agy = 네이버 웨일의 실제 창만 씁니다. 각 CLI는 자기 브라우저만 조작하고 다른 CLI의 창·탭은 건드리지 않습니다. 이것은 **기본 할당**이고, **필요하면 주인님이 그 세션에서 브라우저를 지정하며 지정받은 세션은 그 브라우저를 작업 브라우저로 씁니다**(예: agy·Codex가 토큰 한도로 멈췄을 때 Claude Code 세션에 엣지/웨일). 지정은 주인님 채팅 지시로만 성립하고, `docs/ACTIVE_WORK.md` 자기 줄에 「브라우저: 엣지(주인님 지정)」처럼 적습니다. 한 브라우저는 한 세션만 쓰며, 지정은 그 세션 안에서만 유효합니다. 지정이 끝나면 기본 브라우저로 돌아갑니다. 원문·deviceId: 루트 `CLAUDE.md` 맨 위, `docs/AI_AGENT_AUTONOMOUS_DEV_WORKFLOW.md` 8-1-2.

9. **공용 문서는 안전 커밋 도우미로 커밋(2026-10-23 주인님 지시)**: 여러 세션이 함께 고치는 문서(HANDOFF·PENDING_DEPLOYS·프로그램 비교표·SHARED_MODULES·아이디어 표·ERROR_LESSONS·ACTIVE_WORK·루트 지침 3종·DESIGN)는 `scripts/safe-commit.mjs`로 커밋합니다.
   - 쓰는 법: `node scripts/safe-commit.mjs --begin <파일>... --as <세션이름>` → 고침 → `node scripts/safe-commit.mjs "<메시지>" <파일>... --as <세션이름> [--push]`. `--as`는 같은 장비의 여러 세션 사본이 섞이지 않게 붙이는 이름(예: `claude-win-thumbnail`, `codex-mac-blog`). 상태 보기 `--status`.
   - 하는 일: 「기준 사본 → 지금 파일」 차이(내 변경)만 최신 HEAD 위에 3방향 병합 → `commit-tree` + `update-ref <새> <옛>`(그사이 HEAD가 바뀌면 다시 병합, 최대 5번) → 공용 스테이징을 새 HEAD로(다른 세션이 실제로 스테이징해 둔 내용이면 그 위에 내 변경도 얹음).
   - 같은 자리에 두 세션이 각자 줄을 넣은 경우는 둘 다 남깁니다(내 줄 위). 다른 세션 미커밋 줄 옆을 고친 경우도 내 변경만 들어갑니다. 같은 줄을 서로 다르게 고친 경우만 「충돌」로 멈추며, 파일·커밋은 그대로입니다.
   - 한계: `--begin` **뒤**에 다른 세션이 같은 작업 파일을 고친 줄은 내 변경과 구별할 수 없어 함께 커밋됩니다. `--begin`은 고치기 직전에, 고친 뒤엔 바로 커밋하고, 커밋 뒤 나오는 「바뀐 줄」 미리 보기로 남의 줄이 없는지 봅니다.
   - 기준 사본 없이 파일 전체가 내 것이면 `--mine`(최근 2시간 다른 커밋 줄을 지우게 되면 멈춤). pre-commit 훅 대신 같은 되돌림 점검을 안에서 합니다.
   - **`--mine` 보호(2026-10-23)**: 최근 2시간 안 같은 파일을 고친 다른 커밋이 있으면 그 목록을 보여 주고, `--push`가 있어도 **푸시를 미룬다** — 「바뀐 줄」 미리 보기가 모두 내 것인지 확인한 뒤 `git push origin master`. 내 것이 아닌 줄이 섞였으면 다음 커밋으로 되돌리고 그 세션에 알린다.
   - **겹침 자동 처리(2026-10-23)**: 기준 사본에 다른 세션 미커밋 줄이 섞여 3방향 병합이 겹치면, 먼저 내 변경 덩어리를 HEAD의 같은 자리에 얹는다(「ℹ … 덩어리 방식」). 자리를 정확히 못 찾을 때만 예전처럼 「둘 다 남기기」 또는 중단. 결과 미리 보기에서 줄 순서도 확인.
   - **일반 파일 커밋 도우미(2026-10-23, 선택)**: `node scripts/commit-paths.mjs "<메시지>" <경로>... [--push]` — 최신 HEAD에서 시작한 임시 스테이징에 `git add -A -- <경로>`(새 파일·삭제·폴더·이미지 가능)로 담아 커밋, 공용 스테이징은 읽지 않고 정상일 때만 내 경로를 맞춘다. 대량 삭제 검사·OpenAI 모델·되돌림 경고를 직접 실행. 공용 문서는 거부(→ safe-commit). 경로 지정 커밋(`git commit -- <경로>`)의 대안이며 최상위 규칙 ①은 그대로.
   - 시험(2026-10-23 임시 저장소): 같은 자리 추가·미커밋 줄 제외·진짜 충돌 멈춤·미커밋 줄 옆 수정·묵은/실제 스테이징 5가지 통과.
   - **HANDOFF 맨 위에 항목 하나 넣기(가장 흔한 경우)**: 항목을 파일로 써 두고 `node scripts/safe-commit.mjs --handoff <항목.md> "<메시지>" --as <세션이름> --push` 한 번이면 사본 뜨기·맨 위 넣기·커밋까지 끝(항목은 `## 날짜 에이전트(장비) — 제목`으로 시작, 같은 제목이 있으면 중복으로 멈춤).
   - **배포는 `node scripts/deploy.mjs <폴더> --go`로(2026-10-23 주인님 승인 제안)**: 확인(미배포 대기·작업 중 표) → 빌드 1회 → 이번 배포 Ready·운영 주소 연결 확인 → DB 버전 비교 → 프로그램 비교표 그 프로그램 한 줄 자동 수정 → 관리자 「운영 상태」 숫자 갱신 → 문서 커밋 명령 안내까지 한 번에 한다. 작업 중 표에 내 줄이 있으면 `--owner "<내 줄 일부>"`. `vercel deploy`를 직접 쓰면 지도 버전 칸·대기 표·관리자 숫자가 어긋난다(2026-10-23 지도 버전 칸 8곳 어긋남 사례). DB 버전은 이어서 `--version-only --set-version`.
   - **메인 사이트 작은 화면 수정은 바로 코드로 쓰지 말고 `docs/PENDING_DEPLOYS.md` 「메인 사이트 — 다음 메인 빌드 때 할 일」 표에 한 줄(급함/보통)**: 메인 사이트는 푸시 즉시 빌드되므로(다른 세션의 푸시에 섞여도 빌드됨) 모았다가 빌드 1회(사전 승인)로 묶는다. `급함`(회원 피해)은 승인 뒤 바로.
   - **표 구조 확인은 운영 DB 칸 목록으로**: `node scripts/program-info.mjs columns <표>` — 행이 0건이어도 실제 칸(user_id 등)을 보여 준다. 첫 마이그레이션 파일만 보고 판단하지 않는다(2026-10-23 착오 사례).
   - **배포 뒤 문서 정리**: `node scripts/deploy.mjs <폴더> --go`가 빌드 전에 `PENDING_DEPLOYS`·HANDOFF·프로그램 비교표 기준 사본을 `--as deploy-<폴더>`로 떠 두고, 배포 뒤 DB 버전이 화면 버전과 같으면 프로그램 비교표의 그 프로그램 한 줄(목록 표 버전 칸·카드 버전)을 자동으로 고친 다음, 끝에 그대로 쓸 커밋 명령(세 파일)을 보여 준다(2026-10-23 — 배포 뒤 지도 버전 어긋남 방지).
   - 잊었을 때: 공용 문서를 일반 `git commit`으로 커밋하면 pre-commit 훅이 「안전 커밋 도우미를 쓰세요」 알림을 띄운다(도우미는 훅을 거치지 않으므로 알림이 뜨면 도우미를 안 쓴 것).
   - **공용 스크립트도 같은 방식(2026-10-23)**: `scripts/deploy.mjs`·`safe-commit.mjs`·`program-info.mjs`·`pending-check.mjs`·`check-*.mjs`(공유 문서 되돌림·공용 모듈·휴대폰 폭·인덱스 상태)·`scripts/git-hooks/*`·`scripts/mac-mini/commit-gate.sh`는 여러 세션이 함께 고친다. 파일 통째로 일반 커밋하면 남의 미커밋 수정이 섞인다(`48b3fc4d0`). 고치기 **전에** `safe-commit.mjs --begin`, 커밋도 `safe-commit.mjs`. 일반 커밋하면 pre-commit 훅이 「ℹ [공용 스크립트]」로 알린다(막지는 않음, 목록 `scripts/check-shared-doc-reverts.mjs` `SHARED_SCRIPTS`).
   - 되돌림 감사: 세션 시작 `node scripts/deploy.mjs --version-only --all`에 최근 24시간 감사가 함께 나온다(「⚠ 사라짐」만 자세히). 의도한 정리로 확인한 커밋은 `scripts/reverts-reviewed.txt`에 「sha 메모」로 적으면 「✓ 확인됨」으로만 표시.
   - **일반 파일도 기본은 안전 커밋 도우미(2026-10-23)**: 경로 지정 커밋(`git commit -- <경로>`)은 공용 스테이징을 읽고 다시 쓰다가 다른 세션과 겹치면 스테이징을 줄이는 사고의 원인으로 의심된다(같은 날 두 번). 내가 처음부터 쓴 파일·내 프로그램 폴더 파일은 `node scripts/safe-commit.mjs "<메시지>" <파일>... --mine --as <세션> --push`(이진 파일=원래 바이트, 지운 파일=삭제 커밋 지원), 다른 세션과 함께 고칠 수 있는 파일은 `--begin` 방식. 시험 `node --test scripts/safe-commit.test.mjs`(8개).
   - **공용 스크립트 일반 커밋 차단(2026-10-23)**: `scripts/deploy.mjs`·`safe-commit.mjs`·`check-*.mjs` 등 공용 스크립트 목록(`scripts/check-shared-doc-reverts.mjs`의 `SHARED_SCRIPTS`)은 일반 `git commit`으로 올리면 pre-commit 훅이 막는다(다른 세션 미커밋 수정이 섞인 `48b3fc4d0` 사고 재발 방지). 고치기 전에 `safe-commit --begin`, 커밋도 safe-commit. 혼자 고친 것을 `git diff`로 확인한 경우만 `AIMASTER_SHARED_SCRIPT_OK=1`. 훅 설치·갱신: `node scripts/git-hooks/install.mjs`.
   - 주소 점검(2026-10-23): 같은 세션 시작 점검에 「문서 속 프로그램 주소」 한 줄이 나온다(`scripts/check-app-urls.mjs --json`, 약 2초). 보고에 프로그램 링크를 쓸 때는 `node scripts/check-app-urls.mjs <slug>`로 DB `app_url`을 확인한다. 연결 안 되는 주소 목록은 인자 없이 실행.

이번 적용 범위: 최상위 AGENTS.md·CLAUDE.md·GEMINI.md 및 공통 개발 방식/인수인계 정책에 같은 규칙을 연결했습니다. 프로그램 기능·키·DB 스키마를 이 문서 작업에서 변경하지 않습니다. 진행 중인 Playlist 참고 메모 작업에도 기존 다크 디자인과 미디어 제작 로직을 보존하는 기준으로 적용합니다.

## 10. 저장소 대량 삭제 사고 재발 방지 (2026-10-23 주인님 지시)

- 사고: 공용 스테이징(`.git/index`)이 65개 항목으로 쪼그라든 채 3번 커밋·푸시돼 원격 master에서 파일 10,464개가 지워짐(`c2e7c4db2`, 복구 `237741cc3`). 같은 날 공용 스테이징 경합으로 다른 세션 파일이 엉뚱한 커밋에 섞인 일도 여러 번.
- 규칙(루트 `CLAUDE.md`·`AGENTS.md`·`GEMINI.md` 최상단과 같음): ① 경로 지정 커밋만(`git commit -- <경로>`·`safe-commit`), 경로 없는 `git commit`·`-a`·`git add -A`/`.` 금지 ② 커밋 직후 `git show --stat HEAD | tail -1` 확인 ③ pre-commit·pre-push 훅 `scripts/check-index-health.mjs`(50개 넘는 삭제·스테이징 절반 아래면 차단)를 끄지 않음, 새 장비는 `node scripts/git-hooks/install.mjs`, 승인된 대량 삭제만 `AIMASTER_ALLOW_MASS_DELETE=1` ④ 이상하면 멈추고 주인님께 — 인덱스 삭제·`reset --hard`·`checkout .`·`stash`·force-push 금지, 복구는 승인 뒤 임시 인덱스로 위에 얹는 커밋 ⑤ git 명령 중간에 끊지 않기(특히 맥미니 SMB).

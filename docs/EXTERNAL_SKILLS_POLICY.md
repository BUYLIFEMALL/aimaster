# 외부 개발 스킬 선택 사용 지침

2026-10-19 주인님 확정: **전체 묶음을 설치하되, 실제 작업에서는 필요한 스킬만 선택하고 AIMaster 최상위 지침을 우선한다.** Codex·Claude Code·Antigravity 등 이 저장소를 다루는 모든 CLI의 공통 운영 기준이다. 플러그인 설치 여부는 CLI·계정마다 다르다.

## 작업 순서

1. 최신 루트 지침·공통 아이디어 원장·대상 프로그램 문서·ACTIVE_WORK를 확인하고 개발 플랜을 먼저 제시한다.
2. 이번 작업에 필요한 스킬만 고른다. 설치된 원본 설명을 읽고 작업 범위·현재 도구·프로그램 구조에 맞는지 확인한다. 선택한 스킬은 사용자에게 알린다.
3. 스킬의 기본값과 주인님 지시/저장소 정책을 대조한다. 저장 위치·작업 추적 방식·운영/Lab 경계·승인 범위는 이 저장소 기준으로 적용하고 다른 CLI 작업을 보존한다.
4. 작업에 맞는 검사를 수행한다. 실제 제품 수정이면 기존 검수·커밋·푸시·해당 앱 배포·운영 확인 절차를 따르고, 설치/문서 작업은 설치 상태·파일·문서 연결을 확인한다.
5. 적용한 스킬·결과·미완료·새 인사이트와 관련 링크를 프로그램 인수인계 또는 공통 인수인계에 남긴다. 새 제안이 없으면 억지로 만들지 않는다.

스킬은 작업 방법을 돕는 지침이다. 설치만으로 새 개발 기능, 외부 계정, 유료 API, DB/환경변수 변경 권한이 생기지 않는다. 기존에 승인된 범위는 계속 유효하며 불필요한 재승인을 만들지 않는다.

## 우선 활용할 스킬

| 스킬 | 사용할 때 | 적용 기준 |
|---|---|---|
| `diagnosing-bugs` | 오류·느려짐·회귀 원인 조사 | 재현 조건·증거·가설을 확인한 뒤 필요한 범위만 수정 |
| `code-review` | 변경 코드 검토 | 기준 커밋·저장소 지침·요구사항을 대조. 필요한 검토에만 선택 |
| `research` | API·기술·공식 자료 조사 | 공식 자료와 코드 근거를 구분해 저장소에 기록 |
| `codebase-design` | 모듈 경계·인터페이스 설계 | 기능 안정화 우선, 검증된 기능을 신규/리뉴얼 때 하나씩 적용 |
| `writing-for-agents` | AGENTS/CLAUDE·CLI용 문서 작성 | 최상위에는 짧은 규칙과 조건부 링크, 세부 내용은 담당 문서에 보관 |
| `to-spec` | 대화를 개발 명세로 정리 | 기존 프로그램 문서·개선 원장·작업 추적 위치를 먼저 재사용 |
| `to-tickets` | 계획을 실행 가능한 작업으로 분할 | 의존관계·완료 기준·담당 범위를 적고 다른 CLI 작업과 분리 |

이 7개도 매 작업에 전부 적용하는 필수 목록은 아니다. 예를 들어 문구 한 줄 수정에 조사·전체 구조 분석·질문 인터뷰·TDD를 모두 실행하지 않는다.

## 기본값을 저장소 규칙에 맞춰야 하는 경우

- **인수인계 위치:** `handoff` 원본은 임시 폴더 저장을 제안한다. AIMaster에서는 대상 프로그램 폴더의 인수인계·개선 원장과 `docs/HANDOFF.md`에 결과·미완료·다음 단계·프로그램 링크를 남긴다. 임시 파일만 남겨 완료로 처리하지 않는다.
- **초기 설정:** `setup-matt-pocock-skills`의 작업 추적·용어·설계 문서 기본값을 현재 구조와 대조한다. 기존 AGENTS/CLAUDE/GEMINI·개선 원장을 유지하며 필요한 연결만 보완한다. 이번 설치는 초기 설정 실행·이슈/라벨 생성이 아니다. 엔지니어링 스킬이 설정 파일을 요구하면 그 시점에 기존 운영 방식을 연결한다.
- **Windows·브라우저:** `wizard`의 Bash 예제는 실제 Windows 실행 환경과 사용자가 할 단계에 맞춰 검토한다. Codex/Antigravity의 실제 화면 검수는 기존 Microsoft Edge 규칙을 따른다.
- **테스트·모듈화:** 변경 영향에 맞는 의미 있는 시험을 선택한다. 안정된 기능만 기준 등록/사본 방식으로 적용하며 기존 프로그램을 일괄 바꾸거나 앱 간 런타임 호출을 만들지 않는다.
- **외부 작업·권한:** 이슈 게시·라벨 생성·키/환경변수·스키마·파괴적 삭제·유료 호출·발행은 기존 사용자 요청과 승인 범위를 확인한다. 스킬에 예제가 있다는 이유로 범위를 넓히지 않는다.
- **동시 협업:** 기존 변경이 있으면 검토·보존한다. 공유 스테이징에 다른 CLI 파일을 섞지 않고 공통 문서에는 본인 항목만 반영한다.

## 설치 상태와 재확인

2026-10-19 **현재 Orca Codex 계정**에 `mattpocock-skills@mattpocock` **v1.3.1**을 설치했다. CLI 목록에서 `installed: true`, `enabled: true`, 설치 파일에서 **27개 스킬·27개 고유 이름**을 확인했다. Claude Code·Antigravity·다른 Codex 계정에 설치했다고 보고하지 않는다.

```powershell
codex plugin list --marketplace mattpocock --json
```

다른 환경에서 설치가 필요할 때만 다음 명령을 사용한다. 이 문서를 읽었다는 이유만으로 다른 계정에 설치하거나 저장소 초기화를 실행하지 않는다.

```powershell
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock
```

공급자 원본은 플러그인 캐시에 보관하고, 저장소별 운영 원칙은 이 문서에서 관리한다. 업데이트 후에는 스킬 목록·저장 위치·외부 작업·질문/승인 기본값을 다시 대조한다. [원본 저장소](https://github.com/mattpocock/skills) · [설치 인수인계](HANDOFF_SKILLS_INSTALL_20261019.md).

# 블로그·티스토리 자동화 완성 기준

> **🧭 블로그 작업 최우선 핵심 지침 (2026-10-24 주인님 지시: 「블로그 프로그램은 항상 최종 원문과 이미지는 자동화 프로그램에서 완성하고 이를 확장프로그램을 통해서 자동포스팅(발행전까지/실제포스팅/예약포스팅) 기능을 사용자가 선택해서 동작시킬수 있도록 하는게 블로그 프로그램의 핵심 지침」·「네이버블로그, 티스토리블로그, 워드프레스, 구글블로그(블로그스팟) 모두 해당」, **네이버 블로그·티스토리·워드프레스·구글 블로그(블로그스팟)** 자동화 프로그램 전체·모든 CLI 공통 — 블로그 작업 전에 가장 먼저 읽는다)**
> ① **최종 원문과 이미지는 자동화 프로그램(웹) 안에서 완성한다** — 제목·본문·소제목·태그·대표/본문 이미지까지 프로그램에서 완성·저장하고 회원이 최종 확인한다. 확장이나 블로그 편집기에서 글을 새로 쓰거나 이미지를 만들게 하지 않는다.
> ② **완성본은 크롬 확장이 각 플랫폼의 글쓰기 화면(네이버 스마트에디터·티스토리·워드프레스·블로그스팟)에 자동 입력한다** — 복사·붙여넣기 안내만으로 끝내지 않는다.
> ③ **포스팅 방식은 회원이 직접 고른다 — ⓐ 발행 전까지(입력만 하고 발행 버튼은 회원이 누름) ⓑ 실제 포스팅(즉시 발행) ⓒ 예약 포스팅.** 세 가지를 원고별로 고를 수 있게 하고(계정 기본값 가능), 회원이 고르지 않은 방식으로 발행하지 않는다.
> ④ 확장은 결과(입력 완료·발행 글 주소·예약 시각·실패 사유)를 프로그램에 돌려줘 기록한다. 결과가 불확실하면 자동으로 다시 발행하지 않는다.
> ⑤ 새 블로그 프로그램 개발·기능 추가·병합·간편 모드 등 **모든 블로그 작업은 시작 전에 이 흐름(웹에서 완성 → 확장 자동 입력 → 회원이 고른 방식으로 포스팅 → 결과 기록)을 깨지 않는지 확인**한다. 세 방식 중 빠진 것이 있는 프로그램은 [블로그 기능 상세 비교표](../docs/BLOG_FEATURE_MATRIX.md)·[블로그·티스토리 자동화 완성 기준](../docs/BLOG_AUTOMATION_COMPLETION_POLICY.md)에 「미구현」으로 적고, 완성 보고에 세 방식별 구현·검수 상태를 밝힌다. 회원 본인 계정·본인 키 최상위 규칙은 그대로다.

## 적용 범위와 목표

모든 블로그·티스토리 자동화 프로그램의 신규 개발·업그레이드·병합 비교에 적용한다. 완성 목표는 **자료 입력/수집 → 원고 생성 → 편집·검수 → 확장프로그램 전달 → 해당 플랫폼 편집기 입력 → 자동 포스팅 → 발행 결과 확인·기록**까지 이어지는 흐름이다. 원고 생성·복사·내보내기·편집기 입력까지만 구현된 상태는 전체 자동화 완료와 구분하여 미완료 단계를 명시한다.

각 프로그램에 확장프로그램을 별도로 중복 개발할 필요는 없다. 해당 플랫폼에서 검증된 공용 기준 확장 기능과 프로그램별 연결부를 사용할 수 있으며, 네이버와 티스토리의 계정·편집기·발행 동작 차이를 실제 코드와 화면으로 확인한다. 회원 본인 계정·본인 API 키, 회원별 데이터 격리·30일 보존, 운영/Lab 분리 규칙을 유지한다.

## 회원 선택 항목 (2026-10-24 주인님 결정)

- **발행 방식:** ① 직접 발행(입력·설정까지, 발행 버튼은 회원이 누름) ② 자동 포스팅(임시저장·즉시·예약 발행까지 자동) 중 회원이 원고별·계정 기본값으로 고른다. 자동 포스팅도 결과(완료 문구·글 주소·예약 건수)를 확인·기록한다.
- **입력 방식:** 기본은 사람처럼 입력. 회원이 고르고 위험 안내에 확인하면 「빠른 입력」(문단 묶음 붙여넣기) 가능 — 구간별 확인·최종 대조·중복 금지 필수.
- 상세 규칙: `docs/PLATFORM_PATTERNS.md` §20 ①·④ 개정 문단. 첫 적용 플랜: `naver-blog-agent/docs/PLAN_20261024_MAEPSI_E1_E4.md`.

## 개발·비교·완료 보고

1. 플랜과 프로그램 비교표에 확장 연동 여부, 대상 플랫폼, 입력/발행 단계, 자동 포스팅까지 남은 작업을 적는다. 단순 카테고리 이동이나 원고 기능의 유사성만으로 병합 완료를 판단하지 않는다.
2. 회원이 선택한 대상 계정·카테고리·공개 범위·예약 설정을 확장에 전달하고, 본문·사진 순서·대표 이미지가 이어지는지 검수한다. 실패·재시도 시 중복 발행을 방지하고 회원에게 진행 상태와 복구 방법을 안내한다.
3. Edge 포그라운드 실세션에서 해당 플랫폼의 전체 흐름을 검수한다. 실제 발행 시험은 해당 시험에 승인된 원고·계정·공개 범위로 수행하고, 기존 준비 탭이나 원고를 임의로 발행하지 않는다.
4. 인수인계에는 생성/편집, 확장 전달, 편집기 입력, 실제 발행, 결과 URL/상태 기록의 검수 결과를 각각 남긴다. 모의 시험·발행 준비·실제 발행을 구분하고, 확인하지 못한 단계는 미검수로 적는다.

# 프로그램별 상세 개선 분석 계획

2026-10-19 · Codex · 주인님 요청: 기존 개선표보다 깊게 프로그램을 하나씩 분석하고 각 개선사항의 필요 이유를 기록합니다.

## 범위와 결과물

- 현재 카탈로그 83개를 기준으로 프로그램별 최신 AGENTS/README·개선/인수인계·핵심 소스 경로를 대조합니다. 분석 시작 커밋과 파일별 근거를 남깁니다.
- 프로그램별로 현재 기능/작업 흐름·보존할 장점·구체적인 개선안·필요한 이유·발생 조건/영향·구현 범위·위험/비용·우선순위·검증 방법을 기록합니다.
- 개발·유지보수 / 디자인·사용성 / 창의적인 신규 자동화 세 관점을 구분하고 안정적 자동화·현재 프로그램 적용성·사용자 편의 세 기준으로 평가합니다.
- 확인된 코드 문제, 기존 기록의 미해결 항목, 검증 과제, 신규 기능 제안을 구분합니다. 이미 해결된 기능을 다시 결함으로 등록하지 않습니다.
- 프로그램별 상세 문서, 전체 목록·검색 HTML·엑셀 표, 공통 아이디어 원장 연결과 완료/미완료 인수인계를 남깁니다.

## 진행 순서

1. 최신 공통 규칙·작업 중 표·Git 상태·기본 분석표를 읽습니다.
2. 프로그램별로 문서 → 핵심 입력/처리/출력 소스 → 인증/본인 키/개인 보관 → 오류/재시도 → 화면/회귀 근거 순서로 검토합니다.
3. 같은 항목이 기존 원장에 있으면 근거/이유/범위를 보완하고 새 ID로 이중 구현하지 않도록 연결합니다.
4. 프로그램별 개별 제안을 작성합니다. 확인하지 않은 기능 부재를 확정하지 않고 다음 검증에서 확인할 사실을 씁니다.
5. 대상 폴더에 다른 CLI 작업/기존 변경이 있으면 그 폴더는 수정하지 않고 중앙의 프로그램별 문서에 남깁니다. 안전한 폴더만 서브폴더 문서·진입 문서로 연결합니다.
6. 참조 위치·상태·표 개수·링크·엑셀·로컬 보고서 화면을 검수하고 본인 문서만 커밋/푸시합니다.

## 비용·한계

이번은 코드·문서 기반 상세 분석과 제안서 작성입니다. 실제 기능 수정·운영 DB/키/환경변수 변경·기존 데이터 삭제·유료 API·최종 게시/발송·전 프로그램 빌드/회원 E2E는 수행하지 않습니다. 실제 실행 검증이 필요한 항목은 미검증으로 남깁니다. 회원별 자료 격리·원생성일30일·개별 계정/API 규칙은 유지합니다. 문서만 바꾸므로 앱 버전/프로덕션 배포는 대상이 아닙니다.

단순한 일괄 점검표를 복제하지 않고 각 프로그램의 실제 처리 경로와 산출물에 맞춰 개선 이유와 검증 표본을 작성합니다. 현황은 INDEX.md와 최종 인수인계를 기준으로 확인합니다.

## 결론 먼저

**5개 → 4개.** 「Threads AI 기획」을 「Threads 콘텐츠 운영」에 합치고, 나머지 4개는 독립으로 남깁니다.
- 기획 앱의 페르소나·훅·다시 쓰기는 이미 콘텐츠 운영에 옮겨져 있습니다(`threads-content-ops/lib/personas.ts`, `lib/attention.ts`). 기획 앱은 실제 게시 기능이 없고, 결과 사본을 회원 구분 없는 브라우저 저장소에 둡니다.
- 쇼핑제휴는 콘텐츠 운영과 상품 등록 화면이 겹치지만, 사용 기록이 가장 많고(159건·6명) BEST 배지이며 고유 기능(네이버 트렌드·상세페이지 연동·Meta 삭제 콜백 담당)이 있어 남깁니다. 대신 상품·제휴 연동 코드를 공용 기준 코드로 묶는 것을 제안합니다.
- 분석 중 **병합과 별개로 바로 고칠 만한 문제 4건**을 찾았습니다(§6).

## 4. 병합 진행 방식 (묶음 A, 주인님 결정 뒤)

매뉴얼 §6 절차를 그대로 따릅니다.
1. 플랜 제시 → `docs/ACTIVE_WORK.md`에 `threads-easy-planner/`·`threads-content-ops/` 등록
2. `programs` 두 행 백업 JSON을 이 폴더에 저장
3. 운영 앱에 기획 앱 장점 ①~④ 이식(콘텐츠 생성 화면 안 「사진·영상으로 쓰기」·「추천 주제」), 기획 앱 보관함 옮기기 버튼 또는 읽기 전용 기간
4. 기획 앱은 주소를 지우지 않고 「운영 앱으로 이동」 안내 화면만 남김
5. 권한 합치기: 기획 앱 권한 회원 181명에게 운영 앱 권한을 같은 기간으로(이미 있으면 긴 쪽) — 두 앱 권한 회원 수가 같아 대부분 겹칠 것으로 보이며 실행 때 실제 겹침을 확인
6. 카탈로그: 기획 앱 `is_active=false`, 운영 앱 설명·상세 소개 갱신
7. 배포·크롬 검수, 운영 앱 버전 +0.01(코드+DB), 역량 지도 카드에 「병합됨 → threads-content-ops(날짜)」
8. 기획 앱 코드 정리는 백업 폴더 + git 태그 뒤

- **배지**: 두 앱 모두 FREE가 아님 → 배지 변경 없음.
- **비용**: 운영 앱 빌드 1회 + 기획 앱 안내 화면 빌드 1회(모두 승인 필요). 새 DB 표는 필요 없음(운영 앱 `tco_posts` 사용). 이미지·영상 분석 기능 실제 시험은 회원 본인 키로 1~2회(소액, 승인 필요).

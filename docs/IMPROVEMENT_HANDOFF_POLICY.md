# 작업 중 개선사항 기록·인수인계 지침

2026-10-16 주인님 지시. AIMaster 메인과 모든 서브프로그램, Codex·Claude Code·Antigravity 등 모든 CLI에 항상 적용합니다. 디자인 작업 외 일반 개발·검수·오류 수정에도 적용합니다.

## 2026-10-19 공통 아이디어 표 — 작업 전 확인·종료 후 갱신

모든 CLI는 신규 개발·개선·수정 전에 [공통 아이디어 표](PROGRAM_IDEA_BACKLOG.md)와 대상 프로그램의 최신 개선/인수인계를 읽습니다. 안정적 자동화·기존 프로그램 적용성·사용자 편의 세 기준으로 검토하고, 작업 중 인사이트/아이디어를 기록한 뒤 종료 시 처리 결과·미작업·다음 단계·프로그램 문서/운영 링크를 보완합니다. 다른 CLI 기록은 보존합니다. 기능 안정화가 우선이며 레퍼런스 모듈은 검증 후 신규/리뉴얼 때 하나씩 적용합니다.


## 모든 작업 종료 시 결과·링크 필수 기록 (2026-10-16 재확인)

모든 CLI는 작업이 끝날 때마다 **사용자에게 결과를 보고하고, 같은 내용을 해당 프로그램 인수인계 문서에 반드시 남깁니다.** 디자인·기능 개발뿐 아니라 오류 수정·검수·문서 작업에도 적용합니다. 변경 내용이 없는 조사 결과도 확인한 사실과 한계를 기록합니다.

- 결과: 완료한 내용, 실제 검수 결과·증거와 미검수 항목, 프로그램 버전, 커밋·푸시 결과, 운영 배포 결과, 남은 작업. 해당 없는 항목은 해당 없음으로 구분합니다.
- 링크: 실제 운영 프로그램 URL과 인수인계 문서 링크. 사용자 보고에는 프로그램 주소를 클릭 가능한 단독 줄 마크다운 링크로 넣습니다. 기존 DB app_url·공식 도메인·배포 증거로 확인하며 주소를 추측하지 않습니다. 미배포/배포 실패는 상태를 명시하고 로컬·미리보기 주소와 운영 주소를 구분합니다.
- 특이사항·개선사항: 발견 즉시 IMPROVEMENTS.md에 기록하고, 재현·원인(미확정이면 가설)·영향·처리 여부·관련 파일·주의점·우선순위·남은 작업·다음 첫 단계·검수 방법을 날짜별 인수인계에 남깁니다. 새 발견이 없으면 추가 특이사항 없음으로 적습니다.
- 연결: 프로그램 AGENTS.md/README.md와 루트 docs/HANDOFF.md에서 최신 인수인계로 연결합니다. 다음 CLI는 작업 전에 이 기록을 읽고 최신 코드·DB·운영 배포와 대조합니다.

완료 보고·프로그램 인수인계에 공통으로 사용할 최소 양식:

```markdown
- 대상 프로그램/폴더/버전:
- 작업 결과(완료/미완료):
- 검수 결과·증거/미검수·한계:
- 코드/문서 커밋·푸시 결과:
- 배포 결과·운영 버전(문서만 변경이면 명시):

[프로그램 이름](확인한 실제 서비스 URL)

- 특이사항·개선 필요사항/처리 상태(없으면 없음):
- 관련 파일·주의사항/다음 CLI의 첫 단계·검수 방법:
- 상세 인수인계 문서 링크:
```

## 저장 위치와 읽는 순서

- 개선사항 원장: `<프로그램>/docs/IMPROVEMENTS.md`. 기존 파일이 있으면 이어서 기록하며 과거 근거를 덮어쓰지 않습니다.
- 종료·중단·이관 기록: `<프로그램>/docs/IMPROVEMENT_HANDOFF_YYYYMMDD.md`. 같은 날짜의 다른 작업은 기존 문서에 구분해 추가하거나 작업명을 접미사로 붙입니다.
- 진입 링크: 해당 프로그램 `AGENTS.md`와 `README.md`. 루트 `docs/HANDOFF.md`에는 요약과 상대 경로 링크만 남겨 상세 기록이 프로그램 밖으로 흩어지지 않게 합니다.
- 메인 AIMaster 앱은 루트가 프로그램 폴더이므로 루트 `docs/`에 같은 형식으로 저장합니다.
- 다음 CLI는 루트 지침·ACTIVE_WORK·최신 HANDOFF → 프로그램 AGENTS/README → 최신 개선 인수인계 → IMPROVEMENTS 순서로 읽습니다. 같은 폴더를 다른 CLI가 작업 중이면 시작하지 않습니다.

## 기록 시점과 상태

1. 작업 중 특이사항·오류·개선 필요를 발견하면 바로 원장에 기록합니다. 재현되지 않은 추정은 가설로 표시합니다.
2. 승인된 현재 범위에서 처리했으면 변경 파일·실제 검수 결과·커밋·배포 증거를 연결합니다. 범위 밖 제안은 구현하지 않은 상태로 남깁니다.
3. 종료·중단·이관 전에 다음 첫 단계까지 적고 프로그램 진입 문서와 루트 현황판에서 연결합니다. 문서도 작업 커밋·푸시에 포함합니다.
4. 다음 CLI는 최신 코드·배포와 대조해 상태를 갱신하고 중복 항목은 기존 항목에 근거를 추가합니다. 완료 항목은 삭제하지 않고 결과를 남깁니다.

상태는 **제안(미구현) / 조사 중 / 구현 중 / 구현 완료·검수 대기 / 운영 검증 완료 / 보류(사유)**로 구분합니다. 우선순위와 승인 범위는 별도로 적습니다. 제안 기록 자체는 구현 승인 또는 완료 증거가 아닙니다. 코드 변경 전 개발 플랜 제시와 특수 작업 사전 승인 규칙을 그대로 따릅니다.

## 항목 양식

```markdown
### <ID> <개선사항 이름>
- 발견: <날짜 · CLI · 당시 프로그램 버전>
- 상태 / 우선순위: <상태> / <높음·중간·낮음 및 이유>
- 근거·영향: <관찰/재현 순서·기대/실제 동작·영향 대상; 추정은 명시>
- 관련 파일: <프로그램 기준 경로·관련 기존 인수인계/증거>
- 제안·승인 범위: <해결 방향·현재 요청 포함 여부·필요 승인/의존 작업>
- 처리 결과: <변경 내용·커밋·푸시·배포 ID·라이브 URL; 미처리는 미처리 표시>
- 검수: <실행한 명령/화면과 결과·증거·미검수 항목·비용/호출 횟수>
- 남은 작업·다음 첫 단계: <바로 착수할 수 있는 행동·통과 기준·주의사항>
```

재개 문서에는 현재 코드/운영 버전, 완료한 범위, 미구현 항목별 상태, 권장 순서, 다음 첫 단계와 검수 방법을 적습니다. 비밀번호·API 키·세션·개인정보 원문은 기록하지 않습니다. 회원 기능은 회원 본인 키·계정으로 검수하며, 실제로 확인하지 않은 화면·DB·배포를 통과로 적지 않습니다.

## 2026-10-17 프로그램별 루트 문서 규격화 및 기능·로직·아이디어·버전 히스토리 / 백로그 규격 (주인님 지시)

## 2026-10-17 CLI 공동작업·차이 검토 규칙

다른 CLI 작업과 내 작업이 다르면 목적·최신 지시·변경 차이·검수 근거를 비교해 더 나은 호환 가능한 방향을 선택하고 이유를 기록합니다. 기존 작업을 대체하거나 의도가 충돌해 판단이 어려우면 원본을 보존하고 주인님께 차이·영향·추천 방향을 확인받기 전에는 변경하지 않습니다. 작성자나 최신 시각만으로 우선하지 않습니다. 다른 CLI의 미커밋·스테이징·공유 문서는 보존합니다. [상세 규칙](CLI_COLLABORATION_RULES.md)을 작업 전에 함께 읽습니다. 인수인계에는 완료/미완료, 비교/선택 이유, 미해결 질문, 다음 첫 단계와 서비스 링크를 남깁니다.

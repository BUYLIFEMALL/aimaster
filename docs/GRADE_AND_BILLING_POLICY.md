## 1. 회원 등급 4종 (DB `member_grades`, 숫자가 클수록 높은 등급)

|---|---|---|---|

## 2. 핵심 원칙: 프리미엄 프로그램은 골드·VIP도 별도 결제한다 (2026-10-12 주인님 확정)
- **운영자에게 실제 비용이 나가는 프로그램**(고정 IP 서버, 자체 서버, 검색엔진·키워드 도구, 서버 용량·트래픽이 큰 프로그램)은 **골드(드림팀)·VIP(드림AI팀)여도 유료로 사용**하게 한다. 등급은 "기본 프로그램의 무료 사용"과 (선택) "프리미엄 결제 할인"에만 쓴다.
- **프리미엄 뱃지 = 지정 방법 + 소개 페이지 안내 (구현 완료, 2026-10-12 루트 배포).** 관리자 프로그램 편집(또는 프로그램 목록 일괄 뱃지)에서 **"💎 프리미엄" 뱃지**를 달면(`programs.badges`에 `premium`, DB 제약 `0030_premium_badge.sql`) 프로그램 소개 페이지 맨 위에 "서버·트래픽 비용이 발생하여 드림팀(골드)·드림AI팀(VIP) 회원도 월 단위로 소정의 사용료를 결제해야 한다"는 안내가 **자동으로 표시**되고, **뱃지를 떼면 안내도 함께 사라진다.** 문구는 `lib/programs/premium.ts`에서 고친다. 카드·목록에도 뱃지가 표시된다. **이 뱃지는 표시만 하며, 무료 권한 무효화(결제 필요)는 아직 구현 전이다** — 뱃지를 달아도 이미 부여된 권한은 그대로 동작하므로 아래 "구현 방식"(DB 트리거, 유예 기간)을 확정해 진행해야 한다.
- **무료 권한을 줬어도 프리미엄은 결제해야 쓴다 (2026-10-12 주인님 확정).** 프리미엄으로 지정한 프로그램은 골드·VIP에게 관리자가 무료로 사용권한(`user_program_access`)을 부여했더라도 **그 권한만으로는 열리지 않고, 유효한 결제 구독이 있어야** 사용할 수 있다.
- **결제 방식은 "월결제"다 (2026-10-12 주인님 확정).** 프리미엄 프로그램은 사용자가 **매월 결제**해서 쓰는 프로그램이다. 요금제는 `pricing_plans`의 `monthly`(30일)를 기본으로 하고, 결제를 멈추면(구독 만료) 사용할 수 없다. 장기(2·3·6·12개월) 요금제를 함께 둘지, **페이앱 정기결제(자동 갱신)**를 쓸지 매월 직접 결제할지는 미확정(6번 결정 사항).
- **구현 방식(프로그램 코드 수정 없이 가능한 안, 제안)**: 판정 코드는 `결제 구독` 또는 `등급 + 부여 권한`이면 연다. 45개 프로그램의 판정 코드를 다시 고치는 대신 **DB 한 곳**에서 막는다 — `user_program_access`에 프리미엄 프로그램의 권한이 들어오거나 수정되면 **트리거가 만료 시각을 즉시 과거로 만들어** 부여가 효력을 갖지 못하게 하고, 기존에 부여된 프리미엄 권한도 같은 방식으로 정리한다(유예 기간이 있으면 그 날짜로 만료). 결제 구독 경로는 그대로 열려 있다. 이렇게 하면 어느 화면·스크립트로 부여해도 우회되지 않고 서브프로젝트 재배포가 필요 없다. 대안은 각 프로그램 판정 코드에 `premium → 구독 필수` 조건을 추가하는 방식(핸드폰 정책처럼 45개 일괄 수정·배포)이다.
- **권한 강제 구현 완료 (2026-10-12, DB 적용·검증됨)**: `supabase/migrations/0031_premium_enforcement.sql`. **"💎 프리미엄" 뱃지를 다는 순간** 그 프로그램의 기존 무료 사용권한(`user_program_access`)이 효력을 잃고(만료일을 과거로, 원래 값은 `premium_prev_expires_at` 보관, `premium_suspended=true`), 이후 새로 부여하거나 만료일을 고쳐도 즉시 무효가 된다. **뱃지를 떼면 마지막으로 의도한 만료일로 복원**된다. 달 때 FREE 뱃지는 자동으로 떨어지고 등급 미지정이면 일반으로 채워진다. 결제 구독·관리자는 영향 없음, 유예 없음, 프로그램 코드 수정 불필요. 검증: 임시 시험 프로그램으로 (달기 → 기존 권한 무효·FREE 제거·등급 채움, 무효 상태에서 관리자가 다시 부여 → 계속 무효, 떼기 → 복원)을 확인하고 시험 행은 삭제했다. **결제 연동 전이라 실제 프로그램에는 프리미엄 뱃지를 달지 않았다(현재 0개).** 연동 후 주인님이 뱃지를 달면 바로 적용된다.
- (구현 계획 기록) 계획: ① (지정은 `premium` 뱃지로 대체 — 별도 `is_premium` 컬럼은 만들지 않는다) 등급별 할인율이 필요하면 컬럼 추가 ② 뱃지 지정(완료) ③ 위 DB 트리거로 프리미엄 권한 무효화 + 관리자 화면에서 부여 시 "프리미엄은 결제 필요" 안내 ④ 기존 부여분은 **유예 만료일**로 바꿔 안내 후 자연 종료(즉시 회수 금지) ⑤ 프로그램 카드·상세에 "프리미엄 · 별도 결제" 배지 ⑥ (선택) 등급 할인을 결제 금액에 반영.
- **새 프로그램을 만들 때**: 운영자 비용이 나가는지 먼저 판단해 프리미엄 여부를 정하고(운영자 키·고정 IP·자체 서버·큰 저장/트래픽·대량 발송이면 프리미엄 후보) 이 문서의 목록(3번)에 기록한다. 회원 본인 키(BYOK)만 쓰고 서버 비용이 거의 없으면 기본 프로그램이다.

## 4. 과금 방식 아이디어 (조합 가능, 제안 단계)
1. **등급 할인**: 일반 0%, 골드·VIP 일정 %(비율 미정). 가장 간단하고 수강생 혜택이 분명하다.
2. **세트·번들**: 실버 = 프리미엄 여러 개 세트 구매자. 낱개보다 싼 세트 요금.
3. **기간 요금제 확장**: 현재 1·2·3개월(1만/2만/3만 원)에 6·12개월을 추가하고 장기일수록 할인.
4. **포함량 + 초과 과금(크레딧)**: 월 기본 포함량(저장 GB, 크롤링 횟수 등) + 초과는 충전식. `usage_logs`를 확장해 구현.
5. **수강생 체험권**: 프리미엄을 7~30일 체험으로 열어 주고 이후 유료 전환.
- **추천 조합**: "프리미엄 분리 + 등급 할인 + 장기 요금제"를 1차로, 사용량이 큰 프로그램에만 4번을 나중에 붙인다.

## 등급별 프로그램 자동 부여 · 사용기간 (2026-10-13 주인님 지시, 마이그레이션 0032)

- **목적**: 골드(드림팀)·VIP(드림AI팀)를 회원 한 명씩 프로그램을 골라 주지 않고, **등급에 프로그램을 미리 체크해 두면 그 등급 회원 전원에게 권한이 한꺼번에 부여**되게 한다. 체크를 풀면 자동 부여분이 회수된다.
- **화면**: 관리자 > 접근 권한 관리(`/admin/access-matrix`) 위쪽 "등급별 자동 부여 · 사용기간" 패널(`components/admin/GradeAccessPolicy.tsx`, API `app/api/admin/grade-access`) + 아래 등급×프로그램 표(체크).
- **동작(DB 트리거, 각 프로그램 판정 코드는 수정 없음)**
  - `member_grades.auto_grant`=true 인 등급만 대상(현재 골드 180일, VIP 365일 = `default_access_days`). 일반·실버는 기존 방식(수동 부여).
  - 등급 표에 체크 → 그 등급 회원 전원에게 `user_program_access` 행 생성(`grant_source='grade'`, `granted_grade_id`), 만료일 = **부여한 날 + 기본 기간(회원마다 가입·등급 지정 시점이 달라 각자 계산)**. 이미 있는 부여(수동)는 건드리지 않음(ON CONFLICT DO NOTHING).
  - 체크 해제 → `grant_source='grade'` 인 해당 행만 삭제(수동 부여는 유지).
  - 회원 등급 변경(`profiles.grade_id`) → 이전 등급 자동분 회수 + 새 등급 프로그램 자동 부여.
  - 프리미엄 가드 트리거(0031)는 그대로 적용(프리미엄 프로그램의 무료 부여는 효력 정지).
- **사용기간 두 가지 방식**

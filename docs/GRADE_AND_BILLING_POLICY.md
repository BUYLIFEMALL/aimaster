# 회원 등급 · 프로그램 과금 정책 매뉴얼 (2026-10-12 주인님 설명, 이후 정책 변경 때 이 문서를 먼저 고친다)

> 루트 `CLAUDE.md` 핵심 원칙 16번의 상세판입니다. **등급·권한·요금·프리미엄 프로그램을 건드리는 작업은 반드시 이 문서를 먼저 읽습니다.** 확정되지 않은 항목(6번)은 임의로 구현하지 않고 주인님께 확인합니다.

> **★ 최상위 규칙은 변하지 않는다(2026-10-12 주인님 재확인).** 모든 회원은 **본인 계정과 본인 API 키를 직접 등록해서** 프로그램을 쓴다(루트 `CLAUDE.md` 맨 위 "절대 불변 최상위 규칙", `docs/TOP_RULE_PERSONAL_ACCOUNT_API.md`). 등급·프리미엄·과금 정책은 이 규칙 **아래**에 있으며, 어떤 경우에도 운영자·다른 회원의 키/계정으로 대신 처리하는 방향으로 바꾸지 않는다. 프리미엄 프로그램도 AI 키·외부 계정은 회원 본인 것을 쓰고, 프리미엄 요금은 **운영자가 부담하는 인프라(고정 IP, 자체 서버, 용량·트래픽)** 비용에 대한 것이다.

## 1. 회원 등급 4종 (DB `member_grades`, 숫자가 클수록 높은 등급)
| 등급 | sort_order | 의미 | 사용 방식 |
|---|---|---|---|
| **일반** | 1 | 일반 등급 이상이어야 프로그램을 쓸 **자격**이 생긴다 | 쓸 수 있는 프로그램은 관리자 화면에서 **사용자별로 사용권한과 기간을 부여**해야 한다 |
| **실버** | 2 | 차후 **유료 사용자 중 여러 개 세트를 구매한 사람**을 위한 등급 | 내용은 **나중에 조정**(현재 회원 0명). 정책 확정 전에는 구현하지 않는다 |
| **골드(드림팀)** | 3 | **이커머스 수강생** | 기본 **6개월** 사용. 사용할 수 있는 프로그램과 기간을 **제한**할 예정 |
| **VIP(드림AI팀)** | 4 | **AI 수업 수강생** | 기본 **1년간 모든 프로그램** 사용 예정(프리미엄 제외, 아래 2번) |

현황(2026-10-12 DB): 회원 237명 = 일반 127 · 실버 0 · 골드 24 · VIP 86. `user_program_access`(사용자별 프로그램 권한·기간)가 약 9천 행 수동 부여돼 있다(VIP 약 4100, 골드 약 910, 일반 약 3900). **등급을 바꿔도 권한이 자동으로 부여·회수되지 않는다.**

## 2. 핵심 원칙: 프리미엄 프로그램은 골드·VIP도 별도 결제한다 (2026-10-12 주인님 확정)
- **운영자에게 실제 비용이 나가는 프로그램**(고정 IP 서버, 자체 서버, 검색엔진·키워드 도구, 서버 용량·트래픽이 큰 프로그램)은 **골드(드림팀)·VIP(드림AI팀)여도 유료로 사용**하게 한다. 등급은 "기본 프로그램의 무료 사용"과 (선택) "프리미엄 결제 할인"에만 쓴다.
- **무료 권한을 줬어도 프리미엄은 결제해야 쓴다 (2026-10-12 주인님 확정).** 프리미엄으로 지정한 프로그램은 골드·VIP에게 관리자가 무료로 사용권한(`user_program_access`)을 부여했더라도 **그 권한만으로는 열리지 않고, 유효한 결제 구독이 있어야** 사용할 수 있다.
- **결제 방식은 "월결제"다 (2026-10-12 주인님 확정).** 프리미엄 프로그램은 사용자가 **매월 결제**해서 쓰는 프로그램이다. 요금제는 `pricing_plans`의 `monthly`(30일)를 기본으로 하고, 결제를 멈추면(구독 만료) 사용할 수 없다. 장기(2·3·6·12개월) 요금제를 함께 둘지, **페이앱 정기결제(자동 갱신)**를 쓸지 매월 직접 결제할지는 미확정(6번 결정 사항).
- **구현 방식(프로그램 코드 수정 없이 가능한 안, 제안)**: 판정 코드는 `결제 구독` 또는 `등급 + 부여 권한`이면 연다. 45개 프로그램의 판정 코드를 다시 고치는 대신 **DB 한 곳**에서 막는다 — `user_program_access`에 프리미엄 프로그램의 권한이 들어오거나 수정되면 **트리거가 만료 시각을 즉시 과거로 만들어** 부여가 효력을 갖지 못하게 하고, 기존에 부여된 프리미엄 권한도 같은 방식으로 정리한다(유예 기간이 있으면 그 날짜로 만료). 결제 구독 경로는 그대로 열려 있다. 이렇게 하면 어느 화면·스크립트로 부여해도 우회되지 않고 서브프로젝트 재배포가 필요 없다. 대안은 각 프로그램 판정 코드에 `premium → 구독 필수` 조건을 추가하는 방식(핸드폰 정책처럼 45개 일괄 수정·배포)이다.
- **아직 구현되지 않았다.** 계획: ① `programs.is_premium`(+ 등급별 할인율) 컬럼 추가 ② 관리자 프로그램 편집 화면에서 지정 ③ 위 DB 트리거로 프리미엄 권한 무효화 + 관리자 화면에서 부여 시 "프리미엄은 결제 필요" 안내 ④ 기존 부여분은 **유예 만료일**로 바꿔 안내 후 자연 종료(즉시 회수 금지) ⑤ 프로그램 카드·상세에 "프리미엄 · 별도 결제" 배지 ⑥ (선택) 등급 할인을 결제 금액에 반영.
- **새 프로그램을 만들 때**: 운영자 비용이 나가는지 먼저 판단해 프리미엄 여부를 정하고(운영자 키·고정 IP·자체 서버·큰 저장/트래픽·대량 발송이면 프리미엄 후보) 이 문서의 목록(3번)에 기록한다. 회원 본인 키(BYOK)만 쓰고 서버 비용이 거의 없으면 기본 프로그램이다.

## 4. 과금 방식 아이디어 (조합 가능, 제안 단계)
1. **등급 할인**: 일반 0%, 골드·VIP 일정 %(비율 미정). 가장 간단하고 수강생 혜택이 분명하다.
2. **세트·번들**: 실버 = 프리미엄 여러 개 세트 구매자. 낱개보다 싼 세트 요금.
3. **기간 요금제 확장**: 현재 1·2·3개월(1만/2만/3만 원)에 6·12개월을 추가하고 장기일수록 할인.
4. **포함량 + 초과 과금(크레딧)**: 월 기본 포함량(저장 GB, 크롤링 횟수 등) + 초과는 충전식. `usage_logs`를 확장해 구현.
5. **수강생 체험권**: 프리미엄을 7~30일 체험으로 열어 주고 이후 유료 전환.
- **추천 조합**: "프리미엄 분리 + 등급 할인 + 장기 요금제"를 1차로, 사용량이 큰 프로그램에만 4번을 나중에 붙인다.

## 5. 이미 있는 구조(변경 시 같이 확인)
- 판정 코드: 루트 `lib/access/checkProgramAccess.ts`(`evaluateProgramAccess`)와 각 서브프로젝트 `lib/access.ts`/`programAccess.ts` — 핸드폰 정책(원칙 15)과 같은 위치.
- 사용권한 부여: 관리자 회원 관리 "만료기간 설정"(`app/api/admin/user-access`), 회원 목록 일괄 처리.
- 요금제: `pricing_plans`(1·2·3개월 기본), 결제: 페이앱(`/api/payment/*`), 무료: `programs.badges`의 `free`.
- 등급 수량 제한 컬럼 `member_grades.max_programs`(현재 모두 NULL), 등급-프로그램 매핑 테이블 `grade_program_access`(행은 있으나 판정에는 쓰이지 않음 — 쓰려면 판정 코드 수정 필요).

## 6. 확정이 필요한 결정 사항 (주인님께 확인 후 구현)
1. **프리미엄 프로그램 목록**(3번 후보 중 어떤 것을 지정할지, "확인 필요" 항목 포함 여부).
2. **기존 골드·VIP 회원에게 이미 부여된 프리미엄 권한의 유예 기간**(예: 30일).
3. **등급 할인 여부와 비율**(골드·VIP 각각).
4. **프리미엄 가격·결제 방식**: 월결제(`monthly`) 금액을 얼마로 할지(기존 1개월 1만 원 그대로 vs 프로그램별 차등), 장기 요금제 병행 여부, **자동 갱신 정기결제(페이앱) vs 매월 직접 결제**.
5. 골드의 "사용 프로그램·기간 제한" 기준(프로그램 지정인지 개수 제한인지)과 **실버**의 정의 확정.
→ 확정되면 이 문서 3·6번을 갱신하고 2번의 계획을 구현한다. 구현 후에는 이 문서의 "아직 구현되지 않았다" 문구를 현황으로 바꾼다.

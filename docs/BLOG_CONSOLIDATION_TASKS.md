## 항목마다 지킬 완료 조건

1. 착수 직전 ACTIVE_WORK·미커밋·최신 인수인계를 확인합니다. **대상 프로그램 하나씩** 진행합니다. 다른 CLI의 변경은 목적/근거를 비교해 보존하고, 판단이 어려운 대체는 주인님께 확인합니다.
2. 코드를 고치기 전에 문제·범위·순서·검수·비용·버전/배포·인수인계 산출물을 채팅과 해당 프로그램 docs에 제시합니다. 기능 차이 대조로 이미 있는 기능은 중복 구현하지 않습니다.
3. 무료/모의 검사부터 실행하고, 실제 회원 검수는 지정 계정·본인 키로 합니다. Codex/Antigravity는 보이는 Edge, Claude는 지정 브라우저 규칙을 따릅니다. 최종 발행/외부 공개·대량 유료 호출 등은 기존 승인 규칙을 유지합니다.
4. 본인 공용 키/연동만 재사용하고 다른 회원·운영자 폴백을 금지합니다. 원고/사진/출처는 회원별 격리, 이관해도 원본 생성일 기준 30일 만료를 연장하지 않습니다.
5. 로컬/운영 검사·비용·버전/확장 ZIP·커밋/푸시·배포·라이브 링크를 구분해 기록합니다. 같은 날 배포를 모으고, 실패/미실행 단계가 있으면 운영 완료로 표시하지 않습니다.
6. 완료/이관/중단 시 해당 프로그램 `docs/IMPROVEMENTS.md`와 `docs/IMPROVEMENT_HANDOFF_YYYYMMDD[_작업].md`, AGENTS 또는 README, 루트 HANDOFF, 공통 아이디어 표, 이 목록을 연결합니다. 다른 CLI 스테이징/미커밋을 포함하지 않습니다.

## 새 기능·개선점을 발견했을 때

- **계속 보고**: 사용자 작업 흐름·안정성·비용·데이터에 영향이 큰 발견은 즉시 채팅으로 알리고, 나머지는 단계 종료 보고에 모아 알려드립니다. 기록만 해두고 진행 보고에서 빠뜨리지 않습니다.
- **즉시 기록**: 발견한 프로그램의 IMPROVEMENTS에 날짜/CLI·근거 파일/재현·영향·이유·우선순위·처리 상태를 남깁니다. 공통 아이디어 표의 기존 항목과 중복을 먼저 확인하고 같은 항목에 이력을 보완합니다.
- **세 관점**: 개발/유지보수, 디자인/사용 흐름, 기존에 없던 구현 가능한 자동화 시스템. 새 시스템이 아닌 단순 개선은 그대로 구분합니다.
- **세 채택 기준**: 안정적으로 자동화 가능한지, 현재 프로그램에 적용 가능한지, 사용자에게 편리한지. 근거·미검증·비용/위험·선행 조건도 적습니다.
- **채택과 완료 분리**: 새 제안은 ‘검토 대기’로 등록합니다. 승인된 범위의 보완은 플랜을 갱신하고 수행하되, 별도 제품/회원 권한/데이터 삭제 등 범위가 커지면 먼저 구체 계획을 제시합니다. 현재 작업을 끝내지 않고 새 아이디어로 옮겨 다니지 않습니다.
- **검증 후 레퍼런스화**: 작동을 확인한 좋은 기능만 기준/사본 후보로 등록합니다. 코드 재사용과 회원 생성 데이터 공유는 구분합니다. 이미지 프롬프트 내용/스타일은 프로그램별로 유지합니다.

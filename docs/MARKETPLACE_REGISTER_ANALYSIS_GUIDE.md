# 쇼핑몰(마켓) 상품 자동 등록기 — 분석·개발 레퍼런스

> 2026-10-27 주인님 지시: 「다른 쇼핑몰 들도 순차적으로 자동 등록기를 만들꺼니까 지금 하고 있는 분석 기법 방식을 레퍼런스 문서로 남겨서 이후 다른 cli들도 참고해서 작업할수 있도록 해놔」
> 기준 사례: 스마트스토어 상품등록 자동화 `smartstore-register` v1.01~v1.03(2026-10-26~27, Claude Code 윈도우 `claude-win-sdp`, 역할 `ecommerce-image`). 「입력만」 실제 시험 6회 만에 배송 템플릿 1칸을 빼고 상세설명 사진까지 자동 입력에 성공했다.
> 대상: 쿠팡 윙, 11번가, G마켓·옥션(ESM), 롯데온, 카카오 쇼핑 등 **앞으로 만들 모든 마켓 등록기**. 모든 CLI(Claude Code·Codex·agy)가 같은 순서로 분석·개발한다.

## 0. 먼저 지킬 것
1. **회원 본인 계정**: 판매자센터 로그인은 회원이 자기 크롬에서 직접 한다. 비밀번호·판매자 API 키를 받지 않는다(최상위 규칙). 마켓이 남의 키로 대신 운영하는 것을 허용하지 않으면(네이버 공식 답변) 서버 API가 아니라 **회원 브라우저 입력 방식(크롬 확장)**으로 만든다. 마켓이 회원 본인 키를 허용하면 API 방식을 먼저 검토한다.
2. **봇 탐지 회피**: [`PLATFORM_PATTERNS.md`](PLATFORM_PATTERNS.md) §20 — 칸 사이 무작위 간격(0.35~0.9초), 사람과 같은 순서, 대량 반복 금지.
3. **확장 운영 규칙**: 루트 `CLAUDE.md` 핵심 원칙 10 — 확장 폴더·ZIP·DB `extension_version`을 같은 배포에서 함께 바꾸고 `scripts/check-extension-release.mjs`로 확인한다.
4. **결과가 불확실하면 다시 등록하지 않는다**: 이중 등록이 가장 큰 사고다. 칸 하나라도 실패하면 저장 버튼을 누르지 않는다.
5. **마켓마다 프로그램을 따로 만든다**: 주인님 「앞으로 스마트스토어용 쿠팡용 계속 만들어 나가야하거든」. 이름은 「○○ 상품등록 자동화」, slug는 `<마켓>-register`.

## 2. 분석 기법 상세
### 2-1. 저장본 정적 분석 (가장 중요)
- **왜**: Claude 크롬 확장은 판매자센터 같은 일부 사이트를 안전 제한으로 열지 못한다(우회 금지). 그래서 회원이 저장한 HTML을 읽는다. 열 수 있는 마켓이어도 저장본 분석을 먼저 하면 실제 계정에 손대지 않고 구조를 다 볼 수 있다.
- **어떻게**: 스크래치 폴더에서 node + `cheerio`(스크립트를 실행하지 않는 HTML 해석기)로 저장본을 읽어 아래를 표로 뽑는다.
  | 뽑을 것 | 찾는 방법 예 | 쓰임 |
  |---|---|---|
  | 입력 칸 이름 | AngularJS `ng-model`, React `name`/`id`, Vue `v-model` 흔적, `placeholder`, 가까운 `label` 글자 | 확장이 칸을 찾는 기준 |
  | 버튼 동작 | `ng-click`·`ncp-click`·`onclick`·버튼 글자 | 섹션 펼치기·저장·임시저장 |
  | 숨은 파일 칸 | `input[type=file]`(숨김 포함), 이미지 버튼 근처 | 대표·추가 이미지 넣기 |
  | 섹션 구조 | 섹션 제목·접힘 표시 클래스 | 접힌 섹션은 칸이 DOM에 없음 → 먼저 펼치기 |
  | 고르기 상자 종류 | selectize·react-select·자체 드롭다운 | 검색어 입력 → 목록에서 고르기 |
  | 상세설명 편집기 | 스마트 에디터·자체 에디터·HTML 입력 칸, 팝업 여부 | 상세 이미지 넣는 방식 |
- **원칙**: 화면 위치(좌표·n번째 칸)가 아니라 **이름**으로 찾는다. 화면 배치가 바뀌어도 이름은 잘 안 바뀐다.
- 저장본 원본은 옮기거나 지우지 않고, 스크래치 폴더에 복사해 읽는다. 저장본 속 스크립트는 실행하지 않는다.

### 2-2. 입력 규칙 시험 페이지
상세설명에 「HTML 붙여 넣기」 칸이 있으면 외부 이미지 주소·`<style>`·표·`<iframe>`이 되는지 시험 HTML을 여러 개(A~E) 만들어 회원이 한 번에 붙여 보고 **미리보기만** 확인한다. 결과로 이미지 넣는 방식(주소 붙여 넣기 / 파일 올리기)을 정한다.

### 2-3. 실측 반복 보정 (확장 개발의 핵심 순환)
1. 시험 상품으로 「입력만」 작업을 만든다(저장 버튼은 누르지 않음).
2. 확장이 칸마다 실행하고, 실패하면 **그 자리에서 멈추고 「등록 기록」에 멈춘 칸 이름과 이유**를 남긴다.
3. 기록 + 회원 캡처로 원인을 하나씩 좁힌다(가설 하나 → 확인 하나).
4. 보정하고 확장 ZIP을 다시 만들어 회원이 덮어쓰기·새로고침 → 1로.
- 스마트스토어 경과: 1회 7칸 실패 → 3회 2칸 → 4회 에디터 못 찾음(팝업 차단) → 5회 에디터 사진 칸 못 찾음 → **6회 배송 템플릿 1칸만**.
- 작은 보정은 운영 배포 없이 회원 PC 확장만 바꿔 시험할 수 있다(확장 폴더를 직접 로드한 경우). 모았다가 한 번에 배포한다.

### 2-4. 스마트스토어에서 찾은 원인과 해결 (다른 마켓도 먼저 의심할 것)
| 증상 | 원인 | 해결 |
|---|---|---|
| 칸을 못 찾음(여러 칸) | 섹션이 접혀 있으면 칸이 DOM에 아예 없음 | 섹션 제목(`div.title-line`)을 먼저 눌러 펼친 뒤 찾기 |
| 에디터가 안 열림 | 편집기가 `window.open` 팝업, 확장 클릭은 사람 동작이 아니라 크롬이 차단 | 회원이 그 판매자센터 주소를 팝업 허용 1회(화면에 안내) |
| 「이전 작성 내용」 확인 창에서 멈춤 | 마켓이 임시 저장본 불러오기를 물음 | 확인 창을 찾아 「새로 작성」 쪽을 누름 |
| 에디터 사진 칸을 못 찾음 | 사진 버튼이 화면에 붙이지 않은 `input[type=file]`을 만들어 `click()` | 페이지 쪽(MAIN)에서 `HTMLInputElement.prototype.click`을 잠깐 가로채 칸을 받고 `DataTransfer`로 파일 넣기 → `change` 보내기 |
| 회원 화면에서 안 보임 | 확장이 연 탭이 뒤쪽 다른 창에 열림 | `chrome.windows.create({focused:true, state:'maximized'})`로 맨 앞 새 창 |
| 값은 들어갔는데 저장 때 빈 칸 | 화면 프레임워크가 값 변경을 모름 | 값 넣은 뒤 `input`·`change`·`blur` 이벤트 보내기 |
| 기록 시각이 9시간 다름 | 서버 UTC 표시 | `toLocaleString("ko-KR",{timeZone:"Asia/Seoul"})` |

## 3. 프로그램 구조 (복사해서 쓰는 틀)
- 뼈대: `smartstore-register/` 전체를 복사하고 마켓 이름·칸 이름만 바꾼다(권한·로그인·사이드바·기록·30일 정리 그대로).
- **마켓마다 바뀌는 곳은 두 군데뿐이 되게 한다**:
  1. `src/lib/<마켓>/fields.ts` — 상품 + 기본값 → 단계 목록 `FillStep[]`(칸 이름·동작·값·필수). 웹에서 만들어 확장에 넘긴다.
  2. `extension/background.js`의 칸 채우기 동작 — 칸 찾기·고르기 상자·파일·에디터 처리.
- 공통으로 유지할 것: 연결 토큰(sha256 해시만 저장, 8자리 번호 10분), 작업 받기는 서버가 「대기→입력 중」으로 먼저 바꾼 작업만, 등록 방식 세 가지(입력만 / 임시저장까지 / 바로 등록, 기본은 입력만), 멈춘 칸 보고, 확장이 중간에 꺼지면 실패로 기록, 상태 창 버전 알약·「연결됨」 표시·새 버전 알림.
- 상품 원본: `shop-detail-page`의 `shop_products`·`shop_product_images`(회원 본인, RLS). 마켓마다 상품을 다시 만들지 않는다.

## 4. 「마켓 화면이 바뀌면 대응할 수 있나」 — 정직한 답
**네, 빠르게 대응할 수 있는 구조입니다. 다만 「알아서 고쳐지는」 구조는 아니고 「어디가 바뀌었는지 바로 알고, 한 곳만 고치면 되는」 구조입니다.**
- 잘 버티는 이유: 칸을 위치가 아니라 **이름**으로 찾고, 단계마다 성공·실패를 확인하며, 실패하면 저장하지 않고 **멈춘 칸 이름을 기록**한다. 그래서 바뀐 곳이 바로 드러나고 잘못 등록되는 일이 없다.
- 고치는 순서: 기록에서 멈춘 칸 확인 → 회원에게 그 화면 저장본 한 장 받기 → 바뀐 이름만 대조 → `fields.ts`·확장 한 곳 수정 → 「입력만」 1회 확인 → 모아서 배포. 보통 칸 이름이 바뀐 정도는 짧은 작업이다.
- 한계: 마켓이 화면 프레임워크를 통째로 바꾸거나(예: AngularJS → React), 등록 흐름 자체를 바꾸거나, 자동 입력 차단(봇 탐지)을 강화하면 분석부터 다시 해야 한다. 회원 PC에 설치된 확장은 자동으로 바뀌지 않으므로 회원이 ZIP을 다시 받아야 한다(상태 창 새 버전 알림으로 안내).
- 보강 후보(대기 목록): 칸 이름이 안 맞을 때 라벨 글자로 한 번 더 찾기(예비 찾기), 주 1회 「입력만」 점검 작업으로 화면 변화 조기 발견.

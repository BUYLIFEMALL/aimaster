## 1. 한 줄 요약
**블로그 계정 여러 개를 돌아가며(계정마다 IP 변경) 주소 목록의 블로그마다 「오늘 방문자 수」가 정해 둔 범위 안이면 같은 신청 문구로 서로이웃을 신청하고, 결과를 6가지 상태로 나눠 기록하는 윈도우 프로그램.** AI 없음.

## 2. 앞 단계와의 연결 (주소 목록 폴더 파일 이름으로 확인)
`address/` 안에 `블로그주소추출_공동구매1000.txt`·`이웃주소추출_0515.txt`·`address_댓글,공감 블로거주소 추출.txt` 등이 있다 → 같은 제작사의 **블로그 주소추출(`nbae`, EXT-BLOG-08)** 결과(키워드 검색 블로거·어떤 글에 공감·댓글 단 블로거)를 그대로 넣어 쓰는 흐름. 즉 「대상 찾기(`nbae`) → 서로이웃 신청(`nbbb`) → 댓글·공감(`nbcl`)」 3단 묶음이다. 우리 `blog-neighbor-care`는 이 셋을 한 프로그램 안에서 회원 계정 하나로 잇는다.

## 3. 입력·설정
| 입력 | 내용 |
|---|---|
| 계정 | `id\blog_ID.txt` 여러 계정(우클릭 「계정 불러오기」) |
| 대상 | `address\*.txt` 블로그 주소 한 줄씩(우클릭 「블로그주소 불러오기」) → `blog.naver.com/` 뒤 블로그 ID만 떼어 씀 |
| 신청 문구 | 입력칸 하나(「서로이웃신청 요청글을 작성하세요」), 줄바꿈은 공백으로 바꿈, **모든 대상에 같은 문구** |
| 서로이웃 체크 | 「서로이웃을 신청하려면 체크하세요」 — 끄면 일반 이웃 추가만 |
| 방문자 수 거르기 | 체크 + 숫자 칸 두 개(최소·최대) → 그 범위 밖이면 「블로그 추가실패 [투데이가 N입니다.]」로 건너뜀 |
| 작업 주기 | 최소·최대 무작위 대기(계정 사이) |
| IP 방식 | ADB 테더링 / 프록시 / VPN(ESvpn) / 없음 — `nbcl`과 같음 |

## 4. 동작 흐름
```
시작 → 별도 스레드 Start
 체크된 계정마다:
  IP 바꾸기 → 새 시크릿 크롬 → 로그인(nbcl과 같은 방식)
  성공이면 주소 목록의 블로그마다:
    블로그 ID 떼기
    [방문자 수 거르기 켬] GetToday(블로그 ID) → 범위 밖이면 건너뜀
    BlogBuddyWork(블로그 ID, 서로이웃 여부)
  VPN이면 해제·대기 → 무작위 대기 → 다음 계정
```

### 4-1. 오늘 방문자 수 (`GetToday`)
- 로그인 없이 서버에서 바로 `http://blog.naver.com/NVisitorgp4Ajax.nhn?blogId=<ID>` 를 요청(옛 파이어폭스 사용자 에이전트)
- 받은 XML의 `<visitorcnt id=… cnt="…">` 값들 중 **오늘 칸**의 숫자를 읽음(최근 며칠 방문자 그래프 자료)
- 실패하면 `NONE`

### 4-2. 서로이웃 신청 (`BlogBuddyWork`)
1. 모바일 신청 화면으로 이동: `https://m.blog.naver.com/BuddyAddForm.naver?blogId=<ID>&returnUrl=…`
2. 주소에 `BuddyAddForm.naver`가 없으면(넘어가지 않으면) 이미 이웃 등 다른 상태로 판정
3. 제목 `.title`이 「이웃추가」인지 확인
4. **서로이웃 칸 `#bothBuddyRadio`가 비활성(disabled)이면 「서로이웃 신청을 받지 않는 블로그」**로 기록하고 끝 → 활성이면 클릭
5. 신청 문구 칸(`#buddyAddForm … textarea`)을 비우고 문구 입력(`SendKeys` — 이 칸만 타자 입력)
6. 확인 버튼 `.btn_ok` 자바스크립트 클릭 → 대기
7. 결과 문구로 판정:

| 화면 문구 | 기록 |
|---|---|
| `.txt` 「서로이웃을 신청하였습니다」 | 서로이웃 신청 완료 |
| `.txt` 「이웃으로 추가하였습니다」 | 이웃추가 완료(서로이웃이 아닌 일반 이웃) |
| 그 밖 | 이웃추가 실패 |
| `.txt_area` 「서로이웃 신청 진행중입니다」 | 서로이웃 신청 진행중(이미 신청해 둔 상태) |
| 신청 화면이 안 열림 | 이미 이웃 상태 |
| 중지 버튼 | 작업중지 |

## 5. 우리에게 쓸모 있는 것
| 항목 | 개발 메모 | 반영 위치 |
|---|---|---|
| **방문자 수 범위로 거르기** | 공개 자료 `NVisitorgp4Ajax.nhn`(로그인 불필요)로 오늘 방문자 수를 읽어 너무 작거나(휴면) 너무 큰(대형) 블로그를 뺀다. **회원 PC 확장에서** 천천히 읽는다(우리 서버가 네이버에 요청하지 않음 — 마케팅 예외 지침 §3-1). 응답 형식·주소는 2024년 기준이라 현재 화면과 다시 대조 | `blog-neighbor-care` 추가 개발 **A-1**(주인님 결정 10-27) |
| **신청 결과 6가지 상태** | 위 표의 문구·요소로 결과를 나눠 기록 → 「진행중」은 다시 신청하지 않고, 「받지 않는 블로그」는 대상에서 영구 제외, 「일반 이웃으로만 추가」는 서로이웃 실패로 구분 | 추가 개발 **A-2**(주인님 결정 10-27) · 지금 우리 관계 기록 상태(`not_requested·pending·accepted·removed·unknown`)에 「신청 안 받음」·「일반 이웃만」 추가 검토 |
| **신청 전 서로이웃 가능 여부 확인** | `#bothBuddyRadio` 비활성이면 누르지 않고 끝 — 헛신청·제한 카운트 낭비 방지 | A-2와 함께 |
| 주소 → 블로그 ID 떼기 | `blog.naver.com/` 뒤 첫 마디 | 주소 목록 붙여넣기 아이디어 `IDEA-BNC-URLLIST-01`과 공용 |

## 6. 쓰지 않을 것
여러 계정·비밀번호 파일 · IP 바꾸기 · **모든 대상에 같은 신청 문구**(우리는 내 블로그·상대 블로그 성격으로 문구를 만들고 회원이 확인) · 상한 없는 대량 신청(우리는 「이웃 신청+수락 합산 하루 상한」) · 자바스크립트 `click()` · 서버에서 직접 네이버 요청.

## 7. 우리 프로그램과 비교
| 항목 | `nbbb` | `blog-neighbor-care` |
|---|---|---|
| 대상 | 다른 프로그램이 만든 주소 파일 | 내 블로그 분석 → 이웃 후보 찾기·선택 |

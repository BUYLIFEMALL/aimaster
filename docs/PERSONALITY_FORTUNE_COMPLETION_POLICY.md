## 1. 완성 흐름 (목표)

성격·운세 자동화의 완성 목표는 아래 흐름이 **로그인한 회원 본인 데이터로, 안전 안내와 함께** 끊기지 않고 이어지는 것이다.

**로그인(FREE면 가입 회원 누구나) → 검사·스프레드 고르기 → 문항 답하기 / 카드 뽑기 → 점수·기본 해석(AI 없이) → (선택) 회원 본인 키로 AI 해석·그림 → 참고용·위기 안내 표시 → 회원이 고른 범위만 저장 → 공유(회원이 누를 때만) → 「이어서 보기」로 다른 성격·운세 프로그램 → 30일 정리**

- 이 카테고리는 회원가입 유도용 FREE 프로그램이 많다. **FREE 배지는 「가입·로그인한 회원 누구나」이며 로그인 없는 공개가 아니다**(루트 CLAUDE.md 핵심 원칙 6). 소개용 첫 화면(랜딩)만 비로그인 방문자에게 보일 수 있다.
- 「이어서 보기」(성격 진단 → 성격코드 → 캐릭코드 → 타로점)는 **글자·유형·지표만** 넘기고, 받는 쪽에서 AI 호출·그림 생성은 회원이 직접 누를 때만 한다(자동 과금 금지, 캐릭코드 v1.21·v1.23).

## 2. 「끝났다」고 말할 조건

아래를 모두 만족해야 그 기능·프로그램을 「완료」로 보고한다. 하나라도 빠지면 빠진 단계를 「미완료」·「미검수」로 적는다.

1. **로그인 + 공통 권한 판정**: 검사·결과·보관함·설정 화면과 **모든** 쓰기·AI 호출 API가 `requireProgramAccess()`/`checkProgramAccessApi()`(정지 → 관리자 → 핸드폰 → FREE → 구독 → 등급+사용기간)를 거친다. 결과 화면도 로그인 대상이다. 미들웨어의 로그인 필요 경로 목록에 결과 화면을 빠뜨리지 않는다.
2. **회원 본인 키로 동작**: AI 해석(Gemini·OpenAI)과 AI 그림(Gemini 나노바나나)은 회원 `user_api_keys` 본인 값만 쓴다. 키가 없으면 AI만 막고 검사·기본 해석은 계속 되게 한다(현재 `personality-suite` 방식).
3. **결과 저장 범위가 정해져 있음**(§5): 저장하는 것·저장하지 않는 것·회원이 고르는 것을 화면에서 알 수 있고, 민감 검사는 기본 저장하지 않는다.
4. **30일 자동 정리**: 서버에 저장한 결과·리딩·생성 그림은 생성일 기준 30일 뒤 자동 삭제하고(예약 작업 + `CRON_SECRET`), 회원별 정리 건수를 공용 `cleanup-usage-log` 사본으로 남긴다. 「회원당 N개까지만 보관」은 30일 정리를 대신하지 못한다.
5. **비공개 저장**: 회원 결과에 딸린 그림은 회원 폴더의 비공개 버킷에 두고 서명 주소로 보여 준다. 공유 미리보기(카카오·OG)에 공개 주소가 꼭 필요하면 **회원이 공유를 누른 그림만** 공개용으로 만들고 그 사실을 화면에 알린다(§6).
6. **당해 연도·오늘 날짜 주입**: 해석을 만드는 모든 AI 호출에 기준 연도와 오늘 날짜(한국 시간)를 넣는다. 「올해」「한 해」「이번 달」 같은 시기를 다루는 해석(타로 한 해 운세 등)은 반드시 연도를 넣는다(루트 CLAUDE.md 핵심 원칙 8).
7. **안전 안내 표시**(§4): 모든 결과 화면에 「참고용·진단 아님/재미용」 안내, 마음 상태·위기 관련 결과에는 위기 상담 고정 안내가 화면에 보인다(프롬프트 안에만 있는 것은 인정하지 않는다).
8. **검수 증거**: 로컬 검사(tsc·시험·필요하면 build) → 배포 Ready → 시험 계정(`buylifemall@naver.com`) 실제 화면 확인을 각각 기록한다. 유료 AI·그림 시험은 승인된 횟수만 하고, 누르지 않은 버튼은 「미검수」로 적는다.
9. **문서 갱신**: 같은 작업에서 [성격·운세 기능 상세 비교표](PERSONALITY_FORTUNE_FEATURE_MATRIX.md) 칸·변경 이력, 프로그램 `AGENTS.md`·`docs/IMPROVEMENTS.md`, [프로그램 비교표](PROGRAM_CAPABILITY_MAP.md) 카드·버전을 고친다.

## 4. 안전 규칙 (상표명·위기 안내·진단 금지)

### 4-1. 상표·공식 검사 이름

- **프로그램 이름·화면 제목·검사 제목·소개·공유 카드·페이지 제목(`<title>`·OG)에 상표·공식 검사 이름을 쓰지 않는다.** 바꿔 쓰는 말: MBTI → 「16유형」·「성격유형」, DISC → 「행동 스타일」, TCI → 「기질·성향 점검」, MMPI → 언급 금지, 상업 타로 덱 이름(예: 특정 출판사 덱) → 「78장 타로」(EXT-TL-08 「하지 않기로 한 것」, `personality-suite/AGENTS.md` 「지킬 것」).
- 무관함을 밝히는 면책 문구(「공식 ○○와 무관한 자체 제작 콘텐츠」)는 화면 아래·매뉴얼에 둘 수 있다. 이때 상표명은 면책 문장 안에서만 한 번 쓰고 ® 표기를 붙인다(현재 `mbti/app/layout.tsx` 71행, `mbti-character/app/layout.tsx` 120행).
- 시험으로 지킨다: 제목·소개에 상표명이 들어가면 실패하는 단위 시험(기준 `personality-suite/tests/ps.test.mjs` 71행 `/MBTI|DISC|TCI|MMPI|마이어스/`)을 다른 프로그램에도 둔다.
- **현재 차이(2026-10-24 코드 기준)**: `personality-code`·`mbti-character`는 프로그램 이름·로그인 화면 제목·페이지 제목에 「(MBTI)」가 들어 있다(근거는 작업표 「우선 처리」). 이름 변경은 카탈로그·검색 노출·공유 링크에 영향이 있어 **주인님 결정 후** 바꾼다.
- 문항·해석문·캐릭터는 모두 새로 쓴다. 공식 검사 문항·리포트·상업 캐릭터를 옮기지 않는다(현재 각 `lib/questions.ts`·`content/*` 머리 주석 유지).

### 4-2. 진단 금지·참고용 안내

- 결과와 AI 해석은 **참고용·자기 이해용**이며 의학적·심리학적 진단이 아니다. 병명·진단·치료·약물을 말하지 않고, 단정(「반드시」「원래 그런 사람」) 대신 경향으로 말한다(기준 지시문 `personality-suite/src/lib/tests/ai.ts` `PERSONA`).
- 운세·타로 해석은 **재미용**이며 확정 예언·중요 결정(투자·의료·법률·취업 확정)의 근거로 제시하지 않는다(현재 `tarot/app/api/generate-reading/route.ts` 스프레드별 지시).
- 이 안내는 **결과 화면에 글자로** 보여야 한다. AI 지시문에만 있고 화면에 없으면 미완료다.

### 4-3. 위기 상담 안내

- 마음 상태·스트레스·우울감 등 정서를 다루는 검사는 점수와 무관하게 **결과 화면과 첫 문항에 위기 상담 고정 안내**를 보여 준다: 자살예방 상담 109, 정신건강 위기상담 1577-0199, 청소년 1388, 긴급 119(기준 `personality-suite/src/lib/tests/content/careTests.ts` `CRISIS_NOTICE`, `ResultView.tsx`·`TestRunner.tsx`).
- 진단 용어(우울증·불안장애 등)와 자해 문항을 쓰지 않는다(단위 시험이 검사).
- 회원이 타로·운세 질문에 위기 신호(자해·극단적 선택 등)를 적을 수 있다. 그런 질문에 해석 대신 위기 안내를 먼저 보여 주는 장치는 **아직 어느 프로그램에도 없다**(작업표 대기 항목).

## 5. 결과 저장 범위

| 무엇 | 저장 여부 | 현재 구현 |
|---|---|---|
| 일반 검사 답·점수·기본 해석 | 회원 기록으로 저장(본인만), 30일 정리 대상 | 종합 진단 `personality_suite_results`(RLS 본인만). **30일 정리 없음 — 회원당 100개 정리만**(`src/lib/results.ts` `MAX_RESULTS`) |
| 마음 상태 점검 결과 | **기본 저장 안 함**, 회원이 고르면 저장. 저장해도 AI 분석·종합 프로필에서 제외 | 종합 진단 `src/app/api/submit/route.ts`, `registry.isSensitive()` |
| AI 해석·종합 프로필 | 회원 기록, 30일 정리 대상 | 종합 진단 `personality_suite_profiles`(30일 정리 없음) |
| 빠른 성격유형 결과 | 서버에 저장하지 않음(브라우저 계산 → 결과 주소) | 성격코드 `mbti/lib/scoring.ts`, `components/TestFlow.tsx` |
| 캐릭터 그림 | 회원 폴더에 저장, **지금은 공개 버킷**, 30일 정리 없음 | 캐릭코드 `mbti-character-images`(`supabase/migrations/0004_character_images_storage.sql`) |
| 타로 리딩(질문·카드·해석·그림 주소) | **지금은 리딩마다 자동 저장**, 30일 정리 없음 | 타로점 `tarot_readings`(`components/ResultInteractive.tsx` `saveReadingHistory`), 그림 공개 버킷 `tarot-card-images` |
| 다른 프로그램으로 넘기는 값 | 유형·축 비율(0~100)·질문 글자만. 민감 검사 점수는 넘기지 않음 | 공용 `personality-program-links`(`personality-suite/src/lib/programLinks.ts`) |

- 저장할 때는 `user_id` + RLS 본인만, 서비스 롤을 쓰면 코드에서 `user_id`로 거른다.
- 「다른 회원 결과를 내 화면에 섞지 않는다」: 공유 링크·옛 링크 복원처럼 `user_id` 조건 없이 찾는 코드는 만들지 않는다(타로 옛 링크 복원 사례, 작업표 「우선 처리」).

## 6. 공유 규칙

- 공유는 **회원이 공유 버튼을 눌렀을 때만** 만든다. 저장만 했는데 누구나 열 수 있는 주소가 생기면 안 된다.
- 공유 화면에 보이는 것은 회원이 공유를 고른 범위(유형·카드·해석)만이다. 회원이 적은 **질문 원문**은 기본으로 공유 화면에 넣지 않거나, 넣으면 공유 전에 알린다.
- 회원이 공유를 취소·기록 삭제하면 공유 주소도 열리지 않아야 한다.
- 카카오·OG 미리보기에 공개 이미지가 필요하면 공유를 고른 그림만 공개용으로 둔다. 회원 폴더 전체를 공개로 두지 않는다.
- 공유 주소로 넘어온 이미지 주소는 우리 저장소 주소인지 검사한다(현재 `getTrustedImageUrl` — `mbti-character/app/result/[type]/page.tsx`, `tarot/app/result/page.tsx`).

## 7. 하지 않을 것

- **로그인 없이 검사·결과·리딩 화면을 열지 않는다**(랜딩만 예외).
- **운영자·다른 회원의 키로 대신 해석·그림을 만들지 않는다.**
- **회원이 누르지 않은 AI 호출·그림 생성을 하지 않는다**(새로고침·공유 링크·다른 프로그램에서 들어올 때 자동 생성 금지).
- **유료 그림 생성을 시간 초과 때 자동 재시도하지 않는다**(공용 `geminiImage.ts`가 시간 초과는 재시도하지 않음, 서버 오류·혼잡만 1회).
- **상표·공식 검사 이름을 제목·소개·공유 카드에 쓰지 않는다**(§4-1).
- **진단·병명·치료·확정 예언을 말하지 않는다.** 투자·의료·법률 결정을 권하지 않는다.
- **민감 검사(마음 상태) 점수를 다른 프로그램 주소·공유 이미지·AI 해석에 보내지 않는다.**
- 문항·해석·캐릭터·카드 그림을 외부 원본에서 복제하지 않는다(EXT-TL-08).
- 이미지 생성 프롬프트(캐릭터·카드 화풍)를 다른 프로그램과 공유·복사하지 않는다. 공용으로 쓰는 것은 모델·주소·호출·대기 시간·이미지 받기까지다([IMAGE_PROMPT_RULES.md](IMAGE_PROMPT_RULES.md)). 사람이 나오는 그림은 기본 한국인 묘사(핵심 원칙 3) — 오리지널 캐릭터·타로 인물 묘사도 프롬프트 설계 때 확인한다.

## 8. 회원 본인 키 규칙 (성격·운세 적용)

- 종합 진단: `gemini` 하나(`personality-suite/src/lib/apiKeys.ts` `KEY_PROVIDERS`). 검사 제출·기본 해석에는 키가 필요 없다.
- 성격코드: AI·키 없음.
- 캐릭코드: `gemini` 하나(`mbti-character/lib/apiKeys.ts`), 그림 생성에만.
- 타로점: 그림 `gemini`, 해석 `openai` — 두 키가 따로 필요하다(`tarot/lib/apiKeys.ts`). 키가 없으면 그 기능만 막고 안내한다.
- 새 외부 키가 필요하면 공용 `user_api_keys`·[회원 연동 정보](MEMBER_INTEGRATIONS.md) 구조에 항목을 추가한다.

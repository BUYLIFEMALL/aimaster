# 개발 플랜 — 골드·VIP 회원 개별 프리미엄 프로그램 권한 (2026-11-01)

대상: ① AIMaster 운영(DB ref `esgxyikcnnvmlhygjkth`) · 메인 사이트 관리자 화면. 상태: **구현·배포 완료(`6d3019c86`), 관리자 화면 클릭 검수만 남음**. 회원 목록 일괄 창에는 칸을 넣지 않고 회원 상세에만 두었다.
주인님 지시: 「지금 필요한건 골드/VIP 등급중에서 선택적으로 개별 프리미엄등급 프로그램 사용권한을 부여해주는 기능이야」.

## 문제
- 기본 정책은 유지한다: 골드·VIP는 프리미엄 프로그램을 결제해야 쓰고, 프리미엄 등급은 체크된 전 프로그램을 쓴다.
- 지금은 관리자가 골드·VIP 회원에게 프리미엄 프로그램을 개별 부여해도 `user_program_access_premium_guard`가 즉시 정지한다. 화면에는 성공으로 나올 수 있다.
- 운영 대조(2026-11-01): 골드·VIP의 프리미엄 프로그램 유효 권한 0건, 프리미엄 프로그램 18개.

## 범위
1. DB 마이그레이션 `0053`
   - `grant_source='premium_manual'`을 개별 프리미엄 부여 표시로 쓴다(새 컬럼 없음).
   - `user_program_access_premium_guard`: 이 표시가 있으면 정지하지 않는다.
   - `programs_premium_badge`: 뱃지를 달 때 이 표시는 정지에서 제외한다. 뱃지를 뗄 때 등급에 체크된 프로그램이면 등급 권한으로 되돌린다.
   - 함께 수정: 프리미엄 등급 전환 때 만료된 옛 권한이 새 권한을 막는 문제(`ON CONFLICT DO NOTHING`). 시험 계정 `blog-neighbor-care` 1건 복구(요청함 `773c0b88-de1b-4a6c-80e9-d405adcb927f`).
2. API `app/api/admin/user-access/route.ts`
   - 부여: 관리자만, 대상은 골드·VIP 회원, 대상 프로그램은 프리미엄 뱃지, 만료일 필수.
   - 회수: 등급에 체크된 프로그램이면 정지된 등급 권한으로 되돌리고, 아니면 행을 지운다.
   - 기존 일반 부여가 프리미엄 프로그램에서 정지되면 응답에 건수를 담아 화면에 알린다.
3. 관리자 화면 `components/admin/MembersTable.tsx`의 회원별 사용만료기간 창, `app/admin/members/[id]`
   - 골드·VIP 회원에게 「💎 개별 프리미엄 권한」 칸: 프로그램 체크, 만료일 지정, 현재 부여 목록과 회수.
   - 대량 일괄 부여는 넣지 않는다.

## 결정한 동작
- 판정 코드와 서브 프로그램은 고치지 않는다. 판정은 프리미엄 뱃지를 따로 보지 않고 유효한 권한만 보므로 그대로 열린다(대표 `access.ts` 확인, 나머지는 구현 때 검색).
- 무기한은 두지 않는다. 잊은 권한이 영구 무료가 되는 것을 막는다.
- 회원 등급이 바뀌어도 개별 권한은 만료일까지 유지하고 회수는 관리자가 한다. 등급 변경 함수는 `grant_source='grade'`만 지우므로 추가 수정이 없다.
- 등급 표시와 다른 프로그램의 기간은 바뀌지 않는다. 다른 회원은 그대로 결제 대상이다.

## 구현 순서와 검수
1. 마이그레이션 작성 → `RAISE EXCEPTION` 자동 롤백 시험: 부여 유지, 일반 부여 정지 유지, 뱃지 켜고 끄기, 회수, 등급 변경.
2. 운영 적용 뒤 다른 회원 권한 수가 바뀌지 않았는지 전후 대조.
3. API·화면 구현 → `tsc`, `npm run build`.
4. 크롬 실제 창 검수: 시험 계정 `buylifemall@naver.com`을 잠시 VIP로 내리고 프로그램 1개를 14일 부여 → 회원 로그인으로 접속 → 회수 → 프리미엄 등급 복구. 로그인은 주인님이 직접 한다.

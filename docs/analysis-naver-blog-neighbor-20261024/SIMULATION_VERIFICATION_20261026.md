## 2. 후보 사전 선별에서 확인한 범위

- F01~F08 **8개**: 다른 회원 프로필 거절, 본인/제외/무관 항목 제거, 잘못된 날짜/주소·중복 식별 쿼리 거절, 블로그별 중복 제거, 최대20개, PC/모바일/PostView 글 주소 정규화, 검색 강조 태그 정리.
- 검색 결과의 제목·요약에 회원 키워드가 있는지만 확인하는 **사전 필터**입니다. 정렬의 `summaryMatchCount`는 키워드 일치 개수이며 본문 AI 점수0~100·신뢰도·실제 활동성 점수가 아닙니다.
- 출력의 `evidenceLevel='search-summary'`, `relationship='unknown'`, `canAutoEngage=false`를 유지합니다. 검색만으로 서로이웃/신청 대상 확정·본문 정독·자동 댓글 가능 상태를 만들지 않습니다.
- 텍스트 정리 출력은 **textContent/React 텍스트 렌더링**으로만 표시하는 계약입니다. HTML 삽입에 안전하다는 sanitizer 검증이 아니며 `innerHTML`에 넣지 않습니다.
- 가상자료의 사전 필터를 통과했다는 이유만으로 실제20명 후보의 최근3~5개 글 분석을 완료했다고 표시하지 않습니다. 실제 API 검색 성공은 [별도0-B 기록](PREVALIDATION_20261026_0B_SEARCH_ACCOUNT_ACCESS.md)입니다.

## 4. 아직 증명하지 못한 것

이 코드는 **분석 폴더의 모의 모델**이며 `blog-neighbor-care/` 앱에 적용한 코드가 아닙니다. 단일 Node 프로세스의 메모리 Mutex와 가상 기기 요청으로 순서를 검증했습니다. 실제 Supabase 트랜잭션/행 잠금·여러 서버 프로세스·RLS·토큰 권한·네이버 DOM/성공 판정·외부 서비스의 중복 방지를 증명하지 않습니다.

`observedActorId`, `policyAllowed`, `matched` 등의 값은 **신뢰된 가상 시험 입력**입니다. 운영 API가 회원의 요청 본문을 그대로 믿어도 된다는 구현 예제가 아닙니다. 운영 이관 시 실제 인증·허용 근거·로그인 계정 판정·결과 근거를 서버/확장에서 확보하고 기존 검증된 부품과 대조해야 합니다.

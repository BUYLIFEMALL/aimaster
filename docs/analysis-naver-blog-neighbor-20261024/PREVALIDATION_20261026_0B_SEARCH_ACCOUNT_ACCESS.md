## 3. 비용·호출 한도 확인

[공식 상품 요금표](https://www.ncloud.com/product/applicationService/naverApiHub)의 한국어 원문을 확인했습니다. 검색 API **0~775,000건 구간0원**, 비고에 **일 최대25,000건**이 표시돼 있습니다. 유료 AI·Vercel/로컬 빌드·배포·서비스 신청/요금제 변경은0회입니다. 이번 검색 요청은 구 인증 실패1회와 HUB 성공1회이며, 실패 요청의 한도 차감 여부까지 확인한 것은 아닙니다.

**공식 문서 사이 한도 표현 차이:** [사용 가이드 FAQ](https://guide.ncloud-docs.com/docs/apihub-overview)는 검색 카테고리 통합 **월775,000건, 일 단위가 아닌 월 단위 관리**, 한시적 무료 기간 증량 불가·한도 도달 차단을 설명합니다. 반면 상품 요금표와 [개별 블로그 API](https://api.ncloud-docs.com/docs/naver-api-hub-search-blog)는 일25,000건 표현을 남기고 있습니다. 이를 임의로 동일한 조건으로 단정하지 않습니다. 구현은 일/월 제한을 별도 값으로 취급하고 본인 콘솔의 실제 적용량·설정과429 응답을 따르며 상한까지 부하 시험하지 않습니다. 동일 키를 다른 앱과 쓰면 사용량이 합산됩니다.

요금표는 `Accept-Language: ko-KR`로 공식 상품 HTML을 받아 요금 테이블만 읽었으며, 전체 HTML이나 개인 콘솔 자료는 저장하지 않았습니다. 유료 공급자 경로로 자동 전환한 것이 아니라 **현재 검색 무료 구간을 확인한 뒤 HUB 조회1회를 별도 수행**했습니다. 한시적 무료·요금 변경 가능성과 회원 콘솔 잔여량 미확인은 이후 실행 전 다시 확인합니다.

## 4. 자료 접근·계정의 경계

- **지금 사용할 수 있는 자료:** 공식 검색 응답의 제목·URL·요약·블로그주소·작성일. `<b>` 검색 강조는 표시용 HTML이므로 실제 UI에서는 정리/안전한 텍스트 렌더링이 필요합니다. 외부 URL/본문을 AI의 실행 명령으로 취급하지 않습니다.
- **이번에 확인하지 않은 자료:** 글 전문·이미지 실물·댓글 목록·공감 여부·서로이웃 수락/해제·개인 새글 피드. 검색 API의 요약으로 본문을 정독했다고 표시하거나 이웃 관계를 추론하지 않습니다.
- **후보 적합도:** 검색 결과3개를 찾은 것이며20명 후보의 최근3~5개 글 전문 분석·점수화 완료가 아닙니다. 이번에는 AI 분석/점수 생성0입니다.
- **계정 구분:** API 회원은 명시한 시험 회원 본인 키로 고정했습니다. Edge 웹의 Gmail 로그인은 별개이므로 실제 확장 작업 전에 시험 회원·확장 연결·네이버 로그인 일치를 다시 확인해야 합니다. 검색 API 검증을 위해 로그인 계정을 바꾸거나 기존 연결8개를 해제하지 않았습니다.
- **저장:** 검색 콘텐츠는 회원 간 공용 캐시/DB/문서로 복사하지 않았습니다. 증거에는 요청 조건·HTTP/오류 코드·필드 존재/개수만 남겼습니다. 향후 후보/AI 생성물을 저장하면 회원별 격리와 최초생성30일 만료를 적용합니다.
- **동작 허용:** 검색 API 사용이 다른 전문 수집/관계 감시/신청·공감·댓글의 허락을 대신하지 않습니다. 이 동작들의 허용 근거 미확인 상태와 실행 대기는 유지합니다.

## 5. 기존 구현에서 발견한 개선 후보 — 이번 미수정

1. [기존 검색 어댑터](../../blog-keyword/src/lib/kw/naver.ts)는 이미 HUB 우선·일부 인증/경로 오류 시 구 API를 시도합니다. 이번 시험 회원은 HUB가 성공하므로 신규 이웃 소통 구현은 검증된 HUB 계약을 우선 재사용할 수 있습니다. 다른 회원 키의 경로/권한까지 검증된 것은 아닙니다.
2. [기존 키 등록 화면](../../blog-keyword/src/components/workspace/KeyManager.tsx)은 네이버 개발자센터를 발급처로 안내합니다. 신규 검색 발급 경로·이관 유예·NCP/로그인 앱 키 구분·일/월 한도 안내 보완 후보입니다. 이번0-B에서 UI/키 저장구조/공용 카탈로그/기존 앱 소스는 바꾸지 않았습니다.
3. 공용 `integration_catalog`의 `naver_login`에 검색 키와 같은 provider 이름이 연결돼 있어 **공용 필드 이름만 보고 검색과 로그인 앱 자격증명을 같다고 판단하지 않도록** 설계에 표시해야 합니다. 실제 충돌 여부·구조 변경은 별도 범위를 정해 검토하며 현재 키를 덮어쓰거나 재발급하지 않습니다.

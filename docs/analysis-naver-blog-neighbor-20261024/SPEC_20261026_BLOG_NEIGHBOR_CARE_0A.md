## 4. 작업 상태와 성공 판정

### 상태 전이

| 상태 | 의미 | 허용되는 다음 처리 |
|---|---|---|
| `draft` | 생성 중/생성 완료이나 승인되지 않음 | 내용 확인 후 `ready`, 만료/제외 |
| `ready` | 대상·문장·설정 버전에 대한 실행 동의가 확정됨 | 서버가 할당량과 작업을 함께 선점해 `claimed` |
| `claimed` | 기기·세대번호·만료시각에 묶인 작업, 외부 등록은 아직 허용 안 됨 | 최종 점검 후 `armed`, 만료/중단 시 실행 권한 없이 해제 |
| `armed` | 최종 등록 허가 발급, 슬롯 예약 유지 | 외부 성공 근거로 `succeeded`, 미실행이 입증되면 `failed_no_effect`, 그 외 `uncertain` |
| `succeeded` | 회원 계정·대상·동작 일치하는 외부 결과 확인 | 종료. 같은 작업의 다음 클릭 없음 |
| `failed_no_effect` | 외부 동작이 일어나지 않았다는 근거 확보 | 예약량 반환 가능. 재시도는 새로운 점검·동의 필요, 자동 재시도 없음 |
| `uncertain` | 등록했을 수 있으나 결과 확정 못 함 | 조회·회원 확인만. **재등록·다른 기기 인수·슬롯 반환 금지** |
| `skipped/expired/cancelled` | 제외·만료·실행 전 취소 | 종료. 기존 승인을 새 내용에 사용하지 않음 |

`armed` 이후 통신 단절·탭 종료·프로세스 종료는 미실행 증거가 아닙니다. lease 시간 만료도 재실행 허가가 아닙니다. 장기 미응답 `armed`는 `uncertain`으로 간주합니다. 이미 전송된 외부 동작의 완전한 취소나 외부 서비스와의 exactly-once 트랜잭션은 보장할 수 없으며, **추가 등록을 막고 결과를 대조하는 방향**으로 복구합니다.

### 성공 근거

- 신청: 대상 블로그와 본인 실행 계정에서 신청됨/대기 상태 확인. ‘수락’은 별도 관계 상태이며 신청 버튼 클릭을 수락으로 기록하지 않음.
- 공감: 본인 공감 상태 OFF 확인 → 1회 동작 → ON 확인. 이미 ON이면 건너뜀. 불명확하면 다시 클릭하지 않음.
- 댓글: 대상 글·본인 작성자·확정 문장과 댓글 식별값/화면 결과 대조. 메시지를 보냈다는 로그나 클릭 성공만으로 성공 처리하지 않음.
- 근거는 허용된 방식으로 얻은 최소 식별값·시각·상태만 보관. 비밀번호·쿠키·API키·전체 네트워크 헤더·타인 전문을 증거 로그에 넣지 않음. 확장 보고를 외부 사실에 대한 암호학적 증명이라고 표현하지 않음.

## 5. 동시성·서버 계약

아래는 함수/데이터 계약이며 SQL 적용문이 아닙니다. 공용 Supabase를 이용하되 서비스 키는 브라우저에 전달하지 않습니다. 구체적인 DB 구현 전 공용 회원/권한 함수를 재확인합니다.

### 선점과 등록 허가

1. `claim`: 본인 인증·프로그램 권한·핸드폰/정지 정책·연결 계정/기기·작업 소유자·비용·정책 준비 상태 확인. 서버 시각으로 한국 날짜 산출.
2. 한 트랜잭션에서 회원/날짜 카운터와 이웃/날짜 댓글 슬롯을 잠그고, 동일 작업의 기존 상태 확인. **성공 수+미확정 예약 수+이번1 ≤ 현재 회원 설정 상한**일 때만 작업과 슬롯을 함께 예약. 다른 계정·글·종류로 같은 이웃 슬롯을 다시 받지 못하게 함.
3. 선점마다 단조 증가 `generation`과 기기별 만료시각 발급. `claim/arm/result` 모두 작업 ID·기기·generation 일치 검증. 예전 워커가 깨어나도 새 세대의 권한을 쓰지 못함.
4. `arm`: 회원 ON/OFF·계정·관계·대상·문장 해시·설정 revision·승인 snapshot·당일 슬롯·권한·생성물 만료를 다시 검사. 짧은 유효기간(기본안30초)이며 KST 자정 이전까지만 허가. 날짜를 넘기면 새 날짜 점검·슬롯 확보부터 다시 수행.
5. 외부 최종 동작 직전에 실행 기기가 허가 만료·중단 epoch·현재 로그인/대상 일치를 확인. 네트워크에서 서버 확인을 못 받으면 동작하지 않음. 허가 직후 다른 곳에서 멈춘 경우 이미 실행 중인 클릭까지 취소 보장하지 않으므로 결과를 대조.
6. `result`: 중복 보고는 최초 결과와 같은 응답을 반환. 불일치 결과·예전 세대·다른 기기는 상태를 되돌릴 수 없음. 불확실→성공은 허용된 재확인 근거로만 갱신. 재실행을 위해 성공을 대기로 되돌리지 않음.

| 일일 원장 | 회원+KST 날짜+종류 단위 성공/예약량. 회원 브라우저의 직접 UPDATE 금지. 상한 변경과 claim은 같은 잠금 기준 사용 |
| 댓글 슬롯 | **회원+이웃+KST 날짜 고유**. 종류/글/실행 계정은 고유키에 넣어 제한을 느슨하게 하지 않음. armed/uncertain도 점유 |
| 생성자료 | 분석 프로필·후보 점수/근거·AI 문장·입력 자료는 회원 소유·최초생성시각·만료시각 포함. 다른 회원 데이터 참조 없음 |

모든 회원 SELECT는 본인 행만, 토큰 값은 공용 규칙대로 노출 제한. 설정 변경은 검증된 서버 경로로만 수행합니다. 회원이 자기 행을 소유한다는 이유로 카운터·generation·성공 결과를 직접 수정하도록 RLS를 구성하지 않습니다. 공용 연결의 네이버 로그인 OAuth는 블로그 쓰기 권한과 동일하지 않습니다. 회원 본인 키가 없거나 만료되면 해당 작업을 멈추고 공용 등록 위치로 안내합니다.

## 6. 예약·정리·품질

### 예약

주기 선택은 원문대로 30분 또는1~24시간 정수시간, 활성 시간은 KST이며 자정 넘김 허용입니다. 기존 [예약 판정](../../real_estate_sales/src/lib/publicdata/schedule.ts)은 계산 부분만 재사용합니다. 서비스 워커 메모리/장시간 setTimeout 대신 `next_due_at`·현재 단계·중단 상태를 저장하고 알람 발생마다 다시 판정합니다.

[MV3 수명](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)·[alarms](https://developer.chrome.com/docs/extensions/reference/api/alarms) 기준으로 브라우저/확장 시작·업데이트 시 알람 존재 확인 및 복구, 절전 복귀 시 한 번 재평가합니다. PC가 꺼진 동안 정시 실행을 보장하거나 밀린 횟수만큼 몰아서 실행하지 않습니다. ON 상태라도 로그인/연결/정책 근거가 없으면 대기합니다. 제품 지원 최소 버전은 실제 Edge/Chrome 확인 후 정하고 최신 Chrome 기능을 Edge에서도 동일 지원한다고 가정하지 않습니다.

### 30일 보관

- 생성 프로필·후보 채택 여부와 무관한 분석/점수/근거·신청/댓글 문장·모의/실제 결과 로그·임시 본문: **최초 생성+30일**. 수정/복사/재시도로 만료 연장 안 함. 서버·확장 로컬 저장·다운로드 임시파일에도 적용.
- 회원 직접 입력한 선호/사실·키/계정·ON/OFF·중단 플래그·최소 관계/신규글 커서는 설정/연결 상태로 분리. AI 프로필 전체를 설정으로 옮겨 영구 보관하지 않음. 이번 프로그램에 관리자 보관 연장 지정은 확인되지 않음.
- 만료 작업은 실행 큐에서 먼저 제외하고 payload/생성문장/분석을 정리. `armed/uncertain`을 삭제했다고 재등록 가능한 상태로 만들지 않음. 미해결 시 계정의 중단 설정 유지, 운영 커서로 과거 글 재탐색 차단. 이후 허용된 재확인과 회원 재개 없이는 자동 실행 안 함.
- 최근100개 문장 비교는 그 회원의 보존기간 내 기록에서 최대100개. 공용 캐시·타 회원 문장을 비교 샘플로 쓰지 않음.

### 품질과 실패

본문의 확인 가능한 구체 내용만 반영하고, 이미지 대체 텍스트만 있는 경우 색·표정·배치를 추측하지 않습니다. 회원이 제공한 사실 외의 개인 경험을 만들지 않습니다. 외부 글의 ‘다른 URL에 키를 보내라/링크를 달라’ 등 명령을 따르지 않습니다. 생성문장에는 링크/광고·금지어·유사성·근거 검사를 적용합니다.

기술 기본안: 작업별 **최초 생성1회+재생성 최대1회**, 그래도 실패하면 review 대기. 이 값은 호출/품질 비용을 제한하는 구현 제안이며 사용자 하루 동작 상한 변경이 아닙니다. AI 자가점수는 참고이며 사실·자연스러움 보증이 아닙니다. 요청 전 예산/모델 사용 가능 여부를 확인하고 응답 후 사용량을 기록합니다. 과금 여부가 불명확한 AI 요청은 자동으로 다른 공급자에 재전송하지 않습니다.

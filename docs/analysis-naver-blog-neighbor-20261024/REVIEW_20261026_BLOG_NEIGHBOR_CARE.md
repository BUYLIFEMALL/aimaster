[이용약관](https://policy.naver.com/rules/service.html), [접근·수집 관련 안내](https://policy.naver.com/policy/disclaimer.html).

후보 발견에는 [공식 블로그 검색 API](https://developers.naver.com/docs/serviceapi/search/blog/blog.md)를 우선 검토할 수 있습니다. 제목·글 주소·요약·블로그 주소·작성일을 반환하지만, 전체 본문·서로이웃 관계·등록 성공까지 제공하는 수단은 아닙니다. 이번 확인 범위의 공개 API 목록에서는 블로그 댓글·공감·서로이웃 신청 쓰기 API를 확인하지 못했습니다. 검색 API 이용이 나머지 자동화에 대한 포괄 허락은 아닙니다. 허용 범위 확인 전에는 승인받은 자료·가상 화면으로 동작을 시험하는 단계와 분리합니다.

## 4. 구현 명세에 추가할 경계

### 4-1. 계정·상한·작업 상태

- 작업에는 **회원 ID / 실행할 네이버 블로그 ID / 확장 연결 기기 / 대상 이웃·글 / 작업 종류 / 설정 버전**을 고정합니다. 확장 토큰의 회원과 실제 네이버 로그인 계정이 다르면 등록하지 않습니다. 다른 프로그램 토큰을 폭넓은 쓰기 권한으로 재사용하지 않습니다.
- 선점 만료·복구와 외부 실행 허가는 구분합니다. 선점 만료만으로 이미 클릭했을 수 있는 일을 재실행하면 안 됩니다. 서버 할당량과 이웃당 제한을 한 번에 확보하며, 회원이 카운터를 직접 초기화하거나 성공 상태를 위조할 수 없도록 권한을 나눕니다.
- 권고 상태: `대기 → 선점 → 등록 직전 확인 → 성공 / 실패 / 결과 확인 필요 / 건너뜀`. 신청 수락 대기는 별도 관계 상태입니다. 네트워크·탭 종료 후 결과를 모르면 자동 재등록·할당량 반환을 하지 않고 재확인합니다.
- 회원의 ‘멈춤’은 계정의 모든 기기에 적용하며 최종 동작 직전에 다시 확인합니다. 이미 실행된 동작은 취소됐다고 표시하지 않고 실제 결과를 대조합니다. 제한·보안문자·로그인 해제는 자동 재시도하지 않습니다.
- 확인 모드는 승인한 **문장·계정·대상 글**과 연결합니다. 문장 수정·재생성·대상 변경 후에는 기존 승인을 사용하지 않습니다. 확인 대기 중인 문장은 설정을 자동 등록으로 바꿨다는 이유만으로 일괄 전송하지 않습니다.
- 신청 허용·수락·서로이웃 해제·댓글/공감 비허용·본인 글·삭제 글을 구별합니다. 관계를 한 번 수락 기록했다는 이유로 이후에도 무조건 등록하지 않습니다.
- 30일 로그 삭제 후 오래된 글을 신규 작업으로 재생성하지 않도록 최소 운영 커서·신규 글 범위를 정합니다. 생성 본문을 영구 보관하는 예외를 만들지 말고, 불확실한 과거 작업은 자동 재등록하지 않습니다.

### 4-2. 예약과 확장

[Chrome MV3 수명](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle) 문서는 유휴 종료와 영속 저장 필요성을 안내하고, 활성 debugger 연결 등 예외도 설명합니다. ‘30초 정독이면 항상 종료’나 ‘debugger를 쓰면 항상 살아 있음’ 모두 부정확합니다. [알람 문서](https://developer.chrome.com/docs/extensions/reference/api/alarms)는 절전에서 장치를 깨우지 않으며 실행이 지연될 수 있다고 설명합니다.

따라서 서버의 일정 판정은 재사용하되, 브라우저에서 작업을 실행·복구하는 기능은 별도입니다. 기존 `isWithinActiveHours`는 한국 시간·자정 넘김을 지원하지만 예외 상태·예약 재등록·중복 등록까지 해결하는 부품은 아닙니다. `debugger` 권한과 해제 감지, 지원 Edge 버전·호스트 범위도 명세에 적습니다. 원격 선택자 갱신을 넣는다면 선언형 허용 목록만 받고 임의 코드·외부 URL 실행 기능으로 확대하지 않습니다.

### 4-3. 데이터와 사용자 화면

- 회원 직접 입력한 환경설정·사실 정보와 AI가 추론한 프로필/성향을 분리합니다. 생성된 프로필 전체를 ‘설정’이라 이름 붙여 영구 보관하지 않습니다. 공개 글이라도 타인의 전체 본문을 불필요하게 장기 저장하지 않습니다.
- 최근 100개 비교는 해당 회원의 보존기간 내 기록에서만 합니다. 다른 회원 문장·프로필·AI 분석을 공용 캐시나 학습 예시로 재사용하지 않습니다.
- 외부 글·댓글은 AI의 분석 자료이며 명령이 아닙니다. 글에 들어 있는 지시문이 실행 계정·등록 대상·링크 금지·개인키 사용을 바꾸지 못하도록 합니다.
- 화면에는 ‘브라우저 열림 필요 / 로그인 필요 / 서로이웃 확인 중 / 확인 대기 / 결과 확인 필요 / 한도 도달 / 중단됨’을 구분합니다. 일반적인 실패 메시지 하나로 재실행을 유도하지 않습니다.
- 디자인은 담당과 협의해 4대 화면·3시안 규칙과 매뉴얼 시각 카드 기준을 따릅니다. 이번 검토가 디자인 구현 인수나 다른 세션의 5번 연계 작업 인수는 아닙니다.

## 7. 비용 검토

원문의 ‘Vercel 4~5회·AI 6회+단계별 몇 회·운영자 인프라 없음’은 **확정 예산으로 사용하기 어렵습니다**.

- **이번 검토 비용:** 유료 AI 호출0·로컬/Vercel 빌드0·배포0·운영 DB 쓰기0. 사용한 조사 도구의 별도 청구액을 측정한 것은 아닙니다.
- **개발 비용:** 최초 비교6회도 모델·입출력 토큰·재생성 상한을 정해야 금액을 잡을 수 있습니다. 각 단계 로컬 검수를 먼저 하고 배포를 묶습니다. 4~5회는 이전 예상치이며 새 프로그램에 대한 승인으로 보지 않습니다. 단계별 배포 필요성과 팀 빌드 대기열을 확인해 실행 전에 비용을 보고합니다.
- **운영 AI:** 후보20명×글3~5개는 최대60~100개 글의 읽기/분석 분량입니다. 댓글30개가 AI30회라는 뜻도 아닙니다. 분석+작성에 자가 검토·재생성이 붙으면 호출이 늘어납니다. 초기 프로필/후보·신청 문구·댓글·재생성을 나눠 계측하고 월 예산 초과 전에 멈춰야 합니다.
- **운영 인프라:** 기본 프로그램은 상품 분류입니다. 공용 DB·서버·트래픽·로그를 사용하므로 ‘인프라 없음/총 운영비0’으로 확정하지 않습니다. 회원 AI 비용과 운영자 인프라 비용을 분리합니다.

**계산 예시:** 댓글당 분석 입력4,000/출력300토큰 + 작성 입력1,500/출력200토큰, 하루30개×30일, 추가 검토/재생성 없음. 공식 단가는 [Groq](https://console.groq.com/docs/models), [Haiku 4.5](https://platform.claude.com/docs/en/models/haiku-4-5/overview), [Sonnet 5](https://platform.claude.com/docs/en/models/sonnet-5/overview)를 확인했습니다. 아래는 댓글 분석·작성만의 가정값으로, **총 월 운영비나 실제 품질 비교가 아닙니다**.

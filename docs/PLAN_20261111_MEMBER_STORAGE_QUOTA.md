**가능합니다.** 결제(페이앱)·구독(`subscriptions`)·등급(`member_grades`)·30일 열외(`profiles.retention_exempt`)·공용 자료함(`member_assets`) 구조가 이미 있어서, 새로 만들 것은 다음 네 가지입니다.

2. 회원별 사용량 측정
3. 회원별 보관 정책 함수
4. 사용량 화면

## 4. 설계

### 4-1. DB (공용 DB `esgxyikcnnvmlhygjkth`, 마이그레이션 `0063_member_storage_quota.sql`)
- `storage_plans`: `slug`, `name`, `quota_bytes`, `retention_days`(null이면 구독 중 무기한), `sort_order`. 관리자 화면에서 숫자를 고칩니다.
- **결제는 기존 흐름을 그대로 재사용합니다.**
  - `programs`에 「저장공간 추가」(slug `storage-plus`, 비공개 카테고리 아님, 화면은 메인 사이트)를 등록합니다.
  - `pricing_plans`에 요금제마다 한 줄을 넣고, 새 칸 `storage_plan_slug`로 `storage_plans`와 연결합니다.
  - 페이앱 결제 → 기존 웹훅 → `subscriptions`(program = `storage-plus`)로 이어집니다. 결제 코드는 새로 짜지 않습니다.
- 함수 `member_storage_policy(uid)`(security definer)는 `quota_bytes`, `retention_days`, `source`를 돌려줍니다. 판정 순서는 이렇습니다.
  1. 관리자·시험 계정(`retention_exempt`) → 무제한
  2. 활성 저장 구독(만료 + 7일 유예 전)
  3. 등급 기본 혜택(결정 시)
  4. 일반: 1GB·30일
- `member_storage_usage`(user_id, bytes, by_bucket jsonb, measured_at)
  - pg_cron이 하루 1회 `storage.objects`를 훑어, 경로 안의 회원 번호로 합산합니다(실측 90% 이상 커버).
  - 회원 화면에서 「다시 계산」을 누르면 본인 것만 즉시 다시 셉니다(1분에 1번 제한).
- `profiles.retention_exempt` 처리
  - 지금 값(관리자·시험)은 새 칸 `retention_exempt_manual`로 옮깁니다.
  - `retention_exempt`는 매일 「manual 또는 무기한 구독 중」으로 다시 계산합니다.
  - 그러면 **40개 프로그램이 코드 수정 없이** 구독 회원 자료를 지우지 않습니다.
  - 기존 보호 트리거는 「회원이 직접 못 바꿈」을 그대로 유지합니다.

### 4-2. 기간이 정해진 요금제(90일·1년)의 처리
- 프로그램이 아직 「회원별 일수」를 모르는 동안에는, 90일·1년 구독 회원도 열외 목록에 넣어 **약속보다 길게 보관**합니다. 자료가 빨리 지워지는 사고가 없게 하기 위해서입니다.
- 구독 기간보다 오래된 파일은 메인 사이트의 **중앙 정리 작업**(새 Vercel 정리 라우트, 하루 1회)이 `member_storage_policy`의 일수로 해당 회원 경로의 파일만 지웁니다.
- 공용 기준 코드 `retentionExempt.ts`에 `getRetentionDaysMap()`을 추가합니다. 프로그램은 「다음에 손댈 때」 「회원별 일수」 방식으로 바꿉니다(일괄 수정 안 함).

### 4-3. 화면 (메인 사이트 — 프로그램 화면은 건드리지 않음)
- **사용량 막대**
  - 위치: 「내 자료함」(`/library`) 맨 위, 대시보드 카드, 좌측 메뉴 아래 작은 막대
  - 표시 예: 「💾 0.8GB / 1GB 사용 중 · 보관 30일 · 마지막 측정 오늘 04:00」
  - 80%에서 노란색, 100%에서 빨간색 + 「용량 늘리기」 버튼
- **`/storage` 「저장공간」 화면**
  - 내 사용량(프로그램별 막대 — `by_bucket`을 프로그램 이름으로 표시)
  - 요금제 카드 3개와 구독 버튼(기존 결제 팝업)
  - 「오래된 자료부터 정리하기」 바로가기(자료함)
- **관리자**: 「저장 요금제」 숫자 편집, 회원별 사용량 순위

### 4-4. 꽉 찼을 때 막기 (단계적)
1. **1단계(알림만)**: 사용량 표시와 경고만 합니다. 새 저장은 막지 않습니다.
2. **2단계(저장 차단)**: 공용 기준 코드 `checkStorageQuota(userId, addBytes)` 사본을 만들어, 생성 결과를 저장하기 직전에 부르게 합니다.
   - 한도를 넘으면 「저장공간이 가득 찼습니다 — 용량 늘리기」 안내를 띄웁니다. 유료 AI 호출 **전에** 확인해 회원 키가 낭비되지 않게 합니다.
   - 용량이 큰 영상·음원·이미지 프로그램부터 적용하고, 나머지는 손댈 때 적용합니다.

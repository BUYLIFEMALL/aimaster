## 4. 병합 진행 방식 (데이터수집·유튜브·인스타 병합과 같은 절차, 매뉴얼 §6)
1. 묶음마다 플랜 → 기준 앱(바나나 캔버스)에 기능 옮기기 → 옛 앱은 **주소를 지우지 않고** 바나나 캔버스로 이동 안내 → 권한 합치기(옛 앱 권한 회원 148명에게 같은 기간 부여, 단 바나나 캔버스가 FREE라 가입 회원은 이미 모두 사용 가능) → 옛 앱 `is_active=false` → 백업 폴더(`D:\Antigravity\AIMaster_backup\retired-programs\`) + git 태그 뒤 정리.
2. **FREE 배지**: 기준(바나나 캔버스)이 FREE이고 옛 앱 두 개는 FREE가 아님 → 합치면 포토 리메이크·올인원 그래픽 기능이 사실상 무료가 됩니다. **그대로 FREE 유지할지 주인님 결정 필요**.
3. 순서: A → B (하나씩 끝내고 다음). 그 뒤 독립 앱 보안 보강(이미지 스튜디오·스타일 분석기 공개 버킷)은 병합과 별개 작업으로 진행 권장.
4. 비용: 새 운영 인프라 없음, 새 DB 표 불필요(바나나 캔버스 기존 표에 모드 값만 추가 — 필요하면 컬럼 하나, DB 변경 승인 대상). 시험은 회원 본인 Gemini 키로 가장 싼 이미지 모델(`gemini-3.1-flash-lite-image`) 몇 회, 배포는 묶음당 2~3회(기준 앱 + 옛 앱 안내 화면) 순차.

## 5. 확인 필요(주인님 결정)
1. 병합 묶음 A(포토 리메이크 → 바나나 캔버스)·B(올인원 그래픽 → 바나나 캔버스)와 순서 동의 여부. B는 대안(이미지 스튜디오 「템플릿」 탭)도 가능합니다.
2. 합친 뒤 바나나 캔버스 **FREE 배지 유지** 여부.
3. 독립 앱 보안 보강(이미지 스튜디오 결과 버킷·스타일 분석기 원본 버킷을 비공개로, 30일 삭제 cron)을 병합보다 먼저 할지.
4. 이미지 스타일 분석기 ↔ `reverse-prompt`(다른 카테고리) 카테고리 간 병합 분석을 따로 진행할지.

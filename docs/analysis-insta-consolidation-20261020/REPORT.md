# 인스타그램 계열 프로그램 병합·독립 분석 (2026-10-20, Claude Code 윈도우)

주인님 지시: 「인스타쪽 지금 개발되어 있는 프로그램을 자세히 비교 분석해서 병합할 프로그램과 독립 진행할 프로그램을 비교 분석하고 이유를 표로」.

## 3. 병합 시 지켜야 할 것 (실제 작업 전 플랜에 넣을 항목)
1. **옛 주소 유지**: 회원이 Meta 개발자 화면에 등록한 OAuth 콜백(`redirect_uri`)과 북마크가 옛 도메인을 가리킴 → 옛 주소·콜백을 지우지 말고 새 프로그램으로 전달(도메인 SSO 정책·핵심 원칙 11).
2. **회원 데이터 이전**: `cns_*` → INSTA 표(또는 반대), `ig_accounts`·`dm_accounts` → 하나로. 회원 본인 소유·RLS·30일 자동 삭제 규칙 그대로.
3. **이용 권한**: 병합 전 두 slug 중 하나라도 권한이 있던 회원은 병합 후에도 쓰게(`user_program_access` 이전), 사라지는 slug는 카탈로그에서 「병합됨」 표시 후 비공개. 요금·FREE 배지(INSTA만 FREE) 처리는 주인님 결정 필요.
4. **역량 지도·카탈로그**: 병합된 카드에 「병합됨 → 대상 slug(날짜)」 표시(원칙 23), 상세 소개 다시 작성(원칙 22).
5. **공용 기준 코드**: 병합으로 사라지는 사본은 `check-shared-modules.mjs`에서 빼고, 남는 프로그램이 기준이 되면 기준 위치 이동.

## 2. 「끝났다」고 말할 조건 (유형별)

아래 단계가 **모두** 코드에 있고, 각 단계의 검수 증거(로컬 시험·실제 회원 화면·운영 배포)를 따로 적었을 때만 그 기능을 「완성」으로 보고한다. 하나라도 빠지면 빠진 단계를 「미구현」 또는 「미검수」로 적는다.

### 2-1. 분석형 (키워드·경쟁사)
1. **입력**: 회원이 키워드·검색엔진·지역을 고른다.
2. **수집**: 회원 본인 SerpApi 키로 검색 결과를 가져오고 유형(자연·광고·질문·지역 등)을 나눠 저장한다.
3. **분석**: 회원 본인 AI 키로 조사·분석하고, 결과는 그 회원 것으로만 저장한다(다른 회원 조사 재사용 금지).
4. **결과물**: 화면 표 + 내려받기(CSV·HTML 등) + 다음 작업으로 넘기기(예: 확장 키워드 → 경쟁사 분석 등록).
5. **보관**: 생성일 기준 30일 뒤 자동 삭제가 실제로 돌고(DB 예약 작업), 화면에서도 30일 지난 행을 숨긴다.
6. **알림(있으면)**: 완료 알림은 회원 본인 텔레그램 봇으로만.

### 2-2. 발송형 (메일·문자·카카오·리마인드)
1. **명부**: 회원이 고객·예약을 직접 입력하거나 엑셀로 올리고, 미리보기 → 등록 순서로 확인한다(잘못 올린 파일이 바로 발송 대상이 되지 않게).
2. **발송 계정**: 회원 본인 메일 계정(SMTP 앱 비밀번호, 공용 `user_smtp_accounts`)·본인 SOLAPI(공용 `user_solapi_accounts`)·본인 카카오 채널 ID만 쓴다. 없으면 **아무것도 보내지 않고** 등록 안내를 보여 준다(다른 채널로 몰래 대신 보내지 않음).
3. **문구**: 광고성 문자에는 「(광고)」 머리말과 수신거부 안내가 자동으로 붙는다. 이메일도 수신거부 방법을 본문에 넣는다(→ §5 「확인 필요」).
4. **예약 실행**: 회원이 고른 실행 방식(AIMaster 기본 Vercel 예약 / 본인 cron-job.org, [예약 기능 지침](SCHEDULER_POLICY.md))으로 돌고, 일시정지·재개가 된다.
5. **중복 방지**: 같은 대상에게 같은 회차·같은 규칙 메시지가 두 번 나가지 않게 선점(claim)하거나 고유 제약을 둔다. 발송 도중 실패해도 자동으로 처음부터 다시 보내지 않는다.
6. **제외**: 수신거부·발송제외(구매 완료 등) 대상은 발송 대상에서 빠진다.
7. **기록**: 대상·채널·성공/실패·시각을 회원별로 남기고 화면에서 확인할 수 있다.
8. **실발송 검수**: 실제 발송 시험은 주인님 승인 후 **본인 번호·본인 메일 1건**으로만 하고, 실제 고객 명부에 대한 캠페인 실행으로 시험하지 않는다.

### 2-3. 응대형 (통합 받은편지함)
1. 원래 프로그램(인스타 댓글·DM, 쓰레드, 유튜브)의 권한을 각각 확인한 뒤 그 플랫폼 대기 항목만 보여 준다.
2. 승인 게시는 원래 프로그램과 같은 게시 함수 사본을 쓰고, 상태를 공유해 이중 게시가 없다.
3. 자동 수집·AI 초안은 원래 프로그램 책임이며, 받은편지함은 수집 상태를 **보여 주기만** 한다.
4. 실제 공개 게시 검수는 주인님 승인 후 플랫폼별 1건.

## 3. 회원이 고르는 항목

| 프로그램 | 회원이 고르는 것 | 기본값 | 근거 파일 |
|---|---|---|---|
| 키워드·경쟁사 | 검색엔진(구글·네이버), 지역·언어, 추적할 내 경쟁사, HTML 리포트 생성 여부, 확장 결과 중 분석으로 보낼 키워드(최대 10개) | 지역 South Korea · ko | `competitor-analysis/lib/actions/keywords.ts`, `components/expand/SendToAnalysis.tsx` |
| Step Mail | 발송 채널(이메일·문자·둘 다), 휴대폰 방식(문자·카카오 브랜드 메시지), 카카오 실패 시 문자 대신 보내기, 대상 차수, 발송 시각·수량, 반복(한 번·매일·매주), 사용할 메일 계정, 예약 실행 방식 | 채널 이메일 · 휴대폰 방식 문자 | `stepmail/lib/actions/campaigns.ts`, `lib/schedule.ts`, `lib/kakaoBrand.ts`, `components/settings/SchedulerModePicker.tsx` |
| 예약 리마인드 | 규칙별 발송 시점(예약 전·후 분), 채널(이메일·문자·알림톡·친구톡), 문구, 규칙 켜기/끄기, 예약 실행 방식 | – | `booking-reminder/lib/actions/reminderRules.ts`, `lib/booking/reminderDispatch.ts` |
| 통합 받은편지함 | 플랫폼 필터, 답장 수정 후 승인·건너뛰기·되돌리기 | 전체 | `comment-inbox/lib/actions/inbox.ts` |

회원이 고르지 않은 채널·시각·대상으로는 보내지 않는다. 기본값을 바꾸는 작업은 기존 캠페인·규칙의 저장값을 바꾸지 않는다(새로 만드는 것에만 적용).

## 4. 하지 않을 것

- **스팸 발송 도구로 만들지 않는다**: 수신 동의가 없는 명부를 사거나 긁어 와서 보내는 기능, 발신자·광고 표시를 숨기는 기능, 수신거부를 무시하거나 끄는 옵션, 메일 서비스 하루 한도를 피하려고 계정을 대량으로 돌리는 기능을 만들지 않는다. 여러 계정 번갈아 쓰기는 회원 **본인** 계정 범위 안에서만.
- **무단 수집을 하지 않는다**: 검색엔진·SNS 화면을 로그인 우회·차단 회피로 긁지 않는다. 검색 결과는 회원 본인 SerpApi(공식 API)로, SNS 댓글은 회원 본인 연동(OAuth) 공식 API로만 가져온다. 경쟁사 「회사 조사」는 공개 정보 요약까지이며 개인(대표자 연락처 등) 신상 수집을 목표로 하지 않는다.
- **다른 회원·운영자 계정·키로 대신 처리하지 않는다**: 운영자 SMTP·운영자 SOLAPI·운영자 SerpApi 폴백 금지. 키·계정이 없으면 안내만 한다.
- **생성 데이터를 공유하지 않는다**: 경쟁사 회사 조사 정보도 회원별로 저장한다(전역 회사 캐시 폐기, `competitor-analysis` v1.08).
- **실제 고객 명부로 시험하지 않는다**: 실발송 시험은 본인 번호·본인 메일 1건, 주인님 승인 후.
- **결과를 보장하지 않는다**: 「상위 노출 보장」「노쇼 0」 같은 문구를 쓰지 않는다.

## 5. 회원 본인 계정·키 규칙 (최상위 규칙의 마케팅 적용)

| 항목 | 저장 위치 | 쓰는 프로그램 | 없을 때 |
|---|---|---|---|
| SerpApi·OpenAI·Perplexity·Anthropic 키 | 공용 `user_api_keys`(`resolveApiKey`, 폴백 없음) | 키워드·경쟁사 | 「본인 키를 등록해 주세요」 안내(`components/settings/ApiKeyRequiredModal.tsx`) |
| OpenAI·Gemini 키 | 공용 `user_api_keys` | Step Mail(초안·이미지) | 이미지만 건너뛰거나 초안 생성 안내 |
| 메일 계정(SMTP) | 공용 `user_smtp_accounts` | Step Mail·예약 리마인드 | 이메일 발송 안 함 |
| SOLAPI·발신번호·카카오 채널 ID | 공용 `user_solapi_accounts` | Step Mail·예약 리마인드 | 문자·카카오 발송 안 함, 선택지 꺼짐 |
| cron-job.org 키 | 공용 `user_api_keys`(`cronjob_org_api_key`) | Step Mail·예약 리마인드 | 기본 실행 방식만 |
| 텔레그램 봇 | 공용 `user_telegram_links`(프로그램별) | 키워드·경쟁사(확장 완료 알림), 예약 리마인드(연결만) | 알림 없음 |
| 인스타·쓰레드·유튜브 연결 | 원래 프로그램 연결 / `member_platform_accounts` | 통합 받은편지함 | 원래 프로그램에서 연결 안내 |

발송 요금(SOLAPI 문자·카카오)과 AI 호출 요금은 회원 본인 계정에 청구된다. 이 사실을 설정 화면·매뉴얼에 적는다.

## 6. 생성 데이터 보관 (회원별 격리·30일)

- 분석 결과·수집 결과·AI 초안·이미지는 회원별(`user_id` + RLS)로 저장하고 생성일 기준 30일 뒤 자동 삭제한다. 계정·키·연동·설정·회원이 직접 만든 키워드 정의는 삭제 대상이 아니다.
- 현황(코드 확인, 2026-10-24): `competitor-analysis`는 DB 예약 작업 2개(`competitor-generated-data-retention-30d` 매시 07분, `longtail-generated-data-retention-30d` 매시 09분 UTC — `supabase/migrations/20261016115339_*`, `20261023120000_*`) ○. **`stepmail`·`booking-reminder`는 매뉴얼 화면에 「30일 데이터 보존」이라고 적혀 있으나(`stepmail/app/(dashboard)/guide/page.tsx`, `booking-reminder/app/(dashboard)/guide/page.tsx`) 자동 정리 코드·예약 작업을 찾지 못했다** → [통합 작업표](MARKETING_CONSOLIDATION_TASKS.md) MKT-INS-01. `comment-inbox`는 자체 저장이 없다(원래 프로그램 표를 읽음).
- 고객 명부(리드·예약)를 「회원이 올린 원본 자료」로 볼지 「생성 데이터」로 볼지는 아직 정해지지 않았다 → 주인님 결정 필요(통합 작업표 「확인 필요」).

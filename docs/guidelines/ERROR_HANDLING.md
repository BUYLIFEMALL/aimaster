# 에러 처리·재발 방지 지침 요약

[분야별 색인](README.md) · 오류 조사 시작 전 [ERROR_LESSONS의 작업 전 점검](../ERROR_LESSONS.md)을 읽고 같은 실패 사례를 찾습니다.

## 증거 확인 → 원인 조사 → 수정 → 재검증 → 기록

| 단계 | 확인·처리할 내용 | 다음 단계로 갈 근거 |
|---|---|---|
| 증거 확인 | 기대/실제 동작·발생 조건·시간·프로그램/버전·실행 번호·재현 순서, 필요한 로그/응답/화면 | 증상과 영향 범위를 설명할 수 있음 |
| 원인 조사 | 코드·환경변수/DB·인증·권한·대상 계정·외부 응답·배포/확장 버전을 대조, 가설과 확정 사실 분리 | 어떤 조건에서 왜 실패하는지 근거가 있음 |
| 수정 | 승인 범위에서 원인에 필요한 부분만 변경, 기존 데이터·다른 CLI 작업 보존 | 재현 원인을 직접 다루는 변경임 |
| 재검증 | 수정 전 실패와 수정 후 결과 비교, 영향받는 기존 흐름 확인, 실제 회원/운영 검수 별도 표시 | 통과한 검사와 미검수 범위가 명확함 |
| 재발 방지 기록 | 증상 → 원인 → 해결/파일 → 다음 점검, 날짜·프로그램·버전·남은 작업 | 다른 CLI가 같은 오류를 다시 조사하지 않고 이어갈 수 있음 |

## 실패 종류별로 먼저 대조합니다

- **로그인/권한:** 화면에 회원 표시가 남아 있다는 사실만으로 세션 정상이라 판단하지 않습니다. 실제 API 응답과 본인 세션·권한을 대조하며 게스트·관리자 우회로 통과시키지 않습니다.
- **DB/환경변수:** 실제 대상 ref·현재 칼럼·마지막 마이그레이션·회원 소유자 조건을 확인합니다. 첫 SQL 파일만 보고 현재 구조를 단정하지 않습니다. 키 호환은 [DB 연동 정책](../DATABASE_CONNECTION_POLICY.md)을 따릅니다.
- **외부 API/AI:** 본인 키·모델/엔드포인트·실제 응답·제한 시간을 확인합니다. 실패/시간 초과 뒤 자동 재시도로 중복 과금되지 않게 기존 정책을 확인합니다.
- **확장/자동 발행:** 웹/확장/ZIP/DB/설치본 버전, 실행 번호·선점·입력/발행/결과 상태를 대조합니다. 발행 요청 이후 결과가 불확실하면 실제 게시 증거와 결과만 복구하는 기존 경로를 확인하며 재클릭으로 중복 발행하지 않습니다.
- **배포:** 실제 해당 배포의 Ready/오류·공식 주소 연결·라이브 파일을 확인합니다. 연속 배포 로그만으로 실패를 단정하지 않고 `vercel inspect` 등 기존 확인 경로로 재확인합니다.
- **브라우저/도구:** 제어 도구의 포커스·탭·선택 실패와 제품 오류를 구분합니다. 현재 창·탭·URL을 확인하고 기존 편집/준비 작업을 보존합니다.

## 종료와 공유

- 실패한 단계는 원인을 조사하고 승인 범위에서 복구합니다. 끝내지 못한 경우 완료한 단계·실패 원인·미완료·다음 첫 단계를 명시합니다.
- 공통 교훈은 [ERROR_LESSONS](../ERROR_LESSONS.md)에 해당 분류로, 상세 재현과 영향은 해당 프로그램 `docs/IMPROVEMENTS.md`·날짜별 인수인계에 남겨 같은 작업 커밋에 포함합니다.
- 키·토큰·비밀번호·회원 원문은 기록하지 않습니다. 검수 증거는 필요한 범위로 제한합니다.
- 회귀 방지가 필요한 로직은 의미 있는 기존/추가 시험으로 확인합니다. 모의 통과·실제 회원 통과·운영 확인을 구분하며, 비용은 [비용·배포 요약](COST_AND_DEPLOY.md)을 따릅니다.

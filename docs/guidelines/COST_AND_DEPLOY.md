# 비용 및 배포 관련 지침 요약

[분야별 색인](README.md) · 비용이 발생하는 작업이나 버전/배포를 다루기 전에 읽습니다.

## 비용 승인과 시험

- 비용 발생 전 항목·횟수·계정/키·대략 비용을 보고하고 승인 범위 안에서 진행합니다. Vercel 배포 빌드 1회도 포함합니다. 이미 승인된 플랜의 비용 범위는 다시 묻지 않으며 새 항목이나 초과 비용만 재확인합니다. **2026-10-22 비용 규칙이 과거 ‘배포까지 재질문 없이 진행’ 설명보다 우선합니다.**
- 무료/로컬/모의 검사를 먼저 사용합니다. 유료 시험은 기능이 가능한 저렴한 모델·최소 횟수로 하며, 품질/성능/특수 기능에 상위 모델이 필요하면 이유와 사용량을 기록합니다.
- 시험은 지정 회원이 등록한 본인 키를 사용합니다. 모델을 저렴하게 시험한다는 이유로 실제 회원 기능의 품질 기준을 낮추지 않습니다.
- 종료 보고와 인수인계에는 항목·횟수·계정/키 소유자·대략 금액·승인 범위 준수 여부를 남깁니다. 비용이 없으면 `비용 없음`으로 적습니다. [시험 비용 원문 §0](../TEST_COST_POLICY.md).

## 배포할 때와 모아 둘 때

| 상황 | 기존 최신 지침의 처리 |
|---|---|
| 작은 문구·화면·내부 정리·작은 수정 | 로컬 검수·커밋/푸시 후 미배포 대기로 모아 다음 배포에 포함 |
| 대량 소스 수정 또는 다음 작업에 실제 배포가 필수 | 즉시 배포 대상이며 비용 승인 범위 확인 후 진행 |
| 회원에게 바로 피해가 있는 버그·보안·이중 과금 | 긴급 배포 대상으로 처리하고 관련 사본까지 영향 확인 |
| 공용 기준의 급하지 않은 변경 | 사본을 저장소에 반영하고 프로그램별 다음 배포로 이월 |

같은 날 같은 프로그램의 변경을 모아 배포 횟수를 줄입니다. 작은 변경의 대기는 프로그램 개선 문서·루트 [미배포 목록](../PENDING_DEPLOYS.md)·HANDOFF에 적으며 공용 사본은 [공용 모듈 목록](../SHARED_MODULES.md)에도 남깁니다. 대기 기록과 운영 반영 완료를 구분합니다.

## 버전·확장·배포 검사

1. 버전은 **실제 배포 때 한 번** 올립니다. 미배포 커밋마다 올리지 않습니다. `v1.01 → v1.02`, `v1.99 → v2.00`을 따르고 주인님 지정의 큰 메이저 변경과 구분합니다. 신규 운영 프로그램은 `v1.01`부터 시작합니다.
2. 코드 `APP_VERSION`과 DB `programs.version`을 맞춥니다. 확장이 있으면 같은 릴리스에서 manifest·ZIP·`extension_version`·다운로드 주소까지 맞춥니다. [확장 배포 원문](../EXTENSION_RELEASE_RULES.md).
3. 로컬 검사와 대상 폴더/ACTIVE_WORK/대기 목록을 재확인한 뒤 `node scripts/deploy.mjs <폴더> --go`를 사용합니다. 본인 작업 행이 있으면 `--owner` 사용법을 확인합니다. 도우미와 DB 버전 동기화 절차는 [협업 원문 9번](../CLI_COLLABORATION_RULES.md)을 따릅니다.
4. 해당 배포의 Ready·공식 도메인 연결·라이브 버전·인증/회원 동작을 확인합니다. 확장은 `node scripts/check-extension-release.mjs <slug>`로 실제 ZIP과 DB를 비교합니다. 회원 PC 설치본 업데이트는 별도이므로 덮어쓰기·새로고침을 안내합니다.
5. 프로그램 인수인계·역량 지도·미배포 목록을 실제 배포 결과에 맞추고 결과와 단독 줄 서비스 링크를 보고합니다.

## 비용을 줄이는 운영 조건

팀 빌드 머신은 Basic 기준을 유지합니다. 메모리 부족은 먼저 해당 프로그램의 Node 메모리 한도를 검토하고, 해결되지 않으면 상위 머신 변경 필요를 보고합니다. 루트 메인 배포는 실제 메인 코드/다운로드 변경과 빌드 제외 규칙을 확인하며 서브프로그램 변경만으로 불필요하게 배포하지 않습니다. [배포 비용 절감 원문](../VERCEL_COST_REDUCTION_PLAN.md).

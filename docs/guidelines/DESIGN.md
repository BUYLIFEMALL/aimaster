# 디자인 관련 지침 요약

[분야별 색인](README.md) · 화면을 고칠 때 읽습니다. 템플릿 선택과 매뉴얼 규격은 [별도 요약](DESIGN_TEMPLATES.md)으로 연결합니다.

## 착수와 화면 구성

1. [디자인 메인 원문](../../DESIGN.md), [프로그램 디자인 표준](../PROGRAM_DESIGN_STANDARD.md), 대상 프로그램의 `docs/DESIGN_HANDOFF.md`를 읽습니다.
2. 리뉴얼 전 프로그램 기능·작업 흐름·불편을 분석하고 플랜과 개선사항을 기록합니다. `ACTIVE_WORK`와 디자인 현황판에서 다른 CLI의 작업 여부를 확인합니다.
3. 프로그램 성격과 기존 검증 템플릿에 맞춰 라이트/다크·배경·포인트 색을 선택합니다. 같은 프로그램의 작업실·목록·설정·매뉴얼 등 모든 페이지가 통일된 테마를 사용해야 합니다.
4. 본문 작업 영역을 중심에 두고 탐색·설정·결과의 관계를 분명하게 만듭니다. 상태·빈 화면·오류·처리 중 반응을 사용자가 이해할 수 있게 표시합니다.

## 메뉴·모바일·조작성

- 사이드바 상단의 `← 다른 프로그램 보기`는 `https://www.buylife.xyz/programs`로 연결합니다.
- 계정·로그아웃의 위치와 메뉴 구성은 [사이드바 표준](../SIDEBAR_LAYOUT_STANDARD.md)을 확인합니다. 767px 이하에서는 좌측 메뉴를 숨기고 위쪽 ☰ 메뉴로 전환하며 메뉴 마크업과 전환 CSS를 함께 구현합니다.
- 모바일 메뉴에서도 데스크톱과 같은 항목·순서·계정 접근을 유지합니다. 좁은 본문은 열 수를 줄이고 조절 점은 24px 이상으로 만듭니다.
- 좁은 칸의 버튼·짧은 문구는 잘림·과도한 줄바꿈·겹침을 확인합니다. 긴 결과·고정 버튼이 본문을 가리는지도 실제 화면에서 확인합니다.
- 로그인/회원가입 화면은 디자인 메인 원문의 표준 2탭 레이아웃과 프로그램 테마별 변형 범위를 따릅니다.

## 매뉴얼·검수·인수인계

- 매뉴얼 메뉴/가이드가 없는 프로그램을 디자인 작업 중 발견하면 기존 지침에 따라 단계별 시각 매뉴얼을 구축합니다. 필수 구성과 템플릿은 [템플릿·매뉴얼 요약](DESIGN_TEMPLATES.md)을 읽습니다.
- CLI에 배정된 실제 브라우저를 포그라운드로 열고 데스크톱·좁은 화면·메뉴 펼침·계정 접근·복사/입력·상태 변화를 확인합니다. 브라우저 배정은 [CLI 협업](COLLABORATION.md)의 최신 조건을 확인합니다.
- `node scripts/check-mobile-account.mjs` 등 기존 점검 도구를 참고하되, 자동 검사와 실제 화면 검수 결과를 구분합니다.
- 완료 시 템플릿명·컬러 토큰·반응형 기준·컴포넌트·검수/한계·남은 작업을 `docs/DESIGN_HANDOFF.md`에 남기고 디자인 현황판을 실제 결과에 맞춰 갱신합니다.
- 추가개선 제안은 기능/로직·UI 가독성과 편의·다른 프로그램 연계로 구분합니다. 타 프로그램에서 발견한 제안도 해당 프로그램 문서에 기록하되 구현 승인을 받은 것으로 간주하지 않습니다.

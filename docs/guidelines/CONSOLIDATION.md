# 프로그램 병합 개발·독립프로그램 지침 요약

[분야별 색인](README.md) · ‘기능 이관’, ‘기존 서비스 독립 유지’, ‘Lab 독립프로그램’을 구분합니다.

## 비교 분석과 실제 개발은 구분합니다

1. [프로그램 비교 분석 매뉴얼](../PROGRAM_COMPARISON_ANALYSIS_GUIDE.md)의 순서로 기존 보고서·운영 메타데이터·권한/사용 이력·코드·실제 화면을 대조합니다.
2. 해당 매뉴얼의 프로그램 분석표·병합 방향표·독립 유지표를 작성하고, 추천 이유·실측/추정·미검증·비용/위험을 표시합니다. 재현 방법·기준 커밋·근거·HTML·CLI 인수인계를 남깁니다.
3. 분석 단계에서는 코드·DB·권한·배포·서비스 상태를 바꾸지 않습니다. 비교 결과를 실제 병합 승인으로 해석하지 않습니다.
4. 승인된 묶음만 한 프로그램씩 플랜 → 구현 → 검사 → 적용 가능한 배포/운영 검수 → 인수인계로 진행합니다. 기존 보고서를 새 분석으로 덮어쓰지 않습니다.

## 기능을 이관할 때 보존할 것

- 원본과 대상의 부족한 기능만 비교해 옮기며, 프로그램의 고유 작업 흐름·대상 플랫폼 어댑터·회원 키/계정을 보존합니다.
- 원고·사진·수집 출처·소유자·최초 생성/수집일·원래 만료일·검수 지문·진행 작업을 확인합니다. 복사/이관으로 회원 데이터 공유나 보관기간 연장이 생기지 않게 합니다.
- 기능 동등성, 실패 복구, 구버전 확장, 회원 이용권, 기존 자료/미완료 작업, 되돌리기와 안내 계획을 대조합니다.
- 검증된 코드 부품만 [공용 기능 지도](../SHARED_FEATURE_MAP.md)·[공용 모듈](../SHARED_MODULES.md)에 기준/사본으로 등록합니다. 코드 공용화와 프로그램 통합·회원 데이터 통합은 별개의 결정입니다.
- 블로그/티스토리는 [자동 포스팅 완성 기준](../BLOG_AUTOMATION_COMPLETION_POLICY.md)에 따라 실제 발행과 결과 URL 기록까지 검사합니다. 생성·입력 준비만으로 이관 완료라고 하지 않습니다.

## 독립 유지와 서비스 종료

| 구분 | 적용 원칙 |
|---|---|
| 운영 프로그램을 독립 유지 | 고유 기능·플랫폼·회원 작업·유지보수 차이를 근거로 판단. 운영 공용 DB/회원/본인 키 원칙 유지 |
| 원본 도구의 신규 개발 중단 | 기능 이관·동등성·회원 전환과 중단 시점을 주인님과 확정한 후 처리 |
| 서비스/도메인/계정/DB 삭제 | 병합 추천이나 신규 개발 중단에 포함된 것으로 간주하지 않음. 명시된 별도 범위 확인 |
| Lab의 독립프로그램 | 프로그램마다 독립 회원/도메인/운영. [Lab 지침](../AIMASTER_DEV_LAB_GUIDELINES.md)을 적용하며 운영 변경 금지 경계 유지 |
| 외부 배포 설치 키트 | 기존 키트 지침의 별도 설치/회원 본인 계정·키·지원 범위를 확인 |

블로그 단계·현재 담당·완료 여부는 [순차 작업목록](../BLOG_CONSOLIDATION_TASKS.md)과 최신 프로그램 인수인계에서 읽습니다. 과거 보고서의 추천·담당 표기를 현재 상태로 단정하지 않습니다.

# 개발 플랜 — 공지에 프로그램 연결 + 「내 작업대」 새 공지 알림 (2026-10-20, Claude Code 윈도우)

주인님 지시: 「공지까지 연결하려면 공지에 프로그램 칸을 추가하는 별도 작업 — 이것까지 진행, 개발 플랜이 세워지면 보여줘」.
앞선 작업: 「내 작업대」 즐겨찾기 DB 저장 + 새 버전 알림(커밋 c9282cf7, 표 `program_favorites`).

## 1. 문제
- `notices` 표: id·title·content·is_pinned·is_active·view_count·created_at·updated_at — **어느 프로그램 공지인지 칸이 없다.**
- 그래서 「내 작업대」에 고정한 프로그램의 새 공지를 알려 줄 수 없다(지금은 버전 변경만).

## 2. 범위와 설계
| 구분 | 내용 |
|---|---|
| DB(운영 `esgxyikcnnvmlhygjkth`) | `notices.program_ids uuid[] not null default '{}'`(비어 있으면 사이트 전체 공지) + GIN 인덱스. `program_favorites.seen_notice_at timestamptz`(이 프로그램 공지를 마지막으로 본 시각). 파일 `supabase/migrations/0041_notice_program_link.sql`. 기존 공지·즐겨찾기는 값이 비어 있어 동작 변화 없음. |
| 관리자 공지 화면 | 공지 추가·수정 창에 「관련 프로그램(선택)」 — 검색되는 체크 목록. 목록 카드에 연결된 프로그램 이름 칩. API(`/api/admin/notices`) POST·PUT이 `program_ids`를 받아 저장(존재하는 프로그램 ID만). |
| 공지 상세(`/support/notice/[id]`) | 연결된 프로그램 칩(누르면 프로그램 상세). |
| 「내 작업대」 | 메인 화면이 최근 60일 켜진 공지 중 프로그램이 연결된 것만 가볍게(id·제목·program_ids·작성 시각) 받아 넘김. 고정 프로그램마다 **마지막으로 본 뒤(없으면 고정한 뒤) 올라온 공지**가 있으면 「📢 새 공지」 표시(누르면 그 공지로 이동). 공지·상세·실행을 누르면 「봤음」 시각 저장 → 사라짐. 새 버전 점과 같은 방식(`lib/favorites/client.ts`). |

## 3. 구현 순서
1. 마이그레이션 SQL 작성 → 크롬 SQL Editor(PRODUCTION 확인)로 적용 → 칸 확인
2. 관리자 API·공지 관리 화면(프로그램 선택) → 공지 상세 칩
3. 즐겨찾기 부품에 seen_notice_at 읽기·쓰기 → 메인 화면 공지 조회 → 「내 작업대」 표시
4. `npm run build` → 커밋·푸시(메인 사이트 자동 배포)

## 4. 검수
- 관리자 계정: 시험 공지 1개를 「웹 크롤링 자동화」에 연결해 **비공개(OFF)로** 만들었다가, 검수 순간만 켜고 끝나면 삭제(회원에게 노출 최소화).
- 시험 회원 계정: 웹 크롤링 고정 → 「📢 새 공지」 표시 → 누르면 공지로 이동·표시 사라짐 → 고정 해제. DB 값 대조.
- 시험 데이터(공지·즐겨찾기) 원상 복구.

## 5. 비용·버전·산출물

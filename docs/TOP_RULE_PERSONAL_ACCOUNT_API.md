> **절대 불변: 사용자는 본인의 계정과 본인이 사용할 본인 API 키를 각각 등록·연동해서 사용한다 (2026-10-09 주인님 재확인 — 핵심 지침 맨 위).**

# ★ 최상위 절대 규칙 — 모든 프로그램은 "회원 개인이 본인 계정·본인 API를 연동해서" 쓴다

> 2026-10-09 주인님 지시: **"AIMaster에 속해 있는 모든 프로그램은 각각의 개인이 개인 계정과 API를 연동해서 사용하는 것이 절대적인 핵심 지침이며 가장 상위에 있는 규칙이다. 이 규칙에서 벗어나지 않도록 하라."**
> 루트 `CLAUDE.md`·`AGENTS.md`의 다른 모든 원칙보다 **위**에 있다. Claude Code · Codex · Gemini 등 모든 CLI는 코드를 쓰기 전에 이 문서를 읽고, 이 규칙과 충돌하는 요청·코드는 만들지 않는다.
> (이 규칙은 새로 생긴 것이 아니라 핵심 원칙 2·4번과 "멀티테넌시 원칙" 1~4번에 흩어져 있던 것을 **가장 위로 올려 못 박은 것**이다.)

## 1. 규칙 한 줄

**모든 사용자는 각각 본인의 API와 플랫폼(외부 계정)을 연동해서 자동화 프로그램을 동작시킨다.** (2026-10-09 주인님 정의) 엔진(코드·로직·화면)은 우리가 만들고, 그 엔진을 돌리는 연료(AI API 키, 외부 서비스 계정, OAuth 앱)는 이용하는 회원 한 사람 한 사람이 본인 것을 연동해서 쓴다. 운영자(주인님)나 다른 회원의 키·계정으로 다른 회원이 대신 쓰이는 일은 어떤 경우에도 없다.

### 1-1. 사용 자격 (2026-10-09 주인님 정의)

**각 사용자는 현재 일반 사용자 등급 이상이고, 해당 프로그램에 대한 사용기간 권한이 있으면, 로그인한 뒤 그 프로그램을 사용할 수 있다.** 이 한 문장이 모든 프로그램의 접근 기준이다.

- 구체 판정 순서는 루트 `CLAUDE.md` 핵심 원칙 6번을 그대로 따른다: 정지 계정 차단 → 관리자 허용 → **FREE 배지 프로그램은 가입한 회원이면 허용** → 결제한 구독 → (최소 등급 미지정이면 허용) → **회원 등급 ≥ 프로그램 최소 등급(일반 이상) 그리고 관리자가 넣어준 사용기간(`user_program_access.expires_at`)이 남아 있음** → 그 외 차단.
- 로그인하지 않은 방문자는 사용할 수 없다(로그인 화면으로 보낸다). "비로그인 열람 허용"·"게스트"는 없다.
- 이 자격을 통과한 사용자도 **자동화에 쓰는 API 키·외부 계정은 반드시 본인 것**이다(위 규칙). 사용 자격이 있다고 운영자·타인의 키를 대신 쓰게 되는 것은 아니다.

## 2. 이 규칙이 요구하는 것 (반드시)

1. **로그인한 회원 본인으로만 동작한다.** 모든 화면·API·Server Action은 로그인 + 해당 프로그램 이용 권한을 확인한다. 비로그인 방문자는 로그인 화면으로 보낸다.
2. **API 키는 `user_api_keys`에서 `user_id = 로그인한 회원`인 행만** 쓴다. 본인 키가 없으면 `null`을 돌려주고, 호출부는 "API 키 등록이 필요합니다" 안내(설정 화면 이동)를 띄운다.
3. **외부 계정(Threads·Instagram·YouTube·네이버·카카오 등)은 회원별로 저장**한다(`user_id` + RLS). OAuth `state`에 회원 ID를 실어 콜백에서 세션과 대조한다.
4. **OAuth 앱(Client ID/Secret, App ID/Secret) 자체도 회원 본인이 만든 것**을 등록한다. 운영자가 만든 공용 앱을 여러 회원이 같이 쓰지 않는다(예외는 대상 플랫폼이 앱 심사 없이 모두 받아주는 것이 확실하고 주인님이 승인한 경우뿐).
5. **회원 데이터는 회원별로 격리**한다(`user_id` + RLS owner-only). 서비스 키(관리자 클라이언트)를 쓸 때는 코드에서 `user_id`로 직접 한정하고, 클라이언트가 보낸 ID로 쓰기 전에는 그 행이 내 것인지 먼저 확인한다.
6. **API 키·토큰은 채팅·로그·문서·커밋에 적지 않는다.** 회원이 채팅에 키를 붙여 넣으면 노출된 것이므로 폐기·재발급을 안내하고, 에이전트는 그 키를 어디에도 입력·저장하지 않는다.

## 3. 금지 (코드·설정·시험 어디서도)

| 금지 | 이유 |
|---|---|
| 비로그인 방문자를 특정 회원(관리자·테스트 계정 포함)으로 간주하는 "게스트 계정"·"임시 열람 허용" | 아무나 그 계정의 데이터·키·권한을 쓰게 된다 |
| `checkProgramAccessApi()` 등이 인증·권한 확인 없이 항상 허용을 돌려주는 코드 | 이용 권한 우회 |
| 본인 키가 없을 때 **다른 회원/운영자의 키로 폴백**(`user_api_keys`를 `user_id` 없이 `limit(1)`로 읽기 등) | 다른 사람 비용이 나가고 키가 오남용된다 |
| 운영자 환경변수 키(`OPENAI_API_KEY` 등)로 회원 요청을 처리 | 운영자 비용을 모든 회원이 쓰게 된다 |
| 운영자가 만든 공용 OAuth 앱·공용 외부 계정을 모든 회원이 공유 | 앱이 개발 모드면 다른 회원은 인증 자체가 거부된다(2026-09-16 사례) |
| 모든 회원이 공유하는 데이터를 일반 회원이 수정·삭제하게 두는 것(관리자 확인 없는 쓰기) | 한 사람이 모두의 데이터를 망칠 수 있다 |
| 소유자 확인 없이 클라이언트가 보낸 ID로 `upsert`/`update`/`delete` (서비스 키 사용 시) | 다른 회원의 행을 덮어쓴다 |
| 시험 편의를 위한 "임시로 열어두기" | 임시는 영구가 된다(ai-image-studio 사례) |

## 4. 시험(테스트)은 어떻게 하나

- **`buylifemall@gmail.com`은 유일한 관리자 계정**이고, **`buylifemall@naver.com`은 일반 회원과 같은 권한으로 시험하기 위한 테스트 계정**이다(2026-10-09 주인님 확인).
- 일반 회원 기능은 **테스트 계정으로 실제 로그인해서** 시험한다. "게스트"·"비로그인 허용"·"관리자 우회"로 시험하지 않는다. 시험 중 로그인이 이어지지 않으면(도메인이 달라 세션이 안 넘어가는 등) 우회를 넣지 말고 쿠키 도메인·리다이렉트 원인을 고친다.
- 테스트 계정도 **본인 키를 설정 화면에 등록해서** 쓴다(관리자 키·다른 회원 키를 빌려 쓰지 않는다).

예외는 **주인님이 채팅에서 명시적으로 승인한 경우에만** 가능하며, 승인 날짜·범위·이유를 이 문서 아래에 적는다. 승인 기록이 없는 예외는 없는 것이다.

- **2026-10-09 승인 — 일반 예외 조항(무료 키·무료 공용 키)**: 주인님이 "키 중 무료키나 무료공용키는 운영자가 등록한 키를 써도 된다"를 메인 지침 하단 예외로 추가하라고 지시. 조건(비용 없음 / 회원 개인 계정·데이터와 무관한 공개 데이터 용도 / 코드·저장소에 키 금지 / 여기에 기록)은 루트 `CLAUDE.md`·`AGENTS.md` 맨 아래 "최상위 규칙의 예외 조항"에 정의돼 있다. **추가 지시(같은 날)**: 무료여도 계정당 한도가 있어 한 키로 몰리면 금방 리밋에 걸리는 키는 예외가 아니라 회원 본인 키를 쓴다(네이버 검색·데이터랩 → `threads-affiliate-poster` v1.49에서 본인 키로 유지). 아래 `real_estate_sales` 항목은 5분 주기 수집 1회분을 전 회원이 캐시로 공유해 호출량이 회원 수와 무관하게 고정되므로 주인님이 개별 승인한 사례다.
- **2026-10-09 승인 — `real_estate_sales`의 무료 공공데이터 키(범위: `SEOUL_OPENDATA_API_KEY`·`DATA_GO_KR_SERVICE_KEY`·`VWORLD_API_KEY`·`VWORLD_REGISTERED_DOMAIN`·`N8N_VWORLD_PROXY_*`, 읽는 곳 `src/lib/publicdata/client.ts`)**: 주인님이 "예외로 인정 (무료 공공 키)"를 채팅에서 명시 승인. 이유: 정부 공개 데이터라 사용 비용이 없고, 5분 주기 수집 결과(실거래·건물대장 등 공개 시장 데이터)를 모든 회원이 함께 쓰는 구조다. **범위 한정**: 위 공공데이터 수집 키에만 적용한다. 같은 프로그램의 AI 키(OpenAI·Claude·Gemini·퍼플렉시티)는 계속 회원 본인 키만 쓴다(v1.04에서 폴백 삭제 완료). 이 예외를 다른 프로그램으로 넓히려면 다시 명시 승인을 받는다.
- **2026-10-09 승인 — `blog_auto_poster`는 회원 서비스가 아닌 운영자 전용 도구(규칙 대상 밖)**: 주인님이 "운영자 전용 도구로 분리 표기"를 승인. 사이트·Vercel 배포가 없고 운영자가 명령줄로 직접 돌리며, 환경변수 `GEMINI_API_KEY`는 운영자 본인 실행에만 쓰인다. 회원이 쓰는 기능으로 바꾸는 순간 이 예외는 사라지고 본인 키 방식으로 만들어야 한다.

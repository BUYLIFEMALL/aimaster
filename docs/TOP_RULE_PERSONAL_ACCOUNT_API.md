## 1. 규칙 한 줄

**모든 사용자는 각각 본인의 API와 플랫폼(외부 계정)을 연동해서 자동화 프로그램을 동작시킨다.** (2026-10-09 주인님 정의) 엔진(코드·로직·화면)은 우리가 만들고, 그 엔진을 돌리는 연료(AI API 키, 외부 서비스 계정, OAuth 앱)는 이용하는 회원 한 사람 한 사람이 본인 것을 연동해서 쓴다. 운영자(주인님)나 다른 회원의 키·계정으로 다른 회원이 대신 쓰이는 일은 어떤 경우에도 없다.

### 1-1. 사용 자격 (2026-10-09 주인님 정의)

**각 사용자는 현재 일반 사용자 등급 이상이고, 해당 프로그램에 대한 사용기간 권한이 있으면, 로그인한 뒤 그 프로그램을 사용할 수 있다.** 이 한 문장이 모든 프로그램의 접근 기준이다.

- 구체 판정 순서는 루트 `CLAUDE.md` 핵심 원칙 6번을 그대로 따른다: 정지 계정 차단 → 관리자 허용 → **FREE 배지 프로그램은 가입한 회원이면 허용** → 결제한 구독 → (최소 등급 미지정이면 허용) → **회원 등급 ≥ 프로그램 최소 등급(일반 이상) 그리고 관리자가 넣어준 사용기간(`user_program_access.expires_at`)이 남아 있음** → 그 외 차단.
- 로그인하지 않은 방문자는 사용할 수 없다(로그인 화면으로 보낸다). "비로그인 열람 허용"·"게스트"는 없다.
- 이 자격을 통과한 사용자도 **자동화에 쓰는 API 키·외부 계정은 반드시 본인 것**이다(위 규칙). 사용 자격이 있다고 운영자·타인의 키를 대신 쓰게 되는 것은 아니다.

## 2. 이 규칙이 요구하는 것 (반드시)

1. **로그인한 회원 본인으로만 동작한다.** 모든 화면·API·Server Action은 로그인 + 해당 프로그램 이용 권한을 확인한다. 비로그인 방문자는 로그인 화면으로 보낸다.
2. **API 키는 `user_api_keys`에서 `user_id = 로그인한 회원`인 행만** 쓴다. 본인 키가 없으면 `null`을 돌려주고, 호출부는 "API 키 등록이 필요합니다" 안내(설정 화면 이동)를 띄운다.
3. **외부 계정(Threads·Instagram·YouTube·네이버·카카오 등)은 회원별로 저장**한다(`user_id` + RLS). OAuth `state`에 회원 ID를 실어 콜백에서 세션과 대조한다.
4. **OAuth 앱(Client ID/Secret, App ID/Secret) 자체도 회원 본인이 만든 것**을 등록한다. 운영자가 만든 공용 앱을 여러 회원이 같이 쓰지 않는다(예외는 대상 플랫폼이 앱 심사 없이 모두 받아주는 것이 확실하고 주인님이 승인한 경우뿐).
5. **생성 데이터·수집 결과·개인 캐시를 포함한 회원 데이터는 회원별로 격리**한다(`user_id` + RLS owner-only). 서비스 키(관리자 클라이언트)를 쓸 때는 코드에서 `user_id`로 직접 한정하고, 클라이언트가 보낸 ID로 쓰기 전에는 그 행이 내 것인지 먼저 확인한다.
6. **API 키·토큰은 채팅·로그·문서·커밋에 적지 않는다.** 회원이 채팅에 키를 붙여 넣으면 노출된 것이므로 폐기·재발급을 안내하고, 에이전트는 그 키를 어디에도 입력·저장하지 않는다.

## 4. 시험(테스트)은 어떻게 하나

- **`buylifemall@gmail.com`은 유일한 관리자 계정**이고, **`buylifemall@naver.com`은 일반 회원과 같은 권한으로 시험하기 위한 테스트 계정**이다(2026-10-09 주인님 확인).
- 일반 회원 기능은 **테스트 계정으로 실제 로그인해서** 시험한다. "게스트"·"비로그인 허용"·"관리자 우회"로 시험하지 않는다. 시험 중 로그인이 이어지지 않으면(도메인이 달라 세션이 안 넘어가는 등) 우회를 넣지 말고 쿠키 도메인·리다이렉트 원인을 고친다.
- 테스트 계정도 **본인 키를 설정 화면에 등록해서** 쓴다(관리자 키·다른 회원 키를 빌려 쓰지 않는다).

2-1. **발송 방식** → ✅ 확정(2026-10-27 주인님): **수집 후 발송 여부는 회원 각자 책임**으로 하고, **회원 본인 PC·핸드폰에서 회원이 직접 발송**하는 형태로 설계해 위험을 분산한다(우리 서버가 대신 대량 발송하지 않음). 광고성 정보 사전 동의(정보통신망법 제50조)는 화면에 고지하고 실제 발송 책임은 회원에게 있음을 밝힌다.
3. **플랫폼 약관**: 네이버·인스타·유튜브·구글·카카오는 자동 수집·자동 발송을 약관으로 금지한다. 걸리면 그 기능을 쓴 **회원 계정이 정지**될 수 있다 → 회원에게 위험을 분명히 고지하고 속도·양을 낮춘다.
4. **횟수 상한·IP 변경** → ✅ 확정(2026-10-27 주인님): **기본은 플랫폼이 제재하지 않을 안정적인 리미트(하루·시간당 상한, 사람 같은 속도)**를 준다. **회원이 필요하면 VPN·IP 변경 서비스를 본인 책임으로 연동해 쓸 수 있게** 한다(선택, 끄면 안 씀). 계정은 회원 본인 계정만 쓰고 운영자·다른 회원 계정으로 대신 쓰지 않는다. 화면에 「IP 변경·대량 발송은 플랫폼 약관 위반·계정 제재 위험이 있으며 회원 책임」을 고지한다.
5. **카카오톡 개인 메신저 대량 발송(koms·B6)**: 카카오는 공식 발송 API를 개인 메신저용으로 주지 않아, 회원 PC의 카톡 앱을 사람처럼 조작하는 방식뿐이다. 받는 사람 사전 동의가 약한 개인 대화방·친구 대량 발송이라 **스팸·계정 영구 정지 위험이 수집형보다 크다.** → 발송은 회원 본인 기기·회원 직접·사전 동의 대상에게만, 안정적 리미트 안에서만, 책임 고지 뒤로 범위를 좁히는 방향을 권한다(주인님 결정). 숫자 조작·보안문자 우회는 포함하지 않는다.

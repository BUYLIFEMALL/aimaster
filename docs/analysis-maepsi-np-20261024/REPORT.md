## 1. 기능·로직

| 영역 | 동작 (근거 파일) |

## 5. 병합 vs 독립 — 판단

[비교 분석 매뉴얼](../PROGRAM_COMPARISON_ANALYSIS_GUIDE.md) §4-1(합칠 조건: 같은 일·같은 사용자·한 흐름 중 둘 이상)·§4-4(독립 조건) 기준.

| 기준 | 판정 |
|---|---|
| 같은 일 | ○ 네이버 일반 글 생성 → 편집기 입력 → 저장·발행 = 에이전트(묶음 A 기준 앱)와 같음 |
| 같은 사용자 | ○ 네이버 블로그 운영자 |
| 한 흐름 | ○ 주제 → 원고·이미지 → 입력 → 발행 |
| 독립 조건(입출력 고유·사용자 다름·동작 다름·합치면 복잡·카테고리 불일치) | 해당 없음 — 다른 점은 「데스크톱 + 붙여넣기」라는 **구현 방식**이지 결과물이 아님 |
| 블로그 통합 방향 | 2026-10-23 결정 8개 → 독립 4개(에이전트·SEO·키워드·티스토리). 새 독립 앱은 방향과 반대 |

**의견: 독립 프로그램으로 만들지 않고, 좋은 기능만 「네이버 블로그 에이전트」(묶음 A 기준)에 병합.** M1·M2·M3·M5는 바로 플랜 가능, M4는 플랫폼 원칙 결정 뒤.

## 6. 주인님 결정 (2026-10-24 확정)

- **붙여넣기 입력: (다) 회원이 고르는 빠른 입력 모드** · **간편 모드를 무료 입구로 사용(BLOG 정리 기반)** · **발행 방식: 사람이 직접 발행 / 자동 포스팅 회원 선택 + 지침 반영**. 플랜: [`naver-blog-agent/docs/PLAN_20261024_MAEPSI_E1_E4.md`](../../naver-blog-agent/docs/PLAN_20261024_MAEPSI_E1_E4.md). 아래는 결정 전 선택지 기록.

### 결정 전 선택지

1. **M4 붙여넣기 입력 허용 여부** — 플랫폼 지침 `docs/PLATFORM_PATTERNS.md` §20 ①「텍스트는 한 글자씩 무작위 간격 타이핑」과 충돌. 붙여넣기는 사람도 흔히 하는 동작이지만, 원칙을 바꾸는 일이라 주인님이 정해야 한다. 선택지: (가) 채택 안 함 (나) **표·이미지만** 붙여넣기(텍스트는 지금처럼 타이핑) (다) 회원이 고르는 「빠른 입력」 선택 모드(기본은 타이핑, 위험 안내). 추천: (나) — 표 서식 보존 문제(콘텐츠 제작 확장의 「표는 행별 텍스트」 한계)도 함께 풀림.
2. **M1 간편 모드를 BLOG(FREE) 입구 대체로 쓸지** — 묶음 A에서 남은 결정 「BLOG의 FREE 무료 입구 유지 여부」와 연결 가능: 에이전트 안 간편 모드를 무료 입구로 쓰면 BLOG를 이동 안내로 정리하기 쉬워짐(제안).
3. 원칙 §20 ④(발행은 사람이 누름)는 이미 에이전트·SEO 실제 자동 발행(주인님 승인)으로 바뀌어 있음 — 지침 문서 갱신 필요 여부.

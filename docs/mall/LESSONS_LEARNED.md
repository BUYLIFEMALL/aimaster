# AI 쇼핑몰 빌더 — 작업 과정 문제·교훈 모음

> 주인님 지시(2026-11-04): 「항상 작업과정과 문제 사항을 남겨 다음에 같은 반복 실수 안 하도록」.
> 이 몰 빌더(`labs/mall-builder`)를 이어 작업하는 모든 세션은 **작업 전에 이 문서를 읽고**, 작업 중 새 문제를 만나면 **같은 커밋에** 한 줄을 추가한다.
> 형식: 증상 → 원인 → 해결 → 다음부터. 모든 CLI 공통 교훈은 `docs/ERROR_LESSONS.md`에도 한 항목으로 올린다.

## 작업 전 점검 (매번)
- [ ] 이 문서와 `labs/mall-builder/README.md` 「남은 일」을 읽었다
- [ ] DB 변경은 **추가만**(add column·create table·create policy·create or replace function). `drop`·`revoke`·`delete` 문장을 지금 실행하는 적용은 하지 않는다
- [ ] DB 적용은 표·규칙과 함수를 **나눠** 보내고, 함수 묶음 맨 위에 「함수 정의만 바꾼다. 지금 지워지는 데이터는 없다」 설명 주석을 붙인다
- [ ] 화면 시험은 ego lite 작업 공간을 **이름**(`taskSpace("AI 쇼핑몰 빌더 시험")`)으로 연다
- [ ] 금액 계산을 바꾸면 `src/lib/pricing.ts`와 DB 주문 함수 `mall_builder_place_order`를 **둘 다** 바꾸고, 같은 숫자로 화면·DB 시험을 한다
- [ ] Lab 배포는 점검 묶음에서만. 배포 전 로컬 `npm run build`, 팀 빌드 중 0건 확인, 배포 뒤 결과는 `vercel inspect`로만 확인(다시 배포 금지)

| 11-04 | 외상 주문 함수(0014c)가 설명 주석을 붙였는데도 두 번 만료(두 번째는 주인님께 미리 알렸지만 자리 비움) | 함수 안 `delete`(장바구니 비우기) | **가장 확실한 해결 = DB 함수에서 지우기를 빼는 설계**: 장바구니 비우기는 주문 성공 뒤 서버 동작이 손님 권한으로 하고(손님은 자기 장바구니 줄 삭제 가능), 준비 중·숨김 줄은 지우지 않고 계산에서만 뺀다 → 바로 적용. 새 함수는 처음부터 이렇게 |
| 11-03 | 사업자등록증 업로드가 본인 폴더도 막힘 | 저장소 규칙 하위 질의에서 `name`이 손님 표의 손님 이름으로 읽힘 | `objects.name`으로 고침(`alter policy`). 다른 표를 읽는 규칙에서는 `objects.` 필수 |
| 11-03 | 운영자 겸 손님 계정의 구매 확정이 「운영자」로 기록 | 상태 함수가 운영자 쪽을 먼저 봄 | 본인 주문이고 손님에게 허용된 이동이면 손님으로(검사 순서 변경) |
| 11-03 | 시험 문장 실수로 결과 앞부분이 덮임 | `select … into r from (select r) x` | 결과 문자열은 `r := r || …`로만 이어 붙인다 |

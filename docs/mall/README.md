## 6. 이 계열에서 항상 지킬 것

1. **회원 본인 계정·본인 키(최상위 규칙)**: 몰 운영자의 결제(PG)·문자·알림톡·AI 키는 그 운영자 본인 것을 등록해 쓴다. 플랫폼(주인님) 키로 대신 결제·발송하지 않는다.
2. **몰 사이 데이터 완전 분리**: 모든 몰 데이터 표에 `store_id` + 보안 규칙(RLS). 서비스 키로 읽을 때도 코드에서 `store_id`로 거른다.
3. **손님 개인정보**: 주소·전화·사업자 서류는 그 몰 운영자와 손님 본인만. 플랫폼 관리자 화면에도 목록으로 노출하지 않는다(필요하면 건수만).
4. **금액은 서버가 다시 계산**: 장바구니·주문서·견적 금액은 화면 값을 믿지 않고 공통 가격 엔진으로 서버에서 다시 계산해 저장한다([ARCHITECTURE.md](ARCHITECTURE.md) §4).
5. **원본 권리**: 프로셀의 코드·스킨·아이콘·문구를 옮기지 않는다. 기능과 흐름만 참고한다(CLAUDE.md 핵심 원칙 21).
6. **Lab과 운영 분리**: Lab 작업 중에는 운영 DB(ref `esgxyikcnnvmlhygjkth`)·운영 사이트를 읽기만 한다.
7. **버전은 코어 + 모듈로**: 새 버전을 만들 때 코어를 복사해 갈라지지 않게, 모듈 켜기/끄기와 설정값으로 차이를 낸다. 코어를 꼭 바꿔야 하면 이 문서 4절에 결정을 남긴다.
8. **비용**: Lab 빌드·유료 API 호출은 사전 승인, 작업 끝에 비용 리포트.
9. **기능 하나씩 + 점검**: 어느 버전이든 기능 단위로 「구현 → 시험 → 내 PC 화면 확인 → 커밋·기록 → 보고」 후 멈추고 주인님 점검을 받은 뒤 다음 기능으로 간다(1차 기능 목록: [플랜](PLAN_20261103_MALL_BUILDER_V1.md) §3-1).

## 2. AI 기능 후보 (「AI 쇼핑몰 빌더」의 AI) — 모듈 `ai_assist`

모두 **몰 운영자 본인 AI 키**(공용 `user_api_keys`, 기본 제공자 Claude — 루트 CLAUDE.md 「기본 AI = Claude」)로 동작한다. 운영자(주인님) 키로 회원 요청을 처리하지 않는다. 모델은 `docs/AI_MODEL_CATALOG.md` 등급표에서 고른다.

| 기능 | 내용 | 우선 | 비고 |
|---|---|---|---|
| AI 상품 등록 도우미 | 사진·짧은 메모 → 상품명·요약·옵션 후보·검색 태그 | 높음 | 결과는 운영자가 확인 후 저장 |
| AI 첫 화면 자동 구성 | 업종·상품 목록 → 블록 배치 초안(띠 문구·쇼윈도 제목·순서) | 높음 | 블록 JSON을 만들어 draft에만 저장 |
| AI 상세페이지 | 기존 `shop-detail-page`(AI 상세페이지 자동화)로 보내 만든 결과를 `detail_html`로 가져오기 | 중 | 그 프로그램은 `ecommerce-image` 역할 — 연동 방식만 협의 |
| AI 문의 답변 초안 | 상품 문의·1:1 문의 답변 초안 | 중 | 2차 문의 기능 뒤 |
| AI 견적 회신 보조 | 등급가·구간 할인·재고를 보고 견적 단가 제안 | 중 | 최종 결정은 운영자 |
| AI 가격 점검 | 원가·배송비 대비 마진 경고 | 낮음 | `trending-product-finder` 마진 계산 참고 |

## 3. 기존 AIMaster 프로그램과 연계 후보

| 우리 프로그램 | 연계 | 방향 | 담당 |
|---|---|---|---|
| `trending-product-finder`(상품 소싱) | 관심 상품 → 「내 몰에 상품 초안으로 보내기」 | 소싱 → 몰 | `ecommerce-image` 협의 |
| `shop-detail-page`(상세페이지) | 상세 HTML·이미지 → 몰 상품 상세 | 상세 → 몰 | `ecommerce-image` 협의 |
| `shop-order-report`(주문 리포트) | 몰 주문 내보내기 → 매출·순이익 리포트 | 몰 → 리포트 | `ecommerce-image` 협의 |
| `seller-label-docs`(셀러 라벨) | 발송 전 주문 → 라벨 | 몰 → 라벨 | `ecommerce-image` 협의 |
| 마켓 등록·쿠팡 계열 | 몰 상품 → 마켓 등록 | 몰 → 마켓 | **쿠팡 담당 세션 몫**(이 역할 범위 밖) — 요청만 남긴다 |
| 인스타·쓰레드 포스팅 | 상품 홍보 글 자동 생성·게시 | 몰 → SNS | 각 담당 |

연계는 「파일 왕복 없이 넘기기」를 목표로 하되, 프로그램끼리 서로 코드를 부르지 않고 넘김 주소·공용 데이터로 연결한다(루트 공용 기준 코드 규칙).

## 4. 버전 계열 카탈로그

각 버전은 코어 + 켜는 모듈 + 추가 개발로 정의한다. 새 버전을 시작할 때 이 카드를 복사해 플랜에 붙인다.

### V-A 기본 B2C 쇼핑몰
| 항목 | 내용 |
|---|---|
| 대상 | 일반 소비자 대상 소규모 몰 운영자 |
| 켜는 모듈 | `bank_transfer`, `block_editor` (+2차 `card_pg`·`coupon_point`·`messaging`) |
| 추가 개발 | 없음(코어로 충족). 카드 결제가 사실상 필수 → 2차 `card_pg` 선행 |
| 선행 | v1 코어 |
| 메모 | v1에서 `b2b`·`quotes`·`credit`만 끄면 바로 나온다 |

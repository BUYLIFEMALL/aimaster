## 1. 무엇을 만드나
프로셀처럼 **회원 한 명이 자기 쇼핑몰 하나를 개설해 운영하는 빌더**. 주인님은 플랫폼 관리자, 회원은 몰 운영자, 각 몰의 소비자·사업자 고객은 손님이다(3층 구조, ARCHITECTURE §1).

- 몰마다 데이터 완전 분리(RLS). 몰 주소: Lab `dev-mall-builder.vercel.app/s/<몰주소>`.
- 디자인은 주인님이 나중에 줄 시안을 테마로 입힌다. 1차는 기능 위주의 깔끔한 기본 화면.

## 2. 1차 기능 범위

**플랫폼**
- 가입·로그인(Lab 공용 인증), 「내 쇼핑몰 만들기」(몰 이름·주소 입력, 예약어·중복 검사), 내 몰 목록, 플랫폼 관리자 몰 목록·정지/재개

**기본 쇼핑**
- 상품: 등록·수정, 1~3단 옵션 조합, 재고(없음/상품/옵션), 다중 카테고리, 과세·면세, 공개 상태
- 손님 화면: 첫 화면(블록), 카테고리 목록, 검색, 상품 상세
- 장바구니·주문서, 배송비 정책(무료/고정/조건부 무료, 제주·도서 추가)
- 주문 상태 흐름(입금대기→결제완료→배송준비→배송중→배송완료→구매확정, 취소·반품 요청)
- 결제: 무통장입금(운영자 계좌 표시, 입금자명, 운영자가 입금 확인)
- 손님 마이페이지: 내 주문·배송지·사업자 정보

**B2B(핵심)**
- 사업자 가입(사업자번호·상호·대표자·사업자등록증 파일) → 운영자 승인/반려 → 사업자 등급
- 등급별 가격(금액 지정 또는 할인율)
- 가격 비공개(로그인/승인 사업자에게만 가격·주문 버튼) · 사업자 전용 상품
- 최소 주문 수량·주문 단위·최대 수량
- 수량 구간 할인(프로셀 「대량구매 할인」과 같은 기능)
- 견적: 요청 → 운영자 회신(단가·유효기간) → 손님 승인 시 같은 금액으로 주문
- 외상(후불): 거래처별 한도, 한도 안에서만 주문, 외상 장부(사용·입금·조정)
- 세금계산서: 주문 때 발행 요청 기록(실제 발행 연동은 2차)

**첫 화면 블록 편집기(1차)**
- 블록: 띠 배너, 슬라이드 배너, 단일 배너, 상품 쇼윈도(직접 선택/카테고리/신상품, 열 수·개수), 글·HTML, 공지
- 추가·순서 올리기/내리기·숨기기·삭제·설정 변경, 미리보기 → 게시
- 머리글·바닥글은 「쇼핑몰 정보」 설정(전자상거래 표시 필수 칸)

**1차에서 하지 않음** → [로드맵](ROADMAP_AND_VARIANTS.md) 2차: 카드 결제, 쿠폰·포인트, 문자·알림톡, 통계, 리셀러, 소셜 로그인, 하위·개인 도메인, 입점, 세금계산서 실발행, 비회원 주문, 부계정 직원, AI 보조.

## 3. 구현 방식 — 기능 하나씩, 기능마다 주인님 점검 (2026-11-03 주인님 지시)

> 「한꺼번에 하려고 하지말고 구현은 하나씩 기능별로 구현해나갈수 있도록 해」, 「중간중간 점검할꺼야」

**기능 1개 = 작업 1번.** 기능마다 아래 순서를 끝까지 마치고 **멈춰서 보고**한다. 주인님이 점검(화면 확인·수정 요청)하고 「다음」이라고 하시면 다음 기능으로 넘어간다. 여러 기능을 섞어 한 번에 만들지 않는다.

1. 그 기능의 작은 설계(바뀌는 표·화면·API)를 [README.md](README.md) §5 작업 기록에 한 줄로 먼저 적는다.
2. 구현 — 그 기능에 필요한 표·화면·API만. 다음 기능을 미리 만들지 않는다.
3. 자동 시험(가격·상태 흐름처럼 계산이 있는 기능은 시험을 먼저 쓴다) + `npx tsc --noEmit`.
4. 내 PC(`npm run dev`)를 크롬 실제 창에 띄워 그 기능을 직접 눌러 확인(무료).
5. 커밋(경로 지정), 작업 기록·남은 일 갱신.
6. **보고하고 주인님 점검을 기다린다** — 보고에는 한 일, 확인한 화면(캡처), 확인 방법(주인님이 눌러 볼 순서), 알려진 한계를 적는다.

Lab 배포(빌드 비용)는 기능마다 하지 않고 아래 **점검 묶음(🚩)** 끝에서만 한다 — 총 4회로 승인 범위(3~5회) 안. 그 사이 점검은 내 PC 화면으로 한다.

### 3-2. 단계별 묶음 요약(참고)

| 단계 | 내용 | 완료 기준(검수) |
|---|---|---|
| 1 기반 | `node scripts/lab/new-lab.mjs mall-builder` 뼈대, 마이그레이션(몰·손님·등급·운영자 표 + RLS + `is_store_staff`), 몰 개설·내 몰 목록, 운영자 화면 틀, 현재 몰 찾기 | 계정 두 개로 각각 몰을 만들고 서로의 몰 관리 화면·데이터에 접근이 거부되는지 크롬 실제 화면 + SQL로 확인 |

| 6 배포 | 로컬 `npm run build` → `dev-mall-builder` 배포(Lab 주소를 dev 인증 허용 목록에 정확한 주소로 추가) → 크롬 실제 화면 검수 | PC·휴대폰 폭(375px), 오류 없음 |

시험 계정: Lab은 누구나 가입 가능 — 몰 운영자용·손님용 계정은 주인님이 직접 가입·로그인한다(비밀번호는 에이전트가 입력하지 않음).

| 몰 사이 데이터 섞임 | 모든 표 RLS + `is_store_staff` 공용 함수, 서비스 키 코드에도 `store_id` 조건, 1단계 검수에서 교차 접근 시험 |
| 금액 조작(화면 값 변조) | 주문·견적 금액은 서버에서 엔진으로 다시 계산 |

| 사업자등록증 파일 노출 | 비공개 버킷 + 서명 주소, 경로에 store_id |

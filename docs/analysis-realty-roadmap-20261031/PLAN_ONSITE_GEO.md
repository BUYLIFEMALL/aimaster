# 개발 플랜 — 위치 기반 임장 사진 관리 (2026-10-31)

작성: Claude Code(윈도우) `claude-win-20261029-statusbar` [역할: 미지정]. 구현 담당 제안: `realty`.
상태: **작업 대기 RQ-G. 담당 `realty`가 지금 작업을 마친 뒤 다음 작업으로 이어 간다(2026-10-31 주인님 지시).** 사전 검증 페이지 준비 완료, 휴대폰 시험 미실시. 구현은 사전 검증 결과 보고 뒤 시작한다. 대상: ① AIMaster 운영(DB ref `esgxyikcnnvmlhygjkth`).
근거: 주인님 「임장지에 가서 사진을 찍어 올리면 자동으로 주소가 등록되어 나중에 분류해서 관리」, 「지리,위치기반으로」, 「플랜 작성하고 사전 검증부터 진행해」.
관계: 작업 대기 RQ-B3(임장 모드)를 앞당기는 작업이다. 주소 리포트와 이어지지만 그 사전 검증에 의존하지 않는다.

## 1. 무엇을 만드나
현장에서 사진을 찍으면 좌표가 저장되고 주소가 자동으로 붙으며, 나중에 지도와 행정구역으로 분류·관리하는 기능.

## 2. 위치 원칙
- 원본은 좌표다. 주소는 좌표에서 만든 값이며 다시 계산할 수 있다.
- 좌표 출처를 함께 저장한다: 촬영 때 위치(정확도 m) / 사진 속 위치 정보 / 회원이 지도에서 확정.
- 회원이 핀을 확인·이동해야 「확정」이 된다. 자동 값은 「추정」으로 표시한다.
- 건물 외관만 보고 AI가 주소를 맞히는 방식은 쓰지 않는다.

## 3. 사전 검증 (비용 없음, 운영 코드 수정 없음)
저장소 밖 임시 폴더의 페이지를 내 PC에서 띄우고 임시 HTTPS 터널로 휴대폰에서 연다. 사진은 휴대폰 밖으로 보내지 않고, 주인님이 「결과 보내기」를 누른 측정값만 내 PC로 온다. 끝나면 터널·페이지·측정값을 지우고 결과만 이 폴더의 문서로 남긴다.

| 확인할 것 | 통과 기준 |
|---|---|
| 웹에서 위치 권한·좌표 받기(아이폰·안드로이드) | 야외에서 5회 중 5회, 정확도 중앙값 50m 이내 |
| 웹 카메라로 찍은 사진의 위치 정보 | 있음/없음 기록(없어도 통과, 방식 결정용) |
| 앨범에서 고른 사진의 위치 정보 | 있음/없음 기록. 없으면 「찍어 둔 사진 올리기」는 수동 핀으로 |
| 좌표 → 주소 | 표본에서 동까지 맞는 비율 기록(시험은 OpenStreetMap, 운영 후보 브이월드·카카오는 키 준비 뒤 별도 비교) |
| 지도 핀 옮기기 | 휴대폰에서 손가락으로 무리 없이 이동 |
| 같은 물건 묶기 반경 | 실측 오차로 50m가 적당한지 판단 |

아직 시험하지 않는 것: AI 글자 판독(유료 호출이라 위치 방식 결정 뒤 소량), 저장 용량.

### 이어받는 담당자 안내 (2026-10-31 기준)
- 페이지 원본: `prevalidation/server.mjs`, `prevalidation/index.html`(이 폴더). **저장소 밖 임시 폴더에 복사해 실행**하고 측정값 `results.jsonl`은 커밋하지 않는다. 실행 때마다 `token.txt`에 새 접속 코드가 생긴다.
- 내 PC 확인 완료: 페이지 열림, 코드 없는 접근 404, 결과 저장, 좌표 1건 주소 변환. 사진 위치 판독 코드는 실제 사진으로 돌려 보지 않았다.
- 막힌 점: 에이전트가 터널을 실행하면 권한 규칙에 막힌다(`npx cloudflared`, 설치된 `cloudflared` 모두). 우회하지 않는다. 주인님이 새 터미널에서 직접 실행하거나 Lab 배포(빌드 1회 승인)를 고른다. 요청함 「임장 사전 검증 휴대폰 연결 방법 선택」 확인.
- 직접 실행 명령(빈 설정 파일 `empty.yml`을 임시 폴더에 만들어 n8n 터널 설정을 읽지 않게 함): `cloudflared tunnel --config "<임시 폴더>\empty.yml" --no-autoupdate --url http://127.0.0.1:8765`. 나온 주소 뒤에 `/<접속 코드>`를 붙여 휴대폰에서 연다.
- 끝나면 터널·임시 폴더를 지우고 결과를 이 폴더 `PREVALIDATION_ONSITE_GEO.md`로 남긴 뒤 §3 기준으로 보고한다.

## 4. 기능 (1차)
| 영역 | 내용 |
|---|---|
| 촬영 | 연속 촬영, 촬영 순간 위치 저장, 줄인 사진 저장 |
| 주소 | 좌표 → 주소 자동, 핀 이동으로 확정, 층·호수·메모 입력 |
| 묶기 | 가까운 사진을 한 물건으로 제안, 나누기·합치기 |
| 지도 | 상태별 색 핀, 지도 범위 목록, 내 주변 500m·1km·3km |
| 분류 | 시·군·구 → 동 자동, 방문일·임장 일정, 유형·상태·별점·태그 |
| 동선 | 같은 날 방문 순서 표시(기본 끔) |

나중: AI 글자 판독, 주소 리포트 연결, 주변 시설, 지적도, 공유.

## 5. 위치·구조
- 위치: `real-estate-sales` 새 메뉴 「📍 임장 노트」로 시작한다(권한·로그인·지역 코드 재사용). 사진 저장·모바일 사용이 커지면 분리를 검토한다. 주인님이 다르게 정하면 따른다.
- DB 새 표(사전 승인): `onsite_properties`(좌표·주소·상태·유형), `onsite_photos`(물건·좌표 출처·정확도·경로). 모두 `user_id` + 본인 전용 RLS.
- 사진: Supabase Storage 비공개 버킷 회원별 경로, 서명 주소로만 표시, 긴 변 1600px 정도로 줄여 저장.
- 공유 금지, 보관 1년(`real-estate-sales` 지정 범위). 회원이 언제든 삭제.
- 지도·주소 API 키: 사전 검증 결과와 한도를 보고 정한다. 회원 수에 비례하는 호출이므로 기존 공공 키 예외를 그대로 쓰지 않는다.

# 부동산 카테고리 자동화 개발 플랜 (2026-10-31)

작성: Claude Code(윈도우) `claude-win-20261029-statusbar` [역할: 미지정]. 구현 담당 제안: `realty`.
상태: **플랜, 주인님 결정 대기.** 이 문서 작성으로 코드·DB·권한·배포는 바뀌지 않았다. 대상: ① AIMaster 운영(DB ref `esgxyikcnnvmlhygjkth`).
범위: 부동산만. 주인님 자료의 「주식 자동화」는 지시 범위 밖이라 다루지 않았다.

## 1. 결론

프로그램을 많이 늘리지 않는다. **기존 3개를 잇고, 빠진 일 두 가지만 새로 채운다.**

| 순서 | 할 일 | 위치 | 이유 |
|---|---|---|---|
| 1 | 진행 중인 상가·건물·토지 시세 비교 마무리, 신고가·거래량 표시, 부동산 3개 사이 이동 | 기존 프로그램 | 새 데이터 없이 바로 체감된다 |
| 2 | **주소 하나로 보는 부동산 리포트 + 임장 모드** | `real-estate-sales` 안 새 메뉴 | 공공 자료 호출 코드가 이미 있고, 지금 「이 물건 하나」를 평가하는 기능이 없다 |
| 3 | 지역 개발·정책 뉴스 레이더 | `real-estate-sales` 지역 분위기 확장 | 비슷한 기능이 있어 새 프로그램이 필요 없다 |
| 4 | **AI 중개사무소 고객관리**(새 프로그램 1개) | 새 폴더 | 사용자가 중개 실무자로 다르고, 고객 개인정보를 따로 격리해야 한다 |

## 4. 구현 묶음

### 0단계. 문서 바로잡기 (비용 없음)
§2의 늦은 문서를 고친다.

### A. 기존 프로그램 강화 (빌드 2~3회)
| ID | 내용 | 주의 |
|---|---|---|
| A1 | 상가: 2단계(시세 대비 %, 후보 점수)는 `realty` 세션이 커밋. 남은 3단계 수익률 계산·AI 요약(`commercial-land-trade-alert/docs/PLAN_20261031_NAVER_LISTINGS.md`) | 이미 승인된 플랜이다. 2단계 배포 여부는 그 세션 기록 기준 |
| A2 | 실거래: 「보유 자료 기준 최고가·최저가」, 지역별 거래량 증가 표시와 알림 | 수집 상한(지역·월 200줄) 때문에 빠지는 거래가 있을 수 있다. 「역대 신고가」라고 쓰지 않고 기간을 함께 표시한다 |
| A3 | 부동산 3개 프로그램 메뉴에 서로 이동 링크. 실거래 줄 → 호가 감시, 호가 → 실거래(일부 있음) | 프로그램끼리 호출하지 않고 링크만 쓴다 |
| A4 | R-ONE 상업용 임대동향으로 상가 임대료·공실률 참고값 추가 | [공공데이터포털 항목](https://www.data.go.kr/data/15134761/openapi.do) 설명까지만 확인. 실제 칸은 사전 검증 뒤 결정 |

### B. 주소 리포트 + 임장 모드 (`real-estate-sales` 새 메뉴 「📍 주소 리포트」, 빌드 3~4회)
```
주소·단지명 입력 또는 사진 → 주소 표준화·확인 → 공공 자료 조회 → 규칙 계산 리포트
                                        → (회원이 누를 때만) AI 총평 → 저장·비교·PDF
```
| ID | 내용 |
|---|---|
| B0 | 사전 검증: 아파트·빌라·오피스텔 표본 20건으로 주소 → 법정동 코드 → 필지 번호 → 실거래·대장·공시가 맞춤률 측정. **70% 미만이면 B1 범위를 주인님과 다시 정한다** |
| B1 | 리포트: 면적별 실거래 추이, 최근 거래 대비, 주변 대비, 공시가 비율, 전세가율, 사용승인일로 계산한 건물 나이, 주차, 용적률·건폐율, 용도지역. 칸마다 출처·기준일·표본 수, 자료가 없으면 「자료 없음」 |
| B2 | 내가 입력한 호가와 실거래 비교, AI 총평(회원 본인 키, 버튼으로만, 사실과 추정 구분), 저장·PDF |
| B3 | 임장 모드: 휴대폰 사진 → AI가 주소·단지명 추출 → 회원 확인, 현장 메모·사진·체크리스트, 여러 물건 비교 |
| B4 | 위험 점검: 전세가율, 사용승인 여부, 위반건축물 표시(대장 칸 확인 뒤). 권리 관계는 회원이 직접 받은 등기부 PDF를 올리면 AI가 근저당·압류 항목을 표시. 원본은 저장하지 않는다 |
| B5 | 2차: 상가·건물·토지(지번이 가려진 실거래 자료 한계를 먼저 검증), 지도 표시 |

기존 임장 플랜과 달라지는 점: 호가는 **회원 직접 입력이 기본**이다. 현장 휴대폰에는 크롬 확장이 없고, 호가는 서버에 저장하지 않는 원칙이라 서버가 대신 불러올 수 없다. PC에서는 호가 화면으로 가는 링크를 둔다.

### C. 지역 뉴스 레이더 (`real-estate-sales`, 빌드 1회)
관심 지역·단지 등록 → 회원 본인 네이버 검색 API 키로 뉴스·블로그 검색 → 새 문서만 → 개발·교통·학교·규제로 분류 → AI 요약(회원 키) → 매일 아침 알림. 원문 링크를 함께 보내고, 지역 분위기(Perplexity)는 키가 있는 회원의 선택 기능으로 둔다.

## 5. 규칙 점검

| 규칙 | 적용 |
|---|---|
| 본인 키·계정 | AI, 네이버 검색, SOLAPI는 회원 본인 것. 폴백 없음 |
| 공공 무료 키 | **기존 예외는 다른 프로그램·용도로 넓힐 수 없다.** 또 예약 수집과 달리 주소 리포트는 회원이 누를 때마다 호출해 호출량이 회원 수에 비례한다. 결정 3 참고 |
| 보관 | 리포트는 기존 지정(`real-estate-sales` 1년) 안. D의 고객 명부는 지정 없음 → 결정 4 |
| 제3자 개인정보 | D의 고객 정보는 수집 동의, 회원별 RLS, 공유 금지. 등기부 원본 미저장. 개인정보 기준은 이번 조사에서 확인하지 못해 구현 전 별도 점검 |
| 네이버 수집 | 기존 원칙 유지(회원 PC, 화면이 받은 응답만, 상한, 차단 시 멈춤). 수집 호가를 고객에게 자동 발송하지 않는다 |
| 투자 표현 | 참고용 고지, 수익 단정 금지. 「급매」 대신 「확인할 후보」와 근거 표시 |
| 광고 | [허위·과장 광고가 금지되고 인터넷 광고에 명시 항목이 있다는 보도](https://www.munhwa.com/article/11181566)가 있으나 입법 예고 기사이므로, D4 착수 전 현행 법령 원문을 대조한다 |

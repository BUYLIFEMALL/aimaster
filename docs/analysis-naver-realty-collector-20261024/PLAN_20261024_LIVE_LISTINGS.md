## 0. 주인님 지시 (절대 지시, 2026-10-24)
1. 「이 프로그램의 취지는 편하게 네이버에 올라오는 실시간 매물정보를 정리해서 받아보는 거야」
2. 「내가 접속하지 않고 특정 지역이나 키워드를 넣어놓으면 알아서 해당 페이지를 스크롤링해서 해당 자료를 파일로 받아보거나 텔레그램이나 이메일로 정리된 자료를 실시간으로 받아볼 수 있는 기능」
3. **「네이버 정책에 위반일 수 있는 부분이 있으니 우리는 플랫폼만 제공하고 실제 사용은 각 개개인 사용자의 로그인 정보를 사용하고, API도 각각 본인 것을 사용」**
4. **「서버에서는 직접 네이버로 트래픽이 안 되고 각 개개인의 PC나 핸드폰에서 진행되는 형태」 · 「우리 쪽에서 데이터가 조회되거나 스크롤링하면 안 된다」**
5. 「다각도로 어떻게 접근하는 게 좋을지 고민하고 플랜을 만들어줘」

→ 설계 원칙 3가지: **ⓐ 네이버 접속·조회·스크롤은 100% 회원 기기에서** ⓑ **우리 서버는 네이버에 요청 0건, 네이버 매물 데이터를 받지도 저장하지도 않음** ⓒ 로그인·텔레그램·이메일·AI 키는 모두 회원 본인 것.

| 안 | 내용 | 판단 |
|---|---|---|
| **① 기기에만 보관(추천)** | 수집·비교·엑셀 만들기·발송을 모두 회원 기기에서. 우리 서버에는 매물 데이터가 한 줄도 오지 않음 | 지시 4 「우리 쪽에서 데이터가 조회되면 안 된다」에 정확히 맞음 |

우리 서버가 다루는 것은 **회원 설정(감시 지역·조건·간격·전달 방법)·권한 확인·매뉴얼·설치 파일·수집 규칙 업데이트**뿐이다. 실거래 비교(우리 공공 데이터)는 기기가 우리 서버에서 받아 기기 안에서 합친다(네이버 데이터를 서버로 보내지 않음).

### 1-4. 네이버 정책·법 관점
- 수집이 회원 기기·회원 로그인으로 이뤄지므로 **운영자 서버·IP·계정은 네이버에 닿지 않는다**(2판의 가장 큰 위험 제거).
- 그래도 **자동으로 반복 조회한다는 사실은 남는다** — 회원 계정이 제한될 수 있고, 도구 제공자로서의 책임이 완전히 사라지는 것은 아니다. 그래서:
  - 처음 실행 때 회원 동의(「본인 계정으로 본인 책임하에 개인 참고용으로 사용, 재배포 금지」).
  - 사람이 보는 속도 수준으로 제한(§3). 차단·확인 화면이 나오면 **멈추고 회원에게 알림** — 우회하지 않는다(웹 크롤링 자동화 `web-crawler/AGENTS.md`의 차단 통지 원칙, 플랫폼 지침 `docs/PLATFORM_PATTERNS.md` §20).
  - 판매 전 법률 확인 권장(약관·데이터베이스 권리).

### 1-5. 유지보수 관점
- 네이버 화면·데이터 형식은 예고 없이 바뀐다 → **수집 규칙(어느 값을 어디서 읽는지)을 우리 서버의 작은 설정 파일로 내려보내** 확장·앱을 다시 설치하지 않고 고칠 수 있게 한다(설정만 내려보내고 데이터는 받지 않음).
- 기기에서 형식 검사가 실패하면 「수집 규칙 업데이트 필요」를 회원에게 표시하고, 관리자에게는 **오류 종류와 확장 버전만** 보고한다(매물 내용 없음).
- 수집·비교·전달 엔진은 **한 묶음의 자바스크립트**로 만들어 확장(1단계)과 PC 프로그램(2단계)이 같이 쓴다.

### 1-6. 사용 편의 관점
- 지역은 시·구·동을 고르면 끝(우리 `districts` 코드 재사용), 단지는 네이버 부동산에서 보고 있는 단지를 확장 버튼 하나로 추가.
- 첫 화면에 「🖥 내 PC 연결 상태 · 마지막 수집 시각 · 다음 수집 예정」과 「원클릭 다운로드 센터」(디자인 최상위 원칙 0).
- 「크롬을 켜 두면 알아서 수집해요 / 완전 무인은 PC 프로그램」을 매뉴얼 Step 1~4로 안내.

### 1-7. 비용 관점
- 운영자 인프라 비용 **없음**(서버는 설정·권한만) → 프리미엄이 아닌 **기본 프로그램**.
- 회원 부담 없음(텔레그램 무료, 이메일은 본인 계정, AI 요약은 선택·본인 키).

### 1-8. 함께 검토한 「자동 cURL 쿠키 추출기 Ver1.3」(EXT-RE-02)
- 같은 제작자의 짝 도구: 크롬 디버거로 네이버 부동산 요청을 잡아 **로그인 쿠키(HttpOnly 포함)를 cURL로 복사** → 원본 수집기에 붙여 넣게 한다. 외부 전송은 패스워드 확인뿐(쿠키는 제작자 서버로 안 보냄).
- 우리 방식에서는 **필요 없는 단계**다: 우리 확장·PC 프로그램은 회원 브라우저(프로필) 안에서 바로 동작하므로 쿠키를 꺼내 옮길 일이 없고, 쿠키를 복사하게 하는 것은 계정 탈취 위험이라 하지 않는다.
- **가져올 기법**: 「페이지가 스스로 불러온 목록 응답을 확장이 읽기」. 확장이 네이버 부동산 화면을 실제로 스크롤하면 페이지가 다음 목록을 불러오고, 확장은 그 응답(디버거 `Network.getResponseBody` 또는 페이지 안에서 응답 읽기)을 정리만 한다 — 별도 요청을 만들지 않아 회원이 손으로 볼 때와 같은 흐름. 수집 방법 1순위로 채택(주소를 직접 부르는 방식은 2순위, 0단계 사전 검증에서 비교).
- 권한은 **네이버 부동산 주소만**(원본은 모든 사이트), 디버거는 수집하는 동안만 붙였다 뗀다.

## 2. 추천 구조 (한눈에)

```
[회원 PC]  크롬 확장(1단계) / PC 프로그램(2단계)
   │ 회원 본인 네이버 로그인·본인 브라우저로 목록 읽기(스크롤·페이지)
   │ 이전 결과와 비교 → 신규·가격 변동·사라짐 → 엑셀 만들기
   ├─▶ 텔레그램(회원 본인 봇) : 요약 + 엑셀 파일 → 📱 휴대폰으로 받기
   ├─▶ 이메일(회원 본인 계정)
   └─▶ PC 폴더에 엑셀 저장
        ▲ 설정·권한·수집 규칙만 받음 (네이버 데이터는 보내지 않음)
[AIMaster 웹]  로그인·권한 · 감시 지역/조건/간격 설정 · 매뉴얼 · 다운로드 · 수집 규칙 파일
```

## 3. 요청 속도·안전 규칙 (구현 필수)
1. 페이지 사이 2~5초 무작위, 감시 대상 사이 10~30초, 감시 대상 최대 10개·대상당 최대 10페이지.
2. 수집 간격 최소 1시간(기본 하루 3회), 시작 시각 ±15분 무작위.
3. 로그인 확인·보안 문자·차단 응답 → 즉시 멈춤, 회원에게 텔레그램 알림 「네이버 확인 화면이 떠서 멈췄어요. 직접 한 번 열어 확인해 주세요」, 그날 자동 수집 중지.
4. 중개사 전화번호 등 개인 정보는 엑셀·알림에 넣지 않는다(상호까지).
5. 기기 안 보관도 30일 지나면 자동 정리(최상위 규칙과 같은 기준).
6. 회원 로그인 정보(비밀번호)는 프로그램이 받지 않는다 — 회원이 브라우저에서 직접 로그인한 상태를 그대로 쓴다.

## 10. 주인님 결정이 필요한 것
1. **추천 구조 승인**: 1단계 크롬 확장 → 2단계 PC 프로그램, 휴대폰은 받기(텔레그램), 데이터는 기기에만.
2. 별도 기본 프로그램(추천, 이름 §5 1안 「AI 부동산 매물 알림 자동화」) / 다른 이름.
3. 수집 간격 최소 1시간·감시 대상 10개 상한 승인.
4. 0단계 사전 검증(주인님 크롬에서 네이버 부동산 목록 1페이지 읽기) 진행 승인.
5. 구현 담당 지정(확장·PC 프로그램 경험 — 블로그 확장/데스크톱 앱 담당 쪽이 유리).

## 3. 수집 방식의 위험 (가장 중요)

| 위험 | 설명 |
|---|---|
| 비공식 주소 | 네이버 부동산은 매물 정보를 외부에 공개하는 **공식 API를 제공하지 않는다**. 이 주소는 네이버 화면이 내부적으로 쓰는 것이라 예고 없이 바뀌거나 막힐 수 있다 |
| 이용약관·자동 수집 | 네이버 이용약관은 허락 없는 자동화 수집을 제한한다. 쿠키·토큰을 복사해 반복 호출하는 방식은 차단·계정 제재 대상이 될 수 있다(**플랫폼 지침 §20 봇 탐지 회피 원칙과 정면 충돌** — 사람처럼 화면을 조작하는 것이 아니라 내부 주소를 직접 대량 호출) |
| 데이터베이스 권리 | 매물 정보는 네이버·제휴 중개사가 모은 데이터베이스다. 대량으로 복제해 재가공·제공하면 데이터베이스 제작자 권리·부정경쟁 문제로 다툼이 생길 수 있다(구체 판단은 법률 검토 필요 — 단정하지 않음) |
| 1분 반복 자동 실행 | 서버 부담·차단 위험을 키우는 동작 |
| 운영자 책임 | 우리 서버가 대신 수집하면 운영자 IP·계정이 직접 위험을 진다. 회원 쿠키를 받아 서버에서 쓰는 구조는 **회원 계정 정보를 운영자가 다루는 것**이라 최상위 규칙 취지(회원 본인 계정을 본인 환경에서)와도 맞지 않음 |

## 5. 병합 vs 독립 — 판단

- **독립 프로그램으로 만들지 않는다.** 이 수집기의 핵심 가치는 비공식 수집 방식 자체에 있어서 우리 플랫폼 원칙(§20, 회원 본인 계정·본인 환경)과 맞지 않는다.
- **`real-estate-sales`에 N1·N2만 넣는 것을 추천**(위험 0, 작은 수정). 「현재 매물」이 꼭 필요하면 N3를 주인님·법률 확인 뒤 별도 검토.

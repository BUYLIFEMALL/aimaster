### 4-3. 한글→영문 AI 변환 (선택 기능)

- 꺼져 있는 것이 기본이다. 꺼져 있으면 영문 프리셋 틀 + 영문 직접 입력으로 그린다(키 0개). 엔진 실행 파일이 ASCII만 읽으므로 한글이 섞인 줄은 「변환을 켜거나 영문으로 적어 주세요」로 막고, 그대로 보내지 않는다.
- 켜면 처음 한 번 동의 창: 「회원님이 등록한 ○○ 키로 유료 호출이 됩니다. 한 묶음(24줄)에 대략 ○원」. 그 뒤로는 묻지 않는다.
- **묶음 1회 호출**: 한 묶음의 줄을 한 번에 보낸다(줄마다 호출하지 않음). 재시도 0.
- **항목 ID로 짝을 맞춘다**: 웹이 줄마다 고정 항목 ID(짧은 무작위 값, 접수 ID와 별개)를 붙여 `[{ id, ko }]`로 보내고, 응답은 구조화 형식 `[{ id, en }]`로만 받는다. 서버가 아래를 모두 확인하고 하나라도 어긋나면 **한 줄도 쓰지 않고** 멈춰 알린다(일부만 쓰지 않음).
  - 응답 항목 수 = 보낸 항목 수, ID 집합이 정확히 같음(빠짐·중복·모르는 ID 없음)
  - 응답 순서가 보낸 순서와 같음(순서가 다르면 내용이 엇갈렸을 수 있어 실패로 본다)
  - `en`이 비어 있지 않고 ASCII만이며 길이 상한 안
- 짝은 위치가 아니라 **항목 ID로** 맺는다. 변환 결과는 「고급」에서 원문 옆에 나란히 보고 고칠 수 있다. 변환이 끝난 뒤에 접수 ID를 만들어 엔진에 넣는다.
- 서버 조건: 회원 본인 `user_api_keys` 키만. 없으면 등록 안내 창(운영자·다른 회원 키 폴백 없음). 프롬프트에 당해 연도 지침, 인물은 한국인 기본(핵심 원칙 3·8).
- 변환한 한글 원문·영문은 서버에 저장하지 않는다.

### 4-4. 엔진과 주고받는 것

| 동작 | 호출 | 지킬 것 |
|---|---|---|
| 연결 | `POST /pair` (코드, 있으면 `prevToken`) | 토큰은 브라우저에 **로그인 회원 번호별**로 보관. 회원이 바뀌면 그 회원 토큰이 없어 다시 짝짓는다 |
| 접수 | `POST /queue` (`kind: "art"`, 영문 설명, 구성, 크기, 시드, `clientRequestId`) | 항목마다 접수 ID를 먼저 만들어 기록한 뒤 보낸다. 응답을 못 받으면 **같은 ID로 다시 물어** 확인하고 새 ID로 다시 그리지 않는다. 내용이 다른데 같은 ID면 엔진이 409 |
| 상태 | `GET /queue` | 자기 범위 작업만 온다 |
| 결과 | `GET /image-art/<번호>` | PNG를 받아 저장 폴더에 쓰기(폴더 접근 허용 1회, 지원하지 않는 브라우저는 내려받기). 파일 이름에 접수 ID를 넣어 같은 항목을 두 번 저장하지 않는다 |
| 취소·지우기 | `POST /queue/<번호>/cancel` · `DELETE` | 남의 작업 번호는 404 |
| 대기열이 닫힘 | 503 | 「엔진 창에서 확인해 주세요」 안내, 자동 재시도 없음 |

엔진을 껐다 켜서 「중단됨」이 된 항목은 자동으로 다시 그리지 않고, 사용자가 고를 때만 새 접수 ID로 다시 넣는다.

**엔진 계약에서 확인한 것과 없는 것**(`e8e52b505`의 [`gateway.mjs`](../../free-music-studio/engine/src/gateway.mjs) `handleScopedQueue`·[`security.mjs`](../../free-music-studio/engine/src/security.mjs) `createScopedTokens`를 읽음):

| 필요한 동작 | 엔진에 있는가 | 웹에서 하는 방법 |
|---|---|---|
| 자기 범위 목록·접수·취소·지우기·결과 | 있음 | 그대로 사용 |
| 전체 일시정지·재개 | **없음**(새 범위 대기열에 멈춤·재개 주소가 없다) | 「모두 멈추기」 = 자기 범위의 대기·진행 작업을 하나씩 **취소**. 다시 시작은 사용자가 「멈춘 항목 다시 시작」을 눌렀을 때 새 접수 ID로 넣는다. 진짜 일시정지(그 자리에서 이어 그리기)는 엔진 변경이 필요해 P1-1에 넣지 않는다 |
| 연결 해제(토큰 폐기) | **없음**(폐기는 `prevToken`을 함께 보낸 다시 짝짓기 때만 일어난다) | 「연결 끊기」 = 먼저 자기 작업을 취소(선택)한 뒤 브라우저에서 토큰을 지운다. 엔진의 기록 파일에는 그 토큰이 남지만 값이 브라우저에서 사라져 쓸 수 없다. 화면에 「엔진 쪽 기록까지 지우려면 엔진 창에서」를 안내한다. 엔진 쪽 폐기 주소는 개선 제안으로 남긴다 |
| 회원 전환 때 격리 | 범위 번호로 격리(있음) | 토큰을 로그인 회원 번호별 키로 보관하고 자기 키만 읽는다. 다른 회원은 토큰이 없어 새로 짝짓고 새 범위를 받으므로 앞 회원의 목록·결과는 404다. 앞 회원이 남긴 진행 작업은 계속 돌며 **엔진 창에서만** 보이고 취소된다 |
| 로그아웃 | — | 토큰은 지우지 않는다(같은 회원이 다시 들어오면 이어 봄). 브라우저 작업 기록도 회원 번호별 |

한계(숨기지 않음): 회원별 토큰 보관은 같은 PC·같은 브라우저 프로필을 쓰는 사람끼리의 **화면상 구분**이지 보안 경계가 아니다. 그 PC의 주인은 엔진 창에서 모든 작업을 보고 취소할 수 있고(주인님 확정 설계), 브라우저 저장소를 직접 여는 사람까지 막지는 않는다.

### 4-5. 디자인

## 9. 미검증·한계

- 8GB 근거는 SUB PC 2장(모델마다 1장)이다. 두 모델 모두 여유가 수백 MB라 다른 프로그램이 그래픽 메모리를 더 쓰면 결과가 달라질 수 있다.
- 10~12GB 장비, 애플 실리콘 맥, CPU 전용은 시험하지 않았다.
- Q4 구성의 품질은 16쌍 소량 비교뿐이고 통과 판정 48장에는 들어 있지 않다.
- 품질 평가자는 주인님 한 분이다. 통과 판정에서 1장이 미선택이다.
- 폴더 저장(File System Access)은 크롬 계열에서만 된다. 다른 브라우저는 내려받기로 대신한다.
- 엔진에 일시정지·토큰 폐기 주소가 없다(4-4절). 「모두 멈추기」는 취소로 구현하고, 연결 끊기는 브라우저 쪽 삭제다.
- 0번 규칙 고지·저장공간 위젯 한 줄은 5-1과 8단계 배포 때 적용한다(지금은 폴더가 없다).

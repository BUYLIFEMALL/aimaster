# AI 무료 이미지 자동화 — P0 종합과 P1 구현 제안

2026-11-19 · IMG-20261119-P1-PROPOSAL · [역할: ecommerce-image] CC-ECOM-01(`claude-win-sdp`)

**상태** 제안 문서. 코드 구현·엔진 변경·설치·실기 추가·배포 0. Master 범위 확인 뒤 구현한다. 근거는 [P0 결과](P0_RESULTS.md) · [개발 플랜](PLAN.md)이며, 엔진 코드는 읽기만 했다.

## 1. P0 종합

### 1-1. 확정된 사실

| 항목 | 값 | 근거 |
|---|---|---|
| RTX 5080 · Q8 | 96/96 성공. 1장 전체 FLUX 약 8.3초, Z-Image 약 13.9초 | [P0 결과](P0_RESULTS.md) 4절 |
| RTX 5080 · Q4 | 16/16 성공. FLUX 약 6.0초, Z-Image 약 10.3초. 그래픽 메모리 최대 약 6.3GB·7.2GB | 10절 |
| 정비율 크기 | 1280×720·720×1280 4/4 성공, PNG 머리 크기 일치 | 9절 |
| 내장 그래픽(Arc, Vulkan) · Q4 | 1장씩 성공. FLUX 200초, Z-Image 499초 | 3절 |
| 고정 엔진의 크기 지정 | 실행 인자 `-W`·`-H`로 1024×1024 밖의 크기를 그린다 | 4·9절 |

### 1-2. 용도별 잠정 후보 (주인님 가림 평가, 평가자 1명)

| 용도 프리셋 | 잠정 후보 | 「그대로 쓸 수 있음」 (12장 중) | 비고 |
|---|---|---|---|
| 실사·블로그 | Z-Image Turbo | Z-Image 12 · FLUX 2 | 차이가 가장 큼 |
| 상품 배경 | FLUX.2 klein 4B | Z-Image 8 · FLUX 10 | Z-Image 「못 씀」 3장 |
| 썸네일 구도 | FLUX.2 klein 4B | Z-Image 9 · FLUX 11 | 차이 작음 |
| 일러스트 | FLUX.2 klein 4B | Z-Image 8 · FLUX 10 | 차이 작음 |
| 내장 그래픽·저사양 전체 | FLUX.2 klein 4B Q4_0 | — | 속도 근거(품질은 Q4 RTX 표본만) |

2차 평가에서 같은 그림의 판정이 1차와 달라진 사례가 있었다(8절·10절). 차이가 작은 세 분류는 **확정이 아니라 시작값**이며, 프리셋의 모델은 사용자가 바꿀 수 있게 둔다.

### 1-3. 양자화 잠정안

- Q4와 Q8의 「쓸 수 있는가」 판정은 16쌍 모두 같았다. 나란히 비교한 선호는 Q8 10 · Q4 3 · 비슷함 3.
- 잠정: 그래픽 메모리가 넉넉하면 Q8, 그보다 작으면 Q4. 기존 [로컬 이미지 실행기](../../free-music-studio/engine/src/imageArt.mjs)의 장치 추천(`localImageChoices`)을 그대로 쓰고 새 추천 규칙을 만들지 않는다.

### 1-4. 통과 기준 80%의 두 해석 (주인님 결정 대기, 출시 판단 보류)

| 해석 | Z-Image | FLUX | 용도별 후보로 나눴을 때 |
|---|---|---|---|
| 「그대로 쓸 수 있음」만 | 77.1% | 68.8% | 43/48 = 89.6% |
| 「손보면 쓸 수 있음」 포함 | 93.8% | 95.8% | 48/48 = 100% |

「용도별 후보」 값은 1-2의 후보대로 고른 48장(실사 12장은 Z-Image, 나머지 36장은 FLUX)을 다시 센 것이다.

### 1-5. 미검증 (지원 표기에서 분리)

- **8GB·12GB급 그래픽카드**: 실측 장비 없음. 16GB 카드의 사용량만 있다. 실기 전에는 「지원」으로 적지 않고 「RTX 5080 실측 / Arc 내장 1장 확인」만 적는다.
- **ERNIE-Image-Turbo 대조군**: 고정 릴리스 도움말에서 지원 표시를 찾지 못해 실행하지 않았다.
- 묶음 24장을 **엔진 대기열로** 돌릴 때의 동작(P0는 장마다 실행 파일을 따로 띄움), 취소·재시작 뒤 중복, 오프라인 생성, 참조 이미지 편집, Arc의 비율·묶음.
- 정비율은 모델·크기마다 1장.

## 2. 지금 구조에서 P1이 닿는 곳

읽기만 한 현재 코드 기준이다.

| 파일 | 지금 동작 | P1에서 필요한 변경 | 기존 사용자 영향 |
|---|---|---|---|
| [`imageArt.mjs`](../../free-music-studio/engine/src/imageArt.mjs) `render` | `-W 1024 -H 1024` 고정, 시드는 `task.seed`가 정수면 그 값·없으면 무작위, 결과에 모델·시드·시간 | `task.width`·`task.height`(허용 목록 안의 값만) 받기. 없으면 1024×1024 | 없음 — 값을 안 보내는 기존 호출은 지금과 같은 인자 |

| [`gateway.mjs`](../../free-music-studio/engine/src/gateway.mjs) | `imageOnly = origin === IMAGE_SITE` 한 곳 비교 | 「그림 전용 출처 집합」으로 비교 | 없음 — 기존 출처는 같은 분기 |
| [`queue.mjs`](../../free-music-studio/engine/src/queue.mjs) | 대기·진행 합계 상한 50, 한 번에 한 작업, 재시작 때 진행 중 → 중단, 완료 30일 보관 | **변경 없음**(24장은 상한 안). 중복 접수 방지는 웹에서 접수 ID로 | 없음 |

## 3. 호환과 되돌리기

- **옛 엔진 + 새 웹**: 옛 엔진은 허용 목록에 없는 출처의 요청을 버전 조회까지 모두 403으로 거절한다(`gateway.mjs`의 출처 검사가 모든 주소 앞에 있다). 브라우저에서는 이 응답이 「엔진이 꺼져 있음」과 구별되지 않으므로, 새 웹은 연결 실패 때 「엔진을 켜 주세요. 켜져 있다면 새 버전으로 올려 주세요」와 내려받기 안내를 함께 보여 준다. 크기 값을 보내도 옛 엔진이 조용히 1024로 그리는 일은 연결 자체가 안 되므로 생기지 않는다. 연결된 뒤에는 응답의 엔진 버전으로 최소 버전을 다시 확인한다.
- **새 엔진 + 기존 웹 2곳**: 요청 형식이 같아 지금과 같은 결과다. 크기 기본값·출처 분기가 그대로인지를 완료 조건에 넣는다.
- **되돌리기**: 엔진은 이전 설치판(0.8.5)으로 다시 설치하면 된다. 모델 폴더·대기열 파일 형식을 바꾸지 않으므로 내려 깔아도 자료가 깨지지 않는다. 웹은 새 프로그램 하나라 배포 중단·이전 배포로 되돌리기로 끝난다. DB 변경이 없어 되돌릴 자료가 없다.
- **모델 파일**: 기존 `ImageModels` 구조와 고정 해시를 그대로 쓴다. 이미 받은 회원은 다시 받지 않는다.

## 4. 최소 첫 단계 (P1-1)

가장 작은 범위로 「용도를 고르고 여러 장을 맡기면 내 PC가 그려서 폴더에 모아 준다」까지만 만든다.

1. **엔진**: `render`에 허용 크기 받기(1024×1024 · 1280×720 · 720×1280 세 가지만), 새 출처 등록, 그림 전용 출처 집합.
2. **웹(새 프로그램)**: 시작하기(엔진 연결·모델 준비 확인) → 만들기(용도 프리셋 4개, 비율 3개, 설명 여러 줄, 장수) → 일괄 시작 → 작업 기록(진행·실패 원인·결과 받기).
3. 프리셋이 모델을 고른다(1-2의 후보). 사용자가 바꿀 수 있다. 프롬프트는 영문 프리셋 틀 + 사용자가 고칠 수 있는 칸(한글 자유 입력의 자동 번역은 이 단계에 넣지 않는다 — 엔진이 ASCII만 읽는다).
4. 저장: 엔진이 그린 PNG를 웹이 받아 사용자가 고른 폴더에 저장(브라우저 폴더 접근 허용 1회) 또는 내려받기. 서버 업로드 0.

P1-1에 넣지 않는 것: 예약 실행, 폴더 감시, 참조 편집, 한글 문구 합성, ZIP·형식 변환, 메인 사이트 등록·요금, 로컬 번역 모델.

자동화 조건(목표): 처음 설정 3단계 · 매 작업 시작 1회 · 실행 중 조작 0회 · 연결 승인 1회 · 유료 호출 동의 0회.

## 5. 완료 조건 (P1-1)

| 구분 | 조건 |
|---|---|
| 기존 호환 | 새 엔진에서 무료음악의 앨범 그림 1장과 이미지 스튜디오 「내 PC 그림」 1장이 변경 전과 같은 크기·흐름으로 나온다. 엔진 기존 시험이 모두 통과한다 |
| 크기 | 세 크기 각각 저장된 PNG 머리 크기가 요청과 같다. 허용 목록 밖의 크기는 접수에서 거절한다 |
| 묶음 | 24장 두 묶음에서 설명 안 되는 실패 0. 새로고침·탭 닫기 뒤에도 엔진이 계속 그리고 다시 열면 이어서 보인다 |
| 중복 | 같은 접수를 두 번 눌러도 한 번만 들어간다. 저장된 항목을 다시 실행해도 같은 파일이 두 번 생기지 않는다 |
| 중단 | 엔진을 껐다 켜면 진행 중이던 항목이 「중단됨」으로 보이고, 자동으로 다시 그리지 않는다 |
| 격리 | 다른 출처·다른 회원 토큰으로는 작업·결과를 볼 수 없다 |
| 비용 | 생성 경로에서 외부 AI 호출 0(네트워크 기록으로 확인), API 키 입력 화면 없음 |
| 고지 | 새 폴더에 `NOTICE`·`public/ai.txt`·`public/robots.txt`, `apply-source-notice --check` 통과 |

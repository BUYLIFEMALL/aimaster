## 1. 기능 (화면에 있는 것)

1. 「리포트 기간」 선택(이번 달·지난 달·최근 3개월·최근 6개월), 「리포트 형식」 선택(종합·마켓별 상세·상품별 상세)
2. 「📊 리포트 생성」 버튼 → 요약 카드 5개(총 매출·총 주문·객단가·반품/교환·정상처리율)
3. 마켓별 매출 막대 그래프(9개 마켓)
4. 일별 매출 추이 막대 그래프(30일)
5. 상세 매출 표(마켓·매출·주문수·객단가·반품·비중, 매출 큰 순)
6. 「📥 PDF 다운로드」 → 새 창에 표만 넣고 브라우저 인쇄 창 띄우기

## 2. 입력·처리·출력 상세

### 2-1. 입력
- **파일 업로드 없음**(`<input type="file">`·`FileReader`·엑셀 라이브러리 없음). 엑셀/CSV 형식·열 이름이라는 개념 자체가 없다.
- **마켓 연동 없음**(어떤 오픈마켓 API·주문 수집도 호출하지 않음).
- 데이터는 코드 안 고정 배열 1개: 마켓 9곳(스마트스토어·쿠팡·G마켓·옥션·11번가·위메프·티몬·인터파크·롯데온) × {매출, 주문수, 반품수, 색}. 위메프·티몬은 현재 정상 영업 여부부터 확인이 필요한 마켓인데 그대로 들어 있다.
- 「기간」「형식」 선택값은 **코드 어디에서도 읽지 않는다** — 무엇을 골라도 결과가 같다.

### 2-2. 처리(집계 기준)
| 항목 | 실제 동작 |
|---|---|
| 일별 | 총매출 ÷ 30 × (0.6~1.4 **무작위 배수**) — 누를 때마다 그래프가 바뀜. 실제 날짜 데이터 아님 |
| 주별·월별 | **없음**(설명 문구에만 있음) |
| 상품별 | **없음**(「상품별 상세」 선택지만 있음) |
| 마켓별 | 고정 숫자 합계·비중(%)·객단가(매출÷주문) |
| 정상처리율 | 1 − 반품수÷주문수 |
| 순이익·수수료·광고비·원가 | **전혀 없음** — 매출(거래액)만 다룸 |

### 2-3. 출력
- 화면 카드·막대 그래프(라이브러리 없이 `div` 높이로 그림)·표.
- PDF: 별도 PDF 생성이 아니라 표 HTML을 새 창에 쓰고 `print()` 호출 → 사용자가 인쇄 창에서 「PDF로 저장」을 골라야 함. 그래프·요약 카드는 PDF에 안 들어감.
- 엑셀·CSV 내보내기 없음, 저장·이력 없음.

### 2-4. AI
- **사용하지 않음.** 모델 호출·키 입력란·서버 호출 모두 없다(첫 화면 설명의 「AI 기반 데이터 분석」 문구와 다름).

## 6. 우리에게 없는 것·가져올 것·하지 않을 것

**우리에게 없는 것**
- 오픈마켓별 판매 실적(매출·주문·반품·객단가·비중)을 한 화면에 모은 리포트
- 반품률·정상처리율 같은 판매 후 운영 지표

**가져올 것(기능 아이디어만)**
1. 「마켓별 판매 실적 리포트」 화면 구성: 요약 카드 5개 → 마켓 비교 → 기간 추이 → 표
2. 실제로 만들려면 원본에 없는 부분을 우리 부품으로 채운다:
   - 입력: 각 마켓 판매자센터에서 받은 **주문·정산 엑셀 업로드**(스마트스토어·쿠팡 등 마켓별 열 이름 매핑 프리셋) — 읽기는 `file-merge`의 엑셀 읽기 부품 재사용, 브라우저 안 처리(서버 업로드 없이)
   - 순이익: `trending-product-finder/lib/margin.ts` `calcMargin` 계산식을 판매 실적에 적용(원가·수수료·배송·광고비 → 실제 순이익)
   - 기간: 일·주·월 실제 날짜 집계, 상품별 상위/하위
   - 출력: 엑셀·CSV 내보내기 + 화면 그래프 포함 PDF
   - (선택) AI 요약: 본인 키로 「이번 달 무엇이 늘고 줄었는지」 한 단락
3. 마켓 공식 API 자동 수집(스마트스토어 커머스 API·쿠팡 Wing Open API)은 회원 본인 판매자 키 연동이 필요해 2단계 후보로만 둔다(최상위 규칙: 본인 계정·본인 키).

**하지 않을 것**
- 고정·무작위 숫자로 「분석 결과」처럼 보이는 시연 화면(회원 오해·신뢰 문제)
- 동작하지 않는 선택지(기간·형식) 노출
- 브라우저 안 고정 비밀번호로 유료 기능을 잠그는 방식
- 원본 코드·문구 복사

### 8-3. 저장·요금·로그인
- 서버 저장 없음, 브라우저 저장(`localStorage`·`sessionStorage`)도 없음 — 새로고침하면 다른 주문 35건이 나온다.
- 로그인·계정 확인 코드 없음. 첫 화면 카드 「✨ 즉시 실행 가능」(무료, 잠금 대상 아님). 카드 설명은 「마켓별 주문 통합관리·배송추적·매출분석·CSV 엑셀 내보내기」로 실제 동작과 다르다.

### 8-4. 매출 리포트와 데이터를 공유하는가
- **공유하지 않는다.** 두 페이지 모두 각자 코드 안에서 데이터를 만들고, 공용 저장소·서버·주소 매개변수 전달이 없다.
- 서로 숫자도 맞지 않는다: 매출 리포트는 9개 마켓 고정 숫자(위메프·티몬·인터파크 포함, 총매출 약 7,180만 원), 주문 대시보드는 6개 마켓 무작위 35건(수백만 원대). 같은 「마켓별 매출」을 두 화면이 다르게 보여 준다.

### 8-5. 우리와의 관계·판단
- 우리에게도 **실제 주문·배송·반품·정산을 모아 보는 화면은 없다**(§5 표와 같음). 가져올 것은 화면 구성 아이디어뿐: 상태별 요약 카드 → 상태 필터 주문 목록 → 배송 단계 막대 → 마켓별 집계 → CSV 내보내기.
- 실제로 만들려면 원본에 없는 ① 데이터 입력(마켓 판매자센터 주문 엑셀 업로드 프리셋, 2단계로 회원 본인 판매자 API 키 연동) ② 정산(수수료·정산 예정액 — `calcMargin` 계산식 재사용) ③ 송장·택배 조회 ④ 회원별 저장·30일 정리를 새로 설계해야 한다.
- **판단: 원본 코드·화면은 개발 대상에서 제외(아이디어 참고만).** §6의 「마켓별 판매 실적 리포트」와 **한 프로그램으로 묶어** 「주문 엑셀 1번 올리면 → 주문·배송·반품 현황 + 마켓별 매출·순이익 리포트」로 설계하는 편이 맞다. 넣을 곳은 §7과 같이 쇼핑몰 묶음(1순위로 재조정 권장 — 주문·배송·정산은 「무엇을 팔지」인 `trending-product-finder` 범위를 크게 벗어남) 또는 `trending-product-finder` 확장.

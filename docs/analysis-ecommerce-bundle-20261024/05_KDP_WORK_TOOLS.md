## 1. 템플릿 캔버스 (`/template/`)

- **하는 일**: 공통 캔버스 크기를 정하고 최대 10페이지에 사진·텍스트·도형·손글씨를 배치하는 **자유 편집 캔버스**(상세페이지·썸네일 「틀 모음」이 아니라 빈 캔버스 + 크기 프리셋). 객체별 서식·애니메이션(시작 지연·효과 시간), 묶음 편집, 레이어 순서, 페이지 복제.
- **크기 프리셋(내장 데이터)**: 기본(1280×720, 800×800, SNS 1080×1080) · 프레젠테이션(1920×1080, 1024×768) · 카드뉴스(1080×1080, 1080×1350) · 웹 포스터(1260×891, 891×1260) · **상세페이지(860×3000)** 등. 즉 「상세페이지 860px 폭」 규격을 프리셋으로만 제공하고, 섹션 틀·문구 틀은 없다.
- **출력**: 선택 페이지를 PNG·JPG·WebP **긴 이미지 한 장**, 페이지별 ZIP, PDF(pdf-lib), GIF(`gif-worker`), 영상 WebM(`MediaRecorder`, vp9/vp8) 또는 브라우저가 되면 MP4(`video/mp4;codecs=avc1.42E01E`). 페이지당 0.5~10초, 전체 최대 60초. 음성 없음.
- **처리 방식**: 전부 브라우저(Canvas + 작업자). 프로젝트 저장·자동 복구 없음(탭을 닫으면 사라짐).
- **장점**: 상세페이지 이미지를 손으로 이어 붙여 한 장/ZIP/PDF/움짤로 뽑는 가벼운 편집기. **단점**: AI·틀·문구 생성 없음, 저장 없음, 페이지마다 크기 다르게 불가.

## 2. A4 라벨메이트 (`/labelmate/`)

- **정체**: tools 사이트 페이지는 **외부 앱을 `iframe`으로 끼워 넣은 껍데기**다(`https://kdp-labelmate.dupal-license-service.workers.dev/`, Cloudflare Workers에 올린 Next.js 계열 앱, 본체 `page-BJAyXJrI.js` 1.35MB). tools 쪽 묶음은 「A4 라벨만 인쇄」 버튼이 `window.print()`를 부르는 225바이트뿐.
- **택배 송장·상품 라벨 계열인가**: **A4 라벨지 인쇄용**이다. 택배사 송장(운송장 번호 발급·택배사 연동)은 **없다**. 주소 라벨·상품명 라벨·이름표·바코드/QR 라벨·**식품 한글표시사항 라벨**(제품명·식품유형·내용량·원재료·알레르기 유발물질 강조·제조원·소비기한·보관방법·포장재질·「부정·불량식품 신고 1399」, 99×68mm 예시 내장)·소비기한/보관방법 체크 라벨 예시가 들어 있다.
- **내장 데이터**: 라벨 규격 **25종**(1칸~84칸, CD 라벨, 원형 12·20칸) + **폼텍 대응 코드**(3108 → 14칸 99×38mm 등, 「LS-3108」로도 검색). 페이지에 「폼텍 공식 프로그램이 아니며 3108 공식 규격은 99.1×38.1mm라 칸 수만 보고 같다고 판단하면 안 된다」는 주의문.
- **기능**: 글자·이미지·도형·1D/2D 바코드 배치(라이브러리 **bwip-js** 흔적 — code128·EAN-13·QR·DataMatrix·PDF417, GS1 Digital Link 예시 주소), **엑셀(.xlsx) 업로드·셀 범위 붙여넣기로 칸마다 다른 내용 채우기**(SheetJS 계열 흔적), 캡처 붙여넣기, 여러 칸 선택, **시작 칸 지정(쓰다 남은 라벨지)**, 인쇄 위치 보정, `queryLocalFonts`(내 PC 글꼴 사용), `localStorage` 2곳(설정 기억으로 추정).
- **처리 방식·통신**: 본체 안 `fetch()` 11건은 모두 bwip-js 내부 명령 이름이고 네트워크 호출이 아니다. 외부 주소는 쿠팡 단축 링크(라벨지 상품 추천)와 폼텍 공식 사이트 링크뿐. 인쇄는 브라우저 인쇄창(PDF 저장도 인쇄창으로).
- **장점**: 쇼핑몰 출고 현장의 「상품명·바코드·식품표시 라벨」을 엑셀로 대량 인쇄 — 우리에게 없는 영역. **단점**: 데스크톱 Chrome·Edge 전용, 송장·택배사 연동 없음, 앱 도메인 이름에 「license-service」가 있어 향후 유료 라이선스 전환 가능성(추정).

## 4. 사진 모자이크 (`/mosaic/`)

- **하는 일**: 여러 사진(붙여넣기·파일)에 네모·원형 영역을 지정해 **픽셀·블러·랜덤 픽셀** 가림, 강도·여백 조절, **얼굴 자동 감지**(불러올 때 자동 적용 선택 가능), 워터마크 추가, 사진별 작업 유지, JPG·PNG·**ZIP**(`KDP_모자이크.zip`) 저장. 저장할 때 촬영·위치·작성자 메타정보(EXIF 등) 제거.
- **라이브러리**: **MediaPipe Tasks Vision**(`vision_bundle` 135KB, `/vendor/vision` 작업 파일, 모델 `/vendor/blaze_face_short_range.tflite`, 최소 신뢰도 0.4). 모델·WASM은 자기 사이트 `/vendor/`에서 받는다.
- **처리 방식**: 브라우저 안(서버 전송 없음).
- **평가**: 상품 후기·주문 화면·택배 사진 공유 전 「개인정보 가리기」에 유용. 페이지 스스로 「낮은 강도 블러는 알아볼 수 있다」고 경고.

## 5. 배경 제거·바꾸기 (`/background/`)

- **하는 일**: 자동 배경 제거(누끼) → 투명·단색·그라데이션·내 사진으로 배경 교체, **지우기·복원 브러시**로 경계 보정, PNG(투명)·JPG 저장, 메타정보 제거.
- **모델**: **U²-Net 경량판 `u2netp.onnx`**(입력 1×3×320×320) + **ONNX Runtime Web**(`ort-wasm-simd-threaded.mjs`, 실행 장치 `wasm`). 첫 실행 때 약 16MB를 받는다고 화면에 안내. 작업자(`background-worker.js`)에서 계산.
- **처리 방식**: 브라우저 안. 다중 스레드 WASM을 위해 교차 출처 격리 안내 주소(web.dev) 흔적.
- **평가**: 320px 입력의 경량 모델이라 머리카락·투명 물체 경계가 약하다(페이지도 수동 점검 권장). 무료·무제한이 장점.

## 6. 사진 분할 (`/split/`)

- **하는 일**: 사진 한 장을 **2·4·8·16조각**으로 나누고 배치를 고른 뒤 **분할선을 끌거나 슬라이더로 조절**(선끼리 교차 불가), 작은 사진은 먼저 확대, 조각별 또는 ZIP 저장(PNG·JPEG), 메타정보 제거.
- **처리 방식**: 브라우저 Canvas.
- **평가**: 「긴 안내 이미지를 게시물 여러 장으로」「상품 상세 사진 4분할」 용도. 우리 상세페이지 섹션별 860px ZIP이 이미 「자동 분할」을 한다.

## 7. 웹페이지 전체 캡처 (`/capture/`)

- **하는 일**: 캡처할 웹페이지에서 확장 아이콘을 누르면 **자동 세로 스크롤 → 화면을 이어 붙여** PNG·JPG·PDF·ZIP 저장. 결과에서 「사이트에서 편집」을 누르면 tools 사이트로 가져와 자르기·텍스트·모자이크 편집. 긴 캡처는 브라우저 저장 한도에 맞춰 여러 장으로 나눔. 내부 스크롤·가로 넘침 미지원.
- **브라우저 확장 사용 — 코드로 확인**: 사이트가 `/downloads/kdp-fullpage-capture-1.0.4.zip`을 내려주고 **개발자 모드로 직접 설치**(스토어 미등록). manifest V3, 권한 **`activeTab`·`scripting`만**, 연결 스크립트(`bridge.js`)는 `tools.kdpmkt.com/capture/*`(한·영·중)에만 붙는다. 캡처는 `chrome.tabs.captureVisibleTab` + `chrome.scripting.executeScript`(스크롤), 합치기·PDF는 확장 안(pdf-lib). 확장 페이지 보안 정책 `connect-src 'self' data:` → **외부 서버 전송 불가 구조**. 확장 안 `fetch`는 캡처한 데이터 주소를 Blob으로 바꾸는 용도. 보관은 확장 기기 내 임시 저장소, 24시간 지난 자료 정리.
- **서버 캡처**: 없음(페이지 FAQ 「일반 홈페이지가 다른 사이트를 임의로 스크롤할 수는 없다」, URL만 넣는 서버 캡처 없음).
- **평가**: 경쟁 상품 상세페이지 통째 보관·벤치마킹에 쓰기 좋다. 단 페이지가 「직접 보관하거나 이용 권한이 있는 페이지」로 범위를 한정해 둔 점을 우리도 따라야 한다.

## 8. 제미나이 영상 워터마크 제거 (`/video-watermark-remove/`)

- **하는 일**: 짧은 영상 한 개에서 **눈에 보이는 작은 고정 표시**(제미나이 생성 영상의 마크)를 **보라색 사각형으로 직접 지정**하고, **초록색 사각형으로 비슷한 배경을 골라** 그 무늬로 메운다(경계 강도·적용 시간 지정). 단색 배경은 FFmpeg `delogo`(주변 보간)도 선택. 현재 위치부터 **최대 3초 실제 MP4 미리보기** 후 전체 길이 MP4 저장.
- **처리 방식 — 코드로 확인**: **ffmpeg.wasm 0.12.10**(`/vendor/ffmpeg-0.12.10/ffmpeg-core.js`, 작업자 `video-restore-worker.js`, 첫 사용 약 10MB). 명령 흔적 `delogo=x=${x}:y=${y}:w=${w}:h=${h}:show=0:enable='<시간>'`, `-c:v`·`-crf`·`-preset`·`-c:a`·`-b:a`·`-movflags`·`-copyts` → **H.264/AAC MP4 재인코딩**. WebCodecs·ONNX 인페인팅·생성형 AI는 **쓰지 않는다**(페이지에도 「생성형 AI 인페인팅·움직이는 물체 추적은 하지 않음」). 서버 업로드 없음.
- **지원 한도(코드 값)**: **60초 · 100MB(`100*1024*1024`) · 1920×1080 화소(`maxPixels:1920*1080`) · 60 FPS 이하**, 최소 영역 4px, PC Chrome·Edge.
- **스스로 둔 안전장치**: 화면 문구 「직접 소유하거나 수정 권한이 있는 영상만 사용하세요. 타인의 저작권·출처 표시를 무단으로 제거하거나 편집 사실을 숨기는 용도로 사용하지 마세요.」 · 보이지 않는 **SynthID는 제거하지 않음**(FAQ) · 자동 감지 없음(사람이 직접 지정).
- **권리 위험 평가(중요)**:
  - **남의 영상 워터마크·로고 제거 = 고위험.** 저작권법상 「권리관리정보」(저작자·출처 표시)를 고의로 지우는 행위 자체가 문제될 수 있고(한국 저작권법 제104조의3 권리관리정보 제거 금지 취지, 미국 DMCA §1202), 플랫폼 약관 위반·도용 영상 재판매의 수단이 된다. 「주의 문구 + 사용자 책임」만으로는 우리 플랫폼 운영자 위험이 사라지지 않는다.
  - **AI 생성 표시(제미나이 마크) 제거**: 생성자가 자기 영상에서 지우는 것은 서비스 약관 문제(구글 생성 AI 이용 정책상 AI 출처 표시 유지 권고)와 「AI 생성 사실을 숨기는」 문제가 겹친다. 한국 AI 기본법(2026년 시행)의 생성형 AI 결과물 표시 의무는 사업자 의무지만, 표시 제거 도구를 우리가 제공하면 취지에 반한다는 비판을 받을 수 있다.
  - **의견: 우리 플랫폼에 넣는다면 「내 영상의 내 로고·내 자막·내 날짜 표시 지우기」로 범위를 좁혀야 한다.** ① 이름·문구에서 「워터마크 제거」「제미나이 마크 제거」를 쓰지 않고 「내 영상 일부 지우기」로 ② 사용 전 「이 영상의 권리자이며 지우는 표시가 제3자 저작권·출처·AI 생성 표시가 아님」 확인 체크(기록 저장) ③ 특정 서비스 마크 위치·모양 자동 감지 프리셋은 만들지 않음 ④ 결과물에 편집 사실 메타 표시 유지. AI 생성 표시 제거 용도는 **넣지 않는다**.

## 9. 파일명 일괄 변경 (`/rename/`)

- **규칙 종류**: **공통 이름 + 순번** 한 가지(시작 번호·번호 자릿수 지정, `localeCompare` 정렬 + 목록 순서 직접 조정). 찾아 바꾸기·날짜·원래 이름 유지·확장자 변경 같은 규칙은 없다.
- **출력**: 새 이름으로 된 파일들을 **ZIP 하나로 다운로드**(원본 파일 이름·내용·메타정보는 그대로 — 파일 이름만 바꾼 사본).
- **처리 방식**: 브라우저 안(묶음 5KB + ZIP 작업자).
- **쇼핑몰 상품 사진 정리 관점**: 「상품코드_01.jpg ~ _12.jpg」처럼 오픈마켓 등록용 이름을 맞출 때 쓸모가 있다. 다만 **상품별로 묶어 여러 이름을 한 번에** 하거나 엑셀(상품코드 목록)과 연결하는 기능은 없어 SKU가 많은 셀러에게는 부족하다.

## 10. 화면녹화 → GIF (`/record/`)

- **하는 일**: PC Chrome·Edge에서 공유 화면(화면·창·탭) 선택 → 미리보기에서 **영역 지정** → 문자·로고 워터마크 → 카운트다운(0·3·5초) → **최대 15초** 녹화 → GIF 저장. 출력 긴 변 640·480·320px, 5·10·15 FPS.
- **처리 방식 — 코드로 확인**: `navigator.mediaDevices.getDisplayMedia`(보안 연결 필요)로 화면을 받고 프레임을 Canvas로 그려 **GIF 작업자(`gif-worker.js`, gifenc 계열 `GIFEncoder`)로 바로 GIF 인코딩**. 이 도구는 `MediaRecorder`(영상 파일)를 쓰지 않으며 **마이크·음성 녹음도 없다**(`getUserMedia` 흔적 없음). 서버 전송 없음, 메타정보 제거.
- **용도 평가**: 상세페이지 「사용법 GIF」(앱 연동 상품, 소프트웨어 상품, 조작 화면), 고객 응대용 설명 GIF에 적합. 실물 상품 사용법 영상(카메라 촬영)은 대상이 아니다.

## 11. PDF 변환·관리 (`/pdf-tools/`) + PDF → Word (`/pdf/`)

- **실제 기능(코드 메뉴 값)**: ① 사진 → PDF 만들기(JPG·PNG·WebP **최대 30장**, 투명은 흰색) ② PDF → 이미지(PNG·JPG, 72·108·144dpi, 여러 페이지 ZIP) ③ **PDF 병합**(여러 문서 페이지를 골라 순서대로) ④ **PDF 분할**(한 장씩·몇 장씩 묶기·선택 추출) ⑤ PDF → Word(텍스트 추출 DOCX 또는 페이지 이미지 DOCX) ⑥ PDF → PPT(페이지 이미지 슬라이드) ⑦ PDF → Excel(단순 표 추정 추출, 저장 전 행·열 수정). 페이지 미리보기·선택·순서·회전. `/pdf/`는 ⑤만 따로 떼어 놓은 페이지(30MB 이하 1개).
- **없는 것**: **PDF 압축 없음**, OCR 없음, Word·Excel·PPT → PDF 없음, 암호·서명·양식 채우기 없음(서명은 별도 도구 — 다른 작업자 분석 범위).
- **라이브러리**: **pdf.js**(`/vendor/pdf/pdf.worker.min.mjs`, cmaps·standard_fonts·iccs·wasm 자기 사이트 제공) 읽기·그리기, **pdf-lib**(`copyPages`) 병합·분할·만들기, **docx** 계열 라이브러리(`Document`·`Paragraph`, JSZip 포함 419KB 묶음) Word 생성, 자체 OOXML 조립(`presentationml`·`spreadsheetml`) PPT·Excel.
- **처리 방식**: 전부 브라우저(「KDP 서버에 업로드하지 않는다」 FAQ와 코드 일치).
- **쇼핑몰 업무 관점**: 사업자등록증·통신판매업 신고증·통장 사본 사진을 **한 PDF로 묶기**(입점 서류 제출), 견적서·계약서 병합, 카탈로그 PDF에서 필요한 페이지만 추출·이미지로 뽑아 상세페이지 재료로 쓰기에 적합. 압축이 없어 「용량 제한 있는 입점 서류 업로드」에는 한계.

## 12. QR 코드 생성 (`/qr/`)

- **생성 옵션(코드 값)**: URL·텍스트 입력(최대 1,200자) · QR 색상 · 점 스타일(사각형·둥근 사각형·원형) · 모서리 표시(사각형·둥근 사각형) · 저장 형식(PNG·JPG·SVG 벡터) · 저장 크기. 오류 정정 수준 **H 고정**. **색 대비 검사**(밝기 대비 4.5 미만이면 「더 어두운 색을 선택」 오류).
- **없는 것**: **로고 넣기 없음**(안내문에 「로고를 줄이세요」 문구만 있고 코드에 로고 삽입 없음), **대량 생성 없음**, **추적용 단축 주소·스캔 통계 없음**(FAQ 「저장 후 목적지를 바꾸는 동적 QR 서비스는 아니다」 — 정적 QR).
- **라이브러리·처리**: node-qrcode 계열(QR 행렬 생성) + 자체 SVG 그리기. 브라우저 안, 외부 통신 없음.
- **쇼핑몰 업무 관점**: 포장 박스·전단·매장 POP에 스토어·리뷰 이벤트 주소를 넣는 용도로 충분히 쓸 수 있으나, **「어떤 전단에서 몇 명이 들어왔는지」(추적)와 로고 QR은 안 된다**. 오프라인 → 스토어 연결 성과 측정이 필요한 셀러에게는 부족.

## 14. 가져올 것·하지 않을 것

### 가져올 것(기능만, 우리 코드로 새로 만듦)
1. **A4 라벨 인쇄**: 라벨 규격표(칸 수·배열·한 칸 mm, 폼텍 등 대응 코드는 「참고」로만 표기), 엑셀 셀 → 칸 채우기, 시작 칸 지정, 인쇄 위치 보정, 실제 크기 인쇄 안내, 1D/2D 바코드(bwip-js MIT), **식품 한글표시사항 라벨 틀**(우리 상세페이지의 상품 정보와 연결 가능). 규격 치수는 각 라벨지 제조사의 공개 규격을 직접 확인해 만든다(상대 표를 그대로 옮기지 않음).
2. **브라우저 무료 누끼**: 공개 모델(U²-Net 계열 Apache-2.0 등)을 ONNX Runtime Web으로 돌려 키 없이 배경 제거 → 이미 있는 `browser-free-erase`(LaMa·PP-OCR, 작업자·Cache API·WebGPU→WASM) 구조에 「배경 제거」 작업 하나를 추가하는 방식이 자연스럽다. 브러시 보정 포함.
3. **얼굴·개인정보 자동 모자이크**(MediaPipe BlazeFace Apache-2.0) + **저장 시 EXIF 제거**: 후기·주문 캡처 공유용.
4. **PDF 병합·분할·사진→PDF·PDF→이미지**(pdf-lib MIT·pdf.js Apache-2.0): 입점 서류 묶기·카탈로그 페이지 추출.
5. **파일명 일괄 변경 + ZIP**: 기존 공용 `store-zip` 재사용. 우리는 한 걸음 더 — **상품코드 목록(엑셀)과 연결한 상품별 이름 규칙**.
6. **QR 생성**: 정적 QR + 대비 검사 + SVG. 확장 아이디어로 **로고 QR·여러 개 일괄·회원 본인 단축 주소/스캔 집계**(추적은 개인정보·비용 검토 필요).
7. **화면녹화 → GIF**: `video-to-gif`의 GIF 엔진에 「화면 녹화 입력」을 붙이고 「🛍 상세페이지로」 보내기 재사용.
8. **원칙 차용**: 「서버 업로드 없음」을 코드로 지키는 방식(확장 CSP `connect-src 'self'`, 모델을 자기 도메인에서 제공)과 화면의 권리 안내 문구(「직접 소유하거나 권한이 있는 것만」).

### 하지 않을 것
- **남의 영상·이미지 워터마크·로고·AI 생성 표시 제거**(제미나이 마크 프리셋 포함) — 넣는다면 「내 영상의 내 표시 지우기」로만(8절 의견).
- **쿠팡 파트너스 제휴 배너를 회원 작업 화면에 넣는 수익 모델** — 우리 회원 서비스 화면 원칙과 맞지 않음.
- **라벨메이트처럼 다른 도메인 앱을 iframe으로 끼워 넣는 구조** — 우리는 서브프로젝트 폴더 + 자기 도메인 원칙.
- **템플릿 캔버스 전체 재현**(10페이지 자유 편집기 + 애니메이션 + 영상 출력) — 범위가 크고 `shop-detail-page`·`banana-canvas`와 겹친다. 필요한 조각(긴 이미지 이어 붙이기·GIF/MP4 출력)만 검토.
- **블로그 본문 정리 단독 도구** — 우리 블로그 묶음이 이미 상위 기능이다.
- **스토어 미등록 개발자 모드 확장 배포**를 기본 방식으로 삼는 것 — 우리 확장 운영 규칙(핵심 원칙 10)대로 하되, 캡처 확장을 만든다면 권한을 `activeTab`·`scripting` 수준으로 최소화.

## 15. 판단 제안(기존 프로그램 병합 위치 vs 쇼핑몰 묶음 vs 제외)

| 도구 | 제안 | 이유 |
|---|---|---|
| A4 라벨메이트 | **쇼핑몰 묶음(신규 「쇼핑몰 출고·라벨」 도구)** | 우리에게 전혀 없는 영역이고 출고 현장 업무. 상품 정보(상세페이지·식품표시)와 연결하면 차별화. 가장 가치 높음 |
| 파일명 일괄 변경 | **쇼핑몰 묶음**(상품 사진 정리 도구 안 한 기능) | 상품 등록 준비 잡무. 엑셀 상품코드 연결로 확장 |
| QR 코드 생성 | **쇼핑몰 묶음**(라벨 도구와 같은 화면 — 라벨에 QR 넣기) | 포장·전단·매장 → 스토어·리뷰 이벤트. 추적은 2단계 검토 |
| PDF 변환·관리 | **쇼핑몰 묶음** 또는 `file-merge` 확장(「엑셀·텍스트 합치기」에 PDF 합치기·나누기 추가) | `file-merge`가 「합치고 나누는」 브라우저 도구라 성격이 같다. 입점 서류 묶기는 쇼핑몰 묶음 안내로 연결 |
| 배경 제거·바꾸기 | **`banana-canvas` 병합**(「🧽 무료 지우기(내 PC)」 옆 「무료 누끼(내 PC)」) + `shop-detail-page` 사진 준비 단계에서 호출 | 공용 `browser-free-erase`에 작업 추가 → 사본으로 전파(공용 기준 코드 규칙) |
| 사진 모자이크 | **`banana-canvas` 병합**(얼굴 자동 감지·여러 장·EXIF 제거) | 같은 브라우저 이미지 편집 계열 |
| 사진 분할 | **`banana-canvas` 병합**(작은 기능) | 우리 상세페이지 ZIP과 겹치므로 별도 프로그램 불필요 |
| 화면녹화 → GIF | **`video-to-gif` 병합**(입력 방식 「화면 녹화」 추가) | GIF 엔진·상세페이지로 보내기 재사용 |
| 웹페이지 전체 캡처 | **보류(낮음)** — 필요하면 쇼핑몰 묶음의 「경쟁 상세페이지 보관」 확장 기능으로 | 확장 배포·검수 비용 대비 수요 확인 필요. 권리 안내 필수 |
| 영상 워터마크 제거 | **제외(현재)** · 넣는다면 `video-to-gif`/`ai-video-studio`에 「내 영상 일부 지우기」로 범위를 좁혀 주인님 승인 후 | 권리 위험 높음(8절). 사진 지우기(`browser-free-erase`)는 이미 있음 |
| 템플릿 캔버스 | **제외**(조각만 `shop-detail-page` 편집기 보강 후보) | 기존 상세페이지·템플릿 프로그램과 겹침 |
| 블로그 본문 정리 | **제외**(블로그 묶음에 「모바일 짧은 줄 미리보기」 아이디어만 등록 후보) | 우리 블로그 흐름의 하위 조각 |

- 비용: 위 「가져올 것」은 모두 브라우저 안 무료 처리라 회원 키·운영자 서버 비용이 없다(모델·WASM 파일 제공 용량·트래픽만 — 배경 제거 모델 수~십수 MB, ffmpeg 약 10MB).
- 다음 단계(주인님 결정 필요): ① 쇼핑몰 묶음에 「라벨·QR·파일명·PDF」 잡무 도구를 넣을지 ② 무료 누끼·모자이크를 `banana-canvas`에 넣을지 ③ 영상 지우기 기능을 「내 영상」 범위로라도 둘지.

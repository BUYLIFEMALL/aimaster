## 1. 정체

- **이름**: Mato Helper(마토헬퍼). 내부 원본 이름은 `google-blog-auto`(추정 근거: 기능 지도 문서, 키워드 저장소의 `GOOGLE_BLOG_AUTO_PATH` 설정).
- **형태**: Windows·macOS **설치형 데스크톱 앱**. 서명되지 않은 실행 파일이라 설치 안내가 「백신 일시 종료」「Windows 보안 경고 → 그래도 실행」「macOS 격리 속성 해제 명령」을 요구한다. 본체는 파이썬 앱으로 보인다(기능 지도의 `1_프로그램/app.py`, `local_agent/*.py`, `_naver_main.py`).
- **용도**: 소개 페이지 제목은 「Google Blogger용 블로그 자동화 도구」, 설치 안내 제목은 「구글 블로그 자동화 프로그램」. 실제로는 기능 지도상 **네이버 블로그 탭(「N 블로그」)이 큰 비중**을 차지한다(구글 블로그스팟 + 네이버 블로그 둘 다).
- **배포·업데이트**: GitHub 릴리스 저장소에 2026-04-06 `v1.0.0` → 2026-09-01 `v1.1.6.118`까지 **208개 릴리스**(하루 1개 넘는 속도, 2026-09-01 이후 멈춤). 릴리스마다 `install_guide.txt` + Mac `dmg` + Windows `zip`. 릴리스 설명은 글자가 깨진 같은 문구(인코딩 오류, 「자동 빌드 릴리스」류로 추정)라 **변경 기록이 없다.** 설치 파일 누적 다운로드 약 9,500회.
- **자동 업데이트**: 실행 때 새 버전을 알리고 「예」를 누르면 **자동 다운로드·설치·재실행**, API 키·인증 정보 유지(설치 안내 원문 기준. 내려받는 주소·서명 확인 방식은 미확인).
- **운영 주체**: 개인 GitHub 계정 `we-insub`. 문의 메일이 페이지마다 다르다(약관·방침 `insubwe@gmail.com`, 소개 `dnlstjq@gmail.com`·`dnlstjq@naver.com`). 같은 계정에 `matohelper-bridge-releases`, `matohelper_0711` 저장소도 있다.

## 2. 기능

### 2-1. 공개 소개 페이지 기준(구글 블로그스팟)
- AI로 블로그 글 생성·서식 → 회원 본인 Google Blogger 계정에 바로 발행
- 이미지를 회원 본인 Google Drive에 올려 그 주소로 교체
- 여러 글 **일괄 발행**, Blogger **임시저장(초안) 관리**
- 「유튜브 라이브 수업 지원」: 유튜브 구독 여부를 확인해 수강 인증·진도 확인(= 수업용 도구)
- 구글 권한: Blogger API(글 작성·발행), Drive `drive.file`(앱이 만든 파일만), YouTube `youtube.readonly`(구독 확인)

### 2-2. 기능 지도 문서 기준(네이버 블로그 탭, 추정)
- 탭 구성: 글작성·설정·글변환규칙·글변환·AI 글 작성·역순작성·역순사진 + 관리자 탭
- 번호별 네이버 Chrome 프로필(`naver_1~3`)에 회원이 직접 로그인 → 프로필 순환 배정 → **Playwright로 스마트에디터에 한 줄씩 타이핑**(지연 시간 설정, 템플릿 「제목을입력해주세요1:」 사용) → 임시저장 또는 공개 발행, 완료 건 건너뛰기·재개
- 네이버 검색 상위 글·지정 URL의 **원문과 이미지를 내려받아** 이를 바탕으로 AI 원고 생성, 블로그별 문체 분석, 링크 카드 넣기
- 「역순작성」: 네이버 글쓰기 화면에서 복사한 원문을 사실 유지·표현 재구성으로 다시 쓰기
- 글 생성 모델·이미지 생성 모델 선택, 사용자 정의 모델 목록, 로컬 AI CLI 모델 탐색(→ 회원 본인 AI 키·로컬 모델 사용으로 추정)
- 작업은 클라우드 작업 대기열(`cf_worker_client` — Cloudflare Worker로 추정)과 PC의 `local_agent`가 나눠 처리(키워드 저장소가 이 대기열에 `oneq_generate_upload` 작업을 넣는다)

### 2-3. 쇼핑몰·이커머스 기능
- 본체 자체의 쇼핑몰 운영 기능(주문·상품 등록·매출)은 **없다**(공개 자료 기준).
- 다만 같은 개발자의 블로그 도구(§7-2)에는 **제휴 마케팅용 상품 글**(마이리얼트립 상품 「CPA 링크」 원큐 작업, 네이버 쇼핑·스마트스토어 상품 페이지 → 판매자 이미지 수집 → 상품 글 작성·발행)이 있어, Mato Helper 계열의 실제 쓰임새는 **블로그 제휴·홍보 글 대량 제작**에 가깝다. 쇼핑몰 업무 단계로는 「판매·홍보(외부 유입)」.

## 3. 키·요금·위험

| 항목 | 내용 |
|---|---|
| 필요한 계정 | 구글 계정(앱 로그인 겸 Blogger·Drive·YouTube 권한), 네이버 계정(번호별 Chrome 프로필에 직접 로그인) |
| 필요한 키 | AI 키는 본체 미확인(모델 선택·「API 키 유지」 문구로 회원 본인 키 추정). 구글 OAuth 앱은 **운영자 앱 하나를 모든 이용자가 공유**(소개 페이지가 구글 앱 심사용 설명으로 작성됨) |
| 요금 | 약관상 **무료**(「서비스는 무료로 제공되며 보증하지 않음」). 단, **일일 사용 횟수 한도**와 **유튜브 구독 시 보너스 포인트**가 있다(개인정보처리방침) |
| 서버로 가는 데이터 | 방침상 구글 이메일·계정 ID·닉네임·**기기 식별자(HWID)**·유튜브 채널 ID·이용 기록을 운영자 Supabase에 저장, Cloudflare가 「API 보안 중계」. 소개 페이지의 「개인정보를 수집·저장하지 않는다」와 **서로 모순** |

**위험**
1. **서명 안 된 실행 파일 + 백신 끄기 안내** — 악성 여부를 이용자가 판단할 수 없고, 자동 업데이트가 이후 무엇을 내려받는지 확인할 방법이 없다(변경 기록 없음).
2. **네이버 화면 자동 조작**: 공식 글쓰기 API가 없는 네이버에 Playwright로 타이핑·발행 → 계정 제재 위험(우리 PLATFORM_PATTERNS §20과 같은 영역). 소스 쪽에서 「세션 전용 쿠키를 영구 저장」하는 처리도 확인됨(§7-2).
3. **남의 글·이미지 재사용**: 검색 상위 글 원문·이미지를 내려받아 원고 재료로 쓰고, 이미지 메타데이터를 지우고 다시 저장하는 「사진세탁」 흐름이 있다(저작권 위험).
4. **가짜 체험 후기**: 마이리얼트립 상품 글의 `simulated_review` 모드는 「가상의 1인칭 체험 평가」를 **독자에게 고지하지 않고** 쓰는 방식이다(문서상 공개 발행은 막고 임시저장만 허용). 국내 추천·보증 표시 규정 위반 소지.
5. 개인 개발자 무보증·약관상 「사전 고지 없이 서비스 종료 가능」, 9월 이후 업데이트 멈춤, 라이선스 없음.

## 5. 가져올 것·하지 않을 것

**가져올 것(기능 아이디어만)**
1. **구글 블로그스팟(Blogger) 발행** — 우리 블로그 지침의 대상 플랫폼인데 담당 프로그램이 없다. Blogger는 **공식 API가 있으므로** 화면 조작 없이 회원 본인 구글 OAuth(회원별 앱 등록 원칙, 공용 연동 `member_platform_accounts`)로 「초안 저장 / 즉시 발행 / 예약 발행(Blogger API `published` 시각)」 세 방식을 모두 구현할 수 있다. 확장 없이 서버에서 처리 가능한 유일한 플랫폼이라 블로그 최상위 지침 ③④(세 방식·결과 기록)를 맞추기 쉽다.
2. **네이버 계정 여러 개 순환 배정**(원고 N개 → 계정 1·2·3 순서) — 확장의 「계정별 발행 대상」 선택으로 검토할 후보(제재 위험 평가 먼저).
3. **이미지 EXIF·GPS 제거 후 재저장** — 회원 **본인** 사진의 위치정보 노출 방지용으로만(세탁 용도 아님).

**하지 않을 것**
- 서명 안 된 설치 파일 배포, 「백신 끄기」 안내
- 남의 글 원문·이미지를 내려받아 재사용, 이미지 세탁
- 고지 없는 가상 1인칭 후기
- 운영자 공용 OAuth 앱·운영자 DB에 기기 ID 저장
- 세션 쿠키를 임의로 영구화하는 처리

## 6. 판단 제안

- **프로그램 자체: 제외(설치·병합 대상 아님).** 핵심 가치가 우리 블로그 묶음과 겹치고, 위험(서명·자동 조작·저작권·가짜 후기)이 커서 들일 이유가 없다.
- **아이디어 1건 채택 후보: 「구글 블로그스팟 발행」**을 블로그 담당 세션에 넘긴다. 넣을 곳은 새 프로그램보다 기존 기준 프로그램(`naver-blog-agent` 또는 `tistory-auto-blog`의 발행 대상 추가)이 낫다 — 원고 생성 엔진은 같고 발행 단계만 다르기 때문이다. 결정은 블로그 담당·주인님.
- **쇼핑몰 묶음에는 넣지 않는다**(쇼핑몰 운영 기능이 없음). 단 §7-2의 「상품 페이지 → 제휴 홍보 글」 흐름은 쇼핑몰 묶음의 「판매 홍보」 단계 참고로만 적는다.
- **설치 파일 정적 분석이 필요한가 — 의견: 지금은 필요 없다.** 채택 후보(블로그스팟 발행)는 구글 공식 API 문서로 설계하면 되고, 본체 코드에서 가져올 것이 없다. 다만 ① 주인님이 이 프로그램을 수강생에게 권하거나 PC에 설치할지 판단해야 하거나 ② 자동 업데이트·서버 통신의 안전성을 확인해야 할 때에만, 주인님 허락을 받고 **실행 없이** REA로 정적 분석(파이썬 묶음 풀기 → 서버 주소·업데이트 주소·서명 확인 여부·키 저장 위치)을 하는 것을 권한다.

## 7. 같은 계정의 다른 저장소 (we-insub 도구들)

### 7-1. `2026-06-22Naver_keyword` — 네이버 뉴스 급상승 키워드 화면
| 항목 | 내용 |
|---|---|
| 형태 | 로컬 웹앱. 파이썬 표준 서버 `app.py`(2,178줄)가 `127.0.0.1:8000`에서 화면(`static/`)을 띄움. 파일 12개 |

| 출력 | 「지금 이슈 후보」 표(10~100개), 관련 뉴스·원문 보기. 공식 실시간 검색어가 아니라 **추정**임을 README에 명시 |

| 쇼핑몰 관련 | **없음**(뉴스 이슈 키워드) |

| 판단 | 코드 제외. 「뉴스 급증 키워드 점수(기사 수·출처 다양성·최신성·검색량 대비 이례성)」 계산 아이디어만 `blog-keyword` 「오늘의 이슈」 보강 후보로 기록. 기사 원문 크롤링·출처 지우기는 하지 않는다 |

### 7-2. `codex_blog_write` — Codex 데스크톱용 네이버 블로그 작성·발행 플러그인(「Mato Blog Codex」)
| 항목 | 내용 |
|---|---|
| 형태 | ChatGPT/Codex 데스크톱 앱 **플러그인**(`.codex-plugin`, 스킬 `naver-blog-workflow`) + 파이썬 스크립트 38개(약 15,600줄) + 시험 코드. 이용자는 자연어로 요청(「이 URL 글로 새 글 2개 만들어 프로필 1,2에 발행해줘」) |
| LLM | **Codex 자신이 원고를 쓴다**(별도 AI 키 없음 — 이용자의 ChatGPT/Codex 구독 사용). Mato Helper 없이 독립 실행 |
| 글 쓰는 법 | ① 요청 해석 → ② 번호별 네이버 Chrome 프로필 로그인 확인 → ③ Codex 내장 브라우저로 네이버 통합검색·블로그탭 **상위 글 최대 5개의 본문·이미지 수집**(또는 지정 URL·본인 글·상품 URL) → ④ 공통 프롬프트 파일 `~/.googleblog/.../prompts/공통.txt`(이용자 수정 가능, SHA-256 기록) 적용 → ⑤ 공통 검색 의도·사실·구조를 합쳐 요청 수만큼(기본 10개) 서로 다른 원고 생성 → ⑥ 검증(`validate_posts.py`: 소제목 3개 이상, 이미지 태그와 JPEG 1:1) → ⑦ 업로드 |
| 프롬프트 구조 | 「Mato 텍스트 형식」: `제목을입력해주세요1:` / `본문2:` / `ㅂㅂㅂ소제목` / 표는 `표 NxM 시작·(행,열) 값·끝` 마커 / `[image_N.jpg]` / `!!` 구분선. 생성 규칙 문서(`generation-policy.md`): 문장·일화 복사 금지, 이용자가 주지 않은 체험 금지, 불안정 정보는 공식 출처 확인, 「원문에 따르면」 등 출처 언급 금지. 「사진역순」 규칙: 정보 70 : 경험 30, 이모지·과장 금지, 꿀팁·총평 소제목 |
| 발행 | **한다.** Playwright로 같은 Chrome 프로필에 재접속해 스마트에디터에 **20ms 고정 타이핑**, 인용구·구분선·표·이미지 삽입, 링크 카드는 클립보드 붙여넣기 → 임시저장(기본) 또는 「발행」 말이 있으면 공개 발행, 결과 주소 확인·재개. 예약 발행은 문서에 없음 |

| 위험 | 남의 상위 글 수집·「사진세탁」(메타데이터 제거·재인코딩), 고지 없는 가상 체험 후기 모드(`simulated_review`), 화면 자동 조작 제재, 세션 쿠키 영구화, 「관리자권한으로 수정해」 한마디로 잠금 해제되는 작업 규칙 |

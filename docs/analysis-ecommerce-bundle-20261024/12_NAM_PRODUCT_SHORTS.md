### 1-4. 실제 동작 여부 판단

- **스크립트 3개(음성·자막·합성)는 실제로 동작하는 코드**로 보인다(입출력 파일·API 호출이 구체적). 다만 실행하지 않았다.
- **「상품 주소만 넣으면 끝까지 자동」은 아니다.** 상품 페이지 수집·기획·이미지는 에이전트 지시문이고, 장면 영상은 사용자가 외부 사이트에서 손으로 만든다. 자동화 정도는 「반자동 제작 키트」.
- 내부 불일치: 스킬 Phase 5는 「자막은 렌더에 포함하지 않고 자막 표로 넘긴다」고 하지만, 실제 Remotion 컴포넌트는 자막을 화면에 그린다. `render.py`에는 특정 작업 폴더 이름(`260823_shorts`)이 박혀 있다(작성자 개인 작업 흔적). 윈도우는 `python3`·macOS 기준 설명이라 바로 안 될 수 있다.

- **팩션 「과장 200%」·「품절 대란」·「군중 심리」식 대본** — 근거 없는 판매량·품절 문구는 표시광고법상 허위·과장 위험이 크다. 우리 상세가 이미 「확인되지 않은 가격·혜택 문구 금지」를 지키므로 쇼츠에도 같은 기준을 둔다. 광고·제휴 표기(「광고」「유료 광고 포함」)는 필수로 안내한다.
- **에이전트가 상품 페이지를 브라우저로 열어 사진을 모으는 방식** — 쿠팡은 봇 차단이 강하고 남의 상세 사진은 저작권 문제가 있다. 우리는 **회원 본인 상품 사진(상세에서 올린 것)**만 쓴다.
- **로컬 GPU 음성 서버(Qwen3-TTS)·로컬 Remotion 렌더** — 회원 PC 설치 부담. 우리는 공식 음성 API(본인 키)와 브라우저 MP4를 유지한다.
- **출처 불명 기본 목소리(`reference_voice.mp3`) 복제** — 목소리 주인의 허락이 확인된 본인 목소리만 쓴다(기존 ElevenLabs 본인 복제 원칙).
- 운영자 `.env` 키 방식 — 최상위 규칙(회원 본인 키).
- 새 독립 프로그램 만들기 — 엔진이 이미 있으므로 넘기기 + 구성 추가로 충분하다.

## 5. 판단 제안

- **product-shorts-studio: 「참고 → 기존 프로그램에 기능 추가」(새 프로그램 아님).** 가치는 코드가 아니라 **쇼핑 쇼츠 기획 문법**(결과 먼저·짧은 비트·루프·분야별 시연·제품 외형 일치)과 「상품 사진 → 쇼츠」라는 빠진 연결을 보여 준 점이다. 우선순위는 A(상세 → 쇼츠 넘기기) + B(쇼핑 쇼츠 구성)이고, C는 장면 영상 단가 때문에 선택 기능으로 둔다. 담당은 영상(쇼츠 원스톱)과 이커머스(상세) 두 쪽 협의가 필요하다.

# 병합 vs 새 프로그램 비교분석표 (2026-10-24, 1차)

> **최종 분류는 [00_COMPARISON_TABLE.md](00_COMPARISON_TABLE.md) §0**(46개 원본 분석 완료 후 확정). 1차와 달라진 점: 새로 만들 것이 「판매 후 관리」 하나에서 **「판매 후 관리」 + 「쇼핑몰 업무 도구함」(라벨·QR·파일명·PDF·서명) 2개**로 늘었고, 영상은 alphacut 「긴 영상 → 쇼츠」를 `ai-video-studio`에 병합, channelup·mixxxi·오픈채팅 목록은 제외로 확정.

작성: Claude Code(윈도우) `claude-win-dotori` [역할: analysis-planning]. 주인님 질문: 「기존에 만들어 놓은 우리 자동화 프로그램에 기능을 병합할지, 아니면 지금 분류된 프로그램들의 장점 기능을 모아서 새로운 프로그램을 만들지 비교분석표를 만들어줘」.
근거: [분석 비교표](00_COMPARISON_TABLE.md) §1·§1-1 분류. **1차 — 원본 분석이 끝나지 않은 칸은 「확인 중」, 결과가 오면 확정.** 분석만, 코드·DB·배포 변경 없음.

## 3. 1차 결론
1. **대부분 A(기존 프로그램에 병합)** — 우리에게 이미 소싱·마진·상세페이지·이미지·영상·홍보 프로그램이 있어, 원본의 장점만 메뉴로 넣는 쪽이 개발량·회원 편의·유지보수 모두 낫다.
2. **새 프로그램(B)이 맞는 곳은 「판매 후」 하나** — 주문·배송·반품·정산·리뷰는 우리 플랫폼에 없는 단계이고, 원본도 시연이라 새로 설계해야 한다. 후보 이름: 「AI 쇼핑몰 주문·매출 관리 자동화」(가칭).
3. **「쇼핑몰 비즈니스 최적화」는 새 거대 프로그램이 아니라 연결로** — 상품소싱 → 상세페이지 → (새) 주문·매출 관리를 버튼 하나로 넘기는 「쇼핑몰 묶음 흐름」(데이터 넘기기·같은 상품 ID)을 만드는 것을 추천. 묶음 판매(요금제 세트)도 가능.
4. 대안(C): 소싱 + 상세페이지 + 판매 후를 **하나의 「쇼핑몰 원스톱」 새 프로그램으로 통합** — 회원 편의는 가장 크지만 기존 두 프로그램을 옮기는 대공사(병합 C 수준)이고 기존 회원 영향이 커서 1차에서는 추천하지 않음. 주인님이 원하시면 별도 비교.

## 4. 남은 일
- 원본 분석이 끝나면 §2의 「원본 품질」·점수·판단을 확정하고, 원본별로 「가져올 기능 목록」을 붙인다.
- 그다음 「쇼핑몰 비즈니스 최적화 묶음」 플랜(§3의 2·3번)을 쓴다.

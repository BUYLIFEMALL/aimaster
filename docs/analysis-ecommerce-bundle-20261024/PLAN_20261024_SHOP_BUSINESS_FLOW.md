## 0. 원칙
1. **거대한 새 프로그램 하나로 합치지 않는다.** 각 단계는 그 일을 가장 잘하는 프로그램이 맡고, 단계 사이는 **「다음 단계로」 버튼 하나**로 잇는다(기존 프로그램 회원·화면·주소는 그대로).
2. 넘기는 방식은 이미 있는 것을 넓힌다 — 상품소싱 → 상세페이지 넘기기(`trending-product-finder/lib/shopDetailLink.ts`, v1.23: 상품명·원본 정보·추천 판매가를 주소에 담아 상세페이지 새 상품 화면을 엶, 도매가는 넘기지 않음).
3. 프로그램끼리 서로 호출하지 않는다(각자 독립 배포). 회원 본인 계정·본인 키, 회원별 데이터 격리, 30일 정리는 그대로.
4. 숫자 조작·가짜 후기·가짜 판매량·남의 콘텐츠 짜깁기는 어느 단계에도 넣지 않는다(개발분석표 §4).

## 3. 단계 사이를 잇는 방법

| 방식 | 내용 | 판단 |
|---|---|---|
| **ⓐ 주소로 넘기기(추천, 1차)** | 지금 상품소싱 → 상세페이지와 같은 방식: 「다음 단계로」 버튼이 받는 프로그램 화면을 값이 채워진 채로 연다(상품명·원본 정보·가격·카테고리·태그 등 짧은 값). 각 프로그램 `lib/<받는곳>Link.ts` 한 파일 | DB 변경 없음, 지금 바로 가능, 받는 쪽에 길이 제한·검증 |
| ⓑ 회원 상품 카드 공유(2차) | 공용 DB에 회원 본인 「상품 카드」 표(상품명·카테고리·판매가·대표 사진 주소·상세 결과 주소, 회원별 RLS) — 단계마다 같은 상품을 이어서 보고 ⑤에서 상품별 실적과 연결 | 사진·긴 문구처럼 주소에 못 담는 것까지 이어짐, DB 변경(승인) 필요 |

- 넘기는 값에서 **도매가·원가는 빼는 기존 규칙**을 유지(상세페이지·홍보 문구에 할인가로 오해되는 것을 막음). 원가는 ③·⑤에서만.
- 각 프로그램 대시보드에 작은 「🛒 쇼핑몰 흐름」 띠: 지금 단계 표시 + 이전·다음 단계 버튼(같은 컴포넌트를 공용 사본으로).

## 7. 검수 기준(흐름 전체)
- 시험 계정으로 ①에서 상품 하나를 골라 ②상세페이지 → ③마켓별 판매가 → ④쇼츠 → ⑤주문 엑셀 반영까지 **버튼만 눌러 이어지는지** 크롬에서 확인.
- 단계마다 넘긴 값이 받는 화면에 정확히 채워지고, 도매가·원가가 상세·홍보 쪽으로 새지 않는지.
- 각 프로그램을 따로 열어도 지금처럼 쓸 수 있는지(흐름은 선택).

## 2. 기능·구조

### 2-1. 한 번의 수집이 흘러가는 순서

| 단계 | 내용 |
|---|---|
| 절대 규칙 0 — 도메인 기록 먼저 | `fingerprints/<도메인>/profile.json`이 있으면 그대로 채택해 정찰을 건너뜀(2026-09-30부터 「재사용할까요?」 묻지 않음, 마지막 사용 3개월 초과·「최신 구조로」 요청 시만 재정찰) |
| 정찰 | `agent-browser`(없으면 Claude in Chrome·ChatGPT 브라우저 → DynamicFetcher)로 화면 구조·네트워크 요청·숨은 JSON API 파악. **정찰 도구로 대량 수집 금지** |
| 수집 사다리 A(자동) | 1단 평문 요청 `plain_get` → 2단 세션 `plain_session` → 3단 JS 렌더링 `plain_dynamic`. 브라우저 위장·가짜 Referer를 끈 「정직한」 상태가 기본 |
| 통지 게이트 | 차단(403·가짜 200·챌린지)이 나오면 **자동으로 넘지 않고 사용자에게 한 번 묻는다**(진행/중단). 진행이면 근거를 묻지 않음 |
| 수집 사다리 B(통지 후) | 4단 curl_cffi 위장 조합(브라우저 지문 × 주소 변형 × Referer) → 5단 StealthyFetcher(`solve_cloudflare=True`) → 6단 사용자 실제 Chrome 연결(Chrome CDP). Akamai급 방화벽은 4·5단을 건너뛰고 6단 직행, CDP가 없으면 중단 보고 |
| CAPTCHA(2026-09-30 추가) | Cloudflare·Turnstile은 5단 도구로 통과, 대화형 퍼즐(reCAPTCHA·hCaptcha)은 **보이는 전용 Chrome 창을 띄워 사용자가 직접 풀고** 그 세션에 붙어 이어감. 외부 유료 풀이 서비스는 쓰지 않음 |
| 안전 장치 | robots.txt 확인, 요청 간격(100건 이하 1초 ~ 2000건 이상 2초+100건마다 15초 휴식), 429면 대기 2배, 0건이면 즉시 중단, 이미 통하던 단이 5회 연속 실패하면 중단, 진행 저장(`progress.py`) 뒤 재개 |
| 결과 | `output/<도메인>/<주제_날짜시각>/crawl_result.xlsx`(+원시 JSON·진행·생성된 수집 스크립트), 개인정보 감지 경고(`utils.detect_pii` — 값 패턴+열 이름) |
| 기록 | 성공한 방법을 `profile.json`에 저장. **우회로 뚫은 프로필은 `.gitignore` 화이트리스트에서 빠져 배포되지 않음**(`profile_policy.py`가 판정, 테스트가 CI에서 다시 검사) |

### 2-3. 장단점

- 장점: 차단을 만났을 때 「조용히 넘지도, 조용히 멈추지도 않는」 통지 게이트 설계가 명확하다. 한국 법(정보통신망법 §48①·저작권법 §93②·§104의2②·개인정보보호법)과 판례(잡코리아 4.5억 배상, hiQ 사건)를 쉬운 말로 정리했다. 쇼핑몰 리뷰 API·페이지 크기 함정 같은 실측 노하우가 도메인 기록으로 쌓인다. 시험 코드가 문서 규칙까지 검사한다.
- 단점: 사용자가 AI 코딩 에이전트와 Python·Node 설치를 다뤄야 한다(비개발자 회원용 아님). 결과가 에이전트 판단에 좌우된다. 사다리 B·사용자 Chrome 연결은 차단 우회 수단이라 법적·약관 위험을 사용자에게 넘긴다(「진행이면 근거를 묻지 않는다」).

### 하지 않을 것

- **6단 사용자 Chrome 연결·사용자 수동 CAPTCHA 풀기를 서버형에 넣기**: 서버(Render)에는 회원 브라우저가 없어 원리적으로 불가. 넣으려면 회원 PC 확장·데스크톱 앱이 필요하고, 차단 우회를 플랫폼이 적극 돕는 구조가 되어 위험이 커진다.
- **원본 15개 도메인 기록을 회원 공용 DB 캐시로 그대로 넣기**: 최상위 규칙(전역 생성 캐시 금지, #8)과 충돌 소지.
- **「진행이면 근거를 묻지 않는다」를 회원 서비스 기본값으로**: 우리 서비스는 운영자가 서버를 돌리므로, 우회 진행의 책임이 회원에게만 있다고 보기 어렵다. 지금처럼 robots 금지는 즉시 실패, Akamai는 바로 실패를 유지.
- 원본 CLI 설치 절차(`setup.ps1`)를 회원 기능으로 만드는 것.

### 이커머스 관점 — 경쟁사 상품·가격·리뷰 수집에 쓰는 법과 위험

| 쓰는 법 | 위험(원본 README·ACCEPTABLE_USE 기준 요약) |
|---|---|
| 경쟁사 상품 목록·가격: 카테고리 주소+「상품명·가격·할인율·배송비」 → 엑셀, 같은 도메인은 기록 재사용으로 반복 비용 절감 | **약관·robots**: 대부분 쇼핑몰 약관이 자동 수집을 금지 — 어기면 계정 정지·중단 요구·손해배상. **기술적 우회(사다리 B)는 들어간 행위 자체가 정보통신망법 §48① 문제**. **목적**: 경쟁사 가격을 긁어 내 가격 결정에 쓰면 팔지 않아도 「자신의 영업을 위하여」(부정경쟁방지법) — 「내부용이니 괜찮다」는 성립하지 않음 |
| 리뷰 수집: 별점·리뷰 본문·옵션 → 불만 키워드 분석·상세페이지 소구점 | **개인정보**: 리뷰 작성자 이름·아이디(크리마 API는 `user_display_name`을 돌려줌)는 개인정보 — 수집 대상에서 빼야 함(우리 서버는 `detect_pii` 경고가 있음). **저작물**: 리뷰 본문은 작성자 저작물이라 대량 복제·재게시 금지, 분석 통계만 |
| 정기 가격 모니터링 | **분량**: 하루 10건씩이라도 1년이면 DB의 「상당한 부분」 — 잡코리아 판례(DB 제작자 권리, 4.5억 배상). **부담**: 초당 1건 이하·429 시 중단 |
| 해외 B2B 소싱(made-in-china 등) | 국외 사이트 약관·현지 법 별도. 연습은 `books.toscrape.com` |

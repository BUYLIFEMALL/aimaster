# 타당성 조사 — 네이버 공개 채널에서 키워드로 타깃 찾기·연락처 수집 (2026-11-05)

작성: 맥미니 Claude Code `claude-mac-20261101-blog` [역할: mac-mini] · 주인님 지시 「테스트로 할 수 있는지 전체 관점에서 자세하고 면밀하게 조사·분석 보고」
기준: 공개된 데이터에서만 확인 수집 · 회원 본인 키·공식 API 우선 · 사람 속도·걸리면 그날 중지 · 숨긴 아이디 추출 ❌
상태: **조사 보고(코드·DB 변경 없음)**. 실제 요청 주소·필드·쿼터는 네이버 개발자 센터에서 재확인 필요.

## 0. 한 줄 결론
**「키워드로 그 주제 채널(블로그·업체·카페글·쇼핑)을 찾는 것」은 공식 API로 안전하게 된다. 그러나 「그 채널의 이메일을 프로그램이 자동으로 긁어 모아 저장하는 것」은 정보통신망법 제50조의2(이메일 자동수집 금지)에 정면으로 걸릴 소지가 커서 권하지 않는다.** → 엔진은 「채널 찾기 + 공개 정보 정리」까지, 이메일 자동 수집·저장은 빼는 설계를 권한다.

## 1. 조사한 것
### 1-1. 공식 검색 API가 무엇을 주나
| API | 주는 것 | 연락처 |
|---|---|---|
| 블로그 검색 | 블로그 이름(`bloggername`)·주소(`bloggerlink`=`blog.naver.com/{id}`)·글 주소·요약·작성일 | ❌ 응답에 연락처 없음 → 프로필 페이지에 따로 |
| 지역(플레이스) 검색 | 상호·주소·카테고리·업체 상세 링크(`link`)·좌표 | ⚠️ **전화번호(`telephone`) 더 이상 안 줌**(「값을 반환하지 않는 요소, 하위 호환용」, 실제 빈 값) |
| 카페글·지식iN·뉴스·쇼핑 검색 | 글·업체·상품 제목·주소·요약 | ❌ 대부분 연락처 없음(쇼핑은 판매자 상호·링크) |
- **정리**: 공식 API는 「누가·어디서 그 주제로 활동하는지(채널 목록)」까지 주고, **연락처 자체는 응답에 거의 없다.** 연락처는 각 채널의 공개 페이지에 본인이 적어 둔 것을 따로 봐야 한다.

### 1-2. 비용·한도·약관
- 공식 검색 API **무료**(앱 등록·일일 쿼터). 하루 25,000회로 안내되나, **API HUB로 이관 중**이라 월 쿼터(각 50,000건) 기준도 있음 → 콘솔에서 현재값 확인 필요. API HUB는 **한시 무료, 유료 전환 시 사전 공지**.
- **검색 API 특약 개정 2026-09-07 시행**: 검색 API 데이터를 **AI 학습·재판매에 쓰는 것 제한.** → 우리는 회원 본인 키로 회원이 쓰고 회원 소유로 격리(재판매 아님)라 맞지만, 「수집 데이터로 AI 학습」은 하지 않도록 못박아야 함.
- 회원 본인 키 규칙과 맞음(운영자 키 폴백 ❌).

### 1-3. 법(가장 중요)
- **정보통신망법 제50조의2**: 「**자동으로 이메일 주소를 수집하는 프로그램·기술 장치로** 타인의 이메일 주소를 수집하는 행위 금지」 — **목적이 영리인지 불문.** 위반 수집 주소의 판매·유통, 그런 주소인 줄 알고 전송하는 것도 금지. 벌칙 1년 이하 징역 또는 1천만원 이하 벌금.
- 핵심: **「공개돼 있느냐」가 아니라 「자동 수집 프로그램으로 모으느냐」가 금지 기준.** 그래서 공개 페이지라도 프로그램이 이메일을 자동으로 긁어 모으면 제50조의2에 걸릴 소지가 크다. 수많은 사이트가 「이메일무단수집거부」를 걸어 둔 것도 이 때문.
- 제50조: 동의 없는 영리 광고 전송 금지(이메일 자동 생성·수집 조치 포함). → 모은 연락처로 광고를 보내는 단계도 동의 필요.

## 2. 그래서 되는 것 / 안 되는 것 / 애매한 것
| 구분 | 내용 | 판정 |
|---|---|---|
| 키워드로 **채널 목록** 찾기(블로그·업체·카페글·쇼핑: 이름·주소·요약) | 공식 API, 회원 키, 공개 데이터 | ✅ **된다**(안전) |
| 찾은 채널을 주제·활동량으로 **정렬·분류** | 우리 서버에서 계산 | ✅ 된다 |
| 각 채널 **공개 프로필을 회원 화면에 띄워 회원이 눈으로 확인** | 회원이 직접 보고 판단 | ✅ 된다 |
| 그 채널의 **이메일을 프로그램이 자동으로 긁어 저장** | 제50조의2 자동수집 금지 | ❌ **권하지 않음**(법적 위험) |
| 모은 이메일로 **광고 자동 발송** | 제50조 동의 없는 광고 | ❌ 안 함 |
| 숨긴 카페 회원 아이디 추출 | §4·접근 우회 | ❌ 안 함 |

## 3. 권하는 설계 — 「타깃 찾기 엔진」(이메일 자동수집 없이)
목적(공동구매 주제의 활동 채널을 찾아 닿기)은 **이메일을 긁지 않고도** 이룰 수 있다.
1. **채널 찾기**(공식 API): 키워드 → 블로그·업체·카페글·쇼핑 목록(이름·주소·요약·활동 신호).
2. **정렬·분류**: 주제 관련도·최신·활동량으로.
3. **회원이 보고 접근**: 회원이 목록에서 채널을 열어 **직접** 제휴 연락하거나, **초대링크를 그 채널·주제 글에 노출**. 연락처를 프로그램이 모아 두지 않음 → 회원이 공개된 자리에서 직접 확인·연락.
- 이러면 ① 공식 API만 써서 안전 ② 이메일 자동수집(제50조의2)·동의 없는 광고(제50조)를 건드리지 않음 ③ 그래도 「공동구매 주제 활동자에게 닿기」라는 목적은 달성.

## 4. 테스트로 확인할 수 있는 것 (비용 거의 없음)
- 회원 본인 키(시험 계정)로 검색 API를 **소량 호출**해 블로그·지역·카페글 목록이 실제로 오는지, 응답에 연락처가 없는지 확인(무료 쿼터 안, AI 비용 없음).
- 공개 프로필 페이지를 회원 브라우저로 열어 연락처가 어디에 어떻게 공개되는지 **눈으로** 확인(저장 안 함).
- 이 두 가지는 코드 없이 사전 검증으로 가능.

## 5. 주인님 결정 필요
1. **이메일 자동수집을 뺀 「타깃 찾기 엔진」**으로 갈지(권장) — 채널 목록·정렬·회원 직접 접근·초대링크.
2. 그래도 공개 이메일 수집·저장을 꼭 넣어야 한다면, 제50조의2 위험을 회원 책임 고지로 넘기는 구조가 되는데, 법적 위험이 커서 **별도로 다시 확인받는 절차**가 필요.
3. 이 엔진을 `competitor-analysis`(이미 키워드로 채널 찾기) 확장으로 할지, 새 프로그램으로 할지.

## 0. 전제 (바꾸지 않음)
- **관리자 지정 예외**(2026-11-05 주인님 「3가지 방식 모두 필요」) — 회원이 **책임 고지에 동의하고 켤 때만** 동작.
- **회원 본인 계정으로 직접 로그인한 브라우저 창**에서만. 프로그램은 로그인·비밀번호를 다루지 않는다.
- 대상 카페는 **회원이 운영하거나 가입한 카페**만, 글은 **공유 가능한 글** 범위만. 남의 카페 전수 수집 ❌.
- 모으는 것: **네이버 아이디 · 닉네임 · 등급 · 게시판 · 글 제목**. 이메일·전화 ❌.
- 우리 서버는 네이버에 직접 요청하지 않는다. 읽기는 회원 PC 확장이, 저장은 서버 `ncr_dispatch`가.
- 보안문자·로그인 풀림·「제한」 안내가 뜨면 **그날 수집 중지**, 다시 시도·우회 ❌. IP 바꾸기·여러 계정·탐지 회피 ❌.

## 1. 회원이 하는 일 (목표: 처음 설정 3단계 · 매일 조작 1번 · 동의 1번)
| 단계 | 화면 | 회원 조작 |
|---|---|---|
| 처음 1 | 「카페 활동 회원 모으기」 켜기 | 책임 고지 읽고 동의 1번 |
| 처음 2 | 카페 고르기 | 확장이 불러온 **내 가입·운영 카페 목록**에서 체크 |
| 처음 3 | 게시판·범위 | 불러온 게시판 체크, 기본값(최근 5페이지·매니저/탈퇴 제외) 그대로 두면 됨 |
| 매일 | 오늘 할 일 | 모인 명단을 보고 「승인」 1번(또는 저장만) |

## 2. 구성 (어디서 무엇을)
| 위치 | 하는 일 | 가져다 쓸 코드 |
|---|---|---|
| **웹 화면** | 수집 설정(카페·게시판·범위·거르기), 진행 상태, 모인 명단·승인, 엑셀 내려받기 | 프로그램 뼈대(윈도우) |
| **서버** | 수집 설정·실행 상태 저장, 확장이 보낸 명단을 `targets_add`로 저장(중복 아이디 자동 제외) | `ncr_dispatch` + 아래 §5 추가분 |
| **확장** | 회원 로그인 창에서 ① 가입 카페 목록 ② 게시판 목록 ③ 게시판 글 목록 페이지별 읽기 ④ 글 작성자 정보 확인 → 서버로 전송 | `blog-neighbor-care/extension`의 `neighbor-extractor.mjs`·`neighbor-importer.mjs`(목록을 페이지별로 읽고 확인 뒤 반영), `target-traversal.mjs`(같은 창 전용 탭 순회·보일 때만 진행), 기기 연결·동의 기억 |

## 3. 수집 흐름 (확장)
1. **시작 확인**: 동의 기록·이 기기 연결·회원 로그인 계정이 연결 계정과 같은지 확인 → 다르면 멈추고 안내.
2. **가입 카페 목록 읽기**(처음 설정 때 1번, 이후 하루 1번까지): 회원 화면의 「내가 가입한 카페」에서 카페 이름·번호·주소 → 웹에 표시.
3. **게시판 목록 읽기**: 회원이 고른 카페마다 게시판 이름·번호·종류.
4. **글 목록 읽기**: 고른 게시판을 최신부터 페이지별로(기본 5페이지, 최대 20). 한 페이지마다 글쓴이 닉네임·등급·글 제목·회원 구분값.
5. **거르기**(읽는 즉시): 매니저·탈퇴 회원 제외, 새싹 등급 제외(선택), 등급 범위, **이미 모은 회원·이미 초대한 회원 제외**(서버에서 받은 목록과 대조), 같은 글쓴이 중복 제외.
6. **작성자 아이디 확인**: 남은 대상마다 **회원 로그인 화면에서 확인 가능한 공유 가능한 글 범위**에서 작성자 네이버 아이디를 확인. 확인이 안 되는 글은 건너뛰고 「확인 불가」로 셈(재시도 1번까지).
   - ⚠️ 어떤 화면 정보로 확인할지는 §6 사전 검증에서 **현재 네이버 화면 기준으로 정하고 기록**한다(원본 2024~2026 방식은 바뀌었을 수 있음, 원본 주소를 그대로 옮기지 않음).
7. **서버로 전송**: 50명 단위로 `targets_add`(source_mode=`extract`) → 서버가 중복 아이디는 건너뛰고 추가 수를 돌려줌.
8. **끝·중지**: 범위를 다 읽거나 하루 수집 상한에 닿으면 끝. 진행 상태(카페·게시판·페이지·모은 수·확인 불가 수·중지 사유)를 웹에 표시.

## 4. 속도·양·멈춤 (사람 같은 패턴, §20)
| 항목 | 기본값 |
|---|---|
| 페이지 사이 간격 | 4~9초 무작위(가끔 15~30초 쉼) |
| 작성자 확인 사이 간격 | 2~5초 무작위 |
| 하루 수집 상한 | **1000명**(2026-11-05 주인님 「1000명으로 맞춰」) — 회원이 100~1000 사이로 조절. 작성자 확인 2~5초 간격 기준 1000명이면 약 1~1.5시간(페이지 읽기 포함), 동작 시간대 안에서 나눠 진행 |
| 한 번에 연속 | 최대 10페이지 뒤 1~3분 쉼 |
| 동작 시간대 | 09:00~22:00(초대와 같은 설정) |
| 실행 탭 | 같은 창의 전용 탭 하나, **화면에 보일 때만 진행**, 가려지면 시계만 멈춤(`blog-neighbor-care` v1.17 방식). 다른 탭을 눌러도 끄지 않고 잠시 멈춤(C-2 개선과 같게) |
| 즉시 중지 | 보안문자 · 로그인 풀림 · 계정 불일치 · 「제한/비정상 이용」 안내 · 화면 구조가 예상과 다름 → **그날 중지**, 웹에 사유 표시 |
| 다시 시작 | 다음 날 자동으로 이어감(이미 읽은 페이지는 건너뜀) — 그날 안에는 자동 재시도 ❌ |

## 5. 서버·DB 추가분 (윈도우 적용, 기존 초안에 더함)
- 표 `ncr_collect_runs`: 회원·카페·게시판 목록·페이지 범위·상태(`queued·running·paused·done·stopped`)·모은 수·확인 불가 수·중지 사유·마지막 읽은 페이지·날짜. 소유자 격리·30일 보관·열외.
- `ncr_dispatch` 연산 추가: `collect_save`(설정 저장), `collect_status`, `collect_progress`(확장이 진행 보고), `collect_stop`, `known_ids`(이미 모은·초대한 아이디 목록 — 확장이 거르기에 사용, 아이디만).
- `targets_add`의 하루 수집 상한 확인 추가(모드 `extract`일 때 오늘 한국 날짜 기준 추가 수 ≤ 상한, **기본 1000·최대 1000**(2026-11-05 주인님 「1000명으로 맞춰」)). 설정 표에 `collect_daily_cap int default 1000 check(between 100 and 1000)` 추가 — 초대 상한(`daily_cap`, 최대 25)과 별개.

3. 글 목록에 보이는 글쓴이 정보(닉네임·등급), 작성자 프로필에서 회원 화면에 보이는 정보

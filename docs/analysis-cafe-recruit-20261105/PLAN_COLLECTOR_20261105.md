## 0. 핵심 결정 — 모으는 것은 「활동 회원 명단」, 아이디는 공식 경로로만
화면 확인 결과([`DOM_CHECK`](../../naver-cafe-recruit/docs/DOM_CHECK_20261105.md) §0) **회원에게 보이는 카페 화면에는 네이버 아이디가 없다**(닉네임·등급만). 숨긴 아이디를 우회로 꺼내는 것은 §4(공개하지 않은 것·우회로만 보이는 것 제외)와 접근 우회 금지에 걸려 **만들지 않는다**(시스템도 그 탐색을 「접근 우회」로 자동 차단함). 그래서:
- **모드 A가 모으는 것 = 화면에 보이는 활동 정보**: 닉네임 · 등급 · 게시판 · 글 제목 · 활동량(글 수 등 보이는 값) · 회원 페이지 링크(암호화 번호). **네이버 아이디·이메일·전화는 모으지 않는다.**
- **아이디는 공식 경로로만 들어온다**: ① 회원이 직접 넣은 아이디(모드 B) ② 블로그 서로이웃(모드 B) ③ 초대링크·QR(아이디 불필요, 모드 C). 모드 A 명단으로 「누가 활발한지」 파악 → 그들에게 초대링크가 담긴 홍보 글로 접근.
- 이 결정으로 「아이디 수집 자동화」의 실제 쓸모(활발한 대상 파악 + 공식 초대)는 지키면서, 숨은 개인정보 수집만 뺀다.

## 1. 전제 (바꾸지 않음)
- **관리자 지정 예외** — 모든 이용 회원이 본인 계정으로 쓰는 기능. 회원이 **책임 고지에 동의하고 켤 때만** 동작. 최상위 규칙 §8에 기록(§8절).
- **회원 본인 계정으로 직접 로그인한 브라우저 창**에서만. 프로그램은 로그인·비밀번호를 다루지 않는다.
- 대상 카페는 **회원이 운영하거나 가입한 카페만**. 남의 카페·가입 안 한 카페 ❌.
- 우리 서버는 네이버에 직접 요청하지 않는다. 읽기는 회원 PC 확장이, 저장은 서버가.
- **사람처럼·상한 안에서** 동작하되(§4), 보안문자·로그인 풀림·계정 불일치·「제한/비정상 이용」 안내가 뜨면 **그날 중지**. 차단을 뚫지 않는다. IP 바꾸기·여러 계정·탐지 회피 장치 ❌.

## 2. 회원이 하는 일 (목표: 처음 설정 3단계 · 매일 조작 1번 · 동의 1번)
| 단계 | 화면 | 회원 조작 |
|---|---|---|
| 처음 1 | 「카페 활동 회원 모으기」 켜기 | 책임 고지 읽고 동의 1번 |
| 처음 2 | 카페 고르기 | 확장이 불러온 **내 가입·운영 카페**에서 체크 |
| 처음 3 | 게시판·범위 | 불러온 게시판 체크, 기본값(최근 5페이지·운영진/탈퇴 제외) 그대로 두면 됨 |
| 매일 | 오늘 할 일 | 모인 명단 보고 「승인」 1번(또는 저장만) |

## 3. 수집 흐름 (확장, 회원 로그인 세션)
1. **시작 확인**: 동의 기록·기기 연결·로그인 계정이 연결 계정과 같은지 → 다르면 멈추고 안내.
2. **가입 카페 목록 읽기**: 회원 화면 「내 카페 관리」에서 카페 이름·번호·주소, 운영/가입 구분.
3. **게시판 목록 읽기**: 고른 카페의 게시판 이름·번호·종류(`ArticleList.nhn`·`/menus/` 형태만, 외부 링크 메뉴 제외).
4. **글 목록 읽기**: 고른 게시판을 최신부터 페이지별로(기본 5, 최대 20). 페이지마다 닉네임·등급·글 제목.
5. **거르기(읽는 즉시)** — 아래 §3-1.
6. **서버로 전송**: 50명 단위로 명단 저장(닉네임·등급·게시판·글 제목·회원 페이지 링크). **아이디 없음.** 중복(회원 페이지 링크 기준)은 서버가 건너뜀.
7. **끝·중지**: 범위를 다 읽거나 하루 상한에 닿으면 끝. 진행 상태(카페·게시판·페이지·모은 수·중지 사유)를 웹에 표시.

### 3-1. 수집에서 빼는 대상 (주인님 지시)
| 제외 | 가려내는 표시 |
|---|---|
| 매니저(운영자) | 운영진 배지(「M」 등) |
| **부운영자** | 운영진 배지 |
| **게시판 관리자(게시판지기)** | 게시판 담당 표시 |

## 5. 서버·DB 추가분 (윈도우 적용)
- 표 `ncr_collect_runs`: 회원·카페·게시판·페이지 범위·상태·모은 수·중지 사유·마지막 페이지·날짜. 소유자 격리·30일 보관·열외.
- `ncr_targets`에서 **`naver_id`를 선택(nullable)로** — 모드 A는 아이디 없이 들어오고, 회원 페이지 링크(`member_ref`)를 중복 기준으로. 모드 B만 아이디 채움.
- `ncr_dispatch` 연산: `collect_save`·`collect_status`·`collect_progress`·`collect_stop`. `targets_add`에 `source_mode='extract'`는 아이디 없이 허용, 하루 수집 상한 확인.

## 6. 쓰는 방법 (모은 명단으로 마케팅)
- 명단·엑셀로 활발한 회원 파악 → **초대링크·QR을 모드 C 홍보 글·블로그·카톡에 넣어** 그 사람들이 보게. 아는 아이디는 모드 B로 초대.

## 7. 사전 확인 (구현 전, 맥미니 ego · 시험 계정 · 읽기만 · 비용 없음)
가입 카페 1곳에서 화면만 확인:
1. 글 목록·글 화면에서 **운영진·부운영자·게시판 관리자·스텝** 표시가 어디에 어떤 형태로 나오는지(가려낼 수 있는지)
2. 낮은 등급·탈퇴 회원 표시
3. 중복 기준으로 쓸 회원 구분값(회원 페이지 링크)이 안정적인지
→ [`DOM_CHECK_20261105.md`](../../naver-cafe-recruit/docs/DOM_CHECK_20261105.md)에 「운영진 구분」 절로 기록. 확인 안 되면 §3-1대로 건너뜀. **숨은 아이디를 꺼내는 확인은 하지 않는다.**

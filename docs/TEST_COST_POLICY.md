# 최상위 공통 필독 — 개발·테스트 비용 최소화 지침

2026-10-16 주인님 지시. **모든 CLI·AI 에이전트는 새 프로그램·프로젝트를 개발하거나 테스트하기 전에 이 문서를 읽는다.** 루트 `CLAUDE.md`·`AGENTS.md` 최상단에도 같은 요약이 있다. 회원 본인 계정·본인 API 키 최상위 규칙(`TOP_RULE_PERSONAL_ACCOUNT_API.md`)은 이 지침보다 위에 있고 그대로 유지한다.

## 1. 원칙 (순서대로 적용)

1. **무료로 가능하면 무료 방법으로 시험한다.** 무료 요금제·무료 공개 API·샌드박스/테스트 모드·로컬 실행·모의(mock) 응답을 먼저 찾고, 그것으로 개발·검수를 진행한다.
2. **유료 API만 가능하면 그 제공사의 가장 저렴한 모델로, 최소 호출만** 해서 시험한다.
   - **예외(2026-10-16 주인님 추가 지시): 프로그램의 성능 검증을 위해 필요하면 상위 모델로 시험 작업을 할 수 있다.** 실제 서비스 품질·응답 형태·처리 시간·한도 동작처럼 저가 모델로는 판정할 수 없는 항목을 확인할 때 쓴다. 이때도 필요한 만큼 최소 횟수로 하고, 어떤 항목을 왜 상위 모델로 확인했는지 §5에 기록한다.
   - **예외(2026-10-16 주인님 지시): 프로그램 카탈로그 썸네일은 상위 이미지 모델을 써도 된다.** 시험이 아니라 회원에게 보이는 대표 이미지라 품질을 우선한다. 관리자 계정 본인 Gemini 키로 `scripts/generate-program-thumbnail.mjs`를 쓰고(`PLATFORM_PATTERNS.md` §13), 결과를 확인해 다시 만들 때도 같은 모델을 쓴다.
3. 시험에 쓰는 키는 **시험 계정(`buylifemall@naver.com`)이 본인 설정 화면에 등록한 본인 키**다. 운영자 키·다른 회원 키로 대신하지 않는다. 키가 없으면 주인님께 등록을 요청한다(핵심 원칙 0번).
4. **대량·반복 호출, 고가 모델, 이미지·영상·음악처럼 건당 비용이 큰 생성은 사전 승인**을 받는다(기존 규칙 유지).
5. 어떤 무료 방법·모델·호출 횟수로 시험했는지 **인수인계에 기록**한다(§5).

> 이 지침은 **개발·시험 단계**에 적용한다. 회원이 실제로 쓰는 기능의 모델 선택(품질 기준)은 각 프로그램 설계를 따르고 이 지침 때문에 낮추지 않는다.

## 2. 무료 시험 방법을 찾는 순서

| 순서 | 방법 | 예 |
|---|---|---|
| 1 | 로컬에서 끝나는 시험 | 단위 테스트, 순수 로직 함수, `npm run build`, 로컬 `localhost` 화면 |
| 2 | 모의(mock)·고정 응답 | AI 응답을 저장해 둔 JSON으로 화면·저장·내보내기 흐름만 검수 |
| 3 | 공급자의 무료 요금제·테스트 모드 | 무료 호출 한도가 있는 API, 결제 샌드박스, 테스트 키 |
| 4 | 무료 공공·공개 데이터 | 공개 시장·공공 데이터 API(핵심 원칙 예외 조항의 조건 안에서만) |
| 5 | 이미 저장된 실제 데이터 재사용 | 앞서 한 번 받아 둔 응답·이미지를 다시 쓰기 |

- **화면·권한·저장·내보내기 같은 비-AI 흐름은 AI를 호출하지 않고 시험할 수 있다.** AI 호출이 필요한 부분만 따로 떼어 최소 횟수로 확인한다.
- 무료 한도가 있는 키는 한도를 소진하지 않게 호출 수를 센다(예: 네이버 검색·데이터랩은 계정당 일일 한도).

## 3. 유료 API만 가능할 때 — 가장 저렴한 모델로

- **모델 이름을 이 문서에 고정하지 않는다.** 가격은 자주 바뀐다. 시험 전에 해당 제공사의 공식 가격표에서 **지금 가장 저렴한 모델**을 확인해 쓴다(보통 각 제공사의 가장 작은 모델 — 예: Claude Haiku 계열, Gemini Flash/Flash-Lite 계열, OpenAI mini/nano 계열 — 이지만 시점에 따라 다르다).
- 기능이 특정 모델만 지원하면(이미지 생성·검색 연동 등) 그 기능을 지원하는 **가장 저렴한 모델·가장 낮은 해상도·가장 짧은 길이**로 시험한다.
- 호출을 줄이는 방법:
  - 입력을 가장 짧은 대표 표본 1건으로, 출력 길이(`max_tokens` 등)를 작게 제한한다.
  - 한 번 받은 실제 응답은 파일로 저장해 두고 이후 화면·후처리 시험에 재사용한다.
  - 같은 호출을 반복하지 않는다. 실패 원인은 로그·응답 본문으로 먼저 조사하고 재호출은 1회로 제한한다.
  - 이미지·영상·음악은 1건, 가장 작은 크기로 한 번만 만든다.
- 외부 API의 응답 "형태"(분포·날짜 집계·문장 형식)는 단위 테스트만으로 드러나지 않으므로(`ERROR_LESSONS.md` 2026-10-16), **저가 모델로 실제 값을 한 번은 받아서** 확인한다.

## 4. 사전 승인이 필요한 경우 (기존 규칙 그대로)

- 유료 API의 **대량·반복 호출**, 이미지·영상·음악 다수 생성. (성능 검증을 위한 상위 모델의 소량 시험은 §1-2 예외에 따라 승인 없이 가능하다.)
- 회원 대신 최종 발행·결제·외부 공개, 실제 메일·문자·카카오 발송.
- 환경변수·키 변경, 데이터 삭제.

## 5. 인수인계에 적는 것

작업 기록(해당 프로그램 `AGENTS.md`/`README.md` 또는 `docs/HANDOFF.md` 항목)에 한 줄을 남긴다.

```
시험 비용: 무료 방법(로컬 테스트·모의 응답) / 유료 호출 N회(모델명, 시험 계정 본인 키) / 상위 모델 호출 없음(또는 "성능 검증용 상위 모델 N회, 확인한 항목: …")
```

## 6. 다른 규칙과의 관계

- 핵심 원칙 0번(본인 계정·본인 API 키): 우선한다. 무료·저가 시험이라도 운영자·타 회원 키로 폴백하지 않는다.
- 핵심 원칙 13번(실제 Chrome 화면 검수): 그대로 한다. 화면 검수는 비용이 들지 않으니 생략하지 않는다.
- 핵심 원칙 12번(검수→커밋→푸시→배포→보고): 그대로 한다. 보고에 시험 비용 한 줄을 포함한다.

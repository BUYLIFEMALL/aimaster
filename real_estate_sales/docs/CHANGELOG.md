## 상세 히스토리

### 1. 프로젝트 시작 (2026-08-10, `d404341`)

기존에 Make.com 시나리오 + n8n(국내 IP 프록시) 조합으로 개인용으로 쓰던 부동산
투자 분석 자동화를, AIMaster 정식 서브프로젝트(멀티테넌트 서비스)로 이식했습니다.

- **국내 IP 전용 공공 API 문제**: 서울 열린데이터광장/공공데이터포털/VWorld가
  전부 국내 IP만 허용 → `vercel.json`의 `regions: ["icn1"]`로 서버리스 함수를
  서울 리전에 고정해서 n8n/Make 프록시 없이 직접 호출 (검증 완료, 3개 API 전부
  성공). `export const preferredRegion` 방식은 최신 Vercel 환경에서 무시되는 것을
  확인했으므로 반드시 `vercel.json`의 `regions` 키를 써야 함.
- **데이터 격리 원칙**: 매물 원본(`real_estate_listings`)은 전역 공유(같은 지역을
  여러 사용자가 봐도 수집은 1번만), 사용자별 관심지역·매칭피드·AI분석·텔레그램
  연동은 `user_id` + RLS owner-only로 분리.
- **텔레그램 연동**: 공용 봇이 아니라 사용자가 BotFather로 직접 만든 개인 봇을
  등록하는 방식(OAuth 없이 `getUpdates`로 chat_id 확보). 이 프로젝트가 이
  패턴의 최초 구현체.

자세한 근거는 `README.md`의 "핵심 아키텍처 결정" 절 참고.

### 2. 접근 제어·RLS 버그 수정 (2026-08-10, `69d9e51` `07ea28b` `fd2f9d3`)

전월세 조회/텔레그램 저장이 RLS에 막혀 실패하던 버그, 서버 액션에 프로그램 이용
권한 검사가 빠져있던 버그를 수정. 이 감사 과정에서 threads/shots/real_estate_sales
전체 서브프로젝트의 동일한 실수(로그인만 확인하고 구독 여부는 확인 안 함)를 함께
전수 수정함 — 이후 새 서브프로젝트를 만들 때마다 반복 확인이 필요한 항목으로
루트 `CLAUDE.md`의 멀티테넌시 원칙에 등록됨.

### 3. AI 분석 자동화 + 실시간 모니터링 최초 구현 (2026-08-10, `458ad5a` `514488c`)

AI 분석 모델을 사용자가 설정 화면에서 고르면, 새 매물이 잡힐 때 자동 분석되어
텔레그램 알림에 결과가 같이 포함되도록 함. 관심 지역마다 "실시간 모니터링"을
켜고 끌 수 있고 수집 주기·동작 시간대를 지역별로 설정하는 기능도 이때 처음
만들어짐 (지금은 "예약 조회"로 이름이 바뀌었지만 코드/DB 구조는 그대로 이어짐).

### 4. Vercel Pro 전환 + 수집 비용 최적화 (2026-08-11, `09b24b8` `220ee33` `2770357` `ae3cafb`)

Hobby 플랜은 cron이 하루 1회로 제한되어 거부되는 것을 실제 배포로 확인한 뒤 Pro로
업그레이드, cron을 30분→5분 간격으로 전환(사용자별로 다른 주기/시간대를 5분 단위로
세밀하게 판정하기 위함). 이 과정에서 수집 파이프라인의 외부 API 호출 비용을
줄이기 위해 매물 존재 여부를 배치(IN 쿼리)로 한 번에 확인하고, 건축물대장/공시가격
/전월세 3종 보강 API를 병렬 호출로 바꿈. AI 분석도 앱 기본 폴백 키를 쓰는 사용자
끼리는 결과를 캐시 공유하도록 해서 같은 매물을 여러 명이 볼 때 중복 분석하지 않게 함.

### 5. AI 분석 품질 개선 (2026-08-11, 다수 커밋)

모델 선택지 정리(mini 모델 제거, 상위 모델과 라벨 구분), AI가 당일 수집된 데이터를
"미래 날짜"로 오판해 오류 취급하던 버그 수정, 결과 가독성(문단 줄바꿈)과 어조
개선, 최종 분석 전 최근 1주일 부동산 정책/동향을 먼저 조사하도록 강화. VWorld
등록 도메인도 하드코딩(`n8n.buylife.xyz`) 대신 `VWORLD_REGISTERED_DOMAIN` 환경변수로
분리해서, 나중에 실제 서비스 도메인으로 등록을 바꿀 때 코드 수정 없이 반영되게 함.

### 6. 컨셉 피벗 — "실시간 매매정보" → "실거래 투자분석" (2026-08-11, `3373207`)

사용자가 "공공데이터 API가 실제 현재 호가가 아니라 최근 거래된 실거래 기록 아니냐"고
질문 → 코드 확인 결과(`tbLnOpendataRtmsV` API, 계약 후 30일 이내 신고 의무) 사실로
확인됨. 실시간 매물 호가(네이버부동산 등)는 공식 공공 API가 없어 별도 크롤링/제3자
연동 없이는 다룰 수 없으므로, **데이터 파이프라인은 그대로 두고 정직하게 "실거래가
분석" 서비스로 이름·문구만 재정의**하는 방향(사용자가 제시한 3가지 옵션 중 2번)을
선택. UI 텍스트, 메타데이터, 텔레그램 메시지, DB `programs` 레코드까지 전부 갱신.

> 향후 매물 호가(현재 판매 중인 매물) 데이터를 다루고 싶다면, 네이버부동산 등의
> 비공식 크롤링이나 제3자 유료 API 연동이 필요합니다 — 별도 검토 과제로 남겨둠.

### 7. 조회 방식 재설계 — 기본 수동 + 선택 예약 (2026-08-11, `90eb6e6`)

컨셉 피벗 이후, "지역을 켜두면 자동으로 계속 감시"하는 실시간 모니터링 중심 UX가
"실거래가 분석" 서비스와 안 맞는다는 사용자 지적으로 재설계:

- **사용자 결정 과정**: (1) 지역 선택 후 조회+분석 버튼 → 텔레그램 수신 형태로
  가자는 제안 → (2) 트리거 방식을 묻는 질문에 "완전 수동(버튼 클릭 시에만)"을
  선택 → (3) "과정상의 데이터는 지금처럼 남겨두라"(DB 구조 변경 없음) → (4) 최종
  지시: **"기본은 수동, 단 기존에 만들어둔 예약(주기/시간대) 기능도 폐기하지 말고
  선택 기능으로 재활용하자"**.
- **구현**: 수집→AI분석→텔레그램 발송 로직을 `src/lib/realestate/collect.ts`
  공유 모듈로 추출해서 cron 라우트(`api/collect/dispatch`)와 신규 Server Action
  (`src/lib/actions/query.ts`의 `queryDistrictsAction`)이 동일 로직을 공유.
  `/districts` 페이지에 "실거래가 조회"(수동, 기본) 섹션을 새로 추가하고, 기존
  UI는 "예약 조회 (선택)"로 이름만 바꿔 그대로 유지.
- **검증**: 실제 브라우저에서 버튼을 눌러 결과 메시지 확인 + DB
  (`real_estate_district_collect_state.last_collected_at`,
  `real_estate_watch_districts.last_run_at`)가 클릭 시점에 갱신된 것을 대조해서
  Server Action이 끝까지 실행됨을 확인.

### 8. 예약 조회 수집 주기 정리 (2026-08-11, `626c497`)

실거래(매매 계약) 데이터는 정부 신고 지연이 있어 5분/10분/30분 단위로 갱신될
이유가 없다는 사용자 판단으로, 예약 조회 최소 주기를 1시간으로 상향. 기존에
5/10/30분으로 설정해둔 지역 3건은 마이그레이션(`20260811120000_...sql`)으로
자동 1시간 이관.

### 9. 토지(대지) 투자분석 확장 (2026-08-11)

**배경**: real_estate_sales를 "일단 종료하고 새 서브프로젝트를 진행하자"는 요청에서
출발해, data.seoul.go.kr/data.go.kr/vworld.kr 공공데이터를 활용할 수 있는 새 비즈니스
아이디어를 함께 조사(콘텐츠 자동화, 상권분석 리포트, 부동산 토지분석, 거시경제 브리핑
4가지)한 뒤, 사용자가 "기존 부동산 투자분석에 투자분석을 확장하는 형태"(가장 재사용
자산이 많고 난이도가 낮은 방향)를 선택. **완전 신규 서브프로젝트가 아니라
real_estate_sales의 기능 확장**으로 진행됨.

**API 조사 결과**: VWorld가 이미 연동된 것과 같은 포털(`api.vworld.kr/ned/data`)로
개별공시지가(`getIndvdLandPriceAttr`)와 토지이용계획(`getLandUseAttr`, 용도지역/지구/구역)을
제공 — 새 API 키/도메인 등록 없이 기존 `VWORLD_API_KEY`/`VWORLD_REGISTERED_DOMAIN`을
그대로 재사용. 실제 응답 필드명은 문서로 확인이 안 돼(브이월드 공식 문서 페이지가
검색으로 잘 안 잡힘) **임시 디버그 라우트를 배포해 실제 PNU로 직접 호출**해서
`pblntfPclnd`(개별공시지가, 원/㎡), `prposAreaDstrcCodeNm`(용도지역/지구/구역명) 등
정확한 필드명을 확인한 뒤 구현, 확인 후 디버그 라우트는 삭제함 — 이 프로젝트 초기의
"Phase 0 스파이크" 방식과 동일한 접근.

**설계 결정**: 지번 주소 → PNU 변환(지오코딩) 인프라를 새로 만드는 대신, 이미 모든
매물(`real_estate_listings.pnu`)에 PNU가 자동 계산되어 있다는 점을 활용해 **"이
아파트가 깔고 앉은 토지" 정보를 매물 상세 페이지에 자동으로 얹는 방식**으로 스코프를
좁힘 — 사용자 입력(주소 검색 UI) 전혀 필요 없이 기존 매물 흐름에 얹혀서 나옴. 공시지가는
연 1회만 갱신되므로 매물마다 다시 부르지 않고 PNU 단위로 `real_estate_land_info`에
캐싱(같은 단지 여러 동/호가 같은 PNU를 공유하는 경우가 많아 캐싱 효과가 큼).

**구현**:
- `src/lib/publicdata/client.ts` — `fetchLandPrice()`, `fetchLandUsePlan()` 추가
  (기존 `fetchApartAssessedPrice()`와 동일한 VWorld 호출 컨벤션).
- `src/lib/realestate/collect.ts` — `ensureLandInfo(pnu)`: 캐시 확인 → 없으면 두 API
  병렬 호출 → 최신 `lastUpdtDt` 기준 공시지가 선택 + 용도지역/지구/구역명 전체를
  중복제거해서 콤마 join → upsert.
- `src/lib/actions/analysis.ts` — `runListingAnalysis`에서 `ensureLandInfo` 호출해서
  분석 프롬프트에 토지 정보 포함.
- `src/lib/ai/analyze.ts` — 시스템 프롬프트에 "토지 정보가 제공된 경우" 지침 추가
  (개별공시지가 대비 거래금액의 토지가치 배율, 토지거래허가구역 등 규제 키워드,
  용도지역 종별에 따른 재건축/용적률 관점 코멘트를 `rationale`에 반영하도록 지시).
- `src/app/(dashboard)/listings/[id]/page.tsx` — "토지(대지) 정보" 섹션 추가.
- 신규 테이블 `real_estate_land_info` (PNU 기준 전역 캐시, `real_estate_listings`와
  동일하게 인증 사용자 read + service-role write RLS).

**검증**: 실제 매물(청담동 아파트, PNU 1168010400100140000)로 매물 상세 페이지를 열어
개별공시지가 16,350,000원/m², 용도지역에 "제2종일반주거지역"·"토지거래계약에관한허가구역"
등이 정상 표시되는 것을 확인했고, AI 분석 rationale에도 "토지 개발 기회보다는 제한
요소가 많은 것으로 판단됩니다"처럼 토지 정보가 실제로 반영된 것을 확인. DB
(`real_estate_land_info`)에도 캐시 행이 정상 생성됨을 대조 확인.

## 알려진 이슈 / 다음 업그레이드 후보

`README.md`의 "현재 상태 / 남은 작업"과 동일하게 유지되는 항목들:

- **가격 정책 미정** — `pricing_plans`가 없어 관리자가 개별 권한을 부여한 계정
  외에는 구독/결제 이용 불가.
- **카테고리/썸네일 미설정** — `/programs` 목록 노출용 메타데이터 필요.
- **서울만 지원** — 경기/인천 등 확장 시 `src/lib/publicdata/districts.ts`에
  자치구 코드 추가 + 다른 지자체 오픈데이터 API로 교체 필요 (서울 열린데이터광장
  API는 서울시 전용).
- **VWorld 등록 도메인**이 아직 과거 n8n 서버 도메인(`n8n.buylife.xyz`)으로 남아
  있음 — VWorld 개발자 포털에서 실제 서비스 도메인으로 바꾸고
  `VWORLD_REGISTERED_DOMAIN` 환경변수만 갱신하면 됨 (사용자의 VWorld 계정 로그인
  필요, README "VWorld API 키 도메인 등록 주의" 절 참고).
- **매물 호가(현재 판매 매물) 데이터**는 공식 공공 API가 없어 이 서비스 범위 밖 —
  다루려면 크롤링/제3자 API 검토 필요 (섹션 6 참고).

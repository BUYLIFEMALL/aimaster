## B0 측정 결과 (2026-11-03, v1.40 `/api/admin/report-probe`, 관리자 로그인)
표본 21곳(아파트 8·빌라 6·오피스텔 6·임장 1, 동탄·부산·일산·서초·방배·창신 등). 전체 칸 채움 **34%**(기준 70% 미달).

| 칸 | 채움률 | 메모 |
|---|---|---|
| 공시가격 | 95% | 오피스텔은 「대상 아님」으로 계산(채움) |
| 개별공시지가 | 95% | 오피스텔 1곳 빔 |

| 같은 단지 매매 3건+ | 14% | **우리 DB는 지역별 회당 20건이라 단지 단위로 부족** |
| 같은 단지 전세 | 5% | 위와 같은 이유 |
| 사용승인일·용적률·건폐율·주차 | 0% | **21곳 모두 표제부 API 403** — 전유부(같은 서비스·같은 키)는 동작하므로 키의 표제부 권한·차단 문제로 추정(미확인). 하루 한도(429)와는 다른 응답 |

**B1 범위 판단(제안)**: ① 공시가·공시지가·용도지역은 그대로 쓴다. ② 같은 단지 실거래·전세는 DB가 아니라 리포트를 열 때 그 법정동 12개월치를 국토부 API에서 바로 받아 단지·면적으로 거른다(매매·전세 각 월 1회 = 최대 24회, 캐시). ③ 표제부 4칸은 403 원인을 확인한 뒤 붙인다 — 다음 날 한 번 더 재고, 그래도 403이면 공공데이터포털에서 「국토교통부_건축HUB_건축물대장정보 서비스」 활용 신청 상태를 주인님이 확인. 그 전에는 「자료 없음」으로 표시.

## B1 배포·확인 (2026-11-03, v1.41)
- 새 메뉴 「📄 주소 리포트」(`/report`), 실거래 상세 「📄 이 단지 주소 리포트」, 임장 기록 「📄 주소 리포트 보기」. 같은 단지는 국토부 12개월(유형 모르면 세 유형 6개월)을 **지번 번호**로 맞추고, 이름·동이 같으면 함께 센다. 계산은 `src/lib/realestate/report.ts`(시험 `tests/report.test.mjs`), 호출은 `reportData.ts`. 건축HUB 주소 https로.
- 크롬 확인(관리자, 마곡수명산파크3단지): 화면·공시가·공시지가·용도지역 정상. **매매·전세·건물 칸 빈 칸 — 국토부 AptTrade·AptRent·건축HUB 표제부 모두 403.**
- 원인 조사: 관리자 계정에는 본인 공공 키가 없어 운영자 공용 키로 호출됨. 공용 키(Vercel Sensitive, 84일 전 만든 그대로)로 받은 국토부 자료는 **2026-11-02 23:23(한국 시간)이 마지막**이고 그 뒤 없음 → 키 값이 아니라 공공데이터포털 쪽 상태(승인·트래픽·계정) 문제로 추정(미확인). B0 표제부 0%도 같은 원인일 수 있다.
- 남은 일: 거부 사유 코드(예: `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`, 트래픽 초과 코드)를 화면 오류에 보이게 한 수정은 **미배포 대기**. 주인님이 공공데이터포털 마이페이지에서 공용 키 상태 확인 → 정상화 뒤 리포트 다시 확인.

## 규칙 점검
- 회원 본인 키: AI는 회원 키만. 공공 무료 키는 기존 예외(§8) 범위 — 주소 검색 키를 추가하면 같은 문서 §8에 적는다.
- 보관: 리포트·호가 입력은 회원별·RLS, 기존 `real-estate-sales` 1년 지정 안.
- 표현: 「급매」「신고가」 대신 근거와 기간을 함께. 참고용 고지.

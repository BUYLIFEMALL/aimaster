# 개발 플랜 — RQ-C 지역 뉴스 레이더 (2026-11-09, 결정 대기)

> [역할: realty] Claude Code(윈도우) `claude-win-realty-docs`. 근거: `docs/analysis-realty-roadmap-20261031/PLAN.md` §C(순서 결정 2026-11-02: A2·A3 → B → D → **C**, 앞의 묶음은 모두 끝남).
> 이 문서는 플랜입니다. 코드·DB는 아직 바꾸지 않았습니다. 아래 「결정 항목」 답을 받은 뒤 구현합니다.

## 1. 무엇을 만드나
실거래 프로그램(`real_estate_sales`, 지금 v1.56)의 **관심 지역마다 개발·교통·학교·규제 소식을 매일 아침 한 번 모아** 텔레그램·알림톡으로 보내고, 화면에 「📰 지역 뉴스」로 쌓아 둡니다. 새 프로그램을 만들지 않고 기존 관심 지역·알림을 그대로 씁니다(로드맵 판정 「기존 기능 확장」).

- 처음 설정 **2단계**: 설정 화면에서 네이버 검색 키 등록(이미 다른 프로그램에 등록했다면 0단계) → 관심 지역 화면에서 「지역 뉴스 받기」 켜기.
- 매일 조작 **0번**(아침 알림을 읽기만). 동의 **0번**(새 외부 계정 연결 없음).

## 3. 동작
1. **검색**: 지역마다 분류 4개 × 검색어 1개 = 하루 4번(뉴스, 최신순, 20건씩).
   - 개발: `<시군구> 재개발 OR 재건축 OR 정비구역`
   - 교통: `<시군구> GTX OR 지하철 OR 역 신설`
   - 학교: `<시군구> 학교 신설 OR 학군`
   - 규제: `<시군구> 토지거래허가 OR 조정대상 OR 투기과열`
   - 네이버 검색은 OR 연산을 보장하지 않으므로 사전 검증에서 결과를 보고 「검색어 여러 개 × 적은 건수」로 바꿀 수 있습니다.
2. **새 문서만**: 링크(정규화) 해시로 이미 받은 것은 뺍니다. 제목이 거의 같은 기사(같은 보도자료 재전송)는 하나로 묶습니다.
3. **분류**: 검색어가 정한 분류를 기본으로 하고, 제목 낱말 규칙으로 고칩니다(무료). AI 분류는 쓰지 않습니다.
4. **AI 요약(회원이 켤 때만)**: 그날 새 문서 제목·네이버 요약문만 넣어 회원당 하루 1번 「오늘 지역 소식 3줄」을 만듭니다. 본문은 가져오지 않습니다.
5. **알림**: 아침에 한 번, 분류별 건수 + 제목 상위 몇 개 + 원문 링크. 새 문서가 0건이면 보내지 않습니다.
6. **화면**: 좌측 메뉴 「📰 지역 뉴스」 — 지역·분류 거르기, 날짜별 목록(제목·언론사·날짜·원문 링크), AI 요약이 있으면 맨 위 카드.

## 4. 저장 (운영 DB `esgxyikcnnvmlhygjkth`, 마이그레이션 1개 — 사전 승인)
- 표 `real_estate_news_items`: `user_id`·`sgg_code`·`category`·`title`·`link`·`link_hash`(회원+해시 unique)·`source`·`published_at`·`snippet`·`created_at`. 본인 전용 RLS(`auth.uid() = user_id`).
- 표 `real_estate_news_digests`: 회원·날짜별 AI 요약 1줄(켠 회원만).
- 회원 설정 칸: `news_enabled`(기본 꺼짐)·`news_ai_summary`(기본 꺼짐)·`news_sent_on`(마지막 보낸 날짜).
- 다른 회원과 공유하는 캐시는 만들지 않습니다(같은 지역이라도 회원별로 저장).
- 보관: 결정 3번에 따릅니다. 정리는 기존 `cleanup-sentiment` 안에 줄을 더합니다(관리자·시험 계정 `retention_exempt` 제외 규칙 그대로).

## 5. 저작권·표기
- 저장·표시는 **제목, 언론사, 날짜, 네이버가 준 요약문(짧은 일부), 원문 링크**까지만 합니다. 본문을 긁어 오지 않습니다.
- 화면과 알림에 「출처: 각 언론사, 네이버 검색」을 적고, 원문은 항상 링크로 엽니다.

## 7. 순서
1. **사전 검증(무료, 코드 변경 없음)**: 시험 계정 네이버 키로 고양시 일산동구·강서구 검색 4분류를 각각 1번씩 돌려 결과 품질(관계없는 기사 비율, OR 동작)을 봅니다. 시험 계정에 네이버 키가 없으면 주인님께 등록을 여쭙니다.
2. 마이그레이션(승인 뒤 ego SQL 편집기).
3. 서버: 검색·새 문서 거르기·분류·저장·알림 묶음, 시험 코드(`tests/newsRadar.test.mjs`).
4. 화면: 메뉴·목록·설정 켜기 칸, 390px 확인.
5. 로컬 `tsc`·시험·`npm run build` → 배포(빌드 1회) → 시험 계정으로 다음 날 아침 알림 도착과 화면 확인.
6. 문서: AGENTS.md·프로그램 비교표 카드·역할 파일·카테고리 작업표.

## 8. 결정 항목 (주인님)
1. **블로그 글도 같이 받을까요?** 추천: 뉴스만. 블로그는 광고 글이 많아 관계없는 비율이 높습니다(2차에서 다시 검토).
2. **AI 요약 기본값**: 추천 「꺼짐(회원이 켬)」. 회원 키 비용이 들기 때문입니다.
3. **보관 기간**: 이 프로그램은 생성 데이터 1년 정리로 지정돼 있습니다(RE-P1). 추천 「뉴스 목록 90일, AI 요약 1년」 — 뉴스는 오래 둘 이유가 적습니다. 1년으로 통일해도 됩니다.
4. **알림 시각**: 추천 아침 8시(고객관리 알림과 같음).
5. **지역 수 상한**: 추천 회원당 관심 지역 중 앞 5곳(하루 검색 20번).
6. **이름**: 메뉴 「📰 지역 뉴스」, 설정 「지역 뉴스 받기」(추천).

## 9. 안 하는 것
- 기사 본문 수집·저장, 언론사 사이트 직접 긁기.
- 운영자 네이버 키로 대신 검색(최상위 규칙 — 키가 없으면 「네이버 검색 키를 등록해 주세요」 안내).
- 다른 회원과 결과 공유 캐시.
- 새 프로그램 만들기, 새 예약 주기 추가.

## 2. 등기부 PDF 읽기 — 동작
1. 리포트 화면 「🧾 등기부로 권리 점검」 칸에 PDF 1개 올림(4MB 이하, 인터넷등기소 발급본).
2. 서버가 메모리에서만 읽어 **회원 본인 Claude 키**(이미 AI 총평에 쓰는 `anthropic` 키, 모델 `claude-sonnet-5-5`, 재시도 0, 구조화 응답)로 보냄.
3. 결과 표: 소유권(현재 소유자 수·최근 이전일, **이름은 가림 「김○○」**), 근저당(채권최고액 합계·건수·말소 여부), 압류·가압류·가처분·경매개시, 가등기, 신탁, 전세권·임차권등기, 발급일. 항목마다 「위험/주의/참고」와 등기부 순위번호.
4. 리포트의 매매·전세 중간값과 합쳐 「채권최고액 + 전세 보증금 ÷ 매매 시세」(깡통 위험 비율)를 계산해 보여 줌.
5. 안내: 「참고용, 법률 자문 아님. 계약 직전 등기부를 다시 발급해 확인하세요.」

**저장하지 않는다:** PDF 원본·추출 글·결과 모두 DB·저장소에 남기지 않는다(화면에만). 서버 기록(log)에도 내용을 찍지 않는다. 저장 리포트에 넣을지는 나중에 따로 결정.
**하지 않는 것:** 등기부 자동 열람·발급(인터넷등기소 대행), 여러 건 일괄 처리, 매수 추천.

## 3. 개인정보 점검 (로드맵 112줄 「구현 전 별도 점검」)
- 등기부에는 소유자·채권자 이름, 주민번호 앞자리, 주소가 들어 있다. 처리: 회원이 직접 발급해 올린 자료를 그 회원 화면에만 보여 주고 저장하지 않음(30일 규칙 대상 자료 자체가 없음).
- AI 업체로 보내는 문제: 회원 본인 Claude 키로 회원이 고른 처리이므로 화면에 「등기부 내용이 회원님의 Claude 계정(Anthropic)으로 전송되어 분석됩니다」를 올리기 전에 보여 주고 체크해야 올리기가 됨.
- 결과 화면에는 이름을 가려 보여 준다(AI 지시 + 서버에서 한 번 더 가림).
- 확인 못 한 것: 개인정보보호법상 회원(중개사·개인)의 처리 근거는 회원 몫이고, 우리는 수탁 처리를 하지 않는 구조(저장 없음)로 둔다. 법률 검토는 하지 않았다 — 공개 전 주인님 판단.

## 구현 순서

1. **실측 데이터로 기준 맞추기(무료, 읽기만)** — 운영 DB(ref `esgxyikcnnvmlhygjkth`) `real_estate_news_items`에서 최근 3일 제목을 읽어, 아래 A·B 규칙을 적용하면 몇 건이 빠지거나 묶이는지 먼저 셉니다. 잘못 빠지는 기사가 보이면 규칙을 조정합니다.
2. **A — `regionTerms` 고치기**
   - 시+구 지역의 통과 이름 = 구 전체 이름 + 구 줄임 이름(「동탄구」→「동탄」, 「영통구」→「영통」, 「일산동구」→「일산」처럼 끝의 동·서·남·북구를 뺀 이름, 2글자 이상만).
   - 시 이름(「화성」「고양」)만 있는 기사는 **빼기(추천)**. 「화성시 동탄」처럼 쓴 기사는 줄임 이름으로 통과하므로 놓치지 않습니다.
   - 서울 「강서구」 같은 단일 구, 「중구」의 시·도 확인 규칙은 그대로입니다.
3. **B — 같은 사건 묶기 함수 `storyKey`/`isSameStory` 추가**
   - 제목에서 괄호·기호를 빼고 2글자 이상 낱말로 나눈 뒤, 지역 이름·검색 낱말(재건축·GTX 등)·흔한 낱말(아파트·단지·추진 등)은 뺍니다.
   - 같은 지역 안에서 남은 낱말이 3개 이상 겹치거나, 숫자 낱말(「20억」「84㎡」)을 포함해 2개 이상 겹치면 같은 사건으로 봅니다.
   - 같은 날 묶음 안에서는 먼저 나온 기사(제목에 지역 이름 있는 쪽이 앞)만 남깁니다.
   - **지난 3일에 이미 받은 기사와도 비교(추천)**: `runner.ts`에서 그 회원·그 지역의 최근 3일 제목을 한 번 읽어 같은 사건이면 넣지 않습니다(다음 날 다른 언론사가 같은 내용을 내도 다시 오지 않게). 회원당 하루 DB 읽기 1번 늘어남.
4. **시험** — `tests/newsRadar.test.mjs`에 추가: 광명 철산자이 기사 → 동탄구 탈락, 「화성시 동탄」 기사 → 통과, 「일산」 기사 → 일산동구 통과, 재초환 탄원 두 언론사 제목 → 묶임, 다른 사건 두 제목 → 안 묶임. 기존 `regionTerms` 기대값(6번 줄 `["일산동구","고양"]`)은 새 규칙 값으로 고칩니다(지우지 않음).
5. **로컬 검사(무료)** — `node --test`, `npx tsc --noEmit`, `npm run build`.
6. **버전·배포** — `lib/version.ts` v1.60 + 마이그레이션 `*_version_v1_60.sql` + 운영 DB `programs.version`. Vercel 빌드 1회(배포 직전 승인).

- 줄임 이름이 흔한 낱말과 겹치는 지역(예: 용인시 수지구 →「수지」)은 엉뚱한 기사가 섞일 수 있습니다. 지금 회원 관심 지역에는 없으며, 생기면 그 지역만 줄임 이름을 쓰지 않는 예외 표로 막습니다.
- 「일산」은 일산동구·일산서구 양쪽에 걸립니다(두 곳 모두 관심 지역이면 같은 기사가 두 지역에 나올 수 있음 — 지금과 같은 수준).

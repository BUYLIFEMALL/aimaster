# 개발 플랜 — 상가·건물·토지 실거래 알림(새 프로그램)

상태: 주인님 승인 대기(2026-10-31). 승인 전에는 폴더·DB·Vercel 프로젝트를 만들지 않는다.
작성: [역할: realty] Claude Code(윈도우) `claude-win-realty-docs`
근거: 주인님 지시 「지금까지 부동산 자동화 프로그램을 만든 경험과 노하우를 잘 살려서 만들어봐」, 묶음 방향(2026-10-31) 「상가/건물/토지를 하나로 묶던가 묶기 힘들면 상가/건물, 토지로」.

## 1. 결론
- 자료 모양이 거의 같아 **한 프로그램으로 묶을 수 있다.** 나눌 필요가 없다.
- 첫 버전은 국토부 실거래 **조회·알림**이다. 네이버 매물 읽기(`HANDOFF_20261025_BUILDING_LISTING_ALERT.md`)는 보류 그대로 두고 별도로 판단한다.

자료에 없는 것: 상가 임대료·수익률, 매도·매수 호가, 정확한 주소.

## 3. 범위 (v1.01)
1. 지역 고르기: 시·도 → 시·군·구, 256곳. 지역 찾기 칸 포함.
2. 유형 고르기: 상가·업무 등 건물 용도, 일반/집합, 토지 지목. 숙박·도로는 기본 꺼 둠(회원이 켤 수 있음).
3. 조건: 금액, 면적, 평당가, 용도지역.
4. 목록: 필터·정렬·쪽 나누기·열어 본 줄 표시·CSV. 지분·취소·직거래 표시.
5. 상세: 같은 동·같은 분류의 평당가 중간값 대비(최근 12개월, 표본 5건 미만이면 표시 안 함). 집합 건물만 지번 공개 표시.
6. 알림: 조건에 맞는 새 거래를 텔레그램으로. 회원 공용 연동값 재사용.
7. 연동 & 사용 매뉴얼(`/guide`), 「자료 한계」 고지: 지번 가림·신고 지연·임대료 없음. 투자 판단 보증 안 함.

하지 않는 것: 네이버 매물, AI 분석, 임대료·수익률, 줄 단위 공시지가, 아파트·빌라·오피스텔(실거래 프로그램 몫).

## 4. 기존 프로그램에서 가져올 경험
| 겪은 일 | 이번 적용 |
|---|---|
| 동시 호출 429(v1.31) | 순차 호출·2초 뒤 1회 재시도(`molitGet`) |
| 승인돼도 호출이 막힘(연립 403 진행 중) | 한 자료가 막혀도 나머지는 수집, 화면에 상태 표시 |
| 잘못된 신청 번호(매물 알림 v1.27) | 번호를 코드 상수 한곳에, 기록 남김 |
| 통합 지역 코드(전남광주) | 256곳 목록 재사용, 표본 대조 |
| 중복 확인 조회 실패(v1.33) | 100개씩 나눠 조회(`findExistingKeys`) |
| 새 칸 값 누락(v1.33 `deal_type`) | 기본값 + 코드 명시 + 시험 |
| 튀는 값·특수 거래(v1.30) | 지분·취소를 통계에서 제외, 표본 수 기준 |
| 알림 폭주 우려(v1.33) | 기본값은 좁게, 회차당 상한 |
| 인쇄 어색한 금액(월세 0.01억) | 금액 표기 시험을 처음부터 |
| 시간 제한 300초 | 회차를 지역 묶음으로 나눔 |
| 만료 회원 수집(v1.20) | 수집·알림에서 권한 확인 |
| 신고 없음과 수집 실패 구분(매물 알림 v1.37) | 지역별 마지막 수집 시각·결과 표시 |

코드는 실거래 프로그램에서 복사한다: `molit.ts`·`client.ts`의 호출부, `districts.ts`, `DistrictSearch.tsx`, `ListingMatrix.tsx` 틀, 권한 `lib/access.ts`, 좌측 메뉴, 설정, 알림, CSV. 지번 가림과 필지 조회가 얽힌 `collect.ts`는 새로 쓴다.

## 5. 구조
- 폴더 `<slug>/`, 독립 Next.js 앱, Vercel 프로젝트, `<slug>.buylife.xyz`, 공용 DB.
- 표 3개: 공용 거래 표(공개 자료, 로그인 회원 읽기만, 쓰기는 서버만), 회원 설정·감시 지역(회원별 RLS), 회원별 알림 기록(회원별 RLS).
- 수집: 회원이 고른 지역만, 하루 1회, 이번 달+지난달. 5분 호출마다 지역 몇 곳씩 처리. 전체 256곳이어도 토지 약 512건이라 한도 1,000 안이다. 페이지 넘기기는 필수(화성 토지는 세 달 1,988줄).
- 고유 키: 코드·동·지번·날짜·금액·면적·분류 + 같은 키 안의 순번. 취소 칸은 키에 넣지 않는다.
- 호출량이 회원 수와 무관해 공용 키 구조가 맞다.

## 6. 단계와 검수
1. 뼈대·DB·수집: 시험 3개 지역 → 줄 수와 원본 대조, 재수집해도 안 늘어남.
2. 화면·알림: 시험 계정 `buylifemall@naver.com`으로 크롬 실제 창, 375px 포함.
3. 전국 표본 수집, 비교 수치 대조, 문서 6종·프로그램 비교표·카테고리 지도 갱신, FREE·준비중 여부는 주인님 결정.

## E-1 입력 검증 강화 (Maepsi M2·M3)

1. 입력 시작 전: 제목·본문·이미지가 비어 있는 새 편집기인지 확인(아니면 멈춤, 기존 내용 보존). 이미 입력 완료한 과제는 다시 입력하지 않음(이미 있는 과제 상태 확인과 맞춤).
2. 구간마다 확인: 제목 일치 → 문단 묶음마다 「본문 끝 일부가 들어갔는가·길이가 늘었는가」 → 이미지마다 「개수 +1·업로드 완료」. 확인 실패 시 그 자리에서 멈추고 중복 재입력 안 함.
3. 끝: 최종 제목·이미지 수 대조.
4. 발행 결과 판정: 임시저장·예약·발행 완료 문구와 예약 건수 증가로 결과 확정, 애매하면 「확인 필요」(지금의 글 주소·시각 기록은 유지).
5. 검증 함수는 확장 안 자기완결형(`chrome.scripting` 주입 제약, `naver-blog-auto-poster_web/AGENTS.md` §7). 안정되면 SEO 확장과 맞출 공용 기준 코드 후보로 `docs/SHARED_MODULES.md`에 제안.

## E-2 빠른 입력 모드 (회원 선택, 결정 (다))

1. 원고 발행 설정(`NaverPublishSettings`)에 「입력 방식」: **기본 — 사람처럼 입력(권장)** / **빠른 입력 — 문단 묶음 붙여넣기**. 기본값은 기본. 원고별 저장(`executionMode`와 같은 곳), 계정 기본값 저장은 선택.
2. 빠른 입력을 고를 때 안내(확인란 필수): 「입력이 빨라지고 표·서식이 그대로 들어가지만, 사람이 치는 방식보다 자동화로 보일 가능성이 있습니다. 계정 보호를 위해 한 번에 많은 글을 연속으로 올리지 마세요.」
3. 동작: 제목은 기본 방식 유지, 본문은 소제목+문단 묶음을 서식 HTML로 붙여넣기, 이미지는 지금 방식(파일 입력) 유지 — 붙여넣기 이미지는 시제품에서 더 안정적일 때만.
4. **먼저 시제품으로 방식 확인(구현 전):** ① 편집기 안에서 `DataTransfer`(text/html·text/plain)를 담은 붙여넣기 이벤트를 보냈을 때 스마트에디터가 서식대로 받는지 ② 안 받으면 실제 Ctrl+V(`chrome.debugger` 권한 추가 — 설치 회원에게 「디버거 연결」 안내가 새로 보이므로 주인님께 먼저 알림) + 클립보드 쓰기. 결과에 따라 한 가지만 구현.
5. 클립보드를 쓰는 방식이면: 붙여넣기 직전 내용 지문 대조(원격 접속 클립보드 공유 대비), 끝나면 원래 클립보드 복구.
6. 검증은 E-1을 그대로 사용. 확장 과제에 `inputMode`(`human`|`fast`) 추가 — **옛 확장은 모르는 값이면 기본 방식으로 입력**(하위 호환, 핵심 원칙 10).
7. 문서: `docs/PLATFORM_PATTERNS.md` §20에 「회원 선택 빠른 입력 모드(2026-10-24 주인님 결정)」 예외 기록(이 플랜과 함께 등록됨).

## E-3 간편 모드 화면 (Maepsi M1)

1. 새 화면 `/quick`(좌측 메뉴 맨 위 「간편 모드」): 주제 입력 → AI가 핵심 키워드 1·보조 3~5·화자 페르소나 추천(「페르소나 바꾸기」) → 이미지 장수(기존 에이전트 상한 그대로, 0장 허용 여부는 구현 때 확인) → 「글과 이미지 만들기」 → 완성 미리보기 → 「네이버에 입력」(기존 확장·발행 설정 그대로).
2. 생성은 **기존 에이전트 단계(기획·작성·윤문)를 자동으로 이어 부름** — 새 생성 엔진을 만들지 않음. 결과는 같은 보관함에 저장(30일 규칙 그대로).
3. 키는 회원 본인 키(없으면 등록 안내). 프롬프트는 에이전트 고유 것 사용(공유 금지 규칙).

## E-4 무료 입구 권한 (결정: 간편 모드 = 무료 입구)

1. `src/lib/access.ts`의 판정을 프로그램 이름을 받도록 일반화(`evaluateProgramAccessForUser(userId, slug)`) — 기존 호출은 그대로 `naver-blog-agent`.
2. 간편 모드 화면·간편 모드 API·**간편 모드 원고의 확장 과제 수신**은 「에이전트 권한 **또는** BLOG(`ai-auto-blog`, 현재 FREE 배지) 권한」으로 판정. FREE 배지 판정은 공통 순서(정지 → 관리자 → 핸드폰 → FREE → 구독 → 등급+사용기간) 그대로라 **새 권한 표·DB 변경 없음**.
3. 간편 모드 사용자는 간편 모드에서 만든 원고만 보고 입력할 수 있음(원고에 `mode: quick` 표시). 전체 기능(단계별 편집·여러 계정·예약 묶음 등)은 에이전트 권한 회원만 — 화면에 「전체 기능 보기」 안내.
4. 대시보드 레이아웃이 전체를 한 번에 막으므로, 간편 모드는 별도 경로 묶음(예: `src/app/(quick)/`)과 자기 레이아웃·권한 확인을 둔다. `dynamic`·`fetchCache` 두 줄 필수.
5. **BLOG 정리(이동 안내·비공개·FREE 배지 이전)는 이 단계가 운영에서 확인된 뒤 별도 작업**(비교 분석 매뉴얼 §6, 회원 권한·카탈로그 변경이라 그때 주인님 확인). 이 묶음에서는 BLOG를 건드리지 않는다.

## E-5 발행 방식 회원 선택 정리 (결정: 사람이 발행 / 자동 포스팅 중 회원이 선택)

1. 지금 있는 `executionMode`(`prepare` = 발행 직전까지 입력, `publish` = 자동 발행)를 화면에서 한눈에 고르게 정리: **① 직접 발행 — 입력만 하고 발행 버튼은 내가 누름** / **② 자동 임시저장** / **③ 자동 발행(즉시·예약)**. ②는 Maepsi의 임시저장 동작을 참고해 새로 추가(값 `draft`, 결과 판정은 E-1).
2. 원고별 선택 + 계정 기본값(설정 화면). **이미 저장된 원고·계정 값은 바꾸지 않는다.** 값이 없을 때의 기본은 지금 동작과 같게 둔다(기존 회원 동작 변화 방지) — 화면에 선택지가 항상 보이게 해 회원이 바꿀 수 있게 한다.
3. 간편 모드(E-3)도 같은 선택을 쓴다.
4. 옛 확장 하위 호환: `draft`를 모르는 확장이면 서버가 과제를 주지 않고 「확장을 새 버전으로 받아 주세요」 안내(기존 `supportsPrepare` 방식과 같게 `supportsDraft`).
5. 다른 블로그 프로그램(SEO·티스토리)은 이미 「입력만 / 자동 포스팅」 선택이 있음 — 이 묶음에서는 에이전트만, 용어 통일은 블로그 기능 비교표에 후보로 기록.

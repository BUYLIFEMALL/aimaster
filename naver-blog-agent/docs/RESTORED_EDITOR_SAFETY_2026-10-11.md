# v1.75 Chrome 복원 탭 보호와 실제 이미지 검수

2026-10-11, Codex. 에이전트만 수정하며 BLOG는 클로드 담당입니다.

## 재현·수정

- 증상: Chrome 재시작 후 기존 준비 편집기의 탭 ID가 바뀌면 preparedEditorTabs의 옛 ID로 보호하지 못하고, freshEditor 작업이 복원된 탭을 글쓰기 URL로 다시 이동시킬 수 있었습니다. 실제 보호 원고를 훼손하는 시험은 실행하지 않았습니다.
- 원인: 새 작업도 전체 탭에서 기존 편집기를 찾고 freshEditor일 때 URL을 갱신했습니다. 수동 작성 중인 미등록 편집기도 같은 위험이 있었습니다.
- 해결: extension/background.js의 editorTab에서 freshEditor 작업은 기존 탭 조회·선택·이동 없이 새 탭을 생성합니다. 회원의 명시적 세션 재연결은 기존 편집기 재사용 동작을 유지합니다. 기존 탭/입력 기록을 삭제하지 않습니다.
- 검사: 실제 worker를 VM 브라우저로 실행하는 회귀2개 추가. 수정 전 복원된 탭2가 선택돼 실패했고, 수정 후 탭 ID 변경/미등록 편집기/읽기 화면 보호와 새 탭 생성 통과. 확장 수명 검사34개 전체 통과. 실제 Chrome 재시작 후 새 prepare 확인은 후속이며 자동 검사와 구분합니다.
- 대시보드 다운로드 버전의 고정 v1.8.0을 APP_VERSION으로 연결했습니다. v1.75 웹/확장/다운로드/DB 릴리스 정보가 같은 값을 사용합니다. 서버 API·스키마·환경변수·키 변경 없음.

## 실제 회원 이미지 검수 진행

회원 buylifemall@naver.com의 정상 로그인 복구를 실제 화면으로 확인했습니다. 본인 등록 OpenAI gpt-4.1과 nanobanana 이미지 모델로 일반 검수 안내 원고를 생성했습니다. 키 값·비밀번호·쿠키·토큰을 읽거나 출력하지 않았습니다.

장수 전환 실패 후 계속 실행한 검수 도구 문제로 75dd90f0-7645-43bd-949d-68672af9da47 원고에는 제목이 3장을 언급해도 실제2장만 생성됐습니다. 3장 성공 표본으로 인정하지 않습니다. 사용자에게 즉시 알렸고, 제어 실패 시 throw 및 생성 전 선택 장수 확인을 추가했습니다. 원고를 삭제하지 않고 별도 증거로 보존합니다.

현재 모든 새 원고는 draft이고 최종 발행은 실행하지 않았습니다. 새로고침 후 회원 UI 복원, 실제 새 prepare의 이미지 장수/순서, 개별 교체/삭제·실제 부분 실패 복구 검수는 완료로 기록하지 않습니다. 이전 v1.69 prepare18/18·이미지4장 증거와 이번 새 유료 생성 검수를 구분합니다. 임시 장수 제어 북마크는 검수 종료 시 삭제/검색0건 확인해야 합니다.

## 릴리스 절차

v1.75 로컬 빌드·타입 통과, 핵심 Node 검사100개+추가 공유 입력 검사14개(겹치는 검수28개 제외)=114개, 확장 수명34개 통과. 발행 설정/상태 검사 통과. 대시보드 lint 오류0/기존 경고12개. React 검토는 기존 UI·흰색 배경을 유지하고 버전 상수만 재사용하며 새 상태/효과/네트워크 호출을 추가하지 않습니다.

커밋·푸시·프로덕션 배포·DB 같은 SQL 버전 갱신·라이브 ZIP·PC 확장 적용은 배포 후 결과를 이 문서에 추가합니다. 설치된 확장은 자동 갱신되지 않으므로 최신 ZIP 재다운로드 → 기존 폴더 덮어쓰기 → chrome://extensions 새로고침이 필요합니다. 기존 준비 탭은 유지합니다.

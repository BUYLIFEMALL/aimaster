## 조사 결론 (읽기 조사 + 코드 직접 확인)

받는 쪽은 네이버 블로그 에이전트. BLOG(`ai-auto-blog`)는 독립 유지·변경 없음. 에이전트에는 이미 빈 편집기 확인(2초 유지·새 탭), 단계별 정확 대조(`matchingWriterPrefix`), 대상 블로그·계정 확인, 조건부 선점·runId·임대·heartbeat, 결과 선보관·영수증, 선점 응답 유실 `recovery`, 발행 불확실 시 재발행 금지, 옛 확장 호환이 **이미 있다** — 다시 만들지 않는다.

남은 빈틈 2개:

| # | 빈틈 | 근거 | BLOG의 대응 |
|---|---|---|---|
| 1 | 본문이 빈 원고도 제목만 입력하고 진행 | `buildWriterSteps`가 빈 본문이면 제목 단계만 만듦, `verify`의 기대값이 비어 통과(`extension/editor.js:426,429`), 서버 task·검수도 빈 본문을 거르지 않음 | `EMPTY_TITLE`/`EMPTY_BODY`로 시작 전 거절(`ai-auto-blog/extension/blog-engine.js:36-37`) |
| 2 | 발행 직전 최종 확인이 느슨 | `verify`가 `indexOf`로 순서 포함만 확인 → 문단 사이 중복·추가 내용 통과(`editor.js:429`). 정확 대조는 입력 단계에만 있고 이미지 AI 표시·발행 설정 뒤에는 다시 하지 않음 | 마지막에도 정확 대조(`blog-engine.js:173` FINAL_MISMATCH) |

가져오지 않는 것: BLOG의 「못 불러온 이미지 건너뛰고 완료」(누락을 완료로 처리해 더 약함), 이미지 위치만 보는 대조(에이전트가 파일명까지 봐서 더 엄격).

## 구현 (에이전트 v2.08 → v2.09)

1. **빈 본문 차단 — 두 겹**
   - 서버: 확장이 원고를 가져갈 때(`src/app/api/extension/task/route.ts`) 본문에 실제 문단이 하나도 없으면 가져가지 않고 원고를 `failed` + 「본문이 비어 있어 입력하지 않았습니다」로 남김(선점 전에 판단, 기존 409/recovery 흐름은 그대로).
   - 확장: `writeArticle` 시작 전 본문 단계 0개면 입력 없이 실패(옛 서버·직접 호출 대비).
2. **발행 직전 정확 대조** — 이미지 AI 표시와 발행 설정을 마친 뒤, 최종 발행 버튼 직전에 기존 `matchingWriterPrefix(현재 문서, 전체 단계) === 전체 단계 수`를 한 번 더 확인. 다르면 발행하지 않고 실패(원고 보존). 기존 `verify`의 인용구·섹션·이미지 수·AI 표시 확인은 그대로 둠. 자동 생성 링크 미리보기는 기존 함수가 이미 제외하므로 오탐 위험이 낮음.
3. 준비 모드(prepare)도 같은 최종 대조를 거친 뒤 `prepared`로 보고.

## 시험

- 무료 회귀: 기존 `scripts/test-*.cjs` 전체 + 새 시험 — 빈 본문 원고는 서버가 가져가지 않음/확장이 입력 안 함, 입력 후 문단이 중복·추가된 문서는 최종 대조에서 발행 0, 정상 문서는 통과, 옛 확장 요청 호환 유지.

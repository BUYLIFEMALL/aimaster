# v1.74 이미지 부분 생성·저장 복구 인수인계

2026-10-11, Codex. 에이전트만 수정하며 BLOG·티스토리는 클로드 담당입니다. 이 작업은 남은 작업3번의 이미지 경로 보완입니다. 실제 유료 이미지1~5장/새 네이버 입력 검수는 아래 제한과 구분합니다.

## 재현한 문제와 수정

- 5컷 중1컷 실패 시 기존 실제 페이지 콜백은 성공4장만 서버에 저장해 실패한 컷의 캡션·프롬프트를 잃었습니다. 새로고침 후 실패 컷 재생성이 불가능했습니다. 완료 URL과 미생성 계획을 같은 images 배열에 보존하고, 갤러리만 URL이 있는 컷으로 표시합니다. 각 성공 후 전체 계획과 진행 상태를 저장합니다.
- 일괄 버튼이 완료 컷까지 재생성했습니다. 이제 미생성 컷만 요청하며 완료 컷을 바꾸려면 해당 컷의 개별 생성 버튼을 사용합니다. 실패한 공급사 이유도 최종 오류 안내에 남깁니다.
- 저장 응답이 불확실하거나409 충돌로 막힌 상태에서도 유료 요청을 먼저 보낼 수 있었습니다. PostSaveClient.needsSaveRecovery로 원고 ID·저장 완료·미확인 요청·충돌·저장 중 상태를 확인한 뒤 요청합니다. 미확인 저장은 보관함 저장으로 재확인하고, 알려진 충돌은 최신 원고를 명시적으로 다시 엽니다. 이미 보낸 공급사 요청의 비용 환불이나 탭 간 생성의 원자적 선점 기능은 아닙니다.
- 삭제는 생성 갤러리의 컷을 기준으로 해당 계획도 제거합니다. 남은 미생성 계획은 보존하며 마지막 컷 삭제는 빈 배열로 유지합니다. 삭제 때문에 본문 이미지 태그가 바뀐 경우에만 본문을 함께 저장합니다.
- 저장/직접 검수 지문에 동일한 전체 이미지 목록을 사용합니다. 저장 배지는 확인된 서버 저장 버전이 있을 때만 표시하고, 이미지 저장 실패 시 확인 필요로 바꿉니다. 수동 저장에 성공하면 실패 안내를 해제합니다. 네이버 확장 전달은 기존처럼 URL이 있는 이미지만 포함해 옛 확장과 호환됩니다.

## 코드와 자동 검사

- src/app/(dashboard)/page.tsx: 전체 이미지 목록 유지, 미생성 재시도, 요청 전 저장 확인, 개별 삭제·갤러리·저장 지문.
- src/lib/draftImages.ts: 완료/미생성 목록 분리.
- src/lib/postSaveClient.ts: 읽기 전용 저장 복구 판정. 서버 API·DB 스키마 변경 없음.
- scripts/test-queue-confirmation.cjs: 신규5개. 수정 전2개 실패(계획4/5개, 저장 미확인 상태에서 유료 요청6회); 수정 후 통과했습니다.
- 실제 TypeScript 페이지 콜백·저장/목록 API·확장 payload 변환을 모의 DB/공급사로 실행해1~5장 각 성공 후 전체 계획 유지, 저장→목록→불러오기→확장 URL 순서/장수 일치를 확인했습니다. 부분 실패/삭제/저장 거절/늦은 결과/충돌 보호도 검사합니다. 실제 공급사 호출이나 실제 Supabase 저장을 실행한 증거는 아닙니다.
- 관련 Node 검사114개, 기존 확장 수명32개 시나리오, 발행 설정/상태/편집 저장/회원 데이터/모델 검사 통과. 로컬 프로덕션 빌드·타입 검사 통과, 변경 TSX/도우미 lint 오류0·기존 경고29입니다.

## 실제 회원 검수 재개 조건

- 본인 검수 회원 buylifemall@naver.com의 OpenAI·Gemini·Replicate 키 등록 여부만 확인했으며 키 값은 읽거나 출력하지 않았습니다. 저장 기본값은 OpenAI gpt-4.1, nanobanana(Gemini 2.5 Flash Image),16:9,2장입니다. 다른 회원/운영자 키 폴백 없음.
- Chrome 재시작으로 에이전트 웹 세션이 종료돼 /login?redirect=%2Fdashboard에 머무릅니다. 저장된 회원 항목은 있지만 현재 도구의 자동 입력·키보드/초점 제어로 로그인 성공을 확인하지 못했습니다. 주인님께 해당 회원 로그인만 요청한 상태입니다. 비밀번호 조회·변경·쿠키/토큰 추출·로그인 우회 없음.
- 현재 PC 확장은 작업 시작 시v1.73 활성/오류 버튼 없음으로 확인했습니다. v1.74 설치 적용 여부는 별도 확인 대상입니다. 이번 웹 저장 형식은 기존 URL 없는 계획 형식과 같아v1.73 확장도 URL 있는 완료 컷만 사용합니다.
- 기존 네이버 편집기/준비 원고·회원 원고를 수정·삭제하지 않았고 새 유료 생성과 최종 발행은 실행하지 않았습니다. 기존 보호 원고9509d689…의 prepare18/18/이미지4장 검수는 이전v1.69 증거이며 이번 새 이미지 검수가 아닙니다.
- 로그인 완료 후 새 검수 원고에서 본인 키1~5장 생성, 각 저장/새로고침 복원, 실패 컷만 재시도, 개별 교체/삭제, 별도 빈 편집기의 prepare 장수/순서를 확인합니다. 실제 공개/예약 최종 발행은 해당 행위 승인 후 별도 진행합니다. 과거 버전에서 이미 사라진 실패 컷 계획을 자동 재구성하지 않습니다.

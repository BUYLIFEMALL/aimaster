## 2. 구현 순서와 검수

1. **랭킹 수집** — `src/lib/naverRanking.ts`(신규): 연예 `api-gw.entertain.naver.com/ranking/most-viewed`, 스포츠 `api-gw.sports.naver.com/news/articles/popular`, 경제 기존 섹션 목록. 본문은 각 `news/article/{oid}/{aid}` JSON에서 텍스트만 추출(이미지 URL 저장 안 함). 고정 호스트만 허용. `api/collector` 에 `action: "ranking"` 추가 → 기존 `structureBlogCandidates`(회원 본인 AI 키)로 글감화. 수집기 화면에 버튼 3개.
   - 검수: 단위 테스트(응답 파싱·호스트 제한), 로컬 실호출 1회씩, 배포 후 Vercel 서버에서 실제 수집(서버 IP 차단 여부 확인).
2. **홈판형 글 구성** — `pipeline.ts`에 `articleFormat: "standard" | "homefeed"` 입력 추가, 생성 화면에 선택칸. 기본값은 기존과 동일(standard).
   - 검수: 프롬프트 생성 단위 테스트, 테스트 계정 본인 키로 가장 저렴한 모델 1회 생성.
3. **간격 예약 일괄 전송** — 보관함 일괄 전송에 「즉시 / 예약(시작 시각·간격 분)」 선택. 선택 순서대로 `scheduled_at` 배정, 네이버 규칙(현재+10분 이후, 10분 단위 올림) 검증. 확장은 기존 예약 입력 그대로 사용.
   - 검수: 시각 배정 단위 테스트, 크롬에서 비공개 예약 1건 실제 등록 후 네이버 예약 목록 확인·삭제는 주인님 확인 후.
4. **쇼핑커넥트 링크** — 생성 화면 선택 입력(링크 최대 5개). 본문 각 섹션 끝에 링크 삽입, 글 첫머리에 공정위 대가성 문구 자동 추가. 링크 형식은 `naver.me`·`brandconnect.naver.com`·`smartstore` 계열만 허용.
   - 검수: 삽입 함수 단위 테스트, 화면 미리보기 확인.
5. 공통: `npx tsc --noEmit` → 테스트 → `npm run build` → 버전 v1.95(코드+DB+확장 manifest/ZIP, 원칙 10) → 커밋·푸시 → Vercel 1회 배포 → 크롬 실화면 검수(테스트 계정) → 인수인계 6종·역량 지도·아이디어 표 갱신.

## 4. 위험과 대응

- 랭킹 데이터 주소는 네이버 **비공식** 주소라 바뀌거나 막힐 수 있음 → 실패 시 「해당 랭킹을 불러오지 못했습니다, URL 수집을 이용해 주세요」 안내, 다른 기능에 영향 없게 분리.
- 이슈 기사 재작성은 유사 문서 위험 → 기존 윤문·검수 단계를 그대로 거치고, 출처 사실만 사용하도록 프롬프트에 명시.
- 쇼핑커넥트는 대가성 문구 누락 시 법적 문제 → 링크가 있으면 문구를 강제로 넣고 지울 수 없게 함.

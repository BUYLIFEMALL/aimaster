# BLC-04 사진 후기 원고 연결 계획

2026-10-21 Codex(윈도우). AIMaster 운영, DB ref `esgxyikcnnvmlhygjkth`.

## 문제와 범위

BLC-03 결과는 화면 메모리와 복사만 지원합니다. 기존 `PostSaveClient`의 UUID·요청 영수증·revision/CAS, 직접 검수 게이트, prepare 기본값과 비공개 사진 확장 기반을 재사용합니다. 다른 프로그램·스키마·권한·키·계정 설정은 바꾸지 않습니다.

## 구현 순서와 검수

1. 사진 후기 → 기존 결과/편집 영역 연결. 새 원고로 분리하고 기존 작업이 있으면 교체 확인, 진행 중 저장/생성 보호. AI 재생성 없이 제목·본문·사진 순서·대표·근거를 인계합니다.
2. 원고 `images`에는 정적 경로·사진 ID·설명·원래 등록/만료만 저장하고 근거는 기존 `research_summary.photo_review`에 보관합니다. 서버가 소유권·실제 Storage·중복·만료를 검사합니다. 새 사진 원고의 생성 기준일은 가장 오래된 사진의 등록일로 잡아 수명을 늘리지 않습니다. 조회 URL은 별도 UI 상태에만 둡니다.
3. 기존 편집기는 사진 원고에 원본 텍스트 모드를 사용해 서명 URL이 HTML에 저장되는 일을 막습니다. 사진 근거는 초기 초안의 자료임을 표시하며 편집 후 재검수를 요구합니다. 보관함 재열기·사진 미리보기 재조회·검수 지문 불변·대기열/준비 모드 회귀를 확인합니다.
4. 무료 자동 시험(타 회원/만료/URL 혼입/변조/중복·재시도·revision·1~6장), 타입·정적 검사·로컬 빌드 후 v2.04 한 묶음 배포. 지정 회원의 보이는 Edge에서 저장·편집·재열기·검수 해제·확장 준비를 확인합니다. 최종 블로그 발행은 하지 않습니다.

## 비용·릴리스·산출물

무료/모의 우선. 실제 후기가 필요하면 지정 회원 본인 키의 저렴한 지원 모델로 1회(관찰/작성 최대 2회)만 생성, AI 이미지 생성 0. 버전은 앱 v2.04/package·manifest 2.4.0/ZIP/운영 DB 메타데이터 동기화. 사용 안내 4단계 시각 카드 갱신, 실제 Edge 검수. 결과·한계·비용·배포·Git을 프로그램 IMPROVEMENTS/인수인계/AGENTS/README 및 루트 HANDOFF·작업목록·아이디어 표에 기록합니다. 회원 생성 본문·관찰 원문을 Git에 넣지 않습니다.

## 2026-10-21 추가 플랜 — 편집 후 열린 상세창 동기화

v2.04 배포 후 추가 검사에서 보관함 편집 ACK는 저장됐지만 뒤의 상세창 본문이 이전 값으로 남는 오류를 재현했습니다. 기존 회귀에 성공 ACK 후 상세창 검사가 없어 발견이 늦었습니다. `handleSaveEditor`가 같은 원고의 열린 상세창을 서버 ACK로 갱신하도록 보완하고 재현 시험을 추가합니다. 본문 snapshot이 바뀌어 기존 검수 게이트가 다시 조회하게 됩니다. 회귀·타입·로컬 빌드 후 v2.05/확장 ZIP/DB 메타데이터로 한 번 추가 배포하며, v2.04 이력은 보존합니다. 새 유료 호출·계정/권한 변경은 없습니다.

## 추가 시험 해석 정정

실제 보관함의 ‘스마트 에디터 편집’은 상세창을 닫으므로, 추가한 성공 ACK 모의의 ‘상세창이 열린 채 유지’ 조건은 현재 일반 UI 흐름과 다릅니다. 이를 실제 오류 재현으로 단정했던 설명은 잘못됐습니다. v2.05는 이 조건에서 같은 원고의 열린 상세창을 ACK로 동기화하는 보호이며 일반 편집 동작의 오류 수정으로 보고하지 않습니다. 실제 회원에서는 편집→저장→다시 열기에서 새 본문·STALE 검수 상태를 확인했습니다. 이 오판으로 추가 배포가 1회 발생했음을 기록합니다.

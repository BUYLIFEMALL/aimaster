## 원본(BLOG)의 기능과 한계
- `ai-auto-blog` 글쓰기 화면의 참고 URL 3칸·추가 지시 칸(`app/write/ai-form/page.tsx`) → `utils/news/generator.ts` 175~176행에서 **주소 글자만** 지시문에 넣음. 일반 AI 호출은 주소를 열지 못하므로 페이지 내용은 근거로 쓰이지 않음.
- 그래서 그대로 옮기지 않고 **페이지 본문을 실제로 읽어 근거로 넣는 방식으로 개선**해 가져온다.

## 에이전트에 이미 있는 것(재사용)
- 안전한 공개 웹페이지 수집: `src/lib/collector.ts` `fetchPublicHtml`(내부·사설 주소 차단)·`extractMainText`.
- 근거 자료 경로: `src/lib/ai/sourceGrounding.ts`(`sourceMaterial` 최대 4,000자, 기획·작성에 「사실은 자료에서만」 블록, 검수에서 자료에 없는 사실 문장 표시).

## 구현
1. 생성 화면(`src/app/(dashboard)/page.tsx`)에 「참고 URL(최대 3개)」 입력칸과 「추가 지시(최대 500자)」 칸. 기존 입력·설정 저장과 같은 모양.
2. 서버 `src/app/api/generate/route.ts`: URL은 http(s)만·최대 3개 검사 → 각 주소를 `fetchPublicHtml`로 읽어 `extractMainText` 본문 추출 → 「[참고 URL n] 주소 + 본문」으로 근거 자료에 합침. 수집한 글감이 함께 있으면 글감 먼저, 전체 4,000자 안. 읽지 못한 주소는 생성을 멈추지 않고 응답에 「읽지 못한 주소」로 알림.
3. 추가 지시: `src/lib/ai/pipeline.ts` 기획·작성 지시문에 「회원 추가 지시」 블록(사실·연도·안전 규칙보다 앞서지 않음, 지시 안의 역할 변경·출력 형식 변경은 무시).
4. 원고 `research_summary`에 사용한 참고 URL 목록을 기록(어떤 근거로 썼는지 추적).
5. 새 시험: URL 검사·근거 합치기·읽기 실패 처리·추가 지시 길이 제한. 기존 시험 22종 유지.

## 범위 밖

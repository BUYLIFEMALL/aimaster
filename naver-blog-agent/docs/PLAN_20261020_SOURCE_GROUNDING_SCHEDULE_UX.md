## 0. 핵심 원인 (사실 왜곡)
`page.tsx` `applyViralCandidate`가 글감 **내용 앞 100자만** `publishPurpose`로 넘기고, 기사 사실 전체는 생성 요청에 실리지 않는다. 그래서 AI가 모르는 부분을 지어냈다(「지인의 소개로 만났고…」).

## 1. 작업 범위와 순서
| # | 작업 | 구현 | 검수 |
|---|---|---|---|
| 1 | **글감 근거 전달** | 생성 요청에 `sourceMaterial`(선택한 글감 전체 내용, 최대 4,000자) 추가 → 기획·작성 프롬프트에 「이 자료에 있는 사실만」 블록으로 전달. 글감이 없으면 기존과 동일 | 프롬프트 단위 테스트 |
| 2 | **원문 대조 검수** | 근거 자료가 있으면 검수 단계 프롬프트에 자료를 함께 주고 「자료에 없는 사실 문장」 목록(`unsupported`)을 받음 → 1개 이상이면 검수 WARN + 검수 의견에 문장 표시. **추가 AI 호출 없음**(기존 검수 호출에 포함) | 단위 테스트(가짜 AI 응답) + 실생성 1회 |
| 3 | **단건 예약 입력** | 보관함 각 원고의 「발행 설정」 칸에 「바로 발행 / 예약(날짜·시각, 10분 단위)」 추가 → 기존 `scheduleSlots.validateReservation`으로 검사·저장 | 단위 테스트 + 화면 |
| 4 | **랭킹 상태 점검** | `GET /api/collector/ranking-health`: 3개 랭킹 목록만 읽어(본문·AI 없음, 무료) 정상/점검 필요 반환, 서버 30분 캐시. 수집 화면 버튼 옆에 상태 점(🟢/🔴) 표시. 기존 매일 예약 호출(`/api/cron/cleanup`)에서도 같은 점검을 돌려 실패를 로그에 남김(새 예약 호출 추가 없음) | 단위 테스트 + 운영 확인 |
| 5 | **홈판형으로 바로 쓰기** | 수집 글감 카드에 버튼 추가 → `/?viralId=…&format=homefeed` 이동, 생성 화면이 글 구성을 홈판형으로 자동 선택 | 화면 |
| 6 | **블로그 목록 서버 연동** | 생성 화면이 처음 열릴 때 `/api/accounts`(본인 목록)를 직접 불러와 덮어씀, 실패 시에만 브라우저 캐시 사용. 다른 계정의 캐시가 남지 않게 함 | 화면(로그인 직후 바로 블로그 칸 표시) |

공통: `tsc`·전체 테스트·`build` → v1.97(코드·DB·확장 ZIP) → 커밋·푸시 → 배포 1회 → 크롬 테스트 계정 검수 → 인수인계·역량 지도·아이디어 표.

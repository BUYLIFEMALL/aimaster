# BLOG 공통 입력 엔진 제안 검토와 에이전트 적용

작성일: 2026-10-10. 검토 대상: 클로드의 [공통화 제안](../../docs/SHARED_NAVER_ENGINE_PROPOSAL_2026-10-10.md), BLOG v1.49 실제 코드·AGENTS의 후속 시험 기록, 에이전트 v1.64. 주인님 지시에 따라 적용 여부를 판단하고 에이전트 v1.65에 필요한 보완을 진행합니다. BLOG 폴더는 수정하지 않습니다.

## 1. 판단

**제안 A(각자 입력기 유지 + 같은 규칙 검사)를 지금 적용합니다.** 공통으로 확인할 대상은 본인 블로그·빈 문서·문서 순서/중복·단일 프레임 변경·원본 보존·결과 선보관·보고만 재시도입니다. 두 입력 방식을 바꾸거나 공용 파일을 복제하기 전에 같은 사례에 실제 코드를 실행해 판단이 일치하는지 확인합니다.

C(순수 공통 규칙 파일과 해시 비교)는 양쪽 표현·검증 기준을 맞춘 뒤 검토합니다. 현재 엔진에는 아래 차이가 있어 파일 해시를 맞추면 에이전트의 더 강한 검증이 빠질 수 있습니다. B(공용 원본을 빌드 때 확장 폴더에 복사)는 현행 프로젝트 자체 완결·확장 소스 위치 규칙과 상충할 수 있어 채택하지 않습니다.

CDP로 교체하지 않습니다. 에이전트는 인용구·숨은 입력 프레임·이모지 분리·파일명 확인 경로를 이미 가지고 있고, BLOG와 속도/성공률을 같은 조건에서 실측하지 않았습니다. BLOG의 문자별 지연을 자동화 탐지 회피나 정책 준수의 보증으로 설명하지 않습니다.

## 2. 제안 체크리스트 검토 결과

| 항목 | 확인한 사실과 적용 판단 |
|---|---|
| 문서 비교 | 양쪽 모두 공백·제로폭 문자를 정규화하고 연속 문단을 합칩니다. 같은 사례의 제목 혼합·중복·순서 변경·이미지 누락/중복·예상하지 않은 구조는 양쪽 모두 중지합니다. 에이전트는 quote의 글자/스타일과 이미지 이름도 확인합니다. BLOG는 image를 위치로만 비교, linkPreview를 항상 제외하므로 동일한 검증으로 보지 않습니다. |
| 스냅샷·프레임 | 에이전트 snapshot은 paragraph/quote/image/linkPreview를 구분합니다. BLOG는 quote 등 복합 구조를 other로 봅니다. 탐색은 여러 프레임, 실제 변경은 확인된 한 프레임 원칙이 양쪽 현재 구현에 있습니다. BLOG의 단순화된 읽기 모델로 에이전트를 교체하지 않습니다. |
| 포커스 | BLOG v1.47~48은 이미 입력한 문단 재클릭 금지·끝의 빈 문단만 선택·안내 문구 제외를 적용했습니다. 에이전트 `lastBody()`·`readText()`도 빈 끝 문단 확인/원문 보존과 안내 문구 제거를 이미 수행합니다. 추가 좌표 클릭 방식을 그대로 복사할 필요가 없습니다. |
| 이미지 업로드 | BLOG는 CDP 선택창 처리와 file input 할당을 함께 쓰고, 에이전트는 file input 할당 후 완료 확인을 합니다. 에이전트는 이미지 시간 초과 후 자동 재업로드 금지 검사가 있습니다. 동일 원고/화면 조건의 실측 우열은 미확인입니다. |
| 실행 번호·임대 | 옛 실행 보고·PC 단절 판단에는 적합합니다. 다만 최종 클릭 시작/완료와 결과 보고 상태를 함께 보존해야 합니다. 임대 만료만으로 자동 재발행·queued 복귀하지 않습니다. `nba_posts` 컬럼 추가는 별도 승인 필요이므로 이번 릴리스에 적용하지 않습니다. |
| 번호로 시작하는 문장 | 에이전트는 문장 분할 때 `1.`만으로 문장을 나누지 않으며, snapshot이 예상하지 않은 목록 구조가 되면 문서 비교로 중지합니다. 실제 네이버 자동 목록 변환의 모든 형태를 검수한 것은 아닙니다. |

정규화 때문에 글자 간 공백·문단 나뉨이 달라도 동등하게 볼 수 있습니다. “정확 비교”는 정규화된 내용·요소 순서·이미지/인용구 확인 기준이며 띄어쓰기·모든 서식의 완전한 동일성을 보장한다는 뜻이 아닙니다.

## 3. v1.65에 적용한 보완

- **라이브러리 패널과 실제 팝업 구분:** BLOG v1.45 실제 시험에서 찾은 `role=dialog` 패널 오인이 에이전트 `activateParagraph()`에도 있었습니다. 실제 editorCommand를 모의 화면에서 실행해 재현했습니다. 보이는 `.se-popup-container` 중 제목/안내 문구가 있는 창만 입력을 막으며, 알림의 문구를 오류에 표시합니다. 라이브러리 패널·숨은 컨테이너는 차단하지 않습니다.
- **기존 문서 안전 중지:** 출처가 맞지 않는 linkPreview를 읽으면 빈 문서 검사에서 null.length 예외가 발생할 수 있었습니다. 이를 기존 내용을 보존하고 별도 빈 글에서 시작하라는 오류로 바꿨습니다. 변경·삭제·재입력은 하지 않습니다.
- **같은 규칙 검사:** `scripts/test-shared-input-rules.cjs`가 BLOG의 실제 `blog-core.js`와 에이전트 `writer.js`에 같은 문서 사례를 실행합니다. 이미지 이름/인용구/링크 카드 차이는 별도 검사로 고정해 에이전트 검증이 약해지지 않게 합니다. BLOG 코드·ZIP·DB 버전은 이 릴리스에서 수정하지 않습니다.

## 4. 검수·릴리스 범위

- `test:editor-safety` 4개: 라이브러리 허용, 실제 이어쓰기/제목 팝업 차단, 안내문 전용 팝업 차단·문구 표시, 숨은/제목 없는 컨테이너 허용. v1.64 이전 코드에서는 라이브러리 사례가 실패합니다.
- `test:shared-input` 14개: 공통10개와 에이전트 추가 검증3개, 기존 문서/비정상 링크 카드에서 변경 없이 안전 중지1개.
- 기존 결과 저장·탭 수명주기·확장·발행·저장 검사와 빌드를 실행합니다. 운영 배포 결과는 후속 기록합니다.
- BLOG 실제 시험 성공 기록은 클로드/주인님의 AGENTS 기록입니다. Codex가 BLOG의 실제 입력을 재검수한 것으로 보고하지 않습니다. 에이전트의 이번 팝업 검수는 실제 함수 모의 실행이며 네이버 실제 입력 E2E 검수와 구분합니다.

## 5. 다음 작업

1. 발행 전 준비 전용 상태·최종 발행 동작을 구분하는 2단계 설계/구현을 계속합니다. 기존 자동 발행 사용자의 승인 범위를 보존합니다.
2. 검수 결과 차단·최근 제목 전달·윤문 URL 보존, 이미지 장수·저장 일관성을 순서대로 보완합니다.
3. 실행 번호·임대의 구체 SQL·최종 발행 상태 보존안과 옛 확장 호환을 준비한 후 에이전트 DB 변경 승인을 받습니다. BLOG 승인 자체를 에이전트 승인으로 확대하지 않습니다.
4. 양쪽이 같은 원고·실제 빈 네이버 편집기로 입력/설정/안전 중지 검수를 마친 뒤 공통 규칙 C방식을 다시 판단합니다.

## 구현과 저장 규칙

- 사진 후기의 ‘원고로 저장·이어서 편집’으로 UUID 새 원고를 만들고 기존 `PostSaveClient`/revision/CAS/영수증·편집기·최종 검수·대기열을 사용합니다. 진행 중 저장/편집은 보호하고 현재 원고 교체는 화면에서 확인합니다. 저장 실패 후 아래 보관함 저장으로 같은 UUID를 재확인하며 같은 초안 연결 버튼을 다시 눌러 복제하지 않습니다.
- `images`에는 사진 ID·storagePath·대표/본문·설명·실제 등록일/만료만 저장합니다. AI 생성 대상으로 분류하지 않습니다. `research_summary.photo_review`에는 최초 초안의 관찰/회원 메모·문단 근거·확인 필요를 보관하며 기존 원고에서 교체할 수 없습니다. AI PASS를 부여하지 않습니다.
- 서버가 실제 Storage 소유권·존재·30일 만료·1~6장·대표 1장·중복·순서/근거 일치·본문 사진 위치 수를 검사합니다. 서명/Blob URL·HTML 사진 본문은 거절합니다. 새 원고 `created_at`은 가장 오래된 사진 등록일로 정해 재사용 시 수명을 연장하지 않습니다. 편집/조회는 생성일을 변경하지 않습니다.
- 임시 URL은 `SavedPhotoReview` 화면 상태에만 보관하고 다시 조회해도 원고/검수 지문을 바꾸지 않습니다. 사진 원고·근거는 공용 브라우저 캐시/미저장 캐시에 기록하지 않고 로그인 회원의 서버 보관함에서 다시 읽습니다. 기존 일반 글 캐시는 유지합니다.
- 사진 원고는 기존 편집기의 원본 텍스트 모드를 사용합니다. [IMAGE INSERT - …]를 유지하며 편집하고 사진은 별도 목록에서 대조합니다. 최초 근거는 편집 후 최신 문장에 대한 검수 증명이 아님을 표시합니다. 저장본 수정 후 기존 직접 검수 게이트가 해제됩니다. 새 원고는 prepare 기본값입니다.
- 사용 안내 4단계에 저장→편집→직접 검수→확장 준비를 반영했습니다. 기존 확장 사진 다운로드 직전 현재 실행 한정 갱신을 재사용하며 실행 코드는 변경하지 않았습니다.

## 구현과 데이터 규칙

- ‘원고로 저장·이어서 편집’으로 새 UUID를 만들고 기존 `PostSaveClient`/revision/CAS/영수증·편집기·직접 검수 게이트·대기열을 재사용합니다. 저장 실패 시 아래 보관함 저장으로 같은 ID를 재확인하고 같은 초안을 다시 연결해 복제하지 않습니다. 현재 원고 교체는 화면 확인, 진행 중 생성/저장/편집은 보호합니다.
- `images`에는 사진 ID·storagePath·대표/본문·설명·실제 등록일/만료만 저장합니다. URL 없는 원본 사진을 미생성 AI 컷으로 분류하지 않습니다. `research_summary.photo_review`에 최초 초안의 관찰/회원 메모·문단 근거·확인 필요를 보관하며 기존 원고에서는 교체하지 않습니다. AI PASS를 부여하지 않습니다.
- 서버가 실제 Storage 소유권·존재·30일 만료·1~6장·대표 1장·중복·순서/근거·본문 사진 위치 수를 검사합니다. 서명/Blob URL·HTML 사진 본문은 거절합니다. 새 원고 `created_at`을 가장 오래된 사진 등록일로 정해 수명을 늘리지 않습니다. 편집/재조회는 원래 날짜를 유지합니다.
- 임시 URL은 `SavedPhotoReview` 화면 상태에만 두고 다시 조회해도 원고·검수 지문을 바꾸지 않습니다. 사진 원고/근거는 공용 브라우저 캐시·미저장 캐시에 기록하지 않고 로그인 회원의 서버 보관함에서 다시 읽습니다. 일반 글의 기존 캐시는 유지합니다.
- 사진 원고는 기존 편집기의 원본 텍스트 모드로 편집합니다. [IMAGE INSERT - …]를 유지하고 사진은 별도 목록에서 대조합니다. 최초 근거는 편집한 최종 문장의 검수 증명이 아님을 안내합니다. 본문 변경 후 직접 검수를 다시 해야 전송할 수 있습니다. 새 원고는 prepare 기본값입니다.
- 사용 안내 Step 4를 저장→편집→직접 검수→확장 준비로 연결했습니다. 기존 확장의 다운로드 직전 현재 실행 한정 주소 갱신을 재사용했습니다. 확장 실행 코드는 바꾸지 않았고 버전/ZIP만 동기화했습니다.

주요 변경: `photoReviewPost.ts`, `privatePhotoPost.ts`, `postCache.ts`, `postSaveHandler.ts`/`postSaveProtocol.ts`/목록 API, `PhotoReviewDraft`·`SavedPhotoReview`·`PhotoReviewEvidence`, 메인/보관함/편집기·안내, 사진 회귀. 공용 기준 사본·다른 프로그램·스키마/정책·계정/권한/키·환경변수 변경 없음. 기존 nba_posts JSON 구조를 재사용합니다.

## 제약·발견과 해석 정정

- 배포 전 기존 화면의 회원 표시는 남아 있었지만 새로고침 후 로그인 화면으로 이동했습니다. 주인님이 실제 회원으로 다시 로그인한 뒤 검수를 진행했습니다. 인증 코드는 변경하지 않았습니다. BLC-INS-08의 갱신 쿠키 가능성은 조사 후보이며 원인 확정이 아닙니다.
- 확장 업데이트 후 최초 queued 수신이 멈춘 듯한 상태에서 기존 준비 원고 정보가 남았습니다. **수신/실행 전·activeTask 없음**을 확인하고 다시 로드하자 수신했습니다. 그 뒤 실행 중에는 다시 로드하지 않았습니다. 새 네이버 로그인은 주인님이 직접 했고 새 시험 탭의 본인 ‘글쓰기’ 링크로 이동하자 준비 완료됐습니다. 초기 폴링 지연의 원인은 미확정이며 별도 조사 후보입니다.
- **상세창 오류 설명 정정:** 처음 추가한 모의는 상세창이 열린 채 편집 저장되는 조건이었지만, 실제 UI는 편집기를 열 때 상세창을 닫습니다. 이를 일반 흐름의 오류로 단정한 설명은 잘못됐습니다. v2.05의 추가 한 줄은 상세창이 열려 있는 경계에서 서버 ACK를 반영하는 보호이고, 실제 편집 후 재검수는 **다시 열기**로 별도 검증했습니다. 이 판단 착오 때문에 v2.04 후 추가 배포 1회(이번 묶음 총 2회)가 발생했습니다.
- BLC-INS-09/P1 제안: 준비된 원본 사진에도 기존 writer의 ‘AI 활용 설정’이 켜지는 것을 픽셀로 확인했습니다. 원본/생성 사진 구분·네이버 표시 기준 확인 후 회원 선택 방식을 검토할 항목이며 이번에는 기존 엔진 동작을 바꾸지 않았습니다. 최종 발행은 회원이 준비 화면을 직접 확인한 뒤 합니다.
- 사진 원본 자체는 생성/편집하지 않습니다. 저장 후 사진 구성/대표 교체는 이번 범위가 아니며 생성 전에 사진 준비에서 정리합니다. 만료된 사진은 저장/전송을 거절하므로 새 사진으로 새 후기를 작성해야 합니다. 일반 실제 사진 품질/6장 실제 네이버 준비는 미검수(1~6장은 무료 회귀, 실제 2장).
- Edge 메뉴/키보드의 포커스 제약은 주소창 UIA SetFocus+값 확인 후 대상 창의 Enter 메시지로 이동해 해결했습니다. 새 시험 탭 이외의 기존 네이버 준비 탭은 탐색/새로고침/삭제하지 않았습니다. 창은 1433×1399로 복원해 화면에 열어 유지합니다.

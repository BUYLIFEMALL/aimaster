## 원본(올인원)의 기능
- `naver-blog-allinone/src/components/TopicIdeaSection.tsx` 「메모/파일 기반」 탭: 메모를 쓰거나 텍스트 파일(`.txt`·`.md`)을 브라우저에서 읽어(`FileReader`) 앞 3,000자를 AI에 주고 **주제 후보 4개(제목·설명)**를 받는다.
- 한계: 후보를 고르면 **제목과 짧은 설명만** 글쓰기로 넘어가고, 메모 내용 자체는 본문 근거로 쓰이지 않는다.

## 에이전트의 현재
- 본문 근거는 서버 글감 목록(`collected_materials`, 회원별·30일 자동 삭제)에서 고른 글감의 `source_text`(최대 4,000자)만 쓴다(`api/generate` → `loadCollected`).
- 글감 수집 방식(`api/collector`의 `action`): `rss`·`url`·`ranking`·`perplexity`·`shorts_search`·`shorts_analyze`. **회원 메모·파일로 글감을 만드는 방식이 없다.**

## 구현 (올인원보다 나아지는 점: 메모가 주제뿐 아니라 본문 근거가 된다)
1. 서버 `api/collector`에 `action: "memo"`: 회원이 준 메모(최대 8,000자, 형식·길이 검사)를 기존 RSS와 같은 `structureBlogCandidates`(회원 본인 AI 키, OpenAI→Gemini→Claude 순)로 **글감 후보 최대 4개**로 정리 → 각 후보의 `source_text` = 메모 원문(최대 4,000자, 기존 상한)으로 저장. 출처 표시는 「내 메모」(외부 주소 없음).
2. 글감 화면(`collector/page.tsx`)에 「📝 메모·파일」 탭: 메모 입력 칸 + 「텍스트 파일 불러오기」(`.txt`·`.md`, 1MB 이하, 브라우저에서 읽어 칸에 채움 — 파일 자체는 서버에 올리지 않음). 「메모로 글감 만들기」 버튼.
3. 만들어진 글감은 기존 글감처럼 목록에 뜨고, 골라서 글을 쓰면 **메모 원문이 근거 자료로 들어가** 지어낸 사실을 검수가 잡는다(A-1과 같은 근거 구조).
4. 타입: `method`에 `"memo"` 추가(글감은 JSON으로 저장 — **DB 변경 없음**). 글감 목록의 방식 이름표에 「내 메모」.
5. 시험: 메모 검사(빈 값·길이·형식), 후보의 근거 원문·출처 표시(가짜 AI). 기존 시험 28종 유지.

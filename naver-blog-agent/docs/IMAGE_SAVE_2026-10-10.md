# v1.68 이미지 장수·자동 저장 인수인계

2026-10-10, 담당 Codex. BLOG/티스토리는 클로드 작업 범위로 수정하지 않습니다. v1.67 검수·저장본 지문 기준을 유지하며 이미지 변경 후 다시 검수합니다.

## 바뀐 동작

- 생성 요청에서 선택한 이미지 장수(썸네일 포함 1~5장)를 서버로 전달하고 범위를 검증합니다. 썸네일1장+본문0~4장의 다른 장면을 소제목·구도별로 계획합니다. 인물 기본 한국인/동아시아인 유지. 추가 LLM 호출 없이 장면별 프롬프트를 구성합니다.
- 본문 이미지 자리 수를 실제 계획과 같게 맞춘 후 최종 Reviewer에 보냅니다. 기존 본문·숫자·출처 줄은 보존하고 이미지 배치 표시만 재배치합니다. 선택 장수는 계획/시도 장수이며 공급사 실패가 있어도 그 수의 생성 성공을 보장하는 표시는 하지 않습니다.
- 자동 이미지 생성은 새로 받은 서버 원고 ID를 명시적으로 사용합니다. 기존 렌더의 currentPostId를 참조하여 이전 글에 이미지를 저장할 수 있던 문제를 수정합니다. 부분 성공은 이미지마다 서버 저장하고 실패한 컷은 별도 안내합니다.
- 개별 생성/같은 컷 재생성/삭제 직후 서버에 저장합니다. 동일 캡션 컷은 교체, 썸네일·계획 순서 유지. 마지막 삭제의 빈 배열은 그대로 저장하며 프롬프트 목록으로 되돌아가지 않습니다. 삭제한 이미지가 편집 HTML/마크다운 본문에도 있으면 그 이미지 태그도 함께 제거해 저장합니다.
- 일반 이미지 저장은 ID/images만 수정하므로 진행 중 본문 편집을 이전 본문으로 덮어쓰지 않습니다. 해당 이미지 삭제로 본문 태그가 바뀐 경우에만 그 본문도 보냅니다. 기존 서버 소유자/사용 권한/대기·입력 중 변경 차단/updated_at 조건을 유지합니다.
- 이미지 생성·삭제는 같은 화면에서 순서대로 진행합니다. 다른 원고를 불러오거나 화면을 떠나면 늦게 도착한 이미지 결과를 새 원고에 적용/저장하지 않고 다음 유료 요청도 시작하지 않습니다. 이미 보낸 공급사 요청을 취소하여 비용을 환불하는 기능은 아닙니다.
- 원고/이미지 저장·전송 성공은 서버 응답 확인 이후 표시합니다. 편집 저장 실패 시 입력 내용을 유지하고 편집창을 닫지 않습니다. 본문 이미지는 실제 body 배열로 조회하므로 썸네일 생성 실패가 본문 위치를 밀지 않습니다. 이미지 생성·저장 중 편집창 열기/전송/전체 저장을 제한합니다.
- 서버 ID·임시 ID 및 저장 확인은 v1.67에서 보완한 경로를 사용합니다. 생성/개별 이미지/본문 편집 저장 후 검수 기록이 수정 전 판정으로 통과하지 않도록 지문 불일치로 다시 검수합니다.

## 위치와 검사

- `src/lib/draftImages.ts`: 장면 계획, 이미지 자리 배치, 컷 교체/정렬, 명시적 빈 이미지 목록, 본문 이미지 조회 및 삭제 태그 정리.
- `src/lib/ai/pipeline.ts`/`api/generate`: 선택 장수 전달/검증, 실제 이미지 자리 반영 후 검수.
- 생성/보관함 화면·`BlogSmartEditorModal.tsx`: 서버 ID 고정·원고 전환 후 늦은 결과 무효·각 이미지 저장·실패 보존·편집 ACK/창 닫기.
- 신규9개 실제 UI 함수/배치 검사 추가, 기존75 포함84개 시나리오 통과(Node 출력60은 worker파일 내부25개를 1개로 집계). 1~5장 실제 파이프라인 요청·결과 검사 및 말투/문체32조합, 모델17개, 연결/상태/발행 설정/편집 저장 검사 통과. 모두 모의 공급사이며 유료 호출은 없습니다.
- `npm run build` 컴파일·타입 검사 및 ZIP 생성 통과. 여러 TSX의 기존 흰색 화면·Hook 순서·저장 중 버튼 제한·편집 버퍼 보존을 확인합니다. 루트 앱 빌드를 잘못 시작한 한 번은 중지하고 해당 프로그램 폴더에서 다시 빌드했습니다. 다른 프로그램 배포/코드 변경 없음.

## 실제 검수와 남은 일

- 실제 네이버 새 prepare/E2E, 실제 유료 이미지 1~5장 생성은 이번에 실행하지 않았습니다. 공유 Chrome에 다른 프로그램 작업이 진행되어 이를 계속 전환하지 않았습니다. 실제 본인 계정 검수는 별도 빈 편집기에서 수행하며 최종 발행은 실행하지 않습니다.
- 저장 응답 유실 시 POST 재시도 전체의 멱등 키, 다중 웹 탭 동시 편집/이미지 변경 충돌 UI, 편집 HTML의 모든 이미지 표현(비표준/비인용 src 등) 파싱은 별도 후속입니다. 일반적인 따옴표 HTML img와 마크다운 이미지를 처리합니다.
- 다음은 5단계 진행·복구: progress/stage/waiting의 실제 상태 저장/표시, 실행 번호·임대, 선점 응답 유실/장기 단절. 실행 ID가 없으므로 취소→빠른 재전송 뒤 매우 늦은 옛 실행 결과까지 구별하는 보장은 없습니다. DB 스키마 변경 필요 시 사전 승인 대상입니다.
- v1.68 설치 적용: 기존 최신 ZIP 주소 재다운로드→기존 확장 폴더 덮어쓰기→chrome://extensions 새로고침. 원고/이미지 변경 후 직접 최종 검수하고 prepare/publish를 확인합니다.

## 원본(올인원)의 기능
- `naver-blog-allinone/src/lib/blog/humanVoice.ts`: 화자 직접 입력(`buildCustomPersona`, 200자)·본인 경험 메모(1,500자)·「경험을 떠올릴 질문 받기」(`requestExperienceQuestions`).
- 같은 일을 하는 검증된 구현이 SEO 스튜디오에도 있음: `naver-blog-seo-studio/app/api/drafts/experience-questions/route.ts`(v1.74 — AI는 질문 5개만, 경험 문장은 만들지 않음). **질문 기능은 이 방식을 따른다.**

## 에이전트의 현재
- 화자는 6가지 중에서 고르기만 가능(`src/types/persona.ts`). 생성 경로는 화면이 보낸 `persona.tonePrompt`를 **검사 없이** 기획·작성 지시문에 넣음 → 이번에 길이·형식 검사를 함께 넣는다.
- 일반 글에는 본인 경험 칸이 없음(사진 후기에만 방문 메모).

## 구현
1. 화자 「직접 입력」: 이름(20자)+설명(200자). 서버가 설명으로 지시문을 만들고, 프리셋·직접 입력 모두 길이 검사(이름 30·배지 20·설명 300자, 형식이 틀리면 400).
2. 「내 실제 경험(선택, 1,500자)」 칸: 기획·작성 지시문에 「회원이 직접 겪은 경험 — 1인칭 경험은 여기 적힌 것만 쓴다」 블록. 검수 단계에서 메모에 없는 1인칭 경험을 지어낸 문장을 표시(기존 근거 검수 문구에 한 줄).
3. 「경험을 떠올릴 질문 받기」 버튼: 새 경로 `POST /api/experience-questions`(로그인+권한, 고른 공급사의 회원 본인 키, 질문 5개만, 경험 문장은 만들지 않음). 질문은 경험 칸 아래에 보여 주기만.
4. 시험: 화자 검사·경험 블록·질문 경로(가짜 AI). 기존 시험 25종 유지.

## 검수
1. 무료: tsc·빌드·시험 전체.
2. 실제 1회씩: ① 질문 받기 1회 ② 직접 입력 화자 + 경험 메모로 글 생성 1회 — gpt-4o-mini, 시험 계정 본인 키, 저장 안 함. 메모의 경험이 1인칭으로 들어가고, 메모 밖 경험을 지어내지 않는지 확인.
3. A-3과 함께 v2.17 배포(빌드 1회) → 크롬에서 사진 후기 방문 정보 칸·화자 직접 입력·경험 칸·질문 버튼 확인.

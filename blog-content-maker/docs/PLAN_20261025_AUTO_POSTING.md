## 3. 가져올 기준 코드와 경계

- 입력과 전체 내용 대조는 콘텐츠 메이커의 `writer.js`/현재 background 흐름을 보존합니다. 처음부터 다시 쓰지 않습니다.
- SEO `extension/auto-publish.js`·`auto-publish-page.js`의 입력 후 verify/settings/arm/결과 확인 순서와 예약 목록 검증을 기준으로 가져옵니다. DOM 속 함수는 실행 방식에 맞게 포함하고, SEO의 UI·토큰·원고 표 이름을 그대로 가져오지 않습니다.
- 서버는 SEO `app/api/extension/drafts/library/[draftId]/auto-publish/route.ts`와 `lib/draftWriteGuard.ts`의 runId/원고 지문/조건부 상태 전이를 참고합니다. 현재 콘텐츠 메이커의 project/revision/소유자/만료 계약에 맞는 어댑터를 둡니다.
- 예약 시각은 SEO `lib/reserveTime.ts`와 에이전트 `src/lib/scheduleSlots.ts`의 동일 규칙을 적용합니다. `docs/SHARED_FEATURE_MAP.md`의 `naver-reserve`는 아직 후보이므로 검증 없이 공용화 완료라고 쓰지 않습니다. 세 번째 사용처 검수 후 기준/사본 등록을 검토합니다.
- 다른 프로그램의 토큰·회원 자료·발행 기록을 복사하거나 기존 SEO/에이전트 동작을 이번 구현에서 일괄 변경하지 않습니다.

## 4. 승인받을 DB·권한 변경안

아래는 설계안이며 **아직 SQL 작성/적용하지 않았습니다**. 구현 승인 뒤 정확한 DDL·RLS·되돌림 범위를 먼저 고정합니다.

1. `blog_content_maker_publications` 1개 표: 소유자, project/revision, 실행 ID·중복 요청 ID, 선택 방식·대상 blogId·공개 범위·예약 시각, 원고 지문, 상태, 결과 URL/확인 시각·오류, 원고와 같은 만료 시각. 본문/이미지/서명 URL/키/토큰은 복제하지 않습니다.
2. 원고/수정본/소유자의 복합 관계를 강제하고 회원은 본인 유효 기록만 읽습니다. 브라우저 직접 상태 변경은 차단하고 서버의 검사된 전이만 허용합니다. 동일 원고의 진행/불확실 실행이 겹치지 않도록 DB의 원자적 선점·조건부 변경을 씁니다.
3. 확장 토큰 scope 허용값을 `read-draft`와 발행용 값으로 구분합니다. 기존 읽기 토큰은 그대로 유지. **회원이 웹 설정에서 발행 기능 연결을 직접 선택해 새로 발급한 토큰만** claim/arm/결과 쓰기를 허용하며, 유효기간7일·해제 확인·프로그램 권한 재확인은 유지합니다. 토큰은 기존처럼 해시만 서버 저장합니다.
4. 공용 계정 저장 기준: 대상 블로그를 영구 등록/재사용할 경우 전용 중복 계정 표를 만들지 않습니다. 현재 공용 카탈로그의 `naver_login`은 네이버 카페용 OAuth이며 블로그 확장 발행 권한으로 간주할 수 없습니다. 기존 공용 `member_platform_accounts`/`integration_catalog`에 블로그 식별용 항목을 추가하는 DDL 없는 카탈로그 변경안을 구현 전에 별도로 제시합니다. 본인 확장에서 확인된 블로그만 저장하고, OAuth 토큰·다른 회원 값을 대체 사용하지 않습니다.
5. 30일 정책: 실행 접근은 원고 만료와 동시에 차단, 원고 삭제 때 결과도 CASCADE. 코드에서 현재 확인한 `cleanupExpired`는 회원 방문 시 정리하므로 이것만으로 정기 자동 삭제 완료라고 쓰지 않습니다. 기존 운영 정기 정리 경로를 대조하고, 없으면 이 앱의 보호된 정리 API+정기 실행을 같은 플랜에 포함해 실제 호출/삭제 증거까지 남깁니다. 생성 콘텐츠 수명은 발행했다고 연장하지 않습니다.

## 5. 실행·중단·복구 원칙

- `claim` 전에 회원/권한/발행용 연결/만료/원고 revision/완성 이미지/회원의 방식·블로그 선택을 검사합니다. 입력 중 편집된 원고는 최종 발행하지 않습니다.
- 일반 입력 경로는 지금처럼 최종 발행 명령을 거부합니다. 발행 전용 경로만 현재 실행 ID·네이버 탭/프레임·유한 대기 기한을 검사합니다.
- `writing → prepared`는 입력만 성공. 실제/예약만 `writing → publishing(arm) → published/reserved`로 갑니다. arm 응답을 잃거나 반복하면 다시 최종 클릭 권한을 주지 않습니다.
- 최종 클릭 뒤 탭 닫힘/연결 끊김/확인 실패는 `uncertain`. 자동 재발행 금지. 결과 확인은 읽기만 하며 기존 글 URL 또는 예약 목록을 재대조합니다. 네트워크 오류 때 다시 보내는 것은 같은 실행의 결과 보고뿐입니다.
- 이미지/본문 대조 실패, 다른 블로그 탭, 빈 편집기가 아님, 예약 설정 잔존은 중지하고 이미 입력된 글을 보존합니다. 회원이 원치 않는 글을 지우거나 임시글을 임의로 취소하지 않습니다.
- 과거 실행의 중지/실패 표시와 최종 발행 뒤 불확실 상태를 구분합니다. 실행 기록 저장 실패를 발행 성공으로 표시하지 않습니다.

## 6. 웹·확장·매뉴얼 변경안

웹 `/export`에서 방식별 목적과 입력/발행/예약 결과를 함께 보여주고, 최종 원문·이미지는 계속 웹에서 확정합니다. 기본값은 **발행 전까지**, 공개 범위·예약 시각은 회원이 명시적으로 고릅니다. 팝업 실행 직전 같은 선택·블로그·원고 수정본을 다시 확인합니다.

설정은 기존 읽기 연결을 유지하며 발행용 연결 발급 목적/권한 차이를 설명합니다. 매뉴얼은 세 방식·중단/불확실 결과 확인·예약 취소·확장 업데이트를 기존 시각 카드 규격으로 설명합니다. 대상은 메인 흐름·상세 결과·매뉴얼·설정이며, 실제 UI 변경 전 루트의 4대 화면 시안/사전승인 규칙을 적용합니다. 기존 적용 스타일은 플로우 위저드 에디션으로 확인했으며, 디자인을 이번 문서 작성으로 확정하지 않습니다.

## 8. 비용·버전·남은 결정

- 현재 분석/문서·배포 메타데이터 정정: 유료 AI0·수동 빌드0·새 배포0.

- 인수인계에 콘텐츠 메이커 **배포 빌드1회 승인**이 기록돼 있습니다. 그 1회 안에서 변경을 모아 배포하고, 실패/추가 배포가 필요하면 기존 승인 횟수 사용 상태와 비용 지침을 먼저 확인합니다. 추가 빌드를 자동으로 반복하지 않습니다. 실제 청구액은 빌드 설정/소요시간으로 기록합니다.
- 운영 버전은 현재v1.12 유지. 실제 배포 때만 다음 버전(v1.13 후보)으로 웹·manifest/version_name·ZIP·DB를 한 번에 맞춥니다. 기존 SEOv2.19 ZIP 미커밋 삭제와 다른 CLI 파일은 이번 커밋에 포함하지 않습니다.
- 별도 확인: 플랜/신규 실행표·토큰 권한/공용 카탈로그 변경안, UI 시안, 실제 비공개 발행·예약·시험 글 처리 범위. 아직 동의하지 않은 항목은 실행하지 않습니다.

## 9. 이번 코드 대조 결론

③-2는 기존 입력기에 발행 버튼을 붙이는 작업보다 범위가 큽니다. 현재 읽기 권한을 보존하면서 **회원 선택·원자적 실행·최종 클릭1회·결과 확인/기록**을 함께 구현하는 안을 권합니다. SEO의 검증된 흐름을 재사용하되 실제 네이버 예약은 그쪽도 미검수라는 한계를 그대로 인계합니다.

## 2. 제품의 역할

**주제나 기존 글을 받아, 제목·본문·이미지와 발행 전 점검을 한곳에서 완성하는 블로그 제작 도구**입니다. 검색 순위 측정이나 상위 노출 보장 서비스로 소개하지 않습니다.

기존 작업실의 장기간 조사·스타일 학습을 그대로 반복하지 않고, 한 원고를 빠르게 작성하고 수정·검수·전달하는 흐름을 만듭니다. 기존 SEO 스튜디오와 겹치는 기능은 분명히 인정하고, 새 제품은 편집한 원고와 검수 결과의 일치·제품 합성·장면 준비·수정본 보존을 중심으로 묶습니다. 기존 프로그램을 대체·수정·이름 변경하는 작업이 아닙니다.

## 4. 첫 공개 버전의 기능 범위

### 원고와 작성 방식

- 주제 기반 새 글, 제목 추천 후 작성, 기존 원고 분석 후 다듬기를 모두 제공합니다.
- 작성 방식은 새 이름으로 **정보 정리형·검색 의도형·질문 답변형·경험 이야기형·문제 해결형** 5종을 구성합니다. 네이버 비공개 알고리즘을 그대로 재현한다는 문구를 사용하지 않습니다.
- 핵심·보조 키워드, 독자 대상, 문체, 실제 경험, 분량 목표, FAQ 포함/제외를 선택합니다. 경험이 없으면 질문·작성 예시만 제안하고 실제 체험처럼 생성하지 않습니다.
- 원본 원고와 새 수정본을 별도로 보관하고 수정 이유를 표시합니다. 저장 전 이탈·동시 수정·오래된 결과 덮어쓰기를 처리합니다.
- 모델 응답은 제목·본문 블록·미디어 계획·출처·점검·SNS 문구의 구조화된 데이터로 검증합니다. 원본의 구간 구분 문자열에 의존하지 않습니다.

### 점검과 출처

- 제목과 본문의 관련성, 길이, 문단·소제목·반복 단어, 표·목록·FAQ, 태그, 실제 삽입 이미지와 ALT, 출처·최신성 확인을 점검합니다.
- 코드로 계산한 결과, AI 검토 의견, 회원이 직접 확인해야 하는 항목을 구분합니다. 각 항목의 이유와 실제값·권장값을 보여줍니다.
- 점수 표시가 필요하면 **원고 점검 충족률**로 이름 붙이고 계산 기준을 공개합니다. 네이버 공식 점수·실제 순위로 소개하지 않습니다.
- 원고나 이미지가 바뀌면 이전 점검을 오래된 결과로 표시하고 다시 검사합니다. 점검은 해당 `revision_id`·내용 해시와 연결합니다.
- 검색 기능을 사용하지 않은 제목 추천은 AI 아이디어로 표시합니다. 실제 인기·검색량·트렌드로 꾸며 표시하지 않습니다.
- 검색 근거를 사용하면 확인한 URL·제목·시각을 보관합니다. 확인되지 않은 날짜·제품 출시·가격·정책·통계를 사실로 단정하지 않습니다. 현재 날짜·연도는 실행 시 동적으로 주입합니다.

### 이미지·장면·활용

- 일반 이미지 1~10장 선택, 이미지 제외, 회원 직접 업로드를 제공합니다. 첫 공개판도 사용자가 요청한 이미지 개수·실제 생성·본문 삽입 상태를 따로 확인합니다.
- 제품 사진을 참고한 합성, 카드별 생성·재생성, 1:1·16:9 비율, ALT·지시문 수정·번역, 다운로드를 제공합니다. 인물이 필요한 장면은 한국인(동아시아인)을 기본으로 합니다.
- 0~3개 장면 계획과 각 첫 장면·끝 장면 이미지를 준비합니다. 메뉴·버튼은 **장면 이미지 준비**로 표시합니다. 실제 MP4 생성은 이번 범위가 아닙니다.
- 제목·본문 텍스트 복사, 서식 유지 복사, Markdown·정리된 HTML 내보내기, 이미지 묶음 다운로드를 제공합니다. 내보내기 파일명도 새 브랜드로 통일합니다.
- Threads·X·Facebook용 요약 문구를 작성·복사합니다. 해당 플랫폼에 자동으로 게시하지 않습니다.

### AI 설정·오류 처리

- 제안: 텍스트는 회원 본인 Gemini 또는 OpenAI 키 중 선택, 이미지는 회원 본인 Gemini 이미지 키를 사용합니다. Gemini 키가 없으면 업로드·이미지 제외를 안내하고 다른 회원 키를 빌리지 않습니다.
- 모델·SDK·기능·가격은 구현 시 공식 문서와 실제 계정 접근을 확인해 정합니다. 원본의 모델명·가격표를 그대로 복사하지 않습니다.
- 검색 기능은 회원이 켠 경우만 사용하고, 해당 선택이 실패하면 알리지 않고 다른 방식으로 바꾸지 않습니다. 계속 작성할지 검색을 끌지 안내합니다.
- 키 저장만으로 유료 진단 호출을 보내지 않습니다. 연결 확인은 회원이 요청했을 때 실행하며, 모델 접근 가능 여부와 과금 등급 추정을 구분합니다.
- 인증·권한·모델 없음·일시 한도·일일 한도·서버 과부하·안전 차단·응답 형식·네트워크 오류를 구분합니다. 일시 실패만 제한적으로 재시도하고 상태가 불명확한 유료 생성은 무조건 다시 호출하지 않습니다.
- 진단 로그에는 키·토큰·회원 원고 전문을 남기지 않습니다. 회원 화면에는 이해할 수 있는 원인과 다음 행동을 제공합니다.

## 5. 웹과 Chrome 확장 구성

웹앱은 AIMaster 서브폴더의 Next.js·TypeScript 앱으로 만들고 공통 로그인·등급·사용기간·API 키 저장·SSO 패턴을 재사용합니다. 회원 데이터·프로그램 권한·확장 식별자는 독립적으로 둡니다.

원본의 Electron webview를 일반 웹페이지 안에 옮기지 않습니다. 네이버 편집기는 회원이 로그인한 실제 Chrome 탭에서 열고, 기존 플랫폼 확장의 검증된 **입력만 하는 흐름**을 새 확장에 적용합니다.

확장은 다음 조건을 충족해야 합니다.

- 웹 출처·프로그램 권한·연결 소유자를 확인합니다. 새 확장 토큰은 해시로 저장하고 만료·폐기·scope를 제한합니다.
- 웹의 해당 수정본만 가져오고 실제 편집기에 기존 글이 있으면 자동 덮어쓰지 않습니다.
- 입력 전 네이버의 실제 DOM을 조사합니다. 제목·전체 본문·마지막 문장·이미지 개수와 중복을 입력 후 다시 확인합니다.
- 표·캡션·이모지·이미지 배치·카테고리·태그는 기존 구현을 살펴 재사용하되 실제 동작을 새 프로그램에서 다시 검수합니다.
- 최종 발행 버튼은 누르지 않습니다. 준비·입력 완료·사용자 발행을 별도 상태로 표시합니다.
- 버전 `v1.01`, manifest `version_name`, 최신 ZIP, DB 확장 버전을 함께 맞춥니다. 새 ZIP 주소 제안은 `/downloads/blog-content-maker-extension-latest.zip`입니다.

## 6. 데이터 구조와 운영 변경 제안

아래는 **2026-10-16 주인님의 진행 지시로 승인받아 적용한 운영 변경**입니다. 신규 테이블 6개·소유자 정책·비공개 Storage와 새 프로젝트의 플랫폼 DB 환경변수 세 개를 등록했습니다. 로그인·등급·결제 테이블의 구조를 바꾸거나 기존 회원 데이터를 이관하지 않습니다.

| 신규 테이블 | 주요 내용 |
|---|---|
| `blog_content_maker_settings` | `user_id` 고유값, AI 제공자·모델·문체·화면 설정. API 키 원문은 저장하지 않음 |
| `blog_content_maker_projects` | `id`, `user_id`, 제목·입력 방식·키워드·작성 방식·작업 상태·현재 수정본·시각 |
| `blog_content_maker_revisions` | 프로젝트·회원, 버전 번호, 제목·본문 블록·출처·점검·SNS 문구·내용 해시. 수정본은 새 행으로 보존 |
| `blog_content_maker_assets` | 프로젝트·회원, 미디어 종류·Storage 경로·MIME·크기·해시·ALT·삽입 위치·생성 상태 |
| `blog_content_maker_jobs` | 회원·프로젝트·작업 종류·요청 키·입력 해시·상태·실패 원인·사용량. 재요청 중복 방지 |
| `blog_content_maker_extension_tokens` | 회원, 토큰 해시, scope·만료·폐기 시각. 토큰 원문은 신규 발급 시만 전달 |

모든 회원 데이터에 `user_id`와 RLS를 적용하고, 읽기·쓰기·수정·삭제 권한을 구분합니다. 서비스 역할을 쓰는 서버 코드도 항상 회원 소유자 조건을 붙입니다. 프로젝트·수정본·자산의 관계에는 같은 소유자 조건을 강제해 다른 회원의 프로젝트를 참조할 수 없게 합니다. 갱신 정책은 `USING`과 `WITH CHECK`를 함께 두며 불필요한 `anon` 권한은 주지 않습니다.

Storage는 새 **비공개** 버킷 `blog-content-maker`, 경로는 `<user_id>/<project_id>/<asset_id>`를 제안합니다. 업로드 형식·파일 크기·실제 MIME를 검사하고, 회원 또는 연결된 확장에 필요한 만료 URL만 발급합니다. 회원의 제품 사진을 공개 버킷에 기본 보관하지 않습니다.

보관 정책 제안은 작업·생성 이미지 30일이며, 만료 예정 안내·내보내기·직접 삭제를 제공합니다. 실제 자동 정리 방식은 기존 보관 규칙과 대조해 구현하고 기존 프로그램 cron을 임의로 바꾸지 않습니다. 진행 중인 작업·전송 중 자산은 정리에서 제외합니다.

운영 변경은 다음 범위를 제안합니다.

1. 공용 DB `esgxyikcnnvmlhygjkth`에 위 신규 테이블 **6개**·필요 인덱스·RLS·명시적 권한과 새 Storage 버킷·정책을 추가합니다. 마이그레이션은 이 프로젝트 `supabase/migrations/`에 기록합니다.
2. 신규 Vercel 프로젝트에 공용 DB 연결용 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`를 등록합니다. **회원용 AI 키를 운영 환경변수에 넣지 않습니다.** 기존 프로젝트 환경변수는 변경하지 않습니다.
3. 새 프로그램·버전·정상 app_url·이미지·상세 설명·연동 가이드와 기본 요금제 3종을 등록합니다. 기본 요금제는 플랫폼 기준 1개월 10,000원·2개월 20,000원·3개월 30,000원입니다. FREE 여부·사용권한은 공통 관리자 정책을 따릅니다.
4. 이름 확정 후 새 `<slug>.buylife.xyz` 도메인을 Vercel에 연결하고 SSO 쿠키 도메인 규칙을 적용합니다. 기존 프로그램 도메인·쿠키를 변경하거나 만료시키지 않습니다.

설계 참고: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control). 2026-10-15 기준 changelog의 TLS 변경·Postgres 변경 공지도 확인했습니다. 이번 계획은 구형 TLS·ltree·특수 연산자에 의존하지 않으며 공용 DB의 버전·확장·암호화 설정을 바꾸는 작업을 포함하지 않습니다.

## 7. 이름·표현 정리 기준

브랜드는 `src/lib/version.ts`에서 관리합니다. 표시명·slug·운영 URL·다운로드 파일명의 변경점을 함께 관리합니다.

| 확인 대상 | 처리 |
|---|---|
| 헤더·메뉴·도움말·툴팁·토스트·오류·로그·빈 화면 | 새 이름과 새 설명으로 작성 |
| HTML 제목·설명·OG·아이콘·이미지 안 글자 | 새 브랜드로 구성 |
| package·앱 상수·Storage·DB 접두사·Vercel·도메인 | 확정 slug로 통일 |
| 확장 이름·설명·팝업·연결 화면·manifest·아이콘 | 새 이름·독립 식별자 사용 |
| ZIP·이미지·내보내기 파일명·README·연동 매뉴얼 | 새 브랜드로 통일 |
| 프롬프트·작성 방식·페르소나·예시 | 기능만 참고하여 새로 작성, 원본 고유 표현·홍보 문구 제거 |
| 원본 제작자·유튜브·홈페이지·인증·업데이트 주소 | 새 앱·확장·배포 파일에 포함하지 않음 |
| 오픈소스 법적 고지, 실제 플랫폼·모델 이름 | 필요한 고지를 보존. 네이버·Gemini 등 실제 연동 대상 이름은 정확히 표시 |

원본 식별 문자열 목록은 분석 폴더에 따로 보관합니다. 소스와 빌드 결과·확장 ZIP의 문자열을 검사하고 실제 화면·다운로드를 함께 확인합니다. 단순 문자열 검색에서 0건이 나왔다는 사실만으로 아이콘·이미지 안 글자까지 검수했다고 보고하지 않습니다.

## 8. 구현 순서와 단계별 완료 조건

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 0 | 분석·이름·개발 계획 | 이름 확정 완료, 이 문서·근거 검토, 필요한 운영 변경 범위 승인 |
| 1 | 앱·권한·브랜드·저장 뼈대 | 일반 회원 로그인·권한 확인, 본인 키 안내, 다른 회원 데이터 차단, PC·모바일 메뉴 |
| 2 | 글감·제목·원고 3가지 입력 | 제목 제안→글 작성, 원문/파일 분석→새 수정본, 저장·재조회·복원 |
| 3 | 편집·점검·출처·SNS | 수정한 원고를 재점검, 기준/실제값 표시, 오래된 결과 분리, 원문 보존 |
| 4 | 이미지·제품 합성·장면 | 개별 성공·실패·취소 처리, 실제 자산과 본문 위치 일치, 재생성 중복 방지 |
| 5 | 내보내기·네이버 확장 | 서식 복사·다운로드·입력 후 전체 내용 검증, 기존 글 보존, 최종 발행 없음 |
| 6 | 운영 릴리스 | 검수·문서·커밋·푸시·지정 프로젝트 프로덕션 READY·운영 회원 흐름·ZIP 검증 |

이 표는 구현 순서입니다. 첫 공개판은 1~6단계를 함께 만족하는 범위로 제안하며, 중간 뼈대를 완성품으로 배포하지 않습니다.

## 9. 실제 검수 계획

- 입력 검증: 빈 값·긴 원문·파일 크기·HTML 스크립트 제거·허용 MIME·모델 선택값·잘못된 AI JSON.
- 소유권: 비로그인 401/리다이렉트, 권한 없는 회원 차단, 다른 회원의 프로젝트·수정본·자산·토큰 ID 사용 차단, 본인 키 미등록 안내. RLS allow/deny 검사와 서버 API 검사를 모두 수행합니다.
- 원고 보존: 붙여넣은 원문·새 수정본 분리, 편집 후 저장·새로고침 복원, 원고 변경 시 이전 점검 무효화, 중복 생성 요청·통신 끊김 후 복구.
- 점검: FAQ 제외·이미지 제외 선택을 그대로 반영, 이미지 자리표시자만 있어서는 생성 완료로 보지 않음, 출처 없는 수치·가상 경험·지난 연도 예시를 통과 처리하지 않음.
- 이미지: 일반 생성·제품 합성·장면 쌍을 최소 표본으로 확인, 업로드 파일 보존, 실패 재시도·다중 클릭 중복 확인. 과금 대량 호출은 하지 않습니다.
- 실제 화면: 주인님과 볼 수 있는 Chrome에서 일반 시험 회원으로 입력→생성→편집→점검→이미지→내보내기·확장까지 확인합니다. PC와 400px 안팎 폭에서 메뉴·가로 넘침·조작점을 확인합니다.
- 네이버: 본인 로그인 탭에서 제목·전체 본문·마지막 문장·표·이미지·중복·태그·카테고리 선택을 대조합니다. **발행 버튼은 누르지 않습니다.**
- 배포: 타입·린트·빌드, 운영 공개 응답·로그인된 보호 흐름·캐시 분리, 코드/DB/확장 버전·최신 ZIP 200·내부 manifest·핵심 파일 해시를 확인합니다.
- 브랜드: 원본 이름·고유 표현·홍보 주소가 앱·확장·빌드·ZIP·문서·내보내기에 남지 않았는지 확인합니다.

## 10. 구현 결과와 검수 경계

정적 분석·계획 후 회원별 웹앱, Chrome 확장·ZIP, 신규 DB·Storage, Vercel 프로젝트·플랫폼 연결 값, programs·요금제 3종·연동 가이드를 구현·등록했습니다. 일반 시험 회원 본인의 키로 원고·이미지 생성과 추가 AI 기능을 검사했습니다. 원본 설치 파일은 실행하지 않았습니다.

추가 승인 대기 상태가 아닙니다. 검수→커밋→푸시→운영 배포→운영 확인을 이어서 수행합니다. [검수 기록](VERIFICATION.md)에 확인한 실제 흐름과 남은 검수·배포 증거를 구분합니다. 이미지 개별 복사는 이미지 열기·저장 및 ZIP을 제공하며, 네이버 표는 행별 텍스트로 옮깁니다. 확장에는 최종 발행 명령이 없습니다.

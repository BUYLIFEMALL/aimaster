## 1. 문제와 목표
로드맵 U8은 「워크스페이스 업무 보드 ↔ 오늘 할 일」 양방향입니다. 그런데 프로그램끼리 서로의 API를 부르지 않는 규칙 때문에, 지금 있는 길은 U7 공용 표 `public.work_inbox`(다른 프로그램 → 워크스페이스 한 방향)뿐입니다. 그래서 두 단계로 나눕니다.

- **U8-A (이번)**: 할 일 플래너 → 워크스페이스 「📨 받은 업무」. DB 변경 없음.
- **U8-B (다음, 결정 필요)**: 워크스페이스 → 할 일 플래너. 반대 방향 길이 없어 DB 변경이 필요합니다(§5).

## 2. U8-A 범위 (할 일 플래너 v1.11)
1. **할 일 하나 보내기**: 할 일 카드의 동작 줄에 「📨 워크스페이스로」 버튼.
   - 종류 `task`, 제목 = 할 일 제목
   - 본문: 분류·우선순위·예정일·예상 시간·상태·집중한 시간
   - 표 행 데이터: `예정일`·`우선순위`·`분류`·`예상 시간(분)`·`상태`·`집중 시간(분)` → 워크스페이스 「표에 행으로 넣기」 때 속성으로 들어감
2. **오늘 성과 보내기**: 「성과 노트」 옆에 「📨 오늘 성과를 워크스페이스로」 버튼.
   - 종류 `document`, 제목 「2026-10-25 할 일·성과 보고」
   - 본문: 완료율·총 집중 시간·완료한 할 일(체크 목록)·남은 할 일·성과 노트(선택한 날짜·분류 기준)
   - AI 분석 결과는 저장되지 않는 값이라 이번에는 넣지 않습니다(유료 호출을 다시 하지 않기 위해).
3. **서버**: 새 라우트 `POST /api/work-inbox` `{ type: "task", taskId } | { type: "day", date, categoryId }`
   - 기존과 같이 출처 확인 + `checkProgramAccessApi()` → **로그인 회원 본인 기록만** 서버에서 읽어 내용을 만듦(브라우저가 보낸 본문을 그대로 넣지 않음)
   - 기준 코드 `ai-work-workspace/src/lib/workInbox.ts`를 `src/lib/workInbox.ts`로 **사본 그대로** 복사(공용 기준 코드 규칙, `docs/SHARED_MODULES.md` 등록)
4. **화면 안내**: 보내면 「업무 워크스페이스 『받은 업무』로 보냈습니다」 + 바로 가기 링크(https://ai-work-workspace.buylife.xyz/inbox). 같은 할 일을 다시 보내면 새 항목이 하나 더 생긴다는 안내.
5. **매뉴얼**: `/guide`에 「워크스페이스로 보내기」 카드 추가.
6. **버전**: v1.11(코드·package·DB `programs.version`).

## 3. 워크스페이스 쪽
- 「받은 업무」 화면의 보낸 프로그램 이름표에 `ai-task-planner` → 「AI 할 일 플래너」가 이미 있어 **코드 수정이 없습니다.**
- 그래서 워크스페이스는 이번에 배포하지 않습니다. 미배포 대기 `c6d4ca3ba`(받은 날 한국 날짜)는 다음 워크스페이스 배포 때 함께 나갑니다.
  - 영향: 그 전까지는 밤 9시 이후 받은 항목을 표에 넣으면 「받은 날」이 하루 전으로 들어갑니다. 바로 고치길 원하시면 빌드 1회가 더 듭니다.

## 4. 시험
- 단위 시험: 보낼 내용 만들기(할 일 1개·하루 보고) — 제목·본문·표 행 데이터, 다른 회원 기록을 읽지 않음

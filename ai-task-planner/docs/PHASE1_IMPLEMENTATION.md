# AI 할 일·성과 관리 — 공통 틀·핵심 기록 구현

2026-10-13. 첫 출시 버전 v1.01. 이번 단계는 공통 틀과 기록 모델이며 AI·전체 백업 복원·CSV 출시 단계와 구분합니다.

## 구현된 코드

- 독립 Next.js 16.4.0/React 19.3.0 프로젝트. 기존 AIMaster 로그인·공통 권한 판정의 사본·핸드폰 정책·SSO 쿠키·서버 API의 JSON 차단을 재사용합니다. 테스트 우회·공용 키는 없습니다.
- 흰색 작업 화면, 대시보드와 번호형 작업 흐름, API키등록·플랫폼연동, 메뉴 바로 아래 회원 이메일·로그아웃, 390px 모바일 메뉴.
- 날짜·분류·검색·우선순위 정렬, 할 일 작성·메타데이터 수정·완료/취소·휴지통·복원, 분류 추가·참조/예약어 검사·기본값 보정.
- deadline 기반 집중/휴식 세션, 일시정지·재개·정산 종료, 완료/휴지통 이동 시 원자적 종료. 시간 수정값 주입 차단, 휴식 제외, 한국 자정 분할. 매초 DB 쓰기 없음.
- 선택 범위 완료율·실측 표본 정확도·성과 참고값·2시간 단위 완료 차트. 실측 없는 정확도는 미측정, 정확도 표본이 없으면 완료율 기준 참고값입니다.
- 노트는 명시적 저장 버튼으로 저장합니다. 자동 저장은 이 단계에 구현하지 않았습니다. 서버 응답 성공 때만 저장 완료를 표시하며 실패·409·응답 유실 재시도 시 입력/요청 ID를 보존합니다.
- 전체 기록 JSON 다운로드. 실행 중 구간은 백업 안에서 일시정지 snapshot으로 저장하며 실제 세션을 멈추지 않습니다. 복원·CSV·원본 JSON 변환은 다음 단계입니다.
- AI 성과 분석은 준비 중으로 표시하고 호출 버튼을 비활성화했습니다. 본인 키 등록은 현재 AIMaster 공통 설정 링크를 제공합니다. 다음 단계에서 실제 본인 Gemini 모델 선택·분석·매뉴얼을 연결합니다.

## 기록 구조 결정

계획의 7개 테이블 대신 **회원별 workspace JSONB 한 행 + revision + command ID + 트랜잭션 RPC**로 초기 저장을 구현했습니다. 할 일·세션·분류·설정·노트의 참조를 서버 Zod 검증으로 확인하고 한 명령의 기록 전체를 원자적으로 확정합니다. 세션은 독립 목록으로 보존하므로 할 일 메타데이터 수정이 시간을 덮어쓰지 않습니다. 회원끼리는 별도 행이고 서버 조회에는 인증된 user_id 조건을 반드시 적용합니다.

사용자당 8MiB, 5,000개 할 일·20,000개 세션 제한이 있습니다. 대용량 장기 이력을 별도 조회하는 정규화/페이지 분할은 후속 과제입니다. 일반 회원·비로그인은 REST 테이블·RPC를 직접 읽거나 수정할 권한이 없습니다. 권한 검사를 통과한 서버 API만 service_role로 접근합니다. RLS와 소유자 SELECT 정책도 설정하며 서버의 명시적 user_id 제한을 병행합니다.

중복 요청은 최근 200개 command ID로 성공 응답을 재사용합니다. 보존 범위를 지난 오래된 요청도 기존 revision 때문에 409로 차단되어 다시 가산되지 않습니다. 두 탭/기기의 수정은 revision 충돌로 차단합니다. 서버 기록만 영속 저장소이며 로컬의 시험용 메모리 저장소는 운영 코드에 없습니다.

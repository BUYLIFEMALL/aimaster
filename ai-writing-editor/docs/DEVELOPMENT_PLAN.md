## 1. 원본 분석

### 기능
| 영역 | 동작 |
|---|---|
| 새 글 생성 | 프롬프트 + 글쓰기 형식 5종(블로그 게시물·에세이·이메일·보고서·자유 형식) + 참고 파일(텍스트) + 인터넷 검색(구글 검색 그라운딩, 출처 표시). 블로그는 메타 제목·메타 설명·H1~H3 구조를 요구하는 SEO 프롬프트 |
| 기존 글 분석 | 글을 붙여넣거나 파일로 올리면 곧바로 에디터로 열고 전체 분석 |
| 인라인 수정 | 텍스트 영역에서 드래그하면 플로팅 툴바(다시쓰기·짧게·자세히·전문적으로·친근하게) |
| 전체 글 분석 | `{originalText, suggestedText, reason}` 배열(JSON 스키마) → 사이드바, 마우스를 올리면 본문 하이라이트, [적용] 시 `replace` |
| 기타 | 본문 복사, 홈으로(초기화), 도움말 모달 |

### 모델·구현
- 생성 `gemini-2.5-pro`(+`googleSearch`), 선택 수정 `gemini-flash-latest`, 분석 `gemini-2.5-pro` + responseSchema. 키는 AI Studio가 브라우저에 주입(`process.env.API_KEY`).

### 약점(통합 버전에서 해결)
1. 저장이 없다 — 새로고침하면 글이 사라진다. → 문서 자동 저장(최근 30개), 이어쓰기.
2. 제안 적용이 `String.replace`(첫 일치)라 같은 문장이 여럿이거나 본문이 바뀐 뒤엔 엉뚱한 곳을 바꾼다. → 적용 시점에 위치를 다시 찾고 없으면 "바뀌어 적용할 수 없음" 처리, 모두 적용·무시 추가.
3. AI 오류 시 원문을 조용히 돌려준다(사용자는 성공으로 오해). → 오류를 명확한 한국어 메시지로 표시, 키 없음 안내.
4. 되돌리기가 없다. → 편집 이력 되돌리기(최대 50단계).
5. 플로팅 툴바 위치 계산이 숨은 div 반복 생성·측정이라 느리고 어긋난다. → 한 번 만드는 거울(mirror) 요소로 캐럿 좌표 계산, 가장자리 보정.
6. "직접 지시"가 없다(5가지 고정 동작뿐). → 선택 영역에 자유 지시문(예: "초등학생도 이해하게") 추가.
7. 파일을 `file.text()`로 아무거나 읽는다. → .txt/.md/.csv만, 크기·글자 수 제한.
8. 분석 제안에 분류가 없어 많아지면 읽기 어렵다. → 문법·표현·구조·명확성 분류와 필터.
9. 어두운 고정 테마·도움말 모달 → AIMaster 흰색 표준 UI + 사용 매뉴얼 페이지.
10. 프롬프트에 날짜·연도 기준이 없다. → 모든 프롬프트에 당해 연도 지침(핵심 원칙 8번).

## 3. 구조
- `src/lib/we/`(순수 로직·단위 테스트): `types`, `util`(연도 지침·정리·제안 정규화·위치 찾기/치환), `prompts`.
- 서버: `gemini.ts`(모델 폴백·JSON 재시도·그라운딩 출처), `documents.ts`, `aiRoute.ts`.
- API(모두 `checkProgramAccessApi` + `force-dynamic`): `POST /api/generate`, `POST /api/rewrite`, `POST /api/analyze`, `GET/POST/PUT/DELETE /api/documents`, `/api/keys`(+`/test`).
- 화면: `/dashboard`(새 글 생성·기존 글 분석·최근 문서), `/editor/[id]`(에디터: 텍스트 영역 + 플로팅 툴바 + 분석 사이드바), `/documents`, `/settings`, `/guide`.

## 5. 리스크
- 텍스트 영역 위 하이라이트 합성이 브라우저마다 어긋나므로 "본문에서 보기"는 선택(setSelectionRange)+스크롤로 구현.
- 제안의 `originalText`가 본문과 글자 단위로 일치해야 한다 → 서버에서 일치하지 않는 제안을 걸러낸다.
- 긴 글: 분석 입력 상한 30,000자(초과 시 앞부분만 분석한다고 안내).

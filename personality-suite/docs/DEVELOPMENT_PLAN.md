| 결과 | 로컬 계산(`calculate`) → 결과 모달: 유형·부제·설명(HTML 문자열) + **AI 분석 버튼** |
| AI 분석 | `gemini-2.5-flash`로 프롬프트 1회: MBTI형은 "성장 조언 3가지"/"어울리는 직업 3가지+환상의 궁합 유형 1가지", 그 외는 "일상 실천 조언 3가지". 결과 텍스트를 정규식으로 HTML로 바꿔 `dangerouslySetInnerHTML` 렌더링 |
| 기타 | 라이트/다크 테마, 사용 설명서 모달, 광고성 크레딧(개발자 유튜브 링크) |

### 1-2. 데이터 모델(`types.ts`)
- `Test = MbtiTest | ScoreTest`. `MbtiTest`: 문항(text, icon), `scoringMap`(문항→[지표쌍]), `results: Record<유형, {subtitle, description}>`, `calculate(answers)`. `ScoreTest`: 문항(text, category, icon), 선택지(value,text), `results`, `calculate`. 결과 키는 유형 문자열.
- 검사 수는 16개, 결과 문구는 파일마다 직접 작성된 HTML 문자열(`<p><strong>…`).

### 1-3. 약점·위험 (통합 버전에서 해결)
1. **API 키가 앱에 주입돼 모든 사용자가 한 키를 씀** → 회원 본인 Gemini 키로 서버에서 호출, 없으면 안내(AI 분석만 키 필요, 검사·기본 결과는 키 없이 가능).
2. **AI 출력을 HTML로 바꿔 `dangerouslySetInnerHTML`** → 저장·렌더 모두 구조화 데이터(JSON 스키마) + React 요소 렌더링(HTML 주입 없음).
3. **결과가 저장되지 않음** → 내 기록(최근 100건), 같은 검사의 변화 비교, 여러 검사를 합친 **종합 프로필**(원본에 없는 "종합"의 실질).
4. **전 문항을 한 화면에 나열** → 한 문항씩 진행바·이전/다음·이어하기(임시 저장), 모바일 친화.
5. **임상 검사처럼 보이는 콘텐츠**: "MMPI 참고 정신 건강 체크", "TCI", "DISC", "MBTI"는 상표·저작권·의료 오해 위험 → 아래 3절 원칙.
6. 크레딧·광고 링크, 어두운 고정 테마 → AIMaster 흰색 표준 UI.
7. 모든 프롬프트에 연도·날짜 기준 없음 → 당해 연도 지침(핵심 원칙 8번).

## 3. 콘텐츠·법적·안전 원칙 (결정 사항)
1. **문항·결과 문구는 전부 새로 작성한다.** 원본 앱의 문장을 쓰지 않는다. 공식 검사의 문항·리포트도 베끼지 않는다(기존 `mbti/README.md` 원칙과 동일).
2. **상표·저작 검사 이름을 서비스 이름과 검사 이름의 전면에 쓰지 않는다.**
   | 원본 표기 | 우리 표기 |
   |---|---|
   | MBTI | "16유형 성격 검사"(설명에 "MBTI는 The Myers-Briggs Company의 상표이며 이 검사와 무관" 고지) |
   | DISC 행동유형 | "행동 스타일 검사(주도·사교·안정·신중)" |
   | TCI 기질 및 성격 | "기질·성향 점검"(문항·척도 새로 작성, 공식 TCI 아님 고지) |
   | 정신 건강 간편 체크(MMPI 참고) | "스트레스·마음 상태 자기점검" — **진단 아님**, MMPI 언급 금지 |
   | Big 5, 에니어그램, 애착유형 | 학술·일반 개념이라 이름 사용 가능(문항은 자체 작성) |
3. **정서·마음 상태 점검은 별도 안전 설계**(v1.02에서 출시): 진단·치료 오해 금지 문구, 점수 구간별 일반 안내, 위험 신호 문항이 해당되면 **AI와 무관하게(고정 문구로)** 위기 상담 안내(자살예방 상담전화 109, 정신건강 위기상담 1577-0199, 청소년 1388 — 구현 시 최신 번호 재확인), AI 프롬프트는 진단·약물·치료 언급 금지. 결과 저장은 **기본 꺼짐**(민감 정보) + 즉시 삭제.
4. **AI 분석은 "참고용 해석"**이라고 모든 결과 화면에 표시. 직업·관계 조언은 단정하지 않는다.

## 5. 구조
- 골격: `ai-writing-editor`/`blog-keyword`에서 복사(Next.js 16, `access.ts`·`proxy.ts`·사이드바·키 관리 재사용).
- `src/lib/tests/`(순수 데이터·로직, 단위 테스트): `types`(Test, Question, Scale, Result), `content/*.ts`(검사별 문항·유형·해석), `scoring.ts`(축 점수·역문항·유형 결정·동점 처리), `registry.ts`(검사 목록·탭), `prompts.ts`(AI 분석 프롬프트·JSON 스키마, 연도 지침).
- 서버: `gemini.ts`(모델 폴백·JSON 재시도·`MAX_TOKENS` 감지, 사고 토큰 한도 주의), `results.ts`(저장·정리), `aiRoute.ts`.
- API(모두 `checkProgramAccessApi` + `force-dynamic`): `POST /api/analyze`(검사 id + 답변 → 점수 서버 재계산 + AI 분석), `GET/POST/DELETE /api/results`, `POST /api/profile`(종합), `/api/keys`(+`/test`).
  - 점수는 **서버에서 답변으로 다시 계산**한다(클라이언트가 보낸 점수를 믿지 않음).
- 화면: `/dashboard`(탭: 16유형 / 심리·성격, 검사 카드), `/test/[id]`(한 문항씩), `/result/[id]`(결과·AI 분석), `/history`, `/profile`, `/settings`, `/guide`.
- DB: `personality_suite_results`(user_id, test_id, scores jsonb, result_type text, answers jsonb|null, analysis jsonb|null, created_at). 정서 점검 계열은 `answers`를 저장하지 않는다.

## 7. 리스크
1. **콘텐츠 작성 분량이 가장 크다**: 약 330문항 + 유형별 해석 수십 건(상황별 변형 10종은 4축 점수 공유 + 변형별 해석 문구). AI 초안 + 단위 시험으로 구조 검증, 심리학적 타당성은 "재미·자기이해 참고용" 고지로 한정.
2. **상표·저작권**: 3절 표기 원칙, 공식 검사 문항 미사용.
3. **민감 정보**: 정서 점검 결과는 기본 저장 안 함, 삭제 기능, 개인정보 안내 문구.
4. **AI 오남용**: 의학적 진단·단정 금지 프롬프트, 위기 안내는 고정 문구.
5. **Gemini 사고 토큰**: 분석 호출 `maxOutputTokens`를 넉넉히(8,192+) 하고 `truncated`면 재시도.

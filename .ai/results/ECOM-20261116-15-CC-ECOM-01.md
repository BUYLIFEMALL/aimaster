## 1. 식별 기준 정리(편집 전)
- 연결 모드는 일괄 실행 중 상품마다 결과를 부모 창으로 바로 보낸다(실행 중 전송) + 4단계 「상세페이지 상품에 반영하기」(다시 보내기).
- 부모의 저장 확인(`aimaster-product-photos-saved`)에는 `jobId`·`productId`·`ok`만 있고 결과 판번호가 없다.
- 그래서 **상품 번호만**으로 「저장됨」을 이으면, 설정을 바꾼 새 결과까지 저장됨으로 잘못 표시된다. 반대로 시작 때 결과를 비우면(기존 368줄) 저장됨이 사라져, 같은 그림을 다시 보낸다.
- 기준: **연결 작업(`linkedJobId`) + 상품 번호 + 합성 설정 판번호(`settingsVersion`, 모든 설정 해시)**. 같은 작업·같은 사진·같은 설정이면 같은 그림.

## 2. 고친 것
- 참조 3개: `sentVerRef`(상품 → 마지막으로 보낸 결과 판번호), `savedVerRef`(상품 → 저장 확인된 판번호), `runVerRef`(화면 결과를 만든 실행 판번호).
- 새 작업(`jobId` 다름) 수신 시 두 기록 비움 — 같은 상품 번호라도 다른 작업과 섞지 않음.
- 저장 확인(`ok`)은 그 상품에 마지막으로 보낸 판번호로 기록(실행 중에 도착해도 잃지 않음). 실패 응답은 기록 안 함.
- 실행 중 전송: 같은 판번호로 이미 저장된 상품은 **보내지 않고 「저장됨」**, 아니면 보내고 판번호 기록.
- 실행 끝 병합: 이전 결과 비교(빈 목록이라 무력) 대신 판번호 기록으로 「전송 중 → 저장됨」 반영.
- 「반영하기」: 화면 결과의 판번호(`runVerRef`)로 이미 저장된 상품 제외, 보낼 때 판번호 기록(예전엔 버튼 누를 때의 현재 설정 판번호를 보냄 → 결과와 다를 수 있었음).

## 6. Master 지적 2건 — 원인 분석·가능 대안(코드 동결, msg_8f8bf3d60ded · 실재현은 MOV-11)
### 6-1. 늦은 V1 저장 응답이 V2 전송 뒤 도착
- 원인(코드 읽기): 저장 응답(`aimaster-product-photos-saved`)에는 판번호가 없어, `onMessage`가 `sentVerRef.get(productId)`(마지막으로 보낸 판번호)를 저장된 판번호로 기록한다. V1 전송 → 설정 변경 → V2 전송(`sentVerRef`=V2) → **V1의 ok가 늦게 도착**하면 `savedVerRef`=V2로 잘못 기록 → 다음 V2 재합성·「반영하기」에서 V2를 **보내지 않고 「저장됨」** 표시(실제 V2는 미저장 — 누락 쪽 오류, 중복보다 나쁨).
- 대안(제가 고르지 않음, Master 판단):
  - 가. **계약 확장**: 바나나가 이미 보내는 `settingsVersion`을 상세·쇼핑몰이 저장 응답에 그대로 되돌려 주고, 바나나는 그 값으로만 기록. 정확하지만 수신 프로그램 2개(`shop-detail-page`·`mall-builder`) 계약 변경 — 임의 변경 금지라 담당 협의 필요.
  - 나. **보수 규칙(바나나만)**: 상품별 「응답 대기 중 전송 수」를 세어, 대기 1건일 때만 그 판번호로 기록하고 2건 이상이면 기록하지 않음(응답 순서 가정 없음). 오판 시 「다시 보냄(중복)」 쪽으로만 틀림 — 누락은 없음.
  - 다. 대기 중인 상품은 새 판번호 전송을 미루기(응답 뒤 전송). 시간 지연·응답이 안 오면 막힘.
### 6-2. 같은 작업·같은 상품에서 입력 사진만 바뀌고 설정은 그대로
- 확인한 것: `settingsVersion`은 `CompositeSettings`만 해시 — 공용 서브 사진·`subMode`·입력 사진은 포함 안 됨.
- 연결 모드 실제 경로: 사진은 받은 메시지로 `filesMap["<상품ID>#<번호>"]`에 고정되고, 연결 모드에선 `buildJobs` 재계산이 막혀 있고(234줄), 공용 서브는 참조 이름이 겹치지 않아 쓰이지 않음, 사진 직접 추가는 파일 이름 키라 `#` 참조를 덮지 않음 → **화면 조작으로 바꿀 길은 코드상 없어 보임**.
- 남는 빈틈: 부모가 **같은 `jobId`로 다른 사진을 다시 보내면** 기록을 비우지 않아(작업 번호가 같으면 유지) 같은 설정의 새 사진을 「저장됨」으로 오판 가능. 부모가 같은 jobId를 재사용하는지는 미확인.
- 대안: 가. 판번호에 상품별 입력 지문(사진 크기·형식·`baseRevision`)을 더하기 / 나. 작업 메시지를 받을 때마다(jobId 같아도) 기록 비우기(가장 단순, 같은 작업 재수신 시 다시 보냄 = 중복 쪽).

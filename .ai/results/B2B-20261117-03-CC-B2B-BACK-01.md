## 2. 공통 계약
- DB 계약 = 0102 함수 4개 인자 그대로(`p_item_id, p_qty, p_to_variant_id, p_reason, p_memo` / `p_exchange_id, p_step, p_courier, p_tracking, p_note` / `p_exchange_id, p_fee` / `p_exchange_id`). 권한·기간·수량·재고·결제 검사는 DB가 다시 함, 화면은 버튼 감춤만.
- 사유 값 `size·change_mind·defect·wrong_item·other`, 단계 값 `requested·collecting·collected·reshipped·done·rejected`, 교환비 상태 `none·waiting·paid`.
- 서버 동작 모양 = 반품과 같음: `(slug, exchangeId|itemId, backPath, form)` → `finish()`로 `?ok=1&msg=` / `?error=`.
- 배송 조회 링크는 M2-11 기존 함수 재사용(회수·재발송 송장).
- 0102 미적용 DB(운영 지금)에서는 패널이 아무것도 안 보이게(읽기 오류 = 빈 목록) — 다음 묶음 배포 때 0102와 함께 나가므로 순서 문제 없음.

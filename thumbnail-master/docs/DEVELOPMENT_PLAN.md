> 분석 방법(핵심 원칙 14번): 공개 HTML과 메인 JS 번들(`/assets/index-BONrdSW4.js`, 450KB)을 통째로 내려받아 앱 코드 구간(전략 생성 프롬프트·응답 스키마·이미지 생성/수정 프롬프트·컴포넌트 5단계·도움말·키 저장 로직)을 전부 정독했다. 서버·별도 API 없음 — 순수 클라이언트 앱이다. 내려받은 파일은 실행하지 않고 읽기만 했다.

## 1. 원본 분석

### 1-1. 한 줄 요약
영상 주제(또는 대본 파일)와 시청 타겟·피사체를 고르면 AI가 **두 가지 전략(A안 직관·정보형 / B안 호기심·감성형)**의 메인·서브 문구와 이미지 프롬프트를 제안하고, 확정하면 **Gemini 이미지 모델이 문구가 박힌 16:9 썸네일 2종을 동시에 만들어** 주며, 마음에 안 드는 부분은 문장으로 수정 요청하는 5단계 마법사다. 서버 없이 브라우저에서 Gemini를 직접 호출하고 기록은 남기지 않는다.

### 1-2. 화면 구성 (단일 페이지, 상태 머신 5단계)
`TOPIC → CHARACTER → AUDIENCE → STRATEGY → IMAGE`
1. **주제 입력**: 텍스트 영역(예시 "집에서 만드는 초간단 알리오올리오 파스타…") + 문서/대본 업로드(`.txt .md .csv .json .js .ts .py …`, FileReader 텍스트 읽기, 크기 KB 표시·제거) → [다음 단계].
2. **썸네일 등장 인물 설정**: "캐릭터/피사체 포함" 토글. 켜면 종류(사람/동물/사물) — 사람: 성별(남/여), 연령대(10대·20대·30-40대·50대 이상·어린이), 인종/국적(한국인 기본·백인·흑인·동양인·히스패닉·다문화/판타지); 동물·사물: 자유 입력. 끄면 텍스트·그래픽 위주.
3. **타겟 선택**: 10대~20대 초반(도파민·고채도·밈) / 20대 후반~40대(세련·미니멀·신뢰·정보) / 50~60대 이상 시니어(시인성 극대화·원색 대비) / 전연령(MrBeast 스타일, 3단어 법칙). 선택 즉시 전략 생성 호출.
4. **전략 제안**: 전략 요약(3줄) + Option A/B 카드(전략 이름·메인 문구·서브 문구·텍스트 스타일 제안, 문구는 직접 수정) + 추가 스타일(테두리: 없음/단색 강조/네온 글로우/손그림·낙서, 브랜딩: 채널명 표시) + 이미지 프롬프트(한국어, 복사) → [썸네일 2종 생성하기](약 20초).
5. **결과**: 2종 나란히, 각각 JPG 다운로드(흰 배경 합성 후 JPEG 0.95, `thumbnail_option_A/B.jpg`), 수정 요청 입력(예: "텍스트를 노란색으로", "표정을 더 놀라게") → 해당 이미지만 재생성, [전체 다시 만들기](전략 단계로).
헤더: 로고·"Powered by Gemini Nano Banana Pro"·도움말·API 설정 / 푸터: 개발자 크레딧·유튜브 링크. 어두운 고정 테마(#0F0F0F, YouTube 레드).

### 1-3. 핵심 로직 (우리가 기준으로 삼는 내용)
- **전략 생성**(`gemini-2.5-flash`, JSON 스키마 강제): 시스템 지침 = "유튜브 썸네일 트렌드를 선도하는 전문 아트 디렉터", 타겟 분석 문단, 캐릭터 요구(사람: 사실적 인물·성별/인종/연령·"표정은 매우 풍부하게(놀람·흥분·눈물·결의)", 동물/사물: 상세, 없음: 텍스트·그래픽 중심), A안(구체 숫자·이득, "5분 만에 100만원 버는 법") / B안(궁금증·질문·강렬한 단어, "아직도 이걸 모르시나요?"), 공통 규칙(메인 3~5단어·서브 필수[숫자/vs/기간]·"Hyper-realistic, 8k, High Contrast, Cinematic Lighting"). 출력: `strategySummary`, `imagePrompt`(영어, 텍스트 제외), `imagePromptKo`(번역 표시용), `option1/2{label, hookMainText, hookSubText, textStyleSuggestion}`. 첨부 문서는 앞 3만 자만 사용.
- **이미지 생성**(`gemini-3-pro-image-preview`, `aspectRatio 16:9`, `imageSize 2K`): 역할 "Professional YouTube Thumbnail Designer" + 비주얼 프롬프트 + 옵션별 스타일 + **텍스트 렌더링 지시(MAIN/SUB 문구를 이미지에 그려 넣기)** + 테두리 규칙 + 채널명 브랜딩 + 타겟별 텍스트 규칙(시니어: 특대 굵은 산세리프·노랑/검정·텍스트 화면 30~40%, 그 외: 임팩트 굵은 폰트·그라데이션/외곽선/그림자) + "문구가 얼굴·눈을 가리지 않게, 네거티브 스페이스에 배치, 8k·하이퍼리얼리즘". A/B 2건을 `Promise.all`로 동시 호출.
- **이미지 수정**: 이전 이미지(PNG base64) + "Modify this thumbnail image. Instruction: …"를 같은 이미지 모델에 보내 전체를 다시 생성(진짜 인페인팅이 아니라 지시문 기반 재생성).
- **API 키**: `localStorage`에 고정 문자열 XOR + base64(사실상 평문), 화면은 "암호화되어 저장" 표기. 연결 테스트는 `gemini-2.5-flash`에 "test" 호출.

### 1-4. 전략 출력 스키마 (우리 기준)
`{ strategySummary, imagePrompt, imagePromptKo, option1{label,hookMainText,hookSubText,textStyleSuggestion}, option2{…} }` — 그대로 유지하되 서버에서 필드 검증·길이 제한·문구 정리(메인 3~5단어 초과 시 경고 표시)를 추가한다.

### 1-5. 결함·한계 (우리 버전에서 해결)
1. **키 보안**: 키를 브라우저에 거의 평문(고정 키 XOR)으로 보관하면서 "암호화" 표기 — 사실과 다름. 우리: 서버 `user_api_keys` + 서버에서만 호출.
2. **결과가 사라진다**: 새로고침하면 전략·이미지 전부 소실, 되돌릴 수 없음. 우리: 프로젝트 저장(전략·설정·이미지)과 불러오기.
3. **수정 이력 없음**: 수정하면 이전 이미지를 덮어써 마음에 안 들면 복구 불가. 우리: 이미지 버전 목록(최근 5개)과 되돌리기.
4. **용어 과장**: "AI Inpainting"이라 쓰지만 실제로는 전체 재생성. 우리: "AI 수정 요청(전체 재생성)"으로 정확히 표기, 원본 유지·새 버전 추가.
5. **오류 처리**: 안전 필터·한도·키 오류·이미지 미반환을 구분하지 않고 일반 문구, 한쪽 이미지만 실패해도 둘 다 실패 처리. 우리: 오류 분류·옵션별 개별 재시도.
6. **인물 기본값 고정관념 없음/있음**: 기본이 "여성·20대·한국인"으로 고정. 우리: "자동(주제에 맞게)" 기본, 한국인 외모 기본 규칙(핵심 원칙 3번) 유지.
7. **옵션 부족**: 이미지에 문구를 넣지 않는 "배경만 생성" 옵션, 문구 색 지정, 해상도 선택(1K/2K), 프롬프트 직접 수정이 없음. 우리: v1.01에 "문구 직접 넣기/배경만" 토글과 이미지 프롬프트 직접 수정 포함.
8. **대본 파일**: 코드 파일(.js .ts .py .c …)까지 받지만 의미 없음, 앞 3만 자만 사용하면서 사용자에게 안내 없음. 우리: 텍스트 문서(txt·md·csv)만, 잘림을 화면에 표시.
9. 어두운 고정 테마·개발자 크레딧 하드코딩 — AIMaster 흰색 표준과 불일치.
10. **연도**: 프롬프트에 기준 연도 규칙이 없음(주제에 연도가 들어가면 과거 연도로 쓸 수 있음). 우리: 당해 연도 주입(핵심 원칙 8번).

### 1-6. 확인한 사실
- 이미지 모델 `gemini-3-pro-image-preview`는 운영자 본인 키로 호출해 카탈로그 썸네일을 정상 생성(2026-10-13~14). 폴백 후보 `gemini-2.5-flash-image`(나노바나나)는 `generate-program-thumbnail.mjs`가 같은 순서로 쓰고 있다. 텍스트(전략)는 `gemini-3.5-flash` 정상.
- **2K 이미지 응답은 4~7MB**(PNG)라 Vercel 함수 응답 한도 4.5MB를 넘을 수 있다 → 서버가 이미지를 Storage에 저장하고 서명 URL만 돌려주는 구조가 필수(§4).

### 1-7. 기존 `seo-thumbnail-pro`와의 관계 (결정)

## 3. 기능 범위

### v1.01 (원본 동등 + 결함 해결)
1. 주제 입력·대본 파일(txt·md·csv, 3만 자 초과 시 잘림 안내), 예시 주제.
2. 피사체 설정(사람/동물/사물/없음, 성별·연령대·국적·표정 강도), 타겟 4종.
3. 전략 생성(A/B 문구·스타일, 요약, 이미지 프롬프트 KO/EN), **다시 생성**, 문구·프롬프트 직접 수정, 글자 수 경고(메인 3~5단어).
4. 스타일: 테두리 4종, 채널명 브랜딩, 문구 직접 넣기/배경만 생성, 해상도 1K/2K.
5. 생성: 2종 병렬, 옵션별 진행 표시·개별 재시도, 결과 JPG/PNG 다운로드, 확대 보기.
6. 수정 요청: 지시문 → 새 버전 추가(원본 유지), 버전 되돌리기, 전체 다시 만들기.
7. 프로젝트 저장·열기·이름 변경·삭제, 자동 저장(변경 후 1.2초).
8. 오류 분류(키 없음/한도/안전 필터/이미지 미반환/시간 초과)와 한국어 안내(alert 미사용), 취소.
9. API키등록·플랫폼연동(Gemini 1종) + 연동 매뉴얼 팝업 + 사용 매뉴얼 페이지.

### 후속
썸네일 A/B 비교 보드, 참고 이미지 업로드(스타일 레퍼런스), 일괄 생성(영상 여러 개), 채널 로고 이미지 합성, 영어 UI.

## 4. 아키텍처
- Next.js 16 App Router + TS, 순수 CSS. `reverse-prompt`/`landing-architect`의 골격(접근 판정·사이드바·키 관리·로그인·`/open`·도메인 SSO 쿠키)을 그대로 복사해 시작(v1.01).
- `src/lib/tmb/`(순수 로직, 단위 테스트): `types`(입력·전략·옵션), `audience`(타겟 4종 규칙·시니어 모드 지시), `prompts`(전략·이미지·수정 프롬프트 조립, 연도 주입, 한국인 기본), `strategy`(응답 검증·정규화·글자 수 경고), `validate`(입력 정리·파일 텍스트 정리·경로 검증).
- 서버 API(전부 `checkProgramAccessApi` + `force-dynamic`): `POST /api/strategy`(전략 생성·재생성), `POST /api/generate`(옵션 1개 이미지 생성→JPEG 변환→Storage 저장→버전 기록, `maxDuration 120`), `POST /api/edit`(Storage 원본 + 지시문 → 새 버전), `GET/POST /api/projects`, `GET/PUT/DELETE /api/projects/[id]`(서명 URL 포함 조회), `/api/keys`.
- DB: `thumbnail_master_projects(id, user_id, name, topic, audience, subject jsonb, strategy jsonb, texts jsonb, style jsonb, images jsonb, created_at, updated_at)` + RLS owner-only(서버는 service role + `user_id` 필터). Storage 비공개 버킷 `thumbnail-master-images`(첫 폴더=uid, 서버만 서명/읽기/삭제, 프로젝트 삭제 시 이미지도 삭제).
- 이미지 변환에 `sharp`(Vercel 기본 지원)를 추가한다. 환경변수 새로 추가 없음(공용 Supabase 3종만). Vercel 프로젝트·도메인은 신규.

## 5. 등록·썸네일
`programs` 등록(slug `thumbnail-master`, 카테고리 유튜브, 최소 등급 일반, 배지 `new`, `app_url`, v1.01) + 요금제 3종 + VIP 등급 접근. 썸네일은 `PLATFORM_PATTERNS.md §13` 템플릿 + `scripts/generate-program-thumbnail.mjs`(한국인 실사 16:9: 크리에이터가 모니터의 썸네일 비교 화면을 보는 장면, 이미지 안 글자 없음)로 생성해 다른 썸네일과 나란히 비교 후 등록.

## 7. 리스크
1. **이미지 생성 비용·시간**: 생성 1건당 본인 키 비용(2K 이미지), 2종 동시 생성은 2건 — 화면에 "이미지 2건 생성(본인 키 사용량)" 안내, 1K 옵션 제공.
2. **한글 문구 렌더링 품질**: 모델이 한글을 깨뜨릴 수 있음 → "배경만 생성" 옵션, 수정 요청, 문구 짧게(3~5단어) 유도. 품질은 실호출로 확인해 매뉴얼에 한계를 명시한다.
3. **응답 4.5MB 한도**: 이미지는 JPEG 변환 후 Storage 서명 URL로만 전달(§4).
4. **안전 필터**: 인물·유명인 요청이 차단될 수 있음 → 오류 분류와 안내, 특정 실존 인물 요청은 매뉴얼에서 금지 안내.
5. **저장소 증가**: 프로젝트 30개·옵션별 5버전 제한, 오래된 버전 자동 삭제, 프로젝트 삭제 시 이미지 동시 삭제.
6. **유사 프로그램 중복**: `seo-thumbnail-pro`와 역할 구분을 카탈로그 설명에 명시(§1-7).
7. **모델명 변동**: 모델 체인 상수화, 화면에 실제 사용 모델 표시.

## 8. 승인 요청 사항
위 플랜대로 구현을 시작해도 되는지 확인이 필요합니다("진행해줘"). 구현 시 새로 하는 외부 영향 작업: 비공개 이미지 Storage 버킷 1개와 프로젝트 테이블 1개 생성, `sharp` 패키지 추가, Vercel 프로젝트·도메인 신규, 카탈로그 썸네일 생성(Gemini 이미지 1회, 운영자 본인 키), 실호출 검수 시 이미지 생성 몇 건(운영자 본인 키).

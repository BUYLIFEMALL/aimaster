## 1. 프로그램 로직 및 기능 개선

1. **티스토리 크롬 확장 연결 상태 실시간 웹 브릿지 표시**:
   - 현재는 확장이 설치되어 있는지 여부를 사이드바나 웹 상단에서 직관적으로 알기 어렵고, 카테고리 불러오기나 발행 패널을 눌러야 확장의 존재 여부를 알 수 있음.
   - 대시보드 및 헤더에 `chrome.runtime` / `window.postMessage` 웹 브릿지 핑을 통해 "확장 연동 활성화됨 (v1.82)" 또는 "확장 미설치/꺼짐" 상태 뱃지를 상시 띄워 사용자 피드백 강화 필요.
2. **글감 수집 시 뉴스 키워드 자동 트렌드 추천**:
   - 현재는 사용자가 직접 검색어/URL/RSS를 넣어야 함. 네이버 실시간 검색어나 Google Trends API 또는 Perplexity 실시간 핫토픽을 자동으로 크롤링/제안하여 클릭 한 번으로 후보를 자동 채워주는 기능 도입 검토.
3. **티스토리 서식(HTML) 템플릿 프리셋 다양화**:
   - 현재는 단일 블로그 본문 서식(소제목 밑줄, 요약 인용구, 이미지 라운딩)만 지원.
   - 'IT 리뷰형', '정보성 가이드형', '스토리텔링형', '뉴스 브리핑형' 등 4가지 HTML/CSS 템플릿 프리셋을 선택할 수 있도록 옵션 확장 제안.

## 3. 현재 만들어져 있는 다른 자동화 프로그램과의 연계가능한 기능

1. **쇼츠 떡상 분석(`shorts-viral-studio`, 31번)과의 글감 파이프라인 결합**:
   - `shorts-viral-studio`에서 분석 완료된 대본 및 핵심 분석 포인트를 티스토리의 `/candidates`로 "1-Click 티스토리 원문 글감으로 내보내기" 버튼 연계.
   - 쇼츠 영상의 핵심 요약과 해설을 티스토리 롱폼 블로그 글로 원스톱 변환하는 크로스 플랫폼 워크플로우 구축 가능.
2. **AI 이미지 자동화(`ai-image-studio`, 34번) 레퍼런스 및 갤러리 연동**:
   - 본문 내 삽입 이미지를 생성할 때 `ai-image-studio`의 최신 이미지 모델 엔진(`gemini-nano-banana-2.1`, `gemini-3-pro-image`)을 사용하는 공용 모듈을 고도화하고, 이미지 스튜디오에서 생성해 둔 갤러리 보관함에서 직접 이미지를 불러와 에디터에 배치하는 기능 연계.
3. **네이버 블로그 원스톱 자동화(`naver-blog-agent`, 29번)와의 원문 교차 발행**:
   - 동일한 주제로 생성된 원문을 티스토리용(TinyMCE/HTML 포맷)과 네이버 블로그용(SmartEditor ONE 클립보드 포맷)으로 동시 분기하여 1회 생성으로 2대 블로그에 동시 발행할 수 있는 크로스 퍼블리싱 파이프라인.

## 4. 타 서브프로그램 탐색 기반 추가개선 제안

1. **`ai-auto-blog` (네이버 블로그 자동화)**:
   - 티스토리와 유사하게 크롬 확장을 사용하고 있으나, 티스토리처럼 예약 발행이나 홈주제 매핑이 세분화되어 있지 않음. 티스토리의 발행 설정 패널(`TistoryPublishPanel`)의 UX 패턴을 네이버 블로그에도 동일하게 적용 권장.
2. **`threads-content-ops` (Threads 콘텐츠 운영 자동화)**:
   - 티스토리에서 작성된 고품질 장문 포스팅을 3~5줄 스레드 연작(Thread Series)으로 자동 요약/변환하여 스레드로 바로 내보내는 원스톱 콘텐츠 리사이클링 기능 제안.


## 2026-10-21 최종 자동 발행·URL 기록 착수

기존 publish_ready는 실제 게시 완료가 아니다. 최신 주인님 요청에 따라 [자동 포스팅 플랜](PLAN_20261021_AUTO_PUBLISH.md)으로 선점/잠금·최종 클릭 1회·실제 결과 기록/불확실 복구를 추가한다. 구현/실제 발행 검수 전 완료 표시 금지. SEO v1.83 종료 뒤 순차 착수, DB esgxyikcnnvmlhygjkth 스키마 변경 예정 없음.


### 실구현 중 검토·보완 근거

- 새 자동 모드는 기존 임대 만료 뒤 재전송도 차단하며 발행 선점 기록을 보존한다. 수정/삭제/재전송의 서버 조건부 갱신을 묶어 늦은 저장/옛 결과가 덮지 못하게 했다. 기존 DB JSON에 revision/자동 실행 상태만 저장하며 스키마 변경은 없다.
- 오래된 확장에는 자동 발행 작업을 전달하지 않도록 capability를 분리했다. 기존 수동 준비·예약 동작은 회귀로 보존한다.
- 최종 검사에서는 HTML 원문과 화면 전체 문자열을 직접 비교하지 않고 기존 의미 구조/문단 검사를 유지한다. 그 검사를 통과한 실제 편집기 스냅샷을 기준으로 설정 중 변경/링크·소제목 소실·발행 저장 원본 불일치를 최종 클릭 직전에 차단한다. setContent로 전체 재작성하지 않는다.
- 자동 경로는 기존 ‘못 받은 이미지 건너뛰기’를 허용하지 않으며 모든 원고 이미지를 받을 때만 진행한다.
- 실제 저장 요청 응답에서 확인한 URL만 따라가 게시 제목을 대조한다. 과거 관리 목록의 같은 제목을 새 발행 증거로 추측하지 않는다. 실제 응답 필드/선택자 검수는 티스토리 로그인 후 진행할 잔여다.
- 공용 OpenAI 사본에 이미 들어 있던 모델 성격/비용 안내를 이번 호출 화면에 연결한다(기준·사본 수정 없음). 무료 시험용 Playwright 1.47.0은 기존 SEO 검수와 동일한 버전으로 개발 의존성에만 추가, 실제 Edge·headless=false 모의 화면 시험을 사용한다.

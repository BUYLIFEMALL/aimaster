# 티스토리 최종 자동 발행·실제 URL 기록 플랜

## 문제와 범위

기존 작업기는 새 빈 탭·본인 블로그·TinyMCE/서식/태그·발행 설정 뒤 publish_ready로 끝나고 마지막 발행을 회원이 눌렀다. 주인님의 최신 자동 포스팅 완성 요청이 과거의 마지막 수동 발행 지침을 이 범위에서 대체한다. 입력 전용 조작은 보존한다. 보호글 비밀번호 금지·TinyMCE MAIN world/전체 setContent 금지·부분 입력 중단 규칙은 유지한다.

## 구현 순서

1. 기존 tistory_publish JSON에 자동 포스팅 선택/상태/실행·원고 지문·URL/시각을 기록한다. 본인 권한·토큰/소유자·원래 생성+30일·runId를 확인하고 조건부 갱신으로 선점/발행 직전 ACK/한 번의 최종 클릭/멱등 기록을 연결한다. 새 열/테이블/RLS/환경변수 변경 없음. 자동으로 보낸 원고의 수정/삭제/재전송을 잠그고, 임대 만료도 재발행 허가로 해석하지 않는다.
2. 기존 engine/adapter의 새 빈 탭·전체 본문 의미 구조/이미지/저장 원본 검사를 사용한다. 자동 경로는 이미지 누락을 건너뛰어 발행하지 않는다. 설정 확인 후 서버 arm→최종 버튼 1회→동일 블로그/제목의 실제 게시 결과 확인→URL/시각 기록. 결과 불확실은 최종 클릭/입력 재실행 없이 결과 확인/기록만 복구한다. 기존 큐/옛 확장의 입력 전용 호환을 유지한다.
3. 웹에 명시적 자동 포스팅 조작·실제 게시 상태/URL·결과 재확인을 표시한다. 기존 예약 입력 준비는 보존하며 이번 자동 포스팅은 즉시 공개/비공개 발행부터 구현·검수한다(예약 자동 최종 발행으로 오인시키지 않음). 매뉴얼은 기존 8대/Step1~4 카드 규격·복사·팁/주의/직링크를 따른다.
4. 원자적 경합/다른 회원·원고 변경/만료·ACK 유실/확장 재시작/중복/잘못된 URL·기존 입력 회귀→타입/빌드→실제 빈 티스토리 검수→한 묶음 배포/버전·ZIP/DB 메타데이터→Edge 지정 일반 회원 비공개 실제 최종 발행·실제 URL 기록·재확인·안내/516px→공동 인수인계/원장/커밋/푸시.

## 비용과 한계

유료 AI/이미지 0, 자체 합성 원고로 최소 실제 비공개 발행 1건을 목표로 한다. 비밀번호는 주인님이 직접 입력한다. 기존 네이버 준비 탭/글·다른 확장은 건드리지 않는다. 공용 확장 엔진 등록은 없으므로 SEO의 원고 지문/서버 ACK/복구 패턴을 참고하되 Tistory의 기존 TinyMCE 입력 코드를 유지한다. 이미지/AI 공용 사본은 직접 수정하지 않는다. 저장소에 있던 GPT 공용 사본은 이번 배포에 함께 반영되며 기존 등록부의 미배포 이력을 갱신한다.

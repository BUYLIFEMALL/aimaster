# 티스토리 자동화 운영·개발 인수인계 및 검수 체크포인트

기준일: 2026-10-03
현재 기준 버전: `v1.53`
운영 주소: `https://tistory-auto-blog-pearl.vercel.app`

이 문서는 다음 작업자가 티스토리 자동화의 **실제 장애 이력, 안전 원칙, 수정 금지 지점, 검수 순서**를 먼저 확인하도록 만든 운영 기준서다. 작업 시작 전에는 이 문서와 상위 `AGENTS.md`, `README.md`, 루트 `docs/ERROR_LESSONS.md`를 모두 읽는다.

## 1. 프로그램의 역할과 책임 경계

`tistory-auto-blog`는 회원의 AI 원문을 만들고, 크롬 확장이 사용자의 티스토리 글쓰기 화면에 제목·본문·이미지·태그·발행 설정을 입력하도록 돕는다.

- 티스토리가 공식 글쓰기 API를 제공하지 않으므로, 입력은 **회원의 브라우저와 로그인된 티스토리 탭 안에서만** 수행한다.
- 확장은 최종 `저장`·`발행` 버튼을 누르지 않는다. 이 마지막 행위는 반드시 회원이 직접 확인 후 수행한다.
- 다른 회원의 글, API 키, 연동 토큰을 조회하거나 재사용하지 않는다. AI는 회원 본인의 등록 키만 사용한다.
- 빈 새 글에서만 자동 입력한다. 제목·본문·이미지·태그가 이미 있는 초안은 덮어쓰지 않고 중단한다.

## 2. 먼저 볼 파일과 책임 분리

| 영역 | 우선 파일 | 역할 |
| --- | --- | --- |
| 버전·배포 자산 | `utils/version.ts`, `scripts/build-extension-archive.mjs` | 앱 버전, 확장 manifest/ZIP 자동 생성 |
| AI 원문 생성·정리 | `utils/news/generator.ts` | 프롬프트, 중복 제목·장식 따옴표 방지 |
| 중복 제목 방어 | `utils/duplicateTitle.ts` | 생성·수정·확장 전달 경로의 제목 중복 제거 |
| 서버 HTML → 입력 블록 | `utils/extensionContent.ts` | 제목/문단/목록/인용/표/링크/이미지 순서 보존 |
| 확장 진입·입력·검수 | `extension/sidepanel.js` | TinyMCE 입력, 이미지 업로드, 태그/발행 설정, 중단·재개 |
| 확장 글 목록 API | `app/api/extension/posts/route.ts` | 선택 글을 안전한 입력 블록으로 변환 |

`npm run build`는 확장 ZIP과 `extension/manifest.json`을 현재 `APP_VERSION`에 맞춰 생성한다. 소스만 고치고 ZIP을 갱신하지 않으면 회원이 이전 확장을 받으므로, 확장 변경 때는 반드시 빌드 산출물까지 함께 커밋한다.

## 3. 절대 지켜야 할 구현 원칙

1. **TinyMCE는 MAIN world에서 다룬다.** `chrome.scripting.executeScript()` 기본 격리 세계에서는 티스토리 페이지의 실제 `window.tinymce`를 읽을 수 없다. 본문 삽입은 `world: "MAIN"`의 TinyMCE `insertContent()`를 우선 사용하고, 입력 뒤 `save()`로 모델을 저장한다.
2. **발행 직전 `setContent()`로 전체 본문을 다시 쓰지 않는다.** 티스토리 고유 구조가 정리되면서 목록·인용·제목·스타일이 사라진 실제 회귀가 있었다. 삽입 후에는 동기화·검증만 한다.
3. **문자열 완전 일치만으로 실패 판정하지 않는다.** TinyMCE와 티스토리는 공백, `&nbsp;`, 엔티티, 태그를 정상적으로 재구성한다. 사람이 보는 텍스트와 의미 구조(`h2/h3`, `ul/ol`, `blockquote`, `table`, 링크 등)를 확인한다.
4. **본문의 `#태그`는 티스토리 등록 태그가 아니다.** 태그 입력 UI에서 태그 칩이 실제 생성된 것을 확인해야 성공이다. UI를 못 찾았다고 본문 해시태그로 대체해 성공 처리하지 않는다.
5. **부분 입력 초안은 발행하지 않는다.** 재개 버튼은 누락된 본문을 복구하는 기능이 아니라 안전 검사 후 발행 설정만 이어가는 기능이다. 블록 수가 맞지 않으면 새 빈 글에서 처음부터 입력한다.
6. **실제 화면을 측정하고 선택자를 넓힌다.** 티스토리 UI는 언제든 바뀐다. 추측으로 고정 선택자를 추가하지 말고 현재 DOM·접근성 트리·실제 생성 결과를 확인한다.

## 4. 핵심 장애 이력과 해결 방법

| 증상 | 실제 원인 | 현재 해결 | 다음 작업 시 확인 |
| --- | --- | --- | --- |
| 원문은 서식이 있는데 발행본이 평문 | 격리 세계에서 `window.tinymce`를 못 읽어 native 입력 대체 경로를 사용 | MAIN world `tinymce.insertContent()` + `save()` 사용 | iframe의 표시뿐 아니라 저장 원본과 `h2`, 목록, 인용, 링크가 남는지 확인 |
| 이미지와 본문을 감싼 컨테이너가 한 문단으로 변형 | HTML 변환기가 컨테이너 전체를 텍스트 하나로 평탄화 | `htmlToInputBlocks()`가 자식을 재귀 순회해 이미지와 의미 블록을 순서대로 분리 | 이미지 주변 제목·문단·목록의 순서가 유지되는지 확인 |
| 본문 제목이 두 번 보임 | AI가 본문 첫 줄에 제목을 재출력하거나 전달 경로가 제목 블록을 포함 | 프롬프트 금지 + `duplicateTitle.ts`의 생성/수정/확장 전달 3중 제거 | 티스토리 제목 칸 외 본문 첫 블록에 같은 제목이 없는지 확인 |
| 태그 1개 뒤 “등록 결과를 확인하지 못했습니다” | 실제 칩은 생성됐지만 이전 선택자 `.editor_tag > .txt_tag`가 새 링크 구조를 못 읽음 | `.txt_tag`, `.tag_link`, 태그 링크를 모두 읽고 `태그 수정/삭제` 꼬리말 제거, 최대 4.5초 대기 | `업무 태그 수정/삭제` 같은 실제 UI가 목록에 잡히는지 확인 |
| 29개 중 7개만 입력되고 재개도 차단 | v1.51의 문장부호 완전일치 검사가 정상 HTML 재구성을 변형으로 오판 | v1.52에서 해당 완전일치 검사 제거, 텍스트·의미 구조 검증으로 복구 | 오류 시 전체 미리보기 블록 수와 편집기 블록 수를 비교, 부분 초안을 발행하지 않기 |
| 게시 결과 문구 양끝에 불필요한 따옴표 | 확장이 덧붙인 것이 아니라 AI 원문 자체에 장식용 인용부호가 포함 | 프롬프트 금지 + 최종 `contentMarkdown`의 `removeDecorativeQuotes()` 정리 | 확장 전체 미리보기와 게시 결과를 먼저 대조해 원천을 판별; 영어 축약형/URL/Markdown은 보존돼야 함 |
| 발행 주제(홈 주제)를 찾지 못함 | 티스토리의 현재 선택지와 캐시된 목록이 달라짐 | 본문 입력 뒤 실제 선택지를 갱신하고, 신뢰된 클릭 후 선택 문구 확인 | 기본값이 없을 때 “목록 갱신” 후 현재 레이블만 사용 |

### 장식 따옴표 처리의 주의점

`v1.53`은 `utils/news/generator.ts`에서 최종 본문 Markdown을 HTML로 바꾸기 직전에 장식용 짝따옴표를 제거한다. 이는 본문 문제를 해결한 것이다. 제목 자체에 따옴표가 들어가는 사례까지 일괄 제거하지는 않는다. 다음에 이 범위를 넓힐 때는 책 제목·직접 인용·영어 축약형·URL·Markdown 링크가 훼손되지 않는 실제 표본을 먼저 추가 검수한다.

## 5. 안전한 입력·재개 절차

### 정상 입력

1. 티스토리에서 **새 빈 글**을 연다.
2. 확장에서 글을 선택하고 전체 미리보기의 제목·본문·이미지·태그를 확인한다.
3. `티스토리 편집기로 입력`을 실행한다.
4. 제목, 본문 의미 구조, 이미지 순서, 등록 태그 칩, 카테고리·공개·홈 주제를 확인한다.
5. 회원이 티스토리 화면에서 최종 저장 또는 발행한다.

### 중단됐을 때

- 오류 문구와 `확인 N/M개 문단` 수를 먼저 기록한다.
- 편집기 본문과 확장 전체 미리보기의 블록 수를 비교한다.
- `N/M`이 부족하거나 원문 저장 검증 실패면 **발행하지 않는다.** 그 초안을 보존하거나 닫고, 확장을 새 버전으로 다시 불러온 뒤 새 빈 글에서 재시도한다.
- `입력 중단 후 설정 이어서 적용`은 본문이 완전하고 입력 후 단계만 중단됐다는 검증을 통과한 경우에만 쓴다. 부분 본문을 살리는 용도로 바꾸지 않는다.

## 7. 빠른 진단 순서

1. **생성 원문 문제인가?** 확장 전체 미리보기와 게시 결과를 대조한다. 둘 다 같으면 AI 생성/정리 단계 문제다.
2. **입력 경로 문제인가?** 원문은 정상인데 편집기에서만 달라지면 MAIN world/TinyMCE/save 동기화와 입력 블록을 본다.
3. **티스토리 UI 변화인가?** 태그·카테고리·홈 주제만 실패하면 현재 화면의 실제 요소와 레이블을 읽고 선택자·대기 조건을 보완한다.
4. **부분 입력 안전장치가 동작한 것인가?** 블록 수 부족 오류는 우회하지 않는다. 원인을 고친 뒤 새 빈 글에서 재검수한다.

## 8. 운영 보안·비용 규칙

- 토큰, 쿠키, API 키, 로그인 정보는 로그·스크린샷·문서·커밋에 남기지 않는다.
- API 키가 없는 회원에게 운영자 키로 폴백하지 않는다.
- 실사용 AI 생성 또는 대량 호출은 비용이 발생할 수 있으므로, 검수는 가능한 기존 글/최소 표본으로 하며 대량 호출은 사전 승인을 받는다.
- 브라우저 자동화는 티스토리 약관과 사용자 계정 범위 안에서만 사용하고, 탐지 회피나 최종 발행 자동화로 범위를 넓히지 않는다.

## 9. 현재 기준 상태

- `v1.53` 확장 다운로드 파일은 운영 주소에서 HTTP 200으로 확인했다.
- 직전 핵심 회귀(서식 평문화, 제목 중복, 태그 확인 오탐, 부분 본문 중단, 장식 따옴표)는 위 원칙과 코드 경로로 수정됐다.
- 다음 변경은 반드시 실제 빈 티스토리 글에서 최소 1회 입력 검수한 후 배포한다. 특히 TinyMCE 저장 방식과 본문 검증 로직을 건드릴 때는 전체 문단 수와 의미 구조를 우선 확인한다.

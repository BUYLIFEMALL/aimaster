## 구현 내용과 경계

기존 `tistory_publish.automation` JSON으로 queued → publishing → published/uncertain/failed와 URL/시각을 기록합니다. 본인 권한·원래 생성일 30일·현재 실행 번호·원고 지문·상태 조건부 갱신을 확인합니다. 기존 입력 준비/예약 준비는 유지하며, 명시적 자동 포스팅은 현재 공개/비공개만 지원합니다. 보호글/비밀번호 자동 입력은 지원하지 않습니다.

서버 ACK 전에는 최종 버튼을 누르지 않고, 최종 시도 뒤에는 자동 재클릭하지 않습니다. 결과 불확실/확장 재시작은 결과 확인과 기록만 수행합니다. 본인 블로그 저장 응답의 게시 번호를 관찰하고 제목을 대조합니다. 커스텀 도메인은 추가 호스트 권한 없이 본인 티스토리 관리 주소를 읽어 확인하는 방식입니다. 실제 응답 형태/최종 선택자는 아직 실검수가 필요합니다.

원고는 자동 실행 뒤 수정/삭제/재전송을 잠그고 새 원고 복제로 복구합니다. 복제해도 원래 생성일을 유지합니다. 구버전 확장은 자동 포스팅 작업을 선점하지 못합니다. 이미지가 하나라도 누락되면 자동 경로는 편집기 입력 전에 중단합니다. 전체 setContent 재작성은 하지 않습니다.

주요 파일: `utils/autoPublication.ts`, `app/api/extension/posts/[id]/auto-publish/route.ts`, `app/api/posts/[id]/extension-handoff/route.ts`, `app/api/extension/task/route.ts`, 기존 input-result/posts API, 새 duplicate API, `extension/tistory-publication.js`와 background/adapter/engine, `components/AutoPublishPanel.tsx`/`AutoPublishGuide.tsx`, 게시글/설정/안내 화면. 공용 OpenAI 사본은 직접 수정하지 않았고 기존 미배포 사본을 쓰는 호출부 모델 안내를 연결했습니다. 실제 배포 후 공용 등록부의 미배포 상태를 갱신해야 합니다.

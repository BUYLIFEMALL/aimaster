작성: 윈도우 `claude-win-blog` [역할: blog] · 주인님 지시(2026-11-10 채팅): 「테스트는 맥미니쪽에서 하니까 디버깅, 테스트 작업은 따로 맥미니에게 요청해」
대상: 운영 https://tistory-auto-blog.buylife.xyz (현재 운영 v1.95, 코드 v1.96 배포 대기)
브라우저: 맥미니 ego lite 실제 창(포그라운드). 프로그램은 시험 계정 `buylifemall@naver.com`으로 주인님이 직접 로그인.

## 역할 나눔
- **맥미니**: 실물 재현·디버깅(원인 찾기·코드 수정 가능)·테스트·결과 기록.
- **윈도우 블로그 세션**: 빌드·배포·운영 DB만. 맥미니가 코드를 고치면 커밋 해시를 알려 주면 다음 배포에 싣는다.
- 맥미니가 이 폴더 코드를 고치는 동안 윈도우는 `tistory-auto-blog/`를 수정하지 않는다. 시작할 때 `docs/ACTIVE_WORK.md`에 맥미니 줄을 넣어 주세요.

## 1. 지금 할 일 — 이미지 배치·비율 약점 재현과 원인 찾기 (운영 v1.95)
기록은 블로그 기능 비교표(`docs/BLOG_FEATURE_MATRIX.md` §1)에 「이미지 배치·비율 약함」 한 줄뿐이고 재현 기록이 없다. 그래서 무엇이 약한지부터 확인한다.

1. 이미지가 이미 들어 있는 기존 원고 1건을 고른다(**새 원고 생성·새 이미지 생성은 회원 키 비용이 들어 주인님 승인 뒤**).
2. 포스팅 방식은 **「발행 전까지」(입력만)**. 실제 발행·예약은 하지 않는다.
3. 티스토리 편집기에 들어간 결과를 프로그램 미리보기와 나란히 캡처해 비교한다.
   - 이미지가 들어간 위치(소제목·문단 기준)가 프로그램과 같은가
   - 이미지 크기·가로세로 비율이 바뀌거나 잘리는가(편집기 안·미리보기·모바일 폭)
   - 대표 이미지가 맞게 지정되는가, 빠지거나 두 번 들어간 이미지가 있는가
4. 원인을 찾으면 관련 위치를 적는다. 후보: `extension/tistory-adapter.js`(이미지 붙여넣기, 820줄 근처 `canvas` 변환), `extension/tistory-engine.js`.
5. 고칠 수 있으면 고치고 시험(`npm test`, 현재 46개)을 통과시킨 뒤 내 파일만 커밋(`node scripts/commit-paths.mjs … --as <세션>`). **빌드·배포는 하지 않는다.**

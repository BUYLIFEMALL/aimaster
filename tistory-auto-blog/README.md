# 티스토리(원문)생성 자동화 — `tistory-auto-blog`

AIMaster 회원이 AI로 글을 만들고, **크롬 확장**이 티스토리 글쓰기 화면에 사람처럼 입력해 주는 프로그램입니다(티스토리 Open API는 2024-02 종료).
최종 발행은 항상 회원이 직접 누릅니다. 상태·계획·이어가기 절차는 [`AGENTS.md`](AGENTS.md)와 [`docs/TISTORY_PLAN.md`](docs/TISTORY_PLAN.md)를 보세요.

- 출발점: `ai-auto-blog`(https://ai-auto-blog-one.vercel.app)를 복제 — 글 생성·이미지·30일 자동 삭제·API 키·권한 로직은 같고, 입력 대상(티스토리)과 데이터 격리(전부 회원별 + 본인만)가 다릅니다.
- 개발 서버: `npm run dev`, 빌드: `npm run build`(prebuild가 확장 ZIP을 만듭니다 — 확장 완성 전에는 ZIP을 커밋·배포하지 않습니다).
- DB: 공용 Supabase에 `tistory_*` 테이블(`supabase/migrations/0001_tistory_init.sql`, 적용은 로컬에서 주인님 승인 후).
- 환경변수: 루트 `.env.local`의 공용 DB 값(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_MAIN_SITE_URL`, `CRON_SECRET`). AI 키는 넣지 않습니다(회원 본인 키만).
- 운영 주소: https://tistory-auto-blog-pearl.vercel.app (`v1.46`). 설정에서 발급한 연동 토큰은 확장에서 서버 검증 후에만 저장됩니다. 카테고리·태그 전용 저장과 태그 추출, 별도 발행 설정 저장(보호 비밀번호 제외)을 지원합니다. 홈주제는 빈 새 글에서도 확장 기본 목록에서 바로 고르고, 제목·본문 입력 뒤 `목록 갱신`을 누르면 현재 티스토리의 실제 선택지로 갱신·캐시합니다. 기본값이 실제 목록에 없으면 발행 설정 적용 전에 갱신을 안내합니다. 홈주제 선택은 실제 포인터 클릭과 선택 문구 확인으로 적용합니다. 새 본문 생성 시 요약 내용은 유지하되 `요약:` 라벨은 출력하지 않습니다. 수정 화면은 기존 본문 HTML의 레이아웃·서식 속성도 보존합니다. 확장은 제목 단계·굵게·목록·인용·표·링크의 의미 HTML과 텍스트 정렬을 보존해 티스토리 편집기에 넣고, 이미지는 티스토리에 별도 업로드합니다. 재개 시 남은 발행 모달을 먼저 닫고, 태그 입력칸이 화면에 없으면 태그만 건너뛴 뒤 나머지 설정을 적용합니다. 웹 앱 전용 클래스·스타일은 티스토리에서 사용할 수 없으므로 전송하지 않습니다. 최종 저장·발행은 절대 누르지 않습니다. 공용 DB의 `programs.version`과 확장 `version_name`·배포 ZIP도 같은 버전으로 맞춥니다.
# v1.48 — 원문 태그를 티스토리 등록 태그로 검증

글 선택 시 원문의 태그를 자동으로 불러오고, 티스토리 태그 칩이 실제로 생성된 경우에만 완료 처리합니다. 본문 `#태그` 문구로 대체해 등록 성공처럼 처리하지 않으며, 태그 UI를 찾을 수 없으면 명확히 중단합니다.

# v1.47 — TinyMCE 실제 모델에 서식 블록 기록

확장 격리 세계에서 호출하던 TinyMCE API는 페이지의 실제 편집기 인스턴스가 아니어서 native HTML 삽입 대체 경로로 떨어질 수 있었습니다. 본문 삽입·저장은 페이지 메인 세계의 `insertContent()`·`save()`로 실행하며, 제목·목록·인용·표·링크 구조가 편집기에 실제 남는지 확인합니다. 텍스트만 남으면 평문화된 글을 저장하지 않고 입력을 중단합니다.

# v1.46 — 이미지 포함 컨테이너 본문 서식 보존

이미지와 문단을 함께 감싼 원문 컨테이너를 평문 하나로 만들지 않고 재귀 순회합니다. 이미지·소제목·문단·목록을 원래 순서와 의미 HTML로 티스토리에 전달합니다.

# v1.45 — 컨테이너 정렬 상속 차단

원문 편집기의 레이아웃 컨테이너에 붙은 `text-align`이 자식 문단 전체에 상속되지 않도록 전송 단계에서 제거합니다. 실제 문단·제목·목록·인용·표 셀의 명시 정렬과 v1.44의 글자·인용·목록 서식 보존은 유지합니다.

# v1.44 — 원본 텍스트 서식 변환 보존

원본 HTML의 Tailwind 클래스와 inline CSS를 정리 단계에서 삭제해 서식이 사라지던 근본 원인을 수정했습니다. 티스토리가 이해할 수 있는 안전한 인라인 CSS로 글자 크기·굵기·줄간격·색상·인용선·목록·테두리 서식을 변환해 유지합니다.

# v1.43 — 원본 서식 보존 입력 경로 복구

발행 직전에 본문 전체를 `setContent()`로 다시 쓰던 방식이 티스토리 고유 서식을 정리해 원본 서식이 깨질 수 있었습니다. 이제 서식 블록은 입력 시 TinyMCE `insertContent()`로 내부 모델에 바로 기록하고, 발행 직전에는 내용을 다시 쓰지 않고 저장만 합니다.

# v1.42 — 발행 원본 텍스트 검증 정확도 보완

`37/45개 문단` 반복 오류는 숨김 본문 원본의 HTML 엔티티를 문자 그대로 비교해, 실제로 저장된 텍스트 일부를 누락으로 오판한 문제였습니다. 이제 HTML을 브라우저가 해석한 실제 텍스트로 변환해 검증하므로 `&nbsp;`·`&amp;` 같은 표기 차이로 중단되지 않습니다. TinyMCE 내부 모델 동기화는 유지됩니다.

# v1.41 — TinyMCE 내부 본문 모델 확정

v1.40에서 확인된 `37/45개 문단` 불일치는 iframe 화면과 숨김 원본만 동기화해서는 TinyMCE 내부 콘텐츠 모델이 갱신되지 않을 수 있기 때문입니다. 발행 전 전체 본문 HTML을 TinyMCE `setContent()`로 확정하고 저장하도록 보강했습니다.

# v1.40 — 발행용 본문 저장 원본 동기화

편집기 화면에는 보이지만 최종 발행본에서 텍스트가 사라지는 문제를 수정했습니다. HTML 삽입 후 TinyMCE가 발행에 사용하는 숨김 본문 원본을 명시적으로 저장·동기화하고, 그 원본에 모든 문단이 있는지 확인한 뒤에만 발행 설정 단계로 넘어갑니다.

# v1.39 — 본문 제목 중복 제거

AI가 본문에 글 제목과 완전히 같은 독립 문단 또는 소제목을 반환하면, 티스토리 제목 입력칸과 본문에 제목이 두 번 보일 수 있었습니다. 새 글 생성 단계에서 해당 줄을 제거하고, 이미 생성된 글도 확장 전송 시 같은 제목 블록을 제외하는 이중 방어를 적용했습니다.

# v1.38 — 본문 텍스트 연속 입력 보존

서식 HTML 블록을 연속 입력할 때 TinyMCE의 비동기 DOM 재구성으로 이전 선택 위치가 남아 다음 문단이 앞 문단을 덮어쓸 수 있던 문제를 수정했습니다. 각 블록은 본문 끝에 삽입한 뒤 실제 텍스트 잔존을 확인하며, 티스토리가 특정 서식을 제거한 경우에만 텍스트 입력으로 복구합니다. 정상적으로 유지되는 블록의 원래 서식은 그대로 보존합니다.

# v1.34 — 본문 끝 해시태그 입력 복구

티스토리 화면에 전용 태그 입력칸이 없을 때는 태그를 생략하지 않고, 본문 끝에 왼쪽 정렬 `#태그` 줄을 입력하고 확인합니다. 기존 본문 또는 전용 태그에 이미 있는 값은 중복으로 넣지 않습니다.
# v1.35 — 홈주제 적용 시 공개 범위 확인

홈주제를 선택하는 빠른 경로도 공개 범위를 명시적으로 선택·검증하므로, 티스토리가 직전 글의 비공개 상태를 유지하지 않습니다.
# v1.36 — 발행창 공개 라디오 구조 보강

티스토리 발행창의 공개 라디오 라벨 구조가 달라도, 실측 `#open20`과 화면상 클릭 대상 후보를 사용해 공개 범위를 선택·검증합니다.
# v1.37 — 발행창 공개 라디오 클릭 경로 보강

공개 범위 라디오는 티스토리의 일반 클릭 경로를 우선 사용하고, 반영되지 않을 때만 실제 포인터 클릭으로 재시도합니다.

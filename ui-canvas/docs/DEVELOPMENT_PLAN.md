## 1. 원본 앱 분석 요약

### 1-1. 기술/구조
- React 19 + Vite + TS, Tailwind(CDN), html2canvas(이미지 저장), @google/genai.
- 단일 화면 에디터: 상단 툴바 / 좌측(컴포넌트·레이어 탭) / 중앙 캔버스(20px 그리드) / 우측(속성·명세 탭).
- 상태는 전부 브라우저 메모리(저장소 없음). 새로고침하면 사라지고, JSON 내보내기·불러오기로만 보존.
- **운영자 키가 클라이언트 번들에 박히는 구조**(`process.env.API_KEY`) → AIMaster 최상위 규칙 위반, 그대로 가져오지 않는다.

### 1-2. 데이터 모델
`CanvasComponent {id, name, type, position{x,y}, size{width,height}, props{}, styles{}, description, parentId?, isLocked?}`
- 타입 25종: 컨테이너·텍스트·버튼·입력·목록상자·이미지·탭·아코디언·드롭다운·라디오·체크박스·토글·슬라이더·알림·로더·진행률·툴팁·모달·팝오버·아이콘·막대/선/파이 차트·기타 + 그룹(그룹화로만 생성).
- 레이어 순서 = 배열 순서(뒤에 있을수록 위). 그룹은 `parentId`로 자식을 가리키고, 자식 좌표는 그룹 기준 상대좌표.

### 1-3. 동작/옵션 (코드 기준)
| 영역 | 동작 |
|---|---|
| 생성 | 도구 선택 후 캔버스에서 드래그(5px 초과) → 그 크기로 생성. 차트는 4~7개 랜덤 데이터 자동 생성 |
| 선택 | 클릭, Shift 다중 선택, 빈 곳 드래그 마퀴(잠금·자식 제외) |
| 이동/크기 | 드래그 이동, 우하단 핸들 크기(최소 10px), 방향키 1px/Shift 10px |
| 편집 | 텍스트 더블클릭 인라인 편집, 아코디언 클릭 펼침 |
| 속성 | 이름·설명·고유 속성(타입별)·크기·위치(읽기전용)·텍스트(색·크기·굵기·정렬)·채우기·테두리 |
| 프리셋 | 스타일 프리셋(버튼 8·컨테이너 4·알림 4·텍스트 4 등) + 버튼 용도 프리셋(재생/일시정지/다음/이전/닫기) |
| 레이어 | 목록·맨앞/앞/뒤/맨뒤·삭제·그룹 트리(펼침/접힘) |
| 그룹 | Ctrl+G / Ctrl+Shift+G, 컨테이너 잠금(잠기면 선택·드래그 안 됨, 도구 사용 시 클릭 통과) |
| 편집 단축키 | Ctrl+Z / Ctrl+Shift+Z, Delete, Ctrl+D 복제(+20px, 그룹은 자식까지) |
| 컨텍스트 메뉴 | 레이어 순서·그룹/해제·잠금·복제·삭제 |
| 내보내기 | PNG(html2canvas), 컴포넌트 JSON, 디자인 명세 JSON(앱 이름/설명 필수) |
| 불러오기 | JSON 여러 개 동시, 배열/`{components}`/명세 형식 모두 인식, 형식 검증 |
| AI ① | "AI로 내용 채우기": 컴포넌트 요약 → 앱 이름·설명·화면 설명 JSON (gemini-2.5-flash, 구조화 응답) |
| AI ② | "이미지에서 불러오기": 스크린샷 → 컨테이너 중심 구조 + 이름/설명/props + 명세를 한 번에 생성해 캔버스 교체 |

### 1-4. 원본의 결함/한계 (우리 버전에서 고칠 점)
1. 운영자 키가 클라이언트에 노출 → 서버 경유 + 회원 본인 키.
2. 저장소가 없음 → 프로젝트 저장/목록/이어서 편집.
3. 위치(X/Y) 입력이 읽기전용, 정렬·스냅·눈금자·줌/팬 없음, 캔버스 크기 고정(뷰포트).
4. 이미지 컴포넌트가 URL을 실제로 렌더링하지 않고 아이콘 자리표시자만 표시.
5. `alert()` 남용, 다크 테마 고정, 이미지 AI 호출 시 이미지 용량·형식 검증 없음, 오류 메시지 빈약.
6. 그룹 안 자식 개별 편집 불가(항상 최상위 선택), 다중 선택 일괄 속성 편집 없음.
7. AI 응답의 좌표/크기 보정이 없어 화면 밖으로 나가는 요소 발생 가능.

### 1-5. 실행 결과 확인 상태
- AI Studio 미리보기 탭은 본 세션에서 렌더러가 응답하지 않아(스크린샷 타임아웃 2회) **라이브 실행 캡처는 못 했습니다.** 대신 소스 전체를 정독해 동작을 코드로 확정했습니다. 구현 후 우리 앱을 실제 Chrome으로 열어 원본 흐름과 1:1 대조 검수합니다.

## 2. 제품 정의 (안)
- 이름: **UI Canvas 자동화** / slug `ui-canvas` / 폴더 `AIMaster/ui-canvas/`
- 한 줄: 드래그로 UI 화면을 설계하고, 스크린샷에서 AI가 화면 구조를 자동 복원하며, 개발 핸드오프용 명세(JSON·PNG)로 내보내는 웹 디자인 캔버스.
- 대상: 기획자·디자이너·1인 개발자. 카테고리: AI 개발/디자인 계열(기존 `react-ui-showcase`와 같은 묶음 후보).
- 최상위 규칙 적용: AI는 **회원 본인 Gemini 키**(`user_api_keys`, provider `gemini`)만 사용, 없으면 키 등록 안내 모달. 폴백 없음.

## 3. 범위 (v1.01)

### 필수 (원본 동등)
- 25종 컴포넌트·프리셋·속성 패널·레이어·그룹·잠금·컨텍스트 메뉴·단축키·Undo/Redo

### 개선 (원본 결함 대응, 최소 범위)
- 프로젝트 저장/불러오기(회원별 DB, 자동 저장, 목록·이름 변경·삭제)
- 흰색 베이스 UI + 한국어 + 표준 사이드바(번호형 흐름, API키등록·플랫폼연동, 계정·로그아웃)
- X/Y 직접 입력, 이미지 URL 실제 표시, `alert` 대신 토스트, 오류 안내 개선
- AI 결과 좌표 클램프(캔버스 안으로 보정), 이미지 업로드 크기·형식 제한(예: 4MB, png/jpg/webp)
- 캔버스 크기 프리셋(데스크톱 1440×900 / 태블릿 / 모바일 390×844)

### 제외 (후속 버전 후보)
줌/팬·스냅·정렬 가이드, 다중 선택 일괄 속성, 그룹 내부 개별 편집, 공유 링크, 협업, HTML/React 코드 내보내기.

## 4. 아키텍처
- Next.js 16 App Router + TS + Tailwind (기존 `markdown-studio` 구조·`src/lib/access.ts`·`programAccess.ts` 패턴 재사용).
- 에디터는 클라이언트 컴포넌트(상태: reducer + history), 순수 로직은 `src/lib/canvas/`로 분리해 단위 테스트(생성·그룹/해제·복제·레이어 이동·JSON 검증·좌표 클램프).
- 서버 API(전부 `checkProgramAccessApi` + `dynamic="force-dynamic"`/`fetchCache="force-no-store"`):
  - `POST /api/ai/spec` — 컴포넌트 요약 → 명세 3종
  - `POST /api/ai/from-image` — 이미지 → 명세+컴포넌트
  - `GET/POST/PATCH/DELETE /api/projects` — 프로젝트 CRUD(소유자 확인)
- 키 해석: 서버에서 `resolveApiKey(user, 'gemini')`, null이면 `needKey` 응답 → 클라이언트 키 등록 모달.
- 모델: `gemini-2.5-flash`(원본과 동일, 구조화 JSON 응답). 호출 한도·타임아웃·입력 크기 제한 적용.
- 이미지 저장: PNG는 클라이언트에서 html2canvas(npm 번들, CDN 미사용)로 생성해 바로 다운로드 — 서버 저장 없음.
- 프롬프트: 당해 연도 주입(규칙 8), 한국어 출력.

## 5. DB (공용 Supabase, `ui-canvas/supabase/migrations/`)
`ui_canvas_projects`
- `id uuid pk`, `user_id uuid not null`, `name text`, `canvas_size jsonb`, `components jsonb`, `app_name/app_description/screen_description text`, `created_at`, `updated_at`
- RLS: owner-only(`auth.uid() = user_id`), 서버는 service role 사용 시 항상 `user_id` 필터.
- 자동 저장은 디바운스 + 버전 충돌 방지(updated_at 비교).
- `programs` 등록: `slug='ui-canvas'`, `app_url=https://ui-canvas.buylife.xyz`, `version='v1.01'`, 기본 3요금제(1/2/3개월 10,000/20,000/30,000), 썸네일, FREE 뱃지 여부는 주인님 결정.
- 프리미엄 후보 여부: 운영자 실비 없음(AI는 회원 키, 저장은 소량 JSON) → 해당 없음으로 기록.

## 7. 리스크/결정 필요
1. **FREE 뱃지 여부**: 가입자 누구나 쓰게 할지(유입용) vs 일반 이상+기간 부여(기본). → 기본안: 기본 3요금제, FREE 아님.
2. **프로젝트 저장**: DB 저장(권장) vs 파일 JSON만(원본 방식). → 권장: DB 저장 + JSON 내보내기 병행.
3. **AI 호출 비용 구조**: 회원 본인 Gemini 키(규칙상 확정). 키 발급 매뉴얼(`platform_guides`)은 기존 Gemini 게시글 재사용.
4. 원본의 개발자 크레딧·유튜브 링크는 복제하지 않음(저작/브랜딩).
5. 이미지→UI 결과 품질은 모델 의존. 좌표 보정과 "결과를 캔버스 교체 전 확인" 단계를 넣어 기존 작업이 날아가지 않게 함(원본은 즉시 덮어씀).
6. 모바일 화면 대응: 에디터 특성상 데스크톱 우선, 모바일은 읽기/내보내기 중심으로 제한.

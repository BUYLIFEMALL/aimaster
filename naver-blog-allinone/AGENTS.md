# naver-blog-allinone — AI 에이전트 작업 지침

## 프로그램 개요
- **프로그램명**: 네이버 블로그 올인원 자동화
- **Slug**: `naver-blog-allinone`
- **버전**: `v1.13`
- **목적**: E-E-A-T 기반 기획, 멀티모달 비전 사진 분석, 실시간 뉴스/키워드 분석, 스마트에디터 ONE 포스팅을 하나로 통합한 네이버 블로그 올인원 솔루션

## 핵심 불변 원칙 준수
1. **사용자 본인 API 키 원칙**: Google Gemini API 키는 사용자 본인의 브라우저 `localStorage`에만 보관하며 서버로 전송하지 않는다.
2. **연도 불변 원칙**: 모든 AI 프롬프트와 기사 생성은 항상 당해 연도(현재 2026년)를 기준으로 작성한다 (`new Date().getFullYear()`).
3. **UI 표준**: 흰색 베이스(Clean White & Slate), 중성 회색 테두리, 카드형 모듈러 레이아웃 준수.

주인님 요청("글은 잘 생성되는데 이미지 생성·편집이 부실하다. naver-blog-agent의 생성 기능을 믹스하고, 생성 콘텐츠를 저장·보관하는 기능도 만들어라")으로 Claude Code가 작업. 두 프로그램의 본문·이미지 로직을 비교 분석해 서로의 장점을 합쳤다(naver-blog-agent 폴더는 Codex 담당이라 읽기만 하고 수정하지 않았다).

### 분석 요약 (v1.15 이전 → 문제)
- 올인원: Gemini 1회 호출로 HTML·마크다운·텍스트를 한꺼번에 받음. **이미지는 `image.pollinations.ai` 주소만 붙이는 가짜(실제 생성·저장 아님)**, "본문 서브 이미지"·"썸네일 글자" 옵션은 화면만 있고 동작하지 않았음, 이미지 편집(재생성·교체·삭제) 없음, 저장 기능 없음(새로고침하면 사라짐).
- naver-blog-agent: 서버 파이프라인(Research→Writer→Humanizer→Reviewer), 말끝 4×문체 7, 목표 글자수·코드 측정, 연도 정책, 컷별 이미지 생성(NanoBanana/GPT Image/FLUX/Z-Image)·재생성·삭제·저장, 원고 서버 보관(30일 자동 삭제).

### 가져온 것(agent → 올인원)
- 4단계 파이프라인(`src/lib/blog/pipeline.ts`): 기획(제목·소제목·**장면별 영어 이미지 프롬프트**) → 본문 → 윤문(문단 단위, 숫자·URL이 바뀌면 그 문단 수정은 버림, `humanizer.ts`) → 검수(글자수는 코드로 측정, PASS/WARN/FAIL, 태그·요약). 단계 기록을 결과 화면에 표시.
- 말끝(해요체·합니다체·친근한 반말·한다체)·문체 7종(`styles.ts`), 목표 글자수 1,000~4,000, 연도 정책(`yearPolicy.ts`, 핵심 원칙 8번), 이미지 규칙(인물은 기본 한국인·이미지 속 글자 금지, 핵심 원칙 3번 — `imagePlan.ts`).
### 올인원이 유지·강화한 것
- 원고는 태그가 붙은 텍스트로 저장하고(`[SECTION - …]`·`[IMAGE INSERT - 컷 이름]`·`- 목록`·`> 인용`·`**강조**`) 네이버 스마트에디터용 인라인 스타일 HTML(컬러 테마 7종)·마크다운·일반 텍스트를 `article.ts`에서 매번 같은 규칙으로 만든다. 이미지는 컷 이름으로 본문 자리와 연결.
- 크롬 확장 전달(`ALLINONE_SYNC_DRAFT`)은 같은 메시지 형식 그대로(생성 완료·이미지 변경 때 자동 전달).
### 새 이미지 기능
- 실제 나노바나나 생성(설정의 Nano Banana 2·2K / Lite·1K, 브라우저에서 회원 본인 Gemini 키로 직접 호출), 비율 16:9·1:1·4:5·9:16, 대표+본문 0~4장(최대 5컷, 수동 추가 시 6컷), 글 완성 후 자동 생성 옵션.
- 컷별 **다시 생성·프롬프트 수정·내 이미지로 교체(업로드)·컷 이름 변경·삭제·크게 보기·원본 열기**, 컷 추가. 컷 삭제·이름 변경은 본문 이미지 자리도 같이 바뀜.
- **썸네일 제목 글자 합성**(`canvas.ts`, 브라우저 캔버스로 하단 어두운 띠+제목) — 기존 "썸네일용 텍스트" 옵션이 처음으로 실제 동작.
- 생성 이미지는 브라우저에서 WebP로 줄여(긴 변 1600px) 서버로 올리고(`/api/posts/images`) 공개 버킷 `allinone-images/<user_id>/<uuid>.webp`에 저장한다. sharp는 쓰지 않는다(운영 libvips 문제 회피).
### 내 보관함(저장·보관)
- 테이블 `aio_posts`(RLS owner-only 4개, 회원당 100개) + 버킷 `allinone-images`(공개 읽기·서버만 쓰기, 5MB). 마이그레이션 `supabase/migrations/20261012100000_allinone_posts_and_bucket.sql`.
- API: `GET/POST /api/posts`, `GET/PUT/DELETE /api/posts/[id]`, `POST /api/posts/images` — 모두 `checkProgramAccess` 사본(`src/lib/programAccess.ts`, 서비스 키로 권한 조회)으로 로그인·이용 권한 확인, 서버가 입력을 다시 정리(`sanitize.ts`: 이미지 주소는 본인 폴더만, 길이·개수 제한, 허용 목록). 수정 시 더는 안 쓰는 이미지 파일 삭제, 글 삭제 시 이미지 파일도 삭제.
- 생성 완료 즉시 자동 저장, 이후 편집·이미지 변경은 1.5초 뒤 자동 저장(저장 상태 표시, 실패 시 다시 시도). 사이드바 [내 보관함]에서 목록(썸네일·검수 상태·글자수)·열기·삭제(화면 안 확인 버튼). 열면 모든 옵션·이미지·편집이 그대로 복원.
- 에이전트의 "30일 자동 삭제"는 가져오지 않았다(보관함이므로 직접 삭제할 때까지 보관, 100개 한도).
- 글 작성 영역을 `page.tsx`에서 한 곳으로 합쳐 탭을 바꿔도 작업 중인 글·이미지가 유지된다.

주인님 요청("각 탭이 수집한 내용을 바탕으로 페르소나를 선택하고 원하는 글자수·세부 조정·말끝·문체를 설정해 최종 본문이 생성되게 하라", "AI 글·이미지 모델도 선택", "기존 로직에 부딪히지 않게 확장", "보관함을 4번으로 올려라")로 Claude Code가 작업.

### naver-blog-agent 분석 → 가져온 장점(읽기만, 폴더 수정 없음)
- 생성 설정 화면: 화자(페르소나) 6종(관점·관심사를 정하고 주제·키워드·발행 목적·말끝 기본값을 채움, [페르소나 불러오기]/[즉시 생성]), 글자수 슬라이더(+빠른 선택·직접 입력), 기획 세부 조건(주제·발행 목적·검색 키워드), 말끝 4×문체 8 선택과 **표현 예시**(`getWritingStyleExample`).
- 모델 선택: 글 엔진 GPT/Claude/Gemini + 세부 모델, 이미지 플랫폼 NanoBanana/GPT Image/FLUX/Z-Image + 세부 모델. **선택한 공급사의 본인 키만 쓰고 없으면 다른 공급사로 자동 전환하지 않는다**(에이전트 원칙). 공급사 오류를 짧은 한국어로 바꾸는 방식(`describeHttpError`).
- 사람 시선: 에이전트는 서버(SDK·`user_api_keys`·`nba_generation_preferences`)에서 처리하지만, 올인원은 키를 이 브라우저에만 두는 기존 구조라 **같은 UX를 브라우저 기준으로 옮겼다**(서버 저장 구조는 가져오지 않음).

### 기존 로직과 부딪히지 않게 한 방식(모두 "덧붙임")
- `AppSettings` 새 필드는 전부 선택값(`openaiApiKey`/`anthropicApiKey`/`replicateApiKey`/`textProvider`/`textModelId`/`imageModelId`). **없으면 기존 Gemini(`textModel`)·나노바나나(`imageModel`) 설정 그대로 동작**한다(`models.ts`의 `resolveTextEngine`/`resolveImageEngine`). 설정창은 저장할 때 `getStoredSettings()`를 펼쳐 새 필드를 지우지 않는다.
- 주제 추천·키워드 분석·장소 키워드 추출 등 **기존 Gemini 직접 호출 코드는 수정하지 않았다**(선택한 글 엔진은 새 4단계 본문 생성에만 적용). 이 탭들은 계속 Gemini 키가 필요하다.
- 설정창에 [추가 AI 키(선택)] 섹션(OpenAI·Claude·Replicate) 추가. FLUX/Z-Image(Replicate)는 브라우저 호출(CORS)이 막혀 `/api/replicate-image`가 중계(키는 요청 헤더로만 받고 저장·기록하지 않음, 로그인·이용 권한 확인, 모델 허용 목록, 응답 3.3MB 제한).

### 세 탭 연결
- 공통 파이프라인에 수집 내용을 모두 전달: 주제·기획 배경(주제 추천·키워드 탭이 넘긴 hint는 발행 목적 칸에 채움)·키워드·발행 목적·**페르소나**·말끝·문체·목표 글자수(300~4,000)·추가 요청.
- **맛집/카페/여행 탭**은 기존 폼(사진·방문 정보·SEO 모드·FAQ)을 유지하고 생성만 새 파이프라인으로 교체: 사진을 기획·작성 단계에 함께 전달(비전, 세 공급사 모두 이미지 입력 모델), 사진에 보이지 않는 메뉴·가격·맛은 지어내지 않도록 명시, 올린 사진(대표 포함 최대 6장)을 이미지 컷으로 저장해 본문 이미지 자리와 캡션으로 연결, 대표 사진에 제목 글자 합성 옵션, 결과는 공통 결과 화면·보관함 자동 저장. 옛 "글쓰기 스타일 A/B"는 말끝·문체 선택으로 대체.
- 글 작성 공통 로직은 `useBlogWorkspace`(자동 저장·이미지 생성·교체·확장 전달), 결과 화면은 `PostWorkspaceView`로 분리해 세 탭이 공유한다.

# video-to-gif 「⚡ 내 PC 고속 변환」(로컬 렌더러)을 영상 프로그램에 쓰는 방안 — 분석 (2026-10-24)

> 작성: Claude Code 윈도우, 영상 담당 `claude-win-video` · 주인님 지시 「여기에 무료로 영상을 만들거나 랜더링 하는 기능이 추가되었어 … 영상쪽에서 활용할 방안을 강구해봐」
> 상태: **분석·제안(코드 변경 없음)**. 렌더러 원본 폴더 `video-to-gif/`는 이커머스 담당(맥미니 `claude-mac-20261023-ecommerce`) 폴더 — 고칠 때는 그 세션과 순서를 맞춘다.
> 읽은 자료: `video-to-gif/docs/IMPROVEMENT_HANDOFF_20261024.md`, `PLAN_20261023_LOCAL_RENDERER.md`(「다른 영상 프로그램으로 넓히기」 LR-02), `lib/localRenderer.ts`, `local-renderer/`(확장·host.pl·host.ps1).

## 1. 로컬 렌더러 요약
- 웹 → 크롬 확장(Native Messaging, ID 고정) → 렌더러(맥 perl·윈도우 PowerShell, 둘 다 기본 내장) → **회원 PC의 ffmpeg**. 서버·유료 서비스 없음.
- 보안: 렌더러는 명령 문자열을 받지 않고, 명령 종류별로 정해진 숫자(가로폭·fps·색 수·구간)만 검사해 ffmpeg 인자를 스스로 만든다. 확장은 `video-to-gif.buylife.xyz`만 연결 허용.
- 전송: 512KB 조각 업로드 → `encode` → 진행률 → 600KB 조각 결과. 없거나 옛 판이면 브라우저 변환으로 자동 전환.
- 효과(1080p 10초 GIF): 브라우저 157초 → 내 PC 25~48초.

## 2. 영상 프로그램의 지금 렌더링 방식
| 방식 | 프로그램 | 렌더러로 옮길 수 있나 |
|---|---|---|
| 브라우저 ffmpeg.wasm(필터 그래프) | `infinite-loop-video` | **그대로 옮길 수 있음** — 같은 ffmpeg 명령 |
| Remotion 브라우저 렌더(`@remotion/web-renderer`, WebCodecs) + mediabunny | `ai-video-studio`(영상 합치기), `music-video-studio`(최종 뮤직비디오) | 장면 조합은 못 옮김(화면을 브라우저가 그림). **앞뒤 처리만** 옮길 수 있음 |
| 캔버스로 직접 그리기 + `mp4-muxer`(공용 `browser-mp4-encoder`) | `shorts-onestop-studio`, `shots`, `lyric-video-studio`, `playlist-channel-studio` | 그리기는 못 옮김. 효과 작음 |

## 3. 활용 방안 (추천 순서)
| 순위 | 방안 | 무엇이 좋아지나 | 난이도 | 비고 |
|---|---|---|---|---|
| **1** | 무한 루프 영상 → 렌더러 `loop` 명령 | 변환이 빨라지고, 렌더러가 `ffprobe`로 소리 트랙을 직접 확인해 **소리 없는 영상 실패 버그(2026-10-24 발견)도 근본 해결** | 낮음 | LR-02 1순위와 같음. 단 브라우저 쪽 소리 판단 버그는 렌더러와 별개로 먼저 고쳐야 함(렌더러 없는 회원) |
| **2** | AI 영상 스튜디오 영상 합치기 → 렌더러 `normalize` 명령(넣는 영상을 H.264 고정 프레임으로 맞춤) | R1(하드웨어 인코딩 영상이 멈춤) 대책인 「시험 렌더 6초 + mediabunny 소프트웨어 다시 인코딩」을 PC ffmpeg로 대신 → 휴대폰 촬영·긴 영상 넣기가 빨라짐 | 중간 | 입력 → 출력 파일 한 개라 기존 메시지 약속 그대로 |
| 3 | AI 영상 갤러리·합치기 결과 → 렌더러 `scale` 명령(1080p 키우기·압축) | 백로그 「1080p 출력」을 업체 추가 요금 없이 | 낮음~중간 | 화질이 새로 생기지는 않음(크기만 키움) — 안내 문구 필요 |
| 4 | 뮤직비디오·합치기 최종 MP4 → 렌더러 `compress` 마무리(빠른 시작·용량 줄이기) | 브라우저 인코더는 비트레이트가 높아 파일이 큼 → 업로드·갤러리 50MB 한도에 유리 | 낮음 | 효과는 용량 위주 |
| ✕ | 캔버스·Remotion 장면 그리기 자체를 렌더러로 | — | 매우 높음 | 화면 그리기를 ffmpeg로 다시 만들어야 해서 추천 안 함 |

## 4. 공통으로 먼저 할 일 (1~4 어느 것이든)
1. 확장 이름을 공용(「AIMaster 내 PC 고속 변환」)으로, `externally_connectable`에 대상 사이트 추가(확장 ID는 같은 키라 그대로).
2. `pong`에 `capabilities`(예: `["gif","loop","normalize"]`)를 넣어 화면이 지원 여부를 앎 → 옛 렌더러는 브라우저 처리로 자동 전환.
3. 웹 쪽 `lib/localRenderer.ts`를 공용 기준 코드로 등록(기준 `video-to-gif`, 사본 각 영상 프로그램) — 프로그램끼리 서로 부르지 않고 사본으로.
4. 렌더러(host.pl·host.ps1)에 명령 추가 → `HOST_VERSION`·`minHost` 올림 → 맥미니·윈도우 둘 다 실검수.
5. 회원에게는 **선택 사항**(설치 안 해도 지금처럼 동작). 휴대폰은 해당 없음.

## 5. 비용·위험
- 회원·운영자 비용: 없음(회원 PC의 무료 ffmpeg). 개발 비용: 프로그램 배포 빌드(각 1회), AI 호출 없음.
- 위험: 렌더러 원본이 다른 세션 폴더 — 명령 추가는 그 세션과 합의 후 한 쪽이 맡는다. 맥 실검수는 맥미니에서만 가능.

## 6. 제안
1. 먼저 **무한 루프 영상 브라우저 버그 수정**(소리 없는 영상, 렌더러와 무관 — 회원 피해 수정).
2. 다음 **방안 1(`loop`)** — 이커머스 세션과 역할 나눔: 렌더러 명령(host.pl·ps1)은 이커머스 세션, 화면 연결은 영상 담당.
3. 회원 반응을 보고 **방안 2(`normalize`)**.

# music-player 개선 작업 개발 플랜 — v1.05

2026-10-16 Codex(Windows). 주인님께 코드 수정 전 플랜을 제시했고 "진행해줘" 지시로 진행합니다.

## 문제와 범위

Antigravity의 v1.04 디자인/메뉴 연동 완료 후 `IMPROVEMENTS.md` BUG #1을 이어받습니다. ID3의 인코딩 번호 0을 Latin-1로만 읽어 구형 국내 CP949/EUC-KR 곡명이 깨집니다. 향후 제안 8건은 이번 오류 수정과 구분해 유지합니다.

1. 합성 ID3v2.2/2.3/2.4 바이트로 실패를 재현합니다. UTF-8/UTF-16·서유럽 문자·손상 태그도 검사합니다.
2. 인코딩 번호 0에 엄격한 UTF-8/한국어 감지를 추가합니다. 자동 추정에는 한계가 있으므로 자동/한국어(CP949)/서유럽(Latin-1) 선택을 제공해 애매한 태그를 직접 복구할 수 있게 합니다. 명시된 UTF 태그는 유지합니다.
3. 이미 저장된 곡은 원본 Blob의 태그를 다시 읽어 선택 곡 또는 전체의 제목·가수·앨범만 갱신합니다. 파일·커버·ID·순서·재생 위치·EQ는 보존하고 저장 실패를 성공으로 표시하지 않습니다.
4. 기존 재생·목록·EQ·저장/복원·회원별 분리·좌측 메뉴·모바일을 보이는 Microsoft Edge에서 검수합니다. 합성 오디오/태그를 사용하고 실제 음원은 서버에 올리지 않습니다.
5. 코드/DB 버전 v1.05, 매뉴얼·AGENTS·README·최신 CLI 인수인계·개선과제 상태를 맞춥니다. 커밋→푸시→해당 프로그램 운영 배포→일반 시험 회원(`buylifemall@naver.com`) 검수→결과 기록까지 진행합니다.

## 비용과 제한

유료 API 호출 0회, 신규 의존성·클라우드 스키마·환경변수 변경 없음. 기존 다크 디자인과 로컬 회원별 저장 방식을 유지합니다. 문자 인코딩은 바이트만으로 완벽히 구분할 수 없어 수동 선택을 남깁니다. OS 잠금화면·블루투스·다중 목록·크로스페이드·파형·가사·저장소 정리·JSON 백업은 이번에 구현했다고 보고하지 않습니다.

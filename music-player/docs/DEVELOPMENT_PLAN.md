# 뮤직 플레이어 자동화 (music-player) — 분석 및 개발 플랜 (2026-10-13, 승인 대기)

> 상태: **분석·플랜 단계. 코드 미착수.** 참고 원본: Google AI Studio 앱 "GPT PARK MUSIC PLAYER"(사운드웨이브 플레이어).
> 원본 소스 ZIP(주인님 승인 후 `D:\PDS\music-player-source`에 받아 전수 정독, 실행하지 않음). 원본 코드는 복제하지 않고 기능·로직만 참고한다.

## 1. 원본 분석

### 1-1. 구성
React 19 + Vite 6 + Tailwind(CDN), 소스 6개 파일 약 44KB: `App.tsx`(493줄, 모든 로직), `components/Visualizer.tsx`(캔버스 시각화), `Equalizer.tsx`(8밴드), `Icon.tsx`(SVG), `types.ts`(Track, RepeatMode). **AI 호출·네트워크 저장이 전혀 없는 순수 브라우저 앱**이다(`GEMINI_API_KEY` 주입 코드는 있으나 사용처 없음).

### 1-2. 기능·옵션 (코드 기준)
| 영역 | 동작 |
|---|---|
| 파일 추가 | `<input type=file multiple accept=audio/*>`, `URL.createObjectURL`, 파일명 `아티스트 - 제목` 규칙으로 이름 분리(없으면 Unknown Artist), `loadedmetadata`로 길이 읽기 |
| 재생 | 재생/일시정지, 이전/다음(처음↔끝 순환), 진행바 시크, 볼륨(0~1), 곡 클릭 재생, 첫 추가 시 자동 재생 |
| 반복·셔플 | 반복 3단(없음/한 곡/전체), 셔플(무작위 인덱스) |
| 목록 | 이름/아티스트 검색, 정렬 순환(이름↑↓·아티스트↑↓), 체크박스 다중 선택·전체 선택(부분 선택 표시), 선택 삭제(확인창), 사이드바 숨김 |
| 시각화 | Web Audio `AnalyserNode`(fft 2048), 5가지 모드(line·bars·wave·circle·dots), 무지개 그라디언트, 앨범 아트 보기 전환 |
| 이퀄라이저 | 8밴드 peaking 필터(60·170·310·600·1k·3k·6k·12k Hz, Q 1.4), ±15dB(0.1 단위), 프리셋 5(Flat·Rock·Pop·Jazz·Classical), 초기화 |
| 기타 | 새로고침 버튼(페이지 재로드), 고정 950×720 창, 다크 테마 |

### 1-3. 결함·한계 (우리 버전에서 해결)
1. **저장이 전혀 없음**: 새로고침 버튼은 재생목록을 전부 날린다. EQ·볼륨·옵션도 초기화.
2. **재생목록을 모두 지우고 다시 추가하면 소리 경로가 깨질 위험**: `createMediaElementSource`는 같은 `<audio>`에 두 번 호출 불가(InvalidStateError). 목록이 비면 AudioContext를 닫고 지우는 로직과 충돌.
3. 앨범 아트가 `picsum.photos` **무작위 사진**(곡과 무관, 외부 의존). ID3 태그·내장 커버 미사용.
4. 메타데이터는 파일명 규칙뿐(ID3 태그 없음), 길이 읽기 실패 시 0:00.
5. 정렬·검색한 화면 순서와 이전/다음 순서가 불일치(재생 순서는 원본 배열 기준).
6. 셔플이 같은 곡 반복 가능, 반복 "없음"+셔플이면 끝나지 않음.
7. `line` 시각화는 주파수 데이터를 시간축 파형처럼 그려 모양이 부정확, `wave`도 의미 없는 좌우 대칭.
8. 키보드 단축키·드래그&드롭·음소거·재생 속도·미니 플레이어 없음. 고정 크기라 반응형 아님, 접근성(라벨·포커스) 부족, `window.confirm` 사용.
9. 이미 작성된 EQ 값이 곡 간 유지되나 앱을 닫으면 사라짐.

### 1-4. 실행 결과 확인 상태
- 운영 미리보기는 열어 초기 화면(빈 재생목록, 컨트롤 바, 시각화 영역)을 확인했다. 파일 선택창은 브라우저 도구로 열 수 없어 오디오 재생 동작은 **코드로 확정**했고, 구현 후 합성 오디오(Oscillator)와 실제 Chrome으로 대조 검수한다.

## 3. 범위

### v1.01 (원본 동등 + 결함 해결)
- 파일 추가(선택·**드래그&드롭**·폴더), 재생/이전/다음/시크/볼륨/**음소거**, 반복 3단, 셔플(중복 최소화), **재생 속도**
- 목록: 검색, 정렬, 체크 선택·삭제(**앱 내 확인창**), 사이드바 접기, **현재 표시 순서 기준 이전/다음**
- 시각화 5모드(주파수 막대·원형·점은 유지, line/wave는 시간축 파형으로 정확히 구현) + 앨범 아트
- 8밴드 EQ + 프리셋 5 + **사용자 프리셋 저장**, 프리앰프, 초기화
- **저장**: 재생목록(메타+파일 Blob)·정렬·볼륨·EQ·시각화 모드를 회원별 IndexedDB에 자동 저장, 다시 열면 복원(파일이 지워졌거나 용량 부족이면 안내)
- **ID3 태그**(제목·아티스트·앨범·내장 커버)와 파일명 규칙 폴백, 곡별 색 그라디언트 기본 커버(외부 이미지 제거)
- 키보드 단축키(Space·←→·↑↓·M·S·R), 반응형 레이아웃(모바일 하단 컨트롤), 접근성 라벨
- 흰색 베이스 작업 화면(AIMaster 규칙) + 시각화 영역만 어두운 무대, 표준 사이드바(번호형 흐름, 메뉴 구성은 §4), 사용 매뉴얼

### 후속 (결정 보류 아님, 단계 분리)
다중 재생목록·즐겨찾기, 클라우드 설정 동기화(EQ·프리셋만, 오디오 제외), 재생목록 JSON 내보내기·불러오기, AI 곡 분석(본인 키).

## 4. 아키텍처

- Next.js 16 App Router + TS, **순수 CSS**, 구조·인증·접근 게이트는 `markdown-studio`/`ui-canvas` 패턴 재사용(`src/lib/access.ts`, `programAccess.ts`, `/login`, 사이드바 표준).
- 서버 API 최소: 세션·접근 확인뿐(오디오 처리는 전부 클라이언트). 모든 route는 `checkProgramAccessApi` + `dynamic="force-dynamic"`/`fetchCache="force-no-store"`.
- 오디오 엔진 `src/lib/audio/engine.ts`: 단일 `AudioContext`와 `MediaElementSource`를 **한 번만** 만들고 목록이 비어도 닫지 않음(결함 2 해결). 노드 그래프 `source → preamp → EQ(8) → analyser → destination`.
- 순수 로직 분리·단위 테스트: 정렬/검색, 다음·이전 곡 계산(셔플·반복·표시 순서), 파일명 파서, EQ 프리셋, 시간 포맷, 저장 스키마 마이그레이션.
- 저장소 `idb`(IndexedDB): `tracks`(Blob·메타), `settings`(EQ·볼륨·모드), 사용자별 키(`userId` 네임스페이스) — 용량 초과·삭제 시 사용자 안내.
- ID3: 경량 파서 직접 구현(ID3v2.3/2.4 제목·아티스트·앨범·APIC) 또는 검증된 소형 라이브러리, 실패 시 파일명 규칙.
- 진입: 접속 즉시 플레이어 화면(UI Canvas의 `/open` 패턴), 별도 목록 화면 없음.

## 7. 리스크
1. 브라우저 저장 용량(음악 Blob): 사용량 표시와 오래된 곡 삭제 안내, 저장 실패 시 파일만 재선택 방식으로 폴백.
2. `AudioContext`는 사용자 제스처 후에만 시작 → 첫 재생 클릭에서 resume.
3. CORS 없는 로컬 Blob이라 분석기는 문제 없음. 포맷 지원은 브라우저 의존(FLAC/OGG/M4A 등 안내).
4. 저작권: 오디오를 서버로 보내지 않으므로 서비스 책임 범위 밖(매뉴얼에 명시).

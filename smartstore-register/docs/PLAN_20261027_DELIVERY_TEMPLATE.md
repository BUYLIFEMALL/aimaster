# 플랜 — 배송 칸 자동 입력 (EC-W8 마지막 수동 칸, 2026-10-27)

> 역할 `ecommerce-image` · Claude Code 윈도우 `claude-win-sdp`. 대상 `smartstore-register` v1.03 → v1.04(배포 때).

## 문제
- v1.03 실제 시험 6회째에 배송 템플릿 1칸만 수동으로 남음.
- 저장본 분석 결과, 지금 코드가 노리던 칸 `vm.savedTemplate['DELIVERY']`는 **템플릿을 고르는 칸이 아니라 「템플릿 추가」 체크 상자**(지금 값을 새 템플릿으로 저장)였다. 확장이 이 단계를 수동으로 건너뛰고 있어서 피해는 없었다.
- 실제 고르기는 「배송비 템플릿」 버튼(`ng-click=vm.templateModal()`)이 여는 목록 창에서 한다. 이 창은 열었을 때만 화면에 생기므로 지금 저장본에 구조가 없다.

## 방법 (두 갈래)
| 방법 | 언제 | 하는 일 | 필요한 것 |
|---|---|---|---|
| 첫 번째: 템플릿 이름으로 고르기 | 기본값에 「배송 템플릿 이름」이 있을 때 | 배송 섹션 펼치기 → 「배송비 템플릿」 버튼 → 목록에서 이름이 같은 줄 선택 → 적용 → 창 닫힘 확인 | **목록 창이 열린 상태의 저장본(주인님)** |
| 두 번째: 칸 직접 입력 | 이름이 비어 있을 때 | 택배사(`vm.modelData.deliveryCompany.id`), 배송비 종류(`vm.modelData.deliveryFee.deliveryFeeType` — 무료/유료/조건부 무료), 기본 배송비(`…baseFee`), 무료 조건 금액(`…freeConditionalAmount`)을 이름으로 찾아 채움 | 기본값 화면에 칸 4개 추가. 저장본에 칸 이름이 이미 있음 |

- 「템플릿 추가」 체크 상자는 절대 누르지 않는다(새 템플릿이 생김).
- 배송비 종류·택배사는 고르기 상자(`select`)라 보이는 글자로 고른다.
- 칸을 못 찾거나 이름이 같은 템플릿이 없으면 지금처럼 멈추고 「등록 기록」에 남긴다(저장 안 함).

## 순서
1. `fields.ts` — 배송 단계 고치기(잘못된 대상 제거, 두 갈래 단계 만들기) + 시험 추가
2. 기본값 화면·`normalizeDefaults` — 택배사·배송비 종류·기본 배송비·무료 조건 금액
3. 확장 `background.js` — 템플릿 창 고르기(저장본 받은 뒤), 직접 입력은 기존 `select`·`type` 동작 재사용
4. 로컬 검사(tsc·시험·build) → 주인님 크롬에서 「입력만」 시험(두 갈래 각각)
5. 배포는 모았다가 한 번(빌드 1회, 실행 전 승인) — 확장 ZIP·DB 버전 함께(원칙 10)

## 검수
- 시험: 이름 있음 → 템플릿 단계, 이름 없음 → 직접 입력 단계, 둘 다 「템플릿 추가」를 건드리지 않음
- 실제: 「입력만」 1회씩, 「등록 기록」 실패 0칸, 판매자센터 배송 섹션 캡처

## 비용
- 개발·시험: 없음(로컬). 배포 때 Vercel 빌드 1회(실행 전 승인). 회원 부담 없음.

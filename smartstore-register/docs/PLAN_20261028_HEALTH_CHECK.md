# 개발 플랜 — 판매자센터 화면 변경 조기 발견 (2026-10-28, `claude-win-sdp` · 역할 ecommerce-image)

> 상태: **플랜 보고 단계(주인님 승인 전, 코드 수정 없음)**. 배포는 「나중에 한 번에 모아서」.
> 근거: [마켓 등록기 공통 레퍼런스](../../docs/MARKETPLACE_REGISTER_ANALYSIS_GUIDE.md) §4(화면 변경 대응), 대기 목록 「화면 변경 조기 발견: 주 1회 점검」.

## 1. 문제
확장은 판매자센터 칸을 이름(`ng-model` 등 약 60개)으로 찾는다. 네이버가 화면을 바꾸면 **회원이 등록을 보낸 뒤에야** 「칸을 찾지 못했습니다」로 알게 된다. 그 전에 먼저 알아채고 싶다.

## 2. 목표
회원 확장이 **주 1회(+ 화면의 「지금 점검」 버튼)** 판매자센터 상품 등록 화면을 **읽기만** 해서, 확장이 쓰는 칸·버튼·데이터 주소가 그대로 있는지 확인하고 결과를 남긴다.
- 회원 화면: 대시보드·확장 연결 화면에 「판매자센터 화면 점검: ✅ 정상(날짜) / ⚠️ 바뀐 칸 N개(이름)」
- 운영자: 주인님 관리자 계정 확장도 같은 점검을 하므로, 바뀌면 **회원보다 먼저 주인님 화면**에 뜬다 → 담당 세션이 확장 보정.

## 3. 방식 결정
| 항목 | 결정 |
|---|---|
| 무엇을 확인 | 칸 목록 = `fields.ts`의 `target`에서 자동으로 뽑은 **칸 이름 표**(섹션별) + 버튼(저장·임시저장·이미지·배송 템플릿·모델명 찾기) + 데이터 주소 2개(카테고리 검색·속성) 응답 모양 |
| 어떻게 | 확장이 판매자센터 「상품 등록」을 **비활성 새 탭**으로 열고(열린 판매자센터 탭은 건드리지 않음) → 「이전 작성 내용」 창은 취소 → 접힌 섹션은 펼쳐서 칸 존재만 확인 → **입력·저장 없음** → 끝나면 그 탭을 닫음 |
| 언제 | 확장 `chrome.alarms` 7일마다(등록 작업·속성 읽기가 없을 때만) + 화면 「지금 점검」 |
| 판정 | 칸 이름이 없으면 「바뀐 칸」. 카테고리에 따라 나오는 칸(옵션·상품속성·어린이제품인증 등)은 「카테고리 의존」으로 표시만(실패로 세지 않음) |
| 저장 | 새 표 `smartstore_register_health`(회원, 시각, 확장 버전, 정상 여부, 바뀐 칸 목록 jsonb) — 회원 본인만, 30일 정리 |

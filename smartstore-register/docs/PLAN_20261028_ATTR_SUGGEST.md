# 개발 플랜 — 상품속성 AI 추천 (2026-10-28, `claude-win-sdp` · 역할 ecommerce-image)

> 상태: **플랜 보고 단계(주인님 승인 전, 코드 수정 없음)**. 배포는 「나중에 한 번에 모아서」.

## 1. 문제
v1.21 「속성 불러오기」로 판매자센터 속성·보기를 고를 수 있게 됐지만, 백팩만 해도 속성 8개·보기 90여 개라 회원이 하나씩 고르기 번거롭다. 상세페이지 자동화에 이미 상품 특징·사양·사용법·대상 글이 있다.

## 2. 목표
속성을 불러온 뒤 **「✨ 상세페이지 내용으로 추천」** 버튼 → 회원 본인 AI 키로, **판매자센터 보기 목록 안에서만** 값을 골라 화면에 미리 체크해 둔다. **자동으로 보내지 않고** 회원이 확인·수정한 뒤 「확장으로 보내기」.

## 3. 방식
| 항목 | 결정 |
|---|---|
| 재료 | `shop_products`의 상품명·카테고리·`key_features`·`specs`·`how_to_use`·`target_customer`(본인 상품만) |
| AI | **(2026-10-28 주인님 「앞으로 기본 api키 사용은 클로드야」로 변경)** 회원 본인 Claude 키(`user_api_keys` provider `anthropic`, 폴백 없음, 없으면 키 등록 안내) · 모델 `claude-opus-5-5`·effort low · 구조화 응답(json_schema) · 거절 시 `fallbacks: "default"` |
| 규칙 | 보기에 없는 값은 버림, 최대 개수 넘으면 앞에서부터 자름, 확신 없는 속성은 비움, 당해 연도 규칙 해당 없음(사실 분류) |
| 저장 | 따로 저장하지 않음(화면에만 채움) → DB 변경 없음 |

## 4. 구현 순서
| 단계 | 할 일 | 파일 |
|---|---|---|
| 1 | 추천 결과 정리 함수(보기 안 값만·최대 개수·중복 제거) + 시험 | `src/lib/smartstore/attributes.ts`, `tests/` |
| 2 | 회원 키 읽기(`user_api_keys`, 본인만) + Gemini 호출(시간 제한 25초, 재시도 없음) + 서버 동작 `suggestAttributesAction(productId, lookupId)` — 권한 확인, 본인 상품·본인 속성 결과만 | `src/lib/ai/gemini.ts`, `src/lib/actions/attributes.ts` |
| 3 | 화면: 버튼, 진행 표시, 추천 값을 고르기 칸에 채움(기존에 고른 값은 덮지 않고 빈 속성만), 키 없으면 등록 안내 링크 | `src/components/AttributePicker.tsx` |
| 4 | 검수: 시험·tsc·build, ego 실물(관리자 계정 백팩 1~2회 호출) | — |

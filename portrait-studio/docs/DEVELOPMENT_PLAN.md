## 1. 원본 앱 분석

### 1-1. 한 줄 요약
사진 1장을 올리면 **촬영 목적(증명사진/비즈니스 프로필/SNS/시네마틱 화보/자유)** 에 맞춘 스튜디오 옵션으로 인물 사진을 Gemini 이미지 모델로 다시 만들어 주고, 여권·면허 규격 후처리(순백 배경·413×531)까지 해 주는 **단일 화면 스튜디오 앱**입니다.

### 1-2. 기술 구조
- Vite + React 19 + TypeScript, **서버 없음**. 브라우저에서 `@google/genai`로 직접 호출(AI Studio가 키를 대신 주입: `process.env.API_KEY`).
- 모델: `gemini-2.5-flash-image`(나노바나나), `gemini-3-pro-image-preview`(프로). 프로만 `imageSize`(1K/2K/4K) 적용, `aspectRatio` 9종(1:1, 3:4, 4:3, 9:16, 16:9, 1:4, 4:1, 1:8, 8:1).
- 상태는 `App.tsx` 한 파일(약 32KB)에 집중. 번역은 ko/en 이중(`translations.ts`).

### 1-4. 원본의 결함·주의점 (그대로 가져오면 안 되는 것)
1. **존재하지 않는 id 참조**: 목적 프리셋의 `kodak-portra-400`, `kodak-gold-200`, `ilford-hp5`, `biker-leather`, `keep-reference`는 실제 데이터에 없습니다(`kodak-portra`, `kodak-gold`, `leather-jacket`, `keep-original`만 존재). `find` 실패 시 조용히 이전 선택이 남아 **목적을 바꿔도 옵션이 안 바뀌는 버그**입니다 → 신규 구현은 id 일관성을 단위 테스트로 막습니다.
2. 카메라 옵션이 데이터에는 4종인데 화면에서 고를 수 없음 → 신규는 선택 UI를 노출합니다.
3. 순백 클린업은 **인물 머리·옷이 밝은 경우 배경으로 오인**해 번질 수 있고(채도 0.35·밝기 205 임계값), 큰 이미지(4K)에서 UI 스레드를 오래 점유 → 신규는 작업 크기 제한·Web Worker/청크 처리와 "영역 미리보기"를 둡니다.
4. **"정부24 100% 통과·여권 규격 완벽" 단정 문구**: 실제 심사 결과를 보장할 수 없고, 공식 서류 사진은 AI 재생성·과한 보정이 규정상 제한될 수 있습니다 → 신규는 "통과 보장 아님·제출 기관 규정 확인" 안내와 용도 구분(프로필/공식 서류 참고용)을 넣습니다.
5. 얼굴 사진은 **민감한 생체 정보**이고 타인 사진 도용·사칭 우려가 있습니다 → 서버 저장 금지(브라우저 보관), 본인/동의받은 사진 확인 문구, 유명인 사칭 금지 안내.
6. 입력 이미지를 base64로 그대로 전송 → 신규는 Vercel 본문 한도(4.5MB)에 맞춰 클라이언트에서 긴 변 1,600px JPEG로 축소(fashion-style 방식).
7. 다크 테마·en 번역·개발자 홍보 푸터 → 신규는 흰색 클린 UI·한국어 단일·크레딧 없음.

## 3. 제품 판단 (루트 CLAUDE.md 핵심 원칙 대조)
- **최상위 규칙(본인 키)**: Gemini 이미지 생성은 **회원 본인 키**만 사용, 키 없으면 `needKey` 안내, 폴백 금지. 이미지 모델(특히 프로·4K)은 본인 키 요금이 발생함을 화면에 명시.
- **회원용 SaaS 맞음**(원칙 4): 운영자 키·계정 의존 없음. **운영자 실비 없음 → 프리미엄 후보 아님**(원칙 16).
- 원칙 3(한국인 묘사): 참조 사진 기반이라 얼굴은 원본 유지. 배경·보조 인물 묘사가 필요한 문구는 한국인 기본.
- 원칙 8(당해 연도): 이미지 프롬프트에는 연도가 필요 없으나, 텍스트 안내/추천 문구를 AI로 만들 경우 연도 지침 포함.
- 흰색 베이스 UI·표준 사이드바(계정은 마지막 메뉴 바로 아래)·`← 다른 프로그램 보기`.
- 서버 DB 테이블 **없음**(사진·결과는 회원 브라우저 IndexedDB). 필요 시 v1.02에서 검토.

## 5. 구현 설계

### 5-1. 구조 (`portrait-studio/`, fashion-style·ai-writing-editor 스캐폴드 기반)
- Next.js 16 + React 19 + TS, 순수 CSS, `idb`, `@google/genai`(서버만). 공용 권한 판정(`access.ts`, 핸드폰 필수·FREE·구독·등급+기간), `user_api_keys`(provider `gemini`) 재사용.
- `src/lib/portrait/` **순수 로직(단위 테스트)**: `options`(옵션 데이터·id 일관성), `purposes`(목적 프리셋), `prompt`(슬롯 치환 `buildPrompt()`), `validate`(요청·응답 검증), `size`(종횡비·축소 계산).
- `src/lib/portrait/post/` 클라이언트 후처리: `flip`, `whiteClean`(BFS, 크기 제한·진행 표시), `licenseSize`(413×531, 250KB 이하로 품질 조정), `tone`(밝기·노출·대비).
- 서버: `gemini.ts`(`imageModel` flash/pro, pro→flash 폴백, 오류 분류: 키/한도/안전/무이미지/시간초과), `aiRoute.ts`(권한→본문 한도→본인 키).
- API: `POST /api/generate`(이미지+옵션 → 생성 이미지), `/api/keys`(+`/test`). 모든 쓰기·유료 호출에 `checkProgramAccessApi` + `force-dynamic`/`force-no-store`.
- 화면: `/studio`(목적 탭 → 3열: 입력·보정 / 결과·후처리 / 스타일 옵션), `/history`(내 기록, IndexedDB), `/settings`(API키등록·플랫폼연동 + 매뉴얼 박스), `/guide`.

### 5-2. 프롬프트 설계
- 원본 `BASE_PROMPT` 슬롯 구조는 유지하되 **영어 고정 템플릿 + 한국어 UI 라벨** 분리, 슬롯 누락 시 빈 문장 방지.
- 규칙: 얼굴 동일성 최우선, 텍스트·로고 금지, 과한 보정·HDR 금지, 자연 질감, 의상·배경만 변경.
- 보정 4종·증명사진 규격 지시문은 원본 의미를 유지하되 **과도한 얼굴 변형 금지**(눈·코·입 형태 변경 금지) 문구를 추가.

### 5-3. 데이터·개인정보
- 사진·결과는 **서버에 저장하지 않음**(요청 처리 후 폐기, 로그에 이미지 미기록). 보관은 브라우저 IndexedDB(회원별), [기록 삭제] 제공.
- 화면에 "본인 또는 동의받은 사진만", "공식 서류는 제출 기관 규정 확인" 고정 안내.

# 개발 플랜 — E9 쇼핑몰 단계 잇기(「🛒 쇼핑몰 흐름」 띠 + 발송 전 주문 → 라벨)

작성: 2026-10-25 Claude Code(윈도우) `claude-win-sdp` [역할: ecommerce-image]
대상: ① AIMaster 운영 — `shop-order-report`·`seller-label-docs`·`trending-product-finder` (상세페이지 `shop-detail-page`는 디자인 담당 작업 중 표 줄이 비면 사본만 추가)
근거: [쇼핑몰 묶음 인계](../../docs/analysis-ecommerce-bundle-20261024/HANDOFF_20261024_ECOMMERCE.md) §0 D7(「각 프로그램은 단독으로 끝까지 쓸 수 있고 연결은 선택, 흐름 띠는 흐름으로 들어왔을 때만」)·§4
상태: **주인님 승인 대기** (코드 없음)

## 1. 만들 것
| # | 연결 | 내용 |
|---|---|---|
| 1 | 📦→🏷 주문 리포트 「발송 전 주문」 → 셀러 라벨 | 주문 현황에서 「🏷 발송 전 주문 라벨 만들기」 → 셀러 라벨이 새 탭으로 열리며 표가 자동으로 채워진다(상품명·옵션·수량·주문번호·주문일). 넘기는 값에 **구매자 개인정보는 없다**(주문 리포트는 처음부터 읽지 않음). 서버를 거치지 않고 주소 뒤 「#」 부분으로만 넘긴다(서버 기록에 남지 않음, 최대 300줄 — 넘으면 엑셀로 받아 올리도록 안내) |
| 2 | 🛒 쇼핑몰 흐름 띠 | 흐름으로 들어왔을 때만 맨 위에 「① 상품 소싱 → ② 상세페이지 → ③ 주문·매출 리포트 → ④ 발송 라벨」 4단계 띠, 지금 단계 강조, 이전·다음 버튼. 그냥 들어오면 보이지 않는다(D7). 흐름 표시는 주소 `?flow=shop`으로 시작해 그 탭 안에서만 기억 |
| 3 | 공용 기준 코드 `shop-flow` | 단계 목록·주소 만들기·흐름 여부 판정 + 띠 컴포넌트(앱마다 디자인이 달라 색은 띠 안에서만 정함). 기준 `shop-order-report`, 사본 셀러 라벨·상품소싱(`docs/SHARED_MODULES.md` 등록) |
| 4 | 기존 연결에 흐름 이어 붙이기 | 상품소싱 「📄 상세페이지 만들기」 링크에 흐름 표시를 함께 넘김(받는 상세페이지는 사본 추가 전까지 띠 없이 지금처럼 동작) |

### 하지 않는 것
- 상세페이지 → 쇼츠 원스톱 넘기기(받는 쪽은 영상 담당 — 넘길 값 형식만 다음에 협의).
- 회원 상품 카드 공유 표(DB, 2차 — 승인 뒤).
- E2(카테고리·태그 초안)는 아직 만들지 않았으므로 넘길 값 없음.

## 2. 검수
- 자동 시험: 주소 만들기·읽기(300줄 제한, 깨진 값 무시), 흐름 판정, 단계 이전·다음, 라벨 쪽 가져오기(열 이름·줄 수).
- 크롬 시험 계정: 주문 리포트 예시 주문 → 「발송 전 주문 라벨 만들기」 → 셀러 라벨 표 자동 채움 확인, 흐름으로 들어왔을 때만 띠 보임·그냥 들어오면 안 보임, 휴대폰 폭. 검수 뒤 예시 데이터 지움.

# 주문 알림(문자 먼저, 메일 다음) — 개발 플랜 (2026-11-04)

- 대상: Lab `labs/mall-builder` (DB `rjjtjakljjxsgjelqgek`). 운영 DB·운영 사이트는 건드리지 않음
- 상태: 2026-11-04 승인(채팅) → 1~4단계 구현·내 PC 확인 완료, Lab 배포·실제 문자 시험 대기. 결과는 `README.md` 「남은 일」 D9
- 구현 중 바꾼 점: 실행 주소를 새로 만들지 않고 D8 주소 `/api/cron/deposit-expire`가 자동 취소와 알림 발송을 함께 한다 — 주소를 바꾸면 이미 등록된 운영자 cron-job.org 작업을 못 찾아 작업이 둘로 늘고 옛 작업이 계속 불린다. 시험 문자는 확인 창 대신 두 번 누르기
- 결정(주인님 채팅 2026-11-04): 문자는 **몰 운영자 본인 솔라피 계정**(시험은 주인님 계정, 이미 충전됨), 메일은 **Resend**(2단계). 키는 주인님이 몰 설정 화면에 직접 입력 — 에이전트가 운영 DB의 키를 꺼내 옮기지 않음

## 1. 문제
주문이 들어와도 운영자는 관리 화면을 열어 봐야 알고, 손님은 입금 계좌·발송 소식을 화면에서만 확인한다.

## 2. 보낼 알림 (1단계: 문자)
| 받는 사람 | 언제 | 내용(예) |
|---|---|---|
| 운영자 | 새 주문(무통장·외상) | `[몰이름] 새 주문 20261104-0007 · 84,600원 · 무통장(입금 대기)` |
| 손님 | 주문 접수(무통장) | 입금 계좌·금액·입금 기한(D8이 켜져 있으면) |
| 손님 | 입금 확인(결제 완료로 바뀜) | 배송 준비 안내 |
| 손님 | 발송(송장 입력) | 택배사·송장 번호 |
| 손님 | 입금 기한 초과 자동 취소 | 취소 안내 |

- 손님 번호는 주문서의 「받는 분 핸드폰」, 운영자 번호는 설정에 적은 「알림 받을 번호」
- 알림 종류마다 켜기/끄기(설정 화면 체크 5개). 문구는 1단계에선 고정, 운영자 문구 편집은 다음 단계
- 긴 문구는 솔라피가 자동으로 장문(LMS)으로 보냄

## 3. 설계 — 「알림 대기 줄」 방식
D8에서 정한 원칙(손님 요청 쪽에서 운영자 키를 꺼내는 길을 만들지 않는다)을 그대로 지킨다.

1. **DB가 대기 줄에 적는다**: 주문이 들어오거나 상태가 바뀌면 DB 트리거가 표 `mall_builder_notifications`에 한 줄을 넣는다(받는 번호·문구·종류). 손님은 이 표를 못 읽고, 그 몰 운영자만 읽는다. 같은 주문·같은 종류는 한 번만(고유 제약) → 중복 발송 방지
2. **운영자 cron-job.org가 보낸다**: D8의 같은 cron-job.org 작업이 부르는 실행 주소가 몰 전용 토큰으로 대기 줄을 꺼내(`for update skip locked`, 한 번에 50건) 솔라피로 보내고 결과(보냄·실패·사유)를 적는다. 솔라피 키는 이 토큰 확인을 통과한 경우에만 DB 함수가 돌려준다
3. **주기**: 알림을 켜면 작업 주기를 10분 → **1분**으로 바꾼다(cron-job.org 무료로 가능). 알림이 없을 땐 바로 끝남. 알림 지연은 최대 약 1분
4. **실패 재시도 안 함**: 유료 발송이라 이중 과금을 막으려고 「보내는 중」으로 먼저 표시한 뒤 보내고, 결과가 불확실하면 다시 보내지 않는다(기록에 「확인 필요」로 남김)
5. **작업 켜기 조건 넓힘**: 지금은 「입금 기한이 있을 때」만 작업이 켜진다 → 「입금 기한 또는 알림이 켜져 있을 때」로. 실행 주소는 새 `/api/cron/store-tasks`(자동 취소 + 알림 발송)로 합치고, 옛 `/api/cron/deposit-expire`는 그대로 둔다(이미 등록된 작업 보호)

검토했지만 쓰지 않는 방법: 주문 즉시 서버에서 바로 보내기 — 빠르지만 손님 요청 처리 중에 운영자 키를 읽어야 해서 Lab 앱에 서버 전용 비밀값(환경변수)을 새로 둬야 함. 1분 지연이 그보다 안전하다고 판단.

## 4. 저장 위치
| 무엇 | 어디 |
|---|---|
| 솔라피 키·시크릿 | D8 비밀 표 `mall_builder_store_scheduler_secrets`에 칸 추가(규칙 0개, 아무도 직접 못 읽음) |
| 발신번호·알림 받을 번호·종류별 켜기 | 새 표 `mall_builder_store_notify_settings`(그 몰 운영자만) |
| 대기 줄·발송 기록 | 새 표 `mall_builder_notifications`(그 몰 운영자만 읽기, 쓰기는 DB 함수만) |
| 발송 코드 | `src/lib/solapi.ts` — 공용 기준 코드 `solapi-client`(기준 `crm-google-form/lib/solapi/client.ts`)에서 문자 보내기·잔액 조회만 가져옴(Lab은 독립 프로그램이라 사본 등록부 밖, 출처 주석) |

## 5. 화면
- 운영자 설정 「주문 알림(문자)」: 솔라피 API 키·시크릿(화면엔 「등록됨」만), 발신번호, 알림 받을 번호, 종류 체크 5개, **「시험 문자 보내기」**(알림 받을 번호로 1건, 운영자 본인만), 솔라피 잔액 표시
- 운영자 「알림 기록」: 최근 발송 목록(시각·받는 번호 뒷자리·종류·결과·실패 사유), 주문 상세에도 그 주문의 알림 기록
- 키가 없거나 cron-job.org 키가 없으면 무엇을 먼저 넣어야 하는지 안내

## 7. 2단계: 메일(Resend) — 2026-11-04 승인(채팅) → 1~3단계 구현·내 PC 확인 완료, Lab 배포 승인 대기(README D10)
1단계(문자)는 Lab 배포·실제 시험 통과(README D9). 같은 대기 줄에 「메일」 채널을 더한다.

**바로잡음**: 앞서 「도메인 인증 전에는 운영자 본인 메일로만 보낼 수 있다」고 적었으나, 2026-11-04 확인한 Resend 공식 문서(domains/add-a-domain)는 **도메인을 인증해야 메일을 보낼 수 있다**고 한다. 그래서 메일은 도메인 인증이 끝난 몰에서만 켜진다.

Resend 무료 요금(2026-11-04 resend.com/pricing 확인): 월 3,000통, 하루 100통, 도메인 3개, 초과 과금 없음(넘으면 안 나감).

### 7-1. 설계
| 항목 | 내용 |
|---|---|
| 키·보내는 주소 | 비밀 표에 `resend_api_key` 칸 추가(규칙 0개), 설정 표에 보내는 주소(`order@mail.내도메인`)·운영자 받을 메일·메일 알림 종류 칸 추가 |
| 대기 줄 | `mall_builder_notifications`에 `to_email` 칸 추가, `channel = 'email'`. 같은 주문·같은 종류·같은 채널은 한 번(고유 제약에 채널 추가) |
| 손님 메일 주소 | 손님 몰 가입 정보의 메일(없으면 메일 알림 건너뜀) — 구현 때 손님 표 칸 확인 |
| 문구 | 문자와 같은 내용 + 제목, 간단한 HTML(몰 이름·주문 번호·금액·주문 상세 링크) |
| 발송 | 같은 실행 주소가 문자 다음에 메일을 꺼내 `POST https://api.resend.com/emails`로 보냄(SDK 없이 fetch). **`Idempotency-Key` 머리글에 알림 번호**를 넣어, 결과가 불확실해도 다시 보내면 Resend가 한 번만 보냄 → 메일은 「확인 필요」 대신 한 번 재시도 가능 |
| 화면 | 설정 「주문 알림(메일)」(키·보내는 주소·받을 메일·종류·시험 메일), 기록 목록에 채널 표시 |
| 오류 안내 | 도메인 미인증·주소 형식 오류 등 Resend 오류를 한국어로 |

### 7-2. 주인님 준비(구현 뒤 시험 때)
1. resend.com 가입(무료) → API Keys에서 키 만들기(Sending access)
2. Domains → Add Domain에 하위 도메인 입력(예: `mail.buylife.xyz`) — 루트 도메인 대신 하위 도메인 권장(공식 문서)
3. Resend가 보여 주는 DNS 기록(DKIM TXT, SPF TXT, 반송용 MX)을 Cloudflare `buylife.xyz` DNS에 추가 — **CNAME은 프록시(주황 구름) 끄기**. 기존 사이트 주소·메일에는 영향 없음(하위 도메인 `send.mail…`·`resend._domainkey.mail…` 등 새 이름만 추가)
4. Resend에서 Verify → 「Verified」 확인
5. 몰 설정 화면에 키·보내는 주소(`order@mail.buylife.xyz`)·받을 메일 직접 입력

DNS 입력은 운영 도메인 설정을 바꾸는 일이라 에이전트가 하지 않는다(주인님 직접).

### 7-3. 순서·확인·비용
| 순서 | 할 일 | 확인 |
|---|---|---|
| 1 | DB 추가(칸·고유 제약·트리거에 메일 줄 추가·꺼내기/기록 함수 채널 구분) | DB 시험(되돌림, 지우기 문장 없이) |
| 2 | Resend 발송 코드(`src/lib/resend.ts`)·실행 주소 | 자동 시험(가짜 응답): 보냄·실패·재시도에 같은 Idempotency-Key |
| 3 | 화면 | 내 PC 빌드·ego |
| 4 | Lab 배포(빌드 1회, 누적 8회 — 직전 재확인) | 실행 주소 401 |
| 5 | 주인님 도메인 인증·키 입력 뒤 실제 시험 | 시험 메일 1통 + 시험 주문으로 메일 4통(무료 범위) |

비용: 개발·시험 무료, Lab 빌드 1회, Resend 무료 요금 안, 문자 추가 발송 없음(메일만 켜서 시험).

## 1. 문제
품절 상품을 보러 온 손님은 그냥 떠나고, 운영자는 누가 그 상품을 기다리는지 모른다. 재고를 다시 채워도 손님에게 알릴 방법이 없다.

## 2. 원본(프로셀) 기능 / AIMaster(이 몰) / 채택
| 기능 | 원본 | 이 몰에 이미 있는 것 | 채택·이유 |
|---|---|---|---|
| 품절 상품에 「재입고 알림 신청」 버튼 | 있음 | 품절 표시만(상품 카드·옵션 「- 품절」) | 추가 |
| 옵션별 신청 | 옵션 선택 후 신청 | 옵션 조합별 재고(`variants.stock`) 있음 | 옵션 조합 단위로 추가 |
| 재입고 시 자동 발송 | 문자·알림톡 | 문자(솔라피)·메일(Resend) 대기 줄과 1분 발송 작업(D9·D10) | **이 몰 쪽 채택** — 대기 줄에 종류 하나 추가, 새 발송 경로 안 만듦 |
| 신청 목록·통계 | 관리 화면 목록 | 없음 | 추가(상품별 대기 인원) |
| 알림톡 | 있음 | 없음 | 하지 않음 — 채널·템플릿 심사 필요(D9과 같은 이유) |

## 3. 동작
1. **신청**: 품절(상품 상태 「품절」, 또는 재고 수량 관리인데 재고 0, 또는 고른 옵션 조합 재고 0) 화면에 「재입고 알림 신청」 버튼. 핸드폰(회원은 가입 정보로 미리 채움) + 개인정보 수집·이용 동의 체크 → 신청
2. **중복 막기**: 같은 몰·같은 상품(옵션)·같은 번호는 대기 중 1건만. 한 번호가 하루에 신청할 수 있는 수 제한(예: 20건)
3. **재입고 감지**: DB 트리거가 재고 0 → 1 이상, 또는 상태 「품절」→「판매 중」으로 바뀌는 순간 그 상품(옵션)의 대기 신청을 알림 대기 줄(`mall_builder_notifications`, 종류 `customer_restock`)에 넣는다. 들어간 신청은 「알림 보냄」으로 바뀌어 다시 안 나간다
4. **발송**: 기존 1분 작업이 문자·메일을 보낸다(새 실행 주소 없음). 문구 예: `[몰이름] 기다리시던 「상품명 / 옵션」이 다시 입고됐습니다. 수량이 적을 수 있어요. 주문하기: <상품 주소>`
5. **운영자 화면**: 「재입고 알림」 메뉴 — 상품별 대기 인원, 신청 목록(번호 뒷자리·신청일·상태), 신청 취소. 상품 목록에 「알림 대기 N」 표시. 설정에서 재입고 알림 켜기/끄기(문자·메일 각각)
6. **손님 취소**: 회원은 마이페이지에서 내 신청 보기·취소

## 4. 설계 (DB는 추가만 — 지우는 문장 없음)
| 무엇 | 어디 |
|---|---|
| 신청 | 새 표 `mall_builder_restock_requests`(몰·상품·옵션·회원 id(있으면)·핸드폰·메일·상태 대기/보냄/취소/만료·신청·발송 시각). 손님은 직접 못 쓰고 DB 함수로만 신청. 그 몰 운영자는 읽기, 회원은 자기 것 읽기 |
| 켜기 | 설정 표에 칸 추가(`restock_sms`, `restock_email` 참/거짓) — 기존 종류 목록 제약을 바꾸지 않으려고 따로 칸 |
| 대기 줄 중복 막기 | 알림 표에 `restock_request_id` 칸 + 고유 색인(신청 1건당 채널별 1번) |
| 1분 작업 켜기 조건 | 「입금 기한 또는 주문 알림」 → 「…또는 재입고 알림」 |
| 정리 | 대기가 오래된 신청은 만료(기간은 결정 항목), 보냄·취소·만료 신청의 번호는 30일 뒤 지움 |

## 7. 결정 항목 (주인님)
1. 누가 신청하나 — 회원만 / 비회원도 핸드폰으로
2. 알림 채널 — 문자만 / 문자 + 메일
3. 대기 기간 — 신청 뒤 몇 일이 지나면 만료할지
4. 보내는 방식 — 재입고 즉시 자동 / 운영자가 「알림 보내기」를 눌러야 발송

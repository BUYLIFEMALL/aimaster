# 개발 플랜 — 자동 배송 완료·구매 확정 (D12, 2026-11-06)

주인님 선택(2026-11-06): 로드맵 2차 후보 중 「자동 배송완료·구매확정」.

## 문제
- 지금은 운영자가 주문마다 「배송 완료」, 손님이나 운영자가 「구매 확정」을 직접 눌러야 한다. 손님은 확정을 잘 누르지 않아 주문이 「배송 완료」에 오래 머문다.
- 자동화 최상위 원칙(처음 설정만 하면 스스로 동작)에 맞게, 날짜가 지나면 자동으로 넘긴다.

## 동작
| 단계 | 조건 | 결과 |
|---|---|---|
| 자동 배송 완료 | 「배송 중」이 된 지 N일 지남(N = 운영자 설정, 비우면 끔) | 「배송 완료」, 기록 「자동 · 발송 N일 지나 자동 배송 완료」 |
| 자동 구매 확정 | 「배송 완료」가 된 지 M일 지남(M = 운영자 설정, 비우면 끔) | 「구매 확정」, 기록 「자동 · 배송 완료 M일 지나 자동 구매 확정」 |

- 기준 시각은 그 상태로 바뀐 마지막 처리 기록 시각이다. 반품을 거절해 「배송 완료」로 돌아오면 그때부터 다시 센다.
- 반품 요청·취소 요청 중인 주문은 상태가 달라 건드리지 않는다.
- 돈이 오가지 않는 단계라 카드·외상 처리와 무관하다(감시 트리거도 통과).
- 한 번에 몰당 200건까지, 잠긴 주문은 건너뛴다(`skip locked`). 전체 일시정지가 켜져 있으면 하지 않는다.

## 구현
1. DB `0032_auto_deliver_confirm.sql`(추가만): 일정 표에 `auto_deliver_days`·`auto_confirm_days`(1~60, 비우면 끔)·마지막/누적 처리 수 칸. 함수 `mall_builder_auto_progress_save`(운영자), `mall_builder_auto_progress(토큰 해시)`(실행 주소용).
2. 실행 주소 `/api/cron/deposit-expire`: 자동 취소 다음에 자동 진행을 부른다(주소 이름은 그대로 — 이미 등록된 cron-job.org 작업이 이 주소를 씀).
3. `job-sync.ts`: 자동 진행이 켜져 있어도 작업을 켠다.
4. 운영자 설정 화면 「자동 배송 완료·구매 확정」 칸(일수 두 개 + 상태 줄). ~~손님 주문 상세(배송 완료)에 「M일 뒤 자동 구매 확정」 안내~~ — 구현 중 제외: 몰 일정 표는 운영자만 읽을 수 있어(RLS) 안내 하나에 새 공개 통로를 만들게 됨. 자동 처리 결과는 손님 진행 기록에 「자동 구매 확정」으로 남는다.
5. 시험: DB 시험(되돌림 방식), 자동 시험, 빌드, 실제 시험(시험 주문을 배송 중으로 → 기록 시각을 당겨 다음 작업 실행 때 자동 진행 확인 → 구매 확정까지).

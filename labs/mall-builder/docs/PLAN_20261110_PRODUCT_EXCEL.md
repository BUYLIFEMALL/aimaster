  - B2B 핵심 순서: 1. 상품 엑셀 대량 등록·수정 → 2. 거래처별 특가 → 3. 빠른 주문(품번·엑셀)·재주문 → 4. 거래명세서·외상 원장 출력 → 5. AI 견적 보조 → 그 뒤 블록 추가 등 원래 순서

## 1. 문제
도매몰은 상품이 수백~수천 개다. 지금은 상품을 화면에서 하나씩 등록·수정해야 하고(옵션·등급가·구간 할인도 상품마다), 가격 일괄 인상이나 재고 일괄 갱신도 불가능하다. 프로셀 「상품 대량등록」에 해당.

## 2. 범위(안)
운영자 「상품」 메뉴에 **「엑셀로 등록·수정」** 화면 추가.

1. **양식 내려받기**: 빈 양식(설명 행·예시 포함) / **지금 상품 전체 내려받기**(그대로 고쳐서 다시 올리면 수정)
2. **올리기 → 미리보기**: 서버가 파일을 읽어 행마다 「새로 등록 / 수정 / 바뀐 것 없음 / 오류(이유)」 표시. 저장 전에는 DB를 바꾸지 않는다
3. **오류 0건일 때만 「적용」 버튼** → 저장 → 결과(등록 n·수정 n·실패 n과 이유)
4. 시트 구성(엑셀 파일 하나, 시트 3개)

| 시트 | 한 행 = | 칸 |
|---|---|---|
| 상품 | 상품 1개 | 품번(필수)·상품명·요약·판매가·정가·원가·과세/면세·상태(판매 중/준비 중/품절/숨김)·재고 방식·재고·카테고리 경로(`식품>과일>사과`, 여러 개는 `;`)·배송비 정책 이름·공개 범위(전체/사업자 전용)·가격 공개(공개/로그인/사업자)·최소 수량·주문 단위·최대 수량·등급가 칸(몰 등급마다 한 칸: 금액 또는 `10%`)·사진 주소(https, `;`로 최대 5개)·상세 설명 |
| 옵션 | 옵션 조합 1개 | 상품 품번·옵션1 이름·값·옵션2 이름·값·옵션3 이름·값·추가금·재고·조합 품번·사용 여부 |
| 구간 할인 | 구간 1개 | 상품 품번·시작 수량·방식(할인율/개당 할인/개당 가격)·값 |

- 한 번에 최대 **1,000행(상품 시트 기준)**, 파일 5MB
- 검사는 기존 화면 저장과 **같은 함수**(`src/lib/products.ts`·`options.ts`·수량/구간 검사)를 그대로 쓴다 — 엑셀이라고 규칙이 달라지지 않게
- 권한: 직원 권한 「상품·재고·공동구매」가 있는 사람만(D22). 서버에서 다시 확인
- 1차에서 하지 않음: 사진 파일 자체를 엑셀에 넣기(주소만), 상품 삭제(숨김으로 대신 — 기존 원칙), 공동구매 설정, 다른 쇼핑몰(프로셀·카페24) 양식 자동 변환

## 3. 결정 항목 (주인님)
| 번호 | 결정할 것 | 추천안 | 다른 안 |
|---|---|---|---|
| 1 | 상품을 알아보는 기준 | **상품에 「품번」 칸 추가**(몰 안에서 겹치지 않음, 선택 칸 — 기존 상품은 비어 있다가 내려받을 때 자동 부여 `P00001`). 다음 작업인 빠른 주문도 이 품번을 쓴다 | 내부 번호(uuid)를 숨은 칸으로 — 사람이 새 상품을 만들 때 쓸 수 없음 |
| 2 | 엑셀 읽기 도구 | **`exceljs`(MIT, npm)** — 서버에서만 읽고 써서 화면 용량에 영향 없음 | SheetJS(npm판 0.18.5는 알려진 보안 문제·최신판은 npm 밖 배포) / CSV만(엑셀에서 한글 깨짐 잦음) |
| 3 | 오류가 섞인 파일 | **오류가 하나라도 있으면 적용 버튼을 막음**(미리보기에서 고쳐 다시 올림) | 정상 행만 저장 |
| 4 | 엑셀에서 옵션을 바꿨을 때 | **그 상품의 옵션 시트 행이 있으면 옵션 전체를 엑셀 내용으로 교체**(조합 품번이 같으면 기존 조합 유지 — 지난 주문 연결 보존), 옵션 시트에 그 상품 행이 없으면 옵션은 건드리지 않음 | 옵션은 엑셀로 등록만, 수정은 화면에서 |
| 5 | 없는 카테고리 경로 | **오류로 표시**(오타로 카테고리가 마구 생기는 것을 막음) | 자동으로 만들기 |

## 4. 구현 순서
1. DB `0044_product_code.sql`: `mall_builder_products.product_code`(text, null 허용) + 몰 안 고유 색인(부분, null 제외) + 형식 검사(영문·숫자·`-_` 1~40자). **추가만**(교훈 문서 원칙)
2. 공용 코드 `src/lib/productExcel.ts`: 행 → 상품 입력값 변환·검사(기존 검사 함수 재사용), 수정 비교(바뀐 칸 목록) — 엑셀 도구와 분리해 `node --test`로 시험
3. 서버 동작: 양식 만들기·내려받기, 올리기 → 미리보기(DB 안 바꿈), 적용(행마다 저장, 서버에서 다시 검사)
4. 화면: 「상품」 목록 위 「엑셀로 등록·수정」 버튼 → 내려받기 2개·올리기·미리보기 표(오류 행 빨강)·적용·결과
5. 상품 등록·수정 화면에 품번 칸, 목록에 품번 표시
6. 문서: README·IMPROVEMENTS·로드맵·역할 파일·교훈

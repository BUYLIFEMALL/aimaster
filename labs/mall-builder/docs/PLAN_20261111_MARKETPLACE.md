# 개발 플랜 — 3차 5번 입점형 마켓플레이스 (V-F, 2026-11-11)

> 근거: `docs/mall/ROADMAP_AND_VARIANTS.md` V-F(공급사 입점·상품 승인·공급가·주문 분배·정산), 프로셀 분석 「공급방식: 자체상품/입점상품·상품 공급자」.

## 1. 무엇을 만드나

한 몰 안에서 **운영자 상품 + 여러 공급사 상품**을 같이 판다. 손님 화면은 지금과 같고(장바구니·주문·결제 한 번), 뒤에서 주문 품목이 공급사별로 나뉘어 각 공급사가 자기 몫만 발송하고, 구매 확정 뒤 공급사에게 정산한다.

## 2. 단계 나누기 (큰 공사라 4단계)

| 단계 | 내용 | 재사용 |
|---|---|---|
| D34 공급사 계정 | 공급사 표(이름·사업자·연락처·상태), 운영자가 이메일로 초대 → 공급사가 로그인해 수락, 운영자 「공급사」 메뉴(목록·일시정지) | D29 직원 초대(`staff_invites`) 흐름 |
| D35 공급사 상품·승인 | 공급사 전용 화면 `/s/<몰>/supplier`(내 상품 등록·수정), 상품에 공급사·공급가·승인 상태, 운영자 승인/반려(사유), 손님에게는 승인된 상품만, 공급사가 고치면 다시 승인 대기 | 기존 상품 편집 컴포넌트 |
| D36 주문 분배·발송 | 주문할 때 품목에 공급사·공급가를 박아 둠, 공급사 화면 「내 주문」(자기 품목만), 송장 입력·발송 처리(품목 단위), 운영자 주문 상세에 공급사별 표시 | 부분 취소·품목 단위 처리 |
| D37 정산 | 구매 확정 품목 → 공급사 장부에 공급가 × 수량 적립, 확정 뒤 반품·취소는 차감, 월 정산서, 운영자가 직접 송금 뒤 「지급 완료」 | D33 리셀러 장부·출금 처리 |

단계마다 기존 방식대로 구현 → DB 되돌림 시험 → ego 화면 시험(390px 포함) → 커밋·푸시 → 요청함 보고, 배포는 미배포로 모은다.

## 3. 지킬 것

- 공급사는 **자기 상품·자기 품목만** 본다. 다른 공급사 상품, 주문 전체 금액, 손님 등급가·다른 품목은 보이지 않는다(보안 규칙 + DB 함수).
- 공급사가 발송하려면 그 품목 주문의 **받는 사람·주소·연락처**는 보여야 한다 — 발송 대기·발송 중인 동안만 보이고, 구매 확정 30일 뒤에는 가린다(개인정보 최소화).
- 쓰기는 모두 DB 함수(security definer) + 보호 트리거, 기존 패턴(0045b~0052) 그대로.
- 판매가·등급가·쿠폰·포인트는 지금처럼 몰(운영자)이 정한다. 할인으로 생기는 차액은 몰 부담, 공급사는 공급가를 받는다.

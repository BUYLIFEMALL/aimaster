# 입금 기한 자동 취소 — 개발 플랜 (2026-11-04)

- 대상: Lab `labs/mall-builder` (DB `rjjtjakljjxsgjelqgek`), 운영 DB·운영 사이트는 건드리지 않음
- 결정: 예약 실행 방식 = **몰 운영자 본인 cron-job.org** (2026-11-04 주인님 채팅 선택, 기준 `docs/SCHEDULER_POLICY.md`)
- 상태: 플랜 승인 대기

## 1. 문제
무통장 주문이 「입금 대기」로 끝없이 남는다. 재고도 그 주문 몫이 계속 빠져 있다.

## 2. 범위
1. 몰 설정에 「입금 기한(시간)」 칸 추가 — 비우면 자동 취소 안 함(기본 끔), 1~168시간
2. 주문 만들 때 `pay_deadline_at` 기록(DB 함수에서 계산, 손님이 바꿀 수 없음) — 주문 완료·마이페이지에 기한 표시
3. 몰 설정에 cron-job.org 키 한 줄(몰 운영자 본인 키, 몰별 저장, 화면엔 「등록됨」만)
4. 몰 전용 실행 토큰(무작위 32바이트, DB엔 SHA-256 해시만) + 몰 전용 실행 주소 `/api/cron/deposit-expire` — 토큰으로 몰을 찾아 **그 몰 주문만** 처리, 틀리면 401
5. 자동 켜기·끄기: 기한이 있는 입금 대기 주문이 생기면 운영자 cron-job.org에 1분 작업 생성·켜기(이미 켜져 있으면 호출 안 함), 처리 후 남은 대기 주문이 없으면 끄기
6. 취소 처리: 기한 지난 입금 대기 주문만 「취소」, 기존 취소 흐름(F11)으로 재고 되돌림, 처리 기록(`order_events`)에 「입금 기한 초과 자동 취소」
7. 운영자 주문 화면에 자동 작업 상태(켜짐·꺼짐·마지막 실행)와 일시정지·재개

## 3. 구현 순서와 확인
| 순서 | 할 일 | 확인 방법 |
|---|---|---|
| 1 | DB 추가(칸·함수, 추가만) | 몰 분리 보안 시험에 새 칸 포함 |
| 2 | 토큰·실행 주소 | 시험: 토큰 없음/틀림 401, 다른 몰 주문 안 건드림 |
| 3 | 취소 로직 | 시험: 기한 전 유지, 기한 후 취소+재고 복귀, 이미 입금된 주문 유지, 두 번 돌아도 한 번만 취소 |
| 4 | cron-job.org 켜기·끄기 | 시험(가짜 응답): 키 없음 거부, 켜기 1회, 대기 0이면 끄기, 실패 시 상태 되돌림 |
| 5 | 화면 | ego에서 설정·주문 화면 확인 |

공용 기준 코드 `member-scheduler`(기준 `cardnews-studio/src/lib/instagram/memberScheduler.ts`)의 호출·켜기/끄기 방식을 따라 쓴다(Lab은 독립 프로그램이라 사본으로 가져와 몰 단위로 맞춤).

## 4. 비용
| 항목 | 비용 |
|---|---|
| 개발·자동 시험 | 없음(내 PC) |
| Lab 배포 빌드 | 1회 — 배포 직전에 따로 승인받음 |
| 실제 cron-job.org 연결 시험 | 운영자(주인님) 본인 무료 계정 키 필요, 비용 없음 |
| 유료 AI 호출 | 없음 |

## 5. 남는 일

# 쿠팡 Open API로 만들 수 있는 자동화 기능 — 다각도 검토 플랜 (2026-10-30)

> 요청: 주인님 「이 api를 통해 어떤 쿠팡 자동화 기능을 구현할수 있을지 다각도로 검토해서 플랜을 짜줘」(2026-10-30).
> 기준 자료: **쿠팡 공식 API 사이트 https://developers.coupang.com/ko/api?market=KR** (12개 묶음 103개, 2026-10-30 목록 다시 읽음). 기능을 만들 때마다 그 API의 상세 페이지를 먼저 읽고 구현한다(주인님 지시, 같은 날).
> 작성: `claude-win-sdp`(역할 `ecommerce-image`). 이 문서는 **기획안**이다 — 적힌 기능을 만들기로 확정한 것이 아니며, 순서·범위는 주인님 결정 뒤 백로그(`IMPROVEMENT_BACKLOG.md`)로 옮긴다.

## 0. 먼저 알아 둘 전제

| 전제 | 내용 | 영향 |
|---|---|---|
| 회원 본인 키 | 모든 호출은 회원 본인 WING 키(최상위 규칙) | 회원마다 자기 쿠팡 계정만 다룸 |
| 고정 IP 프록시 | 쿠팡은 허용 IP만 받음 → 운영 호출은 모두 Fixie(운영자 비용) | 자동·반복 조회는 호출 수를 아껴야 함 → 조회 간격 제한(`lib/readGap.ts`)·버튼 누를 때만 조회가 기본 |
| 쓰기 = 실제 판매 변경 | 가격·재고·주문 상태·송장·취소는 실제 고객·판매자 점수에 영향 | 모든 쓰기는 확인 단계 + 재시도 없음 + 결과 기록. 자동 실행(사람 확인 없이)은 별도 승인 |
| API에 없는 것 | 공식 목록에 **리뷰·광고·경쟁사 가격·검색 순위·판매자 점수 조회 API가 없다** | 그런 기능은 이 프로그램에서 하지 않는다(화면 긁기는 봇 탐지·약관 위험) |
| 개인정보 | 주문자·수취인·반품 신청인 정보 | 화면에만 보이고 저장하지 않음(안심번호만). 저장이 필요하면 회원별 격리 + 30일 |

## 2. 다각도 검토 — 만들 수 있는 자동화 기능

### 2-1. 관점 A: 판매자의 하루 업무 흐름 (시간 절감)

| # | 기능 | 하는 일 | 쓰는 API | 효과 | 난이도 |
|---|---|---|---|---|---|
| A1 | **오늘 할 일 한 화면** | 결제완료(발주 확인할 것)·상품준비중(송장 넣을 것)·출고중지요청(**발송 전 꼭 확인**)·반품접수·교환요청·미답변 문의 개수를 한 번에 | 발주서 목록, 반품·취소 요청 목록(`status=RU`·`UC`), 교환 요청 목록, 상품 문의·고객센터 문의 | WING 여러 메뉴를 돌던 아침 업무를 한 번에 | 중 |
| A2 | **발주 → 송장 한 번에** | 결제완료 주문 골라 상품준비중 → 송장 엑셀 붙여넣기 → 등록 (지금 따로 있는 단계를 한 흐름으로) | 상품준비중 처리, 송장 업로드 | 클릭 수 절반 | 하 (이미 부품 있음) |
| A3 | **송장 넣기 전 안전 점검** | 송장 등록 직전에 그 주문에 출고중지요청이 들어왔는지 자동 확인, 있으면 막고 안내 | 반품·취소 요청 목록(`status=RU`, 주문번호) | **출고중지 건을 보내 왕복 배송비를 무는 사고 방지**(명세: 판매자 귀책) | 하 |
| A4 | **처리 뒤 배송지 재확인** | 상품준비중 처리 직후 발주서 단건 조회로 배송지가 바뀌었는지 비교해 바뀐 주문만 표시 | 발주서 단건 조회(shipmentBoxId) | 명세 권고 사항 자동화 — 잘못된 주소 발송 방지 | 하 |
| A5 | **배송 상태 추적** | 배송지시 이후 주문의 배송 상태 변경 이력, 오래 안 움직이는 주문 표시 | 배송상태 변경 히스토리 | 송장 오입력·미집하 조기 발견 | 하 |
| A6 | **장기 미배송 배송완료 처리** | 약속일이 한참 지난 주문을 골라 배송완료로 처리 | 장기미배송 배송완료 처리 | 정산 지연 해소 | 하(조건 확인 필요) |

### 2-2. 관점 B: 실수·불이익 방지 (판매자 점수·비용)

| # | 기능 | 하는 일 | 쓰는 API | 효과 |
|---|---|---|---|---|
| B1 | **품절 예방 재고 점검** | 내 상품 옵션 재고를 훑어 0개·N개 이하 옵션 목록, 한 번에 재고 채우기 | 옵션 재고·가격·상태, 수량 변경 | 품절로 인한 판매자 취소(점수 하락, 명세 경고) 예방 |
| B2 | **가격 실수 방지** | 가격 변경 전 −50%~+100% 규칙·10원 단위·할인 기준가 대비 확인(이미 일부 구현) | 가격 변경, 할인율 기준가격 변경 | 0 하나 빠진 가격 등록 사고 방지 |
| B3 | **반려 상품 알림** | 등록 기록 중 승인반려를 모아 반려 사유와 함께 보여 주고 고칠 곳 안내 | 상품 조회, 상태변경이력 | 반려 방치 방지 |
| B4 | **이미출고/출고중지 처리 기한 관리** | 출고중지요청이 들어온 뒤 미처리 건을 남은 시간 순으로 | 반품·취소 요청 목록 | 자동 처리 전에 판매자가 결정 |
| B5 | **송장 형식 사전 검사** | 택배사별 송장 형식(CJ 숫자만 등) 미리 검사(이미 구현) | — | 400 오류·재입력 감소 |

### 2-3. 관점 C: 매출·운영 효율

| # | 기능 | 하는 일 | 쓰는 API | 메모 |
|---|---|---|---|---|
| C1 | **일괄 가격 조정** | 고른 상품 옵션 가격을 %·금액으로 한 번에(미리보기 → 확인 → 적용) | 가격 변경 | 대량 쓰기 → 건수 제한·확인 필수 |
| C2 | **쿠팡 자동가격조정 설정** | 옵션별 최저가(`apMinSalePrice`)·켜기(`apActive`) 설정 | 가격 변경(쿼리) | 쿠팡 자체 기능을 켜는 것뿐(우리 쪽 경쟁가 감시 아님) |
| C3 | **즉시할인 쿠폰** | 계약·예산 확인 → 쿠폰 만들기 → 옵션 추가 → 요청 상태 확인 → 만료 | 프로모션 공통(계약·예산), 즉시할인 쿠폰 생성·아이템 추가·상태·만료 | 비용(할인 예산)이 드는 기능 → 회원 확인 필수 |
| C4 | **다운로드 쿠폰** | 다운로드 쿠폰 생성·아이템·만료 | 다운로드 쿠폰 API | C3과 같은 화면 |
| C5 | **매출·정산 리포트** | 기간별 매출 내역·지급 내역 표·엑셀 | 매출내역 조회, 지급내역 조회 | 읽기만. `shop-order-report`와 겹치는 부분 정리 필요 |
| C6 | **옵션 자동생성 끄기/켜기** | 쿠팡이 자동으로 만드는 옵션 관리 | 자동생성옵션 opt-in/out | 원치 않는 옵션 생성 차단 |
| C7 | **승인 불필요 상품 수정** | 이미지·상세 등 승인 없이 바꿀 수 있는 항목 수정 | 상품 수정(승인불필요) | 상품 개선 반복을 빠르게 |

### 2-4. 관점 D: 고객 응대 (AI 활용)

| # | 기능 | 하는 일 | 쓰는 API | 메모 |
|---|---|---|---|---|
| D1 | **문의 모아 보기** | 상품 문의 + 고객센터 이관 문의를 한 목록, 미답변 먼저 | 상품별 고객문의 조회, 고객센터 문의 조회·단건 | 읽기 |
| D2 | **AI 답변 초안** | 회원 본인 Claude 키로 문의 + 주문·배송 상태를 보고 답변 초안 → 회원이 고친 뒤 등록 | 문의 답변, 고객센터 문의 답변·확인 | 기본 AI = Claude(지침). 자동 등록은 하지 않음 |
| D3 | **반품 처리 도우미** | 반품 접수 → 입고 확인 → 승인, 회수 송장 등록 | 반품요청 단건·입고 확인·승인, 회수 송장 등록, 반품 철회 이력 | 승인은 환불이 나가는 쓰기 → 확인 필수 |
| D4 | **교환 처리** | 교환 요청 목록 → 입고 확인 → 교환상품 송장 또는 거부 | 교환 요청 목록·입고 확인·송장·거부 | |

### 2-6. 관점 F: 자동 실행(사람이 안 눌러도)

| # | 기능 | 방식 | 판단 |
|---|---|---|---|
| F1 | 아침 「오늘 할 일」 요약 알림 | 회원 본인 cron-job.org(예약 지침 `docs/SCHEDULER_POLICY.md`) → 읽기만 → 알림 | **가능**. 읽기만이라 위험 낮음. Fixie 호출 수 계산 필요 |
| F2 | 출고중지요청 즉시 알림 | 주기 조회(예: 30분) → 새 요청 있으면 알림 | 가능하지만 호출 수가 많아짐 → 회원 선택·간격 하한 |
| F3 | 재고 0 자동 판매중지 / 자동 재입고 | 주기 조회 → 쓰기 | **보류**. 사람 확인 없는 쓰기 — 주인님 별도 승인 전에는 만들지 않음 |
| F4 | 자동 발주 확인(결제완료 → 상품준비중) | 주기 실행 | **보류**. 고객이 취소할 여지를 줄이고 배송 의무가 생김 — 회원이 명시적으로 켤 때만 검토 |

### 2-7. 하지 않을 것

- 리뷰·광고·경쟁사 가격·검색 순위 기능(공식 API 없음, 화면 긁기 금지).
- 사람 확인 없는 대량 쓰기(가격 일괄 자동 변경, 자동 취소, 자동 반품 승인).
- 대만 전용 API(직배송 택배 2종), 도서 캐시백(도서 판매자 전용 — 요청 있을 때만).
- 로켓그로스는 회원이 로켓그로스 계약이 있을 때만 의미 → 수요 확인 뒤.

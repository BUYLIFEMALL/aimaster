# B1 품절 예방 재고 점검 플랜 (2026-10-31, 승인 대기)

## 문제
옵션 재고가 0이 되면 주문을 못 받거나 품절로 판매자 취소가 생겨 판매자 점수가 떨어질 수 있다. 지금은 상품을 하나씩 열어야 옵션 재고를 볼 수 있다.

## 명세 확인(2026-10-31, 공식 사이트)
- 상품 목록 `GET seller-products`: 한 쪽 최대 100건, 옵션·재고 정보 없음.
- 옵션 재고 `GET vendor-items/{id}/inventories`: **옵션 1개당 1회 호출**, 여러 옵션을 한 번에 읽는 방법은 위 문서에서 찾지 못함. 응답은 `amountInStock`·`salePrice`·`onSale`.
- 재고 변경 `PUT vendor-items/{id}/quantities/{n}`: 승인완료로 옵션ID가 있어야 가능.
- 위 페이지에 초당 호출 제한 값은 없음. `client.ts`의 429 대응을 그대로 쓴다.

## 핵심 제약: 호출 수
쿠팡 호출은 모두 Fixie를 거치고 요금제는 월 2,500회(추정, 토스 연동과 공유). 상품 50개·옵션 3개면 1회 전체 점검에 약 200회가 든다(목록 1 + 상품 50 + 옵션 150). 그래서 자동 점검은 하지 않는다.

## 범위
1. 새 화면 `/stock` 「품절 예방」과 좌측 메뉴, 매뉴얼 설명.
2. 버튼을 눌렀을 때만 승인완료·부분승인완료 상품을 **한 번에 20개씩** 점검(옵션 최대 60개, 1회 최대 약 81회). 「다음 20개」로 이어 간다. 회원별 조회 간격 제한은 `lib/readGap.ts`를 쓴다. 이번 호출 수를 화면에 표시.
3. 기준 수량 입력(기본 5개, 브라우저에만 저장, DB 변경 없음). 품절(0개)·부족(기준 이하)·판매 중지를 나눠 표시.
4. 재고 채우기: 고른 옵션에 수량을 넣고 2단 확인 뒤 **순서대로 1건씩** 기존 `updateQuantityAction`으로 전송(직전 값 재확인, 재시도 없음). 결과는 옵션별로 표시.

## 하지 않는 것
자동·예약 점검, 새 DB 표, 재고 자동 채우기, 판매 중지 옵션 자동 재개.

## 구현 순서와 검수
1. `lib/coupang/stock.ts` 판정 함수와 시험 → `src/lib/actions/stock.ts` → 화면.
2. 시험·`tsc`·로컬 빌드.
3. 운영 배포 뒤 크롬에서 읽기 점검 실제 확인.
4. 재고 쓰기 실제 시험은 요청함 `3bb801f0` 승인 범위로 따로 1건만.

## 승인 후 실행 순서

1. 같은 프로젝트 ref를 다시 확인하고 사전 점검 SQL 실행. 기존 운영키·회원권한·구독·프로그램 공개상태는 바꾸지 않습니다.
2. 승인된 합성 SQL1회 적용. 오류 시 전체 트랜잭션 취소. 성공 후 읽기 검수8조건 모두 true 확인. 운영에 가상회원/자료를 넣지 않습니다.
3. 실제 릴리스 시에만 v1.02와 package/manifest1.2.0·ZIP을 일괄 갱신, 기존 미배포 목록 전체 확인. 타입/단위/필요한 로컬 빌드·ZIP 사전 검사.
4. Vercel 팀 buylife 전체 BUILDING/QUEUED/INITIALIZING 없음과 Basic/동시추가구매OFF 설정 재확인. **프로덕션 배포 빌드1회만** 실행, 실패 시 승인 범위를 넘겨 자동 재배포하지 않습니다. 푸시는 별도 자동 빌드를 만들므로 배포와 섞어 실행하지 않습니다.
5. Ready 후 운영 HTTP·신규 API 인증 가드·명칭/버전/ZIP/DB·정리RPC 가용성 대조. 기존 설치 확장 폴더는 백업 후 같은 폴더를 갱신하고 기존 Edge에서 다시 로드합니다. 토큰 저장소를 지우거나 불필요하게 재연결하지 않습니다.
6. 새 UI의 실제 회원/계정 범위·연결 표시와 읽기 게이트 차단을 확인합니다. **허용 근거 미확인이면 여기서 네이버 자동 추출을 실행하지 않습니다.** 이전 요청 `3e257d73-f19e-407b-b625-9cb757deb332`를 유지하며 사용자 로그인 성공을 정책 허용으로 간주하지 않습니다.

## 실패 시 복구

- SQL 실패: 단일 트랜잭션이 새7표/함수2개를 함께 취소합니다. 오류·정확한 실패 단계를 확인한 뒤 새로운 승인 범위에서 재검토합니다.
- SQL 성공·배포 실패: 기존 운영 배포를 유지하고 새 표/함수는 남깁니다. 자동 소통/읽기OFF 유지. 자료 삭제·DROP·권한/회원키 복원을 위해 광범위 SQL을 실행하지 않습니다.
- 배포 후 회귀: 운영 별칭을 이전 Ready 배포로 되돌리는 별도 승인 범위를 확인합니다. 새스키마는 기존 운영이 사용하지 않으므로 삭제하지 않습니다. 이미 저장된 회원자료를 되돌림 대상으로 삼지 않습니다. 버전 표시는 실제 서비스 버전에 맞춰 대조합니다.

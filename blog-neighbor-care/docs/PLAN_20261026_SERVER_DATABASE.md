# 1단계 — 서버·DB 구현 플랜

2026-10-26 · `codex-win-20261025-blog`. 주인님 「순서대로 하나씩 진행해」에 따라 남은 목록1번만 구현합니다. 대상① AIMaster 운영(ref `esgxyikcnnvmlhygjkth`), 신규 독립 기본 프로그램 `blog-neighbor-care`. [상세 계약](../../docs/analysis-naver-blog-neighbor-20261024/SPEC_20261026_BLOG_NEIGHBOR_CARE_0A.md)·[모의32개](../../docs/analysis-naver-blog-neighbor-20261024/SIMULATION_VERIFICATION_20261026.md)를 운영 계층 검수로 이관합니다.

1. 기존 공용 인증·프로그램 권한·Supabase/쿠키 부품을 사본 규칙대로 가져와 서버 API에 적용합니다. 회원이 보낸 user_id를 소유자로 사용하지 않습니다.
2. 회원 설정/작업/일일원장·이웃슬롯과 서비스역할 전용 RPC를 작성합니다. 조회는 회원별RLS, 카운터/상태 직접 변경과 일반회원 RPC 실행은 차단합니다. 한 회원 설정 행을 잠그는 순서를 통일해 여러기기·계정·글의 동시 실행에도 상한/이웃일일1개를 적용합니다.
3. 로컬 격리 PostgreSQL17에서 동일 SQL의 제약/RLS·서버전용권한·복수 세션 동시성·KST/선점/성공불명을 검사합니다. 모의 메모리Mutex 결과와 실제SQL검사를 구분합니다.
4. API 요청의 인증/권한/동일출처·입력 검증·소유자 결합·RPC 오류 처리를 검사합니다. 실제 네이버 쓰기 기능은 포함하지 않으며 라이브 실행 게이트는 기본 차단합니다.
5. 운영 반영 SQL·검수 근거·남은 절차를 준비합니다. 원본 인수인계의 「운영 DB 쓰기는 주인님 승인 뒤…Run은 주인님」 절차를 유지합니다. 이번 개발 지시를 사이트 로그인/키 교체·유료 배포 실행까지 확장하지 않습니다.

비용: 기존 Docker 이미지 `postgres:17-alpine`로 네트워크/호스트포트/운영연결 없는 가상회원 전용 컨테이너. 무료 패키지설치·타입/로컬검수만, 유료AI/네이버호출/Vercel빌드·배포0. 현재 서버소스 작성과 로컬검수를 진행하며, 운영스키마/프로그램 등록/권한·환경변수는 아직 변경하지 않습니다.

UI는 디자인 담당의4대 화면3시안·승인 후 별도 진행합니다. 주인님이1번서버/DB를 먼저 지정하신 범위 안에서 백엔드만 작성합니다. 다른 세션5번 워크스페이스·플래너/이미지원고복귀 연계와 기존Edge/SEO 대기는 보존합니다.

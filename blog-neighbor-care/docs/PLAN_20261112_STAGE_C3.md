# 단계 C-3 플랜 — 받은 신청 수락·답방을 자동 운영에 넣기

이전: [C-2 플랜](PLAN_20261105_STAGE_C2.md) — 「답방·받은 신청 수락 자동은 다음 묶음」. 운영 v1.19(2026-11-12, 감시 AI 켜짐).

## 1. 지금 상태 (코드 확인 결과)
| 기능 | 있는 것 | 없는 것 |
|---|---|---|
| 공감·댓글 자동 | v1.18 자동 운영(`bnc_autopilot_prepare`가 새 글마다 공감 작업, 감시 AI 초안 중 통과한 댓글 작업) | — |
| 받은 신청 수락 | 확장 `accept-dom.mjs`(신청 화면 읽기·수락 버튼)·`accept-bridge.mjs`·`accept-schedule.mjs`(**지금 열려 있는 신청 화면에서만** 반복), 서버 `acceptApi.ts`·`/api/neighbors/requests/extension` | 자동 운영 연결(할 일 칸이 `like`·`comment`만 허용), 신청 화면을 스스로 여는 동작, **실제 네이버 화면 성공 기록 0건** |
| 답방(내 글에 댓글·공감한 사람 글 찾아가기) | 받은 댓글 읽기 `engagementIntake.ts`(돌아갈 글 번호 포함), 작업 종류 `reply`(대댓글) | 자동 운영 연결, 「답방 공감」 작업 만들기, **실제 성공 기록 0건** |

→ 둘 다 **실물 확인이 먼저**입니다. 확인 안 된 화면 선택자로 자동 운영을 켜지 않습니다(기존 원칙).

## 2. 순서
1. **실물 확인(맥미니, 비용 없음)** — v1.19 확장으로 ① 네이버 「받은 이웃 신청」 화면에서 현재 화면 수락 1건 ② 내 글 댓글 1건 읽기(답방 대상 글 번호가 잡히는지). 실패하면 화면 선택자부터 고칩니다(코드 수정 → 미배포 대기).
2. **수락 자동**(DB 마이그레이션 1개 + 웹·확장):
   - 자동 운영 할 일 칸에 `accept` 추가(기본 꺼짐, 회원이 켬). 하루 상한 기본 10(최대 30).
   - 확장 10분 알람이 시간대 안이면 하루 1~2번, **지금 창에 새 탭**으로 신청 화면을 열어 기존 `accept-schedule` 흐름 실행 → 끝나면 탭 닫기. 로그인 풀림·보안문자면 멈추고 알림.
   - 요약 카드 「오늘 수락 n」은 이미 있는 `request` 집계 사용.
3. **답방 공감 자동**(같은 마이그레이션):
   - 할 일 칸에 `visit` 추가(기본 꺼짐). 내 최근 글에 댓글 단 이웃의 최신 글에 **공감만**(AI 없음), 같은 사람 하루 1번, 공감 상한 안에서.
   - 대댓글(내 글 댓글에 답글)은 감시 AI 초안이 있을 때만 — 이번 묶음에서는 **넣지 않고** 다음으로(결정 3).
4. 시험·배포: 단위·DB 시험 → 빌드 1회 → 맥미니 실물(수락 1건·답방 공감 1건 자동).

## 3. 결정 항목
| 번호 | 결정 | 추천 |
|---|---|---|
| 1 | 수락 범위 | ✅ **확정** 모든 받은 신청 수락(단 글이 0개이거나 이름이 비어 있는 계정은 건너뜀) — 지금 확장은 신청 번호·블로그 아이디만 읽음 → 글 수는 회원 PC RSS(`feed-watch` 방식)로 0개 확인, 이름은 신청 목록 이름 칸 읽기 추가(위치는 맥미니 실물로 확인) |
| 2 | 수락 하루 상한 기본값 | ✅ **확정** 10(회원이 30까지 조정) |
| 3 | 답방 범위 | ✅ **확정** 공감만(AI 없음). 대댓글 자동은 다음 묶음 |
| 4 | 두 기능 기본값 | ✅ **확정** 꺼짐 — 회원이 시작하기에서 켬(지금 쓰는 회원 설정이 바뀌지 않음) |
| 5 | 순서 | ✅ **확정** 실물 확인 먼저(맥미니) → 통과하면 구현 |

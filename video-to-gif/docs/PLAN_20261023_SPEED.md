# 플랜 2026-10-22~23 — v1.15 GIF 변환 속도 개선 (Claude Code 맥미니, 주인님 승인 「진행해」)

## 조사
- 엔진: `@ffmpeg/core` 0.12.6 단일 스레드. 한 단계마다 영상을 두 번 해석(palettegen → paletteuse).
- 사다리: 8MiB를 넘으면 크기 94%→…→45%로 한 칸씩 처음부터 다시(최대 8단계 = 최대 16번 해석).

## 결정 — 길 A(지금 엔진 그대로 낭비 줄이기)
1. 한 번에 만들기: `fps,scale,split[a][b];[a]palettegen[p];[b][p]paletteuse` — 같은 필터·같은 화질, 해석 1번.
   색상표가 나올 때까지 프레임(RGBA)을 쌓으므로 예상 메모리(가로×세로×4×프레임 수) 512MB 이하일 때만(`canSinglePass`), 넘거나 실패하면 예전 두 번 방식(실패 시 엔진 새로 불러오기).
2. 사다리 건너뛰기: 결과가 상한을 넘으면 가로 비율 ≈ √(0.9×상한/결과)로 어림해 그 이하인 첫 단계로(`nextCandidateIndex`, 최소 한 칸).
3. 진행률 정수 표시(「25.77…%」 문제), 시도마다 25% 구간.

## 보류 — 길 B
- WebCodecs 해석: 컨테이너 분해 라이브러리 필요, 프레임 메모리 수백 MB, 사파리 부분 지원 — 엔진 재작성 수준.
- 멀티스레드 엔진 `core-mt`: `Cross-Origin-Opener-Policy`가 필요해 v1.14 「🛍 상세페이지로」(창끼리 postMessage) 연결이 끊김.
→ 길 A 뒤에도 느리다는 회원 의견이 있을 때 다시 검토.

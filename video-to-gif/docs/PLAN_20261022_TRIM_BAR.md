# 플랜 2026-10-22 — v1.13 끌어서 고르는 구간 막대·장면 미리보기 (Claude Code 맥미니, 주인님 승인 「2-5 진행해」)

## 문제
v1.11 구간 자르기는 시작·끝을 숫자로만 입력한다. 회원은 원하는 장면이 몇 초에 있는지 몰라 다른 플레이어로 확인하거나 여러 번 변환해야 했다.

## 범위
| 위치 | 내용 |
|---|---|
| `lib/trimBar.ts`(새) | 순수 계산: 비율→초, 0.1초 맞춤, 시작·끝 최소 0.1초 간격, 영상 길이 밖 금지, 처음/끝까지는 빈칸으로 돌려줌(기존 `trimArgs` 규칙 그대로) |
| `components/TrimBar.tsx`(새) | 막대(고른 구간 노란색) + 손잡이 2개(24px, 포인터 이벤트로 마우스·터치, 키보드 ←→ 0.1초) + 「장면 보기」 미리보기(끄는 동안 그 시점 장면, 「구간 재생」 반복) |
| `components/ConverterWorkspace.tsx` | 구간 줄 아래에 막대. 숫자 칸과 같은 `trimStart`/`trimEnd` 사용. 미리보기는 한 번에 한 줄만(`scenePreviewId`) |
| 버전 | v1.13 — `lib/version.ts`, `package.json` 1.13.0, `supabase/migrations/20261022_trim_bar_v1_13.sql`(버전만) |

바꾸지 않는 것: 서버·DB 구조·AI·변환 엔진(ffmpeg 옵션)·ZIP·썸네일. 미리보기도 브라우저 안에서만.

## 안전장치
- 미리보기 object URL은 열린 동안만 만들고, 닫기·다른 줄 열기·줄 삭제·변환 시작(구간 칸이 사라짐) 때 정리.
- 장면 이동 요청은 이전 이동이 끝난 뒤 마지막 위치만 보냄(느린 브라우저에서 쌓이지 않게).
- 길이를 못 읽은 영상은 막대 없이 숫자 칸만.

## 검수
- 계산 함수 시험 12가지(node, 스크래치 폴더) 통과. tsc 0, eslint 0.
- 배포 뒤 맥미니 크롬: 손잡이 끌기 ↔ 숫자 칸 동기, 장면 미리보기·구간 재생, 변환 GIF 길이가 고른 구간과 맞는지(GIF 프레임), ZIP·썸네일 회귀, 휴대폰 폭(창 최대화 해제 필요).

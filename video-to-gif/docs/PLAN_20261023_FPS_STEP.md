# 개발 플랜 — 8MiB 초과 영상: 사다리 끝에 초당 장면 수 낮추는 단계 (2026-10-23, Claude Code 맥미니 · 주인님 승인 「진행해」)

## 문제
결과가 8MiB를 넘으면 가로폭·색상 수만 8단계로 낮춘다. 마지막 단계(가로 45%·128색)로도 넘으면 「8MiB 이하로 줄이지 못했습니다」로 끝난다. 2026-10-23 v1.15 실검수에서 매 프레임 색이 바뀌는 영상으로 실제 실패(백로그 「매우 복잡한 영상은 45%에서도 8MiB 초과」).

## 고칠 내용
1. `lib/gifLadder.ts` — `CANDIDATES` 끝에 `{ scale: 0.45, colors: 128, fps: 25 }`, `{ scale: 0.45, colors: 128, fps: 20 }`. 재생 길이는 그대로, 움직임만 덜 부드러움. 25·20fps는 GIF 장면 간격(0.04·0.05초)이 정확히 맞는 값. 건너뛰기 계산(`nextCandidateIndex`)은 가로 비율 기준이라 그대로 새 단계로 이어짐.
2. `components/ConverterWorkspace.tsx` — 단계에 `fps`가 있으면 그 값으로 변환·메모리 어림(`canSinglePass`). 완료 줄에 「· N fps로 낮춤」.
3. 화면 문구 — 작업 화면 사다리 안내, `/guide` FAQ 2곳.
- 기존 8단계 안에서 끝나는 영상은 결과가 지금과 같다.

## 검수

- 배포 뒤 맥미니 크롬: 색 블록 시험 영상(화면 안에서 생성) → 8MiB 이하·「fps로 낮춤」 표시, 일반 영상 크기 그대로.

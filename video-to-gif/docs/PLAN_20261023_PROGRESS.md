# 플랜 2026-10-23 — v1.16 변환 진행률 바로잡기 (Claude Code 맥미니, 주인님 승인 「진행해」)

## 문제
v1.15 실측에서 한 시도 안에서 진행률이 되돌아감(35% → 59% → 35%). 한 번에 만들기(10초 영상)·두 번 방식(큰 영상) 모두.
원인: 엔진 진행 이벤트의 `progress`는 엔진 안에서 입력 길이 기준으로 계산돼 구간 자르기·두 번째 입력(palette.png)에서 튀고, 두 번 방식은 실행이 2번이라 0부터 다시 참.

## 바꿀 것
- `lib/gifLadder.ts` `progressRatio(event, seconds)`: 변환할 길이를 알면 `time`(마이크로초) ÷ 길이, 모르거나 1.2 초과면 `progress`, 0~1로 자름.
- `ConverterWorkspace.tsx`: 시도 안에서 줄어들지 않게(`shown`), 두 번 방식은 색상표 0~0.5·GIF 0.5~1(`phase`), 한 번에 만들기는 0~1.
- 변환 방식·화질·속도·사다리·화면 구성은 그대로.

## 검수
- 순수 함수 시험 8가지(스크래치) 통과, tsc 0, eslint 0.
- 배포 뒤 맥미니 크롬: v1.15와 같은 시험 영상(10초·큰 영상·구간 3초)에서 0.2초마다 진행률 기록 → 시도 안에서 줄지 않는지, 시간·결과가 v1.15와 같은지, `time` 단위 확인.

# 개발 플랜 — 4단계 「11번가에 보내기」 (2026-11-11, `claude-win-sdp`, 역할 ecommerce-image)

주인님 지시: 「순서대로 진행해」. 근거 명세: `docs/API_SPEC_NOTES.md` §4·§8·§9.

## 1. 흐름
「🧪 검사하기」 통과 → **「🟠 11번가에 보내기(등록 후 바로 전시중지)」** → 확인 창(「11번가는 임시저장이 없어 보내면 상품이 생깁니다. 바로 전시중지해 손님에게는 보이지 않게 둡니다」) →
1. 기록 표 `elevenst_register_jobs`에 `sending` 한 줄(같은 상품이 `sending`/`unknown`이면 막고 「11번가 셀러오피스에서 먼저 확인」 안내 — **불확실하면 다시 보내지 않음**)
2. 대표·추가 이미지 짧은 주소 만들기(`/i/<id>`, 쿠팡 운영 방식 그대로 — 11번가가 받아 감)
3. `POST /rest/prodservices/product`(회원 본인 키, EUC-KR, 재시도 0)
4. 성공(200/210) → 상품번호 저장 → `PUT …/stopdisplay/{prdNo}` → `stopped`(전시중지 실패면 `registered` + 「셀러오피스에서 직접 전시중지해 주세요」)
5. 오류 응답 → `failed` + 11번가 메시지 그대로 / 시간 초과·연결 끊김 → `unknown`(보냈을 수도 있음)
6. 화면에 결과 + 「셀러오피스에서 확인·판매 시작」 링크, 상품 목록에 배지(등록됨·전시중지·실패·확인 필요). 상세페이지 「🟠 11번가」 배지는 이미 만들어 둠.

## 2. 새로 만드는 것
| 파일 | 내용 |
|---|---|
| DB `elevenst_register_image_links` | 짧은 이미지 주소(쿠팡 `coupang_ops_image_links`와 같은 모양, RLS 켬·서버만 쓰기) — **마이그레이션 1개(운영 DB 쓰기, 승인 필요)** |
| `src/app/i/[id]/route.ts`, `src/lib/imageLinks.ts` | 쿠팡 운영 사본(크기 확대는 11번가가 하므로 뺌) |
| `src/lib/elevenst/register.ts` | 등록·전시중지 응답 읽기(순수 함수, 시험) |
| `sendProductAction` | 위 1~5, 권한 확인 먼저 |
| `src/app/api/cron/cleanup/route.ts` + `vercel.json` crons | 기록·이미지 링크 30일 정리(`retention_exempt` 회원 제외 — 최상위 보관 규칙 그대로, 「발행 1년」 없음) — **환경변수 `CRON_SECRET` 추가(승인 필요)** |
| 상품 목록 배지·기록 | `/products`에 마켓 결과 |

## 3. ⚠ 결정 항목 — 상세설명 이미지 보관
11번가는 대표·추가 이미지는 자기 서버에 저장하지만 **상세설명 이미지는 우리 주소를 그대로 띄움**. 상세페이지 이미지는 일반 회원 30일 뒤 지워지고 짧은 주소도 30일 만료 → **30일 뒤 11번가 상세 이미지가 깨짐**.
| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **1안(추천)** | 상세설명은 **글(핵심 특징·상품 정보 표·사용법) + 대표·추가 이미지**로 만들고, 상세페이지 섹션 이미지는 넣지 않음. 등록 뒤 「셀러오피스에서 상세 이미지 올리기」 안내 | 깨지지 않음, 저장공간 규칙 그대로, 비용 0 | 상세페이지 이미지가 11번가에 바로 안 들어감(회원이 셀러오피스에서 올려야 함) |
| 2안 | 섹션 이미지를 우리 주소로 넣되 **11번가에 올린 상품의 이미지는 판매 중 계속 보관**(보관 규칙 예외: 11번가 등록 상품 이미지는 30일 정리에서 빼고 회원 용량에 계산) | 상세페이지 그대로 11번가에 보임 | 보관 규칙 예외 필요(최상위 규칙 변경 → 주인님 결정), 우리 서버가 11번가 손님 트래픽까지 부담 |
| 3안 | 2안을 저장 구독 회원(90일 이상)에게만 | 구독 유도 | 무료 회원은 1안과 같음, 구독 끝나면 깨짐 |

## 4. 검수·배포
- 시험: 응답 읽기(200·210·오류·인증 실패)·중복 보내기 막기·상태 전환. tsc·build.
- **실제 보내기 시험은 5·6단계(주인님 승인 1건, 실제 11번가 상품이 생김 → 바로 전시중지 → 확인 뒤 삭제는 셀러오피스에서)**.
- 배포: 3단계 연계·미배포 대기 2건과 함께 — 11번가 등록기 1회 + 상세페이지 1회 = **빌드 2회**(배포 직전 다시 여쭘). DB 마이그레이션 1개 + 환경변수 1개(`CRON_SECRET`).

## 5. 주인님 결정 항목
1. 상세설명 이미지: **1안(추천)** / 2안 / 3안
2. DB 마이그레이션 1개(짧은 이미지 주소 표) 운영 적용 승인
3. 환경변수 `CRON_SECRET` 추가 승인(30일 정리 예약 작업용)

## 6. 결정·결과 (2026-11-12)
- 주인님 채팅: 결정 2(DB 표) 「진행해」, 결정 3(`CRON_SECRET`) 「진행해」. 결정 1(상세설명 이미지)은 설명 요청 뒤 **답 대기**.
- 운영 DB: `elevenst_register_image_links` 생성 확인(`to_regclass` 결과 표 있음, `rls_on = true`). Vercel: `CRON_SECRET` production 등록(이름만 확인).
- 코드 완료(미배포): §2 표 전부. 상세설명은 1안(글만)으로 넣어 둠 — 결정이 다르면 `src/lib/actions/send.ts`의 `detailHtml` 한 곳만 바꿈. 시험 37/37·tsc·build 통과.
- 남은 일: 결정 1 → 묶음 배포(11번가 등록기 + 상세페이지, 빌드 2회, 직전 다시 여쭘) → 5·6단계 실제 보내기 1건(상세 이미지가 11번가 주소로 바뀌는지도 확인).

## 7. 결정 1 확정 (2026-11-13)
- 주인님: 「3안」 + 「서버 보관 비용이 발생하는 내용이므로 유료 사용자에게만 이 기능이 동작하도록, 단 테스트 및 운영관리를 위해 관리자 계정과 테스트 예외」 + 「이 관련 내용도 해당 프로그램 설명에 넣어놔」.
- 유료 판정 = `profiles.retention_exempt`(저장 구독 회원은 매일 자동으로 켜짐, 관리자·시험 계정은 항상) — 코드에 이메일을 적지 않음.
- 유료 회원: 상세설명 = 상세페이지 섹션 사진(최대 20장). 그 밖: 글 상세설명. 대표·추가 사진은 11번가가 직접 보관하므로 모두 같음.
- 사진 주소는 30일이 지나도 유료 회원이면 계속 보여 주고, 구독이 끝나면 404 → 정리 예약 작업이 기록을 지움. CDN 하루 보관으로 11번가 손님 조회 비용을 줄임.
- 안내: 등록 화면(검사 결과·7번), 매뉴얼 FAQ, 메인 사이트 설명(v1.05 SQL, 배포 때 적용).

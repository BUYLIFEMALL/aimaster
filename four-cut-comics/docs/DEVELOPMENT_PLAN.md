## 1. 원본이 하는 일 (정밀 분석 결과)

한 줄 요약: 주제를 넣으면 **대본(4컷) → 등장인물 캐릭터 시트 → 컷 그림 4장 → 말풍선 합성 → 저장**까지 한 번에 해 주는 인스타툰/4컷 만화 생성기.

### 1-1. 4단계 흐름
| 단계 | 화면 | 내용 |
|---|---|---|
| 1 주제 선정 | 스타일·모델·말풍선·장르·형식·주제 | 입력 후 [대본 생성하기], 별도 [만화 합치기] |
| 2 대본 확인 | 등장인물 이름·묘사, 컷별 화자·묘사·대사 | 인라인 편집, 이름 바꾸면 화자·대사 속 이름도 같이 변경 |
| 3 등장인물 확인 | 인물별 전신 캐릭터 시트 | 재생성 / 내 이미지로 교체(PNG·JPG·WEBP) |
| 4 만화 생성 | 컷 4장 그림 + 말풍선 + 저장 + 인스타 문구 + 이어서 만들기 | 전체 일괄 생성, 컷별 다시 그리기, 말풍선 재배치 |

### 1-2. 선택 옵션
- **그림 스타일 4종**: 명랑만화(2~3등신·점눈·셀 채색, 기본값), 아메리칸 코믹스(굵은 잉크·벤데이 점·원색), 한국 최신 웹툰(5~6등신·큰 눈·그라데이션), 린 클레어(땡땡풍·일정한 선·단색). 각각 역할/스타일 가이드/"피해야 할 요소" 3블록 프롬프트.
- **그림 모델 2종**: `gemini-3.1-flash-lite-image`(Nano Banana 2 Lite, 초안·기본), `gemini-3.1-flash-image`(Nano Banana 2, 최종본·캐릭터 일관성). 선택은 localStorage 기억. 1·3·4단계와 설정에서 바꿀 수 있음.
- **텍스트(대본·아이디어·인스타 문구·말풍선 위치) 모델**: `gemini-flash-lite-latest` 고정.
- **말풍선 6종**: AI 자동 말풍선(기본·추천) / 말풍선 직접 배치 / 심플(하단 반투명 흰 상자) / 웹툰(하단 둥근 흰 상자+테두리, 화자명 주황색) / 나레이션(상단 노란 상자) / 시네마틱(흰 글자+검은 테두리).
- **장르 11종**: 사용자 주제에 따름, 시사 풍자(Google 검색 grounding), 일상 공감·개그, 반려동물, 감동실화, 자기계발, 캠페인, 매뉴얼, 가상 역사/SF, 개념 설명, 언어 학습. 장르마다 `role`+`rules` 프롬프트. 장르 옆 전구 버튼으로 **주제 아이디어 5개 추천**.
- **형식**: 4컷 단편 / 연속 만화(첫 화, 다음 화 궁금하게 끝냄).

### 1-3. AI 호출 구성(프롬프트 설계가 핵심 자산)
1. **대본**: JSON schema(`characters[{name,description}]`, `panels[4]{panel,character,description,dialogue}`) 강제. 규칙: 주제에 이미 이름·대사가 있으면 그대로 사용(묘사만 창작), 인물 2~3명 이하, 익살스러운 이름, 시각 특징을 구체 묘사(일관성용), 컷 묘사는 이미지 프롬프트로 쓰임. 시사 풍자만 `tools:[googleSearch]`(JSON schema와 병용 불가 → 텍스트에서 JSON 추출).
2. **캐릭터 시트**: 인물 1명 전신, 단색 배경, 다른 사물 금지. 스타일 가이드 + "그림 속 글자는 영어만, 특정 국가 연상 요소 금지".
3. **컷 그림**: 캐릭터 시트 이미지들을 `inlineData`로 전부 첨부 + 장면 묘사. "시트의 외모·의상·스타일과 동일해야 함(깨지면 실패)", "시트 배경은 무시", **말풍선 절대 금지**. 비율 1:1 고정.
4. **말풍선 자동 배치**: 완성된 컷 이미지를 텍스트 모델에 보내 JSON(빈 영역 사각형 0~1000, 화자 입 위치, 스타일 speech/thought/shout) 수신 → 실패하면 컷 상단 중앙 기본 배치.
5. **인스타그램 문구**: 설명(이모지 1~3, 질문 포함)+해시태그 5~10개 JSON.
6. **후속편**: 이전 대본 요약+기존 인물 설정 고정+새 주제(비우면 AI 자동), "계속"(여운) 또는 "완결".
7. **연결 테스트**: 텍스트 모델 1회 + 이미지 모델 `models.get` 가용성 확인(설정 화면).
8. **재시도**: 429/5xx/네트워크는 지수 백오프로 최대 2회, 오류 메시지는 401/403/404/429/5xx별 한국어 안내, 이미지 응답에서 `thought` 파트 제외하고 마지막 inlineData 사용, finishReason 안내.

### 1-4. 말풍선 편집/합성 (브라우저 Canvas)
- 컷 이미지 위에 말풍선을 올려 **이동·크기·회전·꼬리 끌기·모양(말풍선/생각/외침)·테두리 색** 편집(마우스·터치, 우클릭 메뉴). 편집용 주황 점은 저장 이미지에 안 들어감.
- 글자는 Noto Sans KR bold, 줄바꿈은 너비 기준 단어/글자 단위 계산, 꼬리는 곡선, 생각 풍선은 구름+작은 원 꼬리, 외침은 뾰족한 모양(다시 누르면 새 모양).
- **한글 대사는 앱이 그림 위에 얹는다**(AI는 한글 렌더링이 약해서 그림 속 글자는 영어만).

### 1-5. 저장·부가
- 저장 4종: 2×2 바둑판(인스타 피드), 가로 연속, 세로 연속, 개별 파일 4장(캐러셀).
- **만화 합치기**: 이미 가진 이미지 여러 장을 세로로 이어 한 장으로 저장.
- 이어서 만들기: 단편 → 이어서 생성 / 연재 → 다음 화 계속·완결. 기존 캐릭터 시트 재사용.
- API 키: AES-GCM 암호화 후 IndexedDB 비추출 키로 localStorage 보관 또는 세션 한정. 사용 설명서·FAQ 모달 내장. 작업 내용은 메모리에만(새로고침 시 소실).

### 1-6. 원본의 한계·문제(우리가 개선할 점)
- 작업 보관 없음(새로고침하면 소실), 컷 개수 4 고정, 비율 1:1 고정, 말풍선 위치 정확도가 AI 텍스트 모델 1회 판단에 의존, 키 입력이 브라우저에만 있어 플랫폼 권한·사용량 관리 불가, 인물이 "특정 국가 연상 요소 금지"라 한국 일상툰 맥락과 충돌 가능, 시사 풍자의 연도 보장 없음.

## 4. 아키텍처 결정
1. **스택**: Next.js 16 App Router + React 19 + TS, 순수 CSS 흰색 UI(`portrait-photo`와 동일 구조 재사용: `lib/access.ts`, `aiRoute.ts`, `keys` API, 사이드바 표준).
2. **AI 호출은 서버 라우트 경유**(원본은 브라우저 직접 호출). 이유: 본인 키를 공용 `user_api_keys`에 두고(최상위 규칙·키 폴백 금지), 모든 쓰기·유료 호출에 `checkProgramAccessApi` + `force-dynamic`/`fetchCache` 적용, 요청 크기·옵션 id 검증, 오류 메시지 통일. 키 없으면 등록 안내 모달.
   - 라우트: `/api/script`(대본·후속편·아이디어), `/api/character`(시트), `/api/panel`(컷 그림), `/api/balloon`(말풍선 위치), `/api/insta`(문구), `/api/keys`(+연결 테스트).
   - 이미지(캐릭터 시트 포함)는 요청 본문으로 받고 **서버에 저장·로그하지 않는다**. 결과는 브라우저(IndexedDB)에 보관.
3. **프롬프트는 서버가 옵션 id로 조립**(스타일·장르·말풍선 id 화이트리스트, 주제·대사 등 자유 텍스트는 길이 제한·구분자 격리). 영어/한국어 혼용 템플릿은 원본 구조를 유지하되 문장은 새로 작성.
4. **캔버스 합성은 클라이언트 순수 함수로 분리**(말풍선 도형·줄바꿈·저장 레이아웃) → 단위 테스트 가능하게 `lib/comic/*.ts`로 모듈화.
5. **모델 ID는 한곳(`lib/gemini.ts`)에서 관리**하고 연결 테스트로 가용성 확인(원본의 ID가 계정마다 다를 수 있음). 폴백: 이미지 모델 404 시 다른 모델 안내.
6. **연도 규칙(핵심 원칙 8번)**: 대본·아이디어·시사 풍자 프롬프트에 `new Date().getFullYear()` 주입, 시사 풍자는 당해 연도 뉴스만.
7. **한국인 기본(핵심 원칙 3번)**: 사람 캐릭터는 별도 지시가 없으면 한국인 외모로 묘사(원본의 "국가 연상 요소 금지"는 폐기, 간판 등 그림 속 글자는 영어만 유지 — 한글 렌더링 불량 때문).
8. **사용 기록**: 완성작(컷 4장+대본)을 IndexedDB에 최근 20개 보관하는 [내 작품] 화면(원본에 없는 개선). 서버 보관함은 2차(선택, `portrait-photo`의 `saved` 패턴 재사용).
9. **권한**: `programs` 등록 시 `app_url` 세트, 요금제 기본 3단계, 핸드폰·FREE·구독·등급+기간 판정 순서 그대로(`lib/access.ts` 복사 후 slug 변경).

5. 모델 ID(`gemini-3.1-*`)가 회원 키에서 안 열리면 연결 테스트 결과에 맞춰 후보 목록을 조정.

## 8. 리스크
- 이미지 모델 안전 필터(`finishReason`)로 실패 → 컷별 재시도·장면 순화 안내.
- 캐릭터 일관성은 모델 품질에 의존 → 시트 단순 배경 전신 + 시트 첨부 방식 유지, Nano Banana 2 권장 안내.
- 시사 풍자의 검색 grounding은 JSON schema 병용 불가 → 파싱 실패 시 1회 재요청.
- 요청 본문 크기: 시트 이미지 여러 장 첨부 → 서버 한도(Vercel 4.5MB) 안에서 시트를 리사이즈(긴 변 768px)해 전송.

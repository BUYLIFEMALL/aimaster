## 2. 삭제 대상이 아닌 것(설정·회원이 고른 자료)
- `trend_watchlist`(관심 카테고리·키워드·알림 설정), `user_api_keys`·SMTP·카카오·텔레그램 등 계정/키/연동.
- `sourcing_saved_products`(회원이 ⭐로 직접 저장한 관심 상품과 가격 추적 상태) — 회원이 고른 즐겨찾기·추적 설정으로 보고 제외안. **주인님 판단 필요**(생성 자료로 볼지).

## 3. 구현안
1. **정리 Cron 신설** `app/api/cron/cleanup-generated/route.ts` — 기존 Cron과 같은 `CRON_SECRET` Bearer 인증, 매일 1회 `50 18 * * *`(UTC, 한국 03:50 · 오전 9시 자동 리포트와 겹치지 않음). `vercel.json`에 4번째 Cron으로 추가(기존 3개 변경 없음).
   - `recommendation_reports` `generated_at < now()-30일` 삭제
   - `trend_snapshots`·`shopping_competition` `fetched_at < now()-30일` 삭제
   - `trend_watchlist.sourcing_alert_last_snapshot` — `sourcing_alert_last_run_at < now()-30일`이면 값만 비움(행·설정 유지). 비운 뒤 "바뀐 것만" 모드는 다음 1회 전체 목록을 보내고 다시 비교 시작.
   - 실행 결과(표별 삭제 수)를 응답·로그에 남김. 회원 자료 내용은 로그에 남기지 않음.
2. **만료 자료 재사용 금지(화면)**: 리포트 화면·대시보드 조회에 `generated_at >= now()-30일` 조건 추가(삭제 전이라도 만료 자료를 보여 주지 않음). 점수 추이 기간 90일 → 30일.
3. 인덱스: 각 표의 날짜 칸 인덱스 유무 확인 후 없으면 추가(스키마 변경 — 승인 범위에 포함).
4. 검수: 단위 테스트(기준 시각 계산), 배포 후 인증 없는 호출 401, 인증 호출 1회로 삭제 수 = 위 표 예상치와 대조(리포트 31·스냅샷 65·캐시 1), 다음 날 Cron 실행 기록 확인.

## 4. 비용·위험

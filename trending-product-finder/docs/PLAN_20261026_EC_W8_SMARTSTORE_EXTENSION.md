## 0. 한 줄 요약
상세페이지 자동화에서 완성한 상품(상품명·가격·대표 이미지·섹션 이미지)을, 회원 크롬의 확장이 **스마트스토어센터 「상품 등록」 화면 칸에 사람처럼 채워 넣고**, 「등록」은 회원이 고른 방식(입력만 / 바로 등록 / 판매대기 등록)으로 처리한 뒤 결과(상품번호·실패 이유)를 프로그램에 돌려준다. 블로그 확장과 같은 흐름이다.

## 1. 왜 이 방식인가
| 항목 | 이 방식 | 비교 — 서버 API 대신 등록 |
|---|---|---|
| 네이버 정책 | 회원 본인이 로그인한 화면에서 회원 브라우저가 입력 → 키를 맡기지 않음 | 회원 「내 스토어」 키를 받아 대신 운영하는 것은 **허용 안 됨**(공식 답변) |
| IP | 회원 PC에서 동작 → 상관없음 | Vercel IP가 고정되지 않음 |
| 회원 준비 | 확장 설치 + 연결 코드 1번 | API 앱 등록·키 발급 |
| 약점 | 판매자센터 화면이 바뀌면 고쳐야 함, 봇 탐지 주의 | — |

## 2. 전체 흐름
1. **웹에서 완성(상세페이지 자동화)**: 상품 화면에 「🛍 마켓 등록」 패널 — 판매가·재고·카테고리 검색어·원산지·배송/반품 기본값을 확인하고, 상세 이미지 형태(섹션 여러 장 / 긴 이미지 한 장)를 고른다. 상품소싱에서 넘어왔으면 상품명·판매가(마진 계산기 값)가 미리 채워진다.
2. **등록 방식 고르기**: ⓐ **입력만**(기본값 — 「등록」은 회원이 누름) ⓑ 바로 등록 ⓒ 판매대기로 등록(전시 안 함). 계정 기본값을 둘 수 있고, 회원이 고르지 않은 방식으로 등록하지 않는다.
3. **확장이 입력**: 「스마트스토어에 등록」 → 확장이 판매자센터 등록 화면을 열고 칸을 순서대로 채운다(사람처럼 간격·입력). 로그인이 안 돼 있으면 멈추고 「스마트스토어센터에 로그인해 주세요」 안내.
4. **결과 기록**: 등록 완료 → 상품번호·상품 주소, 입력만 → 「입력 완료(회원 확인 대기)」, 실패 → 어느 칸에서 왜. 결과가 불확실하면 **자동으로 다시 등록하지 않는다**(중복 상품 방지).

## 4. 시스템 구조
### 4-1. 프로그램 쪽(`shop-detail-page`)
- **「🛍 마켓 등록」 패널**(상품 화면): 위 칸 값과 등록 방식, 「스마트스토어에 등록」 버튼, 마지막 결과 표시.
- **마켓 기본값 저장**: 원산지·A/S 전화·배송 템플릿 이름·고시 품목 유형 — 회원별 1행(다른 상품에서 다시 안 넣게).
- **등록 작업 기록 표(새)** `shop_market_jobs`: 회원·상품·마켓·방식·상태(대기/입력 중/입력 완료/등록 완료/실패)·마켓 상품번호·실패 이유·시각. RLS 본인만, **30일 자동 정리**(기존 정리 작업에 추가, 공용 `cleanup-usage-log`).
- **확장 전용 API**(회원 토큰, 권한 확인 `checkProgramAccessApi` + `dynamic`/`fetchCache` 두 줄): 연결 코드로 짝짓기 → 다음 작업 받기 → 이미지 받기(회원 본인 비공개 저장소 서명 주소) → 결과 보고.
- 이미지는 지금처럼 비공개 버킷, 확장에는 짧게 쓰는 서명 주소만 준다.

### 4-2. 확장(`shop-detail-page/extension/`, 새로)

## 7. 검수
- 단위 시험: 칸 대응 변환(상품 → 입력값), 글자 수·필수값 검사, 작업 상태 바뀜(중복 방지).
- 확장: 시험 상품으로 **「입력만」** 실행을 크롬 실제 창(포그라운드)에서 주인님과 함께 확인 — 칸별 캡처.
- 실제 등록 시험은 주인님 계정에서 **판매대기 등록 → 확인 → 삭제**(삭제는 주인님이 직접 또는 승인 뒤).
- 확장 ZIP·DB 버전 확인 스크립트, 휴대폰 폭 390px 패널 넘침 없음.

## 8. 비용
| 항목 | 내용 | 승인 |
|---|---|---|
| 0단계 | 무료(화면 읽기) | 없음 |
| 빌드 | 상세페이지 배포: 1차 1~2회, 2단계 1회, 쿠팡 1회 | **단계마다 여쭘** |
| AI 호출 | 없음(이미 만든 상세페이지를 그대로 씀) | — |
| 운영자 인프라 | 없음(회원 PC에서 동작, 이미지는 기존 저장소) | — |

## 9. DB 변경 (1단계 때 승인 필요)
- `shop_market_jobs`(등록 작업 기록, RLS 본인만, 30일 정리)
- `shop_market_defaults`(회원별 마켓 기본값 1행) — 또는 기존 표에 칸 추가(0단계 뒤 결정)
- 확장 연결 토큰 저장(블로그 확장과 같은 방식인지 0단계 뒤 결정)

## 10. 주인님께 여쭐 것
1. **진행 승인**: 0단계(화면 분석)부터 시작
2. **로그인**: 크롬에서 스마트스토어센터(판매자 계정)에 로그인해 주실 수 있는지 — 제가 화면을 읽기만 함
3. **시험 등록 방법**: 2단계 실제 등록 시험을 「판매대기 등록 → 확인 → 삭제」로 해도 되는지
4. **상세페이지 폴더 작업 순서**: 디자인 담당(agy) 작업 중 표 줄이 남아 있어, 1단계 코드 시작 전에 그 작업이 끝났는지 확인 필요

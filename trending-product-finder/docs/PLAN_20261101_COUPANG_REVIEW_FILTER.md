# 쿠팡 리뷰 수 거르기 확장 개발 플랜 (승인 대기)

- 작성: 2026-11-01, `claude-win-sdp` [역할: ecommerce-image]
- 주인님 결정: 리뷰 수 API 경로 포기, 약관 문의 없이 「사용자들이 각자 알아서 하는 거야」(회원 책임). 지정 목록: `docs/TOP_RULE_PERSONAL_ACCOUNT_API.md` §8.

## 문제
쿠팡 공식·파트너스 API로는 리뷰 수를 받지 못한다(파트너스 응답 실측). 판매 후보를 찾을 때 리뷰가 있는 상품만 남기려면 회원이 보는 검색 화면을 읽어야 한다.

## 범위
- 회원이 쿠팡에서 직접 검색한 화면에서 버튼을 누를 때만 그 페이지를 읽는다.
- 기준: 리뷰 1개 이상 / 2개 이상 / 직접 입력. 광고 제외 선택, 같은 상품번호 합치기.
- 결과 표(상품명·가격·리뷰 수·주소)와 CSV 저장. 결과는 회원 PC에만 두고 서버로 보내지 않는다.
- 첫 사용 때 약관 위반·계정 제재 소지와 회원 책임 고지, 동의 체크.

## 하지 않는 것
자동 페이지 넘기기, 상품별 자동 방문, 예약 수집, 서버 수집, 리뷰 본문 수집, 차단·확인 화면 우회. 차단 화면이나 카드 0개면 멈추고 안내한다.

## 구현 순서
1. `trending-product-finder/extension/` 생성, 표시명은 본 프로그램명과 동일.
2. 카드 읽기·거르기 순수 함수와 시험(저장한 HTML 조각으로, 쿠팡 접속 없음).
3. 팝업·결과 표·CSV·고지.
4. 프로그램 화면에 다운로드와 3단계 설치 안내, 매뉴얼.
5. 빌드·배포 후 manifest·ZIP·DB 버전을 맞추고 `check-extension-release` 확인.

## 검수
시험 계정으로 로그인, 회원처럼 직접 검색한 1페이지에서 버튼을 눌러 화면과 대조. 시험 접속은 1~2페이지로 제한.

## 비용
Vercel 빌드 1회 예상(사전 승인 필요). AI 호출 없음, 회원 비용 없음.

## 남은 위험
회원 책임 고지를 해도 제공자인 우리 책임이 모두 없어진다고 볼 수 없다. 쿠팡 화면 구조가 바뀌면 수정이 필요하다. 2페이지 「검색결과 없음」의 원인은 미구분이지만, 회원이 직접 넘기는 설계라 구현을 막지 않는다.

## 산출물

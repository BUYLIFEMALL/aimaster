## 1. 지금 문제
- 마진 계산(소싱 결과 패널·일괄 CSV·검색 결과 전체)이 모두 「플랫폼 수수료율 한 칸(기본 10.8%)」만 쓴다 → 마켓·카테고리·배송 방식에 따라 실제 정산과 다르다.
- 수수료 참고표(`/fees`, E0에서 공식 값으로 고침)와 계산기가 따로 논다 — 표를 보고 숫자를 손으로 옮겨야 한다.
- 같은 상품을 어느 마켓에 올려야 남는지 비교할 수 없다.

## 2. 만들 것
| # | 기능 | 내용 |
|---|---|---|
| 1 | 마켓 고르기 | 스마트스토어·쿠팡·11번가·G마켓·옥션·직접 입력 |
| 2 | 카테고리 요율 자동 | **G마켓·옥션은 E0에서 확인한 ESM 공식 표**에서 카테고리를 고르면 요율이 채워진다(✅). 쿠팡·11번가·스마트스토어는 공식 표를 확인하지 못해 **대표값(⚠) + 회원이 판매자센터 값으로 바꾸는 칸** — 원본 프로그램의 카테고리 표는 쓰지 않는다 |
| 3 | 배송 방식 | 무료배송 / 선결제 유료배송(배송비에도 수수료, ESM 공식 3.3%) / 착불 |
| 4 | 마켓별 정산 규칙(확인된 것만) | ESM: (판매가+옵션가) × 요율 + 선결제 배송비 × 3.3%, 전월 판매 500만 원 이상이면 월 서버 이용료(옥션 공식 55,000원 — 월 예상 판매 수량으로 나눠 개당 반영, 선택) · 스마트스토어: 주문관리 수수료(등급별, 부가세 포함)와 판매수수료(유입 경로별, 부가세 별도)를 **두 칸으로 나눠** 입력(대표값 ⚠) · 판매자 할인 금액 칸(할인 후 가격으로 계산) |
| 5 | 여러 마켓 나란히 | 같은 원가·판매가로 5개 마켓의 수수료·정산액·공헌이익·마진율을 한 표에 — 가장 남는 마켓 표시 |
| 6 | 손익분기 판매가 | 마켓별 「이 가격 아래로 팔면 손해」 가격 + 목표 마진율(예: 20%)을 넣으면 필요한 판매가 |
| 7 | 포장비 칸 | 개당 포장·부자재비(지금은 입고비에 섞여 있음) |
| 8 | 일괄 CSV에 마켓 열 | 줄마다 마켓(+선택 카테고리)을 넣으면 그 마켓 규칙으로 계산, 결과 CSV에 마켓·적용 요율·확인 여부 열 추가 |
| 9 | `/fees` 표와 계산기 한 곳 | 수수료 숫자를 공용 `market-fees` 한 파일로 옮기고 `/fees` 화면도 그 파일을 읽는다(숫자가 두 곳에 있지 않게) |

### 하지 않는 것(이번 범위 밖)
- 쿠팡 **로켓그로스** 물류비(입출고·보관·반품 12항목) — 공식 요금표 확인이 필요해 다음 후보로 둔다(원본 예시 숫자는 옮기지 않음).
- 11번가 쿠폰 부담·제휴 수수료, ESM 제휴·프로모션 수수료 — 공식 문서로 확인되면 추가(지금은 「기타 추가 수수료(%)」 칸 하나로 회원이 넣음).

## 3. 공용 기준 코드 `market-fees` 확장(기준 `shop-order-report`)
- 기준 파일이 `MarketId` 타입을 다른 파일에서 가져오고 있어 사본이 다른 앱에서 깨진다 → **타입을 파일 안에 두어 혼자 서게** 고친다.
- 추가: ESM 카테고리 요율표(E0 `/fees`의 G마켓·옥션 공식 값을 이 파일로 이동, 확인일·출처 포함), 배송 방식별 계산, 스마트스토어 두 칸 구조, 손익분기 함수, 마켓 비교 함수.
- `node scripts/check-shared-modules.mjs --sync`로 `trending-product-finder/lib/marketFees.ts` 사본 생성(사본 직접 수정 금지).
- `shop-order-report`는 계산 결과가 같도록 기존 함수 이름·값을 유지 → **급하지 않은 변경이라 다음 배포 때 함께**(미배포 대기 등록, 빌드 없음).

## 4. 화면 변경(상품소싱)
- 소싱 결과 마진 패널: 「판매 플랫폼 수수료율」 한 칸 → 마켓·카테고리·배송 방식 선택 + 「⚖ 5개 마켓 비교」 펼침 표 + 손익분기 판매가.
- 일괄 마진 화면: 예시 CSV에 `마켓`·`카테고리` 열, 결과 표에 마켓 열.
- `/fees`: 보이는 값은 그대로(같은 숫자를 공용 파일에서 읽음), 「이 요율로 마진 계산하기」 바로가기.
- 기존 「수수료 한 칸」 계산 함수(`calcMargin`)는 남겨 기존 저장 결과·시험이 그대로 통과하게 하고, 새 함수 `calcMarketMargin`을 더한다.

## 5. 검수
- 자동 시험: ESM 공식 계산식 예시(판매가·옵션·선결제 배송비) 직접 대조, 배송 방식 3종, 판매자 할인, 서버 이용료 개당 배분, 스마트스토어 두 칸, 손익분기·목표 마진 판매가, 5개 마켓 비교 순서, 일괄 CSV 마켓 열, 기존 `calcMargin` 시험 그대로 통과, 공용 사본 일치 검사.
- `tsc`·로컬 빌드, 크롬 시험 계정으로 마진 패널·비교 표·일괄 CSV·`/fees` 확인, 휴대폰 폭.

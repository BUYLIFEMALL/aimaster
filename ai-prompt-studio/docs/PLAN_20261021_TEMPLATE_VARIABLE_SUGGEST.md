# 개발 플랜 — 「내 템플릿으로 저장」 때 바뀌는 부분을 {{변수}}로 자동 제안 (2026-10-21, Claude Code 윈도우)

주인님 지시: 병합 C 「추가개선 제안 2」 진행. 대상: `ai-prompt-studio` v1.07 → v1.08. DB 변경 없음.

## 1. 문제
결과 화면에서 「📁 내 템플릿으로 저장」을 누르면 완성 프롬프트가 그대로 저장 창에 들어간다. 설계한 프롬프트에는 `{{변수}}`가 거의 없어서, 회원이 바뀔 부분을 직접 찾아 고쳐야 다시 쓸 수 있다.

## 2. 해결
| 항목 | 내용 |
|---|---|
| 자동 제안 | 결과 화면에서 넘어온 초안이고 본문에 변수가 0개이면, 저장 창이 열릴 때 AI가 **한 번** 「바뀌는 부분」을 찾아 제안한다(회원 본인 Gemini 키, Flash 1회). |
| 직접 실행 | 본문 칸 옆 「🪄 변수 찾기」 버튼 — 어떤 템플릿에서도 원할 때 다시 받을 수 있다. |
| 제안 화면 | `{{상품명}} ← "딥슬립 코치"`처럼 목록 + 체크박스(기본 모두 선택) → 「선택한 것 변수로 바꾸기」 / 「그대로 둘게요」. |
| 바꾸는 방식 | AI가 본문 전체를 다시 쓰지 않고 「원래 문구 → 변수 이름」 목록(JSON)만 받는다. 실제 바꾸기는 화면에서 문구를 정확히 찾아서 한다 → 나머지 문장은 그대로 유지(본문 변질 방지). 본문에 없는 문구·중복 이름은 버린다. |
| API | 기존 `/api/templates/suggest-field`에 `field: "variables"` 추가(권한·본인 키·캐시 방지 그대로). 응답 `{ success, suggestions: [{ name, original }] }`, 최대 8개. |

## 3. 구현 순서
1. `suggest-field` 라우트에 `variables` 분기(JSON 응답, 결과 검증).
2. `PromptFormModal`: 제안 상태·목록·적용 함수, 「🪄 변수 찾기」 버튼, 초안 자동 1회 실행(`autoSuggestVariables` prop).
3. `TemplatesView`: 결과 화면 초안일 때 자동 실행 표시, 새 API 호출 연결.
4. 매뉴얼(가이드) 보관함 안내에 한 줄 추가, 버전 v1.08(코드·DB).

## 4. 검수
`npx tsc --noEmit`·`npm run build` → 배포 → 크롬(일반 회원 계정): 프롬프트 설계 결과 → 저장 → 자동 제안 표시 → 일부 해제 후 바꾸기 → 변수 태그 확인 → 저장·실행 창 변수 칸 확인 → 시험 템플릿 삭제. 390px 확인.

## 5. 비용
| 구분 | 내용 |
|---|---|
| 개발·시험 | 회원 본인(시험 계정) Gemini Flash: 설계 1~2회 + 변수 찾기 1~2회 |
| 운영자 인프라 | 없음(배포 1회) |

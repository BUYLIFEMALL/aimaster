### 2-1. 전달 방법 비교 — 매물값이 URL·서버 로그·방문 기록에 남지 않게

| 방법 | 서버 요청·Vercel 로그 | Referer | 방문 기록·주소창·동기화 | 그 밖의 노출 | 판정 |
|---|---|---|---|---|---|
| ① URL 쿼리 `?price=…` | **남음**(요청 줄 전체) | 남을 수 있음 | **남음** | 링크 공유·확장 | **쓰지 않음**(초안 방식 폐기) |
| ② 프래그먼트 `#…` | 안 남음(브라우저가 `#` 뒤를 보내지 않음) | 안 남음(프래그먼트는 Referer에서 빠짐) | 열리는 순간 기록에 남음 → 받는 쪽이 읽자마자 `history.replaceState`로 지우면 그 항목은 정리된 주소로 바뀜. **남는 한계**: 지우기 전 아주 짧은 순간의 기록·동기화, 읽기 전에 열린 다른 확장·화면 캡처, 받는 쪽 스크립트가 실패하면 그대로 남음 | 같은 탭 새로고침 시 이미 지워져 재입력 없음(의도) | 예비안 |
| ③ 창 사이 메시지(`window.open` + `postMessage`) | 안 남음 | 안 남음(주소에 값 없음) | **안 남음**(고객관리 주소는 `/listings?from=listing-alert` 표시용 고정 글자만, 값 없음) | 두 창 메모리에만. 받는 쪽은 `event.origin`이 매물 알림 두 주소일 때만, 보내는 쪽은 `targetOrigin`을 고객관리 주소로 정확히 지정 | **추천** |
| ④ 클립보드 복사·붙여넣기 | 안 남음 | — | 안 남음 | 클립보드는 다른 앱이 읽을 수 있음, 회원 조작 늘어남 | 쓰지 않음 |
| ⑤ 서버 임시 토큰(DB) | 서버에 매물값 저장 | — | 안 남음 | DB 변경·보관 규칙 | 쓰지 않음 |

③ 세부(구현 때 지킬 것):
- 보내는 쪽: 버튼 클릭 때만 `const w = window.open(DESK_URL, "realty-desk-candidate")`(`noopener` 쓰지 않음 — 메시지 창 핸들이 필요). 받는 쪽이 `{type:"ready"}`를 보내면 그때 한 번만 `w.postMessage({type:"candidate", v:1, fields}, "https://realty-client-desk.buylife.xyz")`. 10초 안에 ready가 없으면 보내지 않고 「고객관리 화면을 열지 못했어요」 안내(값 재시도 없음).
- 받는 쪽: `window.opener`가 있을 때만 `opener.postMessage({type:"ready"}, 매물 알림 origin)` — origin 목록 밖이면 무시. 받은 값은 §3 재검증 후 상태로만 두고 `localStorage`·`sessionStorage`·쿠키·서버로 보내지 않음. 한 번 받으면 리스너 해제(재사용 없음). 받은 뒤 `window.opener = null`.
- 확인한 전제: 두 프로그램 모두 `Cross-Origin-Opener-Policy` 헤더 설정이 없음(`next.config`·`vercel.json`·proxy에서 검색 0) → 창 핸들 유지 가능. 나중에 COOP를 켜면 ③이 끊기므로 그때 ②로 전환.
- 남는 한계: 같은 브라우저의 다른 확장이 두 페이지의 DOM·메시지를 읽을 수 있는 것은 이 방법으로도 막지 못함(지금 결과 표 자체도 같은 화면에 있음). 전송값은 화이트리스트 최소 칸이라 노출 범위는 화면에 이미 보이는 것보다 넓어지지 않음.

## 4. 결정 항목(주인님/Master)

1. **법적 경계(가장 중요)**: 매물 알림 행은 **다른 중개사가 올린 매물**이다. 의뢰받지 않은 매물을 내 매물로 광고하는 일이 생기지 않도록 화면에서 회원의 확인을 받는 장치가 필요하다(법률 판단은 이 문서에서 하지 않음 — 필요하면 주인님 확인). 추천: 후보로 들어온 매물은 저장 시 **「의뢰를 직접 받은 매물입니다」 확인란을 체크해야 등록**되게 하거나, 새 상태 「후보(광고 불가)」를 둠(→ DB 상태 값 추가 = DB 변경 승인). 추천은 확인란(DB 변경 없음).
2. 주소 수준: 결과에 지번 주소가 없어 「시군구 동 단지명」만 채움 — 회원 보완으로 충분한지.
3. 중복 기준: 위 휴리스틱(경고만)으로 충분한지, 아니면 출처 칸(`source_ref`, 네이버 매물 번호) 추가(DB 변경)로 정확히 막을지. 추천: 경고만(매물 번호는 넘기지 않는 원칙 유지).
4. 버튼 위치: `/results` 새 매물 행만 vs 변동 기록 탭까지.

**승인 필요 한 줄(묶음)**: C-1을 「확장 수정 없이 매물 알림 결과 → 창 사이 메시지 → 고객관리 미저장 후보 폼(전화번호·중개사·원문·매물 번호 미전달), 의뢰 확인란 체크 뒤에만 회원이 직접 등록」 방식으로 구현할지, 등록 시 기본 상태(광고 중/회원 선택)·중복은 경고만·버튼 위치를 함께 정해 주세요 — 구현은 두 프로그램 로컬 시험까지 비용 0, 배포·실시험은 각 빌드 1회 별도 승인.

# 개발 플랜 2026-11-03 · AI 중개사무소 고객관리 자동화 (`realty-client-desk`)

[역할: realty] Claude Code(윈도우) `claude-win-realty-docs`. 근거: 카테고리 플랜 `docs/analysis-realty-roadmap-20261031/PLAN.md` §4 D·결정 4(고객 명부 1년)·결정 5(이름). **승인 전, 코드·DB 변경 없음.** 대상: ① AIMaster 운영(DB ref `esgxyikcnnvmlhygjkth`).

## 1. 한 줄 요약
공인중개사가 매수·임대 관심고객을 동의를 받아 모으고, 내 매물과 조건으로 맞춰 **사람이 확인한 뒤** 안내를 보내고, 임장·계약·잔금·만기 일정을 챙기는 중개사무소 도구.

## 2. 쓰는 사람과 하는 일
| 사용자 | 하는 일 |
|---|---|
| 회원(개업공인중개사·중개보조원) | 고객 접수 링크 공유, 고객 조건 관리, 내 매물 등록, 맞는 고객 후보 보기, 안내 문자 초안 확인·발송, 일정 알림 |
| 고객(제3자, 회원 아님) | 접수 링크에서 조건 입력 + 개인정보 수집 동의(필수) + 광고성 정보 수신 동의(선택) |

## 3. 기능 (단계별)
| ID | 기능 | 재사용 | 비고 |
|---|---|---|---|
| D1 | 관심고객 등록 — ① 고객이 여는 **접수 링크**(동의 체크 필수) ② 중개사 수기 입력(「동의 받음」 확인 칸 필수, 받은 방법·날짜 기록) ③ 엑셀 올리기(같은 확인 칸). 조건: 거래(매매·전세·월세)·지역·유형·예산·면적·입주 시기·메모 | `crm-google-form` 접수 흐름, `booking-reminder` 엑셀 등록 | 고객 연락처는 회원별 격리(RLS) |
| D2 | 내 매물 등록 → 조건 맞는 고객 후보 표 → **중개사가 고른 고객에게만** 안내 초안 → 확인 후 발송 | SOLAPI 공용 코드(`solapi-client`), 회원 본인 SOLAPI 계정 | 자동 일괄 발송 없음 |
| D3 | 일정 알림 — 임장 약속·계약·중도금·잔금·임대차 만기(만기 N일 전) | `booking-reminder` 예약 규칙, 회원 cron-job.org(예약 지침) | 회원에게 알림(텔레그램·문자) |
| D4 | 매물 설명·상담 답변 초안(회원 본인 Claude 키) + **광고 명시 항목 빠짐 점검** | 기본 AI Claude | 보내기는 사람이 누름 |
| D5 | 후순위: 중개보수 계산기 | — | 요율 근거 확인 뒤 |

## 5. 데이터·보안 설계(안)
| 표 | 내용 | 보관 |
|---|---|---|
| `realty_desk_clients` | 회원별 고객(이름·연락처·조건 jsonb·동의 기록: 수집 동의 일시/방법/문구판, 광고 동의 일시, 야간 동의, 수신거부 일시) | 1년(결정 4) — 마지막 상담일 기준, 관리자·시험 계정 제외 규칙 그대로, 회원·고객 요청 시 즉시 삭제 |
| `realty_desk_listings` | 회원 매물(광고 명시 항목 칸 포함) | 1년 |
| `realty_desk_events` | 일정(임장·계약·잔금·만기) | 1년 |
| `realty_desk_sends` | 발송 기록(누구에게·언제·광고 여부, 본문 요약) | 1년 |
| `realty_desk_intake_links` | 접수 링크(회원별 토큰 해시, 공개 페이지는 쓰기만) | 회원 삭제까지 |
- 모든 표 `user_id` + RLS(회원 본인만). 접수 링크로 들어온 고객 입력은 서버가 토큰을 확인해 해당 회원 줄로만 넣는다(고객은 읽기 권한 없음).
- 키·계정: AI는 회원 본인 Claude 키, 문자는 회원 본인 SOLAPI 계정(공용 `user_solapi_accounts` 재사용). 운영자 키 폴백 없음.
- 최상위 규칙 문서 §8에 「`realty-client-desk` 고객 명부 1년(관리자 지정 2026-11-01)」 기록.

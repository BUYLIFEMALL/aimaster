## 1. 원본 분석

### 1-1. 한 줄 요약
인물 사진 한 장을 올리면 **① 상황(TPO)별 의상·액세서리를 AI가 제안하고 아이템 이미지를 생성 → ② 사진 위로 드래그해 가상 피팅 → ③ 메이크업·헤어를 분석·적용 → ④ 결과 저장**하는 AI 퍼스널 스타일리스트. Gemini 이미지 편집 모델(나노바나나)을 직접 브라우저에서 호출하는 클라이언트 전용 앱이다.

### 1-2. 화면 구성 (실제 미리보기 확인)
상단 헤더(제목·설정·가이드·KO/EN) · 3열: **왼쪽 "AI 추천 스타일"**(상황 입력 + 의상/액세서리 탭), **가운데 캔버스**(사진 업로드/결과, 드롭 영역), **오른쪽 "나만의 옷장"**(웹 이미지 드래그·붙여넣기) · 캔버스 아래 **AI 뷰티 스튜디오** 버튼, **피팅 모드**(레이어드/갈아입기), **새로 시작 / 저장하기** · 하단 개발자 크레딧·유튜브 링크.

### 1-4. 옵션별 상세
- **AI 모델**: Standard = 텍스트 `gemini-2.5-flash` + 이미지 `gemini-2.5-flash-image` / NanoBanana2(Pro) = 텍스트 `gemini-3-pro-preview` + 이미지 `gemini-3.1-flash-image-preview`. 아이템 이미지·이름 생성은 항상 Standard.
- **피팅 모드**: 레이어드(누적) · 갈아입기(원본 기준 재생성).
- **언어**: KO/EN(화면 문구 전체와 뷰티 조언 언어).
- **추천 탭**: 의상(2세트×2~3벌) · 액세서리(주얼리·모자·가방·스카프·안경·벨트만).
- **사진 입력 경로**: 파일, 클립보드, 드래그한 웹 이미지 URL.

### 1-5. 호출·비용 구조 (사용자 키로 환산)
추천 1회 = 텍스트 1 + 이미지 4~6, 아이템 이름 = 텍스트 1/개, 피팅 = 이미지 1(레이어드 누적), 뷰티 분석 = 텍스트 1 + 이미지 2, 적용 = 이미지 1. 즉 **한 사용자가 한 룩을 완성하는 데 이미지 호출 10~20회**.

### 1-6. 결과물
편집된 인물 이미지 1장(원본 종횡비, PNG 데이터를 `.jpeg` 이름으로 저장), 화면 안의 AI 아이템 이미지(저장 기능 없음), 뷰티 조언 텍스트. **서버·계정·히스토리 없음** — 새로고침하면 전부 사라진다.

### 1-7. 결함·한계 (우리 버전에서 해결)
1. **API 키가 브라우저 안**(난독화만, 원본 배포본은 빌드에 운영자 키 주입 경로 존재) → 키 탈취·노출 위험, AIMaster 최상위 규칙 위반 구조.
2. 도움말은 "AI 추천 의상을 입으면 상황에 맞는 배경으로 자동 변환"이라 하지만 **실제 프롬프트는 배경 유지**를 명시하고 `situation` 값은 사용되지 않음 → 문구와 동작 불일치.
3. 저장 없음: 옷장·결과·추천 모두 새로고침 시 소실, **되돌리기·히스토리·비교 보기 없음**(레이어드는 누적만).
4. 파일명 `.jpeg`인데 실제는 PNG 등 포맷 불일치, 5MB 제한은 문구뿐(검증 없음), 큰 사진을 그대로 base64로 전송.
5. 외부 공개 프록시 `cors-anywhere` 의존(불안정·보안 위험), URL 가져오기 실패 처리 단순.
6. 아이템 생성이 직렬+2초 대기라 느리고, 실패 아이템의 개별 재시도·취소 없음, 오류 메시지가 일반적("Failed to…").
7. 옷장 아이템 type이 항상 `accessory`, 카테고리·즐겨찾기·이름 편집 없음, 빈 파일 `ItemGallery.tsx` 잔재.
8. 안전 필터 회피를 위해 프롬프트에서 "얼굴/신원" 표현을 일부러 빼는 식의 우회, 거부(FinishReason) 시 사용자 안내가 불친절.
9. 인물 사진(민감 정보)에 대한 동의·보관 안내 없음, 개발자 크레딧·유튜브 링크 하드코딩.

### 1-8. 실행 결과 확인 상태
운영 미리보기를 열어 **초기 화면·기능 배치·옵션 UI**를 확인했다. 실제 생성 결과는 사용자 본인 사진과 Gemini 키(과금)가 필요해 원본 앱으로는 호출하지 않았고, **프롬프트·스키마·상태 전이는 소스로 확정**했다. 구현 후에는 주인님 본인 키로 1~2회 실제 호출해 결과를 대조한다(본인 사진·소액).

## 3. 범위

### v1.01 (원본 동등 + 결함 해결)
1. 사진 입력(파일·붙여넣기·드래그·URL): 클라이언트에서 **긴 변 1600px로 축소·JPEG 변환**(4.5MB 한도 대응), 형식·크기 검증과 친절한 안내.
2. AI 추천(의상/액세서리): 서버 1회 호출로 세트 목록 → **동시 2개 병렬·지수 백오프**로 아이템 이미지 생성, 개별 **재생성·취소**, 진행률 표시.
3. 내 옷장: 업로드·붙여넣기·URL(서버 이미지 프록시, SSRF 방어), AI 이름 자동 생성, 이름 편집·삭제·카테고리, **IndexedDB 영구 보관**.
4. 가상 피팅: 드래그&드롭 + **클릭 적용** 병행, 레이어드/갈아입기, **배경 처리 옵션 명시**(유지 / 상황에 맞게 변환 — 원본의 문구·동작 불일치 해소), 결과마다 **히스토리(되돌리기·다시 실행)와 원본↔결과 비교 슬라이더**.
5. 뷰티: 분석·참고 이미지·적용(메이크업/헤어), 누적 적용과 되돌리기.
6. 저장: 정확한 포맷(PNG/JPEG 선택) 다운로드, 최근 룩 갤러리(브라우저 보관).
7. KO/EN 전환, 흰색 UI, 표준 사이드바(키 등록 메뉴 포함), 사용 매뉴얼(키 발급 안내 연결).
8. 안전 안내: "본인 사진 또는 사용 권한이 있는 사진만 사용" 동의 체크, 서버에 이미지가 저장되지 않는다는 고지, 거부 응답(안전 필터)에 대한 구체적 안내.

### 후속
룩북(저장한 룩 묶음)·공유 이미지 카드, 아이템 구매 링크 연동(쇼핑 API), 다중 인물, 체형 분석 리포트.

## 4. 아키텍처
- Next.js 16 App Router + TS, 순수 CSS, `ui-canvas`/`music-player` 패턴 재사용(접근 게이트·사이드바·키 관리·`/open` 진입).
- 서버 API(전부 `checkProgramAccessApi` + `force-dynamic`): `POST /api/ai/recommend`, `/api/ai/item-image`, `/api/ai/tryon`, `/api/ai/beauty-advice`, `/api/ai/beauty-apply`, `/api/ai/item-name`, `GET /api/fetch-image`(SSRF 방어: http/https만, 사설 IP·메타데이터 주소 차단, 크기·시간 제한, 이미지 MIME만), `/api/keys`.
- `src/lib/gemini.ts`: 프롬프트·스키마·모델 선택·오류 매핑(키 오류/한도/안전 필터/타임아웃)을 한곳에. 프롬프트에 `[기준 연도: ${currentYear}년]`·한국인 기본 인물 규칙 주입, 응답 JSON 검증(원본은 길이만 확인).
- 클라이언트: 상태 reducer + 히스토리, IndexedDB(`idb`, 회원별 DB), 이미지 처리 유틸(축소·종횡비 선택·비교 슬라이더).
- 이미지 전송량: 입력 ≤1600px JPEG(~0.3–0.8MB), 응답 base64 ~1–2MB → Vercel 4.5MB 한도 안. `maxDuration` 60.
- 비용 안내 UI: 작업별 예상 호출 수 표시(추천 ≈ 이미지 4~6회 등), 본인 키 사용량이라는 점 명시.

## 7. 리스크
1. **안전 필터 거부**(실제 인물 편집): 거부 사유를 분류해 안내하고 재시도 가이드(정면·밝은 사진), 자동 우회 프롬프트는 쓰지 않는다.
2. 모델명/가용성 변동: 상수화 + 사용 불가 시 Standard로 폴백하고 안내.
3. 이미지 생성 지연·한도(429): 병렬 2·백오프·취소, 진행 표시.
4. 개인정보: 서버 비저장·로그에 이미지 미기록, 동의 체크·고지 문구, 에러 로그에도 이미지 데이터 제외.
5. 외부 이미지 URL 가져오기 악용(SSRF): 서버 프록시에 강한 제한과 속도 제한.

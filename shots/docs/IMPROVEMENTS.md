## 1. 3대 관점 분석 및 개선 아이디어

### ① 프로그램 개발 및 유지보수 관점 (로직/안정성/재사용)
- **비디오 렌더링 큐 시스템 도입**: Remotion 영상 합성은 서버 CPU/메모리 부하가 높으므로, 동시 요청 시 Vercel 서버리스 람다 제한(300초)을 피할 수 있도록 비동기 작업 큐 및 웹훅 콜백 체계 도입 검토.
- **이미지 생성 실패 시 자동 재시도 & 캐싱**: 나노바나나 2.1 API 호출 중 일시적 네트워크 타임아웃 발생 시 씬별 단위로 캐싱하여 성공한 이미지는 재호출하지 않고 실패한 씬만 재시도하는 로직 고도화.
- **공용 YouTube OAuth 모듈 연계**: 현재 프로그램 내 개별 OAuth 콜백을 공용 `insta_accounts`와 유사한 `youtube_channels` 중앙 테이블로 점진 통합하여 타 유튜브 자동화 프로그램과 연동 계정 공유 지원.

### ② 디자인 및 UX 관점 (가독성/조작/작업 흐름)
- **유튜브 스튜디오 감성 완벽 일체화**: 사용자의 "유투브 느낌을 살려줘" 지시를 충실히 반영하여 옵시디언 다크(`#0f0f0f`), 스튜디오 서피스(`#181818`), 유튜브 레드(`#ff0000`) 알약형 토큰 시스템 완성.
- **5단계 파이프라인 시각화**: 좌측 사이드바에 1~5단계 번호형 스텝퍼를 배치하여 사용자가 현재 쇼츠 제작의 어느 단계에 있는지 즉시 직관적으로 인지.
- **독립 비주얼 가이드북 (`/guide`) 신설**: 5단계 제작 흐름, 9:16 프롬프트 매트릭스 표, 3대 오디오 팁, FAQ 5종 레드 아코디언을 제공하여 신규 사용자 진입 장벽 대폭 해소.

### ③ 기존 AIMaster에 없던 창의적 자동화 시스템 관점
- **AI 훅(Hook) A/B 스플릿 테스터**: 하나의 쇼츠 소재로 초반 3초 훅 3종을 동시 생성하고, 클릭률(CTR)과 시청 지속 시간이 가장 높을 것으로 예측되는 베스트 훅을 AI가 점수화하여 자동 추천하는 기능.
- **음악 비트 자동 싱크 컷 편집(Auto Beat-Sync Editor)**: Suno AI가 생성한 BGM의 드럼 킥과 베이스 드롭 타이밍을 파형 분석하여 6개 씬의 전환 타이밍을 밀리초(ms) 단위로 완벽하게 자동 정렬하는 하이퍼 싱크 시스템.
- **쇼츠 ➔ 릴스 ➔ 틱톡 동시 원클릭 배포기**: 완성된 MP4를 한 번에 3대 숏폼 플랫폼 규격에 맞춰 제목, 해시태그를 플랫폼별로 자동 최적화 변환하여 동시 예약 게시하는 멀티 플랫폼 디스패처.

## 2026-10-20 (Claude Code 윈도우) — Facebook 로그인 앱 키 이름 불일치
- 근거: INSTA 포스팅은 Facebook 로그인에 `facebook_app_id`(없으면 `meta_app_id`), 이 프로그램은 `meta_app_id`만 쓴다(`src/app/api/instagram/callback/route.ts`, `lib/actions/instagram.ts`). `meta_app_id`는 원래 Instagram 앱 칸이라 회원이 두 프로그램에 다른 값을 넣어야 할 수 있다.
- 영향: 중간(혼동). 상태: ✅ 처리(v1.23, 2026-10-20) — Facebook 앱 칸 먼저, 없으면 예전 Meta 칸. 다음 첫 단계: 이 프로그램 설정 화면에 `facebook_app_id` 칸을 INSTA와 같은 순서로 읽게 바꾸는 플랜.

## 2026-10-21 (Claude Code 윈도우) — 브라우저에서 만들기 뒤 남은 개선
- **Suno 배경음악 주소 만료**(로직, 높음): `shorts_bgm_tracks.audio_url`이 `tempfile.aiquickdraw.com` 임시 주소라 운영 2건 모두 404(2026-10-21 확인). 브라우저 만들기는 음악 없이 만들고 경고, JSON2Video 합성은 실패할 수 있음. 제안: 음악 생성 완료 때 파일을 저장소(`shots-bgm`)로 옮겨 저장. 상태: 미착수.
- **음성 지연**(로직, 중간): `gpt-4o-mini-tts`가 가끔 한 장면만 60~90초 늦음 → v1.26에서 30초 제한·1회 재시도로 보완. 계속되면 `tts-1`로 다시 시도하는 안 검토. 상태: 보완됨, 관찰.
- **장면 음성 다시 쓰기**(편의, 중간): 다시 만들 때마다 음성 6회를 새로 만든다(약 10원). 대사가 안 바뀐 장면은 음성을 저장소에 두고 재사용하면 비용·시간 절약. 상태: 제안.
- **연계**: 원스톱처럼 렌더 화면에서 바로 「유튜브에 올리기」(브라우저 직접 PUT, `createYoutubeResumableSession`)를 붙이면 서버가 영상을 다시 받지 않아도 됨. 상태: 제안.

- (2026-10-21 v1.27 처리) Suno 배경음악 주소 만료 → 서버 저장·임시 주소 저장 안 함으로 보완(이미 만료된 운영 2건은 복구 불가 — 배경음악을 다시 만들어야 함). 장면 음성 다시 쓰기 → 보관·재사용으로 처리(2회째 OpenAI 0회·시간 절반).
- 남은 점(2026-10-21): 배경음악 트랙 파일(`shots-bgm/<회원>/<영상>-*.mp3`)은 30일 자동 삭제 대상이 아님 — 최상위 규칙(생성 데이터 30일)에 맞추려면 트랙 행과 함께 지우는 정리 추가 필요. 상태: 검토 대기.
- **유튜브 연결 버튼 찾기 어려움**(UI, 높음, 2026-10-21 주인님 「유투브 연동 버튼이 없어 어디서 하는거야」): 연결·재연동 버튼이 설정 화면에는 없고 영상마다 있는 「유튜브 쇼츠 업로드」 칸에만 있으며, 상태 표시(`미게시`·`연동중`)와 같은 작은 알약 모양이라 버튼으로 보이지 않음. 제안: ① 설정(API키등록·플랫폼연동)에 「유튜브 채널 연결」 칸(상태·연결/재연동 버튼) 추가 ② 「연결이 만료되었습니다」 안내 상자 안에 큰 「다시 연결하기」 버튼 ③ 상태 표시와 버튼 모양 구분. 상태: 미착수.
- 업로드 기록 칸: Shots는 영상당 유튜브 결과를 한 칸(`youtube_video_id`)만 저장 — 다시 올리면 덮어씀. 원스톱처럼 올린 기록 목록이 있으면 좋음. 상태: 제안.

## 1. 문제와 목표
지금 알림은 수집할 때마다 「이번 회차 변동」만 보낸다. 한 주 동안 단지 시세가 어떻게 움직였는지는 회원이 웹 통계 화면을 직접 열어야 안다.
→ **일주일에 한 번, 감시 단지들의 7일 변화를 한 장으로 정리해 텔레그램·메일·카톡으로 보내 준다.**

## 2. 이미 있어서 그대로 쓰는 것
| 있는 것 | 위치 | 주간 리포트에서 |
|---|---|---|
| 1년치 통계 기록(`history`)·변동 기록(`eventLog`) | `extension/lib/stats.js` | 7일 전과 지금 비교 |
| 7일 변화 숫자 만들기 | `extension/lib/aiSummary.js` `buildAiInput` | 단지별 매물 수·매매 평균 변화·새/내림/오름/사라짐 합계·실거래 대비 |
| AI 요약(회원 본인 키) | `makeAiSummary` | 주간용 긴 프롬프트(400자)만 추가 |
| 여러 번 내린 매물·오래 안 팔린 매물 | `lib/repeatDrops.ts` · `extension/lib/stale.js` | 상위 3건씩 첨부 |
| 텔레그램·메일·카톡 보내기 | `deliver` · `lib/notify.js` | 같은 채널로 보냄 |

## 3. 동작
1. **보내는 때**: 회원이 고른 요일(기본 월요일)의 **그날 첫 수집이 끝난 뒤 1번**. 새 타이머는 만들지 않고 기존 예약 수집에 붙는다.
   - 그날 PC가 꺼져 수집이 없으면 그 주 안의 다음 수집 때 보낸다(놓치지 않음). 같은 주에는 두 번 보내지 않는다(`weeklySentWeek` 기록).
   - 기록이 7일치가 안 되면 「기록 n일치 기준」이라고 밝히고 보낸다. 2회 미만이면 보내지 않는다.
2. **내용**(숫자는 확장이 계산, AI 없이도 완성)
   - 단지마다: 지금 매물 수(7일 전보다 ±) · 매매 평균(±%) · 7일간 🆕 새 매물 / 📉 내림 / 📈 오름 / 👋 사라짐 · 실거래 대비 평균
   - 📉 여러 번 내린 매물 상위 3 · ⏳ 오래 안 팔린 매물 상위 3(네이버 바로가기)
   - 🤖 AI 주간 요약(AI 키를 등록하고 켠 회원만, 400자 안, 투자 권유 금지·당해 연도 기준 — 기존 프롬프트 규칙 그대로)
3. **채널별 모양**
   - 텔레그램: 전체 글
   - 메일: 같은 내용을 표 모양 HTML로
   - 카톡: 200자 요약 + 「결과 보기」 버튼(웹 통계 화면으로)
4. **설정**: 웹 「⏰ 예약 설정」(또는 받는 곳) 화면에 「📅 주간 리포트 받기」 켜기·끄기 + 요일 고르기
5. **웹**: 통계 대시보드 맨 위에 「📅 지난 주간 리포트」 접는 상자(확장이 마지막으로 보낸 리포트를 그대로 보여 줌)

## 4. 개인정보·규칙
- 매물 정보는 지금처럼 회원 PC 안에서만 계산하고 서버로 보내지 않는다. AI에는 숫자 통계만 보낸다(중개사 이름·전화번호 제외 — 기존 시험이 확인 중).
- AI는 회원 본인 키만 쓴다(운영자 키 폴백 없음).

## 5. DB 변경(승인 필요)
`realty_alert_settings`에 칸 2개 추가 — `notify_weekly boolean not null default false`, `weekly_day smallint not null default 1 check (weekly_day between 0 and 6)`.
설정 읽기 API(`/api/extension/settings`)가 두 값을 확장에 넘긴다. 옛 확장은 이 값을 모르므로 아무 일도 없다(하위 호환).
> DB 없이 하는 대안: 「월요일 고정·AI 요약을 켠 회원만 자동」으로 칸 추가 없이 만들 수 있다. 다만 회원이 끄거나 요일을 바꿀 수 없다.

## 6. 구현 순서
1. `extension/lib/weekly.js` — `buildWeeklyReport(history, eventLog, states, now)` → { 텍스트, HTML, 카톡 글 } (순수 함수) + 시험
2. 주간 AI 프롬프트(`buildWeeklyPrompt`, 400자) + 시험
3. `background.js` — 수집 끝에 「주간 보낼 때인가」 판단(`shouldSendWeekly`) → 보내기 → `weeklySentWeek`·`weeklyReport` 저장, 기록 줄 「📅 주간 리포트를 보냈어요」
4. 마이그레이션·설정 API·설정 화면 켜기/요일
5. 통계 대시보드 「지난 주간 리포트」 상자
6. 시험·tsc·빌드 → v1.33 배포(미배포 대기 3건과 함께) → DB 버전·확장 검증

## 7. 검수
- 로컬 시험: 요일·주 계산(일요일 넘어감, 놓친 날 다음 수집), 기록 부족, 같은 주 두 번 막기, 글자 수 제한
- 실물: 시험 계정에서 요일을 오늘로 바꾸고 「지금 수집」 → 텔레그램·메일·카톡 도착을 크롬 작업 창과 받은 메시지로 확인 → 요일 원래대로

## 1. ① 숫자 판정 기준 조절 (바로 구현)

## 2. ② 한글 개인정보(이름·주소) 가리기 — 검토 결과
| 항목 | 내용 |
|---|---|
| 모델 | PaddlePaddle 공식 `korean_PP-OCRv5_mobile_rec_onnx` — `inference.onnx` **13.4MB**, 글자 목록은 `inference.yml`(96KB) |
| 라이선스 | **Apache-2.0**(상업 이용 가능, 고지 필요), 내려받기 제한 없음(gated 아님) |
| 다른 후보 | `korean_PP-OCRv3_mobile_rec_onnx`(9.9MB, Apache-2.0, 개인 변환본) — 공식이 아니라 제외 추천 |
| 방식 | 지금의 글자 자리 찾기(PP-OCRv4 det) → 각 자리를 한국어 모델로 읽기 → 규칙으로 고르기: **주소** = 시·도·구·군·동·읍·면·로·길·번지 + 숫자 / **이름** = 「받는분·수령인·보내는분·성함·이름·고객명」 옆 한글 2~4자 / **전화번호** = 지금처럼 숫자 규칙 |
| 비용·부담 | 회원 브라우저가 첫 1회 약 13.5MB 더 받음(무료), AI 호출 없음 |
| 한계 | 손글씨·작은 글씨·기울어진 송장은 잘 못 읽음. 규칙은 「가릴 후보」만 고르므로 회원이 미리보기에서 확인·추가·빼기 필요 |
| 추천 | **구현해도 됨** — 「숫자 자리만」 옆에 「이름·주소도」 선택을 추가(기본 끔). 글자 목록은 `inference.yml`에서 뽑아 프로그램 안 작은 파일로(라이선스 고지 포함) |

## 3. ③ 되돌려 넣기 확대(카드뉴스·인스타 게시 이미지) — 보류 필요
- 대상 `insta_auto_poster`(INSTA 포스팅·카드뉴스)는 작업 중 표에 **디자인 담당(agy) 줄이 「진행 중」**(2026-10-25, 7대 플랫폼 키 버튼·3D 실행 버튼, 완료 표시 없음). 같은 폴더 동시 작업 금지 규칙에 걸림.
- 방식(준비만): 바나나 쪽은 지금 `nukki-handoff`를 넓혀 보낸 곳 주소를 둘 이상 허용하는 공용 약속으로 일반화(`image-return-handoff` 가칭) → INSTA 「새 글」 첨부 이미지 옆 「✂ 누끼」/「🙈 가리기」 → 결과를 첨부 이미지로 되돌림.
- **agy 작업이 끝나거나 주인님이 끝난 것으로 확인해 주시면** 착수.

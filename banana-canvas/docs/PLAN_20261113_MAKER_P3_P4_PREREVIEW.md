## 2. P3 — 사진을 어디서 받을 수 있는가(경로별 판정)

| 경로 | 되는가 | 위험·제약 | 판정 |
|---|---|---|---|
| A. 내 PC 파일 | 됨(P1 배포) | 없음 | **유지(기본)** |
| B. 상세페이지에 이미 올린 사진 | 됨(P2 배포) | 없음 | **유지(기본)** |
| C. 브라우저에서 이미지 주소 직접 받기(`fetch`) | 대부분 안 됨 — 마켓 이미지 서버는 교차 출처 허용이 없어 캔버스에 그리면 저장이 막힘 | 주소 만료·403·HTML 응답 | **하지 않음**(되는 서버만 되는 기능은 혼란) |
| D. 우리 서버가 대신 받기(프록시) | 기술로는 됨 | 내부망 접근·대용량·리다이렉트 악용, **우리 서버 고정 IP로 수집**(마케팅 수집 예외 조항의 「회원 기기에서만」 원칙과 충돌), 서버 비용 | **하지 않음**(v1.15에서 닫은 빈틈을 다시 여는 것) |
| E. 소싱 확장이 회원 PC에서 받기 | 됨 — 확장은 회원 브라우저·회원 IP로 화면에 보이는 사진을 받을 수 있음 | 확장 권한 추가(이미지 서버 주소), 확장 새 버전·ZIP·DB 버전, 마켓 약관, **남의 상품 사진 재사용 권리** | **조건부 후보** — 아래 결정 1·2가 「예」일 때만 |
| F. 공급사가 준 사진 묶음(ZIP·폴더)·공급사 공식 API | 됨 — ZIP은 지금도 풀어서 A 경로로 가능, API는 공급사별 | 공급사마다 형식 다름 | **1순위 추천** — 「ZIP 그대로 넣기 + 폴더 이름=상품코드」만 추가(작음) |

### P3 추천 범위(작게)
1. **F-1 ZIP·폴더 넣기**: 바나나 상품 합성에 「ZIP 파일 넣기」(브라우저에서 풀기, 이미 `jszip` 사용 중)와 폴더 끌어놓기 — `상품코드/main.jpg`, `상품코드/sub1.jpg` 구조면 폴더 이름을 코드로. 순수 함수 `rowsFromFolderPaths` 추가 + 시험. 서버·DB·비용 없음.
2. **소싱 → 상세에 대표 썸네일 「참고로만」 넘기기는 하지 않음**: 등록용 사진과 참고 사진의 권리 구분이 흐려짐.
3. E(확장 받기)는 결정 1·2 뒤 **사전 검증 페이지**로 먼저(되는지·해상도·차단 여부), 통과하면 별도 플랜.

### P3 권리·정책 메모
- 「내려받을 수 있다」는 「상품 사진을 다시 써도 된다」가 아니다. 화면 문구에 「공급사가 허용했거나 본인이 찍은 사진만 등록용으로 쓰세요」를 넣고, 남의 판매 페이지 사진은 **참고 자료**로만(합성 입력으로 자동 연결하지 않음).
- 확장 수집은 [`docs/MARKETING_AUTOMATION_EXCEPTION_POLICY.md`](../../docs/MARKETING_AUTOMATION_EXCEPTION_POLICY.md)의 지정 프로그램 여부부터 확인(소싱이 지정돼 있는지, 사진 받기가 범위에 드는지).

## 3. P4 — E2(키워드·등록 초안)와 성과 연결

| 조각 | 지금 | 필요한 것 | 걸림돌 |
|---|---|---|---|
| 검색 표본(상위 N개) | 소싱 확장이 쿠팡·네이버 쇼핑 **회원이 연 검색 화면**을 읽음 | 표본에 카테고리 경로·상품명 낱말을 함께 저장(회원 본인 결과, 30일) | 화면 구조 변경에 약함, 표본 크기·광고 포함 여부 기록 필요 |
| 카테고리 분포 | 없음 | 표본의 카테고리 경로 집계(브라우저 계산, AI 0) | 마켓별 분류 ID를 하나로 합치지 않기 |
| 연관어·자동완성·태그 근거 | 없음 | 표본 상품명에서 낱말 빈도(브라우저 계산) / 네이버 검색광고 키워드 도구는 **회원 본인 키**로만(무료지만 계정 한도가 있어 공용 키 금지) | 종료된 쇼핑 검색 API 대체 자료의 현재 제공 여부 확인(30일 넘은 정보는 다시 확인) |
| 상품명·태그 초안 | 상세 `CopyTonePanel`(상품명 후보 3)·`analyzeByNameAction` | 근거 낱말을 입력으로 받는 선택 기능(회원 본인 Claude/Gemini 키 1회) | 새 AI 호출은 비용 안내 + 회원이 켬 |
| 초안 검사 | 태그 길이 검사만 | 금지어·상표·중복·길이·광고 문구 검사(규칙 기반, AI 0) | 마켓별 규칙표 유지 비용 |
| 성과 연결(소싱 예상마진 ↔ 실제 손익) | 주문리포트는 상품명+옵션 집계(회원 PC 로컬) | 내부 상품 ID로 잇기 | 주문리포트 로컬 자료를 서버로 올리지 않는 원칙 유지 → 회원 브라우저 안에서만 대조 |

### P4 추천 순서(각 단계 별도 플랜·결정)
1. **E2-0 자료 확인(문서만)**: 표본에서 실제로 읽을 수 있는 칸, 네이버 키워드 도구·쇼핑 인사이트의 현재 제공·약관·한도. 비용 0.
2. **E2-1 표본 요약(AI 0)**: 소싱 결과 화면에 「카테고리 분포·많이 쓰인 낱말」 카드. 확장 변경 없이 이미 모은 결과로 가능한지부터.
3. **E2-2 초안·검사**: 근거 낱말 → 상품명/태그 초안(선택, 회원 본인 키) + 규칙 검사.
4. **E2-3 넘기기**: 소싱 → 상세 → 등록기에 카테고리·태그·근거를 함께(지금은 이름·가격만). 상세 `shop_products`에 칸이 필요하면 DB 결정.
5. 성과 연결은 E2-3 뒤.

## 4. 재사용·담당

- 재사용: 소싱 확장·`sourcingResults.ts`, 상세 `CopyTonePanel`·`copyTonePrompt.ts`·`detailBlocks.ts`(위험 문구 거르기), 등록기 카테고리 추천, 바나나 `productJobs.ts`.
- 담당: 기능·계약 A, 화면 agy, 수집·저장 정책 policy(C), 검수 Codex. 소싱·등록기 폴더는 `claude-win-sdp` 작업 중 표를 먼저 확인.

## 5. 결정 항목(주인님)

1. **확장으로 마켓 사진 받기(P3-E)를 검토 대상에 둘지**: 두지 않음(추천 — 권리·약관 위험, ZIP·폴더로 충분) / 사전 검증 페이지까지만 / 진행.
2. 소싱 프로그램이 마케팅 수집 예외 「지정 프로그램」인지, 사진 받기가 그 범위인지(1번이 「진행」일 때만).
3. **P3-F-1 ZIP·폴더 넣기를 바로 만들지**: 만듦(추천 — 작고 비용 0, 다음 바나나 배포 때 함께) / 보류.
4. **P4를 지금 시작할지**: E2-0 자료 확인만 먼저(추천, 문서만) / E2-1까지 / 보류.
5. E2 초안에 쓸 AI: 회원 본인 Claude(추천, 기본 AI 규칙) / 기존 Gemini 유지.

# SEO 블로그 데이터 보관·삭제 정책

최종 갱신: 2026-10-01 / 적용 버전: v1.57

## 보관 대상과 기간

| 대상 | 보관 기간 | 삭제 시 함께 정리되는 항목 |
| --- | --- | --- |
| 블로그(원문) 초안 | 생성일 기준 30일 | 제목, 본문, 키워드, SEO 메타데이터, 확장 전송·입력 상태, 대표 이미지, 본문 매칭 이미지 |
| 제목 추천 기록 | 생성일 기준 30일 | 추천 제목·주제·키워드 정보 |
| URL 재작성 분석 원문 | 보관하지 않음 | 외부 URL의 HTML·원문 문장은 DB에 저장하지 않음 |

## 정리 실행 시점

- Vercel Cron: 매일 `/api/cron/draft-retention` 실행
- 새 블로그(원문) 생성 전: 해당 회원의 만료 초안 정리
- 생성 기록 조회 전: 해당 회원의 만료 초안 정리
- 제목 추천 생성 전: 해당 회원의 만료 제목 추천 기록 정리
- 한 번에 최대 500개 초안과 제목 추천 기록을 처리합니다.

## 이미지 삭제 규칙

- 이미지 버킷은 비공개 `naver-blog-seo-images`입니다.
- 만료 초안 또는 직접 삭제한 초안에서는 `image_path` 대표 이미지와 `seo_report.contentImages`에 기록된 모든 본문 매칭 이미지 경로를 모아 함께 삭제합니다.
- Storage 이미지 삭제가 실패하면 초안 DB 삭제를 중단합니다. 따라서 다음 정리 주기에 안전하게 재시도할 수 있으며, DB 레코드만 먼저 사라져 이미지가 고아 파일이 되는 상황을 막습니다.
- 이미지 재생성·본문 일반 수정으로 이미지가 교체되는 경우에도 기존 이미지 경로는 즉시 제거합니다.

## 접근·전송 원칙

- 초안 테이블과 Storage 객체는 `user_id` 기준 RLS/소유자 정책으로 분리합니다.
- 이미지 Storage는 공개 URL을 사용하지 않으며, 권한을 확인한 웹·확장 API가 필요한 이미지 데이터만 반환합니다.
- Chrome 확장에는 연결 토큰과 카테고리·태그 설정만 브라우저 저장공간에 남습니다. 선택한 블로그(원문)·이미지는 사이드패널 실행 중 메모리에만 유지됩니다.

## 운영 주의

- 30일이 지나면 콘텐츠와 생성 이미지를 복구할 수 없습니다. 장기 보관이 필요한 원문은 네이버 발행 전 별도 저장해야 합니다.
- 정책 변경 시 `lib/draftRetention.ts`, `vercel.json`, 이 문서, `README.md`, `CLI_HANDOFF_2026-10-01.md`를 함께 검토합니다.

# 네이버 블로그 SEO 스튜디오

## 프로그램 버전

- 회원용 앱·확장 프로그램 공개 버전: `v1.53` (`lib/version.ts`의 `APP_VERSION`, 공용 `programs.version`, 확장 `manifest.json`의 `version_name`, 다운로드 ZIP을 같은 값으로 유지)
- 최신 CLI 인수인계: [`CLI_HANDOFF_2026-10-01.md`](./CLI_HANDOFF_2026-10-01.md)
- 작은 기능·화면·버그 수정 배포마다 두 공개 버전을 함께 `0.01` 올립니다. 메이저 버전은 주인님 지시가 있을 때만 올립니다.
- Chrome 확장의 `manifest.json.version`은 기존 설치본보다 높은 숫자가 필요한 내부 업데이트용 값이며, 공개 버전은 `version_name`을 기준으로 표시합니다.

`naver-blog-auto-poster_app`과 `naver-blog-auto-poster_web`을 수정하지 않고 새로 시작하는 독립 서브프로젝트입니다.

## 제품 방향

AI가 네이버 블로그 글의 기획·초안·SEO 점검을 돕고, 사용자가 사실을 검수한 뒤 네이버에서 직접 발행하는 콘텐츠 제작 스튜디오입니다. 자동 로그인, 자동 발행, 대량 댓글·공감·이웃추가 기능은 기본 범위에 포함하지 않습니다.

## 1차 구현 상태

- 새 글 기획 화면(주제·키워드·전략 선택) 골격 구현
- C-Rank 기본, ALCON, AEO, 홈판 스토리, 인사이트 엣지 전략 선택 UI
- 사실 확인·사람의 최종 발행 원칙을 화면에 명시
- 공용 Supabase 권한 게이트와 `/api/drafts/generate` 초안 생성 API 골격 구현
- 실제 AI 호출은 사용자가 등록한 OpenAI 키가 있을 때만 실행되며, 현재 테스트에서는 외부 AI 호출을 실행하지 않음

## 글쓰기 페르소나 초안 생성

- `새 글 만들기` 화면에서 글쓰기 전략 아래의 **글쓰기 페르소나 선택**으로 본문 초안의 말투와 관점을 선택한다.
- 기본 프리셋은 정보 전달형 전문 에디터, 솔직한 실사용 후기형, 친근한 초보자 안내형, 자영업자·브랜드 운영자 관점, 꼼꼼한 비교·정리형, 따뜻한 일상 스토리형이다.
- 필요하면 커스텀 페르소나에 독자 대상·말투·설명 방식을 500자 이내로 직접 입력할 수 있다.
- 선택값은 `/api/drafts/generate`에서 서버 검증 후 OpenAI 초안 프롬프트에 반영된다. 확인되지 않은 개인 체험이나 사실은 만들지 않고 `[확인 필요]`로 남기는 규칙은 모든 페르소나에 적용된다.
- 콘텐츠 기획·생성은 웹 스튜디오에서만 수행합니다. Chrome 확장은 전송된 완성 초안을 네이버 편집기에 입력하는 역할만 맡습니다.
- 제목 추천에서 제목을 선택해 생성하는 본문은 공백 제외 2,000~3,500자를 기준으로 한다. 4개 소제목, 실무 흐름·선택 기준·점검 방법을 포함한 완성형 초안을 만들고, 기준에 못 미치면 짧은 글을 저장하지 않고 다시 생성하도록 안내한다.

## 기존 글 최적화 3가지 모드

`/dashboard#draft`에서 다음 작업 방식을 제공합니다.

1. **내 글 바로 최적화** — 직접 붙여넣은 원문의 의미와 확인 가능한 사실을 유지하면서 제목·문단·키워드 흐름을 다듬는다. 최근 30일 생성 기록에서 기존 초안을 선택하면 저장된 제목·본문·키워드를 자동으로 불러온다. 결과는 새 초안으로 저장해 대표 이미지 생성과 Chrome 확장 전송까지 이어갈 수 있다.
2. **붙여넣기 분석 후 재작성** — 원문에서 핵심 주제, 핵심·연관 키워드, 검색 의도, 독자 대상, 강점·보완점과 추천 구조를 추출한다. 사용자가 주제·키워드를 수정·확인한 뒤 원문 문장을 복제하지 않는 새 SEO 초안을 만든다.
3. **URL에서 가져와 재작성** — 공개 HTML 블로그 글에서 핵심 주제·키워드·구조만 임시 분석해 새 초안을 만든다. 원문은 서버 DB에 보관하거나 문장 그대로 복제하지 않는다. 사설망·localhost·비표준 포트·과도한 리디렉션·대용량 응답은 차단하며, 로그인·유료벽·접근 제한 글은 직접 붙여넣어야 한다.

세 모드 모두 OpenAI API 키는 해당 회원의 키만 사용합니다. 최신 수치·가격·정책·의학·법률 정보는 결과를 발행하기 전에 사용자가 직접 확인하며, Chrome 확장은 최종 네이버 발행 버튼을 자동으로 누르지 않습니다.

## 생성 기록 관리

생성 기록은 최근 30일간 보관합니다. 제목·주제·키워드 검색, 오늘·최근 7일·최근 30일 기간 필터, 확장 입력 상태 필터를 제공하며, 복제는 원본을 보존한 새 초안을 만들고 대표 이미지는 복제하지 않습니다.

## 선택형 3장·4장 이미지와 블로그(원문) 편집기

- 기본 구성은 대표 이미지 1장과 본문 핵심 문장 이미지 2장(총 3장)이며, 생성 전에 대표 1장과 본문 핵심 문장 이미지 3장(총 4장)을 선택할 수 있습니다.
- 본문 이미지는 서로 다른 핵심 문장을 기준으로 해당 문장 바로 위에 배치합니다. 각 본문 이미지 카드는 기준 문장과 위치를 유지한 채 해당 이미지 한 장만 다시 생성할 수 있습니다.
- 본문 이미지의 실제 삽입 위치는 핵심 문장이 포함된 **문단의 시작 전**입니다. 문단 중간을 자르지 않고 문단 전체를 설명하는 이미지로 배치합니다.
- OpenAI가 완성된 본문에서 시각적으로 의미가 분명한 핵심 문장 2개 또는 3개를 서로 다른 섹션에서 고르고, Gemini 나노바나나가 각 문장만 묘사하는 16:9 이미지를 생성합니다.
- 이미지의 문장·삽입 순서·비공개 Storage 경로는 해당 초안의 SEO 메타데이터에만 보관합니다. 공개 URL이나 다른 회원의 이미지 경로는 노출하지 않습니다.
- `새 글 만들기`의 **블로그(원문) 편집기**에서 문단 텍스트를 직접 수정하고, 대표·본문 이미지를 위아래로 옮기거나 전송에서 제외할 수 있습니다.
- 저장하면 텍스트와 이미지의 최종 순서를 초안 메타데이터에 블록으로 보관합니다. Chrome 확장은 블록이 있는 초안은 문장 검색에 의존하지 않고 이 순서 그대로 네이버 편집기에 입력합니다. 최종 네이버 발행 버튼은 자동으로 누르지 않습니다.
- 기존 초안처럼 일반 본문 편집기만 수정한 경우에는 문장과 이미지의 불일치를 막기 위해 기존 본문 이미지를 자동 삭제하고 다시 생성합니다. 블로그(원문) 편집기에서 명시적으로 저장한 블록은 사용자가 정한 이미지 위치를 보존합니다.
- 이 기능은 회원 본인의 OpenAI 키(문장·프롬프트 분석)와 Gemini 키(이미지 생성)만 사용합니다.
- 제목 선택 뒤 **대표 이미지 생성 (나노바나나)** 박스 오른쪽에서 이미지 생성 모델을 선택합니다. 선택값은 대표 이미지, 본문 핵심 문장 이미지, 개별 이미지 재생성에 동일하게 적용됩니다. `API키등록·플랫폼연동` 화면은 API 키 등록만 제공합니다.
- 대표 이미지 생성 박스 바로 위에서 콘텐츠 생성 플랫폼(OpenAI)과 모델을 고릅니다. 기본 모델은 GPT-4.1이며, 선택 모델은 제목 선택 뒤 생성하는 완성형 블로그(원문)의 본문 생성에 적용됩니다.
- 이미지 모델 선택은 최초 생성 단계 한 곳으로 통합합니다. 이 Gemini NanoBanana 선택값은 최초 대표·본문 이미지 생성과 생성 후 이미지 재생성에 함께 적용됩니다.
- `새 글 만들기`의 본문 이미지 영역은 자동 생성 선택(좌측)·이미지 모델(우측), 그 아래 총 이미지 구성, 그 아래 본문 이미지 생성 버튼 순으로 표시합니다. 본문 문장 매칭 제목은 좌측, 설명은 우측에 표시합니다.

## 확장 프로그램 전송 콘텐츠 미리보기 (현재 공개 버전 v1.14)

- `전송된 콘텐츠 목록 새로고침`은 웹에서 전송한 콘텐츠의 **목록만** 가져옵니다. 목록에서 하나를 선택하면 이미지·입력 대상이 자동으로 준비되고, `전체 포스팅 미리보기` 팝업에서 제목·본문·이미지 순서를 확인한 뒤 바로 네이버 편집기 입력을 실행할 수 있습니다.
- 불러온 제목·본문·대표 이미지·본문 이미지는 전체 포스팅 미리보기 팝업에서 입력 순서 그대로 확인할 수 있습니다.
- 확장 목록에는 준비된 이미지 장수를 표시합니다. 선택한 대표·본문 이미지 구성이 모두 준비되지 않은 블로그(원문)은 웹에서 전송하지 않도록 막아, 본문만 전달되는 상황을 예방합니다.

## 카테고리·태그 설정 자동 준비 (현재 공개 버전 v1.14)

- 저장된 카테고리·태그가 있으면 콘텐츠·이미지 입력과 DOM 검증이 끝난 직후, 확장이 편집기 화면의 첫 발행 버튼 후보를 하나로 확인해 설정창을 자동으로 엽니다.
- 설정창이 열린 것을 태그 입력란으로 확인한 뒤 카테고리·태그를 입력하고 웹 기록에 `최종 발행 준비 완료` 상태를 남깁니다. 자동 입력이 실패하면 확장의 `카테고리·태그 다시 입력` 버튼으로 재시도할 수 있습니다.
- 네이버 설정창의 마지막 발행 버튼은 확장이 탐색하거나 자동 클릭하지 않으며, 사용자가 내용을 검토한 뒤 직접 클릭합니다.

## 공용 Supabase 반영 상태

- 프로그램 slug: `naver-blog-seo-studio` (개발 중 상태로 등록)
- 기본 요금제: 1·2·3개월 표준 요금제 등록
- 사용자 초안 테이블: `naver_blog_seo_drafts`
- RLS: `user_id = auth.uid()` 소유자 정책 적용
- 마이그레이션 원본: `supabase/migrations/20260921093000_register_naver_blog_seo_studio.sql`
- 대시보드: `/dashboard`에서 프로그램 권한을 확인한 뒤 접근
- 로그인: `/login`에서 AIMaster 공용 계정 사용
- API 키 설정: `/settings`에서 기존 공용 `user_api_keys`의 `openai`·`gemini` provider를 사용

## 운영 원칙

### 확장 프로그램 역할 정리 (확장 v1.05)

- 확장 프로그램에서 새 글 기획, AI 초안·이미지 생성, 본문 직접 편집, 발행 전 SEO 검토 기능을 제거했습니다.
- 웹 스튜디오에서 콘텐츠·이미지·편집·SEO 검토를 완료한 뒤, **확장으로 전송**합니다.
- 확장은 전송된 초안의 읽기 전용 미리보기, 네이버 편집기 입력, 발행 설정창 열기·카테고리·태그 입력, 구조 분석만 제공합니다.
- 사이드패널의 **웹에서 새 콘텐츠 만들기** 링크는 `/dashboard#new-draft`로 연결됩니다.

### 발행 전 SEO 검토 (웹 스튜디오)

- 확장에서 제목 길이, 핵심 키워드 반영, 본문 문단·분량, 대표 이미지, 카테고리, 태그, 사실·최신 정보 확인을 발행 직전에 점검한다.
- 제목·키워드·본문·사실 확인은 필수 항목, 대표 이미지·카테고리·태그는 권장 항목으로 구분한다.
- 검토 기능은 네이버 최종 발행 버튼을 절대 누르지 않는다. 모든 필수 항목을 통과해도 사용자가 실제 내용을 검토한 뒤 직접 발행한다.

### 이미지 생성 오류 표시 및 입력 차단 (확장 v1.0.32)

- `나노바나나 대표 이미지도 생성`을 선택한 원클릭 입력에서 Gemini 이미지 생성이 실패하면, 기존에는 초안만 입력하고 실패 원인을 숨겼다.
- 이제 Gemini의 안전한 오류 설명(HTTP 상태 포함)을 확장 상태 영역에 표시하고, 이미지가 없는 상태에서는 네이버 편집기 입력을 시작하지 않는다.
- 새 초안 요청 전에 이전 대표 이미지 미리보기를 비워, 실패한 요청이 이전 이미지로 잘못 입력되는 상황을 막는다.

### 발행 설정 검수 (v1.0.31)

- v1.0.30은 사용자 네이버 실환경에서 팝업 없이 콘텐츠·이미지 입력 완료 확인.
- 네이버 발행 버튼으로 설정창을 연 뒤 확장의 카테고리·태그 입력 버튼을 실행한다. 최종 발행은 사용자 직접 실행.
- 태그 입력 전에 카테고리를 열어 포커스를 빼앗던 버그 수정. 각 태그마다 포커스/입력란 비워짐 확인 후 카테고리를 선택한다.
- 발행 설정이 발견된 프레임만 조작하고, 글감 카테고리나 일반 li를 클릭하지 않는다.
- 중복 태그 및 앞쪽 # 정리, 30개 초과 시 안내. 카테고리는 전체 이름 우선, 부분 일치가 여러 개면 선택 중단. 선택 후 버튼 표시 검증.

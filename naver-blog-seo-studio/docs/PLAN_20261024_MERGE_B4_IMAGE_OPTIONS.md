## 원본(작업실)
- `blog-workroom/src/components/views/ImagesView.tsx`·`src/lib/actions/image.ts`: 비율 4가지(4:3·1:1·3:4·16:9), 이미지마다 표현 방식 5가지(스마트폰 생활 사진·깔끔한 정보 카드·일러스트·제품·사물 클로즈업·풍경·장소), 공통 요청 문구, **공통 참고 사진 최대 10장**(브라우저에서 긴 변 1,280px JPEG로 줄여 요청에 같이 보냄, 「본인이 쓸 권리가 있는 사진만」 안내).

## SEO 스튜디오의 현재
- 대표·본문 이미지(`lib/ai/nanoBanana.ts` `generateNanoBananaImage` ← `api/images/generate`·`regenerate-content`)는 **항상 16:9, 「사진 같은 편집 이미지」 한 가지**, 참고 사진 없음.
- 공용 사본 `lib/ai/geminiImage.ts`(기준 ai-image-studio, `gemini-image-client`)는 이미 `aspectRatio`와 참고 이미지 조각(`parts`의 `inlineData`)을 받는다 → **공용 기준 코드는 고치지 않고** SEO 호출 쪽만 고친다(이미지 프롬프트는 프로그램 고유, `docs/IMAGE_PROMPT_RULES.md` 준수 — 한국인 묘사·글자 금지 유지).

## 구현
1. `lib/imageOptions.ts`(순수 함수): 비율 4가지(기본 16:9 = 지금), 표현 방식 「기본(지금 그대로)」+작업실 5가지 — 방식마다 SEO 고유 프롬프트 한 줄. 값 검사(모르는 값은 기본).
2. `generateNanoBananaImage`에 `aspectRatio`·`style`·`refs`(최대 5장) 선택 인자: 참고 사진이 있으면 `parts`로 「참고 사진의 분위기·색감·구도만 참고, 사람 얼굴·글자·로고는 그대로 복제하지 않음」 지시와 함께 보낸다.
3. 서버(`api/images/generate`·`regenerate-content`): 값 검사, 참고 사진은 형식(JPEG·PNG·WebP)·장당 크기·개수(5) 검사. **참고 사진은 저장하지 않고 그 요청에만 쓴다**(30일 보관 규칙과 무관, 개인정보 최소화).
4. 화면(새 글 화면 이미지 영역): 「이미지 비율」·「표현 방식」 선택, 「참고 사진 첨부(최대 5장)」(브라우저에서 1,280px JPEG로 줄임, 「본인이 쓸 권리가 있는 사진만」 안내). Vercel 요청 크기(4.5MB) 안에 들도록 줄인 뒤 합계를 검사.
5. 시험: 값 검사·프롬프트 조각·참고 사진 검사(개수·형식·크기)·`parts` 구성(가짜 Gemini).

## 범위 밖
- 작업실의 「이미지마다 담당 문단·노드 편집」 구조(SEO는 이미 BLC-10 본문 이미지 노드가 있음). 참고 사진 보관함.

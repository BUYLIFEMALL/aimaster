## D-1 어조 강도 (은은하게 · 균형 · 뚜렷하게)

1. 원고 만들기·구간별 쓰기 화면의 「내 문체」 선택 옆에 3칸 선택(기본 「균형」 = **지금과 글자까지 같은 지시문**).
2. `styleSection(style, strength)` — 은은하게: 끝맺음·쓰지 않는 표현만 지키고 자주 쓰는 표현은 쓰지 않음 / 뚜렷하게: 자주 쓰는 표현·문장 리듬·독자에게 말 거는 방식을 적극 반영(사실·경험은 여전히 지어내지 않음).
3. 원고 `seo_report.style.strength`에 기록, 화면 계정 기억(기존 `savedModel` 방식).
4. 시험: 세 단계 지시문 차이·기본값 동일성(문자열 비교).

## D-2 전개 구조 선택 (8가지 + 기본)

1. 「기본(지금처럼)」 + 8가지: ① 답 먼저 ② 막힌 문제 해결 ③ 장면에서 시작 ④ 고르는 기준 ⑤ 단계별 따라하기 ⑥ 질문 이어가기 ⑦ 사실 하나에서 넓히기 ⑧ 내 관점과 이유. 설명 문구는 우리가 새로 씀.
2. 새 파일 `lib/narrativeStructure.ts`(순수 함수): 구조 ID → 목차·도입 지시 한 단락. 고정 소제목이 아니라 「풀어가는 순서」만 지시.
3. 적용: 새 글(`generateSeoDraft` options) + 구간별 쓰기 목차(`outlinePrompt`). 기본이면 지시문 변화 없음.
4. 원고 `seo_report.structure` 기록. 시험: 9개 값 검증·기본값 무변화.

## D-3 한 번에 고치기 (검수 지적 반영 + 다시 검수 비교)

1. B-1 검수 카드에 「지적 반영해 고치기」 버튼(필수만 / 필수+권장 선택). **AI 호출 없이** 서버가 `quote` → `suggestion`을 본문에서 바꿈 — 인용이 본문에 정확히 한 번 있을 때만, 겹치거나 못 찾은 지적은 건너뛰고 개수 표시.
2. 바꾸기 전 원본은 B-6 수정본 이력에 자동 보관(되돌리기 가능).
3. 이어서 자동으로 **다시 검수 1회**(회원 키 AI 1회) → 「고치기 전/후」 필수·권장 개수 비교. 필수가 늘면 「원본으로 되돌리기」를 먼저 권함. 반복 고치기는 회원이 다시 누를 때만(자동 반복 없음).
4. 선택 확장(같은 묶음): 검수 영역에 「검색 의도(첫 문단에 답이 있나)」「답변 명료성(질문에 짧게 답한 문장이 있나)」 2개 추가 — 도톨이의 SEO·GEO 점검을 우리 기준으로. 기존 6영역 결과는 그대로 읽힘.
5. 새 경로 없이 기존 `review` 경로에 `apply` 단계 추가 또는 `POST /api/drafts/[draftId]/review/apply`. 시험: 바꾸기 규칙(중복·미발견·겹침), 이력 보관, 비교 개수.

## D-4 자료 읽기 넓히기 (유튜브 자막 · PDF · 붙여넣기)

1. 유튜브 주소: 공개 자막 트랙만 읽음(로그인·비공개·자동 차단 우회 없음). **Vercel 서버에서 유튜브가 막을 수 있어 실패 가능** — 실패하면 「자막을 붙여 넣어 주세요」 칸으로 안내(제목·설명만으로 영상 내용을 쓰지 않음).
2. 텍스트 PDF: 공개 주소의 PDF에서 글자만 추출(이미지 PDF는 실패 안내). 패키지 `unpdf` 추가(서버 전용, 3MB·12초 제한).
3. 읽기 실패한 주소마다 「원문 붙여넣기」(100~20,000자) — 자료에 `kind: "paste"`로 구분 저장(「사이트 직접 확인 아님」 표시).
4. 보안: 새로 읽는 경로는 공용 기준 코드 `safe-fetch` 사본(리디렉트마다 재검사·DNS 고정)을 들여와 사용 — `check-shared-modules.mjs` 사본 목록에 등록(`undici` 7.30.0). 기존 웹 주소 읽기도 같은 사본으로 바꿀지는 시험 뒤 결정(동작 회귀 확인).
5. 시험: 주소 판별(유튜브·PDF·일반), 붙여넣기 길이, 사설 주소 차단.

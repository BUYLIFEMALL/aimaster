## SEO 스튜디오의 현재
- 문체 테이블 `naver_blog_seo_styles`: 이름·분석 결과(`profile`)·원문 예시(`samples`)·가져온 내 글(`posts`)·승인(`approved_at`·`approval_hash`).
- `lib/draftRetention.ts` `purgeExpiredStyles`: **만든 지 30일 뒤 행 전체 삭제** → 회원은 한 달마다 문체를 다시 가져와 분석·승인해야 한다(AI 비용·수고).
- 승인 지문은 분석 결과 `profile`의 정해진 항목만으로 계산(`lib/style.ts`). 글쓰기 때 문장 끝맺음은 매번 `samples`·`posts`에서 다시 찾는다(`detectEnding`).

## 구현 (A안 기준)
1. `purgeExpiredStyles`를 「삭제」 대신 **30일 지난 문체의 원문만 비우기**로: 비우기 전에 원문에서 찾은 끝맺음을 `profile.ending`에 저장(지문 계산 항목이 아니라 승인 유지) → `samples`·`posts`를 빈 배열로, `profile.sourceClearedAt` 기록. 정리 기록(`usage_logs cleanup_expired`)은 「styles」 개수 그대로.
2. 글쓰기·구간 집필(`api/drafts/generate`, `lib/outlineContext.ts`): 원문이 비었으면 `profile.ending`을 쓴다.
3. 문체 화면: 원문이 비워진 문체에 「원문 정리됨(30일) · 분석 결과는 계속 사용」 표시, 「다시 분석」은 새 글을 가져오도록 안내.
4. 회원이 직접 지우는 기능은 그대로(본인 문체 삭제). **DB 변경 없음**(`profile` JSON 안에 칸 추가).
5. 시험: 비우기 대상·끝맺음 보존·승인 유지·원문 빈 문체로 글쓰기 끝맺음(가짜 DB).

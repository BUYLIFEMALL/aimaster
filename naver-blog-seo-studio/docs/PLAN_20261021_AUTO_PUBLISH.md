주인님 최신 지시 「자동 포스팅 완성 … 이것부터 하자」에 따라 BLC-07 일반 이관보다 먼저 진행한다. SEO를 먼저 완결한 뒤 티스토리, 에이전트 실제 발행 검수 순서다. [분석/공동 인계](../../docs/analysis-blog-consolidation-20261020/HANDOFF_20261021_CLI_REFERENCE.md).

## 문제·범위

현재 SEO 확장은 원고 입력/발행 설정 뒤 마지막 버튼을 수동으로 누르도록 구성돼 있다. API의 `publish_ready` 저장은 운영 DB CHECK 허용값(`not_started/in_progress/completed/failed`)과도 다르다. 최종 발행을 누르는 동작과 실제 게시 확인/URL 저장·응답 유실 복구가 필요하다.

기존 수동 입력 경로와 생성/편집 기능을 유지하고 **대상 블로그 ID·공개 범위를 확인해 새 빈 탭에서 입력부터 실제 즉시 발행까지 수행하는 별도 자동 포스팅 조작**을 추가한다. 기존 준비 탭/원고를 사용하지 않는다. 이 단계는 즉시 공개/비공개 발행이며 예약 자동 발행은 기존 SEO 기능에 없으므로 이번에 새로 추가하지 않는다.

## 구현 순서

1. 기존 `seo_report` JSON에 원고 저장 revision·자동 발행 실행 번호/지문·writing/publishing/published/uncertain/failed 상태·결과 URL/시각을 저장한다. 새 테이블/열·RLS·계정 저장소·환경변수 변경 없이 회원 원고의 최초 30일 수명을 유지한다. 본인 확장 토큰/권한·소유자·만료를 확인하고 조건부 갱신으로 같은 원고 동시 발행을 막는다.
2. 원고/이미지/발행 대상 수정과 자동 발행 선점이 경합해도 오래된 내용이 발행되지 않게 저장 revision과 실행 잠금을 확인한다. 완료/불확실 원고 자동 재발행을 막고 결과 확인만 재시도한다. 원고 복제 시 이전 발행 실행/URL은 복제하지 않는다.
3. 확장은 새 탭의 실제 블로그 ID·빈 편집기 확인→기존 본문/이미지 입력→제목/전체 문단·사진 수 대조→분류/태그·공개 범위 적용→서버 발행 직전 ACK→최종 버튼 1회→동일 블로그/제목의 게시 URL 확인→서버 기록으로 연결한다. 최종 클릭 이후 실패는 결과 불확실로 남겨 재클릭하지 않는다. 브라우저 저장 미전송 결과를 재조회/기록할 수 있게 한다.
4. 생성 기록에 실제 발행 상태/게시 링크와 재확인 안내를 표시한다. 4단계 시각 안내·상세 단계/복사·팁/주의·설정/콘솔 직링크를 기존 매뉴얼 규격에 맞춘다. 수동 마지막 버튼 관련 옛 안내·시험은 새 조작의 범위와 구분해 갱신한다.
5. 로컬 검수→버전/manifest/ZIP 갱신→한 묶음 배포→DB 버전 메타데이터 일치→Edge 지정 일반 회원·전용 새 합성 원고 비공개 실제 자동 발행/URL·재조회 검수→인수인계·커밋/푸시. SEO 완료 보고 뒤에 티스토리 작업을 시작한다.

## 검수·비용·주의

- 기존 무료 회귀와 새 상태 전이/동시 실행/다른 회원·만료/변경 후 발행 차단/응답 유실/중복 발행·URL 검증 시험. 실제 실행 함수/가짜 DOM 검사를 실제 회원 발행 시험과 구분한다.
- 기존 확장 회귀는 Chrome/headless를 기본으로 실행하는 스크립트였다. 앞선 비교의 46통과/1건너뜀은 그 기존 스크립트 결과이며 별도 Edge 안내 실세션과 구분해야 한다. 이번에는 Edge 전용 실행 파일·보이는 창을 명시하고 기존 준비 프로필을 건드리지 않는 별도 시험 창을 사용한다.
- 이미지/AI는 새 유료 생성 없이 기존 합성 자료를 사용한다. 기능 시험용 본인 원고·본인 블로그의 비공개 실제 발행 최소 1건을 목표로 하며 공개 게시·기존 준비 원고 발행으로 범위를 늘리지 않는다. 추가 유료 API 비용 없음. 배포는 로컬 확인 후 프로그램 한 묶음, 서버/도메인/유료 라이브러리 신규 비용 없음.
- 공용 기능 지도에 확정된 발행 엔진 모듈은 없으며 에이전트의 최종 클릭/URL 검증 패턴을 참고한다. 등록된 공용 사본/이미지 프롬프트는 수정하지 않는다. 엔진 기준 확정은 실제 검수 근거 뒤 별도 기록한다.

## 17:48 실세션 보완 플랜 — v1.83

지정 일반 회원의 실제 Edge 검수에서 이미지 없는 합성 원고의 웹 전송이 기존 이미지 3장 필수 조건에 막혔다. 이번 합성 원고만 DB에서 전송함으로 준비해 확장 나머지 경로를 분리 진단했으며 웹 전송 성공으로 집계하지 않는다. 첫 자동 실행은 빈 편집기 확인에서 failed로 종료했고 arm/최종 발행은 없었다. 새 탭에 네이버 복원 창과 U+200B 빈 문자도 관찰됐다.

선택한 이미지 블록의 실제 파일만 검사해 텍스트/전송 제외 원고를 허용하고, 확장 이미지 0장 안내를 바로잡는다. 빈 문자 정규화와 복원 창 차단, 새 편집기 확인 진행 안내를 보완한다. 자동 발행 JSON을 SEO 설명란에서 직접 렌더하지 않도록 문자열 분석 항목만 표시하고 발행 결과는 전용 컴포넌트에서 유지한다. 수동 전용 조작과 자동 포스팅 안내를 구분한다. 관련 회귀/타입/빌드 뒤 웹 전송·실제 비공개 발행·URL/기록·결과 재확인을 끝내고 한 묶음 배포한다. 추가 유료 AI 0, DB 스키마 변경 없음. 실패 원고/실행은 보존하고 새 복제 원고로 검수한다.

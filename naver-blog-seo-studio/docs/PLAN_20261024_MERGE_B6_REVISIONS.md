## 원본(콘텐츠 메이커)
- `blog-content-maker`: 저장할 때마다 수정본을 따로 쌓고(`saveRevision`, 수정본 번호·시각), 「수정 이력」 카드에서 이전 수정본을 골라 **그때의 전체 글**을 보여 준다. 줄 단위 비교·되돌리기는 없다.

## SEO 스튜디오의 현재
- `app/api/drafts/[draftId]` `PATCH`가 제목·본문을 **덮어쓴다** — 고치기 전 글이 남지 않는다. `app/api/drafts/history`는 원고 목록일 뿐.

## 구현 (콘텐츠 메이커보다 나아지는 점: 바뀐 문단 비교 + 되돌리기)
1. 서버: 원고 저장(`PATCH`)에서 제목이나 본문이 실제로 바뀌면, **바뀌기 전** 제목·본문을 원고의 `seo_report.revisions`에 넣는다(최근 10개까지, 시각·글자 수·원인 「직접 수정」). 원고와 함께 30일 뒤 지워진다. **DB 변경 없음**(JSON 칸).
   - 같은 방식으로 본문을 바꾸는 다른 경로(기존 글 최적화 저장 `save-optimized` 등)가 있으면 같은 도우미를 부른다.
2. `lib/draftRevisions.ts`(순수 함수): 이력 넣기(최대 10, 같은 글 중복 저장 안 함), **문단 단위 비교**(빈 줄 기준 문단을 맞춰 「추가·삭제·그대로」 표시 — 간단한 LCS).
3. 화면(원고 편집): 「수정 이력 (N)」 카드 — 수정본 고르기 → 지금 글과 바뀐 문단 비교(삭제는 빨간 줄, 추가는 초록) → **「이 수정본으로 되돌리기」**(확인 창 → 저장 → 지금 글도 이력에 남아 다시 되돌릴 수 있음). 자동 포스팅 중인 원고는 되돌리기 잠금(기존 쓰기 보호 그대로).
4. 시험: 이력 넣기(바뀐 때만·10개 상한·중복), 비교 결과, 되돌리기 저장 흐름(가짜 DB).

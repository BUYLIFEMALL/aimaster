# G-2 커스텀 봇·내장 봇 개발 플랜

2026-10-24 · Codex(윈도우·Edge) `codex-win-20261024-docbot-g2` · 역할 `docbot-prompt`.

주인님 「그럼 계속 진행」에 따라 추천 구성인 **문서 챗봇의 채팅방에서 봇 선택**을 기준으로 구현합니다. Groq/OpenRouter 키는 나중에 등록하며, 기존 회원 본인 Upstage를 기본으로 유지합니다. Prompt와의 양방향 동기화/봇 복사·G-3 전체 역할 검수·G-4 문서 개선·G-5 로컬 AI는 이번 범위에 넣지 않습니다.

## 구현·검증 순서

1. 회원별 `dcb_bots`에 이름(60자)·직접 지침(6,000자)·지원 공급자/모델·온도(0~1)를 저장합니다. API/모델 허용 목록은 G-1 기준을 재사용하고 NVIDIA/다른 회원 키는 사용하지 않습니다. 기본 봇은 직접 작성한 번역·요약·업무 문서 3종입니다.
2. `/bots`에서 생성/수정/삭제·기본 봇을 내 설정으로 복사합니다. 수정·삭제 시 정수 `revision`을 비교해 다른 창의 변경을 덮어쓰지 않습니다(`updated_at`은 시각 표시). API는 권한 확인 후 본인 `user_id`로 한정합니다. 회원당 100개 제한은 API 개수 검사이며 동시 생성까지 막는 DB 제약은 아닙니다.
3. 채팅방에는 `bot_ref`만 저장하고 응답에는 당시 실제 공급자/모델/온도·봇 지침의 사본을 `generation_context`에 기록합니다. 과거 답변의 설정은 봇 수정/삭제로 바꾸지 않습니다. 삭제된/지원 종료 봇은 알리고 해제/다른 봇 선택을 요구합니다(자동 대체 안 함).
4. `/chat`에서 봇 선택/해제·방 재열기를 연결합니다. 서버가 본인 봇을 다시 조회해 지침·모델을 적용하며, 클라이언트가 보낸 가짜 지침/소유자 값을 신뢰하지 않습니다. 기존 일반 채팅/문서 파싱/1024차원/30일 정리는 유지합니다.
5. 운영 DB ref **`esgxyikcnnvmlhygjkth`**에 추가 마이그레이션만 적용합니다. `dcb_bots`는 직접 저장하는 설정이라 생성 콘텐츠 30일 삭제와 구분합니다. 답변 설정 사본은 메시지와 함께 기존 30일 보관을 따릅니다. 새 표의 본인 RLS·권한과 기존 방 쓰기 경계를 확인합니다.
6. 모의 DB/fetch 시험으로 본인 CRUD·타 회원/삭제/변경 충돌·모델/온도·설정 기록을 검증하고 타입/로컬 빌드, Edge 실제 화면 CRUD/재열기를 확인합니다. 실제 AI는 일반 시험 회원 본인 기존 키가 있을 때 원래 승인 예산에서 최소 호출만 수행합니다.

## 배포·비용

- 기존 G-1~G-4 앱당 1회·총2회 묶음 배포 계획을 유지합니다. 이번 소스 작업만으로 운영 배포 완료라 하지 않고 v1.07을 유지합니다.
- 모의/타입/로컬 빌드·설정 CRUD 검수에는 AI 요금이 없습니다. 실제 호출은 전체 텍스트 10회/실비1,000원 상한에서 누적 관리합니다. 관리자 키를 다른 회원을 위한 대체 키로 쓰지 않습니다.
- 관리자 화면 요청: `node scripts/dev-requests.mjs list --role docbot-prompt` — 대기 요청 없음 확인. 이전 G-1 새 공급자 실제 호출은 주인님 결정대로 키 등록 후로 남깁니다.

## 선택값과 삭제 처리

기본 봇은 공개된 정적 설정(`preset-*`), 내 봇은 본인 UUID로 식별합니다. 방의 참조는 서버에서 매번 소유권/지원 상태를 검증합니다. 기존 방의 RLS는 본인 조회만 허용하고, 변경은 인증된 서버 API로만 처리합니다. 삭제된 봇의 방 참조를 자동으로 지우지 않아, 다시 열 때 삭제 사실을 알려 사용자가 직접 해제/변경하도록 합니다. 과거 메시지 사본을 수정하지 않습니다.

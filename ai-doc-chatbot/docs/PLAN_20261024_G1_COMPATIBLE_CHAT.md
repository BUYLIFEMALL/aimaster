# G-1 공용 공급자·회원 공용 키 구현 플랜

2026-10-24 · Codex(윈도우, Edge) `codex-win-20261024-docbot-g1`.

주인님이 [G-1~G-5 플랜·비용](../../docs/analysis-autogemma-starter-20261024/PLAN_G1_G5_20261024.md)을 보신 뒤 「순서대로 한스텝 한스텝 진행」하도록 지시했습니다. 이번 작업은 **G-1만** 구현·로컬 검수합니다. G-2 봇 위치와 G-5 진행 선택은 해당 단계 전에 확정하며 지금 구현하지 않습니다.

## 범위와 순서

1. 공식 공급자 설정/메시지·결과/스트리밍·취소·오류 계약을 문서 챗봇의 기준 모듈로 작성하고 Prompt에 동일 사본을 둡니다. Groq·고정 무료 OpenRouter·Cloudflare 활성, NVIDIA는 운영 조건 확인 전 비활성입니다.
2. 회원 공용 `user_api_keys`의 같은 항목을 두 프로그램에서 사용합니다. 기존 Upstage/Gemini는 유지하고 새 공급자 선택 시 필요한 키만 확인합니다. 문서 파싱·1024차원 임베딩은 Upstage 그대로입니다.
3. 무료 Prompt 회원도 다른 유료 프로그램 권한 없이 키를 등록할 수 있도록 **같은 공용 등록 UI/로직**을 각 프로그램의 기존 설정에 배치합니다. 새 저장소나 별개 키 복사본을 만들지 않습니다. 두 앱 권한을 합치거나 무료 정책을 바꾸지 않습니다.
4. 문서 챗봇 답변/라우터와 Prompt의 템플릿 실행에 공급자/모델 선택을 연결합니다. Prompt 설계·변수 제안·자동 채우기는 기존 Gemini를 유지합니다.
5. 현재 provider 제약·카탈로그를 먼저 읽고 기존 값을 보존한 추가 마이그레이션을 작성합니다. 대상은 운영 DB ref `esgxyikcnnvmlhygjkth`이며 회원 키/자료를 일괄 수정하지 않습니다.
6. 공용 모듈 등록과 사본 일치, 스트림/키 소유권/오류/취소·기존 기능 시험, 타입·로컬 빌드를 검사하고 G-1 결과와 남은 실회원 검수를 인계합니다.

## 검수·비용·배포

- 무료/모의 검사부터 수행합니다. 외부 실호출은 시험 회원 본인 키가 있을 때 제안된 전체 예산(텍스트10회+임베딩3요청+PDF1쪽1요청, API 실비 최대1,000원) 안에서만 합니다. 키 등록만으로 외부 AI를 호출하지 않습니다.
- 기존 G-1~G-4 묶음 배포(프로그램당1회·총2회·Basic 실비 상한$0.20) 계획을 유지합니다. G-1 로컬 작업만으로 운영 반영 완료라고 보고하지 않습니다.
- 승인된 단계를 보존해 한 단계씩 진행하고 실제 비용·검수/미검수·DB 적용 여부·버전/배포 상태를 결과에 구분합니다. 미배포 단계에서는 버전을 올리지 않습니다.

## 현재 판단 보완

초기안의 ‘챗봇 설정 한 곳 등록→Prompt 재사용’은 유료 챗봇 권한이 없는 FREE Prompt 회원을 막을 수 있습니다. 공용 표/항목과 동일 등록 부품을 재사용해 두 기존 설정에 표시하는 방식으로 보완합니다. 메인 사이트 코드/권한/별도 배포는 추가하지 않습니다.

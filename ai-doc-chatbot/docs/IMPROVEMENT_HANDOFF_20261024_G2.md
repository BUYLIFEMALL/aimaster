## 범위와 구현

새 공급자 키가 필수가 아님을 설명한 뒤 주인님 「그럼 계속 진행」에 따라 추천한 문서 챗봇 채팅방 선택 구성으로 진행했습니다. Groq/OpenRouter 등록은 나중이라는 결정을 유지하며 기본은 회원 본인 Upstage입니다. 외부 원본의 코드·프롬프트·지식 자료는 복사하지 않았습니다.

## 운영 DB 적용

- 대상 **`esgxyikcnnvmlhygjkth`**, 마이그레이션 **`20261024085152_g2_member_bots`**, SQL은 `supabase/migrations/`에 있습니다. 적용 이력을 확인하고 중복 실행하지 않습니다.
- `dcb_bots` 새 표·본인 RLS. authenticated 본인 SELECT만, 직접 INSERT/UPDATE/DELETE·anon 차단. 프로그램 권한을 검사한 서버만 변경합니다.
- `dcb_rooms.bot_ref` nullable 추가, 삭제 사실을 알리기 위해 FK 자동 삭제 없음. 기존 방 NULL 유지.
- `dcb_messages.generation_context` nullable JSON 객체 추가. 기존 메시지 NULL 유지. 실제 공급자·모델·온도·봇 지침만 명시적으로 골라 저장하며 키/회원 ID는 제외합니다.
- 실제 SQL 트랜잭션에서 본인 1행/타 회원 0행 조회·직접 쓰기 거부를 확인 후 **ROLLBACK**, 임시 시험 행 0건 확인. 이는 실제 회원 브라우저 검수와 별개인 DB 권한 검사입니다.
- 보안 권고에 새 봇 객체 관련 지적 없음. 기존 키·회원 권한·문서·대화 데이터는 덮어쓰지 않았습니다.

- 관리자 요청 먼저 확인: `dev-requests list --role docbot-prompt`, 대기 0건.
- 문서 챗봇=업무자동화, AI Prompt=AI 프롬프트로 역할 현황 정정.
- 일반 회원 기능은 `buylifemall@naver.com` 실제 로그인·본인 키로 검수. G-1 관리자 화면 관찰과 구분.

- 공용 스테이징 개수=HEAD, 타 작업 묵은 항목 경고는 보존. 본인 변경만 안전 도우미로 커밋합니다.

## 다음 첫 단계·추가 개선

1. 역할 요청·ACTIVE_WORK·최신 HEAD·이 문서를 확인하고 현재 Edge 창을 새로 찾습니다(옛 창 번호 재사용 금지).
2. `http://localhost:4311/bots`에 시험 회원이 직접 로그인하면 합성 봇 생성→수정→목록 재열기→기본 봇 선택→방 설정 저장/재열기→삭제된 봇 안내와 좁은 화면을 확인합니다. 기존 회원 자료는 바꾸지 않습니다.
3. 실제 답변은 시험 회원 본인 키 준비 뒤 승인된 최소 호출 예산에서 수행합니다. 새 Groq/OpenRouter 등록을 지금 요구하지 않습니다.
4. G-2 검수 뒤 G-3 역할 경계·G-4 문서 근거를 순서대로 진행합니다. 앱별 묶음 배포 때 버전·DB·프로그램 비교표를 맞춥니다.
5. 관리자 0044 적용 후 결과는 `report`, 필요한 로그인 요청은 `ask --category account`에 등록합니다.

기능 제안은 G-3의 역할 경계 검수, 화면 제안은 긴 지침/삭제 경고의 좁은 화면 조작성 확인, 연계 제안은 Prompt 템플릿에서 회원이 선택한 지침 복사입니다. 연계는 별도 설계 후보이며 자동 동기화를 구현하지 않았습니다.

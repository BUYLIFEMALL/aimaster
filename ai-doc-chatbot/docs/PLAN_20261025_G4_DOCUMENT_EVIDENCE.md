# G-4 문서 근거 보강

2026-10-25 · `docbot-prompt` · `codex-win-20261025-docbot-g4` · 기존 G-1~G-4 승인과 주인님 「다음 진행해줘」로 진행합니다. 대상 AIMaster 운영 DB ref **`esgxyikcnnvmlhygjkth`**. 디자인은 agy 담당이며 기존 테마에서 기능에 필요한 선택/미리보기 조작만 추가합니다.

## 확인한 문제

단일 문서 선택은 전체 벡터 상위20개를 받은 뒤 선택 문서만 골라 근거를 놓칠 수 있습니다. 문서 분류/자체 미리보기/PDF 추출 경고가 없고, 서비스 키 조회가 30일 만료와 저장 완료 상태를 즉시 제외하지 않습니다. 기존 벡터+키워드 혼합 검색은 이미 있어 재구현하지 않습니다.

## 단계와 완료 조건

1. DB 실제 칼럼·함수·RLS 조회 후 추가 마이그레이션: 문서 `category`(40자), `processing_status`(기존 문서는 ready, 새 업로드는 processing→ready), `extraction_warning`(추출 의심 코드). 기존 `dcb_match_chunks` 계약·1024차원·원문/조각·생성일·정리 Cron은 유지합니다. 새 범위 검색 함수는 service_role만 실행하고 SECURITY INVOKER·고정 search_path를 적용합니다.
2. 서버는 다중 UUID(최대30개)/옛 단일 documentId를 검증하고 키·방·질문 저장 전에 본인 소유/30일 미만/ready를 확인합니다. 빈 선택을 전체 검색으로 바꾸지 않습니다. 벡터·키워드·요약 앞부분 조회 모두 같은 허용 ID 범위와 조각 수명을 검색 전에 적용하고, 새 함수 실패 시 전체 검색으로 폴백하지 않습니다.
3. 본인 문서 분류 수정·저장 텍스트 앞부분 미리보기 API를 추가합니다. 키가 없어도 사용하고, 타 회원/만료/처리 중 문서 내용을 노출하지 않습니다. 목록도 만료 자료를 제외합니다. 원본 파일은 계속 보관하지 않으며 미리보기는 저장된 앞부분 조각임을 밝힙니다.
4. PDF의 빈 글·대체문자·과도한 비정상 제어/자모를 조심스럽게 감지합니다. 빈 글은 임베딩 전에 설명하고 멈추며, 읽을 글이 있으면 경고와 함께 저장합니다. 파일 손상의 확정 진단이나 자동 유료 재파싱/OCR은 하지 않습니다. 동기/비동기 경로를 모두 반영합니다.
5. 채팅의 여러 문서 체크·분류 필터·기존 단일 문서 링크, 내 문서의 분류/미리보기/추출 경고를 기존 부품으로 연결합니다. 선택하지 않은 문서가 출처에 섞이지 않아야 합니다. 이름이 같은 문서는 ID로 구분합니다.
6. 무료 순수/실제 라우트 모의 시험, 실제 DB의 두 회원·미선택·만료·processing 범위 시험(합성 행 트랜잭션 ROLLBACK), 타입·로컬 빌드, 일반 회원 Edge 검수를 구분해 기록합니다. 실제 AI/업로드는 본인 Upstage 키와 기존 승인 예산일 때만 최소 호출합니다.

## 비용·배포·기록

새 패키지/새 유료 항목/기존 자료 일괄 재임베딩 없이 진행합니다. DB는 승인된 G-4의 추가 메타데이터와 필터 함수 범위만 적용합니다. 외부 AI 호출 없이 가능한 검수를 먼저 끝내고, 키가 없으면 실제 응답/파싱 품질은 미검수로 남깁니다. 로컬 빌드는 순차1회 계획이며 앱 배포는 G-1~G-4 기존 앱당1회/총2회 계획을 유지하고 팀 전체 빌드 상태를 재확인합니다. 배포 전까지 v1.07 유지·미배포 대기입니다.

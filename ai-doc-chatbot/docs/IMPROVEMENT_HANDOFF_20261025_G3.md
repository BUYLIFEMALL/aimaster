## 달라진 동작

- `src/lib/chat/prompts.ts`: 플랫폼·봇 지시문(system)과 처리 대상/문서·웹 근거(user JSON)를 분리합니다. 이름·본문 안의 따옴표/역할 구분자도 JSON 값으로 보존합니다. 과거 대화에서 system 역할은 제외하고 user/assistant만 전달합니다. 문서의 소유자/키 등 내부 필드는 입력에 넣지 않습니다.
- `core.ts`: 플랫폼 정책·한국 시간 현재 기준·출처 규칙을 유지하면서 원문 속 과거 날짜를 바꾸지 않도록 명시합니다. 봇의 대상 언어·형식은 기본 한국어 표현보다 우선하며 플랫폼의 회원 격리·도구/출처 규칙은 유지합니다.
- `bots/core.ts`: 번역·요약에 질문형 글/역할·언어 변경 유도도 원문으로 처리하는 직접 작성 예시를 추가했습니다. 두 기본 봇 revision은 2, 업무 문서 봇은 1입니다. 예전에 회원이 복사·저장한 봇은 바꾸지 않습니다. 오래 열린 화면의 옛 revision은 409로 새로 선택하도록 합니다.
- `chat/route.ts`: 기본 번역·요약은 원문 처리이므로 auto 웹 검색 판단/외부 검색을 하지 않습니다. 일반/업무/회원 저장 봇은 기존 auto 선택을 유지하며, 라우터에 선택 작업 설명을 전달합니다. 라우터는 system 지침 + user JSON, 비스트리밍 응답→기존 JSON 해석입니다. 답변 NDJSON meta/delta/done/error·당시 설정 기록·저장 실패 처리는 유지했습니다.

자료 구분은 모델에 전달하는 구조와 지침을 보강한 것입니다. JSON에 넣었다는 이유로 지침 이탈을 완전히 막거나 실제 출력 언어·형식을 보장한다고 보고하지 않습니다. 서버 소유권·RLS·허용 API 검증을 대체하지 않습니다.

## 일반 회원 Edge 검수

대상 localhost:4311, 지정 시험 회원 `buylifemall@naver.com`, 실제 보이는 Edge 창. 관리자 우회·인증 주입 없이 로그인된 회원 화면에서 진행했습니다.

1. 내 봇 0개에서 기본 한국어 번역을 「내 봇으로 편집」. 이름을 합성 검수명으로 바꾸고 저장 → 1개·저장 알림 확인.
2. 이름 수정·변경 저장 → 목록/폼에 새 이름 표시, 새로고침 후 유지 확인.
3. 「이 봇으로 새 대화」 → 선택한 이름·온도0.2·Solar 모델 확인. 아직 대화방은 0개.
4. 이 검수에서 만든 봇만 삭제 확인 창에서 삭제 → 0개. 기본 봇 3개와 기존 회원 자료는 그대로입니다.
5. 삭제된 시험 봇 링크로 재진입 → 삭제/사용 불가 안내와 일반 채팅으로 해제 동작 확인. 임의 다른 봇으로 자동 대체되지 않습니다.
6. 설정에서 본인 Upstage/Tavily 미등록 확인. 합성 연결 질문 전송 → Upstage 본인 키 등록 안내·대화방 목록 0개 확인. AI 호출 전에 막히는 서버 경로이며 실제 AI 요청 0회입니다. 새 대화로 임시 화면 질문을 정리했습니다.

임시 시험 봇 id `d65e28f7-e693-4a67-8ca3-3f939e3bfc9e`는 삭제 완료입니다. 시험 봇 생성 1회·수정 1회·삭제 1회 외 회원 설정/자료 변경 없음. 질문·방은 서버에 생성되지 않았습니다. 화면 캡처는 이번 Orca 실행의 임시 캡처 경로에 있으며 장기 보관 증거가 아닙니다. 위 재현 순서와 자동 검사는 저장소에 남깁니다.

## 재개 순서

1. 관리자 역할 요청·ACTIVE_WORK·이 문서를 먼저 확인합니다. 디자인은 agy 담당이며 로그인/CSS/테마를 손대지 않습니다. 기능 파일도 다른 세션 예약이 있으면 대조합니다.
2. G-4 기존 단일 문서/혼합 검색/snippet을 재사용해 여러 문서 선택·분류·미리보기·PDF 경고를 보강합니다. 검색 전 소유자·상태·만료 범위 검증, 1024차원·기존 RPC 계약을 보존합니다. G-3을 새 검색 구현이라고 표시하지 않습니다.
3. 시험 회원 본인 Upstage 키가 준비되면 실제 번역/요약·방 저장/재열기·봇 수정 뒤 당시 설정 보존을 기존 승인 최소 호출로 검수합니다. Groq/OpenRouter 새 키는 나중이라는 결정 유지. 키를 다른 회원/운영자에게서 가져오지 않습니다.
4. 실제 AI/휴대폰 폭 미검수를 끝낸 뒤 프로그램 버전·DB·문서·비교표를 맞춰 순차 묶음 배포합니다. G-5 로컬 AI·NVIDIA 운영은 별도 결정입니다.

개선 관점: 개발은 입력/지시 경계·기존 저장 계약 보존, 디자인은 기존 화면 기능 검수만(실제 디자인 변경은 agy), 신규성은 기존 챗봇 안정화이며 새 독립 시스템이 아닙니다. 새 모듈 제안·회원 간 자료 공유는 없습니다.
